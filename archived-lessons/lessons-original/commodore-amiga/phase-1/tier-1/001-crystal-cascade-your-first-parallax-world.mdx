## Your First Parallax World

Let's start with the magic. Here's the code that creates your multi-layered crystal world:

```nasm
; Crystal Cascade - Parallax World Creation
    SECTION code,CODE

start:
    ; Initialize background layer (far mountains)
    MOVE.L  #$00040000, A0      ; Point to bitplane 0 (background)
    MOVE.W  #$0123, D0          ; Mountain pattern (binary: 0001001000100011)
    MOVE.W  D0, (A0)            ; Draw first mountain stripe
    MOVE.W  D0, 40(A0)          ; Repeat on next row

    ; Initialize middle layer (crystal formations)
    MOVE.L  #$00042000, A1      ; Point to bitplane 1 (middle layer)
    MOVE.W  #$4567, D1          ; Crystal pattern (more detailed)
    MOVE.W  D1, 20(A1)          ; Place crystals offset from mountains
    MOVE.W  D1, 60(A1)          ; Continue pattern

    ; Initialize foreground layer (metallic structures)
    MOVE.L  #$00044000, A2      ; Point to bitplane 2 (foreground)
    MOVE.W  #$FEDC, D2          ; Metal structure pattern (very detailed)
    MOVE.W  D2, 10(A2)          ; Offset for depth illusion
    MOVE.W  D2, 50(A2)          ; Continue foreground elements

    ; Set spectacular colors using copper
    MOVE.L  #$00DFF180, A3      ; Point to color palette
    MOVE.W  #$000F, (A3)        ; Background: Deep blue mountains
    MOVE.W  #$0F0F, 2(A3)       ; Middle: Bright cyan crystals
    MOVE.W  #$FF0F, 4(A3)       ; Foreground: Metallic gold structures

    ; Infinite loop to admire your parallax creation
loop:
    BRA.S   loop
```

## What Just Happened? The Magic Behind Your Game

### The 68000: Your Professional Game Partner

The **68000 processor** is what made the Amiga revolutionary. While other computers used simple 8-bit chips, the Amiga had the same processor powering expensive workstations. This gives you incredible power for games:

```nasm
MOVE.L  #$00040000, A0      ; Point to bitplane 0
MOVE.W  #$0123, D0          ; Load mountain pattern
MOVE.W  D0, (A0)            ; Store pattern to graphics memory
```

This simple sequence:

1. Loads a graphics memory address into **address register A0**
2. Loads a visual pattern into **data register D0**
3. Stores the pattern to the memory location A0 points to

### Data and Address Registers: Your Game Architecture

The 68000's power comes from its rich register set - perfect for complex games:

**Data Registers (D0-D7)**: Your game's calculation engine

- **D0**: Background layer patterns and positions
- **D1**: Middle layer crystal formations
- **D2**: Foreground metallic structures
- **D3**: Animation counters and timing
- **D4-D7**: Additional game objects and effects

**Address Registers (A0-A7)**: Your memory management system

- **A0**: Points to background graphics memory
- **A1**: Points to middle layer graphics memory
- **A2**: Points to foreground graphics memory
- **A3**: Points to color palette memory
- **A4-A6**: Additional memory areas for game data

### Professional Game Programming

**Why Assembly for Amiga Games?**

You might wonder: "Why not use a high-level language?" Here's why assembly unleashes the Amiga's power:

**High-Level Version** (slow, limited):

```c
for(int i = 0; i < 100; i++) {
    screen[i] = pattern;
}
```

**68000 Assembly Version** (blazing fast, direct hardware control):

```nasm
MOVE.W  #100, D7            ; Loop counter
MOVE.L  #pattern, A0        ; Source pattern
MOVE.L  #screen, A1         ; Destination screen
loop:
    MOVE.W  (A0), (A1)+     ; Copy pattern, auto-increment A1
    DBRA    D7, loop        ; Decrement and branch
```

The assembly version is **dramatically faster** and gives you direct control over every graphics operation.

### Multi-Layered Graphics Architecture

In **Crystal Cascade**, you'll use the Amiga's bitplane system to create stunning parallax effects:

- **Bitplane 0** ($40000): Background mountains (moves slowly)
- **Bitplane 1** ($42000): Crystal formations (moves medium speed)
- **Bitplane 2** ($44000): Foreground metals (moves fast)
- **Color Palette** ($DFF180): Controls all layer colors

This creates the illusion of depth through different movement speeds!

## Understanding the Amiga's Professional Capabilities

### 16/32-bit Power

The 68000 can work with different data sizes in the same program:

```nasm
MOVE.B  #$FF, D0        ; 8-bit: Byte operations for flags
MOVE.W  #$1234, D1      ; 16-bit: Word operations for coordinates
MOVE.L  #$12345678, D2  ; 32-bit: Long operations for large values
```

This flexibility lets you optimize every aspect of your game for maximum performance.

### Professional Memory Management

Unlike simple computers, the Amiga can address **16 megabytes** of memory directly:

```nasm
MOVE.L  #$00040000, A0  ; Graphics memory (256KB area)
MOVE.L  #$00080000, A1  ; Program code (512KB area)
MOVE.L  #$00200000, A2  ; Large data structures (2MB area)
```

This means your games can be huge and sophisticated!

### Quick Reference: Today's Assembly Instructions

- **MOVE.L address, An**: Load a 32-bit address into an address register
- **MOVE.W value, Dn**: Load a 16-bit value into a data register
- **MOVE.W Dn, (An)**: Store data register contents to memory address in An
- **MOVE.W Dn, offset(An)**: Store with offset (for positioning graphics)
- **BRA.S label**: Branch to a program location (infinite loop)

Save this reference - you'll use these instructions to create professional games!
