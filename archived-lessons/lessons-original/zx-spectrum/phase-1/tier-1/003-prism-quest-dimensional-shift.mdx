## Your Dimensional Shift Awakens

Let's start with the magic - adding interactive color shifting to your dimensional maze:

```nasm
; Prism Quest - Dimensional Shift Creation
    ORG $8000
    
start:
    ; Set up dimensional maze world from Lessons 1-2
    CALL clear_screen
    CALL draw_dimensional_maze
    
    ; Initialize dimensional navigator from Lesson 2
    LD BC, $0205        ; Navigator position: B=X(2), C=Y(5)
    LD (navigator_x), BC ; Store in memory
    
    ; Initialize dimensional shift system
    CALL init_color_dimensions
    
    ; Create interactive shift zones
    CALL create_shift_zones
    
    ; Main dimensional interaction loop
main_loop:
    CALL read_navigator_input
    CALL update_navigator_position
    CALL check_dimensional_triggers
    CALL update_color_dimensions
    JR main_loop

; Initialize color dimension system
init_color_dimensions:
    ; Set up dimension state in memory
    LD A, $01           ; Dimension 1 (immediate addressing)
    LD (current_dimension), A ; Store current dimension (direct addressing)
    
    ; Initialize color patterns for each dimension
    LD HL, $5800        ; Point to attribute memory (direct addressing)
    LD A, $47           ; Bright white on black (immediate addressing)
    LD (HL), A          ; Set base color (register indirect addressing)
    
    ; Create dimension color lookup table
    LD HL, dimension_colors ; Point to color table (direct addressing)
    LD (color_table_ptr), HL ; Store table pointer (direct addressing)
    
    RET

; Create interactive dimensional shift zones
create_shift_zones:
    ; Create shift zone 1 (red dimension)
    LD HL, $4000 + (8*32) + 10  ; Screen position (direct addressing)
    LD A, $7F           ; Solid block character (immediate addressing)
    LD (HL), A          ; Place shift trigger (register indirect addressing)
    
    ; Set attribute for shift zone 1
    LD HL, $5800 + (8*32) + 10  ; Attribute position (direct addressing)
    LD A, $42           ; Red on black (immediate addressing)
    LD (HL), A          ; Set red shift zone (register indirect addressing)
    
    ; Create shift zone 2 (blue dimension)  
    LD HL, $4000 + (12*32) + 15 ; Screen position (direct addressing)
    LD A, $7F           ; Solid block character (immediate addressing)
    LD (HL), A          ; Place shift trigger (register indirect addressing)
    
    ; Set attribute for shift zone 2
    LD HL, $5800 + (12*32) + 15 ; Attribute position (direct addressing)
    LD A, $41           ; Blue on black (immediate addressing)
    LD (HL), A          ; Set blue shift zone (register indirect addressing)
    
    ; Create shift zone 3 (green dimension)
    LD HL, $4000 + (6*32) + 20  ; Screen position (direct addressing)
    LD A, $7F           ; Solid block character (immediate addressing)
    LD (HL), A          ; Place shift trigger (register indirect addressing)
    
    ; Set attribute for shift zone 3  
    LD HL, $5800 + (6*32) + 20  ; Attribute position (direct addressing)
    LD A, $44           ; Green on black (immediate addressing)
    LD (HL), A          ; Set green shift zone (register indirect addressing)
    
    RET

; Check if navigator triggered dimensional shift
check_dimensional_triggers:
    ; Calculate navigator screen position
    LD A, (navigator_y) ; Load Y position (direct addressing)
    ADD A, A            ; Multiply by 2
    ADD A, A            ; Multiply by 4  
    ADD A, A            ; Multiply by 8
    ADD A, A            ; Multiply by 16
    ADD A, A            ; Multiply by 32 (row * 32)
    LD H, A             ; Store high byte
    LD A, (navigator_x) ; Load X position (direct addressing)
    LD L, A             ; Store low byte
    LD BC, $5800        ; Base attribute address (immediate addressing)
    ADD HL, BC          ; Calculate exact attribute position
    
    ; Read current attribute at navigator position
    LD A, (HL)          ; Read attribute (register indirect addressing)
    AND $07             ; Mask to get foreground color (immediate addressing)
    
    ; Check which dimension to shift to
    CP $02              ; Check for red (immediate addressing)
    JR Z, shift_to_red_dimension
    CP $01              ; Check for blue (immediate addressing)
    JR Z, shift_to_blue_dimension
    CP $04              ; Check for green (immediate addressing)
    JR Z, shift_to_green_dimension
    
    RET                 ; No shift trigger found

shift_to_red_dimension:
    LD A, $01           ; Red dimension ID (immediate addressing)
    LD (current_dimension), A ; Store new dimension (direct addressing)
    CALL apply_red_dimension_effects
    RET

shift_to_blue_dimension:
    LD A, $02           ; Blue dimension ID (immediate addressing)
    LD (current_dimension), A ; Store new dimension (direct addressing)
    CALL apply_blue_dimension_effects
    RET

shift_to_green_dimension:
    LD A, $03           ; Green dimension ID (immediate addressing)
    LD (current_dimension), A ; Store new dimension (direct addressing)
    CALL apply_green_dimension_effects
    RET

; Apply red dimension color effects
apply_red_dimension_effects:
    ; Transform maze colors to red dimension
    LD HL, $5800        ; Start of attribute memory (direct addressing)
    LD BC, $0300        ; 768 attribute bytes (immediate addressing)
    
red_transform_loop:
    LD A, (HL)          ; Read current attribute (register indirect addressing)
    AND $F8             ; Keep background and brightness (immediate addressing)
    OR $02              ; Set foreground to red (immediate addressing)
    LD (HL), A          ; Write transformed attribute (register indirect addressing)
    
    INC HL              ; Next attribute position
    DEC BC              ; Decrement counter
    LD A, B             ; Check if BC = 0
    OR C
    JR NZ, red_transform_loop
    
    ; Flash border to indicate dimension shift
    LD A, $02           ; Red border (immediate addressing)
    OUT ($FE), A        ; Set border color (immediate addressing)
    
    RET

; Apply blue dimension color effects
apply_blue_dimension_effects:
    ; Transform maze colors to blue dimension
    LD HL, $5800        ; Start of attribute memory (direct addressing)
    LD BC, $0300        ; 768 attribute bytes (immediate addressing)
    
blue_transform_loop:
    LD A, (HL)          ; Read current attribute (register indirect addressing)
    AND $F8             ; Keep background and brightness (immediate addressing)
    OR $01              ; Set foreground to blue (immediate addressing)
    LD (HL), A          ; Write transformed attribute (register indirect addressing)
    
    INC HL              ; Next attribute position
    DEC BC              ; Decrement counter
    LD A, B             ; Check if BC = 0
    OR C
    JR NZ, blue_transform_loop
    
    ; Flash border to indicate dimension shift
    LD A, $01           ; Blue border (immediate addressing)
    OUT ($FE), A        ; Set border color (immediate addressing)
    
    RET

; Apply green dimension color effects
apply_green_dimension_effects:
    ; Transform maze colors to green dimension
    LD HL, $5800        ; Start of attribute memory (direct addressing)
    LD BC, $0300        ; 768 attribute bytes (immediate addressing)
    
green_transform_loop:
    LD A, (HL)          ; Read current attribute (register indirect addressing)
    AND $F8             ; Keep background and brightness (immediate addressing)
    OR $04              ; Set foreground to green (immediate addressing)
    LD (HL), A          ; Write transformed attribute (register indirect addressing)
    
    INC HL              ; Next attribute position
    DEC BC              ; Decrement counter
    LD A, B             ; Check if BC = 0
    OR C
    JR NZ, green_transform_loop
    
    ; Flash border to indicate dimension shift
    LD A, $04           ; Green border (immediate addressing)
    OUT ($FE), A        ; Set border color (immediate addressing)
    
    RET

; Update dimensional color effects continuously
update_color_dimensions:
    ; Load current dimension
    LD A, (current_dimension) ; Load dimension ID (direct addressing)
    
    ; Create pulsing effect based on dimension
    LD HL, dimension_pulse_counter ; Point to pulse counter (direct addressing)
    INC (HL)            ; Increment pulse counter (register indirect addressing)
    LD A, (HL)          ; Load counter value (register indirect addressing)
    AND $1F             ; Mask to 0-31 range (immediate addressing)
    
    ; Apply pulsing brightness
    CP $10              ; Compare with midpoint (immediate addressing)
    JR C, dim_phase     ; If less, dim phase
    
bright_phase:
    ; Brighten the current dimension colors
    LD A, $08           ; Bright bit (immediate addressing)
    LD (dimension_brightness), A ; Store brightness (direct addressing)
    JR apply_pulse
    
dim_phase:
    ; Dim the current dimension colors
    LD A, $00           ; No bright bit (immediate addressing)
    LD (dimension_brightness), A ; Store brightness (direct addressing)
    
apply_pulse:
    ; Apply brightness to navigator character
    CALL calc_navigator_attribute_position
    LD A, (HL)          ; Read current attribute (register indirect addressing)
    AND $F7             ; Clear bright bit (immediate addressing)
    LD B, A             ; Save base attribute
    LD A, (dimension_brightness) ; Load brightness (direct addressing)
    OR B                ; Combine with base
    LD (HL), A          ; Write pulsing attribute (register indirect addressing)
    
    RET

; Calculate navigator attribute position
calc_navigator_attribute_position:
    LD A, (navigator_y) ; Load Y position (direct addressing)
    ADD A, A            ; Multiply by 2
    ADD A, A            ; Multiply by 4
    ADD A, A            ; Multiply by 8
    ADD A, A            ; Multiply by 16
    ADD A, A            ; Multiply by 32
    LD H, A             ; High byte of offset
    LD A, (navigator_x) ; Load X position (direct addressing)
    LD L, A             ; Low byte of offset
    LD BC, $5800        ; Attribute base address (immediate addressing)
    ADD HL, BC          ; Calculate final position
    RET

; Clear screen using efficient addressing
clear_screen:
    ; Clear character memory
    LD HL, $4000        ; Character memory start (direct addressing)
    LD BC, $1800        ; 6144 bytes (immediate addressing)
    LD A, $00           ; Clear character (immediate addressing)
    
clear_char_loop:
    LD (HL), A          ; Clear character (register indirect addressing)
    INC HL              ; Next position
    DEC BC              ; Decrement counter
    LD A, B             ; Check if BC = 0
    OR C
    JR NZ, clear_char_loop
    
    ; Clear attribute memory
    LD HL, $5800        ; Attribute memory start (direct addressing)
    LD BC, $0300        ; 768 bytes (immediate addressing)
    LD A, $47           ; White on black (immediate addressing)
    
clear_attr_loop:
    LD (HL), A          ; Clear attribute (register indirect addressing)
    INC HL              ; Next position
    DEC BC              ; Decrement counter
    LD A, B             ; Check if BC = 0
    OR C
    JR NZ, clear_attr_loop
    
    RET

; Draw basic dimensional maze structure
draw_dimensional_maze:
    ; Draw maze walls using character patterns
    LD HL, $4000 + (4*32) + 8   ; Wall position (direct addressing)
    LD A, $FF           ; Solid wall character (immediate addressing)
    LD B, 16            ; Wall length (immediate addressing)
    
draw_wall_loop:
    LD (HL), A          ; Place wall character (register indirect addressing)
    INC HL              ; Next position
    DJNZ draw_wall_loop ; Continue until B=0
    
    RET

; Enhanced navigator input (from Lesson 2)
read_navigator_input:
    ; Read keyboard input using Z80 port system
    LD A, $FD           ; Select keyboard row (immediate addressing)
    IN A, ($FE)         ; Read keyboard port (immediate addressing)
    
    ; Check for movement keys
    BIT 0, A            ; Check key state
    JR NZ, no_input     ; No key pressed
    
    ; Process movement (simplified for demonstration)
    CALL move_navigator_right
    
no_input:
    RET

; Update navigator position from stored values
update_navigator_position:
    ; Load navigator position
    LD BC, (navigator_x) ; Load X,Y position (direct addressing)
    
    ; Calculate screen position for navigator
    CALL calc_navigator_screen_position
    
    ; Place navigator character
    LD A, $81           ; Navigator character (immediate addressing)
    LD (HL), A          ; Place navigator (register indirect addressing)
    
    RET

; Calculate navigator screen position
calc_navigator_screen_position:
    LD A, C             ; Load Y position
    ADD A, A            ; Multiply by 2
    ADD A, A            ; Multiply by 4
    ADD A, A            ; Multiply by 8
    ADD A, A            ; Multiply by 16
    ADD A, A            ; Multiply by 32
    LD H, A             ; High byte
    LD L, B             ; X position as low byte
    LD BC, $4000        ; Screen base (immediate addressing)
    ADD HL, BC          ; Final screen position
    RET

; Simple navigator movement
move_navigator_right:
    LD A, (navigator_x) ; Load current X (direct addressing)
    INC A               ; Move right
    CP 31               ; Check boundary (immediate addressing)
    JR NC, no_move      ; Don't move if at edge
    LD (navigator_x), A ; Store new position (direct addressing)
no_move:
    RET

; Memory variables
navigator_x:        DB 2
navigator_y:        DB 5
current_dimension:  DB 1
dimension_brightness: DB 0
dimension_pulse_counter: DB 0
color_table_ptr:    DW dimension_colors

; Dimension color lookup table
dimension_colors:
    DB $42, $41, $44    ; Red, Blue, Green dimension colors
```

## What Just Happened? The Magic Behind Dimensional Color Control

Now that you've seen your dimensional shifting, let's understand how **Z80 addressing modes** orchestrated this color transformation system.

### Z80 Addressing Modes: Your Dimensional Control System

The most important thing to understand: **Z80 addressing modes determine how efficiently you can manipulate color dimensions**. In your dimensional shift code:

**Immediate Addressing (value)**: Loading known color values
```nasm
LD A, $47           ; Load white on black attribute (immediate addressing)
LD A, $02           ; Load red color code (immediate addressing)
LD BC, $0300        ; Load 768 bytes counter (immediate addressing)
```

**Direct Addressing ((address))**: Accessing specific memory locations
```nasm
LD A, (current_dimension)    ; Load from dimension variable (direct addressing)
LD (navigator_x), A          ; Store to navigator position (direct addressing)
LD HL, $5800                 ; Load attribute memory address (direct addressing)
```

**Register Indirect Addressing ((register))**: Dynamic memory access
```nasm
LD A, (HL)          ; Read attribute from calculated position (register indirect)
LD (HL), A          ; Write color to current position (register indirect)
INC HL              ; Move to next position for efficient loops
```

**Z80 Addressing Mode Examples in Dimensional Color Control:**

| Mode | Example | Use Case |
|------|---------|----------|
| **Immediate** | `LD A, $47` | Load color values and constants for dimensional effects |
| **Direct** | `LD A, (navigator_x)` | Access navigator position and dimension state variables |
| **Register Indirect** | `LD A, (HL)` | Dynamic color reading and writing for attribute transformation |

### The Spectrum Attribute System: Your Creative Constraint

**Spectrum Memory Map - Your Dimensional Control Panel:**
- **$4000-$57FF**: Character memory (maze structure)
- **$5800-$5AFF**: Attribute memory (color dimensions)
- **Each attribute byte**: Controls 8×8 pixel color
- **Border register**: $FE port for dimensional feedback

When you write `LD (HL), A` to attribute memory, you're transforming entire character blocks instantly!

### Why These Addressing Modes Matter for Color Dimensions

**Immediate Addressing** - Perfect for color constants:
```nasm
LD A, $42           ; Red dimension color (known at programming time)
LD BC, $0300        ; Attribute memory size (constant value)
```

**Direct Addressing** - Essential for game state:
```nasm
LD A, (current_dimension)    ; Current dimensional state
LD (navigator_x), A          ; Navigator position storage
```

**Register Indirect Addressing** - Critical for dynamic color transformation:
```nasm
LD A, (HL)          ; Read current color from calculated position
LD (HL), A          ; Write transformed color to same position
```

**Why this matters for dimensional games**: Color transformation happens across 768 attribute bytes - register indirect addressing makes mass color changes efficient.

### Quick Reference: Today's Z80 Addressing Mode Instructions

- **LD A, value**: Load immediate value (for color constants)
- **LD A, (address)**: Load from direct address (for game variables)
- **LD A, (HL)**: Load from register indirect (for dynamic color access)
- **LD (address), A**: Store to direct address (for state updates)
- **LD (HL), A**: Store to register indirect (for color transformation)

Save this reference - you'll use these addressing modes to control all your dimensional systems!
