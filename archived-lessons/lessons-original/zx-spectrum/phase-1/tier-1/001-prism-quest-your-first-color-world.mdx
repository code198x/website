## Your First Game Screen

Let's start with the magic. Here's the code that creates your color-shifting maze world:

```nasm
; Prism Quest - Color World Creation
    ORG 32768

start:
    ; Create the color-shifting maze structure
    LD HL, $4000        ; Point to screen memory
    LD A, 143           ; Block character (solid square)
    LD (HL), A          ; Place block at top-left
    
    ; Create maze walls
    INC HL              ; Move to next position
    LD A, 32            ; Space character
    LD (HL), A          ; Create corridor
    
    INC HL
    LD A, 143           ; Another wall block
    LD (HL), A
    
    ; Move to next row (40 characters down)
    LD BC, 37           ; Calculate row position
    ADD HL, BC          ; Jump to next row
    LD A, 32            ; Space for corridor
    LD (HL), A
    
    ; Set spectacular colors
    LD HL, $5800        ; Point to color memory
    LD A, %01000111     ; Bright white on black
    LD (HL), A          ; Set color for first wall
    
    INC HL
    LD A, %01000010     ; Bright red on black
    LD (HL), A          ; Corridor color
    
    INC HL  
    LD A, %01000100     ; Bright green on black
    LD (HL), A          ; Another wall color
    
    ; Infinite loop to admire your creation
loop:
    JR loop
```

## What Just Happened? The Magic Behind Your Game

Now that you've seen something cool happen, let's understand the magic. This is how the **Z80 processor** - the brain of your Spectrum - made your game world appear.

### Screen Memory: Your Game Canvas

The most important thing to understand: **everything you see on the Spectrum screen is stored in memory**. When you want graphics in your game, you're actually writing data to specific memory locations.

```nasm
LD HL, $4000        ; Point to screen memory start
LD A, 143           ; Load block character
LD (HL), A          ; Store it at screen position 0,0
```

This simple sequence:
1. Loads screen memory address $4000 into the **HL register pair**
2. Loads character 143 (a solid block) into the **A register**
3. Stores the character at the screen position pointed to by HL

### The HL Register Pair: Your Graphics Pointer

The **HL register pair** is like the processor's pointing finger. It tells the Z80 exactly where to put things on screen:

### ZX Spectrum's Color Magic

But wait - there's more! The ZX Spectrum has a unique color system that makes it special:

```nasm
LD HL, $5800        ; Point to color memory
LD A, %01000111     ; Bright white on black
LD (HL), A          ; Set the color
```

Each screen position has two pieces of information:
- **Character** (what shape): stored at $4000-$57FF
- **Color** (what colors): stored at $5800-$5AFF

This dual system is what makes Spectrum graphics so distinctive!

### Color Attribute System

The Spectrum's color system uses 8-bit values where each bit controls a different aspect:

```
Bit 7: FLASH (blinking on/off)
Bit 6: BRIGHT (normal or bright colors)
Bit 5-3: PAPER (background color 0-7)
Bit 2-0: INK (foreground color 0-7)
```

So `%01000111` means:
- No flash
- Bright mode
- Black background (000)
- White foreground (111)

## Understanding Game Programming

### Why Assembly for Games?

You might wonder: "Why not use BASIC?" Here's why assembly makes better games:

**BASIC Version** (slow, limited):
```basic
FOR I = 1 TO 100
  PRINT AT I, 0; CHR$(143)
NEXT I
```

**Assembly Version** (fast, powerful):
```nasm
LD B, 100
LD HL, $4000
loop:
  LD A, 143
  LD (HL), A
  INC HL
  DJNZ loop
```

The assembly version is **dramatically faster** and gives you direct control over every aspect of the hardware.

### Your Game Architecture

In **Prism Quest**, you'll use these same concepts to create:
- **Player character** (moving through the maze)
- **Color-shifting walls** (changing as you approach)
- **Puzzle elements** (doors that respond to colors)
- **Visual effects** (smooth transitions and color cycling)
- **Sound effects** (using the Spectrum's beeper)

All using the same fundamental principle: **store the right values in the right memory locations**.

### Quick Reference: Today's Assembly Instructions

- **LD HL, address**: Load a 16-bit address into the HL register pair
- **LD A, value**: Load an 8-bit value into the A register  
- **LD (HL), A**: Store A register contents to memory address in HL
- **INC HL**: Increment the HL register pair (move to next memory location)
- **JR label**: Jump to a program location (infinite loop)

Save this reference - you'll use these instructions in every game you create!
