# Movement Patterns: Bringing Sprites to Life

**Give your sprites personality through movement**

Static sprites are boring. Moving sprites are better. But sprites that move with purpose and personality? That's where the magic happens! Today you'll learn to create movement patterns that bring your sprites to life - from simple back-and-forth patrols to smooth circular motions.

This is the secret behind every memorable game character. When Bub and Bob bounce around in "Bubble Bobble," when ghosts patrol in "Pac-Man," when enemies swoop down in "Galaga" - they're all using the movement patterns you're about to learn.

## What You'll Create

By the end of this lesson, you'll have sprites that:

- Patrol back and forth like guards
- Bounce around the screen like balls
- Move in smooth circles and waves
- Follow complex predetermined paths

Your sprites will move autonomously - no joystick required!

## Understanding Movement Patterns

Movement patterns are the soul of arcade games. Before complex AI, before sophisticated physics engines, there were movement patterns. They're simple math that creates complex-looking behavior. A guard patrolling back and forth is just checking boundaries and reversing direction. A swooping alien is following a sine wave. Magic emerges from simplicity.

The C64's hardware makes this efficient. You're just changing two memory locations (X and Y coordinates) each frame. The VIC-II chip handles drawing the sprite at the new position. You can have multiple sprites following different patterns simultaneously, creating rich, dynamic scenes with minimal code.

## Basic Movement Patterns

Let's start with simple patterns and build up to complex behaviors. Each pattern teaches a fundamental concept you'll use throughout your C64 programming journey.

### Pattern 1: Horizontal Patrol

The simplest pattern - moving left and right. This is the foundation of countless game behaviors:

```text
*=$0801
        ; BASIC launcher
        !byte $0b,$08,$0a,$00,$9e,$32,$30,$36,$31,$00,$00,$00

*=$080d
start:
        ; Setup sprite
        lda #$80
        sta $07f8              ; Sprite pointer
        lda #%00000001
        sta $d015              ; Enable sprite 0
        lda #$02               ; Red color
        sta $d027

        ; Initial position
        lda #50
        sta $d000              ; X position
        lda #100
        sta $d001              ; Y position

        ; Initial direction (1=right, 255=left)
        lda #1
        sta x_direction
```

The key insight here is using signed arithmetic with unsigned bytes. The value 1 moves right (adding 1), while 255 acts as -1 (subtracting 1) due to byte wraparound. This is a classic 6502 technique - the processor doesn't distinguish between signed and unsigned; it's all in how you interpret the values.

```text
main_loop:
        ; Wait for raster
        lda #250
wait:   cmp $d012
        bne wait

        ; Move sprite
        lda $d000              ; Get current X
        clc
        adc x_direction        ; Add direction
        sta $d000              ; Store new X

        ; Check boundaries
        cmp #24                ; Left edge?
        beq reverse_direction
        cmp #255-24            ; Right edge?
        bne main_loop

reverse_direction:
        ; Flip direction
        lda x_direction
        eor #$fe               ; Toggle between 1 and 255
        sta x_direction
        jmp main_loop

x_direction:    !byte 1
```

The `eor #$fe` instruction is elegant. It flips between 1 (00000001) and 255 (11111111) by toggling all bits except the lowest. This kind of bit manipulation is what makes assembly programming both challenging and beautiful.

### Pattern 2: Box Pattern - State Machines in Action

Moving in a rectangular path introduces state machines - a fundamental game programming concept:

```text
; State machine for box movement
; States: 0=right, 1=down, 2=left, 3=up

box_movement:
        lda movement_state
        asl                    ; Multiply by 2
        tax
        lda state_table,x      ; Get routine address low byte
        sta jump_addr
        lda state_table+1,x    ; Get routine address high byte
        sta jump_addr+1
        jmp (jump_addr)        ; Indirect jump to state handler

state_table:
        !word move_right, move_down, move_left, move_up
```

This is a jump table - a powerful assembly technique. Instead of a chain of comparisons, we calculate the address of the code to execute. The `asl` instruction multiplies by 2 because addresses are 2 bytes. This pattern scales beautifully - you could have dozens of states with no performance penalty.

```text
move_right:
        inc $d000              ; Move right
        lda $d000
        cmp #200               ; Right boundary
        bne done_move
        inc movement_state     ; Next state
        jmp done_move

move_down:
        inc $d001              ; Move down
        lda $d001
        cmp #180               ; Bottom boundary
        bne done_move
        inc movement_state     ; Next state
        jmp done_move

move_left:
        dec $d000              ; Move left
        lda $d000
        cmp #50                ; Left boundary
        bne done_move
        inc movement_state     ; Next state
        jmp done_move

move_up:
        dec $d001              ; Move up
        lda $d001
        cmp #60                ; Top boundary
        bne done_move
        lda #0
        sta movement_state     ; Reset to state 0

done_move:
        rts

movement_state: !byte 0
jump_addr:      !word 0
```

Each state handler does three things: move the sprite, check if we've reached the boundary for this edge, and transition to the next state if needed. This pattern extends to complex AI behaviors - enemies in games like "Commando" or "Ikari Warriors" use similar state machines.

### Pattern 3: Circular Motion - The Power of Lookup Tables

Using sine/cosine for smooth circles demonstrates why lookup tables are essential in C64 programming:

```text
; Circular motion using lookup tables
circular_motion:
        ; Update angle
        inc angle
        lda angle
        and #$3f               ; Keep in range 0-63
        sta angle
        tax

        ; Calculate X position
        lda sine_table,x       ; Get sine value
        clc
        adc #128               ; Center X
        sta $d000
```

Why use lookup tables? The 6502 has no multiply or divide instructions, let alone trigonometric functions. Calculating sine in real-time would take thousands of cycles. But looking up a pre-calculated value? Just 4 cycles. This is the trade-off in C64 programming: memory for speed.

```text
        ; Calculate Y position
        txa
        clc
        adc #16                ; 90 degree phase shift
        and #$3f
        tax
        lda sine_table,x       ; This is cosine
        clc
        adc #100               ; Center Y
        sta $d001

        rts

angle:  !byte 0

; Sine table for 64 steps (0-360 degrees)
sine_table:
        !byte 128,140,152,164,175,185,195,203
        !byte 211,217,222,226,229,231,232,232
        !byte 232,230,228,224,220,214,208,201
        !byte 193,185,176,167,157,147,137,127
        !byte 117,107,97,87,78,69,61,53
        !byte 46,40,34,29,25,22,20,19
        !byte 19,19,21,24,27,31,36,42
        !byte 49,56,64,72,81,90,100,110
```

The magic here is the phase shift. Sine and cosine are the same wave, just 90 degrees apart. By adding 16 to our table index (16 = 90 degrees in our 64-step circle), we get cosine from our sine table. No need for a separate table! This efficiency thinking is crucial when you only have 64KB of RAM.

### Pattern 4: Bouncing Ball - Simple Physics

Physics-based movement with gravity shows how simple rules create complex behavior:

```text
bouncing_ball:
        ; Apply gravity
        inc y_velocity

        ; Update Y position
        lda $d001
        clc
        adc y_velocity
        sta $d001
```

One line - `inc y_velocity` - creates gravity. Each frame, velocity increases by 1, accelerating the sprite downward. This is numerical integration, the same technique used in modern physics engines, just simplified.

```text
        ; Check ground collision
        cmp #200               ; Ground level
        bcc no_bounce

        ; Hit ground - bounce!
        lda #200
        sta $d001              ; Snap to ground

        ; Reverse and dampen velocity
        lda y_velocity
        eor #$ff               ; Negate (two's complement)
        clc
        adc #1
        ; Reduce bounce height
        lsr                    ; Divide by 2
        sta y_velocity
```

The bounce logic is elegant. `eor #$ff` followed by `adc #1` performs two's complement negation, reversing the velocity. The `lsr` (logical shift right) divides by 2, dampening the bounce. Each bounce is half the height of the previous one - realistic physics from three instructions!

```text
        ; Stop tiny bounces
        cmp #2
        bcs no_bounce
        lda #0
        sta y_velocity

no_bounce:
        ; Horizontal movement
        lda $d000
        clc
        adc x_velocity
        sta $d000

        ; Check walls
        cmp #24
        beq reverse_x
        cmp #255-24
        bne done_bounce

reverse_x:
        lda x_velocity
        eor #$ff
        clc
        adc #1
        sta x_velocity

done_bounce:
        rts

x_velocity:     !byte 2
y_velocity:     !byte 0
```

## Advanced Patterns

### Wave Motion - Smooth and Hypnotic

Create smooth sine wave paths that mesmerize:

```text
wave_motion:
        ; Move horizontally
        inc $d000

        ; Calculate Y from sine wave
        lda $d000              ; Use X as phase
        lsr                    ; Scale down
        lsr
        and #$3f               ; Wrap to table size
        tax

        ; Get sine value
        lda sine_table,x
        lsr                    ; Reduce amplitude
        clc
        adc #100               ; Center Y
        sta $d001
```

Using the X position as the phase input is clever - as the sprite moves right, it naturally progresses through the sine wave. The `lsr` instructions control the wave's properties: before the table lookup affects wavelength, after affects amplitude.

```text
        ; Wrap X position
        lda $d000
        cmp #0                 ; Wrapped to 0?
        bne wave_done
        lda #24                ; Reset to left
        sta $d000

wave_done:
        rts
```

### Figure-8 Pattern - Mathematical Beauty

Combine two circles for a figure-8 (lemniscate):

```text
figure_eight:
        ; Update angle
        inc angle
        lda angle
        and #$7f               ; 0-127 range (two loops)
        sta angle

        ; Determine which loop
        cmp #64
        bcc first_loop

second_loop:
        ; Second circle
        sec
        sbc #64
        tax
        lda sine_table,x
        lsr                    ; Half size
        clc
        adc #128
        adc #30                ; Offset right
        sta $d000
        jmp calc_y
```

The figure-8 is two circles with their centers offset horizontally. By checking if our angle is above 64, we switch between circles. This creates the distinctive crossover in the middle - the sprite appears to trace an infinity symbol.

```text
first_loop:
        ; First circle
        tax
        lda sine_table,x
        lsr
        clc
        adc #128
        sec
        sbc #30                ; Offset left
        sta $d000

calc_y:
        ; Y is same for both
        lda angle
        clc
        adc #32                ; Phase shift
        and #$7f
        lsr                    ; Map to 64 entries
        tax
        lda sine_table,x
        lsr
        clc
        adc #100
        sta $d001

        rts
```

### Following a Path - Waypoint Navigation

Define waypoints and move between them:

```text
follow_path:
        ; Get current waypoint
        ldx waypoint_index
        lda waypoints_x,x
        sta target_x
        lda waypoints_y,x
        sta target_y

        ; Move towards target
        lda $d000              ; Current X
        cmp target_x
        beq check_y
        bcc move_right_path
        dec $d000              ; Move left
        jmp check_y
move_right_path:
        inc $d000              ; Move right
```

This simple pathfinding moves one pixel at a time toward the target. It's not the shortest path (it moves diagonally by moving both X and Y), but it's predictable and smooth. Games like "Gauntlet" use similar waypoint systems for enemy patrol routes.

```text
check_y:
        lda $d001              ; Current Y
        cmp target_y
        beq reached_waypoint
        bcc move_down_path
        dec $d001              ; Move up
        rts
move_down_path:
        inc $d001              ; Move down
        rts

reached_waypoint:
        ; Next waypoint
        inc waypoint_index
        lda waypoint_index
        cmp #num_waypoints
        bne path_done
        lda #0                 ; Loop back
        sta waypoint_index

path_done:
        rts

waypoint_index: !byte 0
target_x:       !byte 0
target_y:       !byte 0

num_waypoints = 4
waypoints_x:    !byte 50, 200, 200, 50
waypoints_y:    !byte 60, 60, 180, 180
```

The waypoint data defines the path. Change these values, and the sprite follows a completely different route. You could read waypoints from level data, creating unique enemy patterns for each stage.

## Complete Demo Program

Here's a program showing multiple patterns simultaneously - this demonstrates how different movement types create visual variety:

```text
; Movement Patterns Demo
; Shows different sprite movement behaviors

*=$0801
        !byte $0b,$08,$0a,$00,$9e,$32,$30,$36,$31,$00,$00,$00

*=$080d
start:
        ; Setup screen
        lda #$00
        sta $d020
        sta $d021

        ; Setup 4 sprites with different patterns
        ldx #0
setup_sprites:
        lda #$80
        clc
        adc sprite_patterns,x
        sta $07f8,x            ; Sprite pointers

        lda sprite_colors,x
        sta $d027,x            ; Sprite colors

        txa
        asl                    ; X*2 for position registers
        tay
        lda sprite_start_x,x
        sta $d000,y            ; X positions
        lda sprite_start_y,x
        sta $d001,y            ; Y positions

        inx
        cpx #4
        bne setup_sprites

        lda #%00001111         ; Enable 4 sprites
        sta $d015
```

The setup loop demonstrates efficient sprite initialization. Using X as an index for data tables and Y for position registers (which are paired) is a common pattern. The `asl` instruction converts sprite number to register offset.

```text
main_loop:
        lda #250
wait:   cmp $d012
        bne wait

        ; Update each sprite
        jsr update_patrol
        jsr update_circle
        jsr update_bounce
        jsr update_wave

        jmp main_loop
```

Each update routine is independent - they don't know about each other. This modular design means you can mix and match movement patterns easily. Want a bouncing patrol? Combine the routines!

```text
update_patrol:
        ; Sprite 0 - horizontal patrol
        lda $d000
        clc
        adc patrol_dir
        sta $d000

        cmp #40
        beq reverse_patrol
        cmp #216
        bne patrol_done
reverse_patrol:
        lda patrol_dir
        eor #$fe
        sta patrol_dir
patrol_done:
        rts

update_circle:
        ; Sprite 1 - circular motion
        inc circle_angle
        lda circle_angle
        and #$3f
        tax

        lda sine_table,x
        lsr
        clc
        adc #128
        sta $d002              ; Sprite 1 X

        txa
        clc
        adc #16
        and #$3f
        tax
        lda sine_table,x
        lsr
        clc
        adc #100
        sta $d003              ; Sprite 1 Y
        rts

update_bounce:
        ; Sprite 2 - bouncing
        inc bounce_yvel

        lda $d005              ; Sprite 2 Y
        clc
        adc bounce_yvel
        sta $d005

        cmp #200
        bcc bounce_done

        lda #200
        sta $d005
        lda bounce_yvel
        eor #$ff
        lsr
        sta bounce_yvel
bounce_done:
        rts

update_wave:
        ; Sprite 3 - wave motion
        inc $d006              ; Move right

        lda $d006
        lsr
        lsr
        and #$3f
        tax
        lda sine_table,x
        lsr
        lsr
        clc
        adc #150
        sta $d007              ; Sprite 3 Y
        rts

; Data
patrol_dir:     !byte 1
circle_angle:   !byte 0
bounce_yvel:    !byte 0

sprite_patterns: !byte 0,1,2,3
sprite_colors:   !byte 2,5,7,3
sprite_start_x:  !byte 50,128,100,24
sprite_start_y:  !byte 80,100,50,150

; Sine table
sine_table:
        !byte 128,140,152,164,175,185,195,203
        !byte 211,217,222,226,229,231,232,232
        !byte 232,230,228,224,220,214,208,201
        !byte 193,185,176,167,157,147,137,127
        !byte 117,107,97,87,78,69,61,53
        !byte 46,40,34,29,25,22,20,19

; Sprite data would go here at $2000, $2040, $2080, $20C0

; (Sprite graphics data)
```

## Tips for Great Movement

### Smoothness is Key

- Always sync with raster for flicker-free motion
- Use small increments (1-2 pixels)
- Consider sub-pixel precision for very smooth motion

### Add Personality

- Vary speeds for different characters
- Add pauses or hesitation
- Mix patterns (patrol that occasionally jumps)

### Performance

- Pre-calculate complex paths
- Use lookup tables for trigonometry
- Keep movement code efficient

## Common Issues

### "Movement is jerky"

- Ensure raster sync is working
- Check for inconsistent frame timing
- Reduce per-frame movement amount

### "Sprite gets stuck"

- Check boundary conditions carefully
- Ensure state changes happen correctly
- Add debug output to track state

### "Pattern doesn't loop smoothly"

- Verify start/end positions match
- Check angle wrapping logic
- Ensure smooth velocity transitions

## Quick Reference

### Common Movement Patterns

- **Patrol**: Back and forth between boundaries
- **Circle**: Sine/cosine for X/Y
- **Wave**: Sine applied to one axis
- **Bounce**: Velocity with gravity and dampening
- **Figure-8**: Two circles with phase shift
- **Path**: Waypoint to waypoint movement

### Useful Formulas

```text
; Circle: x = centerX + radius * sin(angle)
;         y = centerY + radius * cos(angle)

; Wave: y = centerY + amplitude * sin(x / wavelength)

; Bounce: velocity += gravity
;         position += velocity
;         if collision: velocity = -velocity * dampening
```

Remember: Movement is what brings games to life. Make it smooth, make it interesting, make it memorable!
