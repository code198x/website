# Enemy AI and Behaviors

Great enemies make great games. From the Pac-Man ghosts' unique personalities to the relentless Terminators in The Paradroid, enemy AI transforms simple mechanics into memorable encounters. On the C64, clever programmers created sophisticated behaviors within tight memory constraints, making enemies feel alive and unpredictable.

The secret wasn't complex algorithms—it was understanding player psychology. Games like Jumpman taught us that predictable patterns create fair challenge, while Impossible Mission showed how seemingly random behaviors could still follow logical rules. Each enemy type became a character with distinct personality traits encoded in just a few bytes.

## Enemy State Machines

State machines became the backbone of C64 AI programming because they're memory-efficient and easy to debug. Games like Defender used simple state systems to create complex-feeling behaviors—enemies would patrol, detect threats, chase players, and retreat when damaged. This approach let programmers build personality into enemies without consuming precious RAM.

The beauty of state machines lies in their predictability during development while appearing unpredictable to players. Each state encapsulates specific behavior, making code modular and bugs easier to isolate.

### Core Enemy Structure

C64 games typically used 16-byte enemy records—small enough to fit many in memory, large enough for rich behavior:

```asm
; Professional 16-byte enemy structure
; Used in games like Turrican and Metal Warrior
ENEMY_TYPE      = 0   ; Behavior type (0-15)
ENEMY_STATE     = 1   ; Current AI state
ENEMY_X         = 2   ; World X position
ENEMY_Y         = 3   ; World Y position
ENEMY_VX        = 4   ; Velocity X (-128 to +127)
ENEMY_VY        = 5   ; Velocity Y (-128 to +127)
ENEMY_HEALTH    = 6   ; Hit points remaining
ENEMY_TIMER     = 7   ; State/animation timer
ENEMY_TARGET_X  = 8   ; AI target X coordinate
ENEMY_TARGET_Y  = 9   ; AI target Y coordinate
ENEMY_SPRITE    = 10  ; Hardware sprite number
ENEMY_ANIM      = 11  ; Animation frame counter
ENEMY_FLAGS     = 12  ; Behavior flags (bits)
ENEMY_PATROL_X1 = 13  ; Left patrol boundary
ENEMY_PATROL_X2 = 14  ; Right patrol boundary
ENEMY_DATA      = 15  ; Type-specific data

; This structure was optimized for 6502 indexed addressing
; Each field accessible with single LDA/STA instructions

MAX_ENEMIES = 8
enemy_table:
    .res MAX_ENEMIES * 16

update_enemies:
    ldx #0
enemy_loop:
    txa
    asl
    asl
    asl
    asl             ; ×16
    tay

    ; Check if enemy active
    lda enemy_table+ENEMY_TYPE,y
    cmp #$FF
    beq next_enemy

    ; Update based on state
    lda enemy_table+ENEMY_STATE,y

    cmp #STATE_IDLE
    beq update_idle
    cmp #STATE_PATROL
    beq update_patrol
    cmp #STATE_CHASE
    beq update_chase
    cmp #STATE_ATTACK
    beq update_attack
    cmp #STATE_RETREAT
    beq update_retreat
    cmp #STATE_STUNNED
    beq update_stunned

next_enemy:
    inx
    cpx #MAX_ENEMIES
    bne enemy_loop
    rts

update_idle:
    jsr enemy_idle_behavior
    jmp next_enemy

update_patrol:
    jsr enemy_patrol_behavior
    jmp next_enemy

update_chase:
    jsr enemy_chase_behavior
    jmp next_enemy

update_attack:
    jsr enemy_attack_behavior
    jmp next_enemy

update_retreat:
    jsr enemy_retreat_behavior
    jmp next_enemy

update_stunned:
    jsr enemy_stunned_behavior
    jmp next_enemy
```

### State Machine Implementation

The state dispatcher became the heart of enemy AI systems. Games like Citadel and Thrust used similar architectures, switching between behaviors based on game conditions:

```asm
; Fast state dispatch using jump tables
; This technique was used in Bruce Lee and similar games
state_jump_lo:
    .byte <ai_idle, <ai_patrol, <ai_chase
    .byte <ai_attack, <ai_retreat, <ai_stunned

state_jump_hi:
    .byte >ai_idle, >ai_patrol, >ai_chase
    .byte >ai_attack, >ai_retreat, >ai_stunned

update_enemy_ai:
    ; Y register contains enemy offset
    lda enemy_table+ENEMY_STATE,y
    asl                     ; ×2 for table lookup
    tax

    lda state_jump_lo,x
    sta ai_jump+1
    lda state_jump_hi,x
    sta ai_jump+2

ai_jump:
    jsr $0000              ; Self-modifying jump
    rts
```

`★ Insight ─────────────────────────────────────`
Self-modifying code was essential on the C64. The jump table technique saves cycles by avoiding conditional branches, letting games update more enemies per frame. Professional C64 games often modified their own code for maximum performance.

## Patrol Behavior

Patrol routines formed the foundation of platformer AI. Games like Impossible Mission and Montezuma's Revenge created memorable enemies through simple but effective patrol patterns. The key was making movement feel natural, not robotic:

### Basic Boundary Patrol

This pattern appeared in countless C64 games—enemies bounce between set boundaries, creating predictable but engaging movement:

```asm
ai_patrol:
    ; Professional patrol implementation
    ; Used in games like Bruce Lee and Karateka

    ; Move according to current velocity
    lda enemy_table+ENEMY_X,y
    clc
    adc enemy_table+ENEMY_VX,y
    sta enemy_table+ENEMY_X,y

    ; Check left boundary
    cmp enemy_table+ENEMY_PATROL_X1,y
    bcc hit_left_boundary

    ; Check right boundary
    cmp enemy_table+ENEMY_PATROL_X2,y
    bcs hit_right_boundary

    ; Still within patrol area - check for threats
    jsr detect_player_presence
    bcc patrol_continue

    ; Player spotted! Switch to aggressive chase
    lda #STATE_CHASE
    sta enemy_table+ENEMY_STATE,y
    lda #180        ; Chase for 3 seconds
    sta enemy_table+ENEMY_TIMER,y

    ; Set hunt target to player position
    lda player_x
    sta enemy_table+ENEMY_TARGET_X,y
    lda player_y
    sta enemy_table+ENEMY_TARGET_Y,y

patrol_continue:
    rts

hit_left_boundary:
    ; Clamp to boundary
    lda enemy_table+ENEMY_PATROL_X1,y
    sta enemy_table+ENEMY_X,y

    ; Reverse direction with slight randomness
    jsr get_patrol_speed
    sta enemy_table+ENEMY_VX,y

    ; Brief pause at boundary (like real guards)
    lda #30
    sta enemy_table+ENEMY_TIMER,y
    rts

hit_right_boundary:
    ; Clamp to boundary
    lda enemy_table+ENEMY_PATROL_X2,y
    sta enemy_table+ENEMY_X,y

    ; Reverse direction
    jsr get_patrol_speed
    eor #$FF
    clc
    adc #1          ; Negate for leftward movement
    sta enemy_table+ENEMY_VX,y

    ; Brief pause
    lda #30
    sta enemy_table+ENEMY_TIMER,y
    rts

; Variable patrol speeds add personality
get_patrol_speed:
    lda enemy_table+ENEMY_TYPE,y
    and #$03
    tax
    lda patrol_speeds,x
    rts

patrol_speeds:
    .byte 1,1,2,1   ; Mostly slow, some faster guards

detect_player_presence:
    ; Advanced detection system inspired by Metal Gear
    ; Considers line of sight, not just distance

    ; First check if player is in detection radius
    lda player_x
    sec
    sbc enemy_table+ENEMY_X,y
    bpl abs_x_distance
    eor #$FF
    clc
    adc #1

abs_x_distance:
    cmp #48         ; Horizontal detection range
    bcs no_detection
    sta temp_x_dist

    lda player_y
    sec
    sbc enemy_table+ENEMY_Y,y
    bpl abs_y_distance
    eor #$FF
    clc
    adc #1

abs_y_distance:
    cmp #32         ; Vertical detection range
    bcs no_detection

    ; Player is close - check line of sight
    ; Simple version: check for walls between enemy and player
    jsr check_line_of_sight
    bcs no_detection    ; Wall blocks view

    ; Check if enemy is facing player
    lda enemy_table+ENEMY_VX,y
    bpl enemy_facing_right

    ; Enemy facing left
    lda player_x
    cmp enemy_table+ENEMY_X,y
    bcs no_detection    ; Player to right, enemy facing left
    jmp player_detected

enemy_facing_right:
    ; Enemy facing right
    lda player_x
    cmp enemy_table+ENEMY_X,y
    bcc no_detection    ; Player to left, enemy facing right

player_detected:
    ; Add detection delay for realism
    inc enemy_table+ENEMY_DATA,y
    lda enemy_table+ENEMY_DATA,y
    cmp #15         ; Takes 15 frames to "notice" player
    bcc no_detection

    sec             ; Player detected!
    rts

no_detection:
    ; Reset detection counter
    lda #0
    sta enemy_table+ENEMY_DATA,y
    clc             ; No detection
    rts

temp_x_dist: .byte 0
```

## Chase Behavior

Chase AI separates good games from great ones. Simple "move toward player" algorithms create boring, predictable enemies. Professional C64 games like The Last Ninja and Impossible Mission used sophisticated pursuit mechanics that felt intelligent and threatening.

### Intelligent Pursuit

The best chase routines don't just home in on the player—they predict where the player is going and cut them off:

```asm
ai_chase:
    ; Advanced pursuit AI from games like Paradroid
    ; Includes prediction and obstacle avoidance

    ; Decrease chase timer
    dec enemy_table+ENEMY_TIMER,y
    beq abandon_chase

    ; Predict player movement (lead the target)
    lda player_x
    clc
    adc player_vx       ; Add player velocity
    adc player_vx       ; Double for more lead time
    sta predicted_x

    lda player_y
    clc
    adc player_vy
    adc player_vy
    sta predicted_y

    ; Calculate chase vector to predicted position
    lda predicted_x
    sec
    sbc enemy_table+ENEMY_X,y
    bpl x_chase_positive

    ; Move left (with chase acceleration)
    lda enemy_table+ENEMY_VX,y
    sec
    sbc #1              ; Accelerate left
    cmp #$FE            ; Clamp to max speed
    bcs set_x_velocity
    lda #$FE            ; Max left speed
    jmp set_x_velocity

x_chase_positive:
    beq x_chase_done    ; Already at target X

    ; Move right (with chase acceleration)
    lda enemy_table+ENEMY_VX,y
    clc
    adc #1              ; Accelerate right
    cmp #3              ; Clamp to max speed
    bcc set_x_velocity
    lda #3              ; Max right speed

set_x_velocity:
    sta enemy_table+ENEMY_VX,y

x_chase_done:
    ; Same logic for Y axis
    lda predicted_y
    sec
    sbc enemy_table+ENEMY_Y,y
    bpl y_chase_positive

    ; Move up
    lda enemy_table+ENEMY_VY,y
    sec
    sbc #1
    cmp #$FE
    bcs set_y_velocity
    lda #$FE
    jmp set_y_velocity

y_chase_positive:
    beq y_chase_done

    ; Move down
    lda enemy_table+ENEMY_VY,y
    clc
    adc #1
    cmp #3
    bcc set_y_velocity
    lda #3

set_y_velocity:
    sta enemy_table+ENEMY_VY,y

y_chase_done:
    ; Apply movement with collision checking
    jsr move_enemy_with_collision

    ; Check if close enough for attack
    jsr check_attack_range
    bcc chase_continue

    ; Close enough - attack!
    lda #STATE_ATTACK
    sta enemy_table+ENEMY_STATE,y
    lda #45         ; Attack animation time
    sta enemy_table+ENEMY_TIMER,y

    ; Stop movement during attack
    lda #0
    sta enemy_table+ENEMY_VX,y
    sta enemy_table+ENEMY_VY,y

chase_continue:
    rts

abandon_chase:
    ; Lost target - return to patrol with memory
    lda #STATE_PATROL
    sta enemy_table+ENEMY_STATE,y

    ; Move toward last known player position
    lda enemy_table+ENEMY_TARGET_X,y
    sec
    sbc enemy_table+ENEMY_X,y
    bpl return_right
    lda #$FF
    jmp set_return_velocity

return_right:
    lda #1
set_return_velocity:
    sta enemy_table+ENEMY_VX,y

    lda #0
    sta enemy_table+ENEMY_VY,y
    rts

predicted_x: .byte 0
predicted_y: .byte 0

check_attack_range:
    lda player_x
    sec
    sbc enemy_table+ENEMY_X,y
    bpl check_attack_x
    eor #$FF
    clc
    adc #1

check_attack_x:
    cmp #8          ; Attack range
    bcs not_in_range

    lda player_y
    sec
    sbc enemy_table+ENEMY_Y,y
    bpl check_attack_y
    eor #$FF
    clc
    adc #1

check_attack_y:
    cmp #8
    bcs not_in_range

    sec             ; In attack range
    rts

not_in_range:
    clc
    rts
```

### Movement with Collision Avoidance

Professional C64 games needed enemies that could navigate complex levels. This required efficient pathfinding within the 6502's limitations:

```asm
move_enemy_with_collision:
    ; Try X movement first
    lda enemy_table+ENEMY_X,y
    clc
    adc enemy_table+ENEMY_VX,y
    sta temp_x

    ; Check X collision
    jsr check_collision_at_temp_x
    bcs x_blocked

    ; X movement is safe
    lda temp_x
    sta enemy_table+ENEMY_X,y
    jmp try_y_movement

x_blocked:
    ; X blocked - try sliding along wall
    lda #0
    sta enemy_table+ENEMY_VX,y

    ; Add upward bias to climb over obstacles
    lda enemy_table+ENEMY_VY,y
    sec
    sbc #1
    sta enemy_table+ENEMY_VY,y

try_y_movement:
    ; Try Y movement
    lda enemy_table+ENEMY_Y,y
    clc
    adc enemy_table+ENEMY_VY,y
    sta temp_y

    jsr check_collision_at_temp_y
    bcs y_blocked

    ; Y movement is safe
    lda temp_y
    sta enemy_table+ENEMY_Y,y
    rts

y_blocked:
    lda #0
    sta enemy_table+ENEMY_VY,y
    rts

temp_x: .byte 0
temp_y: .byte 0
```

## Smart Movement

The most memorable C64 enemies could navigate complex environments. Games like Impossible Mission and Paradroid created the illusion of intelligent robots through clever pathfinding algorithms optimized for the 6502 processor:

```asm
; Efficient pathfinding for C64 constraints
; Used in games like The Last Ninja and Paradroid
find_path_to_target:
    ; Convert world positions to 8×8 grid coordinates
    lda enemy_table+ENEMY_X,y
    lsr
    lsr
    lsr             ; Divide by 8
    sta enemy_grid_x

    lda enemy_table+ENEMY_Y,y
    lsr
    lsr
    lsr
    sta enemy_grid_y

    ; Target position (usually player)
    lda enemy_table+ENEMY_TARGET_X,y
    lsr
    lsr
    lsr
    sta target_grid_x

    lda enemy_table+ENEMY_TARGET_Y,y
    lsr
    lsr
    lsr
    sta target_grid_y

    ; Try direct path first (most common case)
    jsr attempt_direct_path
    bcs pathfinding_done

    ; Direct path blocked - use wall-following
    jsr follow_wall_navigation

pathfinding_done:
    rts

attempt_direct_path:
    ; Calculate desired movement direction
    lda target_grid_x
    sec
    sbc enemy_grid_x
    bpl check_x_positive

    ; Need to move left
    lda enemy_grid_x
    sec
    sbc #1
    jsr check_grid_walkable
    bcs x_path_blocked

    lda #$FE        ; Left velocity (faster than -1)
    sta enemy_table+ENEMY_VX,y
    jmp check_y_direction

check_x_positive:
    beq check_y_direction   ; Already at target X

    ; Need to move right
    lda enemy_grid_x
    clc
    adc #1
    jsr check_grid_walkable
    bcs x_path_blocked

    lda #2          ; Right velocity
    sta enemy_table+ENEMY_VX,y
    jmp check_y_direction

x_path_blocked:
    lda #0
    sta enemy_table+ENEMY_VX,y

check_y_direction:
    lda target_grid_y
    sec
    sbc enemy_grid_y
    bpl check_y_positive

    ; Need to move up
    lda enemy_grid_y
    sec
    sbc #1
    jsr check_grid_walkable
    bcs y_path_blocked

    lda #$FE        ; Up velocity
    sta enemy_table+ENEMY_VY,y
    sec             ; Direct path successful
    rts

check_y_positive:
    beq direct_path_success

    ; Need to move down
    lda enemy_grid_y
    clc
    adc #1
    jsr check_grid_walkable
    bcs y_path_blocked

    lda #2          ; Down velocity
    sta enemy_table+ENEMY_VY,y

direct_path_success:
    sec             ; Path found
    rts

y_path_blocked:
    lda #0
    sta enemy_table+ENEMY_VY,y
    clc             ; Direct path failed
    rts

; Wall-following algorithm for navigation around obstacles
; This creates believable "intelligent" movement
follow_wall_navigation:
    ; Determine which wall to follow based on target direction
    lda target_grid_x
    cmp enemy_grid_x
    bcc follow_left_wall
    bne follow_right_wall

    ; Same X - check Y
    lda target_grid_y
    cmp enemy_grid_y
    bcc follow_top_wall
    jmp follow_bottom_wall

follow_right_wall:
    ; Try: right, down, left, up (clockwise)
    jsr try_move_right
    bcs wall_nav_done
    jsr try_move_down
    bcs wall_nav_done
    jsr try_move_left
    bcs wall_nav_done
    jsr try_move_up

wall_nav_done:
    rts

; Movement attempt functions
try_move_right:
    lda enemy_grid_x
    clc
    adc #1
    jsr check_grid_walkable
    bcs cant_move_right

    lda #2
    sta enemy_table+ENEMY_VX,y
    lda #0
    sta enemy_table+ENEMY_VY,y
    sec
    rts

cant_move_right:
    clc
    rts

; Grid collision checking
check_grid_walkable:
    ; A = grid X, current_check_y = grid Y
    ; Returns carry clear if walkable

    ; Bounds check
    cmp #40         ; Screen width in tiles
    bcs not_walkable

    ; Calculate screen memory offset
    pha
    lda enemy_grid_y
    asl
    asl
    asl
    asl
    asl             ; ×32
    adc enemy_grid_y    ; Total ×40
    sta temp_offset
    pla
    clc
    adc temp_offset
    tax

    ; Check tile at position
    lda $0400,x
    cmp #$20        ; Space = walkable
    beq is_walkable
    cmp #$A0        ; Wall = not walkable
    beq not_walkable

    ; Default to walkable
is_walkable:
    clc
    rts

not_walkable:
    sec
    rts

; Variables
enemy_grid_x:   .byte 0
enemy_grid_y:   .byte 0
target_grid_x:  .byte 0
target_grid_y:  .byte 0
temp_offset:    .byte 0
```

## Group Behaviors

The most impressive C64 enemies worked together. Games like Defender and Thrust created memorable encounters through coordinated group tactics. These systems made enemies feel like they were communicating and planning attacks.

### Formation Flying

Defender's alien formations became a template for group movement in shoot-em-ups:

```asm
; Professional formation system
; Creates impressive coordinated movement like in R-Type
update_formation:
    ; Formation leader (usually enemy 0)
    lda enemy_table+ENEMY_X
    sta formation_center_x
    lda enemy_table+ENEMY_Y
    sta formation_center_y

    ; Update formation facing direction
    lda enemy_table+ENEMY_VX
    bmi formation_left

    lda #0          ; Formation facing right
    jmp set_formation_dir

formation_left:
    lda #1          ; Formation facing left

set_formation_dir:
    sta formation_direction

    ; Position followers in V-formation or diamond
    ldx #1          ; Skip leader
formation_loop:
    cpx #MAX_FORMATION_SIZE
    beq formation_done

    ; Calculate enemy array offset
    txa
    asl
    asl
    asl
    asl             ; ×16 bytes per enemy
    tay

    ; Check if this enemy is active
    lda enemy_table+ENEMY_TYPE,y
    cmp #$FF        ; Inactive enemy
    beq next_formation_member

    ; Calculate formation offset for this member
    txa
    dec             ; Member index (leader is 0)
    tax

    lda formation_offsets_x,x
    pha             ; Save X offset

    ; Apply formation direction
    lda formation_direction
    beq right_formation

    ; Left formation - negate X offset
    pla
    eor #$FF
    clc
    adc #1
    pha

right_formation:
    ; Set target position relative to leader
    pla
    clc
    adc formation_center_x
    sta enemy_table+ENEMY_TARGET_X,y

    lda formation_offsets_y,x
    clc
    adc formation_center_y
    sta enemy_table+ENEMY_TARGET_Y,y

    ; Move smoothly toward formation position
    jsr move_to_formation_target

next_formation_member:
    inx
    jmp formation_loop

formation_done:
    rts

; V-formation offsets (classic Defender style)
formation_offsets_x:
    .byte 12, -12, 20, -20, 28, -28
formation_offsets_y:
    .byte 8, 8, 16, 16, 24, 24

formation_center_x: .byte 0
formation_center_y: .byte 0
formation_direction: .byte 0
MAX_FORMATION_SIZE = 7

move_to_formation_target:
    ; Smooth formation movement with spring physics
    ; X offset relative to target
    lda enemy_table+ENEMY_TARGET_X,y
    sec
    sbc enemy_table+ENEMY_X,y

    ; Limit movement speed for smooth formations
    bpl positive_x_diff

    ; Negative difference (move left)
    cmp #$F8        ; Less than -8?
    bcs clamp_left_speed
    lda #$F8        ; Max left speed

clamp_left_speed:
    clc
    adc enemy_table+ENEMY_X,y
    sta enemy_table+ENEMY_X,y
    jmp check_y_formation

positive_x_diff:
    cmp #8          ; Greater than +8?
    bcc apply_x_diff
    lda #8          ; Max right speed

apply_x_diff:
    clc
    adc enemy_table+ENEMY_X,y
    sta enemy_table+ENEMY_X,y

check_y_formation:
    ; Same logic for Y axis
    lda enemy_table+ENEMY_TARGET_Y,y
    sec
    sbc enemy_table+ENEMY_Y,y

    bpl positive_y_diff
    cmp #$F8
    bcs clamp_up_speed
    lda #$F8

clamp_up_speed:
    clc
    adc enemy_table+ENEMY_Y,y
    sta enemy_table+ENEMY_Y,y
    rts

positive_y_diff:
    cmp #8
    bcc apply_y_diff
    lda #8

apply_y_diff:
    clc
    adc enemy_table+ENEMY_Y,y
    sta enemy_table+ENEMY_Y,y
    rts
```

### Swarm Intelligence

Swarm attacks create intense, overwhelming encounters. Games like Galaxian perfected this with coordinated dive-bomb attacks:

```asm
; Sophisticated swarm behavior
; Creates dynamic, organic-feeling group attacks
coordinated_swarm_attack:
    ; Check if swarm should activate
    lda player_aggression_level
    cmp #5          ; High aggression triggers swarm
    bcc individual_behavior

    ; Activate swarm mode for all enemies
    lda #60         ; Swarm duration
    sta swarm_timer

    ldx #0
swarm_activation_loop:
    cpx #MAX_ENEMIES
    beq swarm_active

    ; Get enemy offset
    txa
    asl
    asl
    asl
    asl
    tay

    ; Only swarm active enemies
    lda enemy_table+ENEMY_TYPE,y
    cmp #$FF
    beq next_swarm_member

    ; Switch to aggressive chase
    lda #STATE_CHASE
    sta enemy_table+ENEMY_STATE,y

    ; Set individual swarm target with offset
    lda player_x
    clc
    adc swarm_target_offsets_x,x
    sta enemy_table+ENEMY_TARGET_X,y

    lda player_y
    clc
    adc swarm_target_offsets_y,x
    sta enemy_table+ENEMY_TARGET_Y,y

    ; Boost speed for swarm attack
    lda enemy_table+ENEMY_TYPE,y
    ora #$80        ; Set swarm boost flag
    sta enemy_table+ENEMY_TYPE,y

next_swarm_member:
    inx
    jmp swarm_activation_loop

swarm_active:
    ; Swarm is active - manage coordination
    dec swarm_timer
    bne maintain_swarm

    ; Swarm time expired - return to normal behavior
    jsr deactivate_swarm

maintain_swarm:
    ; Dynamic target adjustment during swarm
    inc swarm_phase_timer
    lda swarm_phase_timer
    and #$1F        ; Update every 32 frames
    bne individual_behavior

    ; Adjust swarm targets to surround player
    jsr update_swarm_formation

individual_behavior:
    rts

; Swarm target offsets create encirclement pattern
swarm_target_offsets_x:
    .byte 0, 16, -16, 0, 12, -12, 8, -8
swarm_target_offsets_y:
    .byte -16, -8, -8, 16, 4, 4, -12, -12

; Variables
swarm_timer: .byte 0
swarm_phase_timer: .byte 0
player_aggression_level: .byte 0
```

## Boss AI

Boss encounters defined the most memorable C64 gaming moments. From the massive robots in Paradroid to the screen-filling demons in Turrican, boss AI combined multiple simple systems into epic battles. The key was creating distinct phases that escalated tension and required different strategies.

### Multi-Phase Boss Design

Professional boss AI uses phase transitions to maintain player engagement:

```asm
; Epic boss AI system inspired by Turrican and R-Type
BOSS_PHASE_INTRO    = 0  ; Dramatic entrance
BOSS_PHASE_NORMAL   = 1  ; Standard attacks
BOSS_PHASE_ANGRY    = 2  ; Faster, more aggressive
BOSS_PHASE_BERSERK  = 3  ; Desperate final phase
BOSS_PHASE_DEATH    = 4  ; Death animation

boss_max_health:    .byte 150
boss_health:        .byte 150
boss_phase:         .byte BOSS_PHASE_INTRO
boss_state_timer:   .byte 0
boss_attack_timer:  .byte 0
boss_invulnerable:  .byte 0

update_boss_ai:
    ; Handle invulnerability frames
    lda boss_invulnerable
    beq check_boss_phase
    dec boss_invulnerable

check_boss_phase:
    ; Determine phase based on health percentage
    lda boss_health
    beq boss_death_phase

    ; Calculate health percentage (simplified)
    cmp #112        ; 75% health
    bcs normal_phase
    cmp #75         ; 50% health
    bcs angry_phase
    cmp #37         ; 25% health
    bcs berserk_phase

    ; Less than 25% - final berserk mode
berserk_phase:
    lda #BOSS_PHASE_BERSERK
    jmp check_phase_change

angry_phase:
    lda #BOSS_PHASE_ANGRY
    jmp check_phase_change

normal_phase:
    lda #BOSS_PHASE_NORMAL
    jmp check_phase_change

boss_death_phase:
    lda #BOSS_PHASE_DEATH

check_phase_change:
    cmp boss_phase
    beq execute_current_phase

    ; Phase transition!
    pha             ; Save new phase
    jsr boss_phase_transition_effects
    pla
    sta boss_phase

    ; Reset phase timers
    lda #0
    sta boss_state_timer
    sta boss_attack_timer

execute_current_phase:
    ; Update timers
    inc boss_state_timer
    dec boss_attack_timer

    ; Execute phase-specific AI
    lda boss_phase
    cmp #BOSS_PHASE_INTRO
    beq boss_intro_behavior
    cmp #BOSS_PHASE_NORMAL
    beq boss_normal_behavior
    cmp #BOSS_PHASE_ANGRY
    beq boss_angry_behavior
    cmp #BOSS_PHASE_BERSERK
    beq boss_berserk_behavior
    cmp #BOSS_PHASE_DEATH
    beq boss_death_behavior
    rts

boss_intro_behavior:
    ; Dramatic entrance sequence
    lda boss_state_timer
    cmp #120        ; 2 seconds
    bcc intro_continue

    ; Intro complete - begin battle
    lda #BOSS_PHASE_NORMAL
    sta boss_phase
    lda #0
    sta boss_state_timer

intro_continue:
    ; Slow menacing movement
    jsr boss_entrance_movement
    rts

boss_normal_behavior:
    ; Standard attack pattern
    jsr boss_basic_movement

    lda boss_attack_timer
    bne normal_done

    ; Time to attack
    lda boss_state_timer
    and #$3F        ; Attack every 64 frames
    bne normal_done

    jsr boss_standard_attack
    lda #30
    sta boss_attack_timer

normal_done:
    rts

boss_angry_behavior:
    ; Faster, more aggressive
    jsr boss_aggressive_movement

    lda boss_attack_timer
    bne angry_done

    ; More frequent attacks
    lda boss_state_timer
    and #$1F        ; Attack every 32 frames
    bne check_special_angry

    jsr boss_rapid_fire
    lda #20
    sta boss_attack_timer
    jmp angry_done

check_special_angry:
    ; Occasional minion spawn
    lda boss_state_timer
    and #$7F        ; Every 128 frames
    bne angry_done

    jsr spawn_boss_minions

angry_done:
    rts

boss_berserk_behavior:
    ; Desperate final attacks
    jsr boss_erratic_movement

    ; Almost continuous attacks
    lda boss_attack_timer
    bne berserk_done

    lda boss_state_timer
    and #$0F        ; Attack every 16 frames
    bne check_screen_clear

    jsr boss_desperation_attack
    lda #15
    sta boss_attack_timer
    jmp berserk_done

check_screen_clear:
    ; Occasional screen-clearing attack
    lda boss_state_timer
    and #$FF        ; Every 256 frames
    bne berserk_done

    jsr boss_screen_nuke

berserk_done:
    rts

boss_death_behavior:
    ; Epic death sequence
    jsr boss_death_animation

    lda boss_state_timer
    cmp #240        ; 4 seconds of death throes
    bcc death_continue

    ; Boss defeated!
    jsr boss_defeated

death_continue:
    rts

boss_basic_movement:
    ; Sinusoidal movement pattern like R-Type bosses
    lda boss_state_timer
    lsr             ; Slow down movement
    tax

    ; Use sine table for smooth movement
    lda sine_wave_x,x
    clc
    adc #100        ; Center position
    sta boss_x

    lda sine_wave_y,x
    clc
    adc #80
    sta boss_y
    rts

boss_aggressive_movement:
    ; More erratic movement in angry phase
    lda boss_state_timer
    tax

    lda aggressive_pattern_x,x
    sta boss_x
    lda aggressive_pattern_y,x
    sta boss_y
    rts

boss_erratic_movement:
    ; Chaotic movement in berserk phase
    lda boss_state_timer
    and #$07
    bne continue_erratic

    ; Change direction randomly
    lda $D41B       ; Hardware random
    and #$07
    sec
    sbc #3          ; -3 to +4 range
    clc
    adc boss_vx
    sta boss_vx

    ; Clamp velocity
    cmp #$F8
    bcs clamp_vx
    cmp #8
    bcc apply_erratic_vx
clamp_vx:
    lda #3

apply_erratic_vx:
    sta boss_vx

continue_erratic:
    ; Apply velocity
    lda boss_x
    clc
    adc boss_vx
    sta boss_x

    ; Keep boss on screen
    cmp #240
    bcc erratic_y
    lda #240
    sta boss_x

erratic_y:
    lda boss_y
    clc
    adc boss_vy
    sta boss_y
    rts

boss_phase_transition_effects:
    ; Spectacular transition effects
    lda #90         ; Invulnerability during transition
    sta boss_invulnerable

    ; Screen shake
    lda #45
    sta screen_shake_intensity

    ; Flash effect
    lda #$01        ; White
    sta $D020
    sta $D021

    ; Clear all enemy bullets
    jsr clear_enemy_projectiles

    ; Dramatic sound effect
    jsr play_boss_phase_sound

    ; Spawn warning particles
    jsr spawn_phase_change_effects
    rts

; Movement pattern data
sine_wave_x:
    .byte 100,103,106,109,112,115,118,121
    .byte 124,127,130,133,136,139,142,145
    .byte 148,151,154,157,160,157,154,151
    .byte 148,145,142,139,136,133,130,127

sine_wave_y:
    .byte 80,82,84,86,88,90,92,94
    .byte 96,94,92,90,88,86,84,82
    .byte 80,78,76,74,72,74,76,78
    .byte 80,82,84,86,88,90,92,94

aggressive_pattern_x:
    .byte 120,125,115,130,110,135,105,140
    .byte 100,140,105,135,110,130,115,125

; Boss position variables
boss_x: .byte 120
boss_y: .byte 80
boss_vx: .byte 0
boss_vy: .byte 0
screen_shake_intensity: .byte 0
```

### Boss Attack Patterns

Different attacks for each phase create escalating difficulty:

```asm
boss_standard_attack:
    ; Phase 1: Basic projectile spread
    lda #3          ; 3 projectiles
    sta projectile_count

    lda boss_x
    sta projectile_spawn_x
    lda boss_y
    clc
    adc #16         ; Spawn below boss
    sta projectile_spawn_y

    ; Aim at player with slight spread
    jsr calculate_player_angle

    ldx #0
std_attack_loop:
    lda player_angle
    clc
    adc standard_spread,x
    jsr spawn_boss_projectile

    inx
    cpx projectile_count
    bne std_attack_loop
    rts

boss_rapid_fire:
    ; Phase 2: Rapid burst fire
    lda #5
    sta projectile_count

    jsr calculate_player_angle

    ldx #0
rapid_loop:
    lda player_angle
    jsr spawn_boss_projectile

    ; Small delay between shots
    ldy #3
rapid_delay:
    dey
    bne rapid_delay

    inx
    cpx projectile_count
    bne rapid_loop
    rts

boss_desperation_attack:
    ; Phase 3: Chaotic spray pattern
    lda $D41B       ; Random number of projectiles
    and #$07
    clc
    adc #4          ; 4-11 projectiles
    sta projectile_count

    ldx #0
desp_attack_loop:
    lda $D41B       ; Random angle
    jsr spawn_boss_projectile

    inx
    cpx projectile_count
    bne desp_attack_loop
    rts

boss_screen_nuke:
    ; Ultimate attack - fills screen with danger
    jsr play_warning_sound

    ; Flash screen red
    lda #$02
    sta $D020
    sta $D021

    ; Spawn projectiles in circular pattern
    ldx #16         ; 16 directions
nuke_loop:
    txa
    asl
    asl
    asl
    asl             ; ×16 for angle spread
    jsr spawn_boss_projectile

    dex
    bne nuke_loop

    ; Warning flash duration
    lda #30
    sta warning_flash_timer
    rts

; Data tables
standard_spread:
    .byte 252, 0, 4     ; -4, 0, +4 degrees

projectile_count: .byte 0
projectile_spawn_x: .byte 0
projectile_spawn_y: .byte 0
player_angle: .byte 0
warning_flash_timer: .byte 0
```

## Complete Enemy System

Here's how all these systems work together in a complete C64 game engine:

```asm
; Complete professional enemy AI system
; Techniques used in Turrican, Last Ninja, and Paradroid

* = $0801
    .byte $0C,$08,$0A,$00,$9E,$32,$30,$36,$31,$00,$00,$00

* = $080D
main_game_loop:
    jsr wait_for_raster

    ; Input and player always get priority
    jsr read_joystick_input
    jsr update_player_physics

    ; Distribute AI processing across frames
    lda frame_counter
    and #$03

    cmp #0
    beq update_enemy_batch_0
    cmp #1
    beq update_enemy_batch_1
    cmp #2
    beq update_boss_ai
    ; Frame 3: light processing frame

continue_main_loop:
    ; Always do collision detection
    jsr check_all_collisions
    jsr render_all_sprites
    jsr update_screen_effects

    inc frame_counter
    jmp main_game_loop

update_enemy_batch_0:
    ; Process enemies 0-3
    ldx #0
batch0_loop:
    jsr update_single_enemy
    inx
    cpx #4
    bne batch0_loop
    jmp continue_main_loop

update_enemy_batch_1:
    ; Process enemies 4-7
    ldx #4
batch1_loop:
    jsr update_single_enemy
    inx
    cpx #8
    bne batch1_loop
    jmp continue_main_loop

init_enemy_system:
    ; Professional initialization
    jsr clear_enemy_table
    jsr init_enemy_spawn_points
    jsr load_enemy_behavior_data
    jsr setup_boss_encounter

    ; Spawn initial wave
    lda current_level
    jsr spawn_level_enemies
    rts

clear_enemy_table:
    ; Efficiently clear 16-byte enemy records
    ldx #MAX_ENEMIES-1
    lda #$FF        ; Inactive marker

clear_loop:
    ; Clear entire 16-byte record
    txa
    asl
    asl
    asl
    asl             ; ×16
    tay

    ; Mark as inactive
    sta enemy_table+ENEMY_TYPE,y

    ; Clear critical fields
    lda #0
    sta enemy_table+ENEMY_STATE,y
    sta enemy_table+ENEMY_HEALTH,y
    sta enemy_table+ENEMY_TIMER,y

    dex
    bpl clear_loop
    rts

professional_spawn_enemy:
    ; A = enemy type, X = spawn X, Y = spawn Y
    ; Returns enemy index in A (or $FF if failed)

    pha             ; Save parameters
    txa
    pha
    tya
    pha

    ; Find available enemy slot
    jsr find_free_enemy_slot
    cmp #$FF
    beq spawn_failed

    ; A = free slot index
    tax

    ; Calculate 16-byte offset
    txa
    asl
    asl
    asl
    asl
    tay             ; Y = byte offset

    ; Initialize enemy from parameters
    pla             ; Y position
    sta enemy_table+ENEMY_Y,y
    pla             ; X position
    sta enemy_table+ENEMY_X,y
    pla             ; Enemy type
    sta enemy_table+ENEMY_TYPE,y

    ; Initialize from enemy type data
    tax             ; X = enemy type

    lda enemy_type_health,x
    sta enemy_table+ENEMY_HEALTH,y

    lda enemy_type_speed,x
    sta enemy_table+ENEMY_VX,y

    lda #STATE_PATROL
    sta enemy_table+ENEMY_STATE,y

    ; Set intelligent patrol boundaries
    jsr setup_patrol_area

    ; Assign sprite (with pooling)
    jsr assign_hardware_sprite

    ; Initialize AI-specific data
    jsr init_enemy_ai_data

    ; Return enemy index
    tya
    lsr
    lsr
    lsr
    lsr             ; Convert back to index
    rts

spawn_failed:
    ; Clean up stack
    pla
    pla
    pla
    lda #$FF        ; Failed
    rts

find_free_enemy_slot:
    ldx #0
find_slot_loop:
    cpx #MAX_ENEMIES
    beq no_slots_free

    ; Check if slot is inactive
    txa
    asl
    asl
    asl
    asl
    tay

    lda enemy_table+ENEMY_TYPE,y
    cmp #$FF
    beq slot_found

    inx
    jmp find_slot_loop

no_slots_free:
    lda #$FF
    rts

slot_found:
    txa             ; Return slot index
    rts

; Enemy type definitions
enemy_type_health:
    .byte 1,3,2,5,1,8,4  ; Health for each type

enemy_type_speed:
    .byte 1,2,1,1,3,1,2  ; Base speed for each type

check_all_collisions:
    jsr check_player_vs_enemies
    jsr check_bullets_vs_enemies
    jsr check_enemy_vs_environment
    rts

check_bullets_vs_enemies:
    ; Optimized collision detection
    ; Only check active enemies against active bullets

    ldx #0
bullet_enemy_loop:
    cpx #MAX_ENEMIES
    beq bullet_check_done

    ; Get enemy offset
    txa
    asl
    asl
    asl
    asl
    tay

    ; Skip inactive enemies
    lda enemy_table+ENEMY_TYPE,y
    cmp #$FF
    beq next_bullet_enemy

    ; Check against all active bullets
    jsr check_enemy_bullet_collision
    bcc next_bullet_enemy

    ; Hit confirmed! Apply damage
    jsr apply_enemy_damage

next_bullet_enemy:
    inx
    jmp bullet_enemy_loop

bullet_check_done:
    rts

apply_enemy_damage:
    ; Professional damage system
    ; Y = enemy offset

    dec enemy_table+ENEMY_HEALTH,y
    bne enemy_still_alive

    ; Enemy defeated!
    jsr enemy_death_sequence
    jsr award_kill_points
    jsr spawn_pickup_chance

    ; Mark as inactive
    lda #$FF
    sta enemy_table+ENEMY_TYPE,y

    ; Free hardware sprite
    jsr release_hardware_sprite

    rts

enemy_still_alive:
    ; Enemy damaged but alive
    lda #STATE_STUNNED
    sta enemy_table+ENEMY_STATE,y

    ; Stun duration based on enemy type
    lda enemy_table+ENEMY_TYPE,y
    and #$07
    clc
    adc #20         ; 20-27 frame stun
    sta enemy_table+ENEMY_TIMER,y

    ; Flash effect
    lda enemy_table+ENEMY_FLAGS,y
    ora #$80        ; Set flash bit
    sta enemy_table+ENEMY_FLAGS,y

    ; Damage sound
    jsr play_enemy_hit_sound
    rts

dynamic_difficulty_system:
    ; Adjust spawn rate based on player performance
    inc difficulty_timer
    lda difficulty_timer
    and #$3F        ; Every 64 frames
    bne diff_done

    ; Check player aggression level
    lda player_kill_streak
    cmp #5
    bcc normal_spawning

    ; Player is doing well - increase pressure
    inc enemy_spawn_rate

    ; Cap spawn rate
    lda enemy_spawn_rate
    cmp #8
    bcc normal_spawning
    lda #8
    sta enemy_spawn_rate

normal_spawning:
    ; Spawn enemies based on current rate
    lda $D41B       ; Random
    cmp enemy_spawn_rate
    bcs no_spawn

    jsr spawn_random_enemy

no_spawn:
diff_done:
    rts

update_single_enemy:
    ; X = enemy index to update
    ; Highly optimized single enemy update

    ; Calculate enemy offset
    txa
    asl
    asl
    asl
    asl
    tay

    ; Skip inactive enemies
    lda enemy_table+ENEMY_TYPE,y
    cmp #$FF
    beq enemy_update_done

    ; Update AI state machine
    jsr update_enemy_ai

    ; Update animation
    jsr update_enemy_animation

    ; Apply physics
    jsr apply_enemy_physics

    ; Update sprite position
    jsr update_enemy_sprite

enemy_update_done:
    rts

; Global game variables
frame_counter:      .byte 0
current_level:      .byte 1
enemy_spawn_rate:   .byte 3
player_kill_streak: .byte 0

; Boss system variables
MAX_ENEMIES = 12
enemy_table: .res MAX_ENEMIES * 16

; Player variables (referenced by AI)
player_x: .byte 100
player_y: .byte 150
player_vx: .byte 0
player_vy: .byte 0
```
