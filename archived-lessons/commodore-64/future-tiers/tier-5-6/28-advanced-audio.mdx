# Advanced Audio Programming

The Commodore 64's SID chip was more capable than its documentation suggested. Programmers discovered techniques that weren't in any manual - sample playback, filter programming, and synthesis tricks that defined the sound of 1980s gaming.

## What You'll Build

This lesson covers four major techniques:
1. **Digital sample playback** - Playing drums and speech through the volume register
2. **Filter programming** - Creating sweeps and resonant effects
3. **Music sequencing** - Building a pattern-based music engine
4. **Advanced synthesis** - Using sync and ring modulation for complex timbres

## Understanding the SID Architecture

The SID (6581/8580) provides three independent voices, each with:
- Four waveforms (triangle, sawtooth, pulse, noise)
- ADSR envelope control
- Individual frequency control

Plus shared resources:
- Programmable filter (low-pass, band-pass, high-pass)
- Ring modulation between voices
- Voice synchronization

### The Volume Register Technique

The volume register at $D418 does more than control volume - it outputs directly to the audio path. By rapidly changing this 4-bit value, you can play digitized samples:

```asm
; 4-bit sample playback
; Used in games like "Impossible Mission" for speech

SAMPLE_RATE = 50        ; Approximately 8kHz

play_sample:
    sei                 ; Disable interrupts for consistent timing
    
    ldy #0
sample_loop:
    lda sample_data,y   
    and #$0F           ; 4-bit resolution
    ora #$10           ; Keep filter enabled
    sta $D418          ; Output to DAC
    
    ; Precise timing for sample rate
    ldx #SAMPLE_RATE
timing_loop:
    dex
    bne timing_loop
    
    iny
    cpy sample_length
    bne sample_loop
    
    cli
    rts

; Example: Simple kick drum sample (4-bit values)
sample_data:
    .byte $F,$E,$D,$C,$B,$A,$9,$8
    .byte $7,$8,$9,$A,$B,$A,$9,$8
    .byte $7,$6,$5,$4,$3,$2,$1,$0
sample_length:
    .byte 24
```

This technique requires careful timing. The sample rate is determined by how quickly you update the volume register. Too fast and you waste CPU cycles; too slow and the audio quality suffers.

### Filter Programming

The SID's analog filter can dramatically shape your sounds. It's controlled by three registers:

```asm
; Filter setup and control
; $D415-D416: Cutoff frequency (11 bits)
; $D417: Resonance and voice routing
; $D418: Filter mode and volume

init_filter:
    ; Route voice 1 through filter
    lda #$01
    sta $D417          ; Bit 0 = Voice 1 routed
    
    ; Set filter type
    lda #$10           ; Low-pass filter
    ora #$0F           ; Maximum volume
    sta $D418
    
    ; Initial cutoff frequency
    lda #$40
    sta $D416          ; Cutoff high byte
    lda #$00
    sta $D415          ; Cutoff low bits
    rts

; Filter sweep effect
filter_sweep:
    ldx #$00
sweep_up:
    stx $D416          ; Update cutoff
    
    ; Small delay
    ldy #20
delay:
    dey
    bne delay
    
    inx
    cpx #$80
    bne sweep_up
    
sweep_down:
    dex
    stx $D416
    
    ldy #20
delay2:
    dey
    bne delay2
    
    cpx #$00
    bne sweep_down
    
    jmp filter_sweep   ; Continue sweep
```

## Building a Music Engine

Professional C64 games used pattern-based music systems, similar to modern tracker software. Here's a simplified but functional implementation:

```asm
; Pattern-based music player
; Organizes music as repeating patterns

; Constants
PATTERN_LEN = 16        ; Steps per pattern
TEMPO = 6              ; Ticks per step

; Note frequency table (partial)
freq_lo:
    .byte $17,$27,$39,$4B  ; C-0 to D#0
    .byte $5F,$74,$8B,$A3  ; E-0 to G-0
    .byte $BD,$D8,$F5,$14  ; G#0 to B-0
freq_hi:
    .byte $01,$01,$01,$01
    .byte $01,$01,$01,$01
    .byte $01,$01,$01,$02

; Simple song structure
song:
    .byte 0,0,1,0      ; Pattern sequence
    .byte 2,2,1,0
    .byte $FF          ; End marker

; Pattern data (note values)
pattern_0:
    .byte 0,0,0,0      ; C major arpeggio
    .byte 4,4,4,4      ; E
    .byte 7,7,7,7      ; G
    .byte 0,0,0,0      ; C

pattern_1:
    .byte 2,2,2,2      ; D minor arpeggio
    .byte 5,5,5,5      ; F
    .byte 9,9,9,9      ; A
    .byte 2,2,2,2      ; D

pattern_2:
    .byte 7,7,7,7      ; G major
    .byte 11,11,11,11  ; B
    .byte 2,2,2,2      ; D
    .byte 7,7,7,7      ; G

; Music player (call from interrupt)
play_music:
    ; Handle tempo
    dec tick_counter
    bne play_done
    lda #TEMPO
    sta tick_counter
    
    ; Get current pattern
    ldx song_pos
    lda song,x
    cmp #$FF
    bne continue_song
    
    ; Loop song
    ldx #0
    stx song_pos
    lda song,x
    
continue_song:
    ; Calculate pattern address
    asl
    asl
    asl
    asl
    tax
    
    ; Get note from pattern
    ldy step_pos
    lda pattern_0,x
    
    ; Play note
    tax
    lda freq_lo,x
    sta $D400          ; Voice 1 frequency
    lda freq_hi,x
    sta $D401
    
    ; Simple envelope
    lda #$21           ; Sawtooth
    sta $D404
    
    ; Advance position
    inc step_pos
    lda step_pos
    cmp #PATTERN_LEN
    bne play_done
    
    ; Next pattern
    lda #0
    sta step_pos
    inc song_pos

play_done:
    rts

; Variables
tick_counter: .byte TEMPO
step_pos:     .byte 0
song_pos:     .byte 0
```

## Advanced Synthesis Techniques

### Voice Synchronization

Synchronizing one voice to another creates complex waveforms that evolve over time:

```asm
; Voice sync for complex timbres
setup_sync:
    ; Voice 1: Audible output
    lda #$10
    sta $D401          ; Base frequency
    
    ; Voice 2: Sync source
    lda #$20           ; Different frequency
    sta $D408          ; Creates timbre
    
    ; Enable sync
    lda #$21           ; Sawtooth + sync
    sta $D404          ; Voice 1 syncs to Voice 2
    
    lda #$21           ; Sawtooth
    sta $D40B          ; Voice 2 normal
    
    rts
```

The frequency ratio between the two voices determines the timbre. Integer ratios (2:1, 3:1) create harmonic sounds, while non-integer ratios create metallic or bell-like tones.

### Ring Modulation

Ring modulation multiplies two waveforms together, creating sum and difference frequencies:

```asm
; Ring modulation setup
setup_ring:
    ; Voice 1: Carrier
    lda #$30
    sta $D400          ; Frequency
    lda #$10
    sta $D401
    
    ; Voice 3: Modulator
    lda #$25           ; Different frequency
    sta $D40E
    lda #$15
    sta $D40F
    
    ; Enable ring mod on Voice 1
    lda #$14           ; Triangle + ring mod
    sta $D404
    
    ; Voice 3 must be active
    lda #$11           ; Triangle
    sta $D412
    
    rts
```

## Putting It Together

Here's a complete program demonstrating these techniques:

```asm
    * = $0801
    ; BASIC stub
    !byte $0b,$08,$0a,$00,$9e
    !text "2061"
    !byte $00,$00,$00

    * = $080d
main:
    ; Initialize
    jsr clear_sid
    jsr setup_irq
    
    ; Display title
    ldx #0
show_title:
    lda title_text,x
    beq main_loop
    sta $0400,x
    lda #1
    sta $D800,x
    inx
    jmp show_title

main_loop:
    ; Check keyboard
    jsr $FFE4
    
    cmp #' '           ; Spacebar
    bne check_1
    jsr play_sample
    
check_1:
    cmp #'1'
    bne check_2
    jsr setup_filter
    
check_2:
    cmp #'2'
    bne check_end
    jsr setup_sync
    
check_end:
    jmp main_loop

title_text:
    !text "SID ADVANCED - SPACE=SAMPLE 1=FILTER 2=SYNC"
    !byte 0

clear_sid:
    ldx #$18
    lda #0
clear_loop:
    sta $D400,x
    dex
    bpl clear_loop
    rts

setup_irq:
    sei
    ; Set up raster interrupt
    lda #$7f
    sta $DC0D
    lda #$01
    sta $D01A
    lda #$80
    sta $D012
    lda #<irq
    sta $FFFE
    lda #>irq
    sta $FFFF
    cli
    rts

irq:
    pha
    txa
    pha
    tya
    pha
    
    ; Run music player
    jsr play_music
    
    ; Acknowledge IRQ
    lda #$ff
    sta $D019
    
    pla
    tay
    pla
    tax
    pla
    rti

; Include all routines from above
; ... (play_sample, filter_sweep, play_music, etc.)
```

## Technical Considerations

### CPU Usage

Audio routines consume CPU cycles that could be used for gameplay:
- Sample playback: 80-90% CPU at 8kHz
- Music player: 5-10% CPU with optimization
- Filter effects: 1-2% CPU

Plan your audio system based on available CPU time. Games with heavy sample playback often simplified graphics or gameplay during audio-intensive moments.

### Memory Usage

- Pattern data: ~64 bytes per pattern
- Sample data: 1 byte per sample (4-bit packed)
- Music engine: ~500 bytes of code

Compression techniques like pattern repetition and shared instrument definitions can significantly reduce memory usage.

## Historical Context

**Rob Hubbard** pioneered many SID techniques, including the use of the test bit to reset oscillators mid-cycle. His music for "Commando" and "International Karate" set the standard for C64 audio.

**Martin Galway**'s "Ocean Loader" demonstrated how rapid arpeggios could simulate multiple voices. The technique became standard in C64 music.

**Ben Daglish** showed how careful filter programming could create atmospheric soundscapes in "The Last Ninja" series, using the filter to simulate different instruments.

These programmers worked within severe limitations - 64KB total RAM, ~1MHz CPU, three voices - yet created audio that defined a generation of gaming.
