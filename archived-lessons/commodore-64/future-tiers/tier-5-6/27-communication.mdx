# Communication and Networking

In 1982, the idea of home computers talking to each other was revolutionary. The C64 came equipped with multiple communication ports, enabling everything from bulletin board systems to early multiplayer games. Today you'll learn the techniques that created the first online communities.

## What You'll Build

This lesson teaches you to:

1. **Connect two C64s** with a simple cable for direct communication
2. **Build a chat system** where users can type messages to each other
3. **Create a multiplayer game** with real-time player interaction
4. **Implement error checking** for reliable data transfer

These are the same techniques used by QuantumLink (later AOL), early BBSes, and pioneering multiplayer games.

## Understanding C64 Communication

The C64 provides several communication methods:

- **User Port**: 8-bit parallel I/O with handshaking
- **Serial Port**: For disk drives and printers
- **Expansion Port**: Direct bus access
- **RS-232**: Through the user port with appropriate signals

### The User Port

The user port is your gateway to custom communication. It provides:

- 8 parallel data lines (PB0-PB7)
- 2 handshaking lines (PA2 for output, FLAG2 for input)
- Direct CIA chip access for precise timing

User port pinout (relevant pins):

```
Pin 2  (PB0) - Data bit 0 / Serial data out
Pin 3  (PB1) - Data bit 1 / Serial data in
Pin 4  (PB2) - Data bit 2
Pin 5  (PB3) - Data bit 3
Pin 6  (PB4) - Data bit 4
Pin 7  (PB5) - Data bit 5
Pin 8  (PB6) - Data bit 6
Pin 9  (PB7) - Data bit 7
Pin 10 (PA2) - Handshake output
Pin B  (FLAG2) - Handshake input
```

## Building a Serial Link Cable

First, let's create a simple null-modem cable to connect two C64s:

```
C64 #1 User Port    <--->    C64 #2 User Port
Pin 2 (PB0/TxD)     ----->   Pin 3 (PB1/RxD)
Pin 3 (PB1/RxD)     <-----   Pin 2 (PB0/TxD)
Pin A (GND)         -------  Pin A (GND)
```

This three-wire connection enables bidirectional communication!

## Implementing Serial Communication

### Basic Bit-Bang Serial

Here's a complete serial communication system:

```asm
; Serial communication routines
; 1200 baud for reliability

; CIA 2 registers for user port
DD01 = $DD01    ; User port data
DD03 = $DD03    ; User port direction

; Timing constants (PAL)
BAUD_1200 = 820  ; CPU cycles per bit at 1200 baud

; Initialize serial communication
init_serial:
    lda DD03
    ora #$01        ; PB0 = output (TxD)
    and #$FD        ; PB1 = input (RxD)
    sta DD03

    ; Set idle state (mark)
    lda DD01
    ora #$01        ; TxD high
    sta DD01
    rts

; Send one byte serially
; Input: A = byte to send
send_byte:
    pha             ; Save byte

    ; Send start bit (0)
    lda DD01
    and #$FE        ; Clear PB0
    sta DD01
    jsr delay_bit

    ; Send 8 data bits
    pla
    pha
    ldx #8
send_loop:
    lsr             ; Get next bit
    pha
    bcc send_0

    ; Send 1
    lda DD01
    ora #$01
    jmp send_bit

send_0:
    ; Send 0
    lda DD01
    and #$FE

send_bit:
    sta DD01
    jsr delay_bit

    pla
    dex
    bne send_loop

    ; Send stop bit (1)
    lda DD01
    ora #$01
    sta DD01
    jsr delay_bit

    pla             ; Restore stack
    rts

; Receive one byte serially
; Output: A = received byte, C = error flag
receive_byte:
    ; Wait for start bit
    lda #$00
    sta recv_timeout+1
    sta recv_timeout

wait_start:
    lda DD01
    and #$02        ; Check PB1
    beq got_start   ; Start bit detected

    ; Timeout check
    inc recv_timeout
    bne wait_start
    inc recv_timeout+1
    bne wait_start

    ; Timeout - no data
    sec             ; Set error flag
    rts

got_start:
    ; Delay to middle of start bit
    jsr delay_half_bit

    ; Receive 8 data bits
    ldx #8
    lda #0
recv_loop:
    jsr delay_bit   ; Wait for next bit

    lda DD01
    and #$02        ; Read PB1
    beq recv_0

    ; Received 1
    sec
    jmp shift_in

recv_0:
    ; Received 0
    clc

shift_in:
    ror recv_data   ; Shift bit into byte
    dex
    bne recv_loop

    ; Wait for stop bit
    jsr delay_bit

    lda recv_data
    clc             ; Clear error flag
    rts

recv_data:    .byte 0
recv_timeout: .word 0

; Precise timing delays
delay_bit:
    ldy #>(BAUD_1200/13)
    ldx #<(BAUD_1200/13)
delay1:
    dex             ; 2 cycles
    bne delay1      ; 3 cycles
    dey             ; 2 cycles
    bne delay1      ; 3 cycles
    rts             ; 6 cycles

delay_half_bit:
    ldy #>(BAUD_1200/26)
    ldx #<(BAUD_1200/26)
delay2:
    dex
    bne delay2
    dey
    bne delay2
    rts
```

### Building a Chat System

Now let's create a simple chat program using our serial routines:

```asm
; Two-player chat system
; Type messages to send to the other C64!

    * = $0801
    ; BASIC stub
    !byte $0b,$08,$0a,$00,$9e
    !text "2061"
    !byte $00,$00,$00

    * = $080d
chat_main:
    ; Initialize
    jsr init_serial
    jsr clear_screen

    ; Show title
    ldx #0
show_title:
    lda title_msg,x
    beq setup_screen
    sta $0400,x
    lda #1
    sta $D800,x
    inx
    jmp show_title

setup_screen:
    ; Draw divider line
    ldx #0
    lda #$C0        ; Horizontal line
draw_divider:
    sta $0400+480,x
    lda #3          ; Cyan
    sta $D800+480,x
    inx
    cpx #40
    bne draw_divider

    ; Set cursor positions
    lda #0
    sta local_x
    sta remote_x
    lda #15         ; Local messages start here
    sta local_y
    lda #13         ; Remote messages above divider
    sta remote_y

chat_loop:
    ; Check keyboard
    jsr $FFE4       ; GETIN
    beq check_receive

    ; Got keystroke
    cmp #$0D        ; Return key?
    beq send_line

    ; Add to buffer and display
    ldx input_len
    cpx #38         ; Max line length
    bcs check_receive

    sta input_buffer,x
    jsr display_char_local
    inc input_len

    ; Echo character to other C64
    jsr send_byte

check_receive:
    ; Check for incoming data
    jsr receive_byte
    bcs chat_loop   ; No data or error

    ; Display received character
    cmp #$0D        ; Return from remote?
    beq remote_newline

    jsr display_char_remote
    jmp chat_loop

send_line:
    ; Send return character
    lda #$0D
    jsr send_byte

    ; New line locally
    lda #0
    sta local_x
    inc local_y
    lda local_y
    cmp #25
    bcc reset_input
    lda #15
    sta local_y

reset_input:
    lda #0
    sta input_len
    jmp chat_loop

remote_newline:
    lda #0
    sta remote_x
    dec remote_y
    lda remote_y
    cmp #1
    bcs chat_loop
    lda #13
    sta remote_y
    jmp chat_loop

; Display character in local area
display_char_local:
    pha
    ; Calculate screen position
    lda local_y
    jsr calc_line_addr
    ldy local_x
    pla
    sta (screen_ptr),y
    lda #1          ; White
    sta (color_ptr),y
    inc local_x
    rts

; Display character in remote area
display_char_remote:
    pha
    ; Calculate screen position
    lda remote_y
    jsr calc_line_addr
    ldy remote_x
    pla
    sta (screen_ptr),y
    lda #7          ; Yellow
    sta (color_ptr),y
    inc remote_x
    rts

; Calculate line address
; Input: A = line number
calc_line_addr:
    ; Multiply by 40
    sta temp
    asl
    asl
    asl             ; *8
    sta screen_ptr
    lda #0
    sta screen_ptr+1

    asl screen_ptr
    rol screen_ptr+1
    asl screen_ptr
    rol screen_ptr+1  ; *32

    lda temp
    asl
    asl
    asl             ; *8
    clc
    adc screen_ptr
    sta screen_ptr
    lda #0
    adc screen_ptr+1
    sta screen_ptr+1

    ; Add base addresses
    lda screen_ptr
    clc
    adc #<$0400
    sta screen_ptr
    lda screen_ptr+1
    adc #>$0400
    sta screen_ptr+1

    ; Color RAM
    lda screen_ptr
    sta color_ptr
    lda screen_ptr+1
    and #$03
    ora #$D8
    sta color_ptr+1
    rts

clear_screen:
    ldx #0
    lda #$20
clear_loop:
    sta $0400,x
    sta $0500,x
    sta $0600,x
    sta $0700,x
    inx
    bne clear_loop
    rts

; Variables
input_buffer: .res 40
input_len:    .byte 0
local_x:      .byte 0
local_y:      .byte 0
remote_x:     .byte 0
remote_y:     .byte 0
temp:         .byte 0
screen_ptr:   .word 0
color_ptr:    .word 0

title_msg:
    .text "C64 CHAT - TYPE TO SEND MESSAGES!"
    .byte 0
```

## Advanced: Packet-Based Protocol

For more reliable communication, implement a packet protocol with error checking:

```asm
; Packet structure:
; [STX] [LEN] [SEQ] [DATA...] [CHECKSUM]
;
; STX = $02 (start of packet)
; LEN = data length (1-255)
; SEQ = sequence number for ordering
; DATA = actual payload
; CHECKSUM = XOR of all bytes

; Packet constants
STX = $02
ETX = $03
ACK = $06
NAK = $15

; Send packet with data
; Input: packet_data = data to send
;        packet_len = length of data
send_packet:
    ; Send header
    lda #STX
    jsr send_byte

    lda packet_len
    jsr send_byte
    pha             ; Save for checksum

    lda sequence_num
    jsr send_byte
    pha             ; Save for checksum

    ; Calculate and send data with checksum
    lda #0
    sta checksum

    ; Include length and sequence in checksum
    pla
    eor checksum
    sta checksum
    pla
    eor checksum
    sta checksum

    ; Send data bytes
    ldx #0
send_data:
    lda packet_data,x
    jsr send_byte
    eor checksum
    sta checksum
    inx
    cpx packet_len
    bne send_data

    ; Send checksum
    lda checksum
    jsr send_byte

    ; Wait for ACK/NAK
    jsr receive_byte
    bcs send_timeout

    cmp #ACK
    beq send_success

    ; NAK received - resend
    jmp send_packet

send_success:
    ; Increment sequence for next packet
    inc sequence_num
    clc
    rts

send_timeout:
    sec
    rts

; Receive packet
; Output: packet_data = received data
;         packet_len = length of received data
;         C = error flag
receive_packet:
recv_wait:
    ; Wait for STX
    jsr receive_byte
    bcs recv_timeout
    cmp #STX
    bne recv_wait

    ; Get length
    jsr receive_byte
    bcs recv_timeout
    sta packet_len
    sta checksum

    ; Get sequence
    jsr receive_byte
    bcs recv_timeout
    sta recv_sequence
    eor checksum
    sta checksum

    ; Receive data
    ldx #0
recv_data:
    jsr receive_byte
    bcs recv_timeout
    sta packet_data,x
    eor checksum
    sta checksum
    inx
    cpx packet_len
    bne recv_data

    ; Get checksum
    jsr receive_byte
    bcs recv_timeout

    ; Verify checksum
    cmp checksum
    beq recv_good

    ; Bad checksum - send NAK
    lda #NAK
    jsr send_byte
    jmp receive_packet

recv_good:
    ; Send ACK
    lda #ACK
    jsr send_byte
    clc
    rts

recv_timeout:
    sec
    rts

; Variables
packet_data:  .res 256
packet_len:   .byte 0
sequence_num: .byte 0
recv_sequence:.byte 0
checksum:     .byte 0
```

## Building a Multiplayer Game

Let's create a simple two-player competitive game using our communication system:

```asm
; Two-Player Pong via Serial Link
; Each player controls a paddle on their screen

    * = $0801
    ; BASIC stub
    !byte $0b,$08,$0a,$00,$9e
    !text "2061"
    !byte $00,$00,$00

    * = $080d
pong_main:
    jsr init_serial
    jsr init_game

game_loop:
    ; Read joystick
    lda $DC00
    and #$1F
    sta local_joy

    ; Send our paddle position
    lda paddle_y
    jsr send_byte

    ; Receive opponent's paddle
    jsr receive_byte
    bcs no_opponent
    sta opponent_y

no_opponent:
    ; Update local paddle from joystick
    lda local_joy
    and #$01        ; Up
    bne check_down
    dec paddle_y

check_down:
    lda local_joy
    and #$02        ; Down
    bne update_display
    inc paddle_y

update_display:
    ; Clear old positions
    jsr clear_sprites

    ; Draw paddles
    jsr draw_paddle_local
    jsr draw_paddle_opponent

    ; Update ball (simplified)
    jsr update_ball

    ; Small delay for game speed
    ldx #10
game_delay:
    ldy #0
delay_inner:
    dey
    bne delay_inner
    dex
    bne game_delay

    jmp game_loop

init_game:
    ; Set up screen
    lda #0
    sta $D020       ; Black border
    sta $D021       ; Black background

    ; Initial positions
    lda #12
    sta paddle_y
    sta opponent_y

    lda #20
    sta ball_x
    lda #12
    sta ball_y

    lda #1
    sta ball_dx
    sta ball_dy
    rts

draw_paddle_local:
    ; Draw at left side
    ldx paddle_y
    ldy #5          ; Paddle height
draw_local:
    lda #40
    jsr mult_a_x    ; Calculate line offset
    clc
    adc #<$0400
    sta screen_ptr
    lda #>$0400
    adc #0
    sta screen_ptr+1

    lda #$A0        ; Solid block
    ldy #0
    sta (screen_ptr),y

    inx
    dey
    bne draw_local
    rts

draw_paddle_opponent:
    ; Draw at right side
    ldx opponent_y
    ldy #5
draw_opp:
    lda #40
    jsr mult_a_x
    clc
    adc #<$0400+39  ; Right side
    sta screen_ptr
    lda #>$0400
    adc #0
    sta screen_ptr+1

    lda #$A0
    ldy #0
    sta (screen_ptr),y

    inx
    dey
    bne draw_opp
    rts

update_ball:
    ; Simple ball physics
    lda ball_x
    clc
    adc ball_dx
    sta ball_x

    cmp #1          ; Hit left paddle?
    bne check_right
    lda ball_y
    sec
    sbc paddle_y
    cmp #5
    bcs miss_left

    ; Bounce off left paddle
    lda #1
    sta ball_dx
    jmp update_y

miss_left:
    ; Reset ball
    lda #20
    sta ball_x

check_right:
    lda ball_x
    cmp #38         ; Hit right paddle?
    bne update_y

    lda ball_y
    sec
    sbc opponent_y
    cmp #5
    bcs miss_right

    ; Bounce off right paddle
    lda #$FF        ; -1
    sta ball_dx
    jmp update_y

miss_right:
    lda #20
    sta ball_x

update_y:
    lda ball_y
    clc
    adc ball_dy
    sta ball_y

    cmp #1
    bne check_bottom
    lda #1
    sta ball_dy

check_bottom:
    cmp #23
    bne draw_ball
    lda #$FF
    sta ball_dy

draw_ball:
    ; Draw ball at position
    lda ball_y
    tax
    lda #40
    jsr mult_a_x
    clc
    adc ball_x
    sta screen_ptr
    lda #0
    adc #$04
    sta screen_ptr+1

    lda #$51        ; Ball character
    ldy #0
    sta (screen_ptr),y
    rts

clear_sprites:
    ; Simple clear by overwriting with spaces
    ; (In a real game, track old positions)
    ldx #0
    lda #$20
cls_loop:
    sta $0400,x
    sta $0500,x
    sta $0600,x
    sta $06E8,x
    inx
    bne cls_loop
    rts

; Simple multiply A*X
mult_a_x:
    stx temp_x
    ldx #0
    stx temp_result
    stx temp_result+1
mult_loop:
    clc
    adc temp_result
    sta temp_result
    bcc no_carry
    inc temp_result+1
no_carry:
    dex
    cpx temp_x
    bne mult_loop
    lda temp_result
    rts

; Game variables
paddle_y:     .byte 12
opponent_y:   .byte 12
ball_x:       .byte 20
ball_y:       .byte 12
ball_dx:      .byte 1
ball_dy:      .byte 1
local_joy:    .byte 0
temp_x:       .byte 0
temp_result:  .word 0
```

## RS-232 and Modem Communication

The C64 can implement standard RS-232 for modem communication:

```asm
; RS-232 configuration for user port
; Requires level converter for true RS-232 voltages

; RS-232 signals on user port:
; Pin 2  - TxD (Transmit Data)
; Pin 3  - RxD (Receive Data)
; Pin 4  - RTS (Request To Send)
; Pin 5  - DTR (Data Terminal Ready)
; Pin 6  - DCD (Data Carrier Detect)
; Pin 7  - DSR (Data Set Ready)
; Pin 8  - CTS (Clear To Send)

init_rs232:
    ; Set up handshaking signals
    lda DD03
    ora #$15        ; RTS, DTR, TxD outputs
    and #$C2        ; Others inputs
    sta DD03

    ; Assert DTR and RTS
    lda DD01
    ora #$14        ; Set RTS and DTR high
    and #$FE        ; TxD idle high
    sta DD01
    rts

; Check modem status
check_modem:
    lda DD01
    and #$40        ; Check DCD
    beq carrier_detected

    ; No carrier
    lda #0
    rts

carrier_detected:
    lda #1
    rts
```

## Historical Context

The techniques you've learned powered:

**Bulletin Board Systems (BBSes)**: By 1985, thousands of C64-based BBSes operated worldwide. SysOps (System Operators) ran these from their bedrooms, creating the first online communities. Software like C-Net and Color 64 BBS turned C64s into multi-user systems.

**QuantumLink**: Launched in 1985, Q-Link was an online service exclusively for C64 users. It offered email, chat rooms, games, and downloads - essentially a proto-internet. It later evolved into America Online (AOL).

**Multiplayer Gaming**: Games like "Modem Wars" (1988) let players compete via modem. "NetWars" supported up to 4 players via null-modem cables. These games pioneered concepts later used in modern online gaming.

**Terminal Software**: Programs like "NovaTerm" and "CCGMS" turned the C64 into a powerful terminal, supporting file transfers (XMODEM, YMODEM), ANSI graphics, and speeds up to 9600 baud with special cartridges.

## Tips for Reliable Communication

1. **Always include timeouts** - Don't wait forever for data
2. **Add packet headers** - Identify data types
3. **Implement retransmission** - Handle lost data
4. **Use checksums** - Detect corruption
5. **Buffer management** - Handle data bursts
6. **State synchronization** - Keep both sides in sync
