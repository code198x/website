When a game ends, players should not have to type RUN again. A "Play again?" prompt lets them start a fresh game immediately. This unit replaces the STOP commands with a jump to a replay routine.

## How It Works

**Lines 1380-1390** in the win-by-elimination check now jump to `GO TO 1950` instead of STOP. The same change applies to lines 1480-1485 in the no-moves check.

**Lines 1950-1990** form the replay routine. After displaying the win message and sound:

1. **Line 1960** prints "Play again? (Y/N)"
2. **Line 1970** waits for a keypress with `PAUSE 0`
3. **Line 1975** reads the key with `INKEY$`
4. **Line 1980** checks for "Y" or "y". If yes, `GO TO 10` restarts the entire program from the beginning, reinitialising the board, clearing the screen, and starting fresh.
5. **Line 1990** stops the program if the player presses anything else.

## GO TO 10: Full Reset

Jumping to line 10 re-executes the initialisation: `BORDER 0: PAPER 0: INK 7: CLS`. This clears the screen, reinitialises all variables, and DIMensions the array fresh. The game starts from scratch with no leftover state from the previous round.

This is the simplest form of game reset. More sophisticated approaches would preserve settings or keep a running score across games. But for draughts, where each game is independent, a full restart is clean and correct.

## PAUSE and INKEY$

`PAUSE 0` waits indefinitely until a key is pressed. `INKEY$` then reads which key it was. This two-step process (wait, then read) ensures we capture the correct keypress. Using INPUT here would require the player to press Enter, which feels wrong for a simple yes/no question.

## Try This

**Play multiple games.** Win a game, press Y, and confirm the board resets correctly. All 24 pieces should be back in their starting positions.

**Add a score tracker.** Before resetting, save the winner in a variable. Display a running score across multiple games: "Player 1: 2 wins, Player 2: 1 win".
