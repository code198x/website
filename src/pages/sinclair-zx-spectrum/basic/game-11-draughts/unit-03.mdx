## How It Works

**Line 30** calls `GO SUB 400` to fill the board array with starting positions, exactly as we did in unit 1.

**Lines 40-50** draw the board first, then the pieces on top. The order matters: the board fills every square with colour, then the pieces overwrite the dark squares where they belong.

**Lines 610-680** loop through the array. If `b(r,c) = 0`, the square is empty and we skip it with `GO TO 660`. If it holds 1, we print a red "o". If it holds 2, a green "o". The same PRINT AT formula places each piece on the correct screen position.

## Mapping Array to Screen

The board array and the screen are two separate things. The array stores numbers. The screen shows colours and characters. The draw pieces subroutine is the bridge between them. It reads each array cell and translates the value into a visual:

- **0** = skip (the square is empty, the board background shows through)
- **1** = red "o" (INK 2)
- **2** = green "o" (INK 4)

This separation is important. When we later move a piece, we change the array values and then call the draw routine. The screen always reflects the array, never the other way around.

## Try This

**Use a different character.** Replace "o" with "*" or a block character like CHR$(143). Some characters look better than others as draughts pieces.

**Remove one player.** Comment out the lines that set up Player 2 in the init subroutine. Run the program and see Player 1 alone on the board. This helps you spot any drawing bugs when one side of the board is empty.
