Error messages have been appearing on line 15 of the screen, but they sometimes linger from a previous attempt. This unit adds a dedicated message-clearing subroutine that runs before each new message, keeping the status area tidy.

## The Program

<CodeFromFile src="sinclair-zx-spectrum/basic/game-11-draughts/unit-27/messages.bas" />

## How It Works

**Lines 1900-1920** form a simple clear-message subroutine. It prints 30 spaces at row 15, column 1, then returns. Every error message now calls `GO SUB 1900` before printing the new message.

**Line 95** calls `GO SUB 1900` at the start of each turn to clear any leftover messages from the previous turn.

Throughout the validation code (lines 856, 870, 910, 920, 930, 970, 975, 980, 990, and the capture checks), each error condition now calls `GO SUB 1900` before displaying its message. This guarantees the old message is wiped before the new one appears.

## Screen Region Management

The Spectrum screen is 32 columns by 24 rows. Without careful management, text from different parts of the program overlaps and old messages persist. By dedicating row 15 to error messages and always clearing it before writing, we keep the display predictable.

The screen layout is now:

| Row | Purpose |
|-----|---------|
| 1 | Column labels (A-H) |
| 3-10 | Board |
| 12 | Current player |
| 13 | Capture counts |
| 14 | Input prompt / chain info |
| 15 | Error messages |
| 17-18 | Win messages |

Each area has a single purpose. No area is written by two different parts of the code without clearing first.

## The Cost of Tidiness

Every error path now includes a subroutine call. This adds a small overhead to each invalid move. On the Spectrum, a GO SUB and RETURN take a few milliseconds. For a turn-based game where the player is typing input, this delay is imperceptible. The trade-off (clean display vs. tiny performance cost) is clearly worth it.

## Try This

**Remove the clearing.** Comment out the `GO SUB 1900` calls and make several invalid moves in a row. Watch how old messages contaminate new ones, especially when a short message follows a long one.

**Add a message for valid moves.** After a successful move, briefly display "OK" or the move notation on row 15 before clearing it on the next turn. This confirms the move was accepted.
