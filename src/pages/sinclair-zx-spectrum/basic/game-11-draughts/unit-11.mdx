A piece cannot land on a square that already holds another piece, whether friendly or enemy. This check catches moves that pass the diagonal and direction checks but target an occupied square.

## How It Works

**Line 975** checks the destination square in the board array. If `b(v,u)` is not zero, something is already there. It does not matter whether the piece belongs to the current player or the opponent. No piece can land on an occupied square during a simple move.

This check sits between the diagonal/direction checks and the move execution. The order of validation is:

1. Source has player's piece (line 910-930)
2. Move is one square diagonally (line 960-970)
3. Destination is empty (line 975) - **new**
4. Move is forward (lines 980-990)

## Why This Check Matters

Without the occupied square check, a piece could move on top of another piece. The array would overwrite the existing value, effectively deleting a piece from the game. The screen would show the new piece but the old one would vanish without being captured.

This is a data integrity issue. Every validation check protects the board array from entering an invalid state. Captures have their own mechanism (unit 12), with explicit rules about what happens to the jumped piece. A simple move should never destroy a piece.

## Layered Checks as a Pattern

By now, the validation subroutine has five checks in sequence. Each one either rejects the move (jumping back to the input prompt) or falls through to the next check. This is the standard pattern on the Spectrum: a cascade of `IF condition THEN GO TO error`. No ELSE needed. Each check is independent and testable.

## Try This

**Test the check.** Try moving a piece to a square occupied by a friendly piece (e.g. moving one of your back-row pieces forward to a square in the second row that already has a piece). The "Square occupied" message should appear.

**Test with an enemy piece.** Try moving one square diagonally to land on an opponent's piece. This should also show "Square occupied" - the move is one square, not two, so it is not a capture.
