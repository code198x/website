The validation is in place. Now we execute the move. The board array updates, the screen redraws, and the turn switches to the other player. For the first time, two players can actually take turns moving pieces.

## How It Works

**Line 1010** copies the piece value from the source to the destination: `LET b(v,u) = b(q,p)`. Whatever was at the source square is now at the destination.

**Line 1020** clears the source: `LET b(q,p) = 0`. The piece has moved. The source is empty.

**Line 1030** clears the old position on screen by printing a space with PAPER 0.

**Lines 1040-1050** draw the piece at its new position, using the correct colour based on which player is moving.

**Line 1060** plays a short click sound to confirm the move.

**Lines 1070-1080** switch the turn. If `t = 1`, set it to 2 and return. Otherwise, set it to 1.

## The Game Loop

Look at lines 80-140. This is the main game loop:

1. **Line 90:** Display whose turn it is
2. **Line 100:** Read the player's move
3. **Line 110:** Validate the source square
4. **Line 120:** Check the move is valid
5. **Line 130:** Execute the move and switch turns
6. **Line 140:** Jump back to the start

`GO TO 80` loops forever. Each pass through the loop is one player's turn. The game runs until we add a win condition later.

## Array First, Screen Second

The move updates the array before touching the screen. This matters. The array is the truth. The screen is just a reflection of that truth. If you update the screen first and the array second, you risk the two getting out of sync, especially when errors or edge cases arise.

## Try This

**Play several turns.** Move pieces back and forth between the two players. Confirm the turn switches correctly and pieces appear in the right positions.

**Watch the turn indicator.** Does "Player 1 (Red)" and "Player 2 (Green)" alternate correctly? If a move is rejected by validation, the turn should not switch.
