Draughts pieces move diagonally. Not horizontally, not vertically, not in an L-shape. A valid move changes both the row and column by exactly one. This unit adds the diagonal check using absolute differences.

## How It Works

**Line 960** calculates two values: `e` is the absolute difference between the source and destination columns, and `f` is the absolute difference between the rows. For a diagonal move of one square, both `e` and `f` must equal 1.

**Line 970** rejects the move if either difference is not 1. A horizontal move would have `f = 0`. A vertical move would have `e = 0`. A two-square jump would have `e = 2` and `f = 2`. Only `e = 1` and `f = 1` passes.

## Why ABS

The `ABS` function returns the absolute value - it strips the sign. A piece at column 3 moving to column 4 gives `4 - 3 = 1`. A piece at column 4 moving to column 3 gives `3 - 4 = -1`. We do not care about the direction yet (that comes in unit 9), only the distance. ABS makes both cases equal 1.

Without ABS, we would need separate checks for each direction: left-forward, right-forward, left-backward, right-backward. ABS reduces four cases to one.

## The Geometry of Diagonals

On a grid, a diagonal move changes both coordinates by the same amount. One square diagonally means both differences are 1. Two squares diagonally (a capture jump) means both differences are 2. Later, when we add captures, we will check for `e = 2` and `f = 2` as well.

This is a general pattern in grid-based games. Any diagonal relationship can be detected by comparing the absolute differences of coordinates.

## Try This

**Test non-diagonal moves.** Try moving a piece horizontally (A3 B3) or vertically (A3 A4). Confirm the error message appears. Then try a valid diagonal move (A3 B4).

**Allow two-square moves.** Change the check to accept `e = 2` and `f = 2` as well. This will be needed for captures later, but for now it shows how the same formula scales.
