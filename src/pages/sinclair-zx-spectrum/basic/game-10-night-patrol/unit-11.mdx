One guard is a puzzle. Two guards are a challenge. Each follows its own patrol route, and you need to find the gap where neither can see you. Parallel arrays track positions and routes for both guards.

## How It Works

**Lines 70-80** create the guard arrays. `DIM y(2)` and `DIM z(2)` hold row and column positions for each guard. `DIM q(2)` tracks each guard's position in its route string. `DIM f$(2, 1)` stores each guard's current facing direction.

**Lines 100-110** set starting positions. Guard 1 starts at row 3, column 5 facing south. Guard 2 starts at row 5, column 12 facing west.

**Line 120** reads both route strings from DATA. Guard 1 follows `d$`, guard 2 follows `b$`. Each guard has its own patrol pattern.

**Lines 220-240** draw both guards in a `FOR` loop. `PRINT AT y(i) + 2, z(i) + 2; INK 2; "G"` draws each guard at its array-stored position.

**Lines 330-362** move both guards. The loop reads the current direction from the appropriate route string, updates the position, and advances the route counter. Each guard moves independently.

**Lines 380-384** check detection against both guards. If the player occupies the same cell as *either* guard, detection triggers.

## Parallel Arrays

Parallel arrays are arrays where the same index refers to the same object. `y(1)` and `z(1)` are guard 1's position. `q(1)` is guard 1's route position. The index number ties them together.

This is how you manage multiple enemies without duplicating code. The `FOR i = 1 TO n` loop processes every guard with the same logic. Adding a third guard would mean adding one more set of starting values — the loop code stays the same.

## Independent Routes

Each guard has its own route string. Guard 1 patrols north-south while guard 2 patrols east-west. The routes can be any length, any direction sequence. This creates complex overlapping patterns that the player must decode.

## Try This

**Crossing paths.** Design routes where both guards pass through the same corridor at different times. The player must time their crossing to avoid both.

**Three guards.** Change `n = 2` to `n = 3`, add `DIM` sizes to 3, and set up a third guard with its own route. The code barely changes.
