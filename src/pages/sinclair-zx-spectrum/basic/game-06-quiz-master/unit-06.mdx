## How It Works

**Nested loops (lines 30-210).** The outer loop (`FOR r`) advances through rounds. The inner loop (`FOR p`) alternates between players. Each player sees the same question.

**Array scoring (line 170).** `LET s(p) = s(p) + 1` increments the current player's score. When `p` is 1, it updates slot 1. When `p` is 2, it updates slot 2. One line handles both players.

**Winner detection (lines 290-310).** Three comparisons cover all cases: player 1 wins, player 2 wins, or a draw. Without arrays, you'd compare `a` and `b` — with arrays, you compare `s(1)` and `s(2)`. The pattern scales to any number of players.

## Arrays as Player State

This is why arrays exist. `s(p)` turns the player number into an index. All the game logic uses `p` — it never mentions "player 1" or "player 2" specifically. Change `DIM s(2)` to `DIM s(4)` and the inner loop to `FOR p = 1 TO 4`, and you have a four-player quiz without rewriting any logic.

## Try This

**Three players.** Change DIM to `s(3)` and the inner loop to `FOR p = 1 TO 3`. Add more DATA lines so each round has fresh questions. Everything else works unchanged.

**Show running totals.** After each player answers, print all scores so far. Use the array-printing loop from Unit 1.

## What You've Learnt

- **Arrays for players** — `s(p)` stores each player's score in one structure
- **Nested loops** — outer loop for rounds, inner loop for players
- **Scalable design** — change the DIM and loop bounds to add more players
- **Winner logic** — compare array elements to determine the outcome
