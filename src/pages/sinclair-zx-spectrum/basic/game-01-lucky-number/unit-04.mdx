You can store numbers, do arithmetic, and ask the player for input. But your program still can't make decisions. It does the same thing every time, no matter what the player types.

A guessing game needs to check: is the guess correct? If yes, say so. If not, say something different. That's what `IF/THEN` does.

## Checking a Guess

Type this program and run it:

<CodeFromFile src="sinclair-zx-spectrum/basic/game-01-lucky-number/unit-04/if-match.bas" />

The secret number is `7`. The program asks you to guess, then checks if you got it right.

Type `7` and press **ENTER**.

![Correct! printed on screen](/images/sinclair-zx-spectrum/basic/game-01-lucky-number/unit-04-making-decisions/if-correct.png)

The Spectrum prints `Correct!`. Here's what happened:

- **Line 10** — `LET n = 7` stores the secret number in `n`.
- **Line 20** — `INPUT "Guess the number: "; g` asks the player to guess. Their answer goes in `g`.
- **Line 30** — `IF g = n THEN PRINT "Correct!"` checks whether `g` equals `n`. If it does, it prints the message. If it doesn't, it does nothing — the whole line is skipped.

That last part is the key. `IF` checks a condition. `THEN` says what to do when the condition is true. If the condition is false, the Spectrum moves on to the next line as if line 30 didn't exist.

## When the Guess Is Wrong

Run the program again. This time type `3`.

Nothing happens. No message, just `0 OK`. The condition `g = n` was false (3 doesn't equal 7), so the `THEN` part was skipped. The program had nothing else to do, so it ended.

That's not great. The player guesses wrong and gets silence. Let's fix that.

## Handling Both Cases

On the Spectrum 48K, there's no `ELSE` keyword. You can't write `IF ... THEN ... ELSE ...` like some other computers. Instead, you use a second `IF` line that checks the opposite condition:

<CodeFromFile src="sinclair-zx-spectrum/basic/game-01-lucky-number/unit-04/if-wrong.bas" />

Run it and type `3`.

![Wrong! printed on screen](/images/sinclair-zx-spectrum/basic/game-01-lucky-number/unit-04-making-decisions/if-wrong.png)

Now the player gets a response either way:

- **Line 30** checks `IF g = n` — is the guess equal to the secret number? If yes, print "Correct!"
- **Line 40** checks `IF g <> n` — is the guess *not* equal to the secret number? If yes, print "Wrong!"

The `<>` symbol means "not equal to." It's the opposite of `=`. Exactly one of these two conditions is true for any guess, so exactly one message prints.

Run it again and type `7`. You get "Correct!" and no "Wrong!" — line 40's condition is false, so it's skipped.

## How IF/THEN Works

Every `IF/THEN` line follows the same pattern:

```
IF condition THEN action
```

The Spectrum checks the condition. If it's **true**, it runs the action. If it's **false**, it skips the entire line and moves to the next one.

The condition compares two values using `=` (equal) or `<>` (not equal). You'll meet more comparisons in the next unit.

The action can be any command — `PRINT`, `LET`, `GO TO` (you'll learn this soon), or anything else the Spectrum understands.

## Try This

**Change the secret number.** Edit line 10 to `LET n = 42`. Run the program and guess a few times. The logic works the same — only the secret number changed.

**Two-part message.** Change line 30 to `IF g = n THEN PRINT "Yes! The number was "; n`. Now the program tells you what the number was when you guess correctly.

**Password checker.** Try this: `LET p$ = "secret"` and `INPUT "Password: "; a$` and `IF a$ = p$ THEN PRINT "Access granted"`. You're comparing strings instead of numbers — it works the same way.

## What You've Learnt

- **IF/THEN** — checks a condition and runs an action only when it's true
- **`=` comparison** — checks whether two values are equal
- **`<>` comparison** — checks whether two values are not equal
- **No ELSE on the 48K** — use a second IF line to handle the opposite case
- **Skipping** — when the condition is false, the entire IF line is ignored
