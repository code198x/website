The reaction timer needs to wait before showing the word. If the word appeared instantly, there'd be no tension — no "get ready" moment. `PAUSE` adds that delay.

## PAUSE

<CodeFromFile src="sinclair-zx-spectrum/basic/game-02-countdown/unit-03/pause-simple.bas" />

Run it. "Wait for it..." appears, then nothing happens for two seconds, then "Go!" prints.

`PAUSE` takes one number: how long to wait, measured in **fiftieths of a second**. The Spectrum screen refreshes 50 times per second (PAL), so:

- `PAUSE 50` = 1 second
- `PAUSE 100` = 2 seconds
- `PAUSE 25` = half a second
- `PAUSE 1` = a fiftieth of a second (barely noticeable)

Why fiftieths? Because the Spectrum's internal clock ticks once per screen refresh. It's a hardware thing — the display drives the timing. You'll see this pattern in assembly language too, if you go that way later.

## A Countdown

Combine `PRINT`, `PAUSE`, and `BEEP` to build a proper countdown:

![3... 2... 1... Go!](/images/sinclair-zx-spectrum/basic/game-02-countdown/unit-03-ready-set/countdown.png)

Each number prints, the program waits one second, then the next number prints. After "Go!" it plays a half-second high-pitched beep. The CLS at the start gives you a clean screen.

This is the shape of the reaction timer taking form. Print something, wait, print something else. The player watches the countdown and gets ready.

## PAUSE and Keypresses

There's a detail worth knowing: `PAUSE` can be interrupted by a keypress. If the player presses a key during a `PAUSE`, the pause ends early and the program continues.

For the countdown, that's fine — if the player is impatient, the program moves on. But later, when you use `PAUSE` to build tension before the reaction word appears, you'll want to be aware that a fidgety player might skip the delay.

## Try This

**Slow countdown.** Change the PAUSE values to 100 (two seconds each). Notice how much slower it feels. Timing changes the mood.

**Fast countdown.** Try PAUSE 10 — a fifth of a second per number. It's a blur. Too fast to read.

**Dramatic pause.** Add a `PAUSE 150` (three seconds) between "1..." and "Go!" — build the tension.

## What You've Learnt

- **PAUSE n** — pauses for `n` fiftieths of a second (50 = one second)
- **Why fiftieths** — the Spectrum's timing is tied to its 50Hz screen refresh
- **Combining commands** — PRINT, PAUSE, and BEEP together create a timed sequence
- **Keypresses interrupt PAUSE** — pressing a key during a PAUSE ends it early
