The wait-for-keypress loop from Unit 5 spins until a key is pressed. But it doesn't know how *long* it waited. For a reaction timer, that's the whole point. You need to measure the gap between "Go!" and the keypress.

The trick: put a counter inside the loop.

## The Reaction Timer

<CodeFromFile src="sinclair-zx-spectrum/basic/game-02-countdown/unit-06/reaction.bas" />

![Reaction time displayed](/images/sinclair-zx-spectrum/basic/game-02-countdown/unit-06-how-fast-were-you/reaction.png)

Run it. "Get ready..." appears, then after two seconds, "Go!" The program waits for you to press a key. When you do, it prints your time.

The number isn't seconds — it's loop iterations. How many times the Spectrum ran through lines 60-80 before you pressed a key. A lower number means a faster reaction.

## How It Works

```basic
50 LET t = 0
60 IF INKEY$ <> "" THEN GO TO 90
70 LET t = t + 1
80 GO TO 60
```

Line 50 sets a counter `t` to zero. Then the loop begins:

1. **Line 60** — check if a key is pressed. If yes, jump out of the loop to line 90.
2. **Line 70** — no key pressed, so add 1 to the counter.
3. **Line 80** — go back to line 60 and check again.

Every time around the loop, `t` goes up by one. The Spectrum runs this loop hundreds of times per second, so `t` climbs fast. The moment a key is pressed, line 60's condition is true and the program jumps to line 90, which prints the time.

This is the same `LET t = t + 1` pattern you used for the guess counter in Lucky Number — but here it's counting loop iterations instead of player actions.

## What Do the Numbers Mean?

The number isn't in any standard unit. It's not milliseconds or seconds — it's "how many times BASIC could run three lines of code before you reacted." On a real Spectrum, each loop iteration takes roughly the same time, so the number is consistent and comparable. Lower is faster.

This is typical for BASIC timing. You don't get precise millisecond measurements — you get a relative number. That's enough for a game. You can compare your time to a friend's time, or try to beat your own best.

## Try This

**Vary the delay.** Change `PAUSE 100` to `PAUSE 200` (four seconds). Does a longer wait make you faster or slower? What about `PAUSE 25` (half a second) — can you react before you're ready?

**Display a message.** Add `IF t < 100 THEN PRINT "Lightning fast!"` after line 90 (make it line 95). If you react within 100 loop cycles, you get praised.

**Cheat test.** What happens if you hold a key down before "Go!" appears? Try it. The program detects the keypress immediately and your time is very low. In the final game, the random delay before the word appears will make cheating harder.

## What You've Learnt

- **Counter in a loop** — `LET t = t + 1` inside an `INKEY$` loop measures how long the player takes
- **Loop iterations as time** — the count isn't in seconds, but it's consistent and comparable
- **The reaction timer pattern** — PAUSE for delay, set counter to zero, spin the loop, print the result
- **Jump out of a loop** — `IF INKEY$ <> "" THEN GO TO` a line after the loop exits when a key is pressed
