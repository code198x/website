Battleships needs to track more state than any game so far. Each player has a grid of ships and a grid of shots they have fired. That is four 10x10 grids, each stored in its own array. Getting this data model right from the start makes everything else — placement, shooting, display — fall into place.

## How It Works

**Lines 10-40** dimension the four core arrays. `DIM a(10,10)` holds Player 1 ship positions. `DIM b(10,10)` holds Player 2 ship positions. `DIM c(10,10)` tracks where Player 1 has fired. `DIM d(10,10)` tracks where Player 2 has fired. Every element starts at 0, meaning empty water.

**Lines 50-70** set up the ship data. `DIM l(5)` stores ship lengths and `DIM n$(5,10)` stores ship names. The DATA statements list the five ships: Carrier (5), Battleship (4), Cruiser (3), Submarine (3), and Destroyer (2).

**Lines 80-120** read the ship data into the arrays using a FOR/NEXT loop and READ statements.

**Lines 130-170** print all the array names and ship data so you can see the data model is correctly loaded.

## The Four-Array Pattern

Why four arrays instead of two? In Draughts, both players see the same board. In Battleships, information is hidden. Player 1 needs to see their own ships but not Player 2 ships. When Player 1 fires a shot, the result goes into their tracking grid `c()`, not into the ship grid `a()`. The ship grids (`a` and `b`) record where ships actually sit. The tracking grids (`c` and `d`) record what each player has discovered.

- **a(r,c)** = Player 1 ships. Values 1-5 identify which ship occupies each cell.
- **b(r,c)** = Player 2 ships. Same encoding.
- **c(r,c)** = Player 1 tracking. Records hits and misses from shots Player 1 has fired.
- **d(r,c)** = Player 2 tracking. Same for Player 2 shots.
