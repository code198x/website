The arrays are set up. Now we need to see them. A battleships grid needs column letters A to J across the top and row numbers 1 to 10 down the side. Each cell displays a character that represents its contents — a dot for water, eventually other symbols for ships, hits and misses.

## How It Works

**Lines 20-30** print the column header. A space for the row number column, then `CHR$(64+c)` for each column from 1 to 10. `CHR$(65)` is "A", `CHR$(66)` is "B", and so on through `CHR$(74)` for "J".

**Lines 40-70** draw each row. The row number prints first, then the loop visits each cell. For now, every cell shows a dot character to represent empty water.

**Lines 80-90** use `PRINT AT` to position each cell character precisely on screen. The row offset (line 40) ensures the grid starts below the header.

## PRINT AT for Grids

`PRINT AT r,c` places text at an exact screen position. Row 0 is the top of the screen, row 21 is the bottom. Column 0 is the left edge, column 31 is the right. For a 10x10 grid with labels, we need 11 columns (1 for the row label plus 10 for cells) and 11 rows (1 for the column header plus 10 for cells). That fits comfortably in one half of the screen, leaving room for a second grid.

## CHR$ for Labels

`CHR$(64+c)` converts a number 1-10 into a letter A-J. This works because the Spectrum character set follows ASCII: code 65 is "A", 66 is "B", and so on. Adding 64 to the column number gives the right code. This same conversion will appear later when parsing coordinate input — going from letters back to numbers.

## Try This

**Add row number 10.** Row 10 is two digits wide, which shifts cells by one column. How do you handle this alignment? One approach: always print row numbers with a fixed width using `STR$` and spacing.

**Change the empty cell character.** Try `CHR$(127)` (copyright symbol) or `CHR$(143)` (a block graphic) instead of a dot. Which reads best as "water"?
