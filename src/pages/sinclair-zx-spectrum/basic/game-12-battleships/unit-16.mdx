## What You Built

Phase 1 delivers a working two-player battleships game. The main flow runs through three stages:

1. **Placement** — each player places five ships with validation
2. **Handover** — CLS and a prompt between players
3. **Shooting** — turns alternate, each firing one shot per turn

Each turn follows a clean sequence: display grids, accept input, validate coordinate, check tracking array, read ship array, update both arrays, play sound, show result, hand over.

## What Works

- Four 10x10 arrays for ships and tracking
- Grid display with column/row headers
- Colour-coded cells: blue water, grey ships, red hits, cyan misses
- Coordinate parsing with lowercase handling
- Ship placement with direction, bounds and overlap checks
- Placement display showing fleet layout
- Full fleet placement for both players
- Handover screens between turns
- Shot validation including duplicate check
- Hit/miss detection and array updates
- Sound effects for hits and misses
- Turn switching with the `3 - p` pattern

## What is Missing

The game has no concept of sinking. A ship can take five hits but the player is never told it sank. There is no fleet status display, no win condition, and no way to know when the game is over. Players must track sinking mentally and agree when someone has won. Phase 2 adds ship health, sunk detection, win conditions, and polish.

## Try This

**Play a complete game.** Two people, one keyboard. Fire shots until one side believes they have sunk everything. Keep a tally on paper. Is the game fun even without sunk detection?

**Look for rough edges.** Does the input ever crash on unexpected values? Is the handover clear enough? Are the grids readable? Make notes — Phase 2 will address many of these issues.
