A game that works in normal play can still break in unusual situations. Edge cases are the inputs and states that sit at the boundaries of what the program expects. Systematic testing finds these problems before players do. This unit walks through the testing process and fixes what it finds.

## How It Works

The code changes in this unit are fixes rather than features. Each fix addresses a specific edge case discovered during testing.

**Placement edge cases:**
- Place the Carrier vertically at A6. It occupies A6 through A10. The bounds check must use `y + l - 1 <= 10`, not `y + l <= 10` (off by one).
- Place all five ships in the same row horizontally: 5+4+3+3+2 = 17 cells, but the row only has 10. The overlap check catches this, but the error message should say why.
- Try to place a ship at J10 vertically. Length 2 would go to J11, which is off the grid. The bounds check catches it.

**Shooting edge cases:**
- Fire at every cell on the grid (100 shots). The game should not crash after shot 100 — it should detect the win or continue normally.
- Fire at A1 then a1. The lowercase handling must convert both to the same coordinate. Without the fix from Unit 27, these could be treated as different cells.

**Display edge cases:**
- Row 10 is two digits. If the grid drawing code assumes single-digit row numbers, column alignment breaks at row 10.
- When all five ships are sunk, the fleet status shows all names in red. The count should show "Ships remaining: 0" not a negative number.

## Testing Methodology

Effective testing follows a pattern:

1. **Boundaries** — test the minimum, maximum, and one beyond each
2. **Transitions** — test where one state becomes another (4 hits to 5 on a length-5 ship)
3. **Empty and full** — test with no ships placed and with the maximum possible
4. **Repetition** — do the same action many times (fire 50 shots in a row)
5. **Invalid input** — test every kind of bad data

## The Off-by-One Bug

The most common bug in grid games is off-by-one. Arrays indexed 1-10 with bounds checks using `<` instead of `<=` (or vice versa) silently exclude the last row or column. The fix is consistent: always use `<=` for upper bounds and `>=` for lower bounds when working with 1-indexed arrays.

## Try This

**Create a testing checklist.** Write down every edge case you can think of. Work through the list systematically. Mark each one as pass or fail. Fix the failures and retest.

**Try to crash the program.** Be creative with your input. Long strings, special characters, pressing BREAK during placement. A robust program handles all of these gracefully.
