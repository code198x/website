If you can take items, you need to drop them. DROP KEY places the silver key in the current room. The item reappears in the room description and can be taken again. Drop is the reverse of take — it changes the same two variables in the opposite direction.

## Reversing the Take

DROP sets `ic(i) = 0` (not carried) and `il(i) = r` (current room). The item now belongs to this room. It will show up in the room description next time it displays. The player can drop items anywhere — the key does not have to go back to the library.

## How It Works

**Lines 590-620** handle the DROP command. The code searches the item array for a matching name among carried items (`ic(i) = 1`). If found, it sets `ic(i) = 0` and `il(i) = r`, then prints "You put down the [item name]."

**Error cases** — if the player types DROP KEY but is not carrying the key, the game prints "You are not carrying that." If the item name does not match anything, "You do not have that."

**The room display** already handles dropped items correctly. The loop at lines 270-280 checks `il(i) = r` and `ic(i) = 0`. A freshly dropped item meets both conditions, so it appears in the room description immediately on the next display cycle.

**Items can accumulate.** The player can drop multiple items in the same room. The display loop prints one line per item. This means you can create item piles — useful for the ritual later, where all items must be in the same room.

## Try This

**Drop and recollect.** Take the key, carry it to a different room, drop it, leave, return, and take it again. Every step should work smoothly. The item system is now fully circular.

**Drop in every room.** Take an item and drop it in five different rooms, picking it up and moving each time. Confirm the item appears correctly in each room's description.

**Handle DROP with no item name.** What happens if the player just types "DROP"? Add a check for an empty noun and respond with "Drop what?"
