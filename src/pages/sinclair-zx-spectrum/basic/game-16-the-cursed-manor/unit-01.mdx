Over the next 64 units you will build The Cursed Manor — a text adventure with 20 rooms, six items, five frozen guests, a parser, autonomous NPCs, and a curse-breaking ritual. It is the largest program in this curriculum, and it starts here with a single room and a single prompt.

## The Scene

Every text adventure begins with arrival. The player reads a description, understands where they are, and types their first command. Before you build rooms, items, or puzzles, you need that fundamental loop: describe the world, read input, respond.

This first version does nothing with the input yet. It simply prints the opening text and waits. That is enough to establish the shape of the program.

## How It Works

**Lines 10-20** clear the screen and set the border and paper to black with white ink. The manor is a dark place — the colour scheme reflects that from the start.

**Lines 30-70** print the opening narration. Each PRINT statement adds a line of text. The empty PRINT on line 40 creates a blank line for visual breathing room.

**Lines 80-90** present the first room description — the entrance hall. This is what the player sees when they arrive.

**Line 100** uses INPUT to read a command from the player. The prompt `"What now? "` tells the player the game is waiting. Their input goes into `c$`.

**Line 110** loops back to the input prompt. No matter what the player types, the game asks again. This is the skeleton of the game loop — read input, do something, repeat. The "do something" part comes in later units.

## Try This

**Change the mood.** Alter the BORDER, PAPER, and INK values to try different colour schemes. Dark blue paper with cyan ink gives a cold, moonlit feel. Which combination best suits a cursed manor?

**Add more opening text.** Expand the arrival narration with details about the weather, the sound of the door closing behind you, or the smell of dust and old wood.

**Print the player input back.** After line 100, add `PRINT "You said: "; c$` before the loop. This confirms the game is reading input correctly — useful for debugging the parser later.
