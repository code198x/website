## How It Works

The complete program is structured as follows:

| Lines | Purpose |
|-------|---------|
| 1-4 | Variable name legend (REM) |
| 5-50 | Title sequence and instructions |
| 51-99 | Initialisation — arrays, item placement, guest data, flags |
| 100-199 | Data loading loop — read rooms, items, guests from DATA |
| 200-300 | Display routine — room name, illustration, description, contents, exits |
| 301-350 | Input and parser — read command, abbreviation expansion, synonym replacement, verb/noun split |
| 400-500 | Movement handlers — GO NORTH/SOUTH/EAST/WEST/UP/DOWN |
| 550-600 | Item handlers — TAKE, DROP |
| 630-700 | Utility commands — INVENTORY, LOOK, HELP, SCORE |
| 700-999 | Illustration subroutines — PLOT/DRAW for each room |
| 1000-1060 | Help screen |
| 1100-1300 | Command handlers — GO, TAKE, DROP, EXAMINE |
| 1300-1500 | Puzzle handlers — UNLOCK, ENTER combination |
| 1500-1700 | Special commands — READ, LIGHT, SAY |
| 1800-1960 | NPC interaction — TALK TO, GIVE TO |
| 2000-2100 | NPC turn system — loop, wake timers |
| 2100-2250 | NPC movement and actions |
| 2300-2400 | Distant events |
| 2400-2550 | Ending sequence and score display |
| 2600-2750 | Ambient events and cat behaviour |
| 9000-9200 | DATA — room definitions (name, description, exits) |
| 9200-9400 | DATA — synonyms, guest home rooms |
| 9400-9700 | DATA — NPC actions, dialogue, guest descriptions |
| 9800-9940 | DATA — ambient events, response alternatives |

**The gap between 2750 and 9000** is intentional. DATA statements live at the end of the program, separated from code by a wide margin. This makes it easy to find and edit data without disrupting code.

**Total line count** — the program is approximately 500-600 BASIC lines. This is large for a Spectrum BASIC program, but well within the machine's memory limits after optimisation.

## Try This

**Read the program from top to bottom.** Follow the flow: title, init, data loading, main loop, handlers, NPC system, data. Does the structure make sense?

**Check for orphaned lines.** Are there any GO SUB targets that are never called? Any IF branches that are unreachable? Orphaned code wastes memory.

**Add a final REM block.** At the end of the DATA section, add a REM with the date, version number, and a note: "The Cursed Manor — complete." This marks the program as finished.
