"I do not understand" is the laziest error message in text adventures. The player typed something — they deserve to know why it failed. Did they use a word the parser does not know? Try an action on the wrong object? Refer to something not present? Each case deserves a different response.

## Error Categories

There are four types of failure: unknown verb (the parser does not recognise the action), unknown noun (the object does not exist in the game), absent noun (the object exists but is not here), and impossible action (the object is here but the action does not apply). Each gets its own message.

## How It Works

**Lines 350-360** handle unknown verbs. After synonym replacement, the code checks whether the verb (first word) matches any known command. If not: "I do not know the word [verb]." This tells the player which word failed, not just that something went wrong.

**Lines 570-575** refine the TAKE errors. "You do not see a [noun] here" when the item exists but is elsewhere. "There is no [noun] in this game" when the item does not exist at all. The distinction matters — the first says "keep looking," the second says "stop trying."

**Lines 690-695** refine EXAMINE errors similarly. "You would need to be closer" when the object is in a different room. "You see nothing special" when examining something with no examine description (like a wall or floor).

**Lines 420-425** improve movement errors. "There is no door to the north" is better than "You cannot go that way." When a door is locked: "The door is locked" rather than the generic refusal. Each message gives the player information they can act on.

**Tone matters.** Error messages should never mock the player. "That is stupid" or "You cannot do that, fool" appears in old adventures but drives players away. Be helpful: explain what went wrong and hint at what might work.

## Try This

**Trigger every error.** Systematically test each error case: unknown verb, unknown noun, absent item, locked door, wrong direction. Read each message and ask: does this help the player understand what happened?

**Add a suggestion.** When the player types an unknown verb, suggest a similar known verb if one exists. "I do not know 'PUSH'. Did you mean 'TAKE'?" This is advanced but very helpful.

**Log failed commands.** Add a counter for error messages. If the player gets five errors in a row, automatically show the HELP text. Frustrated players need guidance, not more failures.
