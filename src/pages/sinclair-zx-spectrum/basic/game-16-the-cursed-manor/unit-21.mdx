TAKE and DROP handle items as objects. EXAMINE treats them as sources of information. When the player types EXAMINE KEY, a longer description appears — the key's shape, the engravings on it, what it might unlock. Examination is how players discover clues and understand the story.

## Examine Descriptions

Each item gets an examine description stored in `ix$(6,80)`. This is separate from the room listing ("There is a silver key here") — it is a close-up look at the object. The player can examine items they are carrying or items in the current room.

## How It Works

**Line 33** adds `DIM ix$(6,80)` for examine descriptions.

**Lines 86-87** set the examine description for the key: "A tarnished silver key with a crown engraved on the bow. It looks old — perhaps as old as the manor itself."

**Lines 670-700** handle the EXAMINE command. The code searches for the named item. If found and either carried (`ic(i) = 1`) or in the current room (`il(i) = r`), the examine description prints. Otherwise: "You do not see that here."

**Clue delivery** — examine descriptions are where you hide puzzle hints. The key's crown engraving hints at its importance. The lantern's description might mention it needs oil. The grimoire's description reveals partial ritual instructions. Every examine text does double duty: atmosphere and information.

## Try This

**Examine the key in both states.** Examine it in the library (on the floor) and after picking it up (in your inventory). Both should work — the player should not have to pick something up before looking at it closely.

**Write examine descriptions for atmosphere.** The description should reveal something the room listing does not. "There is a silver key here" tells the player it exists. "A tarnished silver key with a crown engraved on the bow" tells them it matters.

**Handle EXAMINE with no noun.** If the player types just "EXAMINE", respond with "Examine what?" This prevents a silent failure and guides the player toward proper syntax.
