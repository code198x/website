A room you cannot leave is a prison, not an adventure. This unit adds a second room and lets the player move between them. The command GO NORTH moves north; GO SOUTH moves south. Movement is the foundation of exploration.

## Two-Word Commands

The player types "GO NORTH". The program needs to check for this exact string. Later you will build a proper parser that splits input into verb and noun, but for now a direct string comparison gets movement working.

Each room stores which room lies in each direction. If there is no exit that way, the value is 0.

## How It Works

**Lines 100-130** now define two rooms. Each room has a name, description, and exit data. `n(r)` stores the room number to the north, `s(r)` stores south. A value of 0 means no exit in that direction.

**Lines 400-430** handle the GO NORTH command. If `c$ = "GO NORTH"` and `n(r) > 0`, the current room changes to `n(r)`. If the exit does not exist, the game prints "You cannot go that way."

**Lines 440-470** handle GO SOUTH in the same way, using `s(r)`.

**Line 500** loops back to the room display after processing the command. Every command eventually returns here.

The pattern is clear: check the command, check whether the action is possible, update the game state, and redisplay.

## Try This

**Add a third room.** Place a kitchen to the south of the entrance hall. Update the exit data so the entrance hall connects to both the corridor (north) and the kitchen (south).

**Handle unknown commands.** If the input does not match any known command, print "I do not understand that." This prevents silent failures when the player types something unexpected.

**Show available exits.** After the room description, print which directions are available: "Exits: north, south." Check each exit variable and only list the ones that are not zero.
