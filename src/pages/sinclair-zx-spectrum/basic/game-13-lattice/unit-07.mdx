The player needs to select nodes, and to do that they need a cursor. In Lattice, the cursor is a yellow circle drawn over the current node. Pressing Q, A, O or P moves the cursor to the nearest node in that direction.

## How It Works

**Lines 10-50** load nodes and draw them as green circles. Variable `p` tracks which node the cursor is currently on, starting at node 1.

**Lines 60-70** draw the cursor — a yellow circle over node `p`. This is the same CIRCLE command used for nodes, but with INK 6 (yellow) instead of INK 4 (green).

**Lines 80-130** form the input loop. INKEY$ checks for key presses. When Q, A, O or P is pressed, the program searches for the nearest node in that direction.

**Lines 200-250** are the nearest-node subroutine. It loops through all nodes, checking whether each one is in the correct direction from the current node. Among those candidates, it picks the closest one. If no node exists in that direction, the cursor stays put.

**Lines 260-290** handle cursor movement: erase the old cursor by redrawing the node in green, update `p` to the new node, and draw a yellow circle at the new position.

## Nearest-Node Navigation

On a grid, cursor movement is simple — just increment or decrement a row or column. But Lattice nodes can be in any arrangement, so we need a different approach.

When the player presses Q (up), the program finds the nearest node that has a higher y value than the current node. For O (left), the nearest node with a lower x value. The "nearest" calculation uses the distance between nodes, with a preference for the direction of movement.

This approach works for any node layout — grids, circles, irregular patterns — because it does not assume any particular arrangement.
