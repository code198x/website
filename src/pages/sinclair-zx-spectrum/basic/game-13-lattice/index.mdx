## What You Will Build

A graphical puzzle game where nodes are drawn as circles on screen and the player must connect them with lines. The catch: lines must not cross. Each puzzle defines a set of nodes and required connections. The player selects pairs of nodes to draw lines between, working out the correct order and arrangement to complete the puzzle without any intersections. Fifteen puzzles in Phase 1 grow to a full set with star ratings, hints and a puzzle select screen by the end.

![Lattice gameplay](/images/sinclair-zx-spectrum/basic/game-13-lattice/gameplay.png)

## Why This Game?

Every game so far has used character-based graphics — PRINT AT to place text and symbols on a 32x22 grid. Lattice is the first game that works in pixel coordinates. PLOT places dots, DRAW extends lines, and CIRCLE renders nodes. The screen becomes a canvas rather than a grid of characters.

This shift introduces a different way of thinking about position. Character coordinates start at the top-left and count down. Pixel coordinates start at the bottom-left and count up. The screen is 256 pixels wide and 176 pixels tall, and every PLOT, DRAW and CIRCLE command works in this space. Understanding both coordinate systems — and converting between them — is a skill that carries into every graphical program you write.

The puzzle design also teaches data-driven programming. Node positions and required connections are stored in DATA statements, and the same game engine handles every puzzle. Adding a new puzzle means adding data, not code.

## What You Will Learn

### Phase 1: Dots, Lines and Puzzles (Units 1-16)

- **Pixel graphics** — PLOT, DRAW and CIRCLE for dots, lines and nodes
- **Pixel coordinates** — the 256x176 screen, origin at bottom-left
- **Colour with INK** — setting ink colour before graphics commands
- **Arrays from DATA** — loading node positions and connections from DATA statements
- **GO SUB for drawing** — subroutines that draw lines between node pairs
- **Cursor movement** — navigating between nodes with keyboard input
- **Two-phase selection** — picking a start node, then an end node
- **Validation** — rejecting invalid or duplicate connections
- **Crossing detection** — sampling ATTR along a proposed line to detect existing lines
- **Undo** — removing the last connection and redrawing
- **Puzzle completion** — checking all required connections are drawn
- **Multiple puzzles** — RESTORE to load sequential puzzle data

### Phase 2: Depth and Polish (Units 17-32)

- **Irregular layouts** — free-form node positions beyond simple grids
- **SIN and COS** — calculating circular arrangements in radians
- **Difficulty bands** — colour-coded puzzles by difficulty
- **Connection preview** — showing available connections from a selected node
- **Visual feedback** — red flash animation for rejected crossings
- **Star ratings** — scoring puzzles on moves and time
- **Puzzle select screen** — menu with star display and progress tracking
- **Hint system** — briefly revealing valid connections
- **Line animation** — incremental line drawing for visual polish
- **Sound design** — ascending tones, completion fanfare, rejection beep
- **Title screen and game flow** — complete menu-to-play-to-results loop
