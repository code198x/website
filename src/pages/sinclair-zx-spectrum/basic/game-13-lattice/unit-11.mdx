The defining rule of Lattice is that lines must not cross. When the player tries to draw a connection, the program must check whether the proposed line would pass through any existing line. The Spectrum has a built-in tool for this: ATTR, which reads the colour attribute of any character cell on screen.

## How It Works

**Lines 10-100** set up the puzzle with nodes, connections and the cursor as before.

**Lines 400-460** are the crossing detection subroutine. Before drawing a proposed line, it samples points along the path from node `s` to node `p`. At each sample point, it converts pixel coordinates to character coordinates and uses ATTR to read the ink colour of that cell.

**Lines 420-440** step along the line in small increments. At each step, the pixel position is converted to a character row and column. The conversion formula is: column = INT(px / 8), row = 21 - INT(py / 8). The row formula accounts for the inverted y axis — pixel y increases upward, but ATTR row increases downward.

**Lines 445-450** check the ATTR value. If the ink colour of any sampled cell matches white (7) — the colour used for connection lines — then an existing line is in the way. Variable `cr` is set to 1, meaning a crossing was detected.

**Lines 110-130** integrate the check. After validating that the connection is in the required list, the program calls the crossing check. If `cr` is 1, the connection is rejected with a beep. Only if both checks pass does the line get drawn.

## How ATTR Works

`ATTR(row, col)` returns a single byte encoding the ink and paper colours of the character cell at that position. The ink colour is stored in the lower three bits: `INK = ATTR(r,c) - 8 * INT(ATTR(r,c) / 8)`. For a black paper with white ink, the ATTR value is 7.

The key insight is that drawing a white line changes the ATTR of every character cell it passes through. So checking ATTR along a proposed line detects whether any existing white line has been drawn in those cells.

## Sampling Density

The subroutine samples every few pixels along the line, not every single pixel. Sampling every pixel would be slow. Sampling too few points might miss a crossing at a narrow angle. Checking every 4 pixels along the longer axis gives a good balance between speed and accuracy.

## Try This

**Test with a crossing.** Draw one connection, then try to draw another that would cross it. Does the program reject it correctly?

**Test near misses.** Draw two lines that pass close to each other but do not cross. Does the program accept them both? The 8x8 character cell granularity means very close lines might trigger false positives.
