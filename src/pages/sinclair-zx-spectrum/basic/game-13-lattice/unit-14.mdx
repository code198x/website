One puzzle is a demo. Multiple puzzles make a game. Lattice stores each puzzle as a block of DATA, and RESTORE with a line number jumps the READ pointer to the start of any block. After completing a puzzle, the program loads the next one.

## How It Works

**Lines 10-20** set the starting puzzle number and store the DATA line numbers for each puzzle in an array. `DIM r(5)` holds the line numbers where each puzzle's DATA begins.

**Lines 30-50** read the line numbers from a lookup table. Puzzle 1 data starts at line 1000, puzzle 2 at line 1050, puzzle 3 at line 1100, and so on.

**Lines 60-70** use RESTORE to set the READ pointer to the correct DATA line for the current puzzle, then load the node and connection data exactly as before.

**Lines 80-150** run the puzzle with the full game loop — cursor, selection, validation, crossing check, undo and completion.

**Lines 160-180** handle puzzle completion. The score is displayed, the puzzle number increments, and if more puzzles remain, the program loops back to line 60 to load the next one. If all puzzles are complete, the game ends.

**Lines 1000-1150** hold the DATA for multiple puzzles, each starting at a known line number.

## RESTORE and Line Numbers

RESTORE on its own resets the READ pointer to the very first DATA statement in the program. RESTORE followed by a line number sets it to the first DATA statement at or after that line. This is how Lattice loads different puzzles — each puzzle's DATA starts at a specific line, and RESTORE jumps directly to it.

The lookup array `r()` maps puzzle numbers to line numbers. This avoids hard-coding line numbers throughout the program. To add a new puzzle, you add its DATA at a new line number and add that line number to the lookup table.

## Resetting State

Loading a new puzzle means resetting everything: the node arrays, connection arrays, drawn flags, history stack and cursor position. The program clears these before reading the new DATA. Forgetting to reset any array would carry state from the previous puzzle into the next one — a subtle bug that would cause incorrect crossing detection or false completion.

## Try This

**Play through three puzzles.** Complete each one and verify that the next puzzle loads correctly with a clean slate.

**Skip a puzzle.** Add a key that advances to the next puzzle without completing the current one. This is useful during testing.
