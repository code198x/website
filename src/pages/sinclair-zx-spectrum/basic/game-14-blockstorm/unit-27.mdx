You have felt the slowdown. This unit measures it. The Spectrum has a system variable at address 23672 that counts frames — it increments 50 times per second on a PAL machine. By reading it before and after the game loop, you can calculate exactly how long each iteration takes. The numbers reveal the performance gap between a simple wave and a dense one.

## How It Works

**PEEK 23672** reads the low byte of the Spectrum system timer (FRAMES). This counter increments every 1/50th of a second. By reading it at the start and end of the main loop, the difference tells you how many fiftieths of a second the loop took.

**At the loop start:** `LET f1 = PEEK 23672`
**At the loop end:** `LET f2 = PEEK 23672`
**Loop time in fiftieths:** `f2 - f1`

If the loop takes 3 ticks, that is 3/50 = 0.06 seconds per frame, or roughly 16 frames per second. If it takes 15 ticks, that is 15/50 = 0.3 seconds per frame, or roughly 3 frames per second.

## The Numbers

Typical measurements (approximate):

| Wave | Enemies | Loop time (ticks) | Frames per second |
|------|---------|-------------------|-------------------|
| 1 | 8 | 4-6 | 8-12 |
| 5 | 14 | 7-10 | 5-7 |
| 10 | 20 | 12-18 | 3-4 |

The relationship is roughly linear: twice as many enemies means the loop takes roughly twice as long. Each enemy adds work: erase the old position (one PRINT AT), calculate the new position (several variable lookups and arithmetic), draw at the new position (one PRINT AT), check collision against bullets (comparisons and conditionals).

## Where the Time Goes

The Spectrum BASIC interpreter has three major sources of overhead:

**Line scanning.** Every GO TO and GO SUB starts from line 1 and scans forward to find the target line. A GO SUB 800 at line 100 scans past every line between 100 and 800. This is why frequently called subroutines benefit from low line numbers.

**Variable lookup.** Every time BASIC encounters a variable name, it searches the variable table from the beginning. Longer names take longer to find. A variable named `score` is slower to access than one named `s` because the interpreter checks more characters.

**Floating point.** All numbers in Sinclair BASIC are floating point. Even `LET x = x + 1` does floating-point addition. Integer addition in machine code takes microseconds. Floating-point addition in BASIC takes hundreds of microseconds.

## The Teaching Moment

This is why assembly language exists. The same game loop in Z80 machine code would run in microseconds, not hundredths of seconds. A machine code shooter could handle 100 enemies at 50 frames per second. BASIC manages 20 enemies at 3 frames per second. The interpreter — the convenience of writing in English-like commands — costs roughly 100x in performance.

## Try This

**Display the loop time.** Print `f2 - f1` in the HUD on every frame. Watch the number change as enemies are destroyed and the wave thins out. Fewer enemies = faster loop = visible improvement.

**Compare operations.** Write a test program that runs 1000 PRINT AT statements vs 1000 LET assignments. Time each with PEEK 23672. Which operation is slower? By how much?
