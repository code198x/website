The ship moves. The bullet flies. But there is nothing to shoot at. This unit places a single drone UDG on screen and adds collision detection — when the bullet reaches the same row and column as the drone, it is a hit. The drone is replaced with an explosion UDG in red, and the score increases.

## How It Works

**Lines 30-35** place a drone at a fixed position. Variables `ex` and `ey` store the column and row. The drone is drawn with PRINT AT using CHR$ 144 (UDG A) in green (INK 4).

**Lines 160-180** add collision checking to the bullet movement routine. Before drawing the bullet at its new position, the program compares the bullet column and row to the drone column and row. If both match, the bullet has hit the drone.

**Lines 185-195** handle the hit. The drone is replaced with the explosion UDG (CHR$ 149) in red (INK 2). The score increases by 10. The drone is marked as destroyed so it is not drawn or checked again.

## Position-Based Collision

Collision detection in a character-based game is simple: two objects collide when they occupy the same character cell. If the bullet is at row 5, column 12, and a drone is at row 5, column 12, they overlap. That is a hit.

```
IF b = ex AND c = ey THEN hit
```

Two comparisons. No pixel-perfect checks, no bounding boxes, no overlap calculations. Character-cell collision is coarse — two objects must be in exactly the same cell to collide — but for an 8x8 grid game, it works well. Bullets are small, enemies are one cell wide, and near-misses feel fair rather than frustrating.

## The Explosion

When a drone is hit, its UDG is replaced with the explosion UDG at the same position. For one frame, the player sees a red starburst where the enemy was. Then the cell is cleared. This is not animation yet — that comes in the next unit. For now, it is a single-frame visual confirmation that the shot connected.

**Add scoring feedback.** When the drone explodes, briefly print "+10" at the explosion position before clearing it. Use PAUSE 5 to hold the text on screen.
