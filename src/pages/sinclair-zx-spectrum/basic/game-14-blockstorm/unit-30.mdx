A high score gives the player a reason to play again. A high score table with names gives them a reason to compete. This unit adds a three-entry high score table: when the game ends, if the score qualifies, the player enters three initials. The table is displayed during game over and on the title screen. Scores persist within the session but are lost when the program is restarted.

## How It Works

**Three arrays** store the high score table: `hs()` for scores, `h$()` for names (three-character strings). DIM at startup creates three entries, all initialised to 0 and empty strings.

**After game over,** the program checks whether the final score qualifies for the table. It compares the score against each entry from bottom to top. If the score exceeds an entry, that slot is available.

**Name entry** prompts the player for three initials. INKEY$ reads one key at a time, displaying each letter as it is entered. Three key presses produce a three-character string.

**Table insertion** shifts lower scores down to make room. If the new score is second-highest, the third entry receives the old second entry values before the new score and name are written into position 2.

**Display** shows the table during game over:

```
 RANK  NAME  SCORE
  1.   ABC   4250
  2.   DEF   2100
  3.   GHI    950
```

PRINT AT with calculated positions places each entry in a clean column. Scores are right-aligned by padding with spaces (or left unaligned — at three digits, the visual difference is small).

## Session-Only Persistence

The high scores live in arrays, which exist only while the program runs. RUN clears all variables and destroys the table. BREAK and CONTINUE preserve the table. There is no way to save to tape from within the program in a way that reloads automatically.

This is a limitation of BASIC. Assembly programs can save memory blocks to tape. BASIC programs can SAVE themselves, but the variable state is lost. The high score table is a within-session feature — motivation to play multiple games in a single sitting.

## Array Sorting

Inserting a new score into a sorted table is a simplified sort. The table is always kept in descending order (highest first). To insert a new score:

1. Find the position where the new score fits.
2. Shift everything below that position down by one (the lowest entry falls off the table).
3. Write the new score and name at the found position.

This is an insertion into a sorted list — one of the most fundamental operations in computer science. With only three entries, the code is simple. With 100 entries, the same algorithm works but the shifting takes longer.

## Try This
