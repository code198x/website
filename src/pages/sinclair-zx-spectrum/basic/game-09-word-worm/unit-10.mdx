The player needs to see their score, level, and misses at a glance. A HUD (heads-up display) puts all the vital information on one line at the top of the screen.

## How It Works

**Lines 700-720** draw the HUD as a subroutine:

```
710 PRINT AT 0, 0; INK 7; "Score:"; e; " Level:"; v; " Misses:"; m; "/3  "
720 RETURN
```

One line, all the information. The trailing spaces ensure old values are overwritten when numbers get shorter.

**Line 150** shows the target word: `PRINT AT 20, 0; "Type: "; INK 5; a$`. Cyan text at the bottom tells the player what to type.

**Line 290** displays typed progress: `PRINT AT 21, 0; INK 4; b$`. Green text below the target shows what they've typed so far.

## Screen Layout

| Row | Content |
|-----|---------|
| 0 | HUD — score, level, misses |
| 2-18 | Falling area |
| 20 | Target word |
| 21 | Typed progress |

The game area sits between the HUD and the input area. Nothing overlaps.

## Subroutine for the HUD

The HUD is called with `GO SUB 700` whenever a value changes — after a word is completed, after a miss, and at the start of each new word. Making it a subroutine means one place to update if you change the layout.

## Try This

**Visual lives.** Instead of "Misses:1/3", show remaining lives as symbols: `FOR i = 1 TO 3 - m: PRINT "*";: NEXT i`. Three stars at full health, two after one miss.

**Level colour.** Change the HUD ink based on level: `INK v`. Each level gets its own colour.

## What You've Learnt

- **HUD design** — compact, readable, one line
- **Screen zoning** — HUD at top, game in middle, input at bottom
- **Subroutine display** — `GO SUB` to update the HUD
- **Trailing spaces** — clearing old values when numbers shrink
