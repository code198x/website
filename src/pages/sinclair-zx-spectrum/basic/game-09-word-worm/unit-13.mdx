The game loop juggles movement, input, misses, and display. Without organisation, the code becomes a tangle. Subroutines separate each job — the main loop becomes a sequence of `GO SUB` calls.

## How It Works

The main loop (lines 130-220) reads like a plan:

```
130 LET t = t + 1
140 IF t < s THEN GO TO 180
150 GO SUB 600          ← move word
160 IF r >= 19 THEN GO SUB 700  ← handle miss
170 LET t = 0
180 PRINT AT r, 12; INK 6; a$
190 LET k$ = INKEY$
200 IF k$ = "" THEN GO TO 130
210 GO SUB 500          ← handle input
220 GO TO 130
```

Each subroutine does one job:

| Subroutine | Purpose |
|-----------|---------|
| GO SUB 500 | Handle input — match character, complete word |
| GO SUB 600 | Move word — erase, increment row |
| GO SUB 700 | Word missed — flash red, increment misses |
| GO SUB 800 | Draw HUD — score, level, misses |
| GO SUB 900 | Pick word — random selection based on level |

## Subroutine as Black Box

The main loop doesn't need to know *how* input is handled. It calls `GO SUB 500` and trusts that it does the right thing. This separation means you can change how input works without touching the main loop.

## Level Progression Inside Subroutines

Line 592 handles levelling up inside the input subroutine:

```
592 IF c >= 10 THEN LET v = v + 1: LET c = 0: LET s = s - 5
```

The main loop doesn't check for level changes — that's the input subroutine's job, triggered when a word is completed.

## What You've Learnt

- **Subroutine dispatch** — main loop calls subroutines by number
- **Single responsibility** — each subroutine does one job
- **Readable main loop** — reads like a plan, not like implementation
- **Encapsulation** — details hidden inside subroutines
