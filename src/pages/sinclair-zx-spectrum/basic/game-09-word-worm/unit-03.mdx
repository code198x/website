`PAUSE` stops the program completely — nothing else can happen while it waits. In a game, you need the loop to keep running so it can check for keypresses. Instead of pausing, count loop iterations and move the word only when the count reaches a threshold.

## How It Works

**Line 100** initialises the counter: `LET t = 0`.

**Line 110** sets the speed threshold: `LET s = 30`. The word moves when `t` reaches `s`.

**Lines 140-190** are the timing logic:

```
140 LET t = t + 1
150 IF t < s THEN GO TO 200
160 REM move word down
...
190 LET t = 0
```

Each loop iteration increments `t`. Most of the time, `t < s` is true and the word stays put. When `t` reaches `s`, the word moves one row and `t` resets.

**Lines 220-240** let you change speed during the demo. Press 1-9 to adjust — lower numbers mean faster falling.

## Counter Timing vs PAUSE

| PAUSE | Counter |
|-------|---------|
| Blocks the program | Loop keeps running |
| Fixed delay | Can check input while waiting |
| Simple | More code, more control |

Counter timing is more work, but it lets the game loop do multiple things — check keys, update the display, and control animation speed — all in the same loop.

## Try This

**Variable speed.** Press 1 for very fast, 9 for very slow. Watch how the threshold value changes the feel.

**Two words.** Add a second row variable `r2` and a second counter. Move both words independently — one fast, one slow.

## What You've Learnt

- **Counter-based timing** — increment a variable, act when it reaches a threshold
- **Non-blocking animation** — the loop runs continuously
- **Speed control** — lower threshold = faster, higher = slower
- **Why not PAUSE** — blocking prevents input during the wait
