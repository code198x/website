The player types a word. Now what? Erase the falling word, add to the score, pick a new word, and start again. The game becomes a cycle: fall, type, complete, repeat.

## How It Works

**Line 70** initialises the score: `LET e = 0`.

**Lines 290-300** check for completion:

```
290 IF p <= LEN a$ THEN GO TO 160
300 REM word complete
```

When `p` exceeds the word length, every character has been typed.

**Lines 310-350** handle a completed word:

1. Erase it from the screen (line 310)
2. Increment the score (line 320)
3. Play a success BEEP (line 330)
4. Clear the typed progress display (line 340)
5. Jump back to pick a new word (line 350)

**Line 210** handles missed words — if the word reaches row 20 without being completed, show "Missed!", pause briefly, and pick a new word. No score change.

## The Game Cycle

```
Pick word → Fall → Type → Complete → Pick next word
                ↓
            Miss → Pick next word
```

Two paths from "Fall": the player completes the word (score increases) or the word reaches the bottom (a miss). Either way, a new word starts.

## Score Display

Line 140 shows the current score and target word:

```
140 PRINT AT 0, 0; "Score: "; e; "  Type: "; a$; "     "
```

The trailing spaces ensure the previous word's characters are erased if the new word is shorter.

## Try This

**Bonus for speed.** Award more points if the word is completed before it reaches row 10. `IF r < 10 THEN LET e = e + 2` — early completion gets double.

**Word length bonus.** Award points equal to the word length: `LET e = e + LEN a$`. Longer words are worth more.

## What You've Learnt

- **Completion detection** — position exceeds word length
- **Game cycle** — complete or miss, then start fresh
- **Score tracking** — increment on success
- **State reset** — new word, position 1, empty progress string
