## How It Works

**Line 40** creates the string array: `DIM w$(50,7)`. The first number is how many strings (50 words). The second is the maximum length of each string (7 characters). Every string starts as 7 spaces.

**Line 50** creates a parallel number array: `DIM l(50)`. This stores the actual length of each word, since the string array pads everything to 7 characters.

**Lines 60-80** load the data. Each `READ` pulls two values: a number (length) and a string (the word). `l(i)` gets the length, `w$(i)` gets the word.

**Line 120** uses string slicing to display only the meaningful characters:

```
120 PRINT w$(i)(1 TO l(i)); " ";
```

`w$(1)` contains `"cat    "` (padded to 7). `w$(1)(1 TO 3)` extracts just `"cat"`.

**Line 130** prints a newline every 10 words, keeping the display organised.

## String Arrays vs Number Arrays

| Feature | Number array | String array |
|---------|-------------|-------------|
| DIM | `DIM a(10)` | `DIM a$(10,5)` |
| Values | Numbers | Strings up to max length |
| Default | 0 | Spaces |
| Access | `a(3)` | `a$(3)` |

The key difference: string arrays need a second dimension for maximum length. `DIM w$(50,7)` means 50 strings, each up to 7 characters.

## Why Store Lengths Separately?

`LEN w$(1)` always returns 7 — the declared maximum, not the actual word length. The Spectrum pads shorter strings with spaces. To know the real length, you store it alongside the word.

## Try This

**Word count.** After loading, count how many 3-letter, 4-letter, 5-letter, and 6-letter words there are. Print the totals.

**Alphabetical.** Add more words to the DATA lines. Keep the total at 50 but try different words. Notice that the order in DATA matches the order in the array.

## What You've Learnt

- **String arrays** — `DIM w$(50,7)` creates an array of strings
- **DATA/READ for strings** — reading numbers and strings in pairs
- **String slicing** — `w$(i)(1 TO l(i))` extracts a substring
- **Parallel arrays** — word text in one array, word length in another
