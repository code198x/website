## Drawing Walls

**Outer walls (lines 90-160).** `=` characters across the top and bottom (rows 1 and 21), `|` characters down the sides (columns 0 and 31). All printed in `INK 1` (blue).

**Inner walls (lines 180-210).** Two horizontal walls inside the arena — one at row 7 and one at row 14. These create corridors the player must navigate.

## Wall Collision

The trick is checking the **destination** cell before moving there:

```
400 LET a = ATTR (u, w)
410 IF a = 57 THEN GO TO 330
```

`u` and `w` are the proposed new position. If `ATTR(u, w)` returns 57, it's a wall (blue ink on white paper: 1 + 56 = 57). The player stays where they are — the `GO TO 330` jumps back to the input loop without updating `r` and `c`.

## Check Before Move

This is a critical pattern: calculate the new position, check it, then decide whether to accept it.

```
350 LET u = r: LET w = c
360 IF k$ = "q" THEN LET u = r - 1
...
400 LET a = ATTR (u, w)
410 IF a = 57 THEN GO TO 330
420 PRINT AT r, c; " "
430 LET r = u: LET c = w
```

Lines 350-390 propose a move into `u` and `w`. Line 400 checks the destination. If it's a wall, reject. Otherwise, line 430 commits the move.

## Coin Placement

Line 270 checks that coins don't land on walls:

```
270 IF ATTR (y, x) = 56 THEN INK 6: PRINT AT y, x; "*": INK 0: GO TO 290
280 GO TO 250
```

If the cell's ATTR is 56 (empty — black ink on white paper), place the coin. If not, try another random position. This ensures coins appear only in open spaces.

## Try This

**Maze.** Add more inner walls to create a maze. Use different row/column ranges in new `FOR` loops.

**Door.** Leave a gap in one inner wall — `FOR i = 5 TO 10` instead of `FOR i = 5 TO 15`. The player can pass through the gap.

## What You've Learnt

- **Wall drawing** — use loops to print characters along rows and columns
- **Wall collision** — check ATTR before moving, reject if it's a wall
- **Check-before-move pattern** — propose, check, commit or reject
- **Placement validation** — ensure random objects don't land on walls
