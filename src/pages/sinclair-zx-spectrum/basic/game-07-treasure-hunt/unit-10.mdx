## How It Moves

**Variable `b`** is the hazard's row. **Variable `d`** is its direction: 1 means down, -1 means up.

On each loop iteration:

1. **Erase** — print spaces across the old row (line 200)
2. **Move** — `LET b = b + d` shifts the row by the direction (line 210)
3. **Bounce** — if it hits the top or bottom edge, reverse direction (line 220)
4. **Draw** — print red `#` characters across the new row (line 230)

This is the same erase-move-draw pattern the player uses, scaled to a full row.

## Collision Check

```
250 IF r = b THEN GO SUB 900
```

If the player's row matches the hazard's row, they lose a life. This check happens on every frame, so the hazard is always dangerous — not just when the player moves.

A second check at line 320 catches the case where the hazard moves onto the player (rather than the player moving onto the hazard).

## Direction as a Number

Using 1 and -1 for direction is elegant. Adding the direction to the position moves it in the right direction automatically. Reversing direction is just `LET d = -d`. No IF statements needed for movement — only for bouncing.

## Try This

**Faster hazard.** Move the hazard 2 rows per frame: `LET b = b + d * 2`. It zooms across the screen.

**Partial bar.** Instead of filling the whole row, print only 10 characters: `PRINT AT b, 10; "##########"`. The player can dodge around the ends.

## What You've Learnt

- **Animated objects** — erase, move, draw on each loop iteration
- **Direction variable** — 1/-1 for up/down or left/right
- **Bouncing** — reverse direction at boundaries
- **Two-way collision** — check when the player moves AND when the hazard moves
