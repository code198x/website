Save without load is a write-only diary. This unit reads a saved game from tape and restores all variables and arrays to their saved state. The player resumes on the same floor, with the same stats, facing the same monsters. The game continues as if it had never stopped.

## How It Works

The load function is available from the title screen. Pressing L triggers the load sequence.

**The load process** reads the saved data block from tape and unpacks the values back into variables. The order must match the save order exactly — if save writes HP before attack, load must read HP before attack. Any mismatch produces garbage values.

**After loading**, the program skips dungeon generation and jumps directly to the main exploration loop. The dungeon array already contains the saved layout. The visibility array shows previously explored cells. Monsters are in their saved positions with their saved HP. The player resumes from exactly where they saved.

## Error Handling

Loading can fail. The tape might be blank. The data might be corrupted. The file might be from a different program. Without error handling, a failed load crashes the game.

The program handles errors by checking whether the loaded values are within expected ranges. Floor number should be 1-10. HP should be positive. The dungeon array should contain only valid cell types. If any check fails, the load aborts and returns to the title screen with an error message.

On real hardware, the most common error is pressing PLAY too late or having the tape at the wrong position. The error message "Tape loading error" tells the player to try again.

## Serialisation Round-Trip

The save and load form a round-trip: game state goes to tape and comes back. The test for correctness is simple — save on floor 5 with 12 HP, load the save, and verify that the game shows floor 5 with 12 HP. If any value is wrong, the save or load has a bug.

Testing the round-trip thoroughly means saving at different points: mid-floor with monsters alive, after a combat with a monster defeated, with different equipment levels, on floor 1 and floor 10. Each case exercises a different part of the state.

## Save Slots

The current implementation uses a single save. Loading always reads the most recently saved game. Multiple save slots would let the player keep several runs in progress, but that adds complexity: the player must choose which slot to save to and load from, and the tape management becomes more involved.

A single save is sufficient for this game. The player has one active run at a time. Saving overwrites the previous save. Loading resumes the current run.

## Try This

**Test the round-trip.** Save on floor 3 with specific stats. Note your HP, equipment, gold, and position. Load the save and verify every value matches.

**Save before a tough fight.** Save, fight the monster, and if you lose, load the save and try again. This "save scumming" is a valid strategy — the game does not prevent it.
