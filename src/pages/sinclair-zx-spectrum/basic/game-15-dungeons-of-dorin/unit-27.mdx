When the player descends to a new floor, the old floor is gone. Regenerating it would produce a different layout — the rooms and corridors are random, so the same floor cannot be recreated. This is a constraint, not a bug. The one-way descent is part of the game design. Every step deeper is permanent, and that permanence creates tension.

## How It Works

**Line 606** prints "DESCENDING..." in bright white before generating the new floor. This message serves two purposes: it tells the player something is happening (generation takes a moment), and it marks the transition as a significant event. The pause and sound effect from line 608 give the moment weight.

The dungeon array `d(16,16)` is overwritten entirely on each new floor. The visibility array `v(16,16)` resets to all zeros. Monster arrays are repopulated. The player position moves to the first room of the new layout. Everything about the previous floor is erased.

## Design Constraints

Storing the complete state of all ten floors would require ten copies of the dungeon array (2,560 cells), ten visibility arrays, and ten sets of monster data. On a 48K Spectrum, this is possible but expensive — roughly 5-6 KB of variable storage. More importantly, it adds complexity: the player would need to navigate between floors, the game would need to track which monsters on which floor are alive, and the generation code would need to run once per floor rather than once per descent.

The one-way approach is simpler and creates better gameplay. Rogue — the game that defined the genre — worked the same way. Each floor is a one-shot challenge. The player must make the most of every room and every chest before moving on. There is no backtracking to a previous floor to farm gold or find a missed potion.

## Communicating the Constraint

The "DESCENDING..." message and the descending tone tell the player this is a significant, irreversible action. The game does not ask for confirmation — stepping on stairs immediately triggers the descent. This is intentional. Adding a "Are you sure?" prompt would break the pace and imply that descending is risky. It is not risky — it is inevitable. The only question is whether the player has explored enough of the current floor first.

## The Tension of Depth

Each floor deeper is a commitment. The player stats carry forward, but the dungeon does not. A player who finds a fountain on floor 3 cannot save it for floor 7. A player who avoids a tough monster on floor 5 will never face that specific monster again (though similar ones will appear on later floors). Every decision is final within the context of each floor.

This finality makes exploration meaningful. When the player finds the stairs, they face a genuine choice: descend now, or explore more of the current floor for chests and monsters. More exploration means more potential loot but also more damage. The right time to descend is when the floor has given what it can.

## Try This

**Add a floor completion percentage.** Count how many floor cells the player has seen versus the total non-wall cells. Display "Floor explored: 73%" on the status panel. This gives the player data for their decision about when to descend.

**Track total cells explored.** Sum the explored percentage across all floors for a final stat on the victory screen: "Total exploration: 64%." Completionists will want to push this higher.
