Graphics established, sound working, now movement. Every action game needs a player character you control. The Spectrum's QAOP keys (reachable with one hand) combined with INKEY$ (non-blocking input) create responsive movement. The erase-and-redraw pattern makes characters glide smoothly across the screen.

Jet Set Willy, Manic Miner, Sabre Wulf—they all use this technique. Store position, check keys, erase old character, draw new. Simple, fast, effective. This is how Spectrum games move.

## The One-Minute Tour

- **INKEY$** reads keyboard without pausing
- **QAOP keys** - Classic Spectrum one-handed control
- **Erase-and-redraw pattern** - Print space at old position, character at new
- **Boundary checking** prevents leaving screen
- Store old position before moving to erase correctly
- This pattern underlies every action game

## Your First Moving Character

Type this carefully:

```basic
10 REM Basic Character Movement
20 REM Simple QAOP movement demo
30 PAPER 0: INK 7: BORDER 1: CLS
40 LET X=15: LET Y=10
50 PRINT AT 0,0;"Use Q/A/O/P to move"
60 LET OX=X: LET OY=Y
70 LET K$=INKEY$
80 IF K$="q" THEN LET Y=Y-1
90 IF K$="a" THEN LET Y=Y+1
100 IF K$="o" THEN LET X=X-1
110 IF K$="p" THEN LET X=X+1
120 REM Boundary checking
130 IF X&lt;0 THEN LET X=0
140 IF X>31 THEN LET X=31
150 IF Y&lt;2 THEN LET Y=2
160 IF Y>21 THEN LET Y=21
170 REM Erase old, draw new
180 PRINT AT OY,OX;" "
190 PRINT AT Y,X;"@"
200 GO TO 60
```

**Run this** and move the @ character around with QAOP!

## How This Works

### The Game Loop Structure

```basic
60 LET OX=X: LET OY=Y
70 LET K$=INKEY$
...
180 PRINT AT OY,OX;" "
190 PRINT AT Y,X;"@"
200 GO TO 60
```

Classic game loop:
1. Store old position (OX, OY)
2. Read input (INKEY$)
3. Update position based on input
4. Check boundaries
5. Erase old position (print space)
6. Draw new position (print character)
7. Loop back

This pattern runs continuously. The Spectrum executes it hundreds of times per second—fast enough for responsive gameplay.

### INKEY$ - Non-Blocking Input

```basic
70 LET K$=INKEY$
80 IF K$="q" THEN LET Y=Y-1
```

INKEY$ checks the keyboard **right now**. If a key is pressed, it returns that key. If no key is pressed, it returns an empty string (""). The program doesn't wait—it keeps running.

Compare to INPUT, which pauses until you press ENTER. INKEY$ never pauses. Perfect for action games where the action never stops.

### QAOP Keys - The Spectrum Standard

```
   Q
 O   P
   A
```

Q = Up, A = Down, O = Left, P = Right. These keys form a diamond pattern reachable with your left hand, leaving your right hand free for fire/jump on the bottom row (M, N, or SPACE). Nearly every Spectrum game uses this layout or offers it as an option.

**Why QAOP?** Sinclair keyboards have flat, membrane keys. Traditional gaming position (hand in center) doesn't work well. QAOP discovered by early developers, became the standard. Z

X Spectrum gaming culture encoded in four keys.

### Position Variables

```basic
40 LET X=15: LET Y=10
60 LET OX=X: LET OY=Y
```

X and Y track current position. OX and OY store old position. Before moving, copy current to old. After moving, use old to erase previous character.

**Screen coordinates:**
- X: 0 (left edge) to 31 (right edge) - 32 columns
- Y: 0 (top) to 21 (bottom) - 22 rows (saving 2 for status display)

Line 40 starts character at center: column 15, row 10.

### Boundary Checking

```basic
130 IF X&lt;0 THEN LET X=0
140 IF X>31 THEN LET X=31
150 IF Y&lt;2 THEN LET Y=2
160 IF Y>21 THEN LET Y=21
```

Without boundaries, the character could move off-screen, causing PRINT AT errors or wrapping to strange positions. Check after movement, clamp to valid range.

Y starts at 2 (not 0) because row 0 displays instructions. Playable area: rows 2-21.

**Clamping** - If X goes negative (moved left past edge), set it to 0. If X exceeds 31 (moved right past edge), set it to 31. Character stops at screen edges.

### The Erase-and-Redraw Pattern

```basic
180 PRINT AT OY,OX;" "
190 PRINT AT Y,X;"@"
```

First, print a space at the old position (OY, OX). This erases the previous character. Then print @ at the new position (Y, X). Character appears to move.

**Why this works:** The Spectrum screen persists. Characters stay where you print them until overwritten. Printing space overwrites with blank, effectively erasing.

**Flicker-free:** Erase then draw happens so fast (within milliseconds) you don't see a gap. Appears smooth.

## Enhanced Movement with Trail

Now create an enhanced version with trail toggle and colour changing:

```basic
10 REM Smooth Character Mover
20 REM Character movement with coloured trail
30 PAPER 0: INK 2: BORDER 1: CLS
40 LET X=15: LET Y=10
50 LET TRAIL=0
60 PRINT AT 0,0;"Q/A/O/P=move  T=toggle trail"
70 PRINT AT 1,0;"SPACE=change colour"
80 LET C=2
90 LET OX=X: LET OY=Y
100 LET K$=INKEY$
110 IF K$="q" THEN LET Y=Y-1
120 IF K$="a" THEN LET Y=Y+1
130 IF K$="o" THEN LET X=X-1
140 IF K$="p" THEN LET X=X+1
150 IF K$="t" THEN LET TRAIL=1-TRAIL
160 IF K$=" " THEN LET C=C+1: IF C>7 THEN LET C=1
170 REM Boundaries
180 IF X&lt;0 THEN LET X=0
190 IF X>31 THEN LET X=31
200 IF Y&lt;3 THEN LET Y=3
210 IF Y>21 THEN LET Y=21
220 REM Erase or leave trail
230 IF TRAIL=0 THEN PRINT AT OY,OX;" "
240 IF TRAIL=1 THEN PRINT AT OY,OX;"."
250 REM Draw character
260 INK C
270 PRINT AT Y,X;CHR$ 144
280 GO TO 90
```

**Run this** and experiment with T (trail) and SPACE (colour)!

## Understanding the Enhancements

### Trail Toggle

```basic
50 LET TRAIL=0
150 IF K$="t" THEN LET TRAIL=1-TRAIL
...
230 IF TRAIL=0 THEN PRINT AT OY,OX;" "
240 IF TRAIL=1 THEN PRINT AT OY,OX;"."
```

TRAIL variable tracks mode. 0 = erase cleanly, 1 = leave dots behind.

Line 150: `LET TRAIL=1-TRAIL` is a toggle. If TRAIL=0, becomes 1. If TRAIL=1, becomes 0. Press T to flip between modes.

Line 230-240: When erasing, check TRAIL. If 0, print space (erase). If 1, print dot (trail marker).

**Trail effect:** Character leaves breadcrumb path showing where it's been. Useful for maze exploration or creating simple drawing programs.

### Colour Cycling

```basic
80 LET C=2
160 IF K$=" " THEN LET C=C+1: IF C>7 THEN LET C=1
260 INK C
```

C variable stores current INK colour (1-7, skipping 0 which is black on black background).

Press SPACE: increment C. If C exceeds 7, wrap back to 1. Then set INK C before drawing character.

Character colour changes with each SPACE press: cyan → magenta → white → red → green → blue → yellow → cyan...

### CHR$ for Graphics Characters

```basic
270 PRINT AT Y,X;CHR$ 144
```

Instead of @, print CHR$ 144—a filled block character from the Spectrum's character set. Looks more solid, more game-like.

**CHR$ function:** Converts number to corresponding character. CHR$ 65 = "A", CHR$ 144 = filled block graphic.

Spectrum character set includes letters, numbers, symbols, and graphics characters (blocks, lines, patterns) at higher ASCII values. Explore 128-255 for sprites made from graphics characters.

## Experiment: Diagonal Movement

Add diagonal controls:

```basic
115 IF K$="w" THEN LET Y=Y-1: LET X=X-1
125 IF K$="e" THEN LET Y=Y-1: LET X=X+1
135 IF K$="z" THEN LET Y=Y+1: LET X=X-1
145 IF K$="c" THEN LET Y=Y+1: LET X=X+1
```

W = up-left, E = up-right, Z = down-left, C = down-right. Now eight-way movement like Gauntlet or Robotron.

## Experiment: Speed Control

Add variable speed:

```basic
45 LET SPEED=1
165 IF K$="+" THEN LET SPEED=SPEED+1: IF SPEED>5 THEN LET SPEED=5
175 IF K$="-" THEN LET SPEED=SPEED-1: IF SPEED&lt;1 THEN LET SPEED=1
...
110 IF K$="q" THEN LET Y=Y-SPEED
120 IF K$="a" THEN LET Y=Y+SPEED
130 IF K$="o" THEN LET X=X-SPEED
140 IF K$="p" THEN LET X=X+SPEED
```

SPEED variable multiplies movement distance. Speed 1 = one character per press. Speed 5 = five characters per press. Fast movement for large playfields.

## Why This Pattern Matters

**Every Spectrum action game uses variations of this:**

- **Manic Miner:** Willy moves with QAOP, platforms checked instead of simple boundaries
- **Jet Set Willy:** Same core loop, adds room transitions and collision detection
- **Sabre Wulf:** Adds animation frames (multiple CHR$ characters cycling)
- **Atic Atac:** Faster movement, weapon firing added to loop

The pattern scales. Start simple (move character), add complexity (collision, animation, enemies, scoring). Foundation remains: store position, read input, update, erase, draw, loop.

## Technical Details

**INKEY$ speed:** The Z80 CPU executes BASIC interpreted bytecode. Full game loop (lines 60-200) runs ~100-200 times per second depending on program complexity. Feels responsive—character moves immediately when key pressed.

**Character printing:** PRINT AT uses ROM routines that write to screen memory (16384-22527) and attribute memory (22528-23295). Fast enough for smooth character movement—no screen tearing or flicker with this pattern.

**Memory usage:** Position variables (X, Y, OX, OY, C, TRAIL, SPEED) use ~14 bytes total. Tiny overhead. Most memory available for game data (levels, enemies, items).
