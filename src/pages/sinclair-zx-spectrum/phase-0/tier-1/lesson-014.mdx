You can move. You can detect walls. Now add a goal worth pursuing—collectible items. Every arcade game revolves around collecting: coins in Pac-Man, rings in Sonic, pills in Manic Miner, keys in Jet Set Willy. Score creates motivation. Win conditions create satisfaction.

This lesson synthesizes everything learnt so far: INKEY$ movement, SCREEN$ collision, BEEP feedback, PRINT AT displays. Add score tracking and win detection. The result—your first complete action game with objective, challenge, and victory.

The pattern established here scales infinitely. Collecting coins, gathering keys, rescuing hostages, destroying enemies—all use the same core mechanics. Detect item with SCREEN$, increment counter, remove item, check win condition. Master this, you've mastered the foundation of game design.

## The One-Minute Tour

- **SCORE variable** tracks collected items
- **ITEMS variable** stores total collectibles
- **Collection subroutine** handles pickup logic
- **Win detection** compares SCORE to ITEMS
- **Display updates** show current progress
- **Sound feedback** confirms collection
- **Victory screen** celebrates completion
- Every Spectrum game uses variations of this pattern

## Your First Collection Game

Type this carefully:

```basic
10 REM Simple Collect
20 REM Basic item collection demo
30 PAPER 0: INK 7: BORDER 1: CLS
40 REM Place collectibles
50 INK 6
60 PRINT AT 5,10;"*"
70 PRINT AT 8,20;"*"
80 PRINT AT 15,5;"*"
90 PRINT AT 12,25;"*"
100 PRINT AT 18,15;"*"
110 REM Game variables
120 LET SCORE=0
130 LET ITEMS=5
140 PRINT AT 0,0;"Collect all stars!"
150 PRINT AT 1,0;"Score: ";SCORE;"/";ITEMS
160 REM Player start
170 LET PX=15: LET PY=10
180 INK 7
190 PRINT AT PY,PX;"@"
200 REM Game loop
210 LET NX=PX: LET NY=PY
220 LET K$=INKEY$
230 IF K$="q" THEN LET NY=NY-1
240 IF K$="a" THEN LET NY=NY+1
250 IF K$="o" THEN LET NX=NX-1
260 IF K$="p" THEN LET NX=NX+1
270 REM Boundary check
280 IF NX&lt;0 OR NX>31 THEN GO TO 210
290 IF NY&lt;3 OR NY>21 THEN GO TO 210
300 REM Check destination
310 LET CH$=SCREEN$(NY,NX)
320 IF CH$="*" THEN GOSUB 1000
330 IF CH$=" " THEN GOSUB 2000
340 REM Check win
350 IF SCORE=ITEMS THEN GOSUB 3000
360 GO TO 210
1000 REM Collect item
1010 PRINT AT PY,PX;" "
1020 LET PX=NX: LET PY=NY
1030 LET SCORE=SCORE+1
1040 PRINT AT 1,7;"        "
1050 PRINT AT 1,7;SCORE;"/";ITEMS
1060 INK 7
1070 PRINT AT PY,PX;"@"
1080 BEEP 0.05,10
1090 RETURN
2000 REM Move to empty space
2010 PRINT AT PY,PX;" "
2020 LET PX=NX: LET PY=NY
2030 PRINT AT PY,PX;"@"
2040 RETURN
3000 REM Win condition
3010 CLS
3020 PAPER 0: INK 2: BRIGHT 1
3030 PRINT AT 10,8;"CONGRATULATIONS!"
3040 PRINT AT 12,6;"You collected all stars!"
3050 BEEP 0.5,0: BEEP 0.5,5: BEEP 0.5,10
3060 PAUSE 0
3070 STOP
```

**Run this** and collect all five stars!

## How This Works

### Placing Collectibles

```basic
40 REM Place collectibles
50 INK 6
60 PRINT AT 5,10;"*"
70 PRINT AT 8,20;"*"
80 PRINT AT 15,5;"*"
90 PRINT AT 12,25;"*"
100 PRINT AT 18,15;"*"
```

Place five star characters (*) at specific positions. Set INK 6 (yellow) first—all stars print in same colour. Each PRINT AT places one collectible.

**Design consideration:** Spread items across screen. Forces player to explore. Items clustered in one corner creates boring gameplay—player collects all immediately, game ends. Distribution creates journey.

**Star character** - Asterisk looks like collectible item. Spectrum character set includes many options: $ (dollar), + (plus), • (bullet), ◆ (diamond). Choose character that looks valuable and stands out.

### Game Variables

```basic
110 REM Game variables
120 LET SCORE=0
130 LET ITEMS=5
140 PRINT AT 0,0;"Collect all stars!"
150 PRINT AT 1,0;"Score: ";SCORE;"/";ITEMS
```

SCORE starts at 0, increments with each collection. ITEMS stores total count (5)—used for win condition check.

Display format: "Score: 0/5" shows current progress. Player always knows how many remain. Creates clear goal.

**Why separate ITEMS variable?** Could hard-code the number 5 in comparisons and displays. But ITEMS makes code flexible—change one line (130) to add more collectibles. All comparisons and displays automatically adjust.

### The Collection Pattern

```basic
300 REM Check destination
310 LET CH$=SCREEN$(NY,NX)
320 IF CH$="*" THEN GOSUB 1000
330 IF CH$=" " THEN GOSUB 2000
```

Read destination character. If star → call collection subroutine. If space → call movement subroutine. If wall (from future mazes) → do nothing.

**Pattern evolution:** Previous lesson checked for walls and goal. This lesson checks for collectibles and empty space. Same SCREEN$ technique, different character tests. Extensible pattern—add more IF statements for more object types.

```basic
1000 REM Collect item
1010 PRINT AT PY,PX;" "
1020 LET PX=NX: LET PY=NY
1030 LET SCORE=SCORE+1
1040 PRINT AT 1,7;"        "
1050 PRINT AT 1,7;SCORE;"/";ITEMS
1060 INK 7
1070 PRINT AT PY,PX;"@"
1080 BEEP 0.05,10
1090 RETURN
```

Collection subroutine at line 1000. Handles everything related to picking up items:

1. **Erase player** at old position (line 1010)
2. **Move to item location** - Copy NX, NY to PX, PY (line 1020)
3. **Increment score** (line 1030)
4. **Update display** - Clear old score with spaces (line 1040), print new score (line 1050)
5. **Ensure correct colour** - Set INK 7 (line 1060) before drawing player
6. **Draw player at new position** (line 1070)—overwrites the star
7. **Sound feedback** - Quick beep confirms collection (line 1080)

**Critical detail:** Player moves *onto* the item's position. Item disappears because player character (@) overwrites it. No need to explicitly erase item—it's replaced by player.

### Updating the Score Display

```basic
1040 PRINT AT 1,7;"        "
1050 PRINT AT 1,7;SCORE;"/";ITEMS
```

Line 1040 prints eight spaces at position (1,7)—clears old score digits. Without this, digits overlap. Collecting item 2: "Score: 2/5" overwrites "Score: 1/5" cleanly. But if score goes from 9 to 10, without spaces you'd see "Score: 10/105"—the 9 remains visible as a 0.

**Always clear before updating numerical displays.** Print spaces wide enough for maximum possible value (score could reach 99? Print two spaces minimum).

Line 1050 prints new score. Positioned at same location (1,7)—column 7 starts after "Score: " text.

### Sound Feedback

```basic
1080 BEEP 0.05,10
```

Brief beep (0.05 seconds, pitch 10) confirms collection. Instant feedback—player knows collection registered even before checking score display.

**Duration:** 0.05 = 50 milliseconds. Quick ping. Longer durations (0.5 seconds) feel sluggish—player collects three items before first beep finishes. Keep collection sounds short.

**Pitch:** 10 = positive, satisfying tone. Higher pitches (15-20) sound brighter. Lower pitches (0-5) sound dull. Experiment to find right feel.

### Win Detection

```basic
340 REM Check win
350 IF SCORE=ITEMS THEN GOSUB 3000
360 GO TO 210
```

After every collection check, test if score equals total items. Only way SCORE changes is through collection subroutine—checking after movement (line 2000) wastes CPU cycles.

**Placement matters:** Check win *after* collection, not during. Let subroutine 1000 complete fully—update score, update display, play sound. Then check win. Otherwise victory screen appears before final score displays.

### Victory Screen

```basic
3000 REM Win condition
3010 CLS
3020 PAPER 0: INK 2: BRIGHT 1
3030 PRINT AT 10,8;"CONGRATULATIONS!"
3040 PRINT AT 12,6;"You collected all stars!"
3050 BEEP 0.5,0: BEEP 0.5,5: BEEP 0.5,10
3060 PAUSE 0
3070 STOP
```

Clear screen, celebrate victory:

1. **Set colours** - Red text (INK 2), BRIGHT 1 makes it vivid
2. **Center message** - Position carefully for visual impact
3. **Victory fanfare** - Three ascending beeps (pitches 0, 5, 10)
4. **Wait for key** - PAUSE 0 holds screen until player presses any key
5. **End program** - STOP returns to BASIC

**BRIGHT attribute:** Makes colours more vivid. BRIGHT 0 = normal, BRIGHT 1 = intense. Victory deserves emphasis—bright red text stands out.

**Fanfare pattern:** Ascending pitches (0→5→10) sound triumphant. Each beep 0.5 seconds creates musical phrase. Compare to single beep—multiple notes feel more celebratory.

## Understanding the Complete Game

### Maze with Multiple Rooms

```basic
130 REM Vertical walls
140 FOR Y=6 TO 18
150 PRINT AT Y,10;CHR$ 127
160 PRINT AT Y,20;CHR$ 127
170 NEXT Y
180 REM Horizontal walls
190 FOR X=5 TO 15
200 PRINT AT 10,X;CHR$ 127
210 NEXT X
220 FOR X=15 TO 25
230 PRINT AT 15,X;CHR$ 127
240 NEXT X
```

Creates grid layout: two vertical walls (columns 10, 20), two horizontal walls (rows 10, 15). Forms four distinct areas:
- Top-left quadrant (rows 3-9, columns 1-9)
- Top-right quadrant (rows 3-9, columns 21-30)
- Bottom-left quadrant (rows 16-20, columns 1-9)
- Bottom-right quadrant (rows 16-20, columns 21-30)
- Center area (rows 11-14, columns 11-19)

```basic
250 REM Create gaps
260 PRINT AT 12,10;" "
270 PRINT AT 15,20;" "
280 PRINT AT 10,12;" "
290 PRINT AT 15,18;" "
```

Strategic gaps connect areas. Gap at (12,10) connects left side to center. Gap at (15,20) connects right side to center. Players must navigate through specific passages—creates puzzle element.

**Maze design principle:** More walls = more challenge. More gaps = less challenge. Balance determines difficulty. Too few gaps creates frustration (player searches for route). Too many gaps removes challenge (player walks straight to goals).

### Strategic Treasure Placement

```basic
300 REM Place treasures
310 INK 3
320 PRINT AT 5,5;"$"
330 PRINT AT 5,25;"$"
340 PRINT AT 18,5;"$"
350 PRINT AT 18,25;"$"
360 PRINT AT 8,15;"$"
370 PRINT AT 17,15;"$"
380 PRINT AT 12,3;"$"
390 PRINT AT 12,28;"$"
```

Eight treasures, each in different location:
- Four in corners (5,5), (5,25), (18,5), (18,25) - forces exploration of all quadrants
- Two in center passages (8,15), (17,15) - rewards route finding
- Two against edges (12,3), (12,28) - requires backtracking

**Distribution strategy:** No treasure in starting area. Player must move to score. Treasures scattered—forces complete maze exploration. Creates natural gameplay arc: find route, collect treasure, backtrack, find new route, repeat.

**Cyan treasures** (INK 3) stand out against walls. Visual hierarchy—walls blend into background, treasures pop.

### Move Tracking System

```basic
430 LET MOVES=0
...
1040 LET MOVES=MOVES+1
2030 LET MOVES=MOVES+1
```

MOVES variable increments in *both* collection subroutine (1000) and movement subroutine (2000). Every player action counts—collecting treasure costs a move, walking to empty space costs a move.

**Why track moves?** Creates efficiency metric. Two players can both collect all treasures. Winner: fewest moves. Transforms exploration game into optimization puzzle. Adds replayability—"Can I beat my record?"

**Display update in movement:**
```basic
2040 PRINT AT 1,21;MOVES;"  "
```

Updates only MOVES portion of status line. Doesn't redraw entire "Gold: X/Y Moves: Z" string—just changes number. Faster, less screen flicker.

### Efficiency Rating

```basic
3070 PRINT AT 12,6;"Total moves: ";MOVES
3080 LET EFFICIENCY=INT (MOVES/ITEMS)
3090 PRINT AT 14,4;"Moves per treasure: ";EFFICIENCY
3100 IF EFFICIENCY&lt;10 THEN PRINT AT 16,9;"EXCELLENT!"
3110 IF EFFICIENCY>=10 AND EFFICIENCY&lt;15 THEN PRINT AT 16,11;"GOOD!"
3120 IF EFFICIENCY>=15 THEN PRINT AT 16,13;"TRY AGAIN!"
```

Calculates moves per treasure. Eight treasures collected in 64 moves = 8 moves per treasure. Collected in 120 moves = 15 moves per treasure.

**INT function:** Converts division result to integer. INT(73/8) = INT(9.125) = 9. Drops decimal portion.

**Performance bands:**
- &lt;10 moves/treasure = EXCELLENT (very efficient, found optimal routes)
- 10-14 moves/treasure = GOOD (solid performance, minor backtracking)
- ≥15 moves/treasure = TRY AGAIN (excessive wandering, poor planning)

**Game design insight:** Rating creates goals beyond "finish game." First playthrough: complete it. Second playthrough: complete it efficiently. Third playthrough: perfect run. Simple addition (efficiency calculation) multiplies engagement.

### Four-Note Fanfare

```basic
3130 BEEP 0.3,0: BEEP 0.3,5: BEEP 0.3,10: BEEP 0.3,15
```

Victory gets longer, more complex fanfare than simple collection game. Four ascending notes (pitches 0, 5, 10, 15), each 0.3 seconds. Total duration 1.2 seconds—feels substantial. Creates sense of achievement.

Compare to collection beep (0.05 seconds, one note). Small achievement = small sound. Big achievement = big sound. Audio feedback matches action significance.

## How Scoring Systems Scale

### Basic Pattern

Every Spectrum game with scoring uses this pattern:

```basic
REM 1. Initialize score
LET SCORE=0

REM 2. Check for scoring event
IF event_happened THEN GOSUB score_subroutine

REM 3. Increment score
LET SCORE=SCORE+points

REM 4. Update display
PRINT AT y,x;SCORE
```

**Pac-Man:** Check for dots with SCREEN$, score += 10
**Manic Miner:** Check for keys with SCREEN$, score += 100
**Jet Set Willy:** Check for items, score += 1
**Chuckie Egg:** Check for eggs, score += 100, check for bonus items, score += 500

### Multiple Item Types

Extend with different point values:

```basic
590 LET CH$=SCREEN$(NY,NX)
600 IF CH$="$" THEN LET POINTS=10: GOSUB 1000
610 IF CH$="*" THEN LET POINTS=50: GOSUB 1000
620 IF CH$="!" THEN LET POINTS=100: GOSUB 1000
...
1000 REM Collect item
1010 PRINT AT PY,PX;" "
1020 LET PX=NX: LET PY=NY
1030 LET SCORE=SCORE+POINTS
```

POINTS variable set based on item type. Collection subroutine uses POINTS—one subroutine handles all item types. Dollar = 10 points, star = 50, exclamation = 100. Visual variety, strategic choice (collect rare valuable items or common cheap items first?).

### Lives System

Add failure states:

```basic
10 LET LIVES=3
...
600 IF CH$="X" THEN GOSUB 5000
...
5000 REM Lose life
5010 LET LIVES=LIVES-1
5020 PRINT AT 0,24;"Lives: ";LIVES
5030 IF LIVES=0 THEN GOSUB 6000
5040 REM Reset player position
5050 LET PX=15: LET PY=10
5060 RETURN
6000 REM Game over
6010 CLS
6020 PRINT AT 11,10;"GAME OVER"
6030 PRINT AT 13,8;"Final score: ";SCORE
6040 PAUSE 0
6050 STOP
```

LIVES decrements on hazard contact. Zero lives triggers game over. Creates risk/reward balance—collect treasures near hazards for points, but risk losing progress.

### High Score Tracking

Add competition:

```basic
10 LET HIGHSCORE=0
...
3080 IF SCORE>HIGHSCORE THEN LET HIGHSCORE=SCORE
3090 PRINT AT 15,6;"High score: ";HIGHSCORE
```

HIGHSCORE variable persists across games (until program stopped). Each victory checks if score beats record. Creates lasting goal—not just complete game, but *best* completion. Simple variable, powerful motivation.

## Experiment: Time Bonus

Reward speed:

```basic
430 LET TIME=500
...
1045 LET TIME=TIME-1
2035 LET TIME=TIME-1
...
3075 LET BONUS=TIME*10
3076 LET SCORE=SCORE+BONUS
3077 PRINT AT 13,6;"Time bonus: ";BONUS
```

TIME decrements each move. Remaining time at victory multiplied by 10 = bonus points. Fast completion = high bonus. Slow completion = low bonus. Adds urgency—encourages efficient routes.

## Experiment: Item Countdown

Show items remaining:

```basic
470 PRINT AT 1,0;"Remaining: ";ITEMS-SCORE
...
1055 PRINT AT 1,11;"  "
1056 PRINT AT 1,11;ITEMS-SCORE
```

Display ITEMS-SCORE instead of "X/Y". Shows how many left to collect. Psychological difference—"5 remaining" creates urgency, "3/8 collected" feels slower. Same information, different framing.

## Why This Pattern Matters

**Foundation of game design:**

The collect-and-score pattern underlies every goal-oriented game:

- **Treasure hunt:** Collect gold, count treasures
- **Platformer:** Collect rings/coins, count score
- **Puzzle:** Match gems, count moves
- **Adventure:** Gather keys, track inventory
- **Shooter:** Destroy enemies, count kills

Pattern scales to any genre. Detect object (SCREEN$), modify state (SCORE=SCORE+1), check goal (IF SCORE=TARGET), provide feedback (BEEP, PRINT).

**Core game loop emerges:**
1. Present challenge (items to collect)
2. Provide tools (movement, collision)
3. Track progress (score display)
4. Define victory (all items collected)
5. Reward completion (victory screen, rating)

This lesson completes the action game foundation. You have:
- Movement (INKEY$, position tracking)
- World interaction (SCREEN$ collision)
- Goal tracking (scoring variables)
- Feedback systems (BEEP, display updates)
- Win conditions (completion checks)

Every other mechanic builds on this base. Enemies? Check SCREEN$ for enemy character, handle collision. Weapons? Check SCREEN$ for hit target, increment kill count. Power-ups? Check SCREEN$ for item, modify player state. The pattern repeats infinitely.

**Collection Pattern:**
```basic
Place items on screen (PRINT AT with item characters)
Initialize counters (SCORE=0, ITEMS=count)
Game loop:
  Read input (INKEY$)
  Check destination (SCREEN$)
  If item → collect (increment, remove, feedback)
  If space → move
  Check win (SCORE=ITEMS)
Victory screen (celebrate, display stats)
```

**Display Update:**
```basic
Print spaces to clear (PRINT AT y,x;"        ")
Print new value (PRINT AT y,x;SCORE)
```

**Efficiency Rating:**
```basic
Calculate ratio (MOVES/ITEMS)
Convert to integer (INT function)
Conditional messages based on performance bands
```
