You've learnt READ and DATA for storing quiz questions. But what happens when you want to run the quiz twice? Or create multiple categories? READ marches forward through DATA—once you've read everything, it's gone. RESTORE solves this: reset the READ pointer back to the start. Read DATA again. Build menu systems. Track high scores across multiple games.

Every quiz compilation on the Spectrum—Trivial Pursuit, Brain Teaser, School Quiz—uses RESTORE to replay questions. It's how menus work: read options, display them, RESTORE, read again for different sections. Combined with GOSUB, you create structured programs with reusable DATA.

## The One-Minute Tour

- **RESTORE** resets READ pointer to first DATA statement
- **RESTORE linenumber** jumps to specific DATA line
- Use RESTORE to replay DATA multiple times
- Build menu systems with category selection
- Track high scores with simple comparison
- Structure programs with logical line number ranges

## Understanding RESTORE

Type this simple demonstration:

```basic
10 REM RESTORE Demo
20 REM Shows how RESTORE works
30 CLS
40 PRINT AT 3,6;"FIRST READ THROUGH:"
50 FOR I=1 TO 3
60 READ N$
70 PRINT AT 5+I,8;N$
80 NEXT I
90 PAUSE 150
100 CLS
110 PRINT AT 3,6;"SECOND READ THROUGH:"
120 RESTORE
130 FOR I=1 TO 3
140 READ N$
150 PRINT AT 5+I,8;N$
160 NEXT I
170 PAUSE 0
200 DATA "Alice","Bob","Charlie"
```

**Run this** and watch it read the same DATA twice!

## How RESTORE Works

### First Read

```basic
50 FOR I=1 TO 3
60 READ N$
70 PRINT AT 5+I,8;N$
80 NEXT I
```

Loop three times, reading one name per iteration:
- Iteration 1: READ "Alice"
- Iteration 2: READ "Bob"
- Iteration 3: READ "Charlie"

After line 80, the READ pointer points past "Charlie"—there's no more DATA to read.

### Resetting with RESTORE

```basic
120 RESTORE
130 FOR I=1 TO 3
140 READ N$
```

RESTORE resets the internal DATA pointer back to line 200 (first DATA statement). Now READ starts over: "Alice", "Bob", "Charlie" again. Without RESTORE, line 140 would cause "Out of DATA" error.

**Key insight:** RESTORE doesn't change DATA. It changes where READ looks. Same data, fresh start.

## Building Quiz Master

Create a complete quiz system with categories and high scores:

```basic
10 REM Quiz Master
20 REM Multiple categories with high scores
30 LET HIGHSCORE=0
40 CLS
50 PRINT AT 2,9;"=== QUIZ MASTER ==="
60 PRINT AT 5,6;"High Score: ";HIGHSCORE
70 PRINT AT 8,7;"Choose a category:"
80 PRINT AT 10,9;"1. Animals"
90 PRINT AT 11,9;"2. Geography"
100 PRINT AT 12,9;"3. Science"
110 PRINT AT 14,9;"Q. Quit"
120 PRINT AT 17,2;"Enter your choice: ";
130 INPUT CH$
140 IF CH$="1" THEN GOSUB 1000
150 IF CH$="2" THEN GOSUB 2000
160 IF CH$="3" THEN GOSUB 3000
170 IF CH$="Q" OR CH$="q" THEN STOP
180 GO TO 40
1000 REM Animals Quiz
1010 RESTORE 9000
1020 GOSUB 5000
1030 RETURN
2000 REM Geography Quiz
2010 RESTORE 9100
2020 GOSUB 5000
2030 RETURN
3000 REM Science Quiz
3010 RESTORE 9200
3020 GOSUB 5000
3030 RETURN
5000 REM Quiz Engine
5010 LET SCORE=0
5020 CLS
5030 FOR QN=1 TO 3
5040 READ QU$,ANS$
5050 PRINT AT 5,2;"Question ";QN;" of 3"
5060 PRINT AT 7,0;QU$
5070 PRINT AT 10,2;"Your answer:"
5080 INPUT A$
5090 IF A$=ANS$ THEN LET SCORE=SCORE+1: PRINT AT 15,6;"Correct!": PAUSE 50
5100 IF A$<>ANS$ THEN PRINT AT 15,4;"Wrong! It was ";ANS$: PAUSE 80
5110 CLS
5120 NEXT QN
5130 PRINT AT 8,4;"You scored: ";SCORE;" out of 3"
5140 IF SCORE>HIGHSCORE THEN LET HIGHSCORE=SCORE: PRINT AT 10,4;"NEW HIGH SCORE!"
5150 PAUSE 150
5160 RETURN
9000 REM Animals DATA
9010 DATA "Biggest mammal?","WHALE"
9020 DATA "Fastest land animal?","CHEETAH"
9030 DATA "Tallest animal?","GIRAFFE"
9100 REM Geography DATA
9110 DATA "Capital of France?","PARIS"
9120 DATA "Longest river?","NILE"
9130 DATA "Largest continent?","ASIA"
9200 REM Science DATA
9210 DATA "Boiling point of water?","100"
9220 DATA "Chemical symbol for gold?","AU"
9230 DATA "Planet closest to sun?","MERCURY"
```

**Run this** and try different categories!

## Program Architecture

### Menu System (Lines 40-180)

```basic
40 CLS
50 PRINT AT 2,9;"=== QUIZ MASTER ==="
...
130 INPUT CH$
140 IF CH$="1" THEN GOSUB 1000
...
180 GO TO 40
```

Classic menu loop:
1. Display title and high score
2. Show options
3. Get user input
4. Branch to appropriate subroutine
5. Return to menu (line 180)

Menu never exits—only STOP (line 170) ends the program. Player can take multiple quizzes, watching high score climb.

### Category Subroutines (Lines 1000-3999)

```basic
1000 REM Animals Quiz
1010 RESTORE 9000
1020 GOSUB 5000
1030 RETURN
```

Each category:
1. RESTORE to its DATA section
2. Call shared quiz engine (5000)
3. RETURN to menu

**Three categories, one engine.** Code reuse at its finest.

### RESTORE with Line Numbers

```basic
1010 RESTORE 9000
```

`RESTORE 9000` doesn't just reset to the first DATA—it resets to line 9000 specifically. This lets you have multiple DATA sections and jump to the one you need.

**Animals quiz** → RESTORE 9000 → reads lines 9010-9030
**Geography quiz** → RESTORE 9100 → reads lines 9110-9130
**Science quiz** → RESTORE 9200 → reads lines 9210-9230

Same READ commands (line 5040), different DATA. RESTORE selects which section to use.

### Quiz Engine (Lines 5000-5999)

```basic
5000 REM Quiz Engine
5010 LET SCORE=0
5020 CLS
5030 FOR QN=1 TO 3
5040 READ QU$,ANS$
...
5160 RETURN
```

Reusable quiz logic:
- Initialise score
- Loop through 3 questions
- READ from wherever RESTORE pointed
- Check answers, update score
- Compare with high score
- RETURN to category subroutine

One engine serves three categories. Want a fourth? Add subroutine 4000, RESTORE 9300, add DATA at 9300. Engine works unchanged.

### High Score Tracking

```basic
30 LET HIGHSCORE=0
...
5140 IF SCORE>HIGHSCORE THEN LET HIGHSCORE=SCORE: PRINT AT 10,4;"NEW HIGH SCORE!"
```

HIGHSCORE initialised once (line 30), persists across quizzes. After each quiz, compare SCORE with HIGHSCORE. If SCORE is better, update HIGHSCORE and celebrate.

**Persistence:** HIGHSCORE survives RETURN and GOSUB. Variables don't reset until program stops or you manually change them.

## Structured Programming

Notice the line number organisation:

**40-180:** Main menu
**1000-3999:** Category handlers
**5000-5999:** Quiz engine
**9000+:** DATA storage

This isn't accidental. Professional Spectrum programmers used line number ranges as "namespaces"—each section has its own thousands block. Makes programs readable, maintainable, extendable.

**Conventions:**
- 10-99: Initialisation
- 100-999: Main logic
- 1000-8999: Subroutines (one per thousand)
- 9000+: DATA statements

Follow these patterns, and your programs stay organised as they grow.

## Why RESTORE Matters

**Quiz games:** Replay questions without retyping DATA. Try again, different category, same engine.

**Level systems:** RESTORE level data to replay levels or return to menus. Store all levels in DATA, RESTORE to whichever you need.

**High score tables:** Read through DATA to display scores, RESTORE to read again for updates.

**Text adventures:** RESTORE room descriptions, item lists, vocabulary. Same DATA, accessed repeatedly as player explores.

The Hobbit stores its entire 1000+ word vocabulary in DATA. Parser RESTOREs and reads through looking for matches. Repton stores level maps in DATA—RESTORE to load level. Elite's trading system READs market prices—RESTORE for new star system.

## Common Mistakes

**Forgetting RESTORE:**
```basic
10 READ N$
20 PRINT N$
30 GO TO 10
DATA "Test"
```

"Out of DATA in line 10" after first READ. Need RESTORE in the loop:

```basic
10 RESTORE
20 READ N$
30 PRINT N$
40 GO TO 10
```

**Wrong RESTORE target:**
```basic
1010 RESTORE 9999
```

If line 9999 doesn't exist or isn't DATA, undefined behaviour. Always RESTORE to existing DATA line.

**Not returning from GOSUB:**
```basic
1000 RESTORE 9000
1010 GOSUB 5000
REM Missing RETURN!
```

Program falls through to next subroutine. Always RETURN from GOSUB.

## Quick Reference: RESTORE

| Command | Purpose | Example |
|---------|---------|---------|
| `RESTORE` | Reset to first DATA | `RESTORE` |
| `RESTORE line` | Reset to specific DATA | `RESTORE 9000` |
| `GOSUB line` | Call subroutine | `GOSUB 1000` |
| `RETURN` | Return from subroutine | `RETURN` |

**RESTORE Behaviour:**
- Resets internal READ pointer
- Doesn't change DATA contents
- Can target specific DATA line
- Multiple RESTOREs allowed in same program
- Works with READ in any subroutine

**Program Structure Pattern:**
```basic
10-90:     Initialisation
100-900:   Main loop/menu
1000+:     Subroutines (1000s blocks)
9000+:     DATA statements
```

**High Score Pattern:**
```basic
10 LET HIGH=0
...
100 IF SCORE>HIGH THEN LET HIGH=SCORE
110 PRINT "Record: ";HIGH
```
