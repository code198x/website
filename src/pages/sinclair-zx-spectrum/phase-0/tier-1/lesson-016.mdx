## Complete Game Structure

First, the simpler version showing the architecture:

```basic
10 REM Simple Survivor
20 REM Complete game structure demo
30 REM Title screen
40 PAPER 0: INK 6: BORDER 1: CLS
50 BRIGHT 1
60 PRINT AT 8,6;"SPECTRUM SURVIVOR"
70 BRIGHT 0
80 PRINT AT 12,5;"Collect stars! Avoid enemy!"
90 PRINT AT 16,6;"Press any key to start"
100 PAUSE 0
110 REM Initialize game
120 CLS
130 LET SCORE=0
140 LET LIVES=3
150 LET ITEMS=5
160 REM Place items
170 INK 3
180 PRINT AT 5,8;"*"
190 PRINT AT 5,22;"*"
200 PRINT AT 15,8;"*"
210 PRINT AT 15,22;"*"
220 PRINT AT 10,15;"*"
230 REM Player start
240 LET PX=15: LET PY=10
250 INK 7
260 PRINT AT PY,PX;"@"
270 REM Enemy start
280 LET EX=5: LET EY=5
290 INK 2
300 PRINT AT EY,EX;"!"
310 REM Display status
320 PRINT AT 0,0;"Score: ";SCORE;"/";ITEMS
330 PRINT AT 0,20;"Lives: ";LIVES
340 REM Game loop
350 REM Player input
360 LET NX=PX: LET NY=PY
370 LET K$=INKEY$
380 IF K$="q" AND NY>1 THEN LET NY=NY-1
390 IF K$="a" AND NY&lt;21 THEN LET NY=NY+1
400 IF K$="o" AND NX>0 THEN LET NX=NX-1
410 IF K$="p" AND NX&lt;31 THEN LET NX=NX+1
420 REM Check player destination
430 LET CH$=SCREEN$(NY,NX)
440 IF CH$="*" THEN GOSUB 1000
450 IF CH$=" " THEN GOSUB 2000
460 REM Enemy AI
470 LET OEX=EX: LET OEY=EY
480 IF EX<PX THEN LET EX=EX+1
490 IF EX>PX THEN LET EX=EX-1
500 IF EY<PY THEN LET EY=EY+1
510 IF EY>PY THEN LET EY=EY-1
520 PRINT AT OEY,OEX;" "
530 INK 2
540 PRINT AT EY,EX;"!"
550 REM Check collision
560 IF PX=EX AND PY=EY THEN GOSUB 3000
570 REM Check win
580 IF SCORE=ITEMS THEN GOSUB 4000
590 REM Check lives
600 IF LIVES=0 THEN GOSUB 5000
610 PAUSE 3
620 GO TO 350
1000 REM Collect item
1010 PRINT AT PY,PX;" "
1020 LET PX=NX: LET PY=NY
1030 LET SCORE=SCORE+1
1040 PRINT AT 0,7;SCORE;"/";ITEMS
1050 INK 7
1060 PRINT AT PY,PX;"@"
1070 BEEP 0.05,15
1080 RETURN
2000 REM Move player
2010 PRINT AT PY,PX;" "
2020 LET PX=NX: LET PY=NY
2030 PRINT AT PY,PX;"@"
2040 RETURN
3000 REM Lose life
3010 LET LIVES=LIVES-1
3020 PRINT AT 0,27;LIVES
3030 BEEP 0.2,3
3040 REM Reset if lives remain
3050 IF LIVES>0 THEN GOSUB 6000
3060 RETURN
4000 REM Victory
4010 CLS
4020 INK 6: BRIGHT 1
4030 PRINT AT 9,8;"YOU SURVIVED!"
4040 INK 7: BRIGHT 0
4050 PRINT AT 11,6;"All stars collected!"
4060 PRINT AT 13,9;"Lives left: ";LIVES
4070 BEEP 0.3,10: BEEP 0.3,15: BEEP 0.3,20
4080 PAUSE 0
4090 STOP
5000 REM Game over
5010 CLS
5020 INK 2: BRIGHT 1
5030 PRINT AT 10,9;"GAME OVER!"
5040 INK 7: BRIGHT 0
5050 PRINT AT 12,6;"Final score: ";SCORE;"/";ITEMS
5060 BEEP 1,0
5070 PAUSE 0
5080 STOP
6000 REM Reset positions
6010 PRINT AT PY,PX;" "
6020 PRINT AT EY,EX;" "
6030 LET PX=15: LET PY=10
6040 LET EX=5: LET EY=5
6050 INK 7
6060 PRINT AT PY,PX;"@"
6070 INK 2
6080 PRINT AT EY,EX;"!"
6090 PAUSE 50
6100 RETURN
```

## Understanding Complete Game Architecture

### Three-Phase Structure

```basic
30 REM Title screen
...
110 REM Initialize game
...
340 REM Game loop
...
4000 REM Victory
...
5000 REM Game over
```

Professional games have distinct phases:

**Phase 1: Introduction (lines 30-100)**
- Clear screen, set colours
- Display title (BRIGHT for emphasis)
- Show instructions
- Wait for player (PAUSE 0)

**Phase 2: Setup (lines 110-330)**
- Clear screen for gameplay
- Initialize variables (SCORE=0, LIVES=3, ITEMS=5)
- Place game objects (items, player, enemies)
- Display status information

**Phase 3: Gameplay (lines 340-620)**
- Main loop runs continuously
- Handle player input
- Update enemy AI
- Check collisions and win conditions
- Branch to endings when appropriate

**Phase 4: Conclusion (lines 4000+ and 5000+)**
- Victory screen (collected all items)
- Game over screen (lost all lives)
- Display final stats
- Wait for acknowledgment
- End program (STOP)

This structure isn't cosmetic—it's essential. Players need context (title), challenge (gameplay), and closure (ending). Without all three, game feels incomplete.

### Centralized Game Loop

```basic
340 REM Game loop
350 REM Player input
...
460 REM Enemy AI
...
550 REM Check collision
...
570 REM Check win
...
590 REM Check lives
...
610 PAUSE 3
620 GO TO 350
```

Everything happens in one loop. Each frame:
1. Read player input → Update player position
2. Run enemy AI → Update enemy position
3. Check if player caught enemy → Handle collision
4. Check if all items collected → Branch to victory
5. Check if lives depleted → Branch to game over
6. Pause for pacing → Loop back

Clean, predictable, maintainable. Adding new mechanics—just insert new section in loop. Want power-ups? Add check after item collection. Want time limit? Add timer decrement. The loop scales infinitely.

### Conditional Endings

```basic
3050 IF LIVES>0 THEN GOSUB 6000
3060 RETURN
```

Lose life subroutine (3000) decrements LIVES. If LIVES still positive, call reset subroutine (6000)—restore positions, continue playing. If LIVES zero, skip reset, return to main loop. Next iteration, line 600 catches zero lives, branches to game over.

**Pattern:** Don't end game immediately in collision handler. Let main loop check conditions and branch appropriately. Keeps control flow centralized, prevents spaghetti branching.

### Victory vs Game Over

```basic
4000 REM Victory
4010 CLS
4020 INK 6: BRIGHT 1
4030 PRINT AT 9,8;"YOU SURVIVED!"
...
5000 REM Game over
5010 CLS
5020 INK 2: BRIGHT 1
5030 PRINT AT 10,9;"GAME OVER!"
```

Different endings for different outcomes. Victory: cyan BRIGHT text, triumphant fanfare, displays remaining lives. Game Over: red BRIGHT text, low-pitched beep, shows final score.

Tonally distinct. Victory feels rewarding. Game over feels definitive but not punishing—shows progress made, encourages retry.

**Design principle:** Endings should match emotional tone. Victory = bright, celebratory. Defeat = somber, respectful of effort.

## The Complete Synthesis Game

Now the full version with maze, two enemies, and increasing difficulty. Due to length, here are the key additions:

**Title Screen Enhancement:**
```basic
40 PAPER 0: INK 6: BORDER 1: CLS
50 BRIGHT 1
60 PRINT AT 6,5;"** SPECTRUM SURVIVOR **"
70 BRIGHT 0
80 INK 7
90 PRINT AT 10,4;"Collect all gold pieces"
100 PRINT AT 11,4;"Avoid the chasers!"
110 PRINT AT 14,4;"Controls: Q/A/O/P to move"
120 PRINT AT 17,4;"Good luck... you'll need it"
130 INK 2
140 PRINT AT 20,6;"Press any key to begin"
```

Professional presentation. Title emphasized with **asterisks** and BRIGHT. Clear instructions. Atmospheric final line. Red "Press any key" draws attention.

**Maze Integration:**
The complete code draws full maze using same techniques from lesson 13—borders, internal walls, strategic gaps. See full code listing in spectrum-survivor.bas.

**Two Independent Enemies:**
```basic
820 REM Enemy 1 AI
830 LET OE1X=E1X: LET OE1Y=E1Y
840 IF E1X<PX THEN LET NE1X=E1X+1: ELSE LET NE1X=E1X
...
920 REM Enemy 2 AI
930 LET OE2X=E2X: LET OE2Y=E2Y
940 IF E2X<PX THEN LET NE2X=E2X+1: ELSE LET NE2X=E2X
...
1020 REM Check collisions
1030 IF PX=E1X AND PY=E1Y THEN GOSUB 3000
1040 IF PX=E2X AND PY=E2Y THEN GOSUB 3000
```

Each enemy has own variables (E1X/E1Y and E2X/E2Y). Each runs same chase algorithm independently. Check collision with each. Two enemies create pincer attacks—exponentially harder than single chaser.

**Increasing Difficulty:**
```basic
1000 REM Collect gold
...
1080 REM Increase difficulty
1090 IF SCORE=3 AND SPEED>1 THEN LET SPEED=SPEED-1
```

SPEED variable controls PAUSE duration. Starts at 3 (easier pace). After collecting third gold piece, decreases to 2 (faster gameplay). Creates progression—comfortable start, intense finish.

**Enhanced Endings:**
```basic
4000 REM Victory
...
4080 PRINT AT 15,3;"You are a Spectrum champion!"
...
5000 REM Game over
...
5070 IF SCORE>=4 THEN PRINT AT 15,7;"So close! Try again?"
5080 IF SCORE&lt;4 THEN PRINT AT 15,5;"Keep trying, survivor!"
```

Victory celebrates achievement. Game over provides contextual encouragement—different messages based on performance. Collected 4+ gold? "So close!" Collected fewer? "Keep trying!" Personalizes experience.

## Why This Structure Matters

**This game demonstrates professional practices:**

**1. Clear Separation of Concerns**
- Title screen code separate from gameplay code
- Each system in own subroutine
- Easy to modify individual parts

**2. Scalability**
- Want third enemy? Copy E2 AI section, rename E3
- Want more items? Add PRINT AT statements
- Want power-ups? Add new item check in loop

**3. Player Experience**
- Introduction sets expectations
- Gameplay delivers challenge
- Endings provide closure
- Status display shows progress
- Sound feedback confirms actions

**4. Maintainability**
- Subroutines organized by thousands (1000s collect, 2000s move, etc.)
- Variables use consistent naming (E1X, E2X, not EX, FX)
- Comments explain purpose
- Line number gaps allow insertions

**This is how professional Spectrum games were structured.** Commercial titles used same patterns—title screen, game loop, subroutine organization, multiple endings. You've learnt the foundation.

## Experiment: Restart Option

Add replay without RUN:

```basic
5100 PRINT AT 17,7;"Play again? (Y/N)"
5110 LET K$=INKEY$: IF K$="" THEN GO TO 5110
5120 IF K$="y" THEN RUN
5130 STOP
```

After game over, ask if player wants another round. Y key runs program from start. Creates arcade-style instant replay.

## Experiment: High Score Tracking

Add persistent high score:

```basic
15 LET HIGHSCORE=0
...
580 IF SCORE=ITEMS THEN LET FINALSCORE=SCORE*100+LIVES*50: GOSUB 4000
...
4050 PRINT AT 11,4;"Score: ";FINALSCORE
4060 IF FINALSCORE>HIGHSCORE THEN LET HIGHSCORE=FINALSCORE: PRINT AT 13,5;"NEW HIGH SCORE!"
4070 IF FINALSCORE<=HIGHSCORE THEN PRINT AT 13,3;"High score: ";HIGHSCORE
```

Score formula: items × 100 + remaining lives × 50. Perfect run (all items, 3 lives) = 600 + 150 = 750 points. Provides replayability goal.

## Experiment: Enemy Patterns

Make enemies patrol instead of constant chase:

```basic
825 LET E1MODE=1: REM 1=patrol, 2=chase
...
840 IF E1MODE=1 THEN GOSUB 7000
850 IF E1MODE=2 THEN GOSUB 7100
...
7000 REM Enemy 1 patrol
7010 IF E1X&lt;20 THEN LET E1X=E1X+1: ELSE LET E1X=5
7020 RETURN
7100 REM Enemy 1 chase
7110 IF E1X<PX THEN LET E1X=E1X+1
7120 IF E1X>PX THEN LET E1X=E1X-1
7130 RETURN
```

Enemy patrols predictably until triggered. When player enters area, switches to chase mode. Creates surprise, requires observation.
