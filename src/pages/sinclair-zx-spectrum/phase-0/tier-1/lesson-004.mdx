You've built interactive programs with INPUT and IF/THEN. But where do you store large amounts of information—quiz questions, high scores, level maps? Typing everything into variables is tedious. DATA statements solve this: embed lists of values directly in your program code. READ retrieves them on demand.

Every quiz game, adventure, or scoreboard on the Spectrum uses DATA. It's how Jet Set Willy stores room layouts, how The Hobbit manages vocabulary, how quiz games pack hundreds of questions into 48K of RAM. You'll build a complete quiz game with scoring and feedback.

## The One-Minute Tour

- **DATA** stores lists of values in your program
- **READ** fetches the next value from DATA
- DATA can mix strings and numbers
- READ processes DATA sequentially (in order)
- Use a counter to know when to stop reading
- RESTORE (next lesson) resets READ to the start

**Run this** and watch it build a formatted high scores table.

## How This Works

### DATA Statements

```basic
200 DATA "Alice",9500,12
210 DATA "Bob",8700,11
```

DATA stores values in your program. Think of it as a list of information waiting to be retrieved. The Spectrum treats all DATA lines as one continuous list, no matter their line numbers.

**Format rules:**
- Separate values with commas
- Strings need quotes if they contain commas: `DATA "Smith, John"`
- Numbers don't need quotes: `DATA 100,200,300`
- Mix types freely: `DATA "Alice",9500,12`

DATA doesn't execute—it's storage. Line 200 could be anywhere in your program; READ will still find it.

### READ Command

```basic
90 READ N$,S,L
```

READ fetches values from DATA in sequence. This line reads three values: a string into N$, a number into S, a number into L.

**First loop iteration:**
- READ gets "Alice" → N$
- READ gets 9500 → S
- READ gets 12 → L

**Second iteration:**
- READ gets "Bob" → N$
- READ gets 8700 → S
- READ gets 11 → L

READ remembers its position. Each READ advances through the DATA list. No need to manage pointers or indexes—the Spectrum handles it automatically.

### Sequential Processing

```basic
80 FOR I=1 TO 5
90 READ N$,S,L
...
120 NEXT I
```

Loop five times, reading three values per iteration. That's 15 values total, which matches our five DATA lines (5 × 3 = 15).

**Critical:** If READ runs out of DATA, you get "Out of DATA in line 90" error. Always count your DATA values and READ operations.

### TAB for Alignment

```basic
100 PRINT AT R,0;N$;TAB 14;S;TAB 23;L
```

TAB moves the print position to a specific column. `TAB 14` moves to column 14, `TAB 23` to column 23. This creates neat columns without manual spacing.

## Building a Quiz Game

Now create a complete quiz with scoring:

```basic
10 REM Brain Challenge
20 REM Quiz game with DATA/READ
30 LET SCORE=0
40 LET Q=0
50 CLS
60 PRINT AT 1,8;"=== BRAIN CHALLENGE ==="
70 PRINT AT 3,6;"Test your knowledge!"
80 PAUSE 100
90 CLS
100 READ QU$,ANS$
110 LET Q=Q+1
120 PRINT AT 5,2;"Question ";Q
130 PRINT AT 7,2;QU$
140 PRINT AT 10,2;"Your answer:"
150 INPUT A$
160 IF A$=ANS$ THEN GOSUB 1000
170 IF A$<>ANS$ THEN GOSUB 2000
180 PAUSE 80
190 IF Q&lt;5 THEN GO TO 90
200 CLS
210 PRINT AT 8,6;"QUIZ COMPLETE!"
220 PRINT AT 10,4;"You scored ";SCORE;" out of 5"
230 IF SCORE=5 THEN PRINT AT 12,7;"Perfect score!"
240 IF SCORE>=3 AND SCORE&lt;5 THEN PRINT AT 12,9;"Good job!"
250 IF SCORE&lt;3 THEN PRINT AT 12,8;"Keep trying!"
260 PAUSE 0
270 STOP
1000 REM Correct answer
1010 LET SCORE=SCORE+1
1020 PRINT AT 15,8;"Correct! Well done."
1030 RETURN
2000 REM Wrong answer
2010 PRINT AT 15,6;"Sorry, that's wrong."
2020 PRINT AT 16,4;"The answer was: ";ANS$
2030 RETURN
9000 DATA "Capital of UK?","LONDON"
9010 DATA "Colour of the sky?","BLUE"
9020 DATA "2 + 2 = ?","4"
9030 DATA "Largest ocean?","PACIFIC"
9040 DATA "Days in a week?","7"
```

**Run this** and answer the questions!

## Understanding Quiz Mechanics

### Question Loop

```basic
90 CLS
100 READ QU$,ANS$
110 LET Q=Q+1
...
190 IF Q&lt;5 THEN GO TO 90
```

Each iteration:
1. Clear screen
2. Read question and answer from DATA
3. Increment question counter
4. Display and process
5. Loop until Q=5

### Score Tracking

```basic
30 LET SCORE=0
...
1010 LET SCORE=SCORE+1
```

SCORE starts at 0. Correct answers add 1. Final score displayed at end. Simple integer arithmetic tracking progress.

### Answer Checking

```basic
160 IF A$=ANS$ THEN GOSUB 1000
170 IF A$<>ANS$ THEN GOSUB 2000
```

Compare user input A$ with stored answer ANS$. Exact match required—"LONDON" works, "London" doesn't. String comparison is case-sensitive on the Spectrum.

**Tip:** Convert inputs to uppercase with `LET A$=A$` after stripping spaces, or accept multiple answers in DATA.

### Performance Feedback

```basic
230 IF SCORE=5 THEN PRINT AT 12,7;"Perfect score!"
240 IF SCORE>=3 AND SCORE&lt;5 THEN PRINT AT 12,9;"Good job!"
250 IF SCORE&lt;3 THEN PRINT AT 12,8;"Keep trying!"
```

Tiered feedback based on performance. Perfect score, good (3-4), or needs improvement (&lt;3). Players love seeing how well they did.

## Why DATA Matters

**Memory efficiency:** 100 quiz questions fit in ~2K of RAM as DATA. Creating 100 variables would waste memory and be unmanageable.

**Easy updates:** Change questions by editing DATA lines. No code changes needed.

**Structured storage:** DATA keeps related information together. Question and answer stay paired.

**Loading speed:** DATA compiles into your program. No disk access, no delays. Instant quiz startup.

Adventures like The Hobbit store entire vocabularies in DATA. Parser reads words, matches them against DATA lists, understands commands. Platformers store level maps as DATA numbers representing tiles. DATA is the foundation of data-driven game design.

## How Hardware Processes DATA

**Z80 CPU:**
- Maintains DATA pointer (memory address of next unread value)
- READ instruction advances pointer through DATA
- String matching for quiz answers uses byte comparison

**Memory layout:**
- Program starts at 23755 ($5CCB)
- DATA embedded in program code
- READ pointer stored in system variables
- Each READ updates pointer automatically

**Speed:**
- READ is instant—no file system overhead
- String comparison fast (Z80 block compare)
- Entire quiz runs at full CPU speed

The Spectrum treats DATA as part of your program, not external data. Everything loads together, runs together. This simplicity made rapid game development possible in bedrooms across Britain in the 1980s.

## Common Mistakes

**Out of DATA error:**
```basic
FOR I=1 TO 10
READ N$
NEXT I
DATA "Alice","Bob"  REM Only 2 values, need 10!
```

Count your READ operations and DATA values. Must match exactly.

**Type mismatch:**
```basic
READ N$  REM Expects string
DATA 123  REM Provides number
```

READ into correct variable type. String variables end with $, numeric don't.

**Forgetting quotes with commas:**
```basic
DATA Smith, John  REM WRONG - seen as two values
DATA "Smith, John"  REM RIGHT - one string
```

Always quote strings containing commas or colons.

## Quick Reference: DATA and READ

| Command | Purpose | Example |
|---------|---------|---------|
| `DATA value1,value2,...` | Store values | `DATA "Alice",100,5` |
| `READ var1,var2,...` | Retrieve values | `READ N$,S,L` |
| `RESTORE` | Reset to DATA start | `RESTORE` (next lesson) |
| `TAB column` | Print at column | `PRINT TAB 10;"Text"` |

**DATA Rules:**
- Separate values with commas
- Strings need quotes if they contain commas
- Numbers don't need quotes
- Can mix strings and numbers
- Multiple DATA lines combine into one list

**READ Rules:**
- Gets values sequentially
- Must match DATA types (string to string, number to number)
- Advances automatically with each READ
- Causes error if no DATA remains

**Typical Pattern:**
```basic
10 FOR I=1 TO 5
20 READ NAME$,SCORE
30 PRINT NAME$;" scored ";SCORE
40 NEXT I
...
100 DATA "Alice",100
110 DATA "Bob",95
120 DATA "Charlie",87
130 DATA "Diana",92
140 DATA "Eve",78
```
