# Lesson 1: Into the Metal

## Touching the Hardware

In Phase 0, you typed `BORDER 2` and waited. The Spectrum thought about it, looked up what BORDER means, validated your number, called a ROM routine, and eventually... the border changed. This took about 20,000 clock cycles.

In assembly, you're going to do the same thing in under 50 clock cycles. No interpreter. No ROM routine. Just you, talking directly to the hardware.

Welcome to Z80 assembly language.

---

## The One-Minute Tour

- Assembly language is instructions the Z80 CPU understands directly
- The **A register** is your main workspace (think of it as your "main hand")
- **Port $FE** controls the border colour (among other things)
- The **OUT** instruction sends data to hardware
- Assembly executes ~400× faster than BASIC for simple operations
- Your code lives in RAM at **$8000** (32768) to avoid slowdown from screen contention

---

## From BASIC to Assembly

Remember this from Phase 0?

```basic
10 BORDER 2
```

Here's the assembly equivalent:

```nasm
        LD A,2              ; Load 2 into A register
        OUT ($FE),A         ; Send A to port $FE (border)
```

**What's happening:**

**BASIC approach:**
1. Interpreter reads "BORDER"
2. Looks up command in ROM table
3. Validates parameter (is 2 a valid colour?)
4. Calls ROM routine at $2294
5. ROM routine does bounds checking again
6. Finally writes to port $FE

**Assembly approach:**
1. Load 2 into A register (7 T-states)
2. Output A to port $FE (11 T-states)
3. Done. (18 T-states total)

The assembly version is **over 1000× faster** for this specific operation. Your Spectrum runs at 3.5MHz, so 18 T-states = about 5 microseconds. BASIC takes roughly 6 milliseconds.

## Example Programme 1: Your First Assembly Code

```nasm
; Into the Metal - Lesson 001
; Change border colour to red

        DEVICE ZXSPECTRUM48 ; Target 48K Spectrum

        ORG $8000           ; Start program at 32768

Start:
        LD A,2              ; Load colour 2 (red) into A
        OUT ($FE),A         ; Send A to border port
        RET                 ; Return to BASIC

End:
```

**Line-by-line breakdown:**

- `DEVICE ZXSPECTRUM48` - Tells the assembler we're targeting a 48K Spectrum
- `ORG $8000` - **Crucial!** Tells assembler this code will run at address $8000 (32768 in decimal)
- `LD A,2` - **LD** = "Load". Copies the value 2 into the A register
- `OUT ($FE),A` - **OUT** = "Output". Sends the value in A to hardware port $FE
- `RET` - **RET** = "Return". Gives control back to BASIC

**To run this:**
1. Type the code and assemble it (we'll cover tools in a moment)
2. In BASIC: `RANDOMIZE USR 32768`
3. The border instantly turns red
4. You're back at the BASIC prompt

## Example Programme 2: Colour Cycling

Ready for something more impressive?

```nasm
; Cycle through border colours 0-7

        DEVICE ZXSPECTRUM48

        ORG $8000

Start:
        LD A,0              ; Start with colour 0

MainLoop:
        OUT ($FE),A         ; Set border to current colour

        ; Delay so we can see each colour
        PUSH AF             ; Save A (we'll need it)
        LD B,0              ; B = 0 (will count 256 times)
DelayLoop:
        DJNZ DelayLoop      ; Decrement B, jump if not zero

        POP AF              ; Restore A

        INC A               ; Increment colour (0→1→2→...)
        AND 7               ; Keep in range 0-7
        JR MainLoop         ; Jump back to start

End:
```

**New concepts:**

- **PUSH AF** / **POP AF** - Save/restore the A register (and flags)
- **LD B,0** - Load 0 into B register (will become 256 due to wraparound)
- **DJNZ DelayLoop** - "Decrement B and Jump if Not Zero" - perfect for countdown loops
- **INC A** - Increment (add 1) to A
- **AND 7** - Bitwise AND with 7 (%00000111) to keep value between 0-7
- **JR MainLoop** - "Jump Relative" - go back to MainLoop (infinite loop)

**To run:**
```
RANDOMIZE USR 32768
```

The border cycles through all 8 colours continuously. Press **BREAK** (CAPS SHIFT + SPACE) to stop it.

## How It Really Works: The Z80 Instruction Cycle

Every Z80 instruction follows this pattern:

1. **Fetch** - Read instruction from memory
2. **Decode** - Work out what to do
3. **Execute** - Perform the operation

This happens in **T-states** (clock cycles). The Spectrum runs at 3.5MHz, so:
- 1 T-state = 1/3,500,000 seconds ≈ 0.286 microseconds

**LD A,2 breakdown:**
- Opcode byte: `$3E` (the instruction code for "LD A,n")
- Operand byte: `$02` (the value)
- T-states: 7
- Memory bytes: 2

**OUT ($FE),A breakdown:**
- Opcode byte: `$D3`
- Port byte: `$FE`
- T-states: 11
- Memory bytes: 2

**Total execution time:** 7 + 11 = 18 T-states ≈ 5 microseconds

Compare that to BASIC's ~6000 microseconds for the same operation!

## The Memory Map: Where Does Code Live?

The Spectrum's 64K memory is divided into regions:

```
$0000-$3FFF (0-16383):     ROM (don't touch!)
$4000-$57FF (16384-22527): Screen bitmap
$5800-$5AFF (22528-23295): Screen attributes (colour)
$5B00-$7FFF (23296-32767): Lower RAM
$8000-$FFFF (32768-65535): Upper RAM ← Your code goes here
```

**Why $8000 (32768)?**

The screen area ($4000-$7FFF) is **contended memory** - the CPU and ULA (video chip) fight over access. Code running there is slower. Code at $8000+ runs at full speed with no contention.

**The A Register:**

Think of the A register as your main workspace. It's like having one hand free while juggling - most Z80 instructions work with A.

```
A register: [00000010] = 2 in binary
            ↓
Port $FE:   [xxxxx010] = border colour bits 0-2
```

Only the lower 3 bits (0-2) control border colour, giving us 8 colours (0-7).

## How Games Use This: Border Effects

Commercial Spectrum games use border colour in creative ways:

**Jet Set Willy** - Changes border during screen drawing as a "loading" indicator

**Manic Miner** - Dramatic border flashes on the title screen

**Elite** - Border flashes white during combat hits

**Many games** - Use border colour changes to visualise timing (a debugging technique)

**Border stripe racing:**

Advanced technique: Change border colour at specific vertical screen positions to create coloured stripes. This adds visual flair without using precious screen memory. We'll learn this in later lessons.

The border is "free" graphics - it doesn't use screen memory or slow down your game.

## Quick Reference: Lesson 001

### Registers

| Register | Purpose | Size |
|----------|---------|------|
| A | Accumulator (main workspace) | 8-bit (0-255) |
| B | Counter/temporary storage | 8-bit (0-255) |
| F | Flags (Zero, Carry, etc.) | 8-bit |

### Instructions Learnt

| Instruction | Meaning | T-states | Bytes |
|-------------|---------|----------|-------|
| LD A,n | Load value n into A | 7 | 2 |
| OUT (n),A | Output A to port n | 11 | 2 |
| RET | Return to caller | 10 | 1 |
| INC A | Increment A by 1 | 4 | 1 |
| AND n | Bitwise AND A with n | 7 | 2 |
| JR label | Jump to label (relative) | 12 | 2 |
| DJNZ label | Decrement B, jump if not zero | 13/8 | 2 |
| PUSH AF | Save A and F to stack | 11 | 1 |
| POP AF | Restore A and F from stack | 10 | 1 |

### Hardware

| Port | Purpose | Bits Used |
|------|---------|-----------|
| $FE | Border colour + keyboard + speaker | Bits 0-2 (colour), bit 4 (speaker) |

### Assembler Directives

| Directive | Purpose |
|-----------|---------|
| ORG address | Set code origin address |
| DEVICE name | Specify target machine |

### Colour Values (Port $FE, bits 0-2)

| Value | Colour | Binary |
|-------|--------|--------|
| 0 | Black | 000 |
| 1 | Blue | 001 |
| 2 | Red | 010 |
| 3 | Magenta | 011 |
| 4 | Green | 100 |
| 5 | Cyan | 101 |
| 6 | Yellow | 110 |
| 7 | White | 111 |
