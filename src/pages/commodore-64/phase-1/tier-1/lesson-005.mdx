# Lesson 5: Timing & Rhythm

## From Crude to Accurate

In Lesson 4, you used delay loops for timing - simple nested loops that burn CPU cycles. But those delays are **approximate** and vary with PAL vs NTSC, making rhythm games impossible.

Now you're going to use **CIA Timer A** - a hardware timer that counts clock cycles with perfect precision. This is how every C64 music player, game, and rhythm application achieved frame-accurate timing.

Welcome to precise timing.

---

## The One-Minute Tour

- **CIA Timer A** counts down from a set value to zero at CPU clock speed
- **60Hz frame rate** provides consistent timing for music and games
- **Frame-based timing** counts frames instead of burning CPU cycles
- **120 BPM tempo** = 2 beats per second = 30 frames per quarter note
- **Polling $DC0D** checks when timer underflows (reaches zero)
- **Continuous mode** automatically reloads timer for next frame

## Example Program: "Mary Had a Little Lamb" at 120 BPM

This program plays the melody with **precise** rhythm using CIA Timer A.

```asm
; Lesson 005: Timing & Rhythm
; Frame-based music playback with CIA Timer A - "Mary Had a Little Lamb" at 120 BPM

        * = $0801       ; BASIC start address
        ; BASIC stub: 10 SYS 2064
        !byte $0c,$08,$0a,$00,$9e,$20,$32,$30,$36,$34,$00,$00,$00

        * = $0810       ; Machine code start ($0810 = 2064 decimal)
        jmp init        ; Jump to initialization

; ============================================================================
; TIMING CONSTANTS
; ============================================================================
; CIA Timer A values for 60Hz frame rate (PAL: 985248 Hz / 60 = 16421 cycles)
TIMER_LO = $2d          ; 16421 & $FF
TIMER_HI = $40          ; 16421 >> 8

; Musical timing at 120 BPM (2 beats per second)
; At 60 fps, quarter note = 0.5 seconds = 30 frames
QUARTER_NOTE = 30
EIGHTH_NOTE  = 15
HALF_NOTE    = 60

; ============================================================================
; FREQUENCY TABLE - Chromatic scale C4-C5 (A440 PAL tuning)
; ============================================================================
freq_lo: !byte $67, $72, $89, $aa, $ed, $3b, $94, $13, $a4, $45, $04, $da, $ce
freq_hi: !byte $11, $12, $13, $14, $15, $17, $18, $1a, $1b, $1d, $1f, $20, $22

; ============================================================================
; MELODY DATA - "Mary Had a Little Lamb"
; ============================================================================
; Note indices: 0=C, 2=D, 4=E, 5=F, 7=G
melody:
        !byte 4, 2, 0, 2, 4, 4, 4       ; E D C D E E E
        !byte 2, 2, 2, 4, 7, 7          ; D D D E G G
        !byte 4, 2, 0, 2, 4, 4, 4, 4    ; E D C D E E E E
        !byte 2, 2, 4, 2, 0, $ff        ; D D E D C (end marker)

; Duration for each note (in frames at 60 fps)
timing:
        !byte QUARTER_NOTE, QUARTER_NOTE, QUARTER_NOTE, QUARTER_NOTE
        !byte QUARTER_NOTE, QUARTER_NOTE, HALF_NOTE

        !byte QUARTER_NOTE, QUARTER_NOTE, HALF_NOTE
        !byte QUARTER_NOTE, QUARTER_NOTE, HALF_NOTE

        !byte QUARTER_NOTE, QUARTER_NOTE, QUARTER_NOTE, QUARTER_NOTE
        !byte QUARTER_NOTE, QUARTER_NOTE, QUARTER_NOTE, QUARTER_NOTE

        !byte QUARTER_NOTE, QUARTER_NOTE, QUARTER_NOTE, QUARTER_NOTE
        !byte HALF_NOTE, 0

; ============================================================================
; VARIABLES
; ============================================================================
note_ptr:    !byte $00          ; Current position in melody
note_frames: !byte $00          ; Frames remaining for current note

; ============================================================================
; INITIALIZATION
; ============================================================================
init:
        jsr clear_sid           ; Initialize SID chip
        jsr init_timer          ; Set up CIA Timer A for 60Hz
        lda #$00
        sta note_ptr            ; Start at beginning of melody
        jsr next_note           ; Play first note
        jmp main_loop

; ============================================================================
; MAIN LOOP - Frame-based playback
; ============================================================================
main_loop:
        jsr wait_frame          ; Wait for next 60Hz tick

        ; Check if current note finished
        dec note_frames
        bne main_loop           ; Still playing current note

        ; Current note finished, start next note
        jsr next_note
        jmp main_loop

; ============================================================================
; NEXT NOTE - Start playing the next note in the melody
; ============================================================================
next_note:
        ; Turn off current note
        lda #$20                ; Sawtooth waveform, gate OFF
        sta $d404

        ; Get next note from melody
        ldx note_ptr
        lda melody,x
        cmp #$ff                ; Check for end marker
        beq restart_melody

        ; Play the note
        tay                     ; Y = note index for frequency lookup
        lda freq_lo,y
        sta $d400               ; Voice 1 frequency low
        lda freq_hi,y
        sta $d401               ; Voice 1 frequency high
        lda #$21                ; Sawtooth waveform + gate ON
        sta $d404               ; Voice 1 control

        ; Set duration for this note
        ldx note_ptr
        lda timing,x            ; Get duration in frames
        sta note_frames         ; Set frame counter

        ; Move to next note
        inc note_ptr
        rts

restart_melody:
        lda #$00
        sta note_ptr            ; Reset to start of melody
        jmp next_note           ; Start playing from beginning

; ============================================================================
; WAIT_FRAME - Wait for next CIA Timer A tick (60Hz)
; ============================================================================
wait_frame:
wf_loop:
        lda $dc0d               ; Read CIA #1 interrupt control register
        and #$01                ; Check bit 0 (Timer A underflow)
        beq wf_loop             ; If 0, timer hasn't fired yet - keep waiting

        ; Timer fired - we've completed one frame
        rts

; ============================================================================
; INIT_TIMER - Set up CIA Timer A for 60Hz timing
; ============================================================================
init_timer:
        lda #$00                ; Stop timer
        sta $dc0e               ; CIA #1 Timer A control register

        lda #TIMER_LO           ; Set timer value (16421 cycles for PAL 60Hz)
        sta $dc04               ; Timer A low byte
        lda #TIMER_HI
        sta $dc05               ; Timer A high byte

        lda #$11                ; %00010001 = Start timer, continuous mode, count system clock
        sta $dc0e               ; Timer A control register
        rts

; ============================================================================
; CLEAR SID - Initialize all SID registers
; ============================================================================
clear_sid:
        lda #$00
        ldx #$00
cls_loop:
        sta $d400,x
        inx
        cpx #$1d                ; 29 SID registers
        bne cls_loop

        ; Set ADSR for musical sound
        lda #$08                ; Attack=0 (instant), Decay=8 (medium)
        sta $d405               ; Voice 1 Attack/Decay
        lda #$b0                ; Sustain=11 (high), Release=0 (instant)
        sta $d406               ; Voice 1 Sustain/Release

        ; Set volume
        lda #$0f                ; Maximum volume
        sta $d418               ; Volume register

        rts
```

**To run:**
```bash
acme -f cbm -o lesson-005.prg example-1.asm
x64sc lesson-005.prg
```

Hear the difference? The rhythm is **precise** - every quarter note exactly 0.5 seconds, every half note exactly 1.0 seconds. This is frame-accurate timing.

## CIA Timer A Explained

The **CIA (Complex Interface Adapter)** chip has two 16-bit timers. Timer A is perfect for precise timing.

**How it works:**

1. **Load a value** into Timer A (e.g., 16421 for 60Hz on PAL)
2. **Start the timer** - it counts down once per CPU clock cycle
3. **When it reaches zero**, bit 0 of $DC0D is set
4. **In continuous mode**, it automatically reloads and starts counting again

**Registers:**
- `$DC04` - Timer A low byte
- `$DC05` - Timer A high byte
- `$DC0E` - Control register
- `$DC0D` - Interrupt flag register (read to check if timer underflowed)

---

## The 60Hz Frame Rate

Why 60Hz? Because it's a **common denominator** for music timing and game logic.

**Calculation for PAL C64:**
```
PAL clock speed: 985,248 Hz
Desired frame rate: 60 frames per second
Cycles per frame: 985248 / 60 = 16421 cycles
```

**In hexadecimal:** 16421 = $402D

But wait - the code uses $402D, which is written as `TIMER_LO = $2d` and `TIMER_HI = $40`.

**Why split?** Timer A is a 16-bit value, so we load low byte ($2D) into $DC04 and high byte ($40) into $DC05.

---

## Musical Timing at 120 BPM

**BPM (Beats Per Minute)** measures tempo. 120 BPM means 120 quarter-note beats every minute.

**Converting to frames:**
```
120 BPM = 2 beats per second
1 quarter note = 1 beat = 0.5 seconds
At 60 fps: 0.5 seconds = 30 frames
```

**Common note durations:**
```
Whole note    = 4 beats = 2.0 seconds = 120 frames
Half note     = 2 beats = 1.0 seconds = 60 frames
Quarter note  = 1 beat  = 0.5 seconds = 30 frames
Eighth note   = 0.5 beat = 0.25 seconds = 15 frames
```

These constants (`QUARTER_NOTE = 30`, etc.) make the code readable and the tempo easy to adjust.

## Frame-Based Playback Loop

The main loop is elegantly simple:

```asm
main_loop:
        jsr wait_frame          ; Wait for next 60Hz tick
        dec note_frames         ; Count down frames for current note
        bne main_loop           ; Still playing? Loop
        jsr next_note           ; Note finished, play next
        jmp main_loop
```

**Every frame:**
1. Wait for next timer tick (16.67ms on PAL at 60fps)
2. Decrement `note_frames` counter
3. If counter reaches zero, start next note
4. Repeat forever

No CPU burning! Between frames, the processor waits efficiently by polling $DC0D.

---

## Polling vs Interrupts

This lesson uses **polling** - repeatedly checking $DC0D until bit 0 is set.

```asm
wait_frame:
wf_loop:
        lda $dc0d       ; Read interrupt flag
        and #$01        ; Check Timer A bit
        beq wf_loop     ; If 0, keep waiting
        rts             ; If 1, timer fired!
```

**Alternative: Interrupts** (covered in later lessons) let the timer **interrupt** your code when it fires, calling a subroutine automatically. More complex but allows background timing while doing other work.

For now, polling is simple and works perfectly for music playback.

---

## The Control Register ($DC0E)

Writing to $DC0E controls Timer A:

```asm
lda #$11        ; %00010001
sta $dc0e
```

**Bit breakdown:**
```
Bit 0: 1 = Start timer (0 = stop)
Bit 1: 0 = Timer output to PB6 disabled
Bit 2: 0 = Pulse output mode
Bit 3: 0 = Continuous mode (1 = one-shot)
Bit 4: 1 = Force load timer (reload immediately)
Bit 5-7: Unused
```

**$11 = %00010001:** Start timer in continuous mode, force load, count clock pulses.

In **continuous mode**, when the timer reaches zero, it automatically reloads from $DC04/$DC05 and starts counting again. Perfect for repeating events like 60Hz frames.

## PAL vs NTSC Timing

**PAL systems** (Europe, Australia) run at 985,248 Hz.
**NTSC systems** (North America, Japan) run at 1,022,727 Hz (~3.8% faster).

**For 60Hz frame rate:**
- PAL: 985248 / 60 = 16421 cycles = $402D
- NTSC: 1022727 / 60 = 17045 cycles = $4295

To support both systems, you'd detect PAL/NTSC at startup and set different timer values. For now, this lesson targets PAL.

## Why Frames Instead of Delay Loops?

**Delay loops (Lesson 4):**
- Approximate timing (depends on loop overhead)
- Wastes CPU cycles (can't do other work)
- No synchronization between events
- Breaks with PAL/NTSC differences

**Frame-based timing (Lesson 5):**
- Precise to the clock cycle
- CPU can do work between frames
- All events synchronized to frame boundaries
- Easy to adjust tempo (change constants)

Frame-based timing is the foundation for **rhythm games**, which require detecting if player input is within a few frames of the beat.

## Quick Reference

**CIA #1 Timer A Registers:**
- `$DC04` - Timer A low byte
- `$DC05` - Timer A high byte
- `$DC0E` - Control register (start/stop/mode)
- `$DC0D` - Interrupt flag (read to check underflow, bit 0 = Timer A)

**Timer Setup (60Hz PAL):**
```asm
lda #$00
sta $dc0e       ; Stop timer
lda #$2D        ; 16421 low byte
sta $dc04
lda #$40        ; 16421 high byte
sta $dc05
lda #$11        ; Start continuous
sta $dc0e
```

**Frame Wait Pattern:**
```asm
wait:   lda $dc0d       ; Read interrupt flag
        and #$01        ; Check Timer A bit
        beq wait        ; Loop until set
        rts
```

**Musical Timing Constants (120 BPM at 60fps):**
```
WHOLE_NOTE    = 120  ; 2 seconds
HALF_NOTE     = 60   ; 1 second
QUARTER_NOTE  = 30   ; 0.5 seconds
EIGHTH_NOTE   = 15   ; 0.25 seconds
SIXTEENTH_NOTE = 8   ; 0.125 seconds (approximate)
```

**BPM Calculation:**
```
Frames per quarter note = (60 fps × 60 seconds) / BPM
For 120 BPM: (60 × 60) / 120 = 30 frames
For 140 BPM: (60 × 60) / 140 = 25.7 frames (~26)
```
