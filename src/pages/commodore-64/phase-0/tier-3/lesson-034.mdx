In the previous lesson, you implemented gravity and jumping with ground collision. That worked brilliantly for flat ground—but most platformers need platforms at different heights. How do you detect collision with multiple platforms? How do you land on platforms from above without getting stuck when jumping up from below?

**Lesson 34 introduces platform collision**—checking multiple surfaces at different heights using arrays. The key insight: only land when falling (VY >= 0) and within vertical range of platform top. Jump up through platforms from below, land on them from above. Simple velocity-based logic creates natural platformer behaviour.

---

## The One-Minute Tour

**Platform Data Structure:**
- **Arrays store multiple platforms:** `PX(I), PY(I), PW(I)` for X, Y, and width
- **Loop through platforms** checking each for collision
- **DATA statements** provide platform coordinates
- **READ loops** load platforms into arrays on initialisation

**Landing Logic:**
- **Velocity check first:** Only land when falling (`VY >= 0`)
- **Y-threshold range:** Within ±8 pixels of platform top accounts for float precision
- **Horizontal overlap:** Player X within platform left-to-right bounds
- **All three required:** Velocity + Y-range + X-overlap = landing

**Falling Through Mechanics:**
- **Rising blocks collision:** `IF VY < 0 THEN RETURN` skips platform checks when jumping
- **Above platform:** `IF Y < PY-8 THEN RETURN` hasn't reached platform yet
- **Outside horizontal:** X beyond platform edges means no collision
- **Natural jumping:** Pass through from below, land from above

**What happens:**

**Line 120: Array Declaration**
```basic
DIM PX(8),PY(8),PW(8)
```
- Creates three arrays for up to 8 platforms
- PX(I) = Platform X position (left edge)
- PY(I) = Platform Y position (top surface)
- PW(I) = Platform width in pixels

**Line 140: Load Platform Data**
```basic
GOSUB 9000
```
- Reads number of platforms from DATA
- Loops through reading X, Y, Width for each
- Fills arrays with platform coordinates

**Line 4020: Velocity Check**
```basic
IF VY<0 THEN RETURN
```
- Critical line: only check platforms when falling
- VY < 0 means rising (jumping upward)
- Returns immediately, allowing jump-through from below
- VY >= 0 means falling, continue checking

**Line 4030-4060: Platform Loop**
```basic
FOR I=1 TO NP
GOSUB 4100
IF OG=1 THEN RETURN
NEXT I
```
- Checks each platform in sequence
- Returns immediately on first landing (OG=1)
- No need to check remaining platforms

**Line 4110-4140: Collision Checks**
```basic
IF Y<PY(I)-8 THEN RETURN    :REM ABOVE PLATFORM
IF Y>PY(I)+8 THEN RETURN    :REM BELOW PLATFORM
IF X<PX(I) THEN RETURN      :REM LEFT OF PLATFORM
IF X>PX(I)+PW(I) THEN RETURN :REM RIGHT OF PLATFORM
```
- Four checks: vertical range and horizontal range
- Y-threshold (±8 pixels) accounts for floating-point velocity
- X bounds check: between left edge and left+width
- All four must pass for collision

**Line 4150: Landing**
```basic
Y=PY(I):VY=0:OG=1
```
- Snap Y to platform top (prevents sinking)
- Zero vertical velocity (stop falling)
- Set grounded flag (allows next jump)

## Understanding Y-Threshold Collision

**Why ±8 pixel range instead of exact Y match?**

Gravity adds floating-point velocity every frame:
```
Frame N:   Y=151.7, VY=0.9
Frame N+1: Y=152.6, VY=1.2
Frame N+2: Y=153.8, VY=1.5
```

If platform Y=152 and you check `IF Y=PY THEN LAND`:
- Y might be 151.7 (before platform)
- Then 152.6 (past platform)
- Never exactly 152!

**The threshold solution:**
```basic
IF Y>=PY-8 AND Y<=PY+8 THEN [CHECK HORIZONTAL]
```

Player within ±8 pixels = potential landing zone. Combined with VY>=0 check (falling), this catches all landings without false positives.

**Why 8 pixels specifically?**

Maximum fall speed (terminal velocity) is typically 8 pixels/frame. The ±8 threshold ensures we catch the player even if they're falling at maximum speed. Smaller threshold might miss fast falls. Larger threshold creates "sticky" platforms that catch you too early.

## Velocity-Based Landing Logic

**The critical insight: only check platforms when falling.**

Without velocity check:
```basic
REM BAD VERSION - NO VELOCITY CHECK
4000 FOR I=1 TO NP
4010 IF Y>=PY(I)-8 AND Y<=PY(I)+8 THEN [CHECK X]
```

**What goes wrong:**
1. Jump upward from ground (VY=-5)
2. Head enters platform's Y-threshold from below
3. Collision detected—player snaps to platform top
4. Player stuck! Can't jump through

**With velocity check:**
```basic
REM GOOD VERSION - VELOCITY CHECK FIRST
4000 IF VY<0 THEN RETURN :REM RISING, SKIP COLLISION
4010 FOR I=1 TO NP
```

**What happens:**
1. Jump upward (VY=-5)
2. VY&lt;0 detected—RETURN immediately
3. No collision check whilst rising
4. Pass through platform from below
5. At peak of jump, VY becomes positive (falling)
6. Now collision checks activate
7. Land on platform from above

Natural jump-through behaviour with one line of code.

## Platform Array Design

**Why three arrays instead of nested structures?**

BASIC V2 doesn't support multi-dimensional arrays efficiently. This works:
```basic
DIM PX(8),PY(8),PW(8)
```

This doesn't exist in BASIC V2:
```basic
DIM PLATFORMS(8,3)  :REM Not available
```

**Array indexing:**
- Platform 1: PX(1), PY(1), PW(1)
- Platform 2: PX(2), PY(2), PW(2)
- Platform I: PX(I), PY(I), PW(I)

**Loading from DATA:**
```basic
9000 READ NP           :REM Read count
9010 FOR I=1 TO NP
9020 READ PX(I),PY(I),PW(I)  :REM Read three values
9030 NEXT I
```

**DATA structure:**
```basic
9110 DATA 6            :REM 6 platforms
9120 DATA 30,200,40    :REM Platform 1: X=30, Y=200, Width=40
9130 DATA 100,200,60   :REM Platform 2: X=100, Y=200, Width=60
```

Simple, efficient, easy to edit.

## Game Integration

**How games use platform collision:**

**Manic Miner (1983):**
- Fixed platform layouts per screen
- Platforms drawn with character graphics
- Exact collision (8×8 character grid)
- No floating-point—character-based movement

**Impossible Mission (C64, 1984):**
- Smooth pixel-based platforming
- Multiple platform heights
- Velocity-based collision
- Lift platforms that move

**Montezuma's Revenge (C64, 1984):**
- Character grid platforms
- Ladder collision (different system)
- Key/door interactions on platforms
- Room-based platform layouts

**Your platformer can:**
1. **Static platforms:** Fixed positions (current implementation)
2. **Moving platforms:** Change PY(I) each frame (oscillate)
3. **Crumbling platforms:** Remove from array after landing
4. **One-way platforms:** Only land from above (check previous Y)

Example 2 uses static platforms—the foundation for all variants.

## From the Vault

**Platform collision in 1980s games:**

- **Jet Set Willy (ZX Spectrum, 1984):** Character-grid platforms. Simple ON/OFF collision per 8×8 block. Fast, effective.
- **Boulder Dash (C64, 1984):** Tile-based collision. Every screen position is a tile type. Check player's tile for collision.
- **Prince of Persia (Apple II, 1989):** Pixel-perfect platform collision. Complex but smooth. Shows evolution of technique.
- **Rick Dangerous (C64, 1989):** Combines platforms with traps. Collision system handles multiple object types.

**Assembly vs BASIC collision:**

The collision logic is identical:
```
Check velocity → Check Y range → Check X range → Land
```

Assembly checks this 50 times per second. BASIC checks 15-25 times per second. The algorithm is the same—the update frequency differs. By Tier 4, you'll measure exact frame rates and understand the trade-offs.

## Common Pitfalls

**1. Missing velocity check**

Without line 4020:
```basic
4000 OG=0
4010 FOR I=1 TO NP  :REM No VY check - WRONG
```
- Player jumps through platform from below
- Head enters Y-threshold
- Collision detected
- Player stuck to platform bottom
- Cannot jump properly

**Fix:** Always check `IF VY<0 THEN RETURN` before platform loops.

**2. Wrong Y-threshold comparison**

Using exact match:
```basic
4100 IF Y=PY(I) THEN [LAND]  :REM WRONG
```
- Floating-point Y (152.6) never equals exact PY (152)
- Player falls through all platforms
- No collision detected

**Fix:** Use range check: `IF Y>=PY-8 AND Y<=PY+8`

**3. Forgetting to set OG=1**

```basic
4150 Y=PY(I):VY=0  :REM Missing OG=1
4160 RETURN
```
- Player lands on platform
- But OG flag not set
- Cannot jump (requires OG=1)
- Stuck on platform!

**Fix:** Always set grounded flag: `Y=PY(I):VY=0:OG=1`

**4. Wrong platform priority**

Checking platforms in wrong order can cause landing on wrong platform when multiple overlap:
```basic
REM If platforms overlap vertically
REM Check lower platforms first
```

Current implementation returns on first match—works for non-overlapping platforms. For complex layouts, sort platforms by Y position or check all and choose nearest.

## Quick Reference

**Platform array setup:**
```basic
100 DIM PX(8),PY(8),PW(8)  :REM 8 platforms max
110 READ NP                :REM Number of platforms
120 FOR I=1 TO NP
130 READ PX(I),PY(I),PW(I) :REM X, Y, Width
140 NEXT I
```

**Platform collision loop:**
```basic
100 IF VY<0 THEN RETURN    :REM Rising, skip collision
110 FOR I=1 TO NP
120 GOSUB [CHECK PLATFORM I]
130 IF ON_GROUND=1 THEN RETURN
140 NEXT I
```

**Individual platform check:**
```basic
100 IF Y<PY-8 THEN RETURN     :REM Above platform
110 IF Y>PY+8 THEN RETURN     :REM Below platform
120 IF X<PX THEN RETURN       :REM Left of platform
130 IF X>PX+PW THEN RETURN    :REM Right of platform
140 Y=PY:VY=0:ON_GROUND=1     :REM Land
```

**Draw platforms:**
```basic
100 FOR I=1 TO NP
110 FOR J=0 TO PW(I) STEP 8
120 CX=INT((PX(I)+J)/8)
130 CY=INT(PY(I)/8)
140 POKE 1024+CY*40+CX,160  :REM Character
150 POKE 55296+CY*40+CX,5   :REM Colour
160 NEXT J:NEXT I
```

**Platform DATA format:**
```basic
100 DATA 3              :REM Number of platforms
110 DATA 50,180,60      :REM Platform 1: X=50, Y=180, W=60
120 DATA 120,160,40     :REM Platform 2: X=120, Y=160, W=40
130 DATA 80,140,50      :REM Platform 3: X=80, Y=140, W=50
```

**Memory locations used:**
- 1024-2023 ($0400-$07E7): Screen memory (40×25 characters)
- 55296-56295 ($D800-$DBE7): Colour memory
- 53248-53249 ($D000-$D001): Sprite 0 X/Y position
- 53269 ($D015): Sprite enable register
- 53287 ($D027): Sprite 0 colour
- 56320 ($DC00): Joystick port 2

**Common platform characters:**
- 160: Horizontal line (─)
- 162: Vertical line (│)
- 176: Half-filled block (▒)
- 224: Full block (█)
