## The One-Minute Tour

**Combat System:**
- **Combat state:** Track combat active/inactive, player/enemy turns
- **Stats:** HP (health), AT (attack), DF (defence), track max HP for healing
- **Actions:** Attack (deal damage), Defend (block next hit), Item (use potion), Flee (escape chance)
- **Turn flow:** Display → Player action → Check victory → Enemy action → Check defeat → Repeat
- **Instant response:** Each action executes in &lt;10ms, feels perfectly smooth

**Damage Calculation:**
- **Formula:** `DAMAGE = ATTACKER_AT - DEFENDER_DF + RND(5)`
- **Minimum damage:** Always at least 1 (prevent stalemate)
- **Randomness:** ±5 damage variance prevents predictability
- **Defence mechanics:** Block flag reduces next damage by 50%

**Enemy AI:**
- **Simple AI:** 80% attack, 20% hesitate (random weighted)
- **Health-based AI:** Defend when HP low, aggressive when HP high
- **Counter AI:** React to player's last action (advanced)
- **No performance cost:** Complex AI = zero speed penalty

**Performance Reality:**
- **Combat loop:** Instant (text-only updates)
- **Damage calculation:** &lt;1ms (simple arithmetic)
- **After platformers:** Feels incredibly polished and professional
- **Reality:** Turn-based design plays to BASIC's strengths perfectly

## Example 1: Simple Combat System

Let's build the core combat mechanics—HP tracking, attack/defend actions, victory/defeat:

```basic
10 REM TURN-BASED COMBAT - SIMPLE
20 PRINT CHR$(147)
30 PRINT "=== TURN-BASED COMBAT ==="
40 PRINT ""
50 REM PLAYER STATS
60 HP=20:MH=20:AT=8:DF=3
70 REM ENEMY STATS
80 EN$="GOBLIN"
90 EH=12:EA=5:ED=2
100 REM COMBAT LOOP
110 GOSUB 1000:REM DISPLAY STATUS
120 GOSUB 2000:REM PLAYER TURN
130 IF EH<=0 THEN GOSUB 4000:END
140 GOSUB 3000:REM ENEMY TURN
150 IF HP<=0 THEN GOSUB 5000:END
160 GOTO 110
1000 REM DISPLAY COMBAT STATUS
1010 PRINT CHR$(147)
1020 PRINT "=== COMBAT ==="
1030 PRINT ""
1040 PRINT EN$
1050 PRINT "HP:";EH
1060 PRINT ""
1070 PRINT "YOU"
1080 PRINT "HP:";HP;"/";MH
1090 PRINT ""
1100 RETURN
2000 REM PLAYER TURN
2010 PRINT "1:ATTACK 2:DEFEND"
2020 PRINT "ACTION> ";
2030 INPUT A
2040 IF A<1 OR A>2 THEN 2020
2050 IF A=1 THEN GOSUB 2100:RETURN
2060 IF A=2 THEN GOSUB 2200:RETURN
2070 RETURN
2100 REM PLAYER ATTACK
2110 DM=AT-ED+INT(RND(1)*5)
2120 IF DM<1 THEN DM=1
2130 EH=EH-DM
2140 PRINT ""
2150 PRINT "YOU HIT FOR ";DM;" DAMAGE!"
2160 PRINT ""
2170 FOR I=1 TO 1000:NEXT I
2180 RETURN
2200 REM PLAYER DEFEND
2210 PRINT ""
2220 PRINT "YOU BRACE FOR IMPACT!"
2230 BL=1:REM BLOCK FLAG
2240 PRINT ""
2250 FOR I=1 TO 1000:NEXT I
2260 RETURN
3000 REM ENEMY TURN
3010 DM=EA-DF+INT(RND(1)*5)
3020 IF BL=1 THEN DM=INT(DM/2):BL=0
3030 IF DM<1 THEN DM=1
3040 HP=HP-DM
3050 PRINT EN$;" HITS FOR ";DM;" DAMAGE!"
3060 PRINT ""
3070 FOR I=1 TO 1500:NEXT I
3080 RETURN
4000 REM VICTORY
4010 PRINT CHR$(147)
4020 PRINT "=== VICTORY! ==="
4030 PRINT ""
4040 PRINT "YOU DEFEATED THE ";EN$;"!"
4050 GD=INT(RND(1)*15)+10
4060 PRINT ""
4070 PRINT "GOLD: +";GD
4080 RETURN
5000 REM DEFEAT
5010 PRINT CHR$(147)
5020 PRINT "=== DEFEATED ==="
5030 PRINT ""
5040 PRINT "YOU HAVE BEEN SLAIN!"
5050 RETURN
```

**Run this.** The combat screen shows enemy HP and your HP. You can attack (deals damage) or defend (sets block flag for 50% damage reduction). After your turn, the enemy attacks. The loop continues until someone reaches 0 HP. Notice the **instant response**—no lag between turns.

![Simple turn-based combat showing Goblin enemy with HP display and action menu](/images/commodore-64/phase-0/tier-3/lesson-044/screenshot-1.png)

**What's happening:**
- **Lines 60-90:** Define player and enemy stats (HP, attack, defence)
- **Line 110:** Display combat status with HP for both combatants
- **Lines 2110-2130:** Damage formula—attacker minus defender defence plus randomness
- **Line 2120:** Minimum damage ensures combat doesn't stall (always at least 1)
- **Lines 3010-3020:** Enemy attack uses same formula, checks block flag
- **Lines 130/150:** Check for combat end after each turn

**The revelation:** Your platformer struggled with collision detection during movement. This combat system handles damage calculations, state tracking, and turn management **instantly**. No frame rate concerns. No visible delays. Turn-based removes all performance bottlenecks.

## Combat Flow Architecture

**Turn-based combat follows a predictable cycle:**

```
┌─────────────────────────────────────┐
│ 1. Display combat status            │
│    - Show enemy HP                  │
│    - Show player HP                 │
│    - Show available actions         │
└─────────┬───────────────────────────┘
          │
          ▼
┌─────────────────────────────────────┐
│ 2. Player chooses action            │
│    - Attack / Defend / Item / Flee  │
│    - INPUT waits (no time pressure) │
└─────────┬───────────────────────────┘
          │
          ▼
┌─────────────────────────────────────┐
│ 3. Execute player action             │
│    - Calculate damage               │
│    - Update enemy HP                │
│    - Display result                 │
└─────────┬───────────────────────────┘
          │
          ▼
┌─────────────────────────────────────┐
│ 4. Check enemy defeated              │
│    - If HP <= 0: Victory!           │
│    - Award gold/XP                  │
│    - End combat                     │
└─────────┬───────────────────────────┘
          │ (if enemy alive)
          ▼
┌─────────────────────────────────────┐
│ 5. Enemy AI chooses action           │
│    - Simple: Always attack          │
│    - Advanced: Check HP, strategy   │
└─────────┬───────────────────────────┘
          │
          ▼
┌─────────────────────────────────────┐
│ 6. Execute enemy action              │
│    - Calculate damage               │
│    - Apply defend reduction         │
│    - Update player HP               │
└─────────┬───────────────────────────┘
          │
          ▼
┌─────────────────────────────────────┐
│ 7. Check player defeated             │
│    - If HP <= 0: Game Over          │
│    - Otherwise: Return to step 1    │
└─────────────────────────────────────┘
```

**Why this works perfectly in BASIC:**
- **No continuous loop:** Each step waits for completion before next
- **Player-paced:** INPUT command means no time pressure
- **Text-only updates:** No sprite animation or screen scrolling
- **Simple state:** Few variables to track (HP, block flag, combat active)

Compare this to your platformer's game loop:
```
Loop: Update player → Update enemies → Check collisions →
      Redraw sprites → Scroll screen → Repeat 60x/sec
```

That loop struggled at 10 fps with complexity. Combat's turn-based loop runs **instantly** no matter how complex the actions.

```basic
4030 REM IF LOW HEALTH, 30% DEFEND
4040 IF EH<MEH*0.4 AND AI<30 THEN GOSUB 4200:RETURN

4060 IF AI<80 THEN GOSUB 4100:RETURN
4070 REM 20% HESITATE
4080 PRINT EN$;" HESITATES!"

4150 PRINT EN$;" HITS FOR ";DM;" DAMAGE!"
4160 PRINT ""
4170 FOR I=1 TO 1500:NEXT I
4180 RETURN
4200 REM ENEMY DEFEND
4210 PRINT EN$;" RAISES SHIELD!"
4220 PRINT ""
4230 FOR I=1 TO 1000:NEXT I
4240 RETURN
5000 REM VICTORY
5010 PRINT CHR$(147)
5020 PRINT "=== VICTORY! ==="
5030 PRINT ""
5040 PRINT "YOU DEFEATED THE ";EN$;"!"
5050 GD=INT(RND(1)*20)+15

5080 PRINT "GOLD: +";GD
```

## Damage Formula Design

**The formula matters more than you'd expect.** Too simple and combat feels repetitive. Too complex and outcomes feel random.

**Method 1: Subtraction (Current)**
```basic
DAMAGE = ATTACKER_AT - DEFENDER_DF + RND(5)
IF DAMAGE < 1 THEN DAMAGE = 1
```

**Pros:**
- Simple and predictable
- Easy to balance (if AT=10, DF=5, expect ~5-9 damage)
- Clear progression (each +1 AT increases damage by 1)

**Cons:**
- High defence can reduce damage to minimum (stale fights)
- Linear scaling (no exponential growth)

**Method 2: Percentage Reduction**
```basic
DAMAGE = ATTACKER_AT * (100 - DEFENDER_DF) / 100 + RND(5)
```

**Pros:**
- Defence as percentage (DF=20 means 20% reduction)
- Scales naturally with attack power
- High defence still allows some damage through

**Cons:**
- Harder to balance (need mental math for outcomes)
- Can produce very low damage early game

**Method 3: Critical Hits**
```basic
CRIT = RND(1) * 100
IF CRIT < 10 THEN DAMAGE = DAMAGE * 2: PRINT "CRITICAL!"
```

**Pros:**
- Exciting unpredictability
- Adds tactical depth (risk vs reward)
- Feels like dice rolls (tabletop RPG vibe)

**Cons:**
- Can trivialise tough fights with lucky crits
- Can frustrate players with bad luck streaks

**Choose based on desired feel:**
- **Tactical precision:** Subtraction method
- **Scaling progression:** Percentage method
- **Exciting unpredictability:** Critical hits

## Enemy AI Patterns

**AI behaviour transforms combat from predictable to engaging.**

**AI Pattern 1: Always Attack**
```basic
1000 REM ENEMY TURN (SIMPLE)
1010 GOSUB ENEMY_ATTACK
1020 RETURN
```

**When to use:** Early game enemies, training encounters, speedrun-friendly fights.

**AI Pattern 2: Weighted Random**
```basic
1000 REM ENEMY TURN (RANDOM)
1010 AI = INT(RND(1) * 100)
1020 IF AI < 70 THEN GOSUB ENEMY_ATTACK: RETURN
1030 IF AI < 90 THEN GOSUB ENEMY_DEFEND: RETURN
1040 GOSUB ENEMY_SPECIAL: RETURN
```

**When to use:** Mid-game enemies, unpredictable behaviour, variety in encounters.

**AI Pattern 3: Health-Based (Example 2)**
```basic
1000 REM ENEMY TURN (HEALTH-BASED)
1010 IF ENEMY_HP < MAX_HP * 0.3 THEN GOSUB ENEMY_HEAL: RETURN
1020 IF ENEMY_HP < MAX_HP * 0.6 THEN GOSUB ENEMY_DEFEND: RETURN
1030 GOSUB ENEMY_ATTACK: RETURN
```

**When to use:** Boss fights, strategic enemies, teaching defensive play.

**AI Pattern 4: Counter Player**
```basic
1000 REM ENEMY TURN (REACTIVE)
1010 IF PLAYER_LAST_ACTION = 1 THEN GOSUB ENEMY_DEFEND: RETURN
1020 IF PLAYER_LAST_ACTION = 2 THEN GOSUB ENEMY_ATTACK: RETURN
1030 GOSUB ENEMY_SPECIAL: RETURN
```

**When to use:** Advanced enemies, pattern recognition rewards, puzzle-like combat.

**Performance note:** All four AI patterns execute instantly. Health-based AI with percentage calculations? Zero lag. Counter AI tracking player history? Zero lag. **Turn-based removes performance as a constraint for AI complexity.**

## Integrating Combat with Your RPG

**Combat doesn't exist in isolation—it connects to exploration.**

**Room-Based Enemy Encounters (from L41):**

Each room can have an enemy ID (0 = none). When entering a room with an enemy, trigger combat. After victory, remove enemy from room (so it doesn't respawn immediately).

**Compare these two scenarios:**

**Your Platformer (L33-40):**
- 6-frame sprite animation at 8-10 fps

**What changed?** Turn-based design eliminated continuous updates. Your platformer recalculated sprite positions, collision, and physics 8-10 times per second. Your RPG calculates once per action **when the player acts**. No wasted cycles. No continuous redraw.

**The lesson:** BASIC's speed limit only matters for real-time gameplay. Turn-based RPGs, puzzle games, and strategy games run perfectly because they don't fight the interpreter's pacing. They embrace it.

You've discovered **BASIC's genre sweet spot**: complex logic with instant response, no animation requirements, player-paced depth. This is why text adventures, roguelikes, and tactical RPGs thrived on 1980s home computers.

## Quick Reference

**Combat State Variables:**
```basic
HP = 20        REM Player health
MH = 20        REM Max health
AT = 8         REM Attack power
DF = 3         REM Defence value
EH = 12        REM Enemy health
EA = 5         REM Enemy attack
ED = 2         REM Enemy defence
BL = 0         REM Block flag (1 = defending)
GS = 1         REM Game state (1 = combat, 0 = end)
```

**Display Combat Status:**
```basic
1000 PRINT CHR$(147)
1010 PRINT "=== COMBAT ==="
1020 PRINT "": PRINT ENEMY_NAME$
1030 PRINT "HP:"; ENEMY_HP; "/"; MAX_ENEMY_HP
1040 PRINT "": PRINT "YOU"
1050 PRINT "HP:"; HP; "/"; MH
```

**Damage Calculation:**
```basic
DAMAGE = ATTACKER_AT - DEFENDER_DF + INT(RND(1) * 5)
IF DAMAGE < 1 THEN DAMAGE = 1
IF BLOCK_FLAG = 1 THEN DAMAGE = INT(DAMAGE / 2): BLOCK_FLAG = 0
DEFENDER_HP = DEFENDER_HP - DAMAGE
```

**Action Menu:**
```basic
PRINT "1:ATTACK 2:DEFEND 3:ITEM 4:FLEE"
INPUT ACTION
ON ACTION GOSUB ATTACK_SUB, DEFEND_SUB, ITEM_SUB, FLEE_SUB
```

**Enemy AI (Health-Based):**
```basic
AI_ROLL = INT(RND(1) * 100)
IF ENEMY_HP < MAX_HP * 0.3 AND AI_ROLL < 30 THEN GOSUB ENEMY_DEFEND
IF AI_ROLL < 80 THEN GOSUB ENEMY_ATTACK
PRINT "ENEMY HESITATES!"
```

**Victory Check:**
```basic
IF ENEMY_HP <= 0 THEN GOSUB VICTORY_SCREEN: COMBAT = 0
```

**Defeat Check:**
```basic
IF PLAYER_HP <= 0 THEN GOSUB GAME_OVER: END
```

**Flee Attempt:**
```basic
FLEE = INT(RND(1) * 100)
IF FLEE < 50 THEN PRINT "ESCAPED!": COMBAT = 0: RETURN
PRINT "CAN'T ESCAPE!"
```

**Combat Loop Structure:**
```basic
100 IF COMBAT = 0 THEN GOSUB EXPLORE_MODE
110 IF COMBAT = 1 THEN GOSUB COMBAT_MODE
120 GOTO 100

1000 REM COMBAT_MODE
1010 GOSUB DISPLAY_STATUS
1020 GOSUB PLAYER_TURN
1030 IF ENEMY_HP <= 0 THEN GOSUB VICTORY: COMBAT = 0: RETURN
1040 GOSUB ENEMY_TURN
1050 IF PLAYER_HP <= 0 THEN GOSUB DEFEAT: END
1060 RETURN
```
