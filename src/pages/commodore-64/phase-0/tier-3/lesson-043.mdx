## Lesson 43 – Shooting Stars

You have states and enemies; now you need teeth. Projectiles in BASIC hinge on a tiny state machine: **ready → firing → cooling down**. Get that right and you can launch lasers, missiles, or magic bolts without clutter.

> [📷 suggested: player sprite firing a glowing shot upward]

---

### The One-Minute Tour

- Keep a `shotActive` flag so the fire button only triggers when the projectile is available.
- Separate input handling from bullet updates—bullets keep flying even if the player stops pressing keys.
- Move sprites off-screen instead of deleting them; reuse them for the next shot.

---

### Example Program

```basic
NEW
10 REM *** SHOOTING STARS ***
20 PRINT CHR$(147);"WASD MOVE  SPACE FIRE  Q QUIT"
30 FOR I=832 TO 957:POKE I,0:NEXT I
40 POKE 2040,13:POKE 2041,14:POKE 2042,15
50 POKE 53269,7:POKE 53287,12:POKE 53288,1:POKE 53289,10
60 PX=160:PY=210:BX=0:BY=0:SHOT=0:COOL=0
70 POKE 53248,PX:POKE 53249,PY
80 GET K$:IF K$="Q" THEN END
90 IF K$="A" THEN PX=PX-4
100 IF K$="D" THEN PX=PX+4
110 IF K$="W" THEN PY=PY-3
120 IF K$="S" THEN PY=PY+3
130 IF PX<24 THEN PX=24
140 IF PX>320 THEN PX=320
150 IF PY<80 THEN PY=80
160 IF PY>233 THEN PY=233
170 POKE 53248,PX:POKE 53249,PY
180 IF K$=" " AND SHOT=0 AND COOL=0 THEN GOSUB 500
190 IF SHOT=1 THEN GOSUB 600
200 IF COOL>0 THEN COOL=COOL-1
210 PRINT CHR$(19);"SHOT:";:IF SHOT=1 THEN PRINT "IN FLIGHT"; ELSE PRINT "READY   ";
220 PRINT TAB(20);"COOLDOWN:";COOL;"   "
230 FOR D=1 TO 3:NEXT D
240 GOTO 80
500 REM *** LAUNCH ***
510 SHOT=1:BX=PX:BY=PY-16:COOL=15
520 POKE 53250,BX:POKE 53251,BY
530 POKE 53287,7:POKE 53288,2
540 RETURN
600 REM *** UPDATE BULLET ***
610 BY=BY-6
620 IF BY<48 THEN SHOT=0:POKE 53251,0:POKE 53250,0:POKE 53288,1:RETURN
630 POKE 53250,BX:POKE 53251,BY
640 RETURN
```

Sample output (status line mid-flight):

```
SHOT:IN FLIGHT    COOLDOWN:12
```

Line 180 checks the fire button and only launches when the shot is idle and the cooldown has elapsed. The launch routine (500–540) reuses the same sprite by resetting its position and colour, while the update routine (600–640) keeps nudging it upwards until it leaves the screen. Once the projectile exits, the flag resets and cooldown counts down so you can fire again.

> **Tip:** Cooldowns stop players from hammering the fire key faster than the sprite can move. Tune it to match bullet speed.

### Experiment Section

- Give the projectile horizontal drift by copying the player’s `DX` into a `shotDX` variable before launch.
- Spawn a second bullet sprite and alternate between them so you can have two shots on screen.
- Add a muzzle flash: briefly change the player sprite’s colour right after launch.
- Let the player hold space to auto-fire by skipping the cooldown when the shot isn’t active.

> [🎥 suggested: clip firing repeatedly with the cooldown number ticking down]

### Concept Expansion

Projectiles are just moving entities with a short life span. By encapsulating launch and update logic in subroutines you can add variants quickly—homing missiles adjust `BX/BY` each frame, bombs fall until they touch the ground, lasers reset when they hit enemies.

---

### Game Integration

Track shots in arrays for larger games:

```basic
INDEX=I
IF SHOT(INDEX)=0 THEN GOSUB 3200
IF SHOT(INDEX)=1 THEN GOSUB 3400
```

Keep the launch routine at line `3200` and the update routine at `3400` (tag them with `REM` headers). Loop through the array each frame to keep every projectile in sync with the game loop.

### What You’ve Learnt

- A single flag and cooldown keep projectile logic predictable.
- Launch and update routines split responsibilities cleanly.
- Reusing sprites off-screen saves you from allocating new graphics mid-game.
