Your room-based dungeon works perfectly. You can navigate N/S/E/W instantly, read room descriptions, and explore a graph-based world. Now you need **items**—weapons to equip, potions to heal, keys to unlock doors. This lesson builds a slot-based inventory system using parallel arrays for item data.

**This is where turn-based RPGs shine**: inventory management requires zero real-time updates. Display a list, get input, update data, redisplay. The player can browse 50 items and BASIC won't break a sweat. Compare this to real-time games where rendering item sprites and handling physics interactions causes frame rate drops.

The key insight: **Complex systems become trivial when you remove time pressure**. An inventory system that would require sprite management, collision detection, and smooth animations in a platformer becomes a simple array lookup with text display. BASIC is perfect for this.

---

## The One-Minute Tour

**Inventory Mechanics:**
- **8 fixed slots:** Array-based storage with empty slots marked as 0
- **Item pickup:** Check room for items, find empty slot, add to inventory
- **Item usage:** Display list, select slot, apply effect, remove if consumable
- **Display:** Show numbered list with item names, count filled/total slots
- **Instant updates:** Pure text, no graphics rendering delay

**Data Architecture:**
- **Inventory slots:** `IN(8)` stores item IDs (0 = empty, 1-20 = item)
- **Item database:** `IN$(20)` names, `IT(20)` types, `IE(20)` effects
- **Parallel arrays:** Three arrays indexed by item ID for complete item data
- **Room items:** `RI(12)` maps room number to item ID (0 = no item)

**Item Types:**
- **Type 1 (Weapons):** Modify attack power, stay in inventory after use
- **Type 2 (Consumables):** Heal HP or buff stats, removed after use
- **Type 3 (Key Items):** Unlock doors/progression, used automatically

**Performance Reality:**
- **Inventory display:** Instant (&lt;5ms for 8 items)
- **Item lookup:** Direct array access, no search time
- **After platformers:** Feels incredibly responsive and polished

## Example 1: Basic Inventory Display

Let's start with the core inventory system—display slots, add items, track capacity:

```basic
10 REM INVENTORY DISPLAY
20 REM SIMPLE 8-SLOT INVENTORY
30 PRINT CHR$(147)
40 PRINT "=== INVENTORY SYSTEM ==="
50 PRINT ""
60 REM DEFINE INVENTORY (8 SLOTS)
70 DIM IN$(8)
80 MS=8:REM MAX SLOTS
90 REM ADD SOME TEST ITEMS
100 IN$(1)="RUSTY SWORD"
110 IN$(2)="HEALTH POTION"
120 IN$(3)="IRON KEY"
130 IN$(4)=""
140 IN$(5)=""
150 IN$(6)=""
160 IN$(7)=""
170 IN$(8)=""
180 REM DISPLAY INVENTORY
190 GOSUB 1000
200 PRINT ""
210 PRINT "TRY ADDING AN ITEM..."
220 PRINT "SLOT NUMBER (1-8)? ";
230 INPUT SL
240 IF SL<1 OR SL>8 THEN 220
250 PRINT "ITEM NAME? ";
260 INPUT IN$(SL)
270 PRINT CHR$(147)
280 GOSUB 1000
290 PRINT ""
300 PRINT "PRESS ANY KEY TO CONTINUE"
310 GET K$:IF K$="" THEN 310
320 PRINT CHR$(147)
330 PRINT "REMOVING ITEM FROM SLOT 2..."
340 IN$(2)=""
350 GOSUB 1000
360 END
1000 REM SHOW INVENTORY
1010 PRINT ""
1020 PRINT "=== INVENTORY ==="
1030 FS=0:REM FILLED SLOTS
1040 FOR I=1 TO MS
1050 PRINT I;": ";
1060 IF IN$(I)<>"" THEN PRINT IN$(I);:FS=FS+1
1070 IF IN$(I)="" THEN PRINT "[EMPTY]";
1080 PRINT ""
1090 NEXT I
1100 PRINT "SLOTS: ";FS;"/";MS
1110 PRINT ""
1120 RETURN
```

**What's happening:**
- **Line 70:** `DIM IN$(8)` creates 8 string slots for item names
- **Line 80:** `MS=8` tracks maximum capacity (could be 4, 12, 16 for different games)
- **Lines 100-170:** Pre-populate 3 items for demonstration (SWORD, POTION, KEY)
- **Line 1030:** `FS=0` counts filled slots as we display inventory
- **Line 1060:** If slot has item (`<>""`), print name and increment counter
- **Line 1070:** Empty slots show `[EMPTY]` placeholder
- **Line 1100:** Display "3/8" showing used/total capacity

**Run it.** You'll see a numbered inventory list. Add an item by entering a slot number and name. The system immediately updates. Remove slot 2's item—instant refresh. **This is the foundation**: display, modify, redisplay. Zero lag.

![Screenshot showing inventory list with 3 items and 5 empty slots](/images/commodore-64/phase-0/tier-3/lesson-042/screenshot-1.png)

**The discovery**: Even with complex string operations (comparing `""`, concatenating for display), BASIC handles inventory instantly. Turn-based design eliminates all performance concerns. You could have 100-item inventories with no speed issues.

## Example 2: Complete Inventory with Pickup and Use

Now let's integrate inventory with the room system—pick up items from rooms, use weapons/potions, manage capacity:

```basic
10 REM FULL INVENTORY SYSTEM
20 REM INVENTORY WITH PICKUP AND USE
30 REM DIRECTION CONSTANTS
40 N=1:S=2:E=3:W=4
50 REM INVENTORY (8 SLOTS)
60 DIM IN(8)
70 MS=8:REM MAX SLOTS
80 REM ITEM DATABASE
90 DIM IN$(10):REM ITEM NAMES
100 DIM IT(10):REM ITEM TYPES
110 DIM IE(10):REM ITEM EFFECTS
120 REM ROOM ITEMS
130 DIM RI(6):REM ITEM IN EACH ROOM
140 REM ROOM DATA
150 DIM RN$(6):REM ROOM NAMES
160 DIM RD$(6):REM ROOM DESCRIPTIONS
170 DIM EX(6,4):REM EXITS (ROOM,DIRECTION)
180 REM PLAYER STATS
190 HP=20:MH=20:AT=5
200 REM GAME STATE
210 GS=0:REM 0=PLAYING
220 REM CURRENT ROOM
230 CR=1
240 REM LOAD DATA
250 GOSUB 9000
260 REM MAIN LOOP
270 GOSUB 1000:REM DISPLAY ROOM
280 GOSUB 2000:REM GET COMMAND
290 GOSUB 3000:REM PROCESS COMMAND
300 IF GS=0 THEN 270
310 PRINT CHR$(147)
320 PRINT "THANKS FOR PLAYING!"
330 END
1000 REM DISPLAY ROOM
1010 PRINT CHR$(147)
1020 PRINT "=== ";RN$(CR);" ==="
1030 PRINT RD$(CR)
1040 PRINT ""
1050 REM SHOW ITEM IF PRESENT
1060 IF RI(CR)<>0 THEN PRINT "YOU SEE A ";IN$(RI(CR))
1070 IF RI(CR)<>0 THEN PRINT ""
1080 GOSUB 1100:REM SHOW EXITS
1090 RETURN
1100 REM SHOW EXITS
1110 PRINT "EXITS: ";
1120 IF EX(CR,N)<>0 THEN PRINT "N ";
1130 IF EX(CR,S)<>0 THEN PRINT "S ";
1140 IF EX(CR,E)<>0 THEN PRINT "E ";
1150 IF EX(CR,W)<>0 THEN PRINT "W ";
1160 PRINT ""
1170 RETURN
2000 REM GET COMMAND
2010 PRINT ""
2020 PRINT "HP:";HP;"/";MH;" ATK:";AT
2030 PRINT "(N/S/E/W/GET/USE/INV/QUIT)"
2040 PRINT ""
2050 PRINT "> ";
2060 INPUT C$
2070 RETURN
3000 REM PROCESS COMMAND
3010 REM MOVEMENT
3020 IF C$="N" OR C$="S" OR C$="E" OR C$="W" THEN GOSUB 3100:RETURN
3030 REM INVENTORY COMMANDS
3040 IF C$="GET" THEN GOSUB 4000:RETURN
3050 IF C$="USE" THEN GOSUB 5000:RETURN
3060 IF C$="INV" THEN GOSUB 6000:RETURN
3070 IF C$="QUIT" THEN GS=1:RETURN
3080 PRINT "INVALID COMMAND"
3090 FOR I=1 TO 500:NEXT I
3100 RETURN
3100 REM MOVE
3110 DR=0
3120 IF C$="N" THEN DR=N
3130 IF C$="S" THEN DR=S
3140 IF C$="E" THEN DR=E
3150 IF C$="W" THEN DR=W
3160 IF EX(CR,DR)=0 THEN PRINT "CAN'T GO THAT WAY":FOR I=1 TO 800:NEXT I:RETURN
3170 CR=EX(CR,DR)
3180 RETURN
4000 REM GET ITEM FROM ROOM
4010 REM CHECK ITEM IN ROOM
4020 IF RI(CR)=0 THEN PRINT "NOTHING TO GET":FOR I=1 TO 800:NEXT I:RETURN
4030 REM FIND EMPTY SLOT
4040 GOSUB 4200
4050 IF ES=0 THEN PRINT "INVENTORY FULL":FOR I=1 TO 800:NEXT I:RETURN
4060 REM ADD TO INVENTORY
4070 IN(ES)=RI(CR)
4080 PRINT "GOT ";IN$(RI(CR))
4090 RI(CR)=0:REM REMOVE FROM ROOM
4100 FOR I=1 TO 1000:NEXT I
4110 RETURN
4200 REM FIND EMPTY SLOT
4210 ES=0:REM EMPTY SLOT (0=NONE)
4220 FOR I=1 TO MS
4230 IF IN(I)=0 THEN ES=I:RETURN
4240 NEXT I
4250 RETURN
5000 REM USE ITEM
5010 GOSUB 6000:REM SHOW INVENTORY
5020 REM COUNT ITEMS
5030 FS=0
5040 FOR I=1 TO MS
5050 IF IN(I)<>0 THEN FS=FS+1
5060 NEXT I
5070 IF FS=0 THEN PRINT "INVENTORY EMPTY":FOR I=1 TO 1000:NEXT I:RETURN
5080 PRINT "USE WHICH SLOT (1-";MS;")? ";
5090 INPUT SL
5100 IF SL<1 OR SL>MS THEN RETURN
5110 IF IN(SL)=0 THEN PRINT "EMPTY SLOT":FOR I=1 TO 800:NEXT I:RETURN
5120 REM APPLY ITEM EFFECT
5130 ID=IN(SL)
5140 PRINT ""
5150 PRINT "USED ";IN$(ID)
5160 REM BRANCH BY TYPE
5170 TY=IT(ID)
5180 IF TY=1 THEN GOSUB 5300:REM WEAPON
5190 IF TY=2 THEN GOSUB 5400:REM POTION
5200 IF TY=3 THEN GOSUB 5500:REM KEY
5210 REM REMOVE IF CONSUMABLE
5220 IF IT(ID)=2 THEN IN(SL)=0
5230 FOR I=1 TO 1500:NEXT I
5240 RETURN
5300 REM WEAPON (TYPE 1)
5310 AT=IE(ID)
5320 PRINT "ATTACK NOW ";AT
5330 RETURN
5400 REM POTION (TYPE 2)
5410 HP=HP+IE(ID)
5420 IF HP>MH THEN HP=MH
5430 PRINT "HEALED ";IE(ID);" HP"
5440 RETURN
5500 REM KEY ITEM (TYPE 3)
5510 PRINT "KEY ITEMS USED AUTOMATICALLY"
5520 RETURN
6000 REM SHOW INVENTORY
6010 PRINT ""
6020 PRINT "=== INVENTORY ==="
6030 FS=0:REM FILLED SLOTS
6040 FOR I=1 TO MS
6050 PRINT I;": ";
6060 IF IN(I)<>0 THEN PRINT IN$(IN(I));:FS=FS+1
6070 IF IN(I)=0 THEN PRINT "[EMPTY]";
6080 PRINT ""
6090 NEXT I
6100 PRINT "SLOTS: ";FS;"/";MS
6110 PRINT ""
6120 FOR I=1 TO 1000:NEXT I
6130 RETURN
9000 REM LOAD DATA
9010 REM ITEM DATABASE
9020 FOR I=1 TO 5
9030 READ IN$(I),IT(I),IE(I)
9040 NEXT I
9050 REM ROOM ITEMS
9060 FOR I=1 TO 6
9070 READ RI(I)
9080 NEXT I
9090 REM ROOM DATA
9100 FOR I=1 TO 6
9110 READ RN$(I)
9120 NEXT I
9130 FOR I=1 TO 6
9140 READ RD$(I)
9150 NEXT I
9160 REM EXITS (ROOM,DIRECTION)
9170 FOR I=1 TO 6
9180 FOR J=1 TO 4
9190 READ EX(I,J)
9200 NEXT J
9210 NEXT I
9220 RETURN
9300 REM ITEM DATABASE
9310 DATA "RUSTY SWORD",1,8
9320 DATA "STEEL SWORD",1,12
9330 DATA "HEALTH POTION",2,10
9340 DATA "MEGA POTION",2,20
9350 DATA "IRON KEY",3,0
9400 REM ROOM ITEMS
9410 DATA 0,1,3,0,2,5
9500 REM ROOM NAMES
9510 DATA "ENTRANCE HALL"
9520 DATA "ARMOURY"
9530 DATA "TREASURE ROOM"
9540 DATA "GREAT HALL"
9550 DATA "KITCHEN"
9560 DATA "THRONE ROOM"
9600 REM ROOM DESCRIPTIONS
9610 DATA "A DUSTY ENTRANCE"
9620 DATA "RUSTY WEAPONS LINE THE WALLS"
9630 DATA "GOLD COINS SCATTERED ABOUT"
9640 DATA "A VAST EMPTY CHAMBER"
9650 DATA "COOKING SUPPLIES EVERYWHERE"
9660 DATA "AN ORNATE GOLDEN THRONE"
9700 REM EXITS (N,S,E,W PER ROOM)
9710 DATA 0,4,2,0:REM ROOM 1
9720 DATA 0,0,3,1:REM ROOM 2
9730 DATA 0,0,0,2:REM ROOM 3
9740 DATA 1,0,5,0:REM ROOM 4
9750 DATA 0,0,6,4:REM ROOM 5
9760 DATA 0,0,0,5:REM ROOM 6
```

**Key systems:**

**1. Parallel Array Item Database (Lines 90-110):**
- `IN$(10)` = Item names ("RUSTY SWORD", "HEALTH POTION")
- `IT(10)` = Item types (1=weapon, 2=potion, 3=key)
- `IE(10)` = Item effects (8 attack, 10 HP heal, 0 for keys)
- All indexed by item ID (1-10), like a database table with 3 columns

**2. Room Items (Lines 130, 9400):**
- `RI(6)` stores which item appears in each room
- `RI(2)=1` means Room 2 has Item 1 (RUSTY SWORD)
- `RI(1)=0` means Room 1 (entrance) has no item
- When you GET, item moves from `RI(CR)` to `IN(slot)`

**3. Item Pickup (Lines 4000-4250):**
- **4020:** Check if room has item (`RI(CR)<>0`)
- **4040:** Find first empty slot (`IN(I)=0`)
- **4050:** If no empty slots, print "INVENTORY FULL"
- **4070:** Store item ID in inventory: `IN(ES)=RI(CR)`
- **4090:** Remove from room: `RI(CR)=0`

**4. Item Usage (Lines 5000-5520):**
- **5010:** Show inventory first so player sees slot numbers
- **5130:** Get item ID from selected slot: `ID=IN(SL)`
- **5170:** Branch by item type: `TY=IT(ID)`
- **5180-5200:** Call type-specific handler (weapon/potion/key)
- **5220:** Delete consumables after use: `IF IT(ID)=2 THEN IN(SL)=0`

**5. Item Effects:**
- **Weapon (5300):** Set attack power `AT=IE(ID)` (e.g., STEEL SWORD = 12 attack)
- **Potion (5400):** Heal HP `HP=HP+IE(ID)`, cap at max `IF HP>MH`
- **Key (5500):** Placeholder for door unlocking (next lessons)

**Run it.** Enter Room 2 (Armoury), type GET to pick up RUSTY SWORD. Check INV to see it in slot 1. Walk to Room 3 (Treasure Room), GET the HEALTH POTION. Type USE, select slot 2, watch HP increase. Type USE again, select slot 1, see attack power change. **Items persist across rooms.** Consumables (potions) disappear after use. Equipment (swords) stays.

**The revelation**: This is a complete RPG item system—pickup, storage, usage, effects, persistence—and it runs **instantly**. No sprite management, no collision detection, no render loops. Turn-based design makes complex game systems trivial to implement.

## Parallel Arrays: The Database Pattern

The item database uses **parallel arrays**—multiple arrays indexed by the same ID:

```
Item ID:    1             2             3             4
IN$(ID):    "RUSTY SWORD" "STEEL SWORD" "HEALTH POT"  "MEGA POT"
IT(ID):     1 (weapon)    1 (weapon)    2 (potion)    2 (potion)
IE(ID):     8 (attack)    12 (attack)   10 (heal)     20 (heal)
```

**Why this works:**
- **Single lookup:** `ID=3` gets all data (name, type, effect) from three arrays
- **Easy expansion:** Add item 11-20 just by extending DATA statements
- **Type safety:** `IT(ID)` determines behaviour (equip vs consume)
- **Memory efficient:** Only store data for items that exist (not all 100 possible items)

**Alternative (worse) approach:**
```basic
10 REM DON'T DO THIS
20 IF ID=1 THEN N$="RUSTY SWORD":TY=1:EF=8
30 IF ID=2 THEN N$="STEEL SWORD":TY=1:EF=12
40 IF ID=3 THEN N$="HEALTH POTION":TY=2:EF=10
...
```

This requires 300+ lines of IF statements for 100 items. Parallel arrays keep it clean.

## Inventory Capacity Management

**The design choice: 8 fixed slots**

**Pros:**
- Forces strategic decisions (what to carry?)
- Creates "full inventory" gameplay moment
- Simple to display (fits on screen)
- Classic RPG feel

**Cons:**
- Can frustrate players ("Why can't I carry more?")
- Requires backtracking to swap items
- Needs drop/stash system for full inventory

**Alternatives:**

**16 slots (comfortable):**
```basic
70 MS=16:DIM IN(16)
```
Most items fit, rare full-inventory situations. Good for 30+ minute games.

**4 slots (hardcore):**
```basic
70 MS=4:DIM IN(4)
```
Forces brutal choices. Good for puzzle games where inventory space is a constraint.

**Unlimited (easy mode):**
```basic
70 MS=100:DIM IN(100)
```
Never worry about space. Removes inventory management as a game mechanic.

**The lesson rule of thumb:** `SLOTS = (GAME_LENGTH_MINUTES / 3) + 2`
- 15 minute game → 7 slots
- 30 minute game → 12 slots
- 60 minute game → 22 slots

Balance between "never full" and "always juggling".

## Item Type Patterns

**Type 1: Equipment (stays in inventory)**
```basic
5300 REM WEAPON
5310 AT=IE(ID):REM SET ATTACK
5320 PRINT "ATTACK NOW ";AT
5330 RETURN
```
Modifies player stats. Effect persists until different item equipped. Examples: SWORD (attack), ARMOUR (defence), BOOTS (speed).

**Type 2: Consumables (removed after use)**
```basic
5400 REM POTION
5410 HP=HP+IE(ID):REM HEAL
5420 IF HP>MH THEN HP=MH
5430 PRINT "HEALED ";IE(ID);" HP"
5440 RETURN
...
5220 IF IT(ID)=2 THEN IN(SL)=0:REM DELETE
```
One-time effect then vanishes. Examples: POTION (heal), BOMB (damage), SCROLL (buff).

**Type 3: Key Items (automatic usage)**
```basic
5500 REM KEY
5510 PRINT "KEY ITEMS USED AUTOMATICALLY"
5520 RETURN
```
Checked when needed (approaching locked door). Examples: IRON KEY (opens iron door), MAP (reveals rooms), TORCH (lights dark areas).

**Extending to Type 4: Quest Items**
```basic
120 DIM IQ(10):REM QUEST FLAGS
...
5600 REM QUEST ITEM
5610 IQ(IE(ID))=1:REM SET QUEST FLAG
5620 PRINT "QUEST ITEM RECORDED"
5630 RETURN
```
Triggers events or dialogue. Examples: KING'S LETTER (starts quest), DRAGON EGG (boss appears).

## Full Inventory Handling

**Problem:** Player tries GET with 8/8 slots full.

**Solution 1: Block pickup (current)**
```basic
4050 IF ES=0 THEN PRINT "INVENTORY FULL":RETURN
```
Simple, clear feedback. Forces player to USE/DROP something first.

**Solution 2: Drop oldest item**
```basic
4050 IF ES=0 THEN IN(1)=RI(CR):RI(CR)=IN(1):PRINT "SWAPPED ITEM":RETURN
```
Auto-drops slot 1, picks up new item. Fast but confusing (what did I lose?).

**Solution 3: Choose item to drop**
```basic
4050 IF ES=0 THEN GOSUB 6000:INPUT "DROP WHICH SLOT";DS:RI(CR)=IN(DS):IN(DS)=RI(CR):RETURN
```
Player control but more complex. Best for strategy games.

**Solution 4: Leave on ground**
```basic
4050 IF ES=0 THEN PRINT "LEFT ON GROUND":RETURN
```
Item stays in room, pick up later. Requires persistent room items (not removed).

**Recommendation:** Start with Solution 1 (block), add Solution 3 (choose) if playtesting shows frustration.

## Item Stacking

**Problem:** Finding 5 potions uses 5 slots (40% of inventory for one item type).

**Solution: Stack counter**
```basic
60 DIM IN(8):REM ITEM IDS
65 DIM IC(8):REM ITEM COUNTS
...
4070 REM WHEN PICKING UP
4080 FOR I=1 TO MS
4090 IF IN(I)=RI(CR) THEN IC(I)=IC(I)+1:GOTO 4110
4100 NEXT I
4105 IN(ES)=RI(CR):IC(ES)=1:REM NEW STACK
4110 RI(CR)=0
...
5220 REM WHEN USING CONSUMABLE
5225 IC(SL)=IC(SL)-1
5230 IF IC(SL)=0 THEN IN(SL)=0
```

**Display with counts:**
```basic
6060 IF IN(I)<>0 THEN PRINT IN$(IN(I));" X";IC(I);:FS=FS+1
```

Shows "HEALTH POTION X5" instead of 5 separate slots. Major quality-of-life improvement for games with common consumables.

## Extending the System

**Item descriptions (examine command):**
```basic
90 DIM ID$(10):REM ITEM DESCRIPTIONS
...
7000 REM EXAMINE
7010 GOSUB 6000:INPUT "EXAMINE WHICH";SL
7020 IF IN(SL)=0 THEN RETURN
7030 PRINT ID$(IN(SL))
7040 RETURN
...
9300 DATA "RUSTY SWORD",1,8,"OLD BUT SHARP"
```

**Item durability:**
```basic
65 DIM IU(8):REM USES REMAINING
...
5310 AT=IE(ID)
5315 IU(SL)=IU(SL)-1
5320 IF IU(SL)=0 THEN PRINT "WEAPON BROKE":IN(SL)=0
```

**Item shops:**
```basic
8000 REM SHOP
8010 PRINT "ITEMS FOR SALE:"
8020 FOR I=1 TO 5:PRINT I;":";IN$(I);" ";IE(I)*10;"GP":NEXT I
8030 INPUT "BUY WHICH";B
8040 IF GP<IE(B)*10 THEN PRINT "NOT ENOUGH GOLD":RETURN
8050 GOSUB 4200:IF ES=0 THEN PRINT "INVENTORY FULL":RETURN
8060 GP=GP-IE(B)*10:IN(ES)=B:PRINT "BOUGHT ";IN$(B)
8070 RETURN
```

All instant. Text-based systems scale effortlessly.

## Performance Reality Check

**Inventory operations (8 slots, 20 items):**
- Display inventory: ~2ms (8 PRINT loops)
- Find empty slot: ~1ms (8 comparisons)
- Item lookup: &lt;0.1ms (direct array access `IN$(ID)`)
- Use item effect: &lt;1ms (3-way branch + math)

**Total time from "USE" command to effect applied:** ~5ms

**Reality:** You could have 100-item inventories with complex effects and BASIC would still feel instant. Turn-based design eliminates all performance concerns. This is why classic RPGs on slow hardware (C64, ZX Spectrum, even Apple II) had sophisticated inventory systems—text rendering is essentially free compared to graphics.

## What You've Learnt

- **Slot-based inventory:** Fixed-size array with empty slot detection
- **Parallel arrays:** Database pattern for item properties (name/type/effect)
- **Item pickup:** Move item from room to first empty inventory slot
- **Item usage:** Apply type-specific effects, remove consumables
- **Capacity management:** Handle full inventory gracefully
- **Item types:** Weapons (persistent), consumables (one-use), key items (auto-use)
- **Turn-based advantage:** Complex systems run instantly with zero performance overhead

**Next lesson:** You'll add NPC dialogue and item trading—give items to characters, receive quests, unlock story events. The inventory system becomes your interface to the game world.

**The pattern emerging:** Turn-based RPGs eliminate BASIC's speed limitations by removing continuous updates. Every system (navigation, inventory, combat, dialogue) becomes an instant text operation. This is why text RPGs remained popular on 1980s hardware—they were perfectly matched to BASIC's strengths.
