## The One-Minute Tour

**Gravity Physics:**
- **Constant acceleration** applies every frame: `VY = VY + GRAVITY`
- **Gravity values** typically 0.2-0.4 (pixels per frame squared)
- **Terminal velocity** prevents infinite acceleration (typically 6-10 pixels/frame)
- **Creates realistic falling** with increasing speed over time

**Jumping Mechanics:**
- **Instant velocity override** when grounded: `VY = JUMP_POWER` (negative = upward)
- **Only works on ground** checked with `ON_GROUND` flag
- **Gravity brings you down** automatically creating parabolic arc
- **Parameter tuning** balances jump height with gravity strength

**Ground Detection:**
- **Simple floor check:** `IF Y >= GROUND_LEVEL AND VY >= 0`
- **Snap to ground** prevents sinking: `Y = GROUND_LEVEL: VY = 0`
- **Sets grounded flag** allowing next jump
- **Foundation for platforms** (next lesson expands to multiple heights)

## Example 1: Simple Gravity

Let's start by seeing gravity in action—a sprite falling and landing:

```basic
10 REM SIMPLE GRAVITY DEMO
20 REM SHOWS CONSTANT DOWNWARD ACCELERATION
30 PRINT CHR$(147)
40 REM SPRITE SETUP
50 POKE 53248,100:POKE 53249,50
60 POKE 2040,13:POKE 53269,1:POKE 53287,1
70 REM DRAW SIMPLE SPRITE (BALL)
80 FOR I=0 TO 62:POKE 832+I,0:NEXT
90 POKE 832,60:POKE 833,126:POKE 834,255
100 POKE 835,255:POKE 836,255:POKE 837,126:POKE 838,60
110 REM PHYSICS VARIABLES
120 Y=50:REM STARTING Y POSITION
130 VY=0:REM VERTICAL VELOCITY
140 GR=0.3:REM GRAVITY CONSTANT
150 GD=200:REM GROUND LEVEL
160 REM MAIN LOOP
170 VY=VY+GR:REM APPLY GRAVITY
180 Y=Y+VY:REM UPDATE POSITION
190 REM CHECK GROUND COLLISION
200 IF Y>=GD THEN Y=GD:VY=0
210 REM UPDATE SPRITE
220 POKE 53249,INT(Y)
230 REM SMALL DELAY FOR VISIBILITY
240 FOR D=1 TO 50:NEXT D
250 REM SHOW STATUS
260 POKE 214,0:PRINT:PRINT "Y:";INT(Y);" VY:";INT(VY*10)/10
270 IF Y<GD THEN 170
280 PRINT:PRINT "LANDED ON GROUND!"
```

![Gravity demonstration showing sprite falling and landing](/images/commodore-64/phase-0/tier-3/lesson-033/screenshot-1.png)

**What happens:**
- Line 170: Velocity increases by 0.3 each frame (acceleration)
- Line 180: Position changes by velocity (motion)
- Line 200: Ground collision stops fall when Y reaches 200
- Line 260: Status display shows Y position and velocity

**The physics loop:**
```
Frame 1: VY=0, apply gravity → VY=0.3, Y=50.3
Frame 2: VY=0.3, apply gravity → VY=0.6, Y=50.9
Frame 3: VY=0.6, apply gravity → VY=0.9, Y=51.8
...
Velocity increases each frame (acceleration)
Position changes faster each frame (falling)
Eventually: Y >= 200, collision detected, landing
```

This demonstrates **constant acceleration**—the foundation of realistic physics.

## Example 2: Jumping System

Now add jumping with joystick control:

```basic
10 REM GRAVITY AND JUMPING
20 REM COMPLETE PLATFORMER PHYSICS
30 PRINT CHR$(147)
40 REM SPRITE SETUP
50 POKE 53248,100:POKE 53249,100
60 POKE 2040,13:POKE 53269,1:POKE 53287,1
70 REM DRAW SPRITE (PLAYER CHARACTER)
80 FOR I=0 TO 62:POKE 832+I,0:NEXT
90 POKE 832,60:POKE 833,126:POKE 834,255
100 POKE 835,255:POKE 836,255:POKE 837,126:POKE 838,60
110 REM PHYSICS VARIABLES
120 X=100:Y=100:REM POSITION
130 VX=0:VY=0:REM VELOCITY
140 GR=0.3:REM GRAVITY
150 JP=-5:REM JUMP POWER (NEGATIVE = UP)
160 GD=200:REM GROUND LEVEL
170 OG=0:REM ON GROUND FLAG (0=AIR, 1=GROUND)
180 REM MAIN LOOP
190 GOSUB 1000:REM JOYSTICK INPUT
200 GOSUB 2000:REM APPLY GRAVITY
210 GOSUB 3000:REM UPDATE POSITION
220 GOSUB 4000:REM GROUND COLLISION
230 GOSUB 5000:REM UPDATE SPRITE
240 GOTO 190
1000 REM JOYSTICK INPUT
1010 J=PEEK(56320)
1020 REM HORIZONTAL MOVEMENT
1030 VX=0:REM RESET (ARCADE-STYLE)
1040 IF (J AND 4)=0 THEN VX=-2:REM LEFT
1050 IF (J AND 8)=0 THEN VX=2:REM RIGHT
1060 REM JUMPING (ONLY IF ON GROUND)
1070 IF (J AND 16)=0 AND OG=1 THEN VY=JP:OG=0
1080 RETURN
2000 REM APPLY GRAVITY
2010 VY=VY+GR:REM CONSTANT DOWNWARD ACCELERATION
2020 REM TERMINAL VELOCITY (OPTIONAL)
2030 IF VY>8 THEN VY=8
2040 RETURN
3000 REM UPDATE POSITION
3010 X=X+VX:Y=Y+VY
3020 REM HORIZONTAL BOUNDARIES
3030 IF X<24 THEN X=24
3040 IF X>320 THEN X=320
3050 RETURN
4000 REM GROUND COLLISION
4010 IF Y>=GD AND VY>=0 THEN GOSUB 4100:RETURN
4020 OG=0:REM IN AIR
4030 RETURN
4100 REM LAND ON GROUND
4110 Y=GD:VY=0:OG=1
4120 RETURN
5000 REM UPDATE SPRITE
5010 POKE 53248,INT(X)
5020 POKE 53249,INT(Y)
5030 RETURN
```

![Interactive gravity and jumping system](/images/commodore-64/phase-0/tier-3/lesson-033/screenshot-2.png)

**How it works:**

**Line 1070: Jump Check**
```basic
IF (J AND 16)=0 AND OG=1 THEN VY=JP:OG=0
```
- Fire button pressed (`J AND 16 = 0`)
- Player is on ground (`OG=1`)
- Set upward velocity (`VY=JP=-5`)
- Clear grounded flag (`OG=0` prevents double-jump)

**Line 2010: Gravity Application**
```basic
VY=VY+GR
```
- Always applies, even during jump
- Slows upward motion
- Creates parabolic arc
- Eventually reverses direction

**Line 4010: Ground Detection**
```basic
IF Y>=GD AND VY>=0 THEN GOSUB 4100
```
- Check if at or below ground level
- Check if moving downward (`VY>=0`)
- Both conditions required for landing

**Jump trajectory:**
```
Jump starts:  VY=-5 (upward)
Frame 1:      VY=-5+0.3=-4.7 (still going up)
Frame 2:      VY=-4.7+0.3=-4.4 (still going up)
...
Frame 17:     VY=-0.2+0.3=0.1 (peak, start falling)
Frame 18:     VY=0.1+0.3=0.4 (falling)
...
Eventually:   Y>=GROUND, land
```

Natural parabola with no special cases.

## Understanding Gravity

**Why constant acceleration matters:**

In real physics, gravity accelerates objects at 9.8 m/s² regardless of mass. In games, we simulate this with small constant additions to velocity:

```basic
VY = VY + GRAVITY   ' Acceleration (velocity changes)
Y = Y + VY          ' Velocity (position changes)
```

This creates **quadratic motion** (position changes based on t²), which is why falling objects travel farther each frame:

```
Time 0: Y=0, VY=0
Time 1: VY=0.3, Y=0.3 (travelled 0.3)
Time 2: VY=0.6, Y=0.9 (travelled 0.6)
Time 3: VY=0.9, Y=1.8 (travelled 0.9)
Time 4: VY=1.2, Y=3.0 (travelled 1.2)
```

Each frame travels more distance—this is acceleration.

**Terminal velocity prevents runaway speed:**

Line 2030 caps maximum fall speed:
```basic
IF VY>8 THEN VY=8
```

Without this, objects falling from great heights would accelerate indefinitely, potentially skipping through platforms. Terminal velocity also feels more natural—real objects reach maximum speed due to air resistance.

## Parameter Tuning

**Finding the right feel requires experimentation:**

### Gravity Values

**Low gravity (0.1-0.2): Floaty, moon-like**
- Slow falls
- High jumps last longer
- Difficult precise landing
- Good for space themes

**Standard gravity (0.3-0.4): Platformer feel**
- Balanced control
- Predictable arcs
- Most games use this range
- Feels "right" to players

**High gravity (0.5-0.8): Heavy, fast fall**
- Quick returns to ground
- Shorter jump arcs
- More challenging timing
- Good for difficult games

**Very high gravity (1.0+): Difficult control**
- Barely leaves ground
- Hard to time jumps
- Feels unresponsive
- Usually too extreme

### Jump Power

**Formula:** `JUMP_POWER ≈ -(GRAVITY × 15 to 20)`

This ensures jump height feels proportional to gravity strength:

| Gravity | Jump Power | Jump Height |
|---------|-----------|-------------|
| 0.2 | -3 to -4 | Low (1-2 char) |
| 0.3 | -5 to -6 | Medium (3-4 char) |
| 0.5 | -7 to -10 | High (5+ char) |

**Experiment to find your game's feel:**
```basic
10 GR=0.3   : REM Try 0.2, 0.3, 0.5
20 JP=-5    : REM Try -3 to -10
30 TV=8     : REM Try 6 to 10
```

Run the program, feel the difference. There's no "correct" value—only what feels right for your game.

## Game Integration

**How games use gravity and jumping:**

**Mario (1985):**
- Gravity: ~0.35
- Jump: Variable (hold button longer = higher)
- Multiple jump heights for precise control
- Different gravity going up vs down (falls faster than rises)

**Manic Miner (1983):**
- Gravity: ~0.4
- Jump: Fixed height parabola
- Cannot control jump arc mid-air
- Precise timing required

**Jet Set Willy (1984):**
- Similar to Manic Miner
- Fixed jump arcs
- Challenge comes from predicting landing
- Gravity reveals platform layouts

**Your platformer choices:**

1. **Fixed jump (easier code):** Press fire, always same height
2. **Variable jump (better feel):** Hold longer = higher jump
3. **Double jump (modern feel):** Allow second jump mid-air
4. **Air control:** Change horizontal velocity while jumping

Example 2 uses **fixed jump with full air control**—simple but effective.

**Assembly language differences:**

The physics calculations (`VY=VY+GR`) are identical in assembly—still just addition. The difference is **update frequency**. Assembly games run physics at 50-60 fps, BASIC at 15-25 fps. The maths is the same, the responsiveness differs.

## Common Pitfalls

**1. Wrong gravity direction**

Remember: **Y increases downward** on computers (opposite of maths class).

```basic
VY = VY + 0.3   ' Correct: positive = down
VY = VY - 0.3   ' Wrong: negative = up (sprite floats away!)
```

**2. Jumping while airborne**

Without the grounded check:
```basic
IF (J AND 16)=0 THEN VY=JP   ' Wrong: can jump mid-air infinitely
```

This creates "infinite jump" where holding fire flies you to the top of the screen. Sometimes fun, usually not intended!

**3. Forgetting terminal velocity**

```basic
' No velocity cap
VY = VY + GR
' Sprite accelerates forever, eventually teleports through ground
```

Always cap maximum speed:
```basic
IF VY>8 THEN VY=8
```

**4. Floating point precision**

Comparing floating point numbers directly can miss collisions:
```basic
IF Y=GD THEN Y=GD:VY=0   ' Wrong: Y might be 200.3, not exactly 200
```

Always use `>=` for ground checks:
```basic
IF Y>=GD THEN Y=GD:VY=0   ' Correct: catches Y >= ground
```
