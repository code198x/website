# Bringing Sprites to Life

You've learnt to move sprites around the screen, but stationary sprites feel lifeless. Real games use **animation**—switching between multiple sprite shapes rapidly to create the illusion of movement. A walking character, a rotating weapon, an exploding enemy—all require multi-frame animation.

In this lesson, you'll learn to create smooth animation sequences by switching sprite data pointers, manage complex animation states (walking left, jumping, attacking), and control timing so animations play at the right speed.

---

## The One-Minute Tour

**Animation Fundamentals:**
- **Multi-frame sequences** - 2-8 sprite shapes that cycle to create motion
- **Sprite pointers** - Registers 2040-2047 ($07F8-$07FF) point to sprite data
- **Frame timing** - Use TI jiffy clock to control animation speed
- **State machines** - Track which animation should play (IDLE=0, WALK=1, JUMP=2)

**Memory Cost:**
- Each sprite frame = 63 bytes of data
- 3-frame walk cycle = 189 bytes
- 8-frame smooth animation = 504 bytes

**Critical Behaviour:**
- BASIC is too slow for 50fps animation (every frame)
- 2-4 frame animations at 12-25fps look convincing
- Assembly games achieve 8+ frames at 50fps smoothly

## Example 1: Simple 2-Frame Walk Cycle

Let's start with the simplest convincing animation—a 2-frame walk cycle like *Boulder Dash*'s Rockford:

```basic
10 PRINT CHR$(147):REM CLEAR SCREEN
20 REM LOAD TWO SPRITE FRAMES
30 FOR I=0 TO 62
40 READ B:POKE 832+I,B:REM FRAME 1
50 NEXT
60 FOR I=0 TO 62
70 READ B:POKE 896+I,B:REM FRAME 2
80 NEXT
90 REM SETUP SPRITE 0
100 POKE 2040,13:REM POINT TO FRAME 1 (832/64=13)
110 POKE 53269,1:REM ENABLE SPRITE 0
120 POKE 53287,5:REM GREEN COLOUR
130 POKE 53248,100:POKE 53249,100
140 REM ANIMATION LOOP
150 F=0:T=TI:REM FRAME COUNTER, TIMER
160 IF TI-T<4 THEN 160:REM WAIT 4 JIFFIES
170 T=TI:REM RESET TIMER
180 F=1-F:REM TOGGLE FRAME (0→1, 1→0)
190 POKE 2040,13+F:REM SWITCH POINTER
200 GOTO 160
210 REM FRAME 1 DATA (LEGS TOGETHER)
220 DATA 0,126,0,1,255,128,3,231,192
230 DATA 3,231,192,3,231,192,1,255,128
240 DATA 1,255,128,0,126,0,0,126,0
250 DATA 0,126,0,0,60,0,0,60,0
260 DATA 0,24,0,0,24,0,0,24,0
270 DATA 0,60,0,0,102,0,0,195,0
280 DATA 0,0,0,0,0,0,0,0,0
290 REM FRAME 2 DATA (LEGS APART)
300 DATA 0,126,0,1,255,128,3,231,192
310 DATA 3,231,192,3,231,192,1,255,128
320 DATA 1,255,128,0,126,0,0,126,0
330 DATA 0,126,0,0,60,0,0,60,0
340 DATA 0,24,0,0,24,0,0,24,0
350 DATA 0,36,0,0,102,0,1,131,0
360 DATA 0,0,0,0,0,0,0,0,0
```

![Two-frame walk cycle animation](/images/commodore-64/phase-0/tier-3/lesson-033/example-1-screenshot.png)

**What's Happening:**
- Lines 30-80: Load two sprite frames into memory at 832 (block 13) and 896 (block 14)
- Line 100: Sprite pointer 2040 points to block 13 (first frame)
- Lines 160-170: Wait 4 jiffies between frames (about 12.5fps)
- Line 180: Toggle F between 0 and 1
- Line 190: POKE 2040 with 13+F (alternates between 13 and 14)

**Result:** Smooth 2-frame walk animation using only 126 bytes of sprite data.

## Example 2: 4-Frame Directional Animation

Now let's create a more complex animation with direction changes—like *Commando* or *Monty Mole*:

```basic
10 PRINT CHR$(147):REM CLEAR SCREEN
20 REM LOAD 4 FRAMES (2 LEFT, 2 RIGHT)
30 FOR F=0 TO 3
40 FOR I=0 TO 62
50 READ B:POKE 12288+(F*64)+I,B
60 NEXT:NEXT
70 REM SETUP SPRITE 0
80 POKE 2040,192:REM START WITH FRAME 0
90 POKE 53269,1:REM ENABLE SPRITE 0
100 POKE 53287,7:REM YELLOW COLOUR
110 X=160:Y=100:REM CENTRE POSITION
120 D=0:REM DIRECTION (0=RIGHT, 1=LEFT)
130 FR=0:REM CURRENT FRAME
140 T=TI:REM TIMER
150 REM GAME LOOP
160 POKE 53248,X:POKE 53249,Y
170 REM READ JOYSTICK
180 J=15-PEEK(56320)AND15
190 IF J=8 THEN X=X-2:D=1:REM LEFT
200 IF J=4 THEN X=X+2:D=0:REM RIGHT
210 REM ANIMATE ONLY IF MOVING
220 IF J=0 THEN 260:REM NO MOVEMENT
230 IF TI-T<3 THEN 260:REM WAIT 3 JIFFIES
240 T=TI:FR=1-FR:REM TOGGLE FRAME
250 REM SET SPRITE POINTER
260 POKE 2040,192+(D*2)+FR
270 GOTO 160
280 REM RIGHT WALK FRAMES (BLOCKS 192-193)
290 DATA 0,126,0,1,255,128,3,231,192
300 DATA 3,231,192,3,231,192,1,255,128
310 DATA 1,255,128,0,126,0,0,126,0
320 DATA 0,126,0,0,60,0,0,60,0
330 DATA 0,24,0,0,24,0,0,24,0
340 DATA 0,60,0,0,102,0,0,195,0
350 DATA 0,0,0,0,0,0,0,0,0
360 DATA 0,126,0,1,255,128,3,231,192
370 DATA 3,231,192,3,231,192,1,255,128
380 DATA 1,255,128,0,126,0,0,126,0
390 DATA 0,126,0,0,60,0,0,60,0
400 DATA 0,24,0,0,24,0,0,24,0
410 DATA 0,36,0,0,102,0,1,131,0
420 DATA 0,0,0,0,0,0,0,0,0
430 REM LEFT WALK FRAMES (BLOCKS 194-195)
440 DATA 0,126,0,1,255,128,3,231,192
450 DATA 3,231,192,3,231,192,1,255,128
460 DATA 1,255,128,0,126,0,0,126,0
470 DATA 0,126,0,0,60,0,0,60,0
480 DATA 0,24,0,0,24,0,0,24,0
490 DATA 0,60,0,0,102,0,0,195,0
500 DATA 0,0,0,0,0,0,0,0,0
510 DATA 0,126,0,1,255,128,3,231,192
520 DATA 3,231,192,3,231,192,1,255,128
530 DATA 1,255,128,0,126,0,0,126,0
540 DATA 0,126,0,0,60,0,0,60,0
550 DATA 0,24,0,0,24,0,0,24,0
560 DATA 0,36,0,0,102,0,1,131,0
570 DATA 0,0,0,0,0,0,0,0,0
```

![Four-frame directional animation with joystick control](/images/commodore-64/phase-0/tier-3/lesson-033/example-2-screenshot.png)

**Key Concepts:**
- **Direction variable (D)**: 0=right, 1=left
- **Frame variable (FR)**: Toggles 0→1 for each direction
- **Pointer calculation**: `192 + (D*2) + FR`
  - Right frame 1: 192 + (0*2) + 0 = 192
  - Right frame 2: 192 + (0*2) + 1 = 193
  - Left frame 1: 192 + (1*2) + 0 = 194
  - Left frame 2: 192 + (1*2) + 1 = 195
- **Animation only when moving** (line 220): Saves CPU cycles
- **Memory location 12288** (block 192): Safe area well above BASIC program

70 REM SETUP SPRITE 0

90 POKE 53269,1:REM ENABLE SPRITE 0
100 POKE 53287,3:REM CYAN COLOUR

120 S=0:REM STATE (0=IDLE, 1=WALK)
130 FR=0:REM FRAME COUNTER
140 T=TI:REM TIMER
150 REM GAME LOOP

170 REM READ JOYSTICK
180 J=15-PEEK(56320)AND15
190 IF J<>0 THEN S=1:GOTO 220
200 REM NO MOVEMENT = IDLE STATE
210 S=0
220 REM HANDLE MOVEMENT

![Animation state machine with idle and walk states](/images/commodore-64/phase-0/tier-3/lesson-033/example-3-screenshot.png)

**State Machine Pattern:**
- **S=0** (IDLE): 2-frame subtle animation when not moving
- **S=1** (WALK): 4-frame walk cycle when joystick moves
- **Variable name note**: Used `S` not `ST` (ST is reserved for I/O status in BASIC)
- **Different frame counts per state**: IDLE uses 2 frames, WALK uses 4 frames
- **Pointer calculation**:
  - IDLE: Blocks 192-193 (FR cycles 0→1)
  - WALK: Blocks 194-197 (FR cycles 0→3)
- **Memory location 12288**: Allows room for 6 full frames (384 bytes)

**This pattern scales:** Expand states to include JUMP, ATTACK, CROUCH, CLIMB.

## Understanding Animation Timing

Animation speed is controlled by how long you wait between frame changes:

**Frame Rate Chart:**

| Jiffies | FPS | Games Using This |
|---------|-----|------------------|
| 1 | 50 | Too fast (flickery in BASIC) |
| 2 | 25 | Fast action (assembly games) |
| 3 | 16.7 | Good BASIC speed (*Commando*-style) |
| 4 | 12.5 | Smooth BASIC animation (*Boulder Dash*) |
| 5 | 10 | Slow but deliberate |
| 6-8 | 6-8 | Very slow (large sprites) |

**Memory vs Smoothness Trade-off:**

```
2 frames × 63 bytes = 126 bytes  → Minimal but effective
4 frames × 63 bytes = 252 bytes  → Good balance
8 frames × 63 bytes = 504 bytes  → Silky smooth (rare in BASIC)
```

**Why 2-4 frames work:**
- Human eye accepts low frame rates if timing is consistent
- *Boulder Dash* uses 2 frames and looks great
- *Impossible Mission* uses 3-4 frames per action
- More frames = diminishing returns in BASIC (speed overhead)

## Animation State Machine Pattern

State machines organize complex behaviour:

```basic
100 ST=0:REM CURRENT STATE
110 REM 0=IDLE, 1=WALK, 2=JUMP, 3=ATTACK

200 REM UPDATE STATE BASED ON INPUT
210 IF BUTTON PRESSED THEN ST=3:REM ATTACK
220 IF MOVING THEN ST=1:REM WALK
230 IF AIRBORNE THEN ST=2:REM JUMP
240 IF NOTHING THEN ST=0:REM IDLE

300 REM CALCULATE SPRITE POINTER
310 BASE=13:REM FIRST SPRITE BLOCK
320 POINTER=BASE+(ST*2)+FR
330 POKE 2040,POINTER
```

**State Priority:** Some states override others:
1. **JUMP** - highest priority (can't walk in mid-air)
2. **ATTACK** - interrupts walking
3. **WALK** - only if grounded
4. **IDLE** - default state

## Game Context: How Commercial Games Animated

### Simple But Effective (2-3 Frames)
- **Boulder Dash** (1984): Rockford's 2-frame walk is iconic
- **Lode Runner** (1983): Minimal animation, maximum gameplay

- **Kung Fu Master** (1985): Punch, kick, walk, crouch animations

### Combat Animation (6-8 Frames)
- **Barbarian** (1987): Multiple sword attack sequences
- **International Karate** (1986): 20+ martial arts moves
- **The Last Ninja** (1987): Complex combat and movement states

- **Mayhem in Monsterland** (1993): 8-frame walk cycles at 50fps
- **Creatures** (1990): Smooth large sprite animation
- **Bubble Bobble** (1987): Bub and Bob's detailed animation

**BASIC Reality:** You can achieve 2-4 frame animation convincingly. Assembly removes the speed ceiling for 8+ frames.

## Quick Reference

### Sprite Pointer Locations

| Sprite | Pointer Address | Decimal |
|--------|----------------|---------|
| 0 | $07F8 | 2040 |
| 1 | $07F9 | 2041 |
| 2 | $07FA | 2042 |
| 3 | $07FB | 2043 |
| 4 | $07FC | 2044 |
| 5 | $07FD | 2045 |
| 6 | $07FE | 2046 |
| 7 | $07FF | 2047 |

**Formula:** Sprite pointer = Memory address / 64

**Example:** Sprite data at 832 → 832/64 = 13 → POKE 2040,13

### Memory Layout Planning

**Small Animations (2-3 frames):**
```
Frame 0: 832 (Block 13) → POKE 2040,13
Frame 1: 896 (Block 14) → POKE 2040,14
Frame 2: 960 (Block 15) → POKE 2040,15
```
**Formula:** Address = 832 + (frame × 64)
**Safe up to block 15** (1023 bytes, just before screen RAM at 1024)

**Larger Animations (4+ frames):**
```
Frame 0: 12288 (Block 192) → POKE 2040,192
Frame 1: 12352 (Block 193) → POKE 2040,193
Frame 2: 12416 (Block 194) → POKE 2040,194
Frame 3: 12480 (Block 195) → POKE 2040,195
```
**Formula:** Address = 12288 + (frame × 64)
**Safe for many frames** - well above BASIC program area

### Animation Speed Calculator

**Target FPS → Jiffies:**
```
Jiffies = 50 / Desired FPS
```

Examples:
- 25 FPS → 50/25 = 2 jiffies
- 12.5 FPS → 50/12.5 = 4 jiffies
- 10 FPS → 50/10 = 5 jiffies

### State Machine Template

```basic
100 REM STATE DEFINITIONS
110 IDLE=0:WALK=1:JUMP=2:ATTACK=3
120 ST=IDLE:REM CURRENT STATE
130 FR=0:REM FRAME WITHIN STATE (0-1)

200 REM UPDATE STATE
210 IF [condition] THEN ST=ATTACK
220 IF [condition] THEN ST=JUMP
230 IF [condition] THEN ST=WALK
240 IF [condition] THEN ST=IDLE

300 REM ANIMATE
310 IF TI-T<4 THEN 330
320 T=TI:FR=1-FR:REM TOGGLE FRAME
330 POKE 2040,32+(ST*2)+FR
```

## What You've Learnt

- Multi-frame sprite animation creates illusion of movement by switching sprite pointers
- 2-4 frame animations look convincing in BASIC with proper timing
- State machines organize complex character behaviour (IDLE, WALK, JUMP, ATTACK)
- TI jiffy clock controls animation speed (3-5 jiffies = 10-16 fps works well)
- Memory cost: 63 bytes per frame (plan accordingly)
- BASIC can achieve good animation; assembly enables 8+ frame smoothness
- Pointer calculation: `BASE + (STATE*2) + FRAME` for state-based animation
