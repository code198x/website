## Example 2: Connect Four Display

Connect Four demonstrates perfect turn-based gameplay with complex win detection:

```basic
10 REM CONNECT FOUR DISPLAY
20 DIM CF(7,6)
30 REM SET UP SAMPLE BOARD
40 CF(3,6)=1:CF(4,6)=2:CF(5,6)=1
50 CF(3,5)=2:CF(4,5)=1:CF(5,5)=2
60 CF(3,4)=1:CF(4,4)=2
70 CP=1
80 REM DISPLAY
90 PRINT CHR$(147)
100 PRINT "=== CONNECT FOUR ==="
110 PRINT ""
120 PRINT "PLAYER ";CP;"'S TURN"
130 PRINT ""
140 PRINT "  1 2 3 4 5 6 7"
150 FOR Y=1 TO 6
160 PRINT " |";
170 FOR X=1 TO 7
180 IF CF(X,Y)=0 THEN PRINT " ";
190 IF CF(X,Y)=1 THEN PRINT "X";
200 IF CF(X,Y)=2 THEN PRINT "O";
210 PRINT "|";
220 NEXT X
230 PRINT ""
240 NEXT Y
250 PRINT " +-------------+"
260 PRINT ""
270 PRINT "COLUMN (1-7, 0=MENU)> ";
```

![Connect Four board showing player positions and column selection](/images/commodore-64/phase-0/tier-3/lesson-048/screenshot-2-connect-four.png)

**What's happening:**
- **Line 20:** 7×6 grid for standard Connect Four board
- **Line 40-60:** Sample board state (player 1 = X, player 2 = O)
- **Line 150-240:** Nested loops draw the entire board with borders
- **Line 180-200:** Display empty spaces, X pieces, or O pieces
- **Line 270:** Prompt for column selection (1-7 to play, 0 to quit)

**Why this is instant:** The board redraw happens once per turn. No animation, no scrolling, no time pressure. The player thinks, chooses a column, and sees the result immediately. The win detection checks all four directions (horizontal, vertical, two diagonals) every turn—exhaustive logic that would slow down a real-time game, but perfect for turn-based play.

## Example 3: Memory Match Display

Memory Match demonstrates randomisation and state tracking:

```basic
10 REM MEMORY MATCH DISPLAY
20 DIM MM(4,4):REM CARD VALUES
30 DIM MF(4,4):REM FACE UP
40 REM SET UP SAMPLE CARDS
50 MM(1,1)=3:MM(2,1)=7:MM(3,1)=2:MM(4,1)=5
60 MM(1,2)=1:MM(2,2)=4:MM(3,2)=8:MM(4,2)=3
70 MM(1,3)=6:MM(2,3)=2:MM(3,3)=7:MM(4,3)=1
80 MM(1,4)=5:MM(2,4)=8:MM(3,4)=4:MM(4,4)=6
90 REM FLIP SOME CARDS
100 MF(1,2)=1:MF(4,3)=1
110 MP=2:REM 2 PAIRS MATCHED
120 REM DISPLAY
130 PRINT CHR$(147)
140 PRINT "=== MEMORY MATCH ==="
150 PRINT "PAIRS: ";MP;"/8"
160 PRINT ""
170 PRINT "   1  2  3  4"
180 FOR Y=1 TO 4
190 PRINT Y;" ";
200 FOR X=1 TO 4
210 IF MF(X,Y)=1 THEN PRINT " ";CHR$(48+MM(X,Y));" ";:GOTO 230
220 PRINT " ? ";
230 NEXT X
240 PRINT ""
250 NEXT Y
260 PRINT ""
270 PRINT "CARD 1 X,Y (0,0=MENU)> ";
```

![Memory Match grid showing face-down cards and match tracking](/images/commodore-64/phase-0/tier-3/lesson-048/screenshot-3-memory.png)

**What's happening:**
- **Line 20-30:** Two arrays—card values (1-8, two of each) and face-up state
- **Line 50-80:** Sample card layout (each number appears twice in grid)
- **Line 100:** Cards at positions (1,2) and (4,3) are face-up
- **Line 180-250:** Nested loops display grid with coordinates
- **Line 210:** If card is face-up, show its value; otherwise show "?"
- **Line 270:** Prompt for first card coordinates (0,0 to return to menu)

**Why randomisation works perfectly:** The card shuffle happens once at game start. No real-time generation, no frame-by-frame updates. The RND function places pairs randomly, the player flips cards, and the game checks for matches—all at human speed, zero lag.

## Game Comparison: Why These Work

**Connect Four Analysis:**
- **Board state:** 7×6 grid (42 cells, 0=empty, 1=P1, 2=P2)
- **Win check:** Examines all possible 4-in-a-row patterns every turn
- **Complexity:** ~70 comparisons per turn (4 directions × ~18 positions each)
- **Result:** Instant response, zero lag

**Why it works in BASIC:**
1. **No time pressure:** Player chooses column, game updates, player sees result
2. **Simple graphics:** Text-based board, no sprites or animation
3. **One update per turn:** Board redraws only when player acts
4. **Pure logic:** Complex win detection doesn't matter when it runs between turns

**Compare to Platformer (L40):**
- **60 updates per second:** Must redraw sprites, check collisions, update physics every frame
- **Result:** 8-10 fps, choppy scrolling, playable but limited

**The discovery:** BASIC's speed limitation disappears when the game waits for the player instead of updating constantly.

## Memory Match Analysis

**Random Shuffle Implementation:**
```basic
15200 REM SHUFFLE CARDS
15210 REM PLACE 8 PAIRS RANDOMLY
15220 FOR I=1 TO 8
15230 REM PLACE PAIR 1
15240 X1=INT(RND(1)*4)+1:Y1=INT(RND(1)*4)+1
15250 IF MM(X1,Y1)<>0 THEN 15240
15260 MM(X1,Y1)=I
15270 REM PLACE PAIR 2
15280 X2=INT(RND(1)*4)+1:Y2=INT(RND(1)*4)+1
15290 IF MM(X2,Y2)<>0 THEN 15280
15300 MM(X2,Y2)=I
15310 NEXT I
15320 RETURN
```

**What's happening:**
- **Line 15220:** Loop through 8 card values (1-8)
- **Line 15240-15260:** Find random empty position for first card
- **Line 15280-15300:** Find random empty position for second card (matching pair)
- **Line 15250/15290:** Retry if position already filled (simple collision avoidance)

**Why randomisation works perfectly in BASIC:**
1. **Happens once:** Shuffle at game start, not every frame
2. **No time limit:** Can take 100 milliseconds or 10 milliseconds—player doesn't notice
3. **Simple retry logic:** If position filled, try again (elegant and sufficient)

**Compare to real-time game randomisation:**
- Generating random enemy positions every frame = slow
- Generating random level layout once at game start = perfect
