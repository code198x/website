## Lesson 39 – Game Loops Revisited

Our world now scrolls, collides, and thinks. The last ingredient is rhythm. Without a timed loop, game speed depends on how fast BASIC executes—bad news when you add effects or run on a different machine. We’ll rebuild our main loop around the `TI` jiffy clock, giving us steady pacing and clear hooks for input, logic, and rendering.

### The One-Minute Tour

- `TI` counts jiffies (1/60th of a second) and resets when you assign `TI$`.
- Poll inputs continuously, but only update the world when the timer reaches the next tick.
- If you fall behind, skip ahead to the next tick instead of running stale frames.

---

### Example Program

```basic
NEW
10 REM *** FIXED TIMESTEP LOOP ***
20 PRINT CHR$(147);"F=FASTER  S=SLOWER  Q=QUIT"
30 POKE 2040,13:POKE 53287,7:POKE 53269,1
40 POKE 53249,120
50 TI$="000000"
60 STEP=6:NEXTT=STEP
70 BASE=PEEK(53270) AND 248
80 PX=24:SCROLL=0
90 GET K$
100 IF K$="F" AND STEP>2 THEN STEP=STEP-1
110 IF K$="S" AND STEP<12 THEN STEP=STEP+1
120 IF K$="Q" THEN END
130 T=TI
140 IF T<NEXTT THEN GOTO 90
150 PX=PX+4:IF PX>320 THEN PX=24
160 POKE 53248,PX
170 SCROLL=SCROLL+1:IF SCROLL>7 THEN SCROLL=0
180 POKE 53270,BASE OR SCROLL
190 IF SCROLL=0 THEN POKE 53270,BASE
200 NEXTT=NEXTT+STEP
210 IF NEXTT<T THEN NEXTT=T+STEP
220 IF NEXTT>30000 THEN NEXTT=STEP:TI$="000000"
230 PRINT CHR$(19);"STEP:";STEP;"  TI:";T
240 GOTO 90
```

The loop checks input every pass (lines 90–120) but only updates motion when `TI` reaches the next scheduled tick (line 140). Horizontal sprite motion and a gentle smooth scroll happen inside the timed block (150–190). If a frame runs long, line 210 fast-forwards `NEXTT` to the current timer to avoid piling up late updates. The printout at line 230 gives live telemetry so you can see the timer and step size in action.

> **Tip:** `STEP` is measured in jiffies. Six jiffies ≈ 0.1 seconds (60 / 6). Shorter steps mean smoother motion but more CPU work each second.

### Concept Expansion

A regulated loop is your contract with the player. Once you own the rhythm, you can stack systems—AI, physics, scrolling—confident they’ll keep sync. For true smoothness, some developers run logic at one rate (say, 1/30 s) and rendering faster. In BASIC we keep it simple: one loop, one timer, consistent speed.

---

### Game Integration

Hook the timer into your scroll runner:

```basic
IF TI>=NEXTT THEN NEXTT=NEXTT+STEP:GOSUB 4000:GOSUB 5000
```

Use `NEXTT<T` checks to skip frames when you lag. Better a brief skip than runaway slow motion.

### What You’ve Learnt

- `TI` and `TI$` give you a reliable heartbeat for BASIC games.
- Poll input constantly but simulate on schedule for smooth motion.
- Skip ahead when frames lag so gameplay never crawls unpredictably.
