You've built a complete platformer with movement, enemies, scrolling, and collectibles. But it lacks **presentation**—there's no title screen, no score display, no game over sequence. Professional games have **polish** that ties everything together.

**This lesson introduces game polish and integration**—the presentation layer that transforms a tech demo into a complete game. You'll learn to implement title screens, heads-up displays (HUDs), game state machines, lives systems, sound integration, and visual feedback effects.

The key insight: **Polish is about state management and efficient updates**. A game state variable (GS) tracks whether you're at the title, playing, or game over. The HUD shows game information without redrawing every frame (change detection). Sound effects trigger on events without blocking gameplay. These techniques create professional presentation with minimal overhead.

---

## The One-Minute Tour

**Game State Machine:**
- **State variable (GS):** 0=title, 1=play, 2=gameover, 3=victory
- **ON GS+1 GOSUB:** Branch to title/play/gameover/victory routines
- **State transitions:** Fire button, death, win condition trigger state changes
- **Clean separation:** Each state has its own screen layout and input handling

**Heads-Up Display (HUD):**
- **Top row reserved:** Screen rows 0-1 for HUD, rows 2-24 for gameplay
- **Change detection:** Only redraw when values change (compare HP&lt;&gt;LH)
- **Screen memory direct:** POKE to 1024+ for characters, +54272 for colours
- **Layout positions:** Hearts (1-5), key icon (15), score label (28-33), digits (34-39)

**Lives System:**
- **Multiple attempts:** Start with 3 lives, lose one on death
- **Respawn logic:** Restore health, reset position, continue level
- **Game over condition:** Lives=0 triggers game over state
- **Checkpoint support:** Save position for respawn point

**Sound Integration:**
- **Event-driven:** GOSUB to sound routine on jump/collect/hit/death
- **Non-blocking:** Quick POKE sequences, FOR loop delays, no GET/INPUT
- **SID registers:** Volume (54296), frequency (54272-54273), waveform (54278)
- **Gate control:** Bit 0 of waveform register gates sound on/off

## Example 1: Title Screen and HUD

Let's start with a title screen that transitions to a HUD demonstration:

```basic
10 REM TITLE SCREEN AND HUD DEMO
20 PRINT CHR$(147)
30 REM DRAW TITLE SCREEN
40 PRINT "  CRYSTAL CAVERNS"
50 PRINT ""
60 PRINT "  PRESS FIRE TO START"
70 PRINT ""
80 PRINT "  USE JOYSTICK TO MOVE"
90 PRINT "  COLLECT GEMS AND KEYS"
100 PRINT "  REACH THE EXIT!"
110 PRINT ""
120 PRINT "  1985 RETRO GAMES"
130 REM WAIT FOR FIRE BUTTON
140 IF (PEEK(56320) AND 16)=0 THEN 140
150 IF (PEEK(56320) AND 16)<>0 THEN 150
160 REM NOW SHOW HUD DEMO
170 PRINT CHR$(147)
180 REM DRAW HUD AT TOP ROW
190 REM HEALTH HEARTS (POSITIONS 1-5)
200 FOR I=1 TO 5
210 POKE 1024+I,83:REM HEART CHARACTER
220 POKE 55296+I,2:REM RED COLOUR
230 NEXT I
240 REM KEY ICON (POSITION 15)
250 POKE 1024+15,11:REM KEY CHARACTER
260 POKE 55296+15,5:REM GREEN COLOUR
270 REM SCORE LABEL (POSITION 28-33)
280 FOR I=0 TO 5
290 READ C
300 POKE 1024+28+I,C
310 POKE 55296+28+I,14
320 NEXT I
330 DATA 19,3,15,18,5,26:REM "SCORE:"
340 REM SCORE VALUE (POSITION 34-39)
350 SC=123456
360 FOR I=0 TO 5
370 D=INT(SC/10^(5-I)):REM EXTRACT DIGIT
380 POKE 1024+34+I,48+D:REM 48 IS '0'
390 POKE 55296+34+I,7
400 SC=SC-D*10^(5-I)
410 NEXT I
420 REM SHOW GAME AREA MESSAGE
430 PRINT:PRINT
440 PRINT "  THIS IS THE GAME AREA"
450 PRINT ""
460 PRINT "  THE HUD STAYS AT THE TOP"
470 PRINT "  SHOWING HEALTH, KEYS, SCORE"
480 PRINT ""
490 PRINT "  PRESS FIRE TO SEE UPDATE DEMO"
500 REM WAIT FOR FIRE
510 IF (PEEK(56320) AND 16)=0 THEN 510
520 IF (PEEK(56320) AND 16)<>0 THEN 520
530 REM DEMO: TAKE DAMAGE
540 POKE 1024+5,32:REM CLEAR LAST HEART
550 FOR J=1 TO 500:NEXT J:REM DELAY
560 POKE 1024+4,32:REM CLEAR ANOTHER HEART
570 FOR J=1 TO 500:NEXT J
580 POKE 1024+3,32
590 FOR J=1 TO 1000:NEXT J
600 REM DEMO: UPDATE SCORE
610 FOR SC=123456 TO 123500 STEP 10
620 FOR I=0 TO 5
630 D=INT(SC/10^(5-I))
640 POKE 1024+34+I,48+D
650 SC=SC-D*10^(5-I)
660 NEXT I
670 SC=SC+10:REM RESTORE FOR NEXT LOOP
680 FOR J=1 TO 100:NEXT J
690 NEXT SC
700 PRINT:PRINT "  HUD DEMO COMPLETE!"
```

![Title screen with game instructions](/images/commodore-64/phase-0/tier-3/lesson-039/screenshot-1.png)

**What's happening:**

**Lines 20-120:** Draw title screen with game name, instructions, controls, and credits. Professional games always explain controls on the title screen.

**Lines 140-150:** Wait for fire button—first loop waits for release (handles autostart), second waits for press. This prevents accidental instant-start.

**Lines 170-410:** Draw HUD components directly to screen memory—hearts at positions 1-5 (red), key icon at 15 (green), score label at 28-33 (light blue), score digits at 34-39 (yellow). Screen memory is 1024, colour memory is 55296.

**Lines 540-580:** Demonstrate damage by clearing hearts from right to left with delays. In a real game, this updates only when HP changes (change detection).

**Lines 610-690:** Demonstrate score update by animating from 123456 to 123500. Each digit is calculated by dividing by powers of 10 (10^5 for leftmost digit, 10^0 for rightmost).

**Key technique:** Direct POKE to screen memory avoids PRINT overhead and screen scrolling. Position 1024 is top-left corner, each row is 40 characters wide.

## Example 2: Complete Game State System

Now let's build a complete game state system with title, play, game over, and victory states:

```basic
10 REM GAME STATE SYSTEM DEMO
20 REM GS=GAME STATE: 0=TITLE,1=PLAY,2=GAMEOVER,3=WIN
30 GS=0:LV=3:SC=0:HP=3:KY=0
40 REM LAST VALUES FOR CHANGE DETECTION
50 LH=-1:LS=-1:LK=-1
60 REM MAIN STATE LOOP
70 ON GS+1 GOSUB 1000,2000,3000,4000
80 GOTO 70
1000 REM TITLE SCREEN STATE
1010 PRINT CHR$(147)
1020 PRINT "  CRYSTAL CAVERNS"
1030 PRINT ""
1040 PRINT "  PRESS FIRE TO START"
1050 PRINT ""
1060 PRINT "  USE JOYSTICK TO MOVE"
1070 PRINT "  COLLECT GEMS AND KEYS"
1080 PRINT "  REACH THE EXIT!"
1090 PRINT ""
1100 PRINT "  1985 RETRO GAMES"
1110 REM WAIT FOR FIRE BUTTON RELEASE
1120 IF (PEEK(56320) AND 16)=0 THEN 1120
1130 REM WAIT FOR FIRE BUTTON PRESS
1140 IF (PEEK(56320) AND 16)<>0 THEN 1140
1150 GS=1:REM CHANGE TO PLAY STATE
1160 GOSUB 9000:REM INIT GAME
1170 RETURN
2000 REM PLAY STATE
2010 GOSUB 2100:REM UPDATE HUD
2020 GOSUB 2200:REM HANDLE INPUT
2030 GOSUB 2300:REM GAME LOGIC
2040 RETURN
2100 REM UPDATE HUD (ONLY IF CHANGED)
2110 IF HP<>LH THEN GOSUB 2500
2120 IF SC<>LS THEN GOSUB 2600
2130 IF KY<>LK THEN GOSUB 2700
2140 RETURN
2200 REM HANDLE INPUT
2210 J=PEEK(56320)
2220 REM FIRE BUTTON FOR DEMO ACTIONS
2230 IF (J AND 16)=0 AND FB=0 THEN FB=1:GOSUB 2400
2240 IF (J AND 16)<>0 THEN FB=0
2250 RETURN
2300 REM GAME LOGIC
2310 REM IN REAL GAME: PHYSICS, ENEMIES, ETC
2320 RETURN
2400 REM DEMO: CYCLE THROUGH GAME ACTIONS
2410 AC=AC+1
2420 IF AC=1 THEN HP=HP-1:REM TAKE DAMAGE
2430 IF AC=2 THEN SC=SC+100:REM COLLECT GEM
2440 IF AC=3 THEN KY=1:REM COLLECT KEY
2450 IF AC=4 THEN HP=HP-1
2460 IF AC=5 THEN HP=HP-1:REM DIE, LOSE LIFE
2470 IF HP=0 THEN GOSUB 2800:REM HANDLE DEATH
2480 IF AC=6 THEN GS=3:REM WIN DEMO
2490 RETURN
2500 REM DRAW HEALTH
2510 FOR I=1 TO 5
2520 CH=1024+I
2530 IF I<=HP THEN POKE CH,83:POKE CH+54272,2
2540 IF I>HP THEN POKE CH,32
2550 NEXT I
2560 LH=HP:REM REMEMBER LAST VALUE
2570 RETURN
2600 REM DRAW SCORE
2610 S=SC
2620 FOR I=5 TO 0 STEP -1
2630 D=INT(S/10^I)
2640 POKE 1024+34+(5-I),48+D
2650 S=S-D*10^I
2660 NEXT I
2670 LS=SC:REM REMEMBER LAST VALUE
2680 RETURN
2700 REM DRAW KEY INDICATOR
2710 CH=1024+15
2720 IF KY>0 THEN POKE CH,11:POKE CH+54272,5
2730 IF KY=0 THEN POKE CH,32
2740 LK=KY:REM REMEMBER LAST VALUE
2750 RETURN
2800 REM HANDLE DEATH
2810 LV=LV-1:REM LOSE LIFE
2820 IF LV<=0 THEN GS=2:RETURN:REM GAME OVER
2830 REM RESPAWN
2840 HP=3:REM RESTORE HEALTH
2850 AC=0:REM RESET ACTION COUNTER
2860 RETURN
3000 REM GAME OVER STATE
3010 PRINT CHR$(147)
3020 PRINT ""
3030 PRINT "  GAME OVER"
3040 PRINT ""
3050 PRINT "  FINAL SCORE:";SC
3060 PRINT ""
3070 PRINT "  YOU HAD";LV;"LIVES LEFT"
3080 PRINT ""
3090 PRINT "  PRESS FIRE TO RESTART"
3100 REM WAIT FOR FIRE RELEASE
3110 IF (PEEK(56320) AND 16)=0 THEN 3110
3120 REM WAIT FOR FIRE PRESS
3130 IF (PEEK(56320) AND 16)<>0 THEN 3130
3140 GS=0:REM RETURN TO TITLE
3150 AC=0:REM RESET ACTION COUNTER
3160 RETURN
4000 REM VICTORY STATE
4010 PRINT CHR$(147)
4020 PRINT ""
4030 PRINT "  LEVEL COMPLETE!"
4040 PRINT ""
4050 PRINT "  SCORE:";SC
4060 PRINT "  LIVES:";LV
4070 PRINT ""
4080 PRINT "  WELL DONE!"
4090 PRINT ""
4100 PRINT "  PRESS FIRE TO CONTINUE"
4110 REM WAIT FOR FIRE RELEASE
4120 IF (PEEK(56320) AND 16)=0 THEN 4120
4130 REM WAIT FOR FIRE PRESS
4140 IF (PEEK(56320) AND 16)<>0 THEN 4140
4150 GS=0:REM RETURN TO TITLE
4160 AC=0:REM RESET ACTION COUNTER
4170 RETURN
9000 REM INIT GAME
9010 PRINT CHR$(147)
9020 HP=3:SC=0:KY=0:AC=0
9030 REM DRAW STATIC HUD ELEMENTS
9040 REM SCORE LABEL
9050 FOR I=0 TO 5
9060 READ C
9070 POKE 1024+28+I,C
9080 POKE 55296+28+I,14
9090 NEXT I
9100 DATA 19,3,15,18,5,26:REM "SCORE:"
9110 REM INITIAL HUD VALUES
9120 GOSUB 2500:REM DRAW HEALTH
9130 GOSUB 2600:REM DRAW SCORE
9140 GOSUB 2700:REM DRAW KEY
9150 REM GAME INSTRUCTIONS IN PLAY AREA
9160 PRINT:PRINT
9170 PRINT "  PRESS FIRE TO:"
9180 PRINT "  1) TAKE DAMAGE"
9190 PRINT "  2) COLLECT GEM (+100)"
9200 PRINT "  3) COLLECT KEY"
9210 PRINT "  4-5) TAKE MORE DAMAGE"
9220 PRINT "  6) WIN LEVEL"
9230 PRINT ""
9240 PRINT "  WATCH THE HUD UPDATE!"
9250 RETURN
```

![Game state system with HUD](/images/commodore-64/phase-0/tier-3/lesson-039/screenshot-2.png)

**What's happening:**

**Lines 20-50:** Initialise game state (GS=0 for title), lives (LV=3), score (SC=0), health (HP=3), keys (KY=0). Last values (LH, LS, LK) are set to -1 to force initial draw.

**Lines 70-80:** Main state loop—use ON GS+1 GOSUB to branch to title (1000), play (2000), gameover (3000), or victory (4000) routines. This is the core state machine pattern.

**Lines 1000-1170:** Title screen state—display game info, wait for fire button, transition to play state (GS=1), initialise game.

**Lines 2000-2040:** Play state dispatcher—update HUD (only if changed), handle input, run game logic. This is where your platformer code would go.

**Lines 2100-2140:** HUD update with change detection—compare current values to last values (HP&lt;&gt;LH), only call draw routines if changed. This prevents flicker and saves CPU.

**Lines 2500-2570:** Draw health hearts—loop through 5 positions, POKE heart character (83) for filled, space (32) for empty. Colour memory offset is +54272 from screen address.

**Lines 2600-2680:** Draw score—extract digits using division by powers of 10, convert to character code by adding 48 ('0'). Remember last score to detect changes.

**Lines 2800-2860:** Handle death—decrease lives, check for game over (GS=2 if LV&lt;=0), otherwise respawn (restore HP=3, reset action counter).

**Lines 3000-3160, 4000-4170:** Game over and victory states—display results, wait for fire, return to title (GS=0).

**Key technique:** Change detection (HP&lt;&gt;LH) updates HUD only when values change. This is essential for flicker-free displays and performance.

## HUD Layout Design

**Top row of screen (40 characters):**

```
♥♥♥         KEY        SCORE:000000
```

**Memory positions:**
- **1024-1029** (0-5): Health hearts (character 83, red colour 2)
- **1024+15** (15): Key icon (character 11, green colour 5) or space (32) if no key
- **1024+28 to 1024+33** (28-33): Score label "SCORE:" (light blue colour 14)
- **1024+34 to 1024+39** (34-39): Score digits (yellow colour 7)

**Colour memory offset:**
- Add **+54272** to screen address for colour (NOT 55296 for HUD area)
- Example: POKE 1024+5,83 for character, POKE 1024+5+54272,2 for red

**Update strategy:**
- **First frame:** Draw everything (LH=-1 forces HP&lt;&gt;LH true)
- **Subsequent frames:** Only redraw when values change
- **Benefits:** No flicker, minimal CPU usage, professional look

## Game State Flow

**State diagram:**

```
     ┌─────────┐
     │  TITLE  │ GS=0
     └────┬────┘
          │ Fire
     ┌────▼────┐
     │  PLAY   │ GS=1 ◄─┐
     └────┬────┘         │
          │              │ Respawn
    ┌─────┴─────┐        │
    │           │        │
 HP=0       Win │        │
    │           │        │
┌───▼───┐  ┌───▼───┐    │
│GAMEOVER│  │VICTORY│    │
│  GS=2  │  │  GS=3 │    │
└───┬───┘  └───┬───┘    │
    │          │         │
    │ Fire     │ Fire    │
    └────┬─────┘         │
         │               │
    ┌────▼────┐          │
    │  TITLE  │          │
    │  GS=0   │──────────┘
    └─────────┘    New Game
```

**State transitions:**
- **TITLE → PLAY:** Fire button pressed
- **PLAY → GAMEOVER:** Lives reach zero (LV&lt;=0)
- **PLAY → VICTORY:** Win condition met (exit touched with key)
- **GAMEOVER → TITLE:** Fire button pressed
- **VICTORY → TITLE:** Fire button pressed (or next level in full game)
- **PLAY → PLAY:** Respawn on death (HP=0 but LV>0)

## Sound Integration Pattern

**Non-blocking sound effects:**

```basic
1000 REM JUMP SOUND
1010 POKE 54296,15:REM VOLUME MAX
1020 POKE 54273,8:POKE 54272,150:REM FREQUENCY
1030 POKE 54276,33:REM ATTACK/DECAY
1040 POKE 54277,0:REM SUSTAIN/RELEASE
1050 POKE 54278,17:REM WAVEFORM TRIANGLE + GATE
1060 FOR I=1 TO 50:NEXT I:REM SHORT DELAY
1070 POKE 54278,16:REM GATE OFF
1080 RETURN
```

**When to trigger:**
- **Jump:** Call sound routine in input handler when fire pressed and on ground
- **Collect gem:** Call in gem collection handler after SC=SC+5
- **Take damage:** Call in collision handler after HP=HP-1
- **Death:** Call in death handler before lives decrease

**Why this works:**
- POKE is instant, no blocking
- FOR loop delay is short (50-100 iterations = few milliseconds)
- Game loop continues running, no freeze

**Wrong approach (NEVER do this):**

```basic
1000 GET K$:IF K$="" THEN 1000  ← BLOCKS ENTIRE GAME
```

GET and INPUT stop all execution. Use FOR loops for delays instead.

## Lives and Respawn System

**Lives system pattern:**

```basic
100 LV=3:REM START WITH 3 LIVES
...
1000 REM DEATH HANDLER
1010 LV=LV-1:REM LOSE LIFE
1020 IF LV<=0 THEN GS=2:RETURN:REM GAME OVER
1030 REM RESPAWN
1040 HP=3:REM RESTORE HEALTH
1050 PX=CPX:PY=CPY:REM RESTORE CHECKPOINT POSITION
1060 VX=0:VY=0:REM RESET VELOCITY
1070 RETURN
```

**Checkpoint system:**

```basic
100 REM CHECKPOINT DATA
110 CPX=50:CPY=50:REM INITIAL SPAWN
...
1000 REM REACH CHECKPOINT
1010 CPX=PX:CPY=PY:REM SAVE POSITION
1020 REM VISUAL/AUDIO FEEDBACK
1030 POKE 53280,5:REM GREEN FLASH
1040 FOR I=1 TO 10:NEXT I
1050 POKE 53280,0:REM RESTORE
```

**Why this works:**
- Players don't restart entire level on death
- Checkpoints reduce frustration
- Lives system adds stakes without punishment

```basic
100 FOR I=1 TO 5
110 POKE 53265,PEEK(53265) XOR 8:REM TOGGLE SCREEN HEIGHT

130 NEXT I
```

**Border flash on hit:**

```basic
100 B=PEEK(53280):REM SAVE ORIGINAL
110 POKE 53280,2:REM RED BORDER
120 FOR I=1 TO 10:NEXT I
130 POKE 53280,B:REM RESTORE
```

**Invincibility flash:**

```basic
100 IV=60:REM INVINCIBLE FRAMES (1 SECOND AT 60 FPS)
110 REM IN GAME LOOP:
120 IF IV>0 THEN IV=IV-1
130 IF IV>0 AND IV MOD 10<5 THEN POKE 53248,255:REM HIDE SPRITE
140 IF IV>0 AND IV MOD 10>=5 THEN POKE 53248,PX:REM SHOW SPRITE
```

**Colour cycling gems:**

```basic

110 FOR I=1 TO NUM_GEMS
120 IF GEM_COLLECTED(I)=0 THEN POKE 55296+GEM_POS(I),COL
130 NEXT I
```

## Performance Impact

**With full polish (HUD + sounds + effects):**

| Component | Time per frame | Notes |
|-----------|----------------|-------|
| HUD update (changed) | ~2ms | Only when HP/SC/KY changes |
| HUD update (no change) | ~0.1ms | Just comparisons |
| Sound effect trigger | ~5ms | FOR loop delay, non-blocking |
| Visual effect (flash) | ~3ms | POKE + delay, occasional |
| **Total overhead** | ~2-5ms | **Minimal impact on gameplay** |

**Frame budget at 10 FPS:** 100ms per frame
**Polish overhead:** 2-5ms (2-5% of budget)
**Remaining:** 95-98ms for gameplay, physics, drawing

**Reality:** Polish adds professional feel with negligible performance cost. HUD is efficient with change detection, sounds are short, effects are rare.

## Common Pitfalls

**1. Redrawing HUD every frame**

```basic
100 REM WRONG: ALWAYS REDRAWS
110 GOSUB DRAW_HUD
```

**Solution:** Change detection

```basic
100 IF HP<>LH THEN GOSUB DRAW_HEALTH
110 LH=HP
```

**2. Blocking sound effects**

```basic
100 GET K$:IF K$="" THEN 100  ← FREEZES GAME
```

**Solution:** FOR loop delays

```basic
100 FOR I=1 TO 50:NEXT I  ← SHORT NON-BLOCKING DELAY
```

**3. Wrong colour memory offset**

```basic
100 POKE 1024+5,83:REM CHARACTER
110 POKE 55296+5,2:REM WRONG! FIXED COLOUR MEMORY
```

**Solution:** Relative offset

```basic
100 POKE 1024+5,83
110 POKE 1024+5+54272,2:REM CORRECT OFFSET
```

**4. Forgetting to restore on exit**

```basic
100 POKE 53280,0:REM CHANGE BORDER
...
900 END  ← BORDER STAYS BLACK
```

**Solution:** Save and restore

```basic
100 B=PEEK(53280):REM SAVE
110 POKE 53280,0
...
900 POKE 53280,B:END:REM RESTORE
```

**5. Using reserved variables**

```basic
100 ST=0:REM STATE  ← ERROR! ST IS RESERVED
```

**Solution:** Different variable name

```basic
100 GS=0:REM GAME STATE  ← CORRECT
```

C64 BASIC reserves ST (I/O status), TI (jiffy clock), TI$ (time string). Never use these as variable names.

## Quick Reference

**Game State Machine:**
```basic
GS=0  :REM 0=TITLE, 1=PLAY, 2=GAMEOVER, 3=WIN
ON GS+1 GOSUB [TITLE],[PLAY],[GAMEOVER],[WIN]
```

**HUD Update with Change Detection:**
```basic
IF HP<>LH THEN GOSUB DRAW_HEALTH
IF SC<>LS THEN GOSUB DRAW_SCORE
LH=HP:LS=SC  :REM REMEMBER VALUES
```

**Draw Health Hearts:**
```basic
FOR I=1 TO 5
CH=1024+I
IF I<=HP THEN POKE CH,83:POKE CH+54272,2
IF I>HP THEN POKE CH,32
NEXT I
```

**Draw Score (6 digits):**
```basic
S=SC
FOR I=5 TO 0 STEP -1
D=INT(S/10^I)
POKE 1024+34+(5-I),48+D
S=S-D*10^I
NEXT I
```

**Non-Blocking Sound Effect:**
```basic
POKE 54296,15  :REM VOLUME
POKE 54272,FREQ_LO:POKE 54273,FREQ_HI
POKE 54278,WAVEFORM+1  :REM GATE ON
FOR I=1 TO 50:NEXT I
POKE 54278,WAVEFORM  :REM GATE OFF
```

**Lives System:**
```basic
LV=3  :REM START LIVES
REM ON DEATH:
LV=LV-1
IF LV<=0 THEN GS=2:REM GAME OVER
HP=3:GOSUB RESPAWN  :REM CONTINUE
```

**Wait for Fire Button:**
```basic
IF (PEEK(56320) AND 16)=0 THEN [LOOP]  :REM WAIT RELEASE
IF (PEEK(56320) AND 16)<>0 THEN [LOOP]  :REM WAIT PRESS
```

**HUD Layout:**
```
Row 0:  ♥♥♥         KEY        SCORE:000000
        [1-5]       [15]       [28-33][34-39]

Rows 2-24: GAMEPLAY AREA
```

**Memory Addresses:**
- Screen memory: 1024 (top-left corner)
- Colour memory offset from screen: +54272 (NOT 55296 for HUD)
- Border colour: 53280
- Background colour: 53281
- SID volume: 54296
- SID voice 1 frequency: 54272-54273
- SID voice 1 waveform: 54278

**Reserved Variables (NEVER use):**
- ST (I/O status)
- TI (jiffy clock)
- TI$ (time string)

Use GS for game state, not ST!
