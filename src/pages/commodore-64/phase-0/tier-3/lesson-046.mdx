# Dungeon Quest: Complete RPG 🔗

You've mastered the individual systems—room navigation, inventory management, NPC dialogue, turn-based combat, and save/load persistence. Now it's time to combine them all into **Dungeon Quest**, a complete 12-room dungeon crawler that demonstrates BASIC's perfect fit for turn-based RPG development.

## What You're Building

**Dungeon Quest** is a classic dungeon crawler where you:
- Explore 12 interconnected rooms with NSEW navigation
- Collect items and manage an 8-slot inventory
- Buy equipment from merchants to upgrade your stats
- Talk to NPCs for quests and information
- Fight monsters in turn-based combat
- Level up and gain new abilities
- Complete a quest to retrieve a stolen amulet from the dragon

This ~300-line game demonstrates that BASIC can create professional-quality RPGs with complex systems running **flawlessly** with instant response times.

## The Complete Integration

### Core Game Loop

The game alternates between two main states:

```basic
330 REM === MAIN LOOP ===
340 IF GS=0 THEN GOSUB 1000:REM EXPLORE MODE
350 IF GS=1 THEN GOSUB 2000:REM COMBAT MODE
360 IF GS=2 THEN GOSUB 8000:REM VICTORY
370 IF GS=3 THEN END
380 GOTO 340
```

This simple state machine keeps the entire game organised. When exploring, you navigate rooms and interact with the world. When combat triggers, the game switches to combat mode until victory or defeat.

### Exploration Mode

When exploring, the game displays your current location, available exits, items, NPCs, and your stats:

```basic
1000 REM === EXPLORE MODE ===
1010 GOSUB 1100:REM DISPLAY ROOM
1020 GOSUB 1250:REM SHOW STATUS
1030 GOSUB 1350:REM GET COMMAND
1040 GOSUB 1450:REM PROCESS COMMAND
1050 REM CHECK COMBAT TRIGGER
1060 IF RE(CR)<>0 THEN GS=1:CE=RE(CR):EH(CE)=EH(CE)+0:RE(CR)=0
1070 RETURN
```

Each frame updates the display, gets player input, processes the command, and checks if combat should trigger. This pattern keeps exploration responsive and clear.

### Combat Mode

Turn-based combat alternates between player and enemy turns:

```basic
2000 REM === COMBAT MODE ===
2010 GOSUB 2100:REM DISPLAY COMBAT
2020 GOSUB 2250:REM PLAYER TURN
2030 IF GS=2 THEN GOSUB 2850:RETURN:REM WON
2040 IF GS=3 THEN GOSUB 2990:RETURN:REM LOST
2050 IF GS=1 THEN GOSUB 2600:REM ENEMY TURN
2060 IF GS=3 THEN GOSUB 2990:RETURN:REM LOST
2070 RETURN
```

After each turn, the game checks if combat has ended (victory, defeat, or fled). This structure makes combat logic crystal clear.

## The Complete Game

Here's the full Dungeon Quest RPG:

```basic
100 REM DUNGEON QUEST RPG
110 REM === INITIALIZATION ===
120 PRINT CHR$(147)
130 PRINT "LOADING DUNGEON QUEST..."
140 REM PLAYER STATS
150 HP=20:MH=20:AT=8:DF=3:GD=0:XP=0:LV=1
160 CR=1:REM CURRENT ROOM
170 REM ARRAYS
180 DIM RN$(12),RD$(12):REM ROOM NAMES, DESCRIPTIONS
190 DIM EX(12,4):REM EXITS (N,S,E,W)
200 DIM IN(8):REM INVENTORY (ITEM IDS)
210 DIM IN$(20):REM ITEM NAMES
220 DIM RI(12):REM ROOM ITEMS
230 DIM NN$(5),NR(5),NS(5):REM NPC NAME,ROOM,STATE
240 DIM EN$(5),EH(5),EA(5),ED(5):REM ENEMY STATS
250 DIM RE(12):REM ROOM ENEMIES
260 DIM QF(5):REM QUEST FLAGS
270 REM DIRECTIONS
280 DN=1:DS=2:DE=3:DW=4
290 REM GAME STATE
300 GS=0:REM GAME STATE (0=EXPLORE,1=COMBAT,2=WON,3=LOST)
310 GOSUB 9000:REM LOAD ALL DATA
320 FOR I=1 TO 1000:NEXT I
330 REM === MAIN LOOP ===
340 IF GS=0 THEN GOSUB 1000:REM EXPLORE MODE
350 IF GS=1 THEN GOSUB 2000:REM COMBAT MODE
360 IF GS=2 THEN GOSUB 8000:REM VICTORY
370 IF GS=3 THEN END
380 GOTO 340
```

The initialisation sets up all the game systems, loads data, and enters the main loop. Notice we use `GS` for game state instead of `ST` (which is a reserved C64 system variable).

### Room Display and Navigation

```basic
1100 REM DISPLAY ROOM
1110 PRINT CHR$(147)
1120 PRINT "=== ";RN$(CR);" ==="
1130 PRINT ""
1140 PRINT RD$(CR)
1150 PRINT ""
1160 REM SHOW ITEMS IN ROOM
1170 IF RI(CR)<>0 THEN PRINT "YOU SEE: ";IN$(RI(CR))
1180 REM SHOW NPCS IN ROOM
1190 FOR I=1 TO 5
1200 IF NR(I)=CR THEN PRINT "YOU SEE: ";NN$(I)
1210 NEXT I
1220 PRINT ""
1230 GOSUB 1300
1240 RETURN

1300 REM SHOW EXITS
1310 PRINT "EXITS: ";
1320 IF EX(CR,DN)<>0 THEN PRINT "N ";
1330 IF EX(CR,DS)<>0 THEN PRINT "S ";
1340 IF EX(CR,DE)<>0 THEN PRINT "E ";
1345 IF EX(CR,DW)<>0 THEN PRINT "W ";
1346 PRINT ""
1347 RETURN
```

The room display shows everything relevant: room name, description, items, NPCs, and available exits. This gives players all the information they need at a glance.

### Movement System

```basic
1600 REM MOVE
1610 DR=0
1620 IF C$="N" THEN DR=DN
1630 IF C$="S" THEN DR=DS
1640 IF C$="E" THEN DR=DE
1650 IF C$="W" THEN DR=DW
1660 IF EX(CR,DR)=0 THEN PRINT "CAN'T GO THAT WAY":FOR I=1 TO 500:NEXT I:RETURN
1670 CR=EX(CR,DR)
1675 RETURN
```

Movement converts the command (N/S/E/W) into a direction index, checks if that exit exists, and updates the current room. Simple and bulletproof.

### Inventory Management

```basic
1680 REM GET ITEM
1690 IF RI(CR)=0 THEN PRINT "NOTHING TO TAKE":FOR I=1 TO 500:NEXT I:RETURN
1700 REM FIND EMPTY SLOT
1710 ES=0
1720 FOR I=1 TO 8
1730 IF IN(I)=0 THEN ES=I:I=8
1735 NEXT I
1740 IF ES=0 THEN PRINT "INVENTORY FULL":FOR I=1 TO 1000:NEXT I:RETURN
1745 IN(ES)=RI(CR)
1746 PRINT "GOT ";IN$(RI(CR))
1747 RI(CR)=0
1748 FOR I=1 TO 1000:NEXT I
1749 RETURN

1750 REM SHOW INVENTORY
1760 PRINT CHR$(147)
1770 PRINT "=== INVENTORY ==="
1780 PRINT ""
1790 FOR I=1 TO 8
1800 PRINT I;": ";
1810 IF IN(I)<>0 THEN PRINT IN$(IN(I))
1820 IF IN(I)=0 THEN PRINT "[EMPTY]"
1830 NEXT I
1840 PRINT ""
1841 GOSUB 1900
1842 RETURN
```

Picking up items finds the first empty inventory slot. The inventory screen shows all 8 slots, with items or [EMPTY] markers. This makes inventory management transparent and user-friendly.

### Turn-Based Combat

```basic
2250 REM PLAYER TURN
2260 PRINT "1:ATTACK 2:DEFEND 3:ITEM 4:FLEE"
2270 PRINT "CHOOSE> ";
2280 INPUT A
2290 IF A<1 OR A>4 THEN 2280
2300 ON A GOSUB 2350,2420,2460,2550
2310 RETURN

2350 REM ATTACK
2360 DM=AT-ED(CE)+INT(RND(1)*5)
2370 IF DM<1 THEN DM=1
2380 EH(CE)=EH(CE)-DM
2390 PRINT "YOU HIT FOR ";DM;" DAMAGE!"
2400 IF EH(CE)<=0 THEN GS=2
2410 FOR I=1 TO 1000:NEXT I
2415 RETURN
```

Combat calculates damage based on your attack minus enemy defence, plus a random element. This creates variety whilst keeping combat predictable and strategic.

### Enemy AI

```basic
2600 REM ENEMY TURN
2610 IF GS<>1 THEN RETURN
2620 AI=INT(RND(1)*100)
2630 IF AI<80 THEN GOSUB 2700:RETURN
2640 PRINT EN$(CE);" HESITATES!"
2650 FOR I=1 TO 1000:NEXT I
2660 RETURN

2700 REM ENEMY ATTACK
2710 DM=EA(CE)-DF+INT(RND(1)*5)
2720 IF BL=1 THEN DM=INT(DM/2):BL=0
2730 IF DM<1 THEN DM=1
2740 HP=HP-DM
2750 PRINT EN$(CE);" HITS FOR ";DM;"!"
2760 IF HP<=0 THEN GS=3
2770 FOR I=1 TO 1500:NEXT I
2780 RETURN
```

Enemies attack 80% of the time, creating tension whilst giving players occasional breathing room. The defend action (setting `BL=1`) halves incoming damage, rewarding strategic play.

### Levelling System

```basic
3050 REM LEVEL UP
3060 LV=LV+1
3070 MH=MH+5
3080 HP=MH
3090 AT=AT+2
3100 DF=DF+1
3110 PRINT ""
3120 PRINT "LEVEL UP! NOW LEVEL ";LV
3130 FOR I=1 TO 2000:NEXT I
3140 RETURN
```

Levelling increases your maximum HP, attack, and defence. Full HP restoration on level-up rewards progress and creates recovery moments during dungeon exploration.

### Merchant System

```basic
3200 REM MERCHANT DIALOGUE
3210 PRINT "WELCOME TO MY SHOP!"
3220 PRINT ""
3230 PRINT "1: BUY POTION (10 GOLD)"
3240 PRINT "2: BUY SWORD (+5 ATK, 50 GOLD)"
3250 PRINT "3: BUY ARMOUR (+3 DEF, 50 GOLD)"
3260 PRINT "4: LEAVE"
3270 PRINT ""
3280 PRINT "CHOOSE> ";
3290 INPUT CH
3300 IF CH=1 AND GD>=10 THEN GOSUB 3900:RETURN
3310 IF CH=2 AND GD>=50 THEN GOSUB 4000:RETURN
3320 IF CH=3 AND GD>=50 THEN GOSUB 4100:RETURN
3330 IF CH=4 THEN RETURN
3340 PRINT "CAN'T AFFORD THAT!"
3350 FOR I=1 TO 1000:NEXT I
3360 GOTO 3200
```

The merchant provides strategic choices: spend gold on healing potions for immediate survival, or save for permanent stat upgrades. Quest flags track purchases to prevent buying the same upgrade twice.

### Quest System

```basic
4200 REM QUEST OFFER
4210 PRINT "GREETINGS, ADVENTURER!"
4220 PRINT ""
4230 PRINT "THE DRAGON IN ROOM 12"
4240 PRINT "HAS STOLEN THE AMULET."
4250 PRINT ""
4260 PRINT "WILL YOU RETRIEVE IT?"
4270 PRINT ""
4280 PRINT "1: YES  2: NO"
4290 PRINT "CHOOSE> ";
4295 INPUT CH
4296 IF CH=1 THEN QF(3)=1:PRINT "THANK YOU!":FOR I=1 TO 1000:NEXT I
4297 RETURN
```

The quest gives the game direction and purpose. Quest flags track progress: 0=not started, 1=accepted, 2=completed. This simple system supports complex branching narratives.

## Data-Driven Design

All game content lives in DATA statements, making the game easy to modify and extend:

```basic
9150 DATA "ENTRANCE HALL","TORCHES FLICKER ON STONE WALLS."
9160 DATA "GUARD ROOM","RUSTY WEAPONS HANG ON WALLS."
9170 DATA "ARMOURY","SHIELDS AND SWORDS EVERYWHERE."
9180 DATA "HALLWAY","A LONG CORRIDOR STRETCHES ON."
9190 DATA "TREASURE ROOM","GOLD COINS SCATTER THE FLOOR."
9200 DATA "WIZARD'S STUDY","BOOKS LINE EVERY WALL."

9310 DATA 2,0,3,0:REM ROOM 1 EXITS
9320 DATA 4,1,0,0:REM ROOM 2 EXITS
9330 DATA 0,0,0,1:REM ROOM 3 EXITS

9740 DATA "GOBLIN",10,5,2
9750 DATA "ORC",18,8,4
9760 DATA "TROLL",25,10,5
9770 DATA "SKELETON",15,7,3
9780 DATA "DRAGON",50,15,8
```

Want to add more rooms? Just add DATA lines and update the room count. Want stronger enemies? Change the numbers. This separation of data from logic makes the game maintainable and extensible.

## Game Balance

The game is balanced for a gradual difficulty curve:

**Early game (Rooms 1-4):**
- Goblins: 10 HP, 5 ATK, 2 DEF
- You: 20 HP, 8 ATK, 3 DEF
- Strategy: Learn combat, buy potions

**Mid game (Rooms 5-8):**
- Orcs: 18 HP, 8 ATK, 4 DEF
- You (upgraded): 25 HP, 13 ATK, 6 DEF
- Strategy: Buy sword and armour, use defensive tactics

**Late game (Rooms 9-12):**
- Trolls: 25 HP, 10 ATK, 5 DEF
- Dragon (boss): 50 HP, 15 ATK, 8 DEF
- You (levelled): 30+ HP, 15+ ATK, 7+ DEF
- Strategy: Stack upgrades, manage resources carefully

## The Discovery: BASIC's Perfect Genre

After building the 8-10 FPS platformer in lesson 40, this RPG reveals something crucial:

**Turn-based games eliminate all of BASIC's performance constraints.**

There's no frame rate. No animation timing. No sprite updates. Every action waits for input, so computation time is invisible. Complex systems run flawlessly because there's no time pressure.

This is why so many commercial C64 RPGs were written in BASIC:
- **Ultima series** (1981-1985): BASIC with assembly helpers
- **Telengard** (1982): Pure BASIC dungeon crawler
- **Temple of Apshai** (1979): BASIC RPG engine
- **Questron** (1984): BASIC-driven gameplay

You've discovered BASIC's sweet spot: **games where depth beats speed.**

## From the Vault

**Early CRPGs that inspired Dungeon Quest:**

- **Telengard** (1982, Daniel Lawrence): BASIC dungeon crawler with 200,000 rooms generated algorithmically
- **Ultima I** (1981, Richard Garriott): BASIC overworld with assembly dungeons, founded the CRPG genre
- **Temple of Apshai** (1979, Automated Simulations): One of the first commercial CRPGs, BASIC engine
- **Akalabeth** (1979, Richard Garriott): Richard Garriott's first game, wire-frame dungeons in BASIC

All these pioneering RPGs used BASIC because **turn-based gameplay hides computation time**. Your discovery parallels the entire history of computer RPGs.
