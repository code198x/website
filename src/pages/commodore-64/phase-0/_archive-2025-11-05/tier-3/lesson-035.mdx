# Making Sprites Bigger

You've learnt to create, animate, and layer sprites. Now it's time to make them bigger. The VIC-II can double sprite width and height independently—turning your 24×21 pixel sprites into 48×42 behemoths without using extra memory.

This is essential for boss characters, large objects, and impressive visual effects. And when combined with multicolour mode, you can create detailed large sprites with three colours instead of one.

---

## The One-Minute Tour

**Expansion Registers:**
- **53277 ($D01D)** - Sprite X expansion (double width to 48 pixels)
- **53271 ($D017)** - Sprite Y expansion (double height to 42 pixels)
- Both use bit masks (bit 0 = sprite 0, bit 7 = sprite 7)

**Multicolour Register:**
- **53276 ($D01C)** - Sprite multicolour enable (bit mask)
- **53285 ($D025)** - Multicolour #0 (shared by all multicolour sprites)
- **53286 ($D026)** - Multicolour #1 (shared by all multicolour sprites)

**Critical Behaviour:**
- Expansion doesn't increase resolution—pixels are just doubled in size
- Multicolour sprites interpret pairs of bits as colour codes
- Multicolour reduces effective horizontal resolution from 24 to 12 pixels
- You can combine expansion with multicolour for large, colourful sprites

## Example 1: X Expansion (Double Width)

Let's create a sprite and double its width:

```basic
10 PRINT CHR$(147):REM CLEAR SCREEN
20 REM LOAD SPRITE DATA
30 FOR I=0 TO 62
40 READ B:POKE 832+I,B
50 NEXT
60 REM SETUP SPRITE 0
70 POKE 2040,13
80 POKE 53287,14:REM YELLOW
90 POKE 53269,1:REM ENABLE SPRITE 0
100 REM POSITION SPRITE
110 POKE 53248,100:POKE 53249,100
120 REM WAIT FOR KEYPRESS
130 PRINT "PRESS SPACE TO EXPAND WIDTH"
140 GET A$:IF A$<>" " THEN 140
150 REM ENABLE X EXPANSION FOR SPRITE 0
160 POKE 53277,1:REM BIT 0 = SPRITE 0
170 PRINT "NOW 48 PIXELS WIDE!"
180 GET A$:IF A$="" THEN 180
190 END
200 REM SPRITE DATA (ARROW)
210 DATA 0,126,0,1,255,128,3,255,192
220 DATA 7,255,224,15,255,240,31,255,248
230 DATA 31,255,248,63,255,252,63,255,252
240 DATA 63,255,252,63,255,252,63,255,252
250 DATA 31,255,248,31,255,248,15,255,240
260 DATA 7,255,224,3,255,192,1,255,128
270 DATA 0,126,0,0,0,0,0,0,0
```

![Sprite before and after X expansion](/images/commodore-64/phase-0/tier-3/lesson-035/example-1.png)

**What's Happening:**
- Sprite initially 24 pixels wide (normal)
- POKE 53277,1 sets bit 0, enabling X expansion for sprite 0
- Sprite becomes 48 pixels wide—each pixel doubled horizontally
- Same sprite data, just displayed larger

## Example 2: Y Expansion (Double Height)

Now let's double the sprite vertically:

```basic
10 PRINT CHR$(147):REM CLEAR SCREEN
20 REM LOAD SPRITE DATA
30 FOR I=0 TO 62
40 READ B:POKE 832+I,B
50 NEXT
60 REM SETUP SPRITE 0
70 POKE 2040,13
80 POKE 53287,2:REM RED
90 POKE 53269,1
100 POKE 53248,100:POKE 53249,80
110 PRINT "PRESS SPACE TO EXPAND HEIGHT"
120 GET A$:IF A$<>" " THEN 120
130 REM ENABLE Y EXPANSION FOR SPRITE 0
140 POKE 53271,1:REM BIT 0 = SPRITE 0
150 PRINT "NOW 42 PIXELS TALL!"
160 GET A$:IF A$="" THEN 160
170 END
180 REM SPRITE DATA
190 DATA 0,126,0,1,255,128,3,255,192
200 DATA 7,255,224,15,255,240,31,255,248
210 DATA 31,255,248,63,255,252,63,255,252
220 DATA 63,255,252,63,255,252,63,255,252
230 DATA 31,255,248,31,255,248,15,255,240
240 DATA 7,255,224,3,255,192,1,255,128
250 DATA 0,126,0,0,0,0,0,0,0
```

![Sprite before and after Y expansion](/images/commodore-64/phase-0/tier-3/lesson-035/example-2.png)

**Key Points:**
- Register 53271 controls Y expansion
- Sprite height doubles from 21 to 42 pixels
- Each row of pixels displayed twice vertically
- Useful for tall characters or vertical scaling effects

## Example 3: Full Expansion (48×42 Pixels)

Combine both expansions for maximum size:

```basic
10 PRINT CHR$(147):REM CLEAR SCREEN
20 REM LOAD SPRITE DATA
30 FOR I=0 TO 62
40 READ B:POKE 832+I,B
50 NEXT
60 REM SETUP SPRITE 0
70 POKE 2040,13
80 POKE 53287,10:REM LIGHT RED
90 POKE 53269,1
100 POKE 53248,120:POKE 53249,100
110 REM ENABLE BOTH X AND Y EXPANSION
120 POKE 53277,1:REM X EXPANSION
130 POKE 53271,1:REM Y EXPANSION
140 PRINT "SPRITE IS NOW 48x42 PIXELS!"
150 PRINT "(4X ORIGINAL AREA)"
160 GET A$:IF A$="" THEN 160
170 END
180 REM SPRITE DATA
190 DATA 0,126,0,1,255,128,3,255,192
200 DATA 7,255,224,15,255,240,31,255,248
210 DATA 31,255,248,63,255,252,63,255,252
220 DATA 63,255,252,63,255,252,63,255,252
230 DATA 31,255,248,31,255,248,15,255,240
240 DATA 7,255,224,3,255,192,1,255,128
250 DATA 0,126,0,0,0,0,0,0,0
```

![Fully expanded sprite at 48×42 pixels](/images/commodore-64/phase-0/tier-3/lesson-035/example-3.png)

**Expansion Combinations:**
- Both registers set to 1 = 48×42 pixels (4× original area)
- Each original pixel becomes a 2×2 block
- Perfect for boss enemies or large power-ups
- No additional memory required—same 63 bytes of sprite data

## Example 4: Multicolour Sprites

Multicolour mode lets sprites use three colours instead of one:

```basic
10 PRINT CHR$(147):REM CLEAR SCREEN
20 REM LOAD MULTICOLOUR SPRITE DATA
30 FOR I=0 TO 62
40 READ B:POKE 832+I,B
50 NEXT
60 REM SETUP SPRITE 0
70 POKE 2040,13
80 POKE 53269,1:REM ENABLE SPRITE 0
90 REM ENABLE MULTICOLOUR MODE
100 POKE 53276,1:REM BIT 0 = SPRITE 0
110 REM SET MULTICOLOUR REGISTERS
120 POKE 53285,11:REM MC0 = DARK GREY
130 POKE 53286,12:REM MC1 = MEDIUM GREY
140 POKE 53287,15:REM SPRITE 0 COLOUR = LIGHT GREY
150 REM POSITION SPRITE
160 POKE 53248,140:POKE 53249,100
170 PRINT "MULTICOLOUR SPRITE"
180 PRINT "3 SHADES OF GREY"
190 GET A$:IF A$="" THEN 190
200 REM MULTICOLOUR SPRITE DATA
210 DATA 0,0,0,0,126,0,1,255,128
220 DATA 7,255,224,15,255,240,31,255,248
230 DATA 63,255,252,127,255,254,127,255,254
240 DATA 255,255,255,255,255,255,255,255,255
250 DATA 127,255,254,127,255,254,63,255,252
260 DATA 31,255,248,15,255,240,7,255,224
270 DATA 1,255,128,0,126,0,0,0,0
```

![Multicolour sprite with three shades](/images/commodore-64/phase-0/tier-3/lesson-035/example-4.png)

**Multicolour Mode Explained:**

In multicolour mode, sprite pixels are read in **pairs of bits**:
- **%00** = Transparent (background shows through)
- **%01** = Multicolour #0 (register 53285, shared by all MC sprites)
- **%10** = Sprite's individual colour (registers 53287-53294)
- **%11** = Multicolour #1 (register 53286, shared by all MC sprites)

**Trade-off:** Horizontal resolution drops from 24 pixels to 12 "fat pixels" (each is 2 bits wide).

## Example 5: Large Boss Sprite (Expanded + Multicolour)

Combine expansion with multicolour for an impressive boss enemy:

```basic
10 PRINT CHR$(147):REM CLEAR SCREEN
20 REM LOAD BOSS SPRITE DATA
30 FOR I=0 TO 62
40 READ B:POKE 832+I,B
50 NEXT
60 REM SETUP BOSS SPRITE
70 POKE 2040,13
80 POKE 53269,1
90 REM ENABLE MULTICOLOUR
100 POKE 53276,1
110 POKE 53285,8:REM MC0 = ORANGE
120 POKE 53286,2:REM MC1 = RED
130 POKE 53287,7:REM SPRITE COLOUR = YELLOW
140 REM ENABLE FULL EXPANSION
150 POKE 53277,1:REM X EXPANSION
160 POKE 53271,1:REM Y EXPANSION
170 REM POSITION BOSS
180 POKE 53248,140:POKE 53249,100
190 PRINT "BOSS ENEMY: 48x42 PIXELS"
200 PRINT "MULTICOLOUR + EXPANDED"
210 GET A$:IF A$="" THEN 210
220 REM BOSS SPRITE DATA (SKULL PATTERN)
230 DATA 0,0,0,0,126,0,3,255,192
240 DATA 15,255,240,31,255,248,63,255,252
250 DATA 127,255,254,255,255,255,255,255,255
260 DATA 255,231,255,255,231,255,255,255,255
270 DATA 127,255,254,63,255,252,31,255,248
280 DATA 15,255,240,7,255,224,3,255,192
290 DATA 1,255,128,0,126,0,0,0,0
```

![Large multicolour boss sprite at 48×42 pixels](/images/commodore-64/phase-0/tier-3/lesson-035/example-5.png)

**Boss Sprite Breakdown:**
- **Multicolour mode** = 3 colours (orange, red, yellow)
- **Full expansion** = 48×42 pixels on screen
- **Still only 63 bytes** of sprite data
- Perfect for end-of-level bosses or large power-ups

## When to Use Expansion

**X Expansion Only (48×21):**
- Wide objects (horizontal beams, platforms)
- Stretching effects
- Wide text/numbers

**Y Expansion Only (24×42):**
- Tall characters (standing figures)
- Vertical poles, trees
- Tall buildings

**Full Expansion (48×42):**
- Boss enemies
- Large collectables
- Title screen logos
- Impact effects

**Trade-off:** Larger sprites mean:
- More screen coverage (good for visibility)
- Blockier appearance (same resolution stretched)
- Easier collision detection (bigger target)

## Understanding Multicolour Sprite Data

When creating multicolour sprite data, remember each byte holds **4 fat pixels** (4 pairs of bits):

**Example byte: %10011011**
```
Bits:     10    01    10    11
Pixels:  [SP] [MC0] [SP] [MC1]
Colours: Grey Dark  Grey Med
```

Where:
- **SP** = Sprite colour (individual, register $D027-$D02E)
- **MC0** = Multicolour #0 (shared, register $D025)
- **MC1** = Multicolour #1 (shared, register $D026)

## Quick Reference

**Expansion Registers:**
| Register | Decimal | Purpose | Effect |
|----------|---------|---------|--------|
| $D01D | 53277 | X expansion | Width: 24 → 48 pixels |
| $D017 | 53271 | Y expansion | Height: 21 → 42 pixels |

**Multicolour Registers:**
| Register | Decimal | Purpose |
|----------|---------|---------|
| $D01C | 53276 | Multicolour enable (bit mask) |
| $D025 | 53285 | Multicolour #0 (shared) |
| $D026 | 53286 | Multicolour #1 (shared) |
| $D027-$D02E | 53287-53294 | Individual sprite colours |

**Multicolour Bit Pairs:**
| Bits | Colour Source | Typical Use |
|------|---------------|-------------|
| %00 | Transparent | Background/outline |
| %01 | MC #0 ($D025) | Shadow/dark shade |
| %10 | Sprite colour | Main colour/detail |
| %11 | MC #1 ($D026) | Highlight/bright shade |

**Size Combinations:**
| X Expand | Y Expand | Size | Pixels |
|----------|----------|------|--------|
| 0 | 0 | 24×21 | Normal |
| 1 | 0 | 48×21 | Wide |
| 0 | 1 | 24×42 | Tall |
| 1 | 1 | 48×42 | Large (4× area) |

## What You've Learnt

- Sprite expansion registers double width ($D01D) and height ($D017) independently
- Expansion doesn't increase resolution—pixels are displayed larger
- Multicolour mode enables three-colour sprites using bit-pair interpretation
- Multicolour reduces horizontal resolution from 24 to 12 fat pixels
- Combining expansion with multicolour creates large, colourful sprites
- Large sprites are essential for bosses, power-ups, and visual impact
