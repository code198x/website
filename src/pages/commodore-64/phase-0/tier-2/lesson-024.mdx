You've played single notes and chords. Now create music—sequences of notes stored as data, played back with precise timing. This is how game music works: melodies defined once, played anywhere in your program.

**DATA holds your melody, TI controls the timing, POKE makes it play.** With these three elements, you're composing music in code.

## The One-Minute Tour

- **Note sequencers store melodies as data** using note numbers and durations instead of hard-coded frequencies
- **TI variable provides timing** incrementing 60 times per second (NTSC) or 50 times per second (PAL)
- **Note tables map numbers to frequencies** making composition easier (note 0 = C, note 2 = D, note 4 = E)
- **Duration measured in jiffies** where 1 jiffy = 1/60 second, so 30 jiffies = half a second
- **Non-blocking sequencers allow gameplay** checking elapsed time rather than blocking in loops
- **READ/DATA pattern processes sequences** advancing through melody data step by step

## First Example: Simple Melody

Type this and hear a familiar tune:

```basic
10 REM NOTE SEQUENCER
20 PRINT CHR$(147)
30 PRINT "NOTE SEQUENCER"
40 PRINT
50 PRINT "PLAYING SIMPLE MELODY..."
60 REM SETUP SID
70 POKE 54296,15:REM MAX VOLUME
80 POKE 54277,9:POKE 54278,0:REM FAST ATTACK
85 REM NOTE TABLE (C4-C5)
90 DIM N(12)
100 FOR I=0 TO 12:READ N(I):NEXT
110 DATA 4286,4541,4811,5096,5401
120 DATA 5713,6052,6412,6791,7200
130 DATA 7628,8085,8556
140 REM PLAY SEQUENCE
150 FOR S=1 TO 14
160 READ NO,DU
170 F=N(NO)
180 FL=F AND 255:FH=INT(F/256)
190 POKE 54272,FL:POKE 54273,FH
200 POKE 54276,0:REM GATE OFF
210 POKE 54276,33:REM GATE ON
220 NT=TI
230 IF TI-NT<DU THEN 230
240 NEXT S
250 POKE 54276,0:REM SILENCE
260 PRINT
270 PRINT "MELODY COMPLETE!"
280 END
290 REM MELODY DATA (TWINKLE TWINKLE)
300 DATA 0,30,0,30,7,30,7,30
310 DATA 9,30,9,30,7,60
320 DATA 5,30,5,30,4,30,4,30
330 DATA 2,30,2,30,0,60
```

**Run this** and the familiar melody plays note by note.

The note table (lines 90-130) maps note numbers to frequencies: 0=C, 2=D, 4=E, 5=F, 7=G, 9=A. The melody data (lines 300-330) stores pairs of note number and duration. Each note plays for its specified duration (30 jiffies = half second, 60 jiffies = one second), then the next note begins. This blocking approach works for demonstrations but would freeze a game.

## Second Example: Non-Blocking Sequencer

Now let's play music while other things happen:

```basic
10 REM NON-BLOCKING SEQUENCER
20 PRINT CHR$(147)
30 PRINT "NON-BLOCKING SEQUENCER"
40 PRINT
50 PRINT "PLAYING MELODY..."
60 PRINT "COUNTER UPDATES WHILE MUSIC PLAYS"
70 PRINT
80 REM SETUP SID
90 POKE 54296,15:REM MAX VOLUME
100 POKE 54277,9:POKE 54278,0:REM FAST ATTACK
110 REM NOTE TABLE (C4-C5)
120 DIM N(12)
130 FOR I=0 TO 12:READ N(I):NEXT
140 DATA 4286,4541,4811,5096,5401
150 DATA 5713,6052,6412,6791,7200
160 DATA 7628,8085,8556
170 REM SEQUENCE VARIABLES
180 SP=0:REM SEQUENCE POSITION
190 NT=0:REM NOTE START TIME
200 DU=0:REM DURATION
210 C=0:REM COUNTER
220 REM MAIN LOOP
230 GOSUB 1000:REM UPDATE SEQUENCER
240 C=C+1:REM UPDATE COUNTER
250 PRINT CHR$(19);:REM HOME
260 FOR I=1 TO 7:PRINT:NEXT
270 PRINT "COUNTER: ";C
280 IF SP<13 THEN 230
290 PRINT:PRINT "MELODY COMPLETE!"
300 POKE 54276,0:REM SILENCE
310 END
1000 REM SEQUENCER UPDATE
1010 IF SP=0 THEN GOSUB 2000:RETURN
1020 E=TI-NT:REM ELAPSED JIFFIES
1030 IF E<DU THEN RETURN
1040 GOSUB 2000:REM PLAY NEXT NOTE
1050 RETURN
2000 REM PLAY NEXT NOTE
2010 READ NO,DU:REM NOTE, DURATION
2020 SP=SP+1:NT=TI
2030 IF NO=99 THEN POKE 54276,0:RETURN
2040 F=N(NO)
2050 FL=F AND 255:FH=INT(F/256)
2060 POKE 54272,FL:POKE 54273,FH
2070 POKE 54276,0:REM GATE OFF
2080 POKE 54276,33:REM GATE ON
2090 RETURN
2100 REM MELODY DATA (MARY HAD A LITTLE LAMB)
2110 DATA 4,30,2,30,0,30,2,30
2120 DATA 4,30,4,30,4,60
2130 DATA 2,30,2,30,2,60
2140 DATA 4,30,7,30,7,60
```

**Run this** and watch the counter increase whilst the melody plays.

The main loop (line 230-280) calls the sequencer update (GOSUB 1000) then continues with other work (updating the counter). The sequencer checks if enough time has elapsed (line 1030)—if not, it returns immediately without blocking. When a note finishes, it plays the next one. The counter demonstrates that your program remains responsive whilst music plays. This is essential for games where you need to handle player input, move sprites, and check collisions whilst background music plays.

## How Note Tables Work

Rather than remembering that C is frequency 4286, use a lookup table:

```basic
90 DIM N(12)
100 FOR I=0 TO 12:READ N(I):NEXT
110 DATA 4286,4541,4811,5096,5401
120 DATA 5713,6052,6412,6791,7200
130 DATA 7628,8085,8556
```

Now note 0 = C (4286), note 1 = C# (4541), note 2 = D (4811), and so on. In your melody data:

```basic
300 DATA 0,30,0,30,7,30,7,30
```

This means: note 0 (C) for 30 jiffies, note 0 (C) for 30 jiffies, note 7 (G) for 30 jiffies, note 7 (G) for 30 jiffies. Much easier than typing frequency values!

The table covers notes C4 through C5 (one octave plus one note). You can extend this to multiple octaves by adding more frequencies.

## Understanding Jiffies and Duration

The TI variable increments 60 times per second on NTSC machines (50 times per second on PAL). Each increment is one "jiffy":

- **30 jiffies** = half a second = quarter note at 120 BPM
- **60 jiffies** = one second = half note at 120 BPM
- **15 jiffies** = quarter second = eighth note at 120 BPM
- **7-8 jiffies** = eighth of a second = sixteenth note at 120 BPM

Common musical durations at 120 beats per minute:
- Whole note: 120 jiffies
- Half note: 60 jiffies
- Quarter note: 30 jiffies
- Eighth note: 15 jiffies

You can adjust tempo by multiplying all durations. For 60 BPM (slower), double all duration values. For 240 BPM (faster), halve them.

## The Timing Pattern

**Blocking version** (freezes program):

```basic
220 NT=TI
230 IF TI-NT<DU THEN 230
```

This loops repeatedly checking time, blocking everything else.

**Non-blocking version** (allows other work):

```basic
1020 E=TI-NT:REM ELAPSED JIFFIES
1030 IF E<DU THEN RETURN
```

This checks time once, returns if note still playing. The main program continues running and calls back later.

The non-blocking pattern is essential for games. Your game loop calls GOSUB 1000 each frame. If the current note is still playing, it returns immediately. When the note finishes, it starts the next one and returns. Meanwhile, your game loop handles joystick input, moves sprites, and checks collisions.

## Rests and Silence

Use a special note number for rests (silence between notes):

```basic
2030 IF NO=99 THEN POKE 54276,0:RETURN
```

In your melody data: `DATA 0,30,99,15,2,30` plays note 0 for 30 jiffies, then silence for 15 jiffies, then note 2 for 30 jiffies.

The silence comes from clearing the gate bit (POKE 54276,0). Without this, notes would run together with no separation. Even when not using explicit rests, you should clear the gate before setting it again (lines 200-210 in example 1) to ensure each note has a distinct start.

## Extending the System

**Multiple octaves:** Add more frequencies to the note table. Note 13 = C#5, note 14 = D5, extending upward. Or create a second table for lower octaves.

**Looping melodies:** Add an end marker:

```basic
2010 READ NO,DU
2020 IF NO<0 THEN RESTORE:READ NO,DU
```

When you read -1, RESTORE the data pointer and start again. Your melody loops forever.

**Multiple voices:** Create three separate sequencers (SP1, SP2, SP3) updating three voices. Each voice can play a different melody simultaneously, creating harmonies or counterpoint melodies.

**Dynamic tempo:** Store a tempo multiplier and apply it to all durations. To play at half speed, multiply all durations by 2.

**Music data compression:** Instead of storing frequency pairs, store just note numbers. Store a default duration globally and only specify duration when it changes.

## What You've Learnt

- **Store melodies as DATA sequences** using note numbers and durations
- **Use note tables for easy composition** mapping numbers to frequencies
- **Measure time with TI variable** for precise musical timing in jiffies
- **Implement non-blocking sequencers** allowing music to play whilst programs run
- **Control note articulation** using gate off/on for distinct note starts
- **Create musical rests** using special note numbers that silence output
- **Calculate tempo and duration** converting musical notation to jiffies

You now have the foundation for game music. The non-blocking sequencer is exactly how professional C64 games play background music—a routine called once per frame that advances the sequence and updates sound registers without freezing gameplay.
