## Lesson 26 – Sprite Motion

Now that your sprite exists, let’s move it. You’ll update the position registers inside a loop, add velocity, and clamp the sprite to the visible playfield.

> [📷 suggested: screenshot of a sprite gliding horizontally]

---

### The One-Minute Tour

- Sprite 0 X/Y registers: `53248` / `53249` (0–255).  
- Update these inside a loop to animate motion.  
- Clamp values so the sprite doesn’t vanish off-screen.  
- Delay loops make motion readable.

---

### Horizontal Slide

```basic
NEW
10 PRINT CHR$(147)
20 FOR I=832 TO 894:POKE I,255:NEXT I
30 POKE 2040,13 : POKE 53269,1 : POKE 53287,6
40 X=40 : Y=120
50 POKE 53248,X : POKE 53249,Y
60 FOR D=1 TO 60:NEXT D
70 X=X+2
80 IF X>255 THEN X=40
90 GOTO 50
```

The sprite slides to the right and wraps when it reaches the register limit.

---

### Horizontal Bounce

```basic
NEW
10 PRINT CHR$(147)
20 FOR I=832 TO 894:POKE I,255:NEXT I
30 POKE 2040,13 : POKE 53269,1 : POKE 53287,2
40 X=100 : Y=100 : VX=2
50 POKE 53248,X : POKE 53249,Y
60 FOR D=1 TO 40:NEXT D
70 X=X+VX
80 IF X<24 OR X>255 THEN VX=-VX
90 GOTO 50
```

Velocity `VX` flips sign at the edges, creating a bounce effect.

---

### Experiment Section

- Adjust `VX` to change speed.  
- Swap `X`/`Y` for vertical motion (`POKE 53249`).  
- Combine with colour changes—`POKE 53287,(COLOR AND 15)` each frame.  
- Add input: check `GET K$` inside the loop to switch between automatic and player-controlled motion.

---

### Concept Expansion

These position updates mirror the screen-coordinate animation you built in Week 3, but sprites move smoother because the VIC-II handles drawing. Upcoming lessons add animation frames and collision detection.

---

### Game Integration

- Patrol enemies: update `X`/`Y` with velocity arrays to reuse the logic for multiple sprites.  
- Projectiles: create a subroutine that spawns a sprite at the player’s position and pushes it with constant `VX`.  
- Camera prototypes: later lessons combine multiple sprites and background scrolling using similar updates.
