## From Output to Input

In previous lessons, you controlled what the C64 displays and plays. But games need input—and the joystick is the primary control device. This lesson introduces the CIA (Complex Interface Adapter) chip, which handles all external input/output. You'll learn to read joystick state through a single memory location and decode its directional data using bitwise operations.

---

### The One-Minute Tour

- CIA chip controls joystick input at memory location 56320
- PEEK(56320) returns single byte encoding all joystick state
- Active-low logic: 0=pressed, 1=released (counter-intuitive!)
- Five bits encode directions and fire: bits 0-4
- AND operation with 31 isolates joystick bits (ignores keyboard bits 5-7)
- AND with specific bit masks tests individual directions
- Port 2 (56320) is standard for games; Port 1 is 56321
- Multiple simultaneous directions enable diagonal movement
- Continuous reading in loop provides real-time response
- Same technique extends to paddles, mice, light pens

### Example Program

```basic
10 REM JOYSTICK TESTER
20 PRINT CHR$(147);CHR$(18)
30 PRINT "JOYSTICK PORT 2 TESTER"
40 PRINT CHR$(146)
50 PRINT
60 PRINT "     UP"
70 PRINT "LEFT   RIGHT"
80 PRINT "    DOWN"
90 PRINT
100 PRINT "FIRE:"
110 REM MAIN LOOP
120 J=PEEK(56320) AND 31
130 REM DISPLAY UP
140 PRINT CHR$(19);CHR$(145);CHR$(145);CHR$(145);CHR$(145);CHR$(145)
150 IF (J AND 1)=0 THEN PRINT "  *";CHR$(157);CHR$(157);CHR$(157):GOTO 160
155 PRINT "   "
160 REM DISPLAY LEFT AND RIGHT
170 PRINT CHR$(145)
180 IF (J AND 4)=0 THEN PRINT "*":GOTO 190
185 PRINT " "
190 PRINT "     ";
200 IF (J AND 8)=0 THEN PRINT "*":GOTO 210
205 PRINT " "
210 REM DISPLAY DOWN
220 PRINT CHR$(145);CHR$(145);CHR$(157);CHR$(157);CHR$(157);CHR$(157)
230 IF (J AND 2)=0 THEN PRINT "  *":GOTO 240
235 PRINT "   "
240 REM DISPLAY FIRE
250 PRINT CHR$(145);CHR$(145);CHR$(145);CHR$(145)
260 IF (J AND 16)=0 THEN PRINT "PRESSED":GOTO 270
265 PRINT "       "
270 REM SHORT DELAY
280 FOR D=1 TO 10:NEXT
290 GOTO 120
```

**Line 120** reads Port 2 (56320) and masks with AND 31 to isolate joystick bits. **Lines 150/180/200/230/260** test individual bits using AND with bit masks (1=up, 2=down, 4=left, 8=right, 16=fire). **Lines 140/220** use cursor positioning codes (CHR$(19)=HOME, CHR$(145)=UP, CHR$(157)=LEFT) to update display in place without scrolling. **Line 280** adds brief delay for readable display updates.

140 IF (J AND 1)=0 AND (J AND 8)=0 THEN PRINT CHR$(19);"UP-RIGHT           ":GOTO 280
150 IF (J AND 2)=0 AND (J AND 4)=0 THEN PRINT CHR$(19);"DOWN-LEFT          ":GOTO 280

**Lines 130-160** detect diagonal directions by checking two bits simultaneously—both must be pressed (both equal 0). **Lines 180-210** detect cardinal directions when only one direction bit is pressed. **Line 230** handles centre position when no direction bits are pressed. Order matters: diagonals checked first, then cardinals, then centre.

### Concept Expansion

**CIA Chip Architecture**

The CIA (Complex Interface Adapter) handles all input/output ports:

```
CIA #1 (56320-56335): Keyboard, joysticks, paddles
CIA #2 (56576-56591): Serial port, RS-232, timers

Port A (56320): Joystick Port 2 (standard for games)
Port B (56321): Joystick Port 1
```

**Joystick Bit Layout**

Reading PEEK(56320) returns single byte with this structure:

```
Bit 7: Keyboard column 7
Bit 6: Keyboard column 6
Bit 5: Keyboard column 5
Bit 4: Fire button    (0=pressed)
Bit 3: Right          (0=pressed)
Bit 2: Left           (0=pressed)
Bit 1: Down           (0=pressed)
Bit 0: Up             (0=pressed)
```

**Why AND 31?** Binary 31 = 00011111—keeps only bits 0-4 (joystick data), ignores bits 5-7 (keyboard interference).

**Active-Low Logic**

Hardware convention: unpowered state = logic 1 (5V), grounded = logic 0:

```basic
J=PEEK(56320) AND 31

REM If joystick unplugged or centred:
REM All bits = 1, so J=31 (binary 11111)

REM If UP pressed:
REM Bit 0 grounded = 0, others = 1
REM J=30 (binary 11110)

REM Test if UP pressed:
IF (J AND 1)=0 THEN PRINT "UP PRESSED"
```

**Bitwise AND for Testing**

AND operation checks specific bits:

```
J = 30 (binary 11110) — UP pressed
Mask = 1 (binary 00001) — Check bit 0

J AND Mask:
  11110
& 00001
-------
  00000 = 0 (true: UP is pressed)

J = 31 (binary 11111) — Centre position
Mask = 1 (binary 00001)

J AND Mask:
  11111
& 00001
-------
  00001 = 1 (false: UP not pressed)
```

**Multiple Simultaneous Inputs**

Diagonal movement requires checking two bits:

```basic
REM UP-LEFT: both bit 0 (UP) and bit 2 (LEFT) must be 0
IF (J AND 1)=0 AND (J AND 4)=0 THEN PRINT "UP-LEFT"

REM Why this works:
REM (J AND 1)=0 verifies bit 0 grounded
REM (J AND 4)=0 verifies bit 2 grounded
REM Both conditions true only when both pressed
```

**Common Bit Masks**

| Direction | Bit | Mask | Check Expression |
|-----------|-----|------|------------------|
| Up | 0 | 1 | (J AND 1)=0 |
| Down | 1 | 2 | (J AND 2)=0 |
| Left | 2 | 4 | (J AND 4)=0 |
| Right | 3 | 8 | (J AND 8)=0 |
| Fire | 4 | 16 | (J AND 16)=0 |
| Any direction | 0-3 | 15 | (J AND 15)&lt;&gt;15 |

**Typical Game Loop Pattern**

```basic
REM Read joystick
J=PEEK(56320) AND 31

REM Update player position
IF (J AND 1)=0 THEN Y=Y-1  : REM UP
IF (J AND 2)=0 THEN Y=Y+1  : REM DOWN
IF (J AND 4)=0 THEN X=X-1  : REM LEFT
IF (J AND 8)=0 THEN X=X+1  : REM RIGHT

REM Fire weapon
IF (J AND 16)=0 THEN GOSUB 5000  : REM FIRE ROUTINE
```

**Port Selection**

```
Port 2 (56320): Primary gaming port
  - Most comfortable for right-handed players
  - Standard convention for single-player games

Port 1 (56321): Secondary port
  - Used for Player 2 in two-player games
  - Same bit layout as Port 2
```

### Common Mistakes

**Problem 1: Reading Wrong Port Number**
```basic
J=PEEK(56321) AND 31  REM Expected Port 2, using Port 1!
```
**Diagnosis:** Port 1 (56321) reads different joystick. Games conventionally use Port 2 (56320) as primary controller.

**Fix:** Use correct port address for Port 2:
```basic
J=PEEK(56320) AND 31  REM Port 2 (standard gaming port)
```
**Why:** CIA chip has two joystick ports—Port A (56320) connects to physical Port 2, Port B (56321) connects to physical Port 1. Single-player games use Port 2 (56320) as standard convention. Easy to confuse because port numbering seems backwards.

**Problem 2: Testing for Wrong Logic Level**
```basic
J=PEEK(56320) AND 31
IF (J AND 1)=1 THEN PRINT "UP"  REM Never detects UP!
```
**Diagnosis:** Checking for 1 instead of 0. Active-low logic means 0=pressed, 1=released.

**Fix:** Check for 0 to detect pressed state:
```basic
J=PEEK(56320) AND 31
IF (J AND 1)=0 THEN PRINT "UP"  REM Now detects UP correctly
```
**Why:** CIA hardware uses active-low logic—joystick grounds the bit when pressed (reads as 0), releases to 5V when unpressed (reads as 1). This is counter-intuitive but standard for all C64 joystick input. Always check (J AND mask)=0 for "pressed".

**Problem 3: Forgetting AND 31 Mask**
```basic
J=PEEK(56320)  REM No mask!
IF (J AND 1)=0 THEN PRINT "UP"  REM Sometimes triggers randomly!
```
**Diagnosis:** Bits 5-7 contain keyboard data that interferes with joystick reading. Random keyboard scan states cause false positives.

**Fix:** Always mask with AND 31 to isolate joystick bits:
```basic
J=PEEK(56320) AND 31  REM Isolate bits 0-4 only
IF (J AND 1)=0 THEN PRINT "UP"  REM Reliable detection
```
**Why:** PEEK(56320) returns full 8-bit value including keyboard matrix data in bits 5-7. Binary 31 (00011111) masks out keyboard bits, keeping only joystick bits 0-4 (up/down/left/right/fire). Without masking, keyboard activity triggers false joystick readings.

**Problem 4: Wrong Bit Mask Values**
```basic
J=PEEK(56320) AND 31
IF (J AND 2)=0 THEN PRINT "LEFT"  REM Thinks bit 2=LEFT!
```
**Diagnosis:** Bit positions confused. Bit 1 is DOWN, bit 2 is LEFT—but mask value for bit 2 is 4 (not 2).

**Fix:** Use correct bit mask values (powers of 2):
```basic
J=PEEK(56320) AND 31
IF (J AND 4)=0 THEN PRINT "LEFT"  REM Correct: bit 2 mask=4
```
**Why:** Bit masks are powers of 2: bit 0=1, bit 1=2, bit 2=4, bit 3=8, bit 4=16. The bit number is NOT the mask value. Bit 2 (LEFT) requires mask value 4 (binary 00000100). See Quick Reference table for all correct masks.

### How Games Use This

**IK+ (International Karate +)** (1987, System 3): Used simultaneous directional input combined with fire button for different moves. UP+FIRE = high kick, DOWN+FIRE = sweep kick, demonstrating how bit checking enables complex control schemes.

**Uridium** (1986, Hewson): Required extremely responsive joystick reading—main loop checked joystick every frame (50 times per second) to achieve smooth spaceship control at high speeds.

**Boulder Dash** (1984, First Star): Checked for diagonal movement to enable efficient digging patterns. Same technique you learned in example 2 allowed players to dig diagonally through dirt.

**Way of the Exploding Fist** (1985, Melbourne House): Detected specific joystick sequences (like fighting game combos) by storing recent joystick states in array and pattern-matching for special moves.

### Quick Reference

**Reading Joystick:**
```basic
J=PEEK(56320) AND 31    REM Port 2 (standard gaming port)
J=PEEK(56321) AND 31    REM Port 1 (player 2)
```

**Testing Directions:**
```basic
IF (J AND 1)=0 THEN ...   REM UP pressed
IF (J AND 2)=0 THEN ...   REM DOWN pressed
IF (J AND 4)=0 THEN ...   REM LEFT pressed
IF (J AND 8)=0 THEN ...   REM RIGHT pressed
IF (J AND 16)=0 THEN ...  REM FIRE pressed
```

**Testing Diagonals:**
```basic
IF (J AND 1)=0 AND (J AND 4)=0 THEN ...  REM UP-LEFT
IF (J AND 1)=0 AND (J AND 8)=0 THEN ...  REM UP-RIGHT
IF (J AND 2)=0 AND (J AND 4)=0 THEN ...  REM DOWN-LEFT
IF (J AND 2)=0 AND (J AND 8)=0 THEN ...  REM DOWN-RIGHT
```

**Port Addresses:**
```
56320 ($DC00): CIA #1 Port A (Joystick Port 2)
56321 ($DC01): CIA #1 Port B (Joystick Port 1)
```

**Bit Masks:**
```
AND 31  : Isolate joystick bits (0-4)
AND 1   : Test UP (bit 0)
AND 2   : Test DOWN (bit 1)
AND 4   : Test LEFT (bit 2)
AND 8   : Test RIGHT (bit 3)
AND 16  : Test FIRE (bit 4)
AND 15  : Test any direction (bits 0-3)
```

### What You've Learnt

- CIA chip at 56320 provides joystick input for Port 2
- PEEK(56320) AND 31 isolates joystick bits from keyboard data
- Active-low logic: 0=pressed, 1=released (counter-intuitive)
- Bitwise AND tests individual direction bits: 1/2/4/8/16 for up/down/left/right/fire
- Multiple simultaneous bits enable diagonal detection
- Continuous reading in loop provides real-time response
- Port 2 (56320) standard for single-player; Port 1 (56321) for player 2
- Same bit layout applies to both ports
- Checking order matters: test diagonals before cardinals
- Technique extends to other CIA input devices (paddles, mice)
