## From Notes to Melodies

In Lesson 024, we shaped individual sounds with ADSR envelopes. But music isn't isolated notes—it's sequences with rhythm, timing, and silence. This lesson transforms frequency values and timing loops into recognisable melodies, using arrays to store musical data and control structures to play it back with precise timing.

---

### The One-Minute Tour

- Arrays store frequency values for note sequences
- FOR loops iterate through music data
- Timing loops control note duration (250 iterations ≈ quarter note)
- Gate bit (17=on, 16=off) triggers each note
- Inter-note gap creates separation between notes
- Rest implementation uses frequency value 0
- Variable durations enable rhythm (250=quarter, 500=half note)
- DIM statement allocates array storage (DIM F(N) creates indices 0-N)
- Same ADSR settings throughout maintain consistent timbre
- Little-endian byte order: low byte first, high byte second

---

### Example Program

```basic
10 REM SIMPLE MELODY PLAYER
20 REM SETUP ADSR
30 POKE 54277,9:POKE 54278,0
40 REM SET VOLUME
50 POKE 54296,15
60 REM NOTE DATA: E D C D E E E (MARY HAD A LITTLE LAMB)
70 DIM F(6)
80 F(0)=5406:F(1)=4817:F(2)=4291:F(3)=4817
90 F(4)=5406:F(5)=5406:F(6)=5406
100 REM PLAY MELODY
110 FOR N=0 TO 6
120 L=F(N) AND 255:H=INT(F(N)/256)
130 POKE 54272,L:POKE 54273,H
140 POKE 54276,17
150 FOR T=1 TO 250:NEXT
160 POKE 54276,16
170 FOR T=1 TO 50:NEXT
180 NEXT
```

**Lines 70-90** store frequency values in array F—seven notes for "Mary Had a Little Lamb" (E D C D E E E). **Line 120** splits each frequency into low and high bytes using AND 255 (masks to lowest 8 bits) and INT(F(N)/256) (extracts upper byte). **Lines 130** write bytes in correct little-endian order: low byte to 54272, high byte to 54273. **Lines 140-150** play the note by setting gate bit and delaying 250 iterations (≈5 seconds per note). **Lines 160-170** clear gate bit and add 50-iteration gap between notes.

**Line 70** declares two arrays: F for frequencies, D for durations. **Line 90** includes F(7)=0 for a rest (silent pause). **Line 180** checks if frequency is zero—if so, skip to gate-off (line 230) without playing anything. **Lines 120-150** set duration values: 250 for quarter notes, 500 for half notes, 125 for eighth-note rest. **Line 220** uses variable duration D(N) instead of fixed value, enabling rhythm.

### Concept Expansion

**Array-Based Music Storage**

Arrays provide efficient storage for musical sequences:

```basic
DIM F(14)        REM Allocates indices 0-14 (15 elements total)
F(0)=4291        REM First note (C)
F(1)=4291        REM Second note (C)
F(14)=4291       REM Final note (C)
```

**Important:** `DIM F(N)` creates array with indices 0 through N inclusive—that's N+1 total elements. For 15 notes, use `DIM F(14)`.

**Frequency Byte Splitting**

SID chip frequency registers use little-endian 16-bit values:

```
Frequency value: 4291 decimal = $10C3 hex = 0001000011000011 binary

Split into bytes:
  Low byte:  $C3 = 195 decimal = bits 0-7
  High byte: $10 = 16 decimal  = bits 8-15

Calculation in BASIC:
  L = F(N) AND 255        REM Mask to lower 8 bits (0-255)
  H = INT(F(N)/256)       REM Divide by 256, integer part = upper byte

Storage order (little-endian):
  POKE 54272,L            REM Low byte first
  POKE 54273,H            REM High byte second
```

**Why AND 255?** Bitwise AND with 255 (binary 11111111) keeps only the lowest 8 bits, effectively performing modulo 256 operation.

**Why INT(F(N)/256)?** Integer division by 256 shifts value right by 8 bits, extracting the high byte.

**Duration Control**

Different note lengths create rhythm:

```basic
REM Quarter note (standard)
D(0)=250         REM ≈5 seconds at PAL speed
FOR T=1 TO D(0):NEXT

REM Half note (twice as long)
D(6)=500         REM ≈10 seconds
FOR T=1 TO D(6):NEXT

REM Eighth note (half as long)
D(7)=125         REM ≈2.5 seconds
FOR T=1 TO D(7):NEXT
```

Each iteration of `FOR T=1 TO N:NEXT` takes approximately 20ms on PAL C64 (50Hz). Therefore:
- 250 iterations ≈ 5 seconds (quarter note at moderate tempo)
- 500 iterations ≈ 10 seconds (half note)
- 125 iterations ≈ 2.5 seconds (eighth note)

**Rest Implementation**

Musical rests (silence) use frequency value zero:

```basic
F(7)=0                    REM Rest marker

REM In playback loop:
IF F(N)=0 THEN 230        REM Skip frequency/gate if rest
POKE 54272,L:POKE 54273,H REM Only reached for non-zero frequencies
POKE 54276,17             REM Gate on
FOR T=1 TO D(N):NEXT      REM Duration (works for rest too)
POKE 54276,16             REM Gate off
```

Line 180 checks for zero frequency. If found, execution jumps to line 230 (gate-off) without setting frequency registers or turning gate on. The timing loop at line 220 still executes using D(7) duration, creating measured silence.

**Inter-Note Gaps**

Brief silence between notes prevents slurring:

```basic
POKE 54276,16             REM Gate off (end of note)
FOR T=1 TO 50:NEXT        REM 50-iteration gap (≈1 second)
```

Without this gap, consecutive notes would blend together. The gap creates articulation, making melody clearer.

**Common Musical Patterns**

| Pattern | Duration Array | Effect |
|---------|---------------|--------|
| Steady quarter notes | All values 250 | Even rhythm |
| Waltz (3/4 time) | 500,250,250 repeated | Strong-weak-weak |
| Dotted rhythm | 375,125 repeated | Long-short pairs |
| Staccato | Short note + long gap | Detached notes |
| Legato | Long note + short gap | Connected notes |

**Memory Considerations**

Each array element consumes 5 bytes (floating-point format). A 15-note melody using two arrays:
```
F(14) = 15 notes × 5 bytes = 75 bytes
D(14) = 15 notes × 5 bytes = 75 bytes
Total: 150 bytes
```

C64 BASIC has 38911 bytes free at startup—plenty for extensive musical data.

**Practical Applications**

**Background music:** Store multiple melodies in arrays, select which to play based on game state.

**Sound effects sequences:** Use same technique for multi-note effects (door open, level complete).

**Interactive music:** Change tempo (duration multiplier) based on gameplay urgency.

**Polyphonic foundation:** This lesson's techniques extend to multi-voice music using voices 2 and 3 with different frequency register bases (54279/54286 for voice 2, 54286/54287 for voice 3).

### How Games Use This

**The Great Giana Sisters** (1987, Rainbow Arts): Used array-based music storage for the famous title theme. Different sections of the melody were stored as separate arrays, assembled during playback to create the complete composition without storing the entire song linearly.

**Ghostbusters** (1984, Activision): The iconic theme tune used variable durations to capture the song's distinctive rhythm. Array storage allowed the same melody data to be replayed when entering the vehicle, conserving memory.

**Monty on the Run** (1985, Gremlin Graphics): Rob Hubbard's legendary soundtrack used similar sequencing techniques in machine code, but the principle remains identical—arrays of frequency values played through timing loops with variable durations.

**Boulder Dash** (1984, First Star): Menu music used rest implementation (silence markers) to create rhythmic variation. The simple melody repeated throughout gameplay without consuming significant CPU cycles.

### Quick Reference

**Array Declaration:**
```basic
DIM F(N)          REM Creates indices 0-N (N+1 elements)
DIM F(N),D(N)     REM Multiple arrays in one statement
```

**Frequency Byte Splitting:**
```basic
L = F(N) AND 255         REM Low byte (0-255)
H = INT(F(N)/256)        REM High byte (0-255)
POKE 54272,L             REM Low byte to $D400
POKE 54273,H             REM High byte to $D401
```

**Playback Loop Structure:**
```basic
FOR N=0 TO [LAST_INDEX]
  IF F(N)=0 THEN [SKIP_TO_GATE_OFF]  REM Handle rests
  [SPLIT_FREQUENCY]
  [SET_FREQUENCY_REGISTERS]
  POKE 54276,17          REM Gate on
  FOR T=1 TO D(N):NEXT   REM Variable duration
  POKE 54276,16          REM Gate off
  FOR T=1 TO 50:NEXT     REM Inter-note gap
NEXT
```

**Duration Values (PAL timing):**
```
125 iterations  ≈  2.5 seconds (eighth note)
250 iterations  ≈  5.0 seconds (quarter note)
500 iterations  ≈ 10.0 seconds (half note)
1000 iterations ≈ 20.0 seconds (whole note)
```

**Common Note Frequencies (Middle Octave):**
```
C:  4291    D:  4817    E:  5406
F:  5729    G:  6430    A:  7217
B:  8099    C': 8581
```

### What You've Learnt

- Arrays store frequency values for musical sequences efficiently
- DIM F(N) creates array with indices 0-N (N+1 total elements)
- Frequency values split into low/high bytes using AND 255 and INT(F/256)
- Little-endian byte order: low byte to 54272, high byte to 54273
- FOR loops iterate through array data for sequential playback
- Timing loops control note duration (250 iterations ≈ quarter note)
- Gate bit (17=on, 16=off) must be toggled for each note
- Inter-note gaps (50 iterations) prevent notes from slurring together
- Rest implementation uses frequency value 0 with conditional skip
- Variable duration array enables rhythm (250=quarter, 500=half note)
- Same technique scales to multi-voice polyphonic music
