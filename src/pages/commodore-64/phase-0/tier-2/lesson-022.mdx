You've mastered sprites, joystick control, bullets, collision detection, and enemy waves. Now **synthesise everything** into a complete game with title screen, lives system, game over state, HUD updates, and defensive programming patterns. This is your first complete sprite-based game—Space Defender.

This lesson introduces **game state machines** (title/play/game over), **lives tracking**, **screen effects** (flashing on damage), and **boundary checking** patterns that prevent crashes. These are professional game development techniques that work on any platform.

## The One-Minute Tour

- **Game states**—Variable GS controls three modes: 0=title, 1=playing, 2=game over
- **State machine**—`ON GS+1 GOSUB` dispatches to correct state handler
- **Lives system**—LI variable tracks remaining lives, game over at LI=0
- **HUD updates**—Top line shows score, lives, wave number
- **Screen flashing**—Visual feedback when player hit (border colour cycling)
- **Player respawn**—Reset position to centre after taking damage
- **Boundary checks**—Validate coordinates before POKE to prevent crashes
- **Defensive programming**—Check ranges before every sprite position update
- **Complete loop**—Title → play → game over → restart

## How This Works

### Game State Machine

The core innovation is **state-based control flow**:

```basic
200 GS=0              ' Start in title state
240 REM MAIN LOOP
250 ON GS+1 GOSUB 1000,2000,3000
260 GOTO 250
```

**`ON GS+1 GOSUB`** dispatches to different subroutines based on state:
- **GS=0** → calls line 1000 (title screen)
- **GS=1** → calls line 2000 (playing game)
- **GS=2** → calls line 3000 (game over)

Each state handler returns, the main loop continues. **State changes** happen inside handlers:
- Title screen: `GS=1` when fire pressed (line 1230)
- Playing: `GS=2` when lives reach 0 (line 2930)
- Game over: `GS=0` when fire pressed to restart (line 3120)

### Lives System and Game Over

**Lives tracking** integrates throughout:

```basic
1310 SC=0:LI=3:WV=1         ' Initialize with 3 lives
2630 IF EY(I)>229 THEN GOSUB 6100:LI=LI-1:RETURN  ' Enemy escaped
2930 IF LI=0 THEN GS=2       ' Game over check
8010 LI=LI-1                 ' Player hit enemy
```

**Two ways to lose lives**:
1. **Enemy escapes** (line 2630)—reaches bottom of screen
2. **Player collision** (line 8010)—touches enemy sprite

When `LI=0`, game transitions to state 2 (game over).

### HUD Updates with POKE 214

The **heads-up display** updates every frame:

```basic
2910 POKE 214,0:PRINT:REM CURSOR TO TOP
2920 PRINT "SCORE: ";SC;"  LIVES: ";LI;"  WAVE: ";WV
```

**POKE 214,0** moves cursor to row 0 without clearing screen. Next PRINT statement overwrites that line, updating HUD while gameplay continues below.

**Why this works**: Normal PRINT scrolls screen. Setting cursor position directly writes to specific location without scrolling.

### Screen Flash Effect

Visual feedback for taking damage:

```basic
8020 REM FLASH SCREEN
8030 FOR F=1 TO 3
8040 POKE 53280,2:FOR D=1 TO 50:NEXT D   ' Red border
8050 POKE 53280,0:FOR D=1 TO 50:NEXT D   ' Black border
8060 NEXT F
```

**Three red/black flashes** (register 53280 = border colour) with timing delays. Player notices damage immediately.

### Defensive Boundary Checks

**Critical crash prevention** pattern throughout:

```basic
2425 IF BY(I)<0 OR BY(I)>255 THEN GOSUB 6000:RETURN
2650 IF EX(I)<0 OR EX(I)>320 THEN GOSUB 6100:RETURN
2655 IF EY(I)<0 OR EY(I)>255 THEN GOSUB 6100:RETURN
5120 IF BY(I)<0 OR BY(I)>255 THEN BA(I)=0:RETURN
```

**Why essential**: POKE expects 0-255. Negative values or values >255 cause **ILLEGAL QUANTITY ERROR** crash. AI patterns (sine wave, tracking) can generate out-of-range coordinates. **Check before every POKE**.

This is **defensive programming**—assume edge cases will happen, prevent crashes before they occur.

### Player Respawn

After taking damage, reset player to safe position:

```basic
8070 REM RESET PLAYER POSITION
8080 PX=160:PY=200
8090 POKE 53248,PX AND 255:POKE 53249,PY
8100 POKE 53264,0
```

Centre screen (160,200), clear MSB. Gives player moment to recover while screen flashes.

## Professional Game Structure

This pattern scales to larger games:

```basic
' Top level: state machine
ON STATE GOSUB TITLE,PLAY,GAMEOVER,HIGHSCORE

' Each state: focused responsibility
TITLE:   Handle input, display instructions, transition to PLAY
PLAY:    Game loop—update, collisions, check win/lose conditions
GAMEOVER: Display results, wait for restart
```

**Benefits**:
- **Clear flow**—easy to see game structure
- **Isolated code**—title screen bugs don't affect gameplay
- **Easy extensions**—add pause state, shop state, level select

**State machines** appear everywhere in game development. You've just implemented your first one.

## Boundary Check Patterns

Three defensive techniques used here:

**1. Check before POKE (crash prevention)**
```basic
IF BY<0 OR BY>255 THEN DESPAWN:RETURN
POKE 53249,BY
```

**2. Clamp to valid range (keep on screen)**
```basic
IF EX<24 THEN EX=24
IF EX>320 THEN EX=320
```

**3. Despawn at boundaries (gameplay rule)**
```basic
IF BY<50 THEN DESPAWN:RETURN  ' Bullet off-screen
IF EY>229 THEN DESPAWN:LOSE LIFE:RETURN  ' Enemy escaped
```

**Choose the right technique** for each situation. Crashes need prevention. Sprites need clamping. Gameplay needs despawning.

## Quick Reference

### Game State Machine

```basic
' Setup
GS=0                           ' Initialize state

' Main loop
ON GS+1 GOSUB STATE0,STATE1,STATE2
GOTO (main loop line)

' State handlers
STATE0: ... :GS=1:RETURN       ' Transition to state 1
STATE1: ... :IF COND THEN GS=2:RETURN
STATE2: ... :GS=0:RETURN
```

### Lives System

```basic
' Initialize
LI=3                           ' Starting lives

' Lose life
LI=LI-1                        ' Decrement
IF LI=0 THEN GS=GAMEOVER       ' Check game over

' Display
PRINT "LIVES: ";LI
```

### HUD Updates

```basic
POKE 214,ROW:PRINT             ' Position cursor
PRINT "TEXT";VAR;"MORE"        ' Update display
```

**Common rows**: 0=top, 12=middle, 24=bottom

### Boundary Checking

```basic
' Before POKE (crash prevention)
IF Y<0 OR Y>255 THEN DESPAWN:RETURN
POKE REG,Y

' Range clamping (keep valid)
IF X<MIN THEN X=MIN
IF X>MAX THEN X=MAX

' Gameplay boundaries
IF Y<TOP OR Y>BOTTOM THEN ACTION:RETURN
```

### Screen Effects

```basic
' Flash border
FOR F=1 TO TIMES
  POKE 53280,COLOUR1:FOR D=1 TO DELAY:NEXT D
  POKE 53280,COLOUR2:FOR D=1 TO DELAY:NEXT D
NEXT F

' Flash background
POKE 53281,COLOUR:FOR D=1 TO DELAY:NEXT D
POKE 53281,ORIGINAL
```
