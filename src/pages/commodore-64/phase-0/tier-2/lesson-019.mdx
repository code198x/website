The VIC-II chip automatically detects when sprites collide. No manual coordinate checking needed—the hardware does it during screen refresh. This lesson reveals how to read collision registers, test which sprites collided, and build responsive collision systems.

Previous lessons moved sprites with keyboard and joystick. Now discover how the C64 knows when sprites touch.

## The One-Minute Tour

- **Hardware collision detection**—VIC-II detects sprite overlaps automatically
- **Collision registers**—53278 (sprite-sprite), 53279 (sprite-background)
- **Bit mapping**—Each bit represents one sprite (bit 0 = sprite 0 collided)
- **Sticky registers**—Collision bits stay set until you clear them
- **Clearing pattern**—Read collision, test bits, respond, then POKE any value to clear
- **Collision response**—Score points, disable sprites, move objects, trigger sounds
- **No coordinate maths**—Hardware does pixel-perfect detection at 60Hz

## How This Works

### The Collision Register

The VIC-II has two collision detection registers:

- **$D01E (53278)**—Sprite-sprite collision
- **$D01F (53279)**—Sprite-background collision

Each register is one byte with eight bits, one per sprite:

```
Bit 7: Sprite 7 collided
Bit 6: Sprite 6 collided
...
Bit 1: Sprite 1 collided
Bit 0: Sprite 0 collided
```

**Reading the register:**
```basic
260 C=PEEK(53278):REM READ SPRITE-SPRITE COLLISION
270 IF C=0 THEN 300:REM NO COLLISION, SKIP
```

If C=0, no sprites collided this frame. If C>0, at least one sprite collided.

### Testing Specific Sprites

Use AND to test which sprite(s) collided:

```basic
C=PEEK(53278)
IF (C AND 1)>0 THEN [SPRITE 0 COLLIDED]
IF (C AND 2)>0 THEN [SPRITE 1 COLLIDED]
IF (C AND 4)>0 THEN [SPRITE 2 COLLIDED]
IF (C AND 8)>0 THEN [SPRITE 3 COLLIDED]
```

**Why AND?** Bit 0 has value 1, bit 1 has value 2, bit 2 has value 4, bit 3 has value 8, etc. AND extracts individual bits.

### The Sticky Register Problem

**Critical:** Collision registers are "sticky"—once set, they stay set until cleared.

```basic
290 POKE 53278,0:REM CLEAR COLLISION REGISTER
```

Write ANY value to clear. The VIC-II doesn't care what value—the write operation clears it.

**Pattern:**
1. Read collision register
2. Test which sprites collided
3. Respond to collision
4. Clear register by writing to it
5. Repeat next frame

## The Collision Pattern

Every collision system follows this structure:

```basic
1000 REM COLLISION CHECK ROUTINE
1010 C=PEEK(53278):IF C=0 THEN RETURN
1020 IF (C AND 1)>0 THEN GOSUB 2000:REM PLAYER HIT
1030 IF (C AND 2)>0 THEN GOSUB 3000:REM BULLET HIT
1040 POKE 53278,0:REM CLEAR REGISTER
1050 RETURN
```

**The pattern:**
1. Read collision register into variable
2. Quick exit if zero (no collisions)
3. Test each sprite bit that matters
4. Call appropriate response subroutines
5. Clear register last (after all tests)

## Multiple Collision Detection

When sprite 0 hits sprite 3:
- Bit 0 is set (sprite 0 collided)
- Bit 3 is set (sprite 3 collided)
- Value = 1 + 8 = 9

**Both sprites** appear in the collision register. You know they touched, but not necessarily with each other. If you have many sprites, you might need additional logic to determine collision pairs.

**Simple case (few sprites):**
```basic
C=PEEK(53278)
IF C=9 THEN [SPRITES 0 AND 3 DEFINITELY COLLIDED]
```

**Complex case (many sprites):**
Test each sprite individually and use game logic to determine what matters.

## Sprite-Background Collision

The second collision register detects sprites hitting screen characters:

```basic
100 B=PEEK(53279):REM SPRITE-BACKGROUND
110 IF (B AND 1)>0 THEN [SPRITE 0 HIT WALL/CHARACTER]
120 POKE 53279,0:REM CLEAR
```

**Uses:**
- Walls and obstacles in mazes
- Platform detection in jumping games
- Collectible items drawn as characters
- Any solid object made from screen characters

**Background** = any non-zero screen code. Spaces (screen code 0) don't trigger collisions.

Prevent multiple hits:

```basic
10 IV=0:REM INVINCIBILITY FRAMES

```

## From the Vault

**Why automatic collision detection?**

Early home computers required manual coordinate checking:

```basic
REM Manual collision (other computers)
IF ABS(X1-X2)<16 AND ABS(Y1-Y2)<16 THEN [COLLISION]
```

This consumed CPU cycles every frame. The C64's VIC-II does pixel-perfect collision detection in hardware at 60Hz with zero CPU cost. Games can check collisions without sacrificing performance.

**The sticky register design** forces programmers to acknowledge collisions. If the register auto-cleared, you might miss collisions between PEEK calls. Sticky registers guarantee detection.
