You've learnt smooth movement, momentum, rotation, thrust, and asteroid management. Now synthesise everything into a complete game: **Asteroid Field**. This is where physics-based gameplay emerges—skill comes from mastering momentum, not reflexes. You'll discover that 7 sprites run smoother than 8, revealing BASIC's true bottleneck.

**This synthesis lesson demonstrates complete game structure:** title screen, game loop, collision detection, wave progression, sound effects, and game over flow. Every system working together creates something greater than the sum of its parts.

## The One-Minute Tour

- **Three game states** manage flow: title screen (ST=0), playing (ST=1), game over (ST=2) switched with ON-GOSUB
- **Ship uses momentum control** with rotation (LEFT/RIGHT), thrust (FIRE+direction), and separate shooting (FIRE alone)
- **Seven sprites total** allocate as ship (sprite 0 with 8 rotation frames), asteroids (sprites 1-3), bullets (sprites 4-7)
- **Physics runs at 20-25 fps** with fewer sprites than Space Defender's 8, proving sprite count matters more than maths
- **Collision detection uses hardware** reading VIC-II register $D01E (53278) for bullet-asteroid and ship-asteroid hits
- **Wave system increases difficulty** spawning 3 asteroids per wave with speed multiplier (1 + WAVE * 0.2)
- **Screen wrapping creates infinite space** with ship and asteroids exiting edges reappearing opposite side
- **Sound effects add polish** using SID for laser fire, explosions, and impact with frequency sweeps

**Playing State (State 1) - Ship Control:**

```basic
2000 REM PLAYING STATE
2010 GOSUB 2100:REM SHIP CONTROL
2020 GOSUB 2500:REM UPDATE BULLETS
2030 GOSUB 3100:REM UPDATE ASTEROIDS AND SHIP
2040 GOSUB 4000:REM COLLISIONS
2050 GOSUB 6000:REM UPDATE SPRITES
2060 GOSUB 7000:REM UPDATE HUD
2070 IF LI=0 THEN ST=2
2080 C=0:FOR I=1 TO 3:IF AA(I)=1 THEN C=C+1
2090 NEXT:IF C=0 THEN GOSUB 5000
2095 RETURN
2100 REM SHIP CONTROL
2110 J=PEEK(56320)
2120 REM ROTATION
2130 IF (J AND 4)=0 THEN SAN=SAN-0.1
2140 IF (J AND 8)=0 THEN SAN=SAN+0.1
2150 IF SAN<0 THEN SAN=SAN+6.28
2160 IF SAN>=6.28 THEN SAN=SAN-6.28
2170 REM CHECK FIRE BUTTON FOR THRUST OR SHOOT
2180 IF (J AND 16)=0 THEN GOSUB 2200
2190 RETURN
2200 REM FIRE BUTTON PRESSED
2210 REM IF JOYSTICK CENTERED, SHOOT
2220 IF (J AND 4)>0 AND (J AND 8)>0 THEN GOSUB 2300:RETURN
2230 REM OTHERWISE APPLY THRUST
2240 SVX=SVX+0.08*COS(SAN)
2250 SVY=SVY+0.08*SIN(SAN)
2260 REM CLAMP VELOCITY
2270 V=SQR(SVX*SVX+SVY*SVY)
2280 IF V>3 THEN SVX=SVX*3/V:SVY=SVY*3/V
2290 RETURN
```

The ship rotates with LEFT/RIGHT, applies thrust with FIRE+direction, and shoots with FIRE alone. This dual-use control scheme (introduced in Lesson 30) fits perfectly on a single-button joystick.

**Bullet System:**

```basic
2300 REM FIRE BULLET
2310 FOR I=1 TO 4
2320 IF BA(I)=0 THEN GOSUB 2400:RETURN
2330 NEXT
2340 RETURN
2400 REM CREATE BULLET I
2410 BX(I)=SX:BY(I)=SY:BA(I)=1
2420 BS=5:REM BULLET SPEED
2430 BVX(I)=SVX+BS*COS(SAN)
2440 BVY(I)=SVY+BS*SIN(SAN)
2450 REM SOUND EFFECT: LASER
2460 V=54279:POKE V+4,33
2470 FOR F=100 TO 20 STEP -5:POKE V,F:FOR J=1 TO 2:NEXT J:NEXT F
2480 POKE V+4,0
2490 RETURN
2500 REM UPDATE BULLETS
2510 FOR I=1 TO 4
2520 IF BA(I)=0 THEN 2580
2530 BX(I)=BX(I)+BVX(I)
2540 BY(I)=BY(I)+BVY(I)
2550 REM DESPAWN IF OFF-SCREEN
2560 IF BX(I)<0 OR BX(I)>255 OR BY(I)<50 OR BY(I)>229 THEN BA(I)=0
2580 NEXT I
2590 RETURN
```

Bullets inherit ship velocity (BVX = SVX + bullet speed), creating realistic physics where shooting while moving forward makes bullets travel faster.

**Physics Update Loop:**

```basic
3100 REM UPDATE ASTEROIDS AND SHIP
3110 FOR I=1 TO 3
3120 IF AA(I)=0 THEN 3200
3130 AX(I)=AX(I)+AVX(I)
3140 AY(I)=AY(I)+AVY(I)
3150 REM SCREEN WRAP
3160 IF AX(I)<0 THEN AX(I)=AX(I)+255
3170 IF AX(I)>255 THEN AX(I)=AX(I)-255
3180 IF AY(I)<50 THEN AY(I)=AY(I)+179
3190 IF AY(I)>229 THEN AY(I)=AY(I)-179
3200 NEXT I
3210 REM APPLY FRICTION TO SHIP
3220 SVX=SVX*0.99:SVY=SVY*0.99
3230 IF ABS(SVX)<0.05 THEN SVX=0
3240 IF ABS(SVY)<0.05 THEN SVY=0
3250 REM UPDATE SHIP POSITION
3260 SX=SX+SVX:SY=SY+SVY
3270 IF SX<0 THEN SX=SX+255
3280 IF SX>255 THEN SX=SX-255
3290 IF SY<50 THEN SY=SY+179
3300 IF SY>229 THEN SY=SY-179
3310 RETURN
```

Friction (multiply by 0.99) slows ship gradually, preventing endless drift. Asteroids have no friction—they maintain momentum forever, creating constant challenge.

**Collision Detection:**

```basic
4000 REM COLLISION DETECTION
4010 C=PEEK(53278):IF C=0 THEN RETURN
4020 REM BULLET VS ASTEROID
4030 FOR B=1 TO 4:IF BA(B)=0 THEN 4120
4040 SB=2^(B+3)
4050 IF (C AND SB)=0 THEN 4120
4060 FOR A=1 TO 3:IF AA(A)=0 THEN 4110
4070 SA=2^A
4080 IF (C AND SA)>0 THEN GOSUB 4500
4110 NEXT A
4120 NEXT B
4130 REM SHIP VS ASTEROID
4140 IF (C AND 1)>0 THEN GOSUB 4700
4150 POKE 53278,0:REM CLEAR COLLISIONS
4160 RETURN
4500 REM ASTEROID A HIT BY BULLET B
4510 SZ=AS(A):AA(A)=0:BA(B)=0
4520 SC=SC+(4-SZ)*50
4530 REM SOUND: EXPLOSION
4540 V=54286:POKE V+4,129
4550 FOR N=200 TO 50 STEP -10:POKE V,N:FOR J=1 TO 3:NEXT J:NEXT N
4560 POKE V+4,0
4570 RETURN
4700 REM SHIP HIT
4710 LI=LI-1
4720 REM SOUND: IMPACT
4730 V=54286:POKE V,20:POKE V+4,17
4740 FOR N=1 TO 20:NEXT N:POKE V+4,0
4750 REM RESPAWN SHIP AT CENTER
4760 SX=160:SY=140:SVX=0:SVY=0
4770 FOR N=1 TO 500:NEXT:REM BRIEF PAUSE
4780 RETURN
```

The collision register $D01E (53278) has 8 bits, one per sprite. Bit 0 = sprite 0 (ship), bits 1-3 = asteroids, bits 4-7 = bullets. Checking which bits are set identifies exact collision pairs.

**Wave System:**

```basic
5000 REM SPAWN WAVE
5010 PRINT CHR$(19);"WAVE ";WV;CHR$(146)
5020 FOR I=1 TO 3
5030 AX(I)=RND(1)*200+27
5040 AY(I)=RND(1)*150+50
5050 SP=1+WV*0.2
5060 AVX(I)=(RND(1)-0.5)*SP
5070 AVY(I)=(RND(1)-0.5)*SP
5080 AS(I)=3:AA(I)=1:REM LARGE
5090 NEXT I
5100 WV=WV+1
5110 FOR N=1 TO 1000:NEXT:REM PAUSE
5120 RETURN
```

Each wave increases speed by 20% (wave 1: speed 1.0, wave 2: speed 1.2, wave 3: speed 1.4). Random starting positions (RND(1)*200+27) keep asteroids within playfield boundaries with edge padding.

**Sprite Update System:**

```basic
6000 REM UPDATE SPRITES
6010 REM SHIP (SPRITE 0)
6020 POKE 53248,INT(SX):POKE 53249,INT(SY)
6030 F=INT((SAN/6.28)*8+0.5)
6040 IF F>=8 THEN F=0
6050 POKE 2040,13+F:REM ROTATION FRAME
6060 REM ASTEROIDS (SPRITES 1-3)
6070 FOR I=1 TO 3
6080 IF AA(I)=0 THEN GOSUB 6200
6090 IF AA(I)=1 THEN GOSUB 6300
6100 NEXT I
6110 REM BULLETS (SPRITES 4-7)
6120 FOR I=1 TO 4
6130 IF BA(I)=0 THEN GOSUB 6400
6140 IF BA(I)=1 THEN GOSUB 6500
6150 NEXT I
6160 RETURN
6200 REM DISABLE ASTEROID SPRITE I
6210 E=PEEK(53269)
6220 POKE 53269,E AND (255-(2^I))
6230 RETURN
6300 REM UPDATE ASTEROID SPRITE I
6310 POKE 53248+(I*2),INT(AX(I))
6320 POKE 53249+(I*2),INT(AY(I))
6330 POKE 2040+I,21+(AS(I)-1)
6340 E=PEEK(53269)
6350 POKE 53269,E OR (2^I)
6360 RETURN
```

Ship rotation uses 8 sprite frames (pointers 13-20) selected by angle (SAN/6.28 * 8). Asteroids use 3 sprite pointers (21-23) based on size. Bullets all use pointer 24.

## Understanding the Control Scheme

The fire button has dual purpose:
- **FIRE + direction = thrust** applies force in facing direction
- **FIRE alone = shoot** fires bullet forward

This works because checking `(J AND 4)>0 AND (J AND 8)>0` detects joystick centred (neither left nor right pressed). If centred, shoot. Otherwise, thrust.

```basic
2220 IF (J AND 4)>0 AND (J AND 8)>0 THEN GOSUB 2300:RETURN
2230 REM OTHERWISE APPLY THRUST
```

## Performance Discovery

Run this game and compare it to your Space Defender from Lesson 27. Notice anything?

**Asteroid Field runs smoother.** It achieves 20-25 frames per second compared to Space Defender's 12-15 fps, despite having physics calculations (COS, SIN, square roots).

**Why?** Sprite count matters more than maths.

- **Space Defender:** 8 sprites (ship + 7 aliens)
- **Asteroid Field:** 7 sprites (ship + 3 asteroids + 3 bullets active)

BASIC handles floating-point maths quickly—COS, SIN, and multiplication are fast. The bottleneck is sprite management: reading positions, calculating updates, poking hardware registers. With one less sprite, the update loop runs faster.

**Key lesson:** Physics calculations don't slow games—sprite count does.

## Common Challenges

**"My ship rotates too fast/slow"**

Adjust rotation speed at line 2130/2140:

```basic
2130 IF (J AND 4)=0 THEN SAN=SAN-0.1
```

Change 0.1 to 0.05 (slower) or 0.15 (faster).

**"Bullets travel too slowly"**

Increase bullet speed at line 2420:

```basic
2420 BS=5:REM BULLET SPEED
```

Try BS=7 or BS=10 for faster bullets.

**"Ship drifts too much/stops too quickly"**

Adjust friction multiplier at line 3220:

```basic
3220 SVX=SVX*0.99:SVY=SVY*0.99
```

Use 0.98 (more friction, stops faster) or 0.995 (less friction, drifts longer).

**"Waves are too hard/easy"**

Modify wave difficulty at line 5050:

```basic
5050 SP=1+WV*0.2
```

Change 0.2 to 0.1 (easier progression) or 0.3 (harder progression).

**"Collision detection misses hits"**

Sprites have 24×21 pixel rectangles. Close proximity triggers collisions even if visual overlap seems small. This is hardware limitation—VIC-II checks rectangular bounds, not pixel-perfect shapes.
