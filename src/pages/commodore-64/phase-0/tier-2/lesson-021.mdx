You've built player control, bullets, and collision detection. Now face **enemy waves**—the heart of any shooter game. Spawn enemies in progressive waves, give them AI patterns for movement, detect bullet collisions to destroy enemies, and track score. This combines everything you've learnt into a complete gameplay loop.

With enemies comes the first taste of **performance awareness**. Eight active sprites (1 player + 4 bullets + 3 enemies) updates noticeably slower than earlier examples—BASIC updates at about 12-15 frames per second with this complexity. The game remains fully playable and fun.

## The One-Minute Tour

- **Enemy management**—Array-based system like bullets: EX(), EY(), EA(), ET()
- **Wave spawning**—Progressive difficulty: wave 1 = 1 enemy, wave 2 = 2 enemies, wave 3+ = 3 enemies
- **AI patterns**—Three behaviours: straight down, sine wave, player tracking
- **Sprite allocation**—Sprite 0 = player, sprites 1-4 = bullets, sprites 5-7 = enemies
- **Collision integration**—Bullets vs enemies using $D01E (53278)
- **Scoring system**—10 points per enemy destroyed
- **Wave progression**—Speed increases with wave number
- **Performance reality**—With 8 sprites active, frame rate drops but gameplay works

## How This Works

### Enemy Sprite Allocation

**Enemies use sprites 5-7** to avoid conflicts with player (sprite 0) and bullets (sprites 1-4):

```basic
130 POKE 2045,15:REM SPRITE 5 POINTER (ENEMY 1)
170 POKE 53292,2:REM RED ENEMY COLOUR (SPRITE 5)
```

Sprite 5 registers are at $D00A-$D00B (53258-53259):
- 53258 = sprite 5 X position (low byte)
- 53259 = sprite 5 Y position
- 53292 = sprite 5 colour ($D027)

### Enemy Arrays

Like bullets, enemies use parallel arrays to track state:

```basic
280 DIM EX(1),EY(1),EA(1)
```

- **EX(1)** = enemy X position
- **EY(1)** = enemy Y position
- **EA(1)** = enemy active flag (0 = inactive, 1 = active)

### Spawning Enemies

Line 1000 creates an enemy at a random X position:

```basic
1010 EX(1)=100+INT(RND(1)*150):EY(1)=50
```

Random X between 100-250 keeps enemies visible. Y starts at 50 (top of playfield).

```basic
1030 POKE 53258,EX(1) AND 255:REM SPRITE 5 X
1040 POKE 53259,EY(1):REM SPRITE 5 Y
1060 E=PEEK(53269):POKE 53269,E OR 32
```

Enable sprite 5 by setting bit 5 in $D015 (53269). Bit 5 = 2^5 = 32.

### Enemy Movement

Line 1510 moves the enemy down each frame:

```basic
1510 EY(1)=EY(1)+1+WV:REM SPEED INCREASES WITH WAVE
```

**Speed = 1 + WV** makes enemies faster each wave:
- Wave 1: speed = 2 pixels per frame
- Wave 2: speed = 3 pixels per frame
- Wave 3: speed = 4 pixels per frame

This creates natural difficulty progression.

### Bullet-Enemy Collision

Line 1700 checks collision register $D01E (53278):

```basic
1710 C=PEEK(53278):IF C=0 THEN RETURN
1730 IF (C AND 2)=0 THEN 1800:REM BULLET NOT HIT
1740 IF (C AND 32)=0 THEN 1800:REM ENEMY NOT HIT
```

**Bit testing:**
- Bit 1 (value 2) = sprite 1 (bullet) collided with something
- Bit 5 (value 32) = sprite 5 (enemy) collided with something

If both bits set, bullet hit enemy. Line 1750 destroys both and adds 10 points to score.

### Wave Progression

Line 1900 spawns the next wave when the enemy is destroyed:

```basic
1900 REM ENEMY DESTROYED, SPAWN NEXT WAVE
1910 WV=WV+1
1920 PRINT "WAVE ";WV
1930 GOSUB 1000:REM SPAWN ENEMY
```

Each wave increments WV, which increases enemy speed. Simple but effective difficulty curve.

## Multiple Enemy Management

### Enemy Type Array

Line 280 adds ET() to store enemy type:

```basic
280 DIM EX(3),EY(3),EA(3),ET(3)
290 REM ET=ENEMY TYPE: 1=STRAIGHT, 2=SINE, 3=TRACK
```

When spawning (line 2060), assign random type 1-3:

```basic
2060 ET(I)=INT(RND(1)*3)+1:REM RANDOM PATTERN 1-3
```

### Sprite Number Mapping

**Critical formula**—enemy I uses sprite (I+4):

```basic
1620 SP=I+4:REM SPRITE NUMBER
```

This maps:
- Enemy 1 → sprite 5 (I=1, SP=5)
- Enemy 2 → sprite 6 (I=2, SP=6)
- Enemy 3 → sprite 7 (I=3, SP=7)

Sprite registers are at 53248 + (SP * 2):
- Sprite 5: 53248 + (5*2) = 53258-53259
- Sprite 6: 53248 + (6*2) = 53260-53261
- Sprite 7: 53248 + (7*2) = 53262-53263

### AI Pattern Dispatch

Line 1580 uses ON...GOSUB to call different movement routines based on enemy type:

```basic
1580 ON ET(I) GOSUB 3000,3100,3200
```

If ET(I)=1, jumps to line 3000 (straight down). If ET(I)=2, jumps to 3100 (sine wave). If ET(I)=3, jumps to 3200 (tracking).

### Pattern 1: Straight Down

```basic
3000 REM PATTERN 1: STRAIGHT DOWN
3010 EY(I)=EY(I)+1+INT(WV/2):REM SPEED INCREASES
3020 RETURN
```

Simple vertical movement. Speed = 1 + INT(WV/2) means:
- Waves 1-2: speed = 1
- Waves 3-4: speed = 2
- Waves 5-6: speed = 3

Slower progression than the simple example, but with 3 enemies it's still challenging.

### Pattern 2: Sine Wave

```basic
3100 REM PATTERN 2: SINE WAVE
3110 EY(I)=EY(I)+1+INT(WV/2)
3120 EX(I)=EX(I)+INT(SIN(EY(I)/10)*3)
3130 IF EX(I)<24 THEN EX(I)=24
3140 IF EX(I)>320 THEN EX(I)=320
3150 RETURN
```

**Sine wave motion** adds horizontal movement:
- `SIN(EY(I)/10)` oscillates between -1 and +1
- Multiply by 3 gives -3 to +3 pixels per frame
- Dividing Y by 10 slows the oscillation frequency

Lines 3130-3140 clamp X position to screen boundaries (24-320).

### Pattern 3: Player Tracking

```basic
3200 REM PATTERN 3: TRACK PLAYER
3210 EY(I)=EY(I)+1+INT(WV/2)
3220 TX=PX:REM TARGET X
3230 IF EX(I)<TX THEN EX(I)=EX(I)+1
3240 IF EX(I)>TX THEN EX(I)=EX(I)-1
3250 RETURN
```

**Simple AI**—move toward player's X position:
- If enemy left of player, move right (+1)
- If enemy right of player, move left (-1)
- Movement is 1 pixel per frame (slower than player's 2 pixels)

This creates enemies that "hunt" the player, making dodging more difficult.

## Collision Detection with Multiple Sprites

Line 1700 checks all bullet-enemy combinations:

```basic
1710 C=PEEK(53278):IF C=0 THEN RETURN
1720 REM CHECK EACH BULLET VS EACH ENEMY
1730 FOR B=1 TO 2:IF BA(B)=0 THEN 1800
1740 IF (C AND (2^B))=0 THEN 1800:REM BULLET NOT HIT
1750 FOR E=1 TO 3:IF EA(E)=0 THEN 1790
1760 IF (C AND (2^(E+4)))>0 THEN GOSUB 1850
1790 NEXT E
1800 NEXT B
```

**Nested loop** checks every active bullet against every active enemy:
1. Loop through bullets (B=1 to 2)
2. Check if bullet B collided (bit B set)
3. Loop through enemies (E=1 to 3)
4. Check if enemy E collided (bit E+4 set)
5. If both set, bullet B hit enemy E

**Bit values:**
- Bullet 1 (sprite 1): 2^1 = 2
- Bullet 2 (sprite 2): 2^2 = 4
- Enemy 1 (sprite 5): 2^5 = 32
- Enemy 2 (sprite 6): 2^6 = 64
- Enemy 3 (sprite 7): 2^7 = 128

If C contains bits 2 and 32 (C=34), bullet 1 hit enemy 1.

## Wave Spawning System

Line 2000 spawns progressive waves:

```basic
2020 NE=WV:IF NE>3 THEN NE=3:REM MAX 3 ENEMIES
2030 FOR I=1 TO NE
2040 EX(I)=50+INT(RND(1)*200):EY(I)=50
2050 EA(I)=1
2060 ET(I)=INT(RND(1)*3)+1:REM RANDOM PATTERN 1-3
2070 SP=I+4:REM SPRITE NUMBER
2080 POKE 53248+(SP*2),EX(I) AND 255
2090 POKE 53249+(SP*2),EY(I)
2100 E=PEEK(53269):POKE 53269,E OR (2^SP)
2110 NEXT I
```

**Difficulty curve:**
- Wave 1: NE=1 (one enemy)
- Wave 2: NE=2 (two enemies)
- Wave 3+: NE=3 (three enemies, maximum sprite budget)

Random X positions (50-250) and random AI patterns create variety.

Line 2120 increments wave number for next time.

### Wave Complete Detection

Line 1510 counts active enemies:

```basic
1510 AE=0:REM COUNT ACTIVE ENEMIES
1520 FOR I=1 TO 3
1530 IF EA(I)=1 THEN GOSUB 1570:AE=AE+1
1540 NEXT I
1550 IF AE=0 THEN GOSUB 2000:REM WAVE COMPLETE
```

When AE=0 (no active enemies), spawn next wave. This creates continuous gameplay—as soon as you clear a wave, the next begins.

## Performance Awareness

With 8 sprites active, you'll notice the game runs slower than earlier examples:
- **Sprite rendering**—VIC-II handles 8 sprites at full 50/60 fps without issue
- **BASIC updates**—Updating positions, checking collisions, running AI takes time
- **Frame rate**—Drops to about 12-15 frames per second with full sprite usage
- **Still playable**—Movement is smooth enough for enjoyable gameplay

**Why the slowdown?**

BASIC is interpreted—every line is parsed and executed at runtime. With this code:
- 6 joystick reads per frame (player movement)
- 2 bullet updates per frame (movement + boundary checks)
- 3 enemy updates per frame (AI + movement + boundary checks)
- Collision detection (nested loops checking all combinations)
- Score display updates (PRINT to screen)

That's 50-60 operations per frame. BASIC V2 executes about 1000-2000 operations per second, giving 12-20 fps.

**Assembly language** (Tier 3) runs 100x faster and maintains 50/60 fps with far more complexity.
