You've mastered keyboard control. Now discover **hardware joystick input**—the secret behind arcade-quality gameplay. The 6526 CIA (Complex Interface Adapter) chip reads joystick state instantly through memory-mapped registers. No waiting like `GET`. This is how real C64 games feel.

Previous lessons used `GET` for keyboard input. Joysticks connect directly to hardware registers, giving instant response and diagonal movement detection.

## The One-Minute Tour

- **CIA chip**—6526 Complex Interface Adapter handles I/O (joysticks, keyboard, timers)
- **Port 2 joystick**—Standard gaming port at address 56320 ($DC00)
- **Active-low encoding**—0 = pressed, 1 = released (hardware pull-ups)
- **Bit mapping**—Bits 0-4 encode Up/Down/Left/Right/Fire
- **Instant reading**—`PEEK(56320)` returns current joystick state
- **AND operator**—Test individual bits: `(J AND 1)=0` checks Up
- **Diagonal detection**—Test multiple bits simultaneously
- **Fire button**—Bit 4 triggers actions

## Joystick Sprite Control

```basic

30 PRINT "LOADING SPRITE DATA..."
```

## How This Works

### CIA Chip Architecture

The C64 has **two CIA chips**:

- **CIA #1 ($DC00-$DC0F)**—Keyboard, joysticks, timers, IRQ interrupts
- **CIA #2 ($DD00-$DD0F)**—Serial bus, VIC bank switching, RS-232, NMI interrupts

**Games use CIA #1** for joystick reading. Port A ($DC00/56320) reads joystick port 2.

### Joystick Bit Encoding

One byte contains the entire joystick state:

```
Bit 7: Not used
Bit 6: Not used
Bit 5: Not used
Bit 4: FIRE button (0=pressed)
Bit 3: RIGHT       (0=pressed)
Bit 2: LEFT        (0=pressed)
Bit 1: DOWN        (0=pressed)
Bit 0: UP          (0=pressed)
```

**Active-low logic**: Pressed = 0, Released = 1. Hardware uses pull-up resistors.

**Value 127** ($7F, binary 01111111) = nothing pressed (all direction bits = 1).

### Reading Joystick State

```basic
170 J=PEEK(56320):REM READ JOYSTICK PORT 2
```

This reads **one byte** containing all directions + fire button.

### Testing Individual Bits

The `AND` operator tests specific bits:

```basic
180 IF (J AND 1)=0 THEN Y=Y-2:REM UP
```

**How this works**:
- `J AND 1` masks bit 0 (Up direction)
- If bit 0 = 0, joystick is pushed up
- Move sprite up by subtracting from Y

**Pattern for all directions**:
- `J AND 1` = Up (bit 0)
- `J AND 2` = Down (bit 1)
- `J AND 4` = Left (bit 2)
- `J AND 8` = Right (bit 3)
- `J AND 16` = Fire (bit 4)

### Why Active-Low?

Hardware design uses **pull-up resistors**. When joystick switch closes, it grounds the line (pulls to 0). When released, resistor pulls line high (1).

This is why **0 = pressed** seems backwards—it's the hardware, not a programming choice.

## Experimenting

Try holding the joystick diagonally. The sprite moves both directions simultaneously because **multiple bits** can be 0 at once.

**Diagonal up-left**: Bits 0 and 2 both = 0, so both `IF` statements execute.

## Common Joystick Values

Understanding the byte values helps with debugging:

| Value | Binary | Meaning |
|-------|--------|---------|
| 127 | 01111111 | Nothing pressed |
| 126 | 01111110 | Up |
| 125 | 01111101 | Down |
| 123 | 01111011 | Left |
| 119 | 01110111 | Right |
| 111 | 01101111 | Fire |
| 122 | 01111010 | Up + Left (diagonal) |
| 118 | 01110110 | Up + Right (diagonal) |
| 121 | 01111001 | Down + Left (diagonal) |
| 117 | 01110101 | Down + Right (diagonal) |
| 110 | 01101110 | Fire + Up |

**Try printing** `J` to see these values: `PRINT J;`

## Hardware Details

### CIA Register Map

**CIA #1 Port A** ($DC00 / 56320):
- **Read mode**: Returns joystick port 2 state
- **Also used**: Keyboard row scanning (bit 5-7)
- **Shared**: Keyboard and joystick share this register

**CIA #1 Port B** ($DC01 / 56321):
- **Read mode**: Returns joystick port 1 state
- **Also used**: Keyboard column scanning

### Two-Player Games

For two players, read both ports:

```basic
100 J1=PEEK(56321):REM JOYSTICK PORT 1
110 J2=PEEK(56320):REM JOYSTICK PORT 2
```

**Most single-player games** use port 2 by convention. Port 1 often conflicts with keyboard scanning in some games.

### Why PEEK Instead of GET?

`GET` waits for keyboard buffer and returns PETSCII codes. Joysticks need **instant hardware reading** every frame.

**Keyboard (GET)**: Slow, buffered, text-oriented
**Joystick (PEEK)**: Instant, unbuffered, hardware-direct

This is why joystick control feels **arcade-quality**.

## Game Integration

### Reading Every Frame

Games read joystick every frame (50 or 60 times per second):

```basic
100 REM GAME LOOP
110 J=PEEK(56320):REM READ JOYSTICK
120 IF (J AND 1)=0 THEN GOSUB 2000:REM MOVE UP
130 IF (J AND 16)=0 THEN GOSUB 3000:REM FIRE
140 GOTO 100
```


## From the Vault

**Why "Port 2" for single player?**—C64 keyboard matrix shares CIA #1 Port B with joystick port 1. Some games scan keyboard continuously, causing port 1 glitches. Port 2 (Port A) has fewer conflicts, becoming the standard.

**Competition Pro joysticks**—Most popular C64 joystick. Digital switches, precise control, indestructible. Launched 1984, still manufactured.

**"Waggler" games**—Some games (Summer Games, Decathlon) required rapid left-right joystick movement. Destroyed many joysticks. Speedball 2 perfected this mechanic.
