## From Variables to Visible Scores

You've been storing scores in variables throughout previous lessons. But players need to see their progress. This lesson teaches direct screen memory manipulation to display numeric values—bypassing PRINT's slowness and limitations. You'll learn digit extraction mathematics and screen code conversion, techniques that form the foundation of every game's score display system.

---

###  The One-Minute Tour

- Screen memory at 1024+ displays directly without PRINT overhead
- Screen codes 48-57 represent digits '0'-'9' (add 48 to numeric values 0-9)
- Extract rightmost digit: `value - INT(value/10)*10` gives ones place
- Remove rightmost digit: `INT(value/10)` shifts remaining digits right
- Display position: 1024+offset for screen location, 55296+offset for colour
- Zero-padding: Display all digits including leading zeros for fixed-width scores
- Subroutine pattern: GOSUB for reusable display update code
- Mathematical extraction faster and more flexible than string manipulation
- Same technique works for any numeric display: lives, time, high scores
- Screen code conversion critical: POKEing raw values 0-9 displays letters @,A-I

### Example Programme

```basic
10 REM SCORE DISPLAY AT TOP OF SCREEN
20 PRINT CHR$(147):POKE 53280,0:POKE 53281,0
30 SC=0
40 REM DRAW SCORE LABEL
50 FOR I=0 TO 4:READ D:POKE 1024+I,D:POKE 55296+I,1:NEXT
60 DATA 19,3,15,18,5
70 REM GAME LOOP
80 SC=SC+1
90 GOSUB 200
100 FOR I=1 TO 30:NEXT I
110 IF SC<999 THEN 80
120 END
200 REM DISPLAY SCORE SUBROUTINE
210 S=SC
220 FOR I=2 TO 0 STEP -1
230 POKE 1024+6+I,48+(S-INT(S/10)*10)
240 S=INT(S/10)
250 NEXT
260 RETURN
```

**Line 20** clears screen and sets border/background colours. **Line 50** draws "SCORE" label using screen codes from DATA statement; note screen codes differ from character codes. **Line 80** increments score each frame. **Line 90** calls display subroutine—separation of scoring logic from display update. **Line 210** copies score to working variable S preserving original. **Lines 220-250** extract and display three digits right-to-left; each iteration displays one digit then removes it from S. **Line 230** extracts rightmost digit with modulo mathematics, adds 48 for screen code conversion, POKEs to screen position 1024+6+offset.

<img src="/images/commodore-64/phase-0/tier-2/lesson-029/example-1.png" alt="Simple 3-digit score counter" />

The mathematical extraction `S-INT(S/10)*10` implements modulo 10 operation. For S=230: INT(230/10)=23, 23*10=230, 230-230=0 (ones digit). The loop processes right-to-left because each `INT(S/10)` removes the rightmost digit we just displayed.

### Experiment: Zero-Padded Score with Sprite

Extend the score display to five digits with zero-padding and combine with sprite movement:

```basic
10 REM ZERO-PADDED SCORE WITH SPRITE
15 REM SPRITE DATA
16 DATA 0,24,0,0,60,0,0,126,0
17 DATA 0,255,0,1,255,128,3,255,192
18 DATA 7,255,224,15,255,240,31,255,248
19 DATA 3,255,192,3,255,192,3,255,192
20 DATA 3,255,192,3,255,192,3,255,192
21 DATA 1,255,128,0,255,0,0,126,0
22 DATA 0,60,0,0,24,0,0,0,0
25 REM SCORE LABEL DATA
26 DATA 19,3,15,18,5
30 REM LOAD SPRITE DATA
31 FOR I=0 TO 62
32 READ B:POKE 832+I,B
33 NEXT
60 REM SETUP SPRITE 0
70 POKE 2040,13:POKE 53269,1:POKE 53287,14
80 X=160:Y=120:SC=0
90 REM SETUP SCREEN
100 PRINT CHR$(147):POKE 53280,0:POKE 53281,0
110 REM DRAW SCORE LABEL
120 FOR I=0 TO 4:READ D:POKE 1024+I,D:POKE 55296+I,7:NEXT
140 REM MAIN LOOP
150 J=PEEK(56320) AND 31:DX=0:DY=0
160 IF (J AND 1)=0 THEN DY=-2
170 IF (J AND 2)=0 THEN DY=2
180 IF (J AND 4)=0 THEN DX=-2
190 IF (J AND 8)=0 THEN DX=2
200 REM UPDATE POSITION
210 X=X+DX:Y=Y+DY
220 IF X<24 THEN X=24
230 IF X>320 THEN X=320
240 IF Y<50 THEN Y=50
250 IF Y>229 THEN Y=229
260 REM UPDATE SPRITE
270 POKE 53248,X:POKE 53249,Y
280 IF X>255 THEN POKE 53264,1 ELSE POKE 53264,0
290 REM INCREASE SCORE
300 SC=SC+1:IF SC>99999 THEN SC=0
310 GOSUB 420
320 FOR D=1 TO 2:NEXT D
330 GOTO 150
420 REM DISPLAY SCORE SUBROUTINE
430 S=SC
440 FOR I=4 TO 0 STEP -1
450 POKE 1024+6+I,48+(S-INT(S/10)*10)
460 S=INT(S/10)
470 NEXT
480 RETURN
```

**Lines 16-26** contain DATA statements—critical ordering: sprite data first (63 bytes), then label data (5 bytes), because READ consumes DATA sequentially from program start. **Lines 31-33** load sprite shape into memory at location 832. **Line 120** draws "SCORE" label; DATA uses screen codes not character codes (S=19, C=3, O=15, R=18, E=5). **Line 300** increments score with wraparound at 99999. **Lines 440-470** display five digits with zero-padding—displays "00354" not "354". **Line 450** adds 48 to convert numeric digit (0-9) to screen code (48-57); without this you'd see letters @,A-I instead of digits.

<img src="/images/commodore-64/phase-0/tier-2/lesson-029/example-2.png" alt="Zero-padded 5-digit score with sprite movement" />

The DATA ordering matters because C64 BASIC's READ statement consumes DATA sequentially regardless of where DATA appears in your programme. Lines 31-33 READ 63 bytes for sprite, then line 120 READs 5 bytes for label. If label DATA appeared before sprite DATA, the sprite READ would consume label values first, corrupting both sprite and label.

### Hardware Details

**Screen Memory Structure:**
- Screen memory starts at 1024 (decimal), $0400 (hex)
- 40 columns × 25 rows = 1000 bytes total
- Position calculation: row*40 + column
- Top-left corner = 1024, top-right = 1024+39
- Second row starts at 1024+40

**Colour Memory Structure:**
- Colour memory starts at 55296 (decimal), $D800 (hex)
- Same layout as screen memory: 40×25 grid
- Each byte sets foreground colour for corresponding screen position
- Lower 4 bits = colour code (0-15)
- Upper 4 bits ignored by hardware

**Screen Codes vs Character Codes:**
- PRINT/CHR$ use PETSCII character codes
- POKE to screen memory uses screen codes
- Digits '0'-'9': PETSCII=48-57, Screen codes=48-57 (same!)
- Letters A-Z: PETSCII=65-90, Screen codes=1-26 (different!)
- Always add 48 when displaying extracted numeric digits

**Mathematical Digit Extraction:**
- Rightmost digit (ones): `value - INT(value/10)*10`
- Remove rightmost digit: `INT(value/10)`
- Example for 4,567: ones=7, INT(4567/10)=456, tens=6, etc.
- This is modulo division: equivalent to `value MOD 10` in other BASICs
- C64 BASIC V2 has no MOD operator, use mathematical equivalent

### How Games Use This

**Space Invaders:** Score displays at top using identical technique—extract digits, convert to screen codes, POKE to fixed positions. Updates after each alien destroyed.

**Pac-Man:** Current score, high score, and lives remaining all use direct screen memory POKEs for instant display without PRINT overhead. Zero-padding creates consistent visual appearance.

**Boulder Dash:** Score, diamonds collected, and time remaining displayed using screen memory writes. Countdown timer uses same digit extraction, counting down instead of up.

**Impossible Mission:** Timer display counts down using this technique—extract minutes and seconds digits, convert to screen codes. Updates every frame without screen flicker.

### Quick Reference

**Display Addresses:**
```
Screen memory: 1024-2023
Colour memory: 55296-56295
Position = 1024 + (row*40) + column
Colour   = 55296 + (row*40) + column
```

**Digit Extraction:**
```basic
REM Get rightmost digit
D = S - INT(S/10)*10

REM Remove rightmost digit
S = INT(S/10)
```

**Screen Codes:**
```
Digits '0'-'9': 48-57
Letters A-Z:    1-26
Letters a-z:    65-90
Space:          32
```

**Score Display Pattern:**
```basic
REM Display N-digit score
S=SC
FOR I=N-1 TO 0 STEP -1
  POKE 1024+OFFSET+I,48+(S-INT(S/10)*10)
  S=INT(S/10)
NEXT
```

- Zero-padding achieved by displaying all digit positions
- Subroutine pattern separates scoring logic from display updates
