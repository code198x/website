You've mastered velocity-based movement where joystick controls velocity directly. Now discover momentum—the physics principle where objects in motion stay in motion. When you release the joystick, your sprite continues drifting in the last direction. Add acceleration (velocity builds gradually) and friction (velocity decays over time) to create realistic physics that feels like ice skating or space flight.

**Momentum transforms arcade control into physics simulation.** The difference is what happens when you let go.

## The One-Minute Tour

- **Momentum means velocity persists** even when joystick is released—sprite drifts instead of stopping instantly
- **Acceleration builds velocity gradually** using joystick to add small increments (VY=VY-0.15) rather than set velocity directly
- **Friction decays velocity over time** by multiplying by 0.90-0.99 each frame, eventually bringing sprite to rest
- **Maximum velocity prevents runaway acceleration** clamping VX and VY to reasonable limits (typically ±3 pixels/frame)
- **Stop threshold prevents endless drift** setting velocity to zero when it drops below 0.05 pixels/frame
- **Physics parameters define feel** with different combinations creating tank-like, car-like, or spaceship-like control
- **Boundary collision stops velocity** zeroing VX/VY when hitting screen edges to prevent bounce or drift-through

## Arcade vs Physics Control

**The old way** (instant arcade response):
```basic
1000 J=PEEK(56320):VX=0:VY=0
1010 IF (J AND 1)=0 THEN VY=-2
```
Joystick pressed → velocity set to -2 instantly.
Joystick released → velocity resets to 0 immediately.
Result: Direct, predictable, easy control.

**The new way** (momentum physics):
```basic
1000 J=PEEK(56320)
1010 IF (J AND 1)=0 THEN VY=VY-0.15
2000 VY=VY*0.97
```
Joystick pressed → velocity increases by 0.15 each frame.
Joystick released → velocity decays by 3% each frame.
Result: Realistic, challenging, skill-based control.

**The critical difference:** No VX=0:VY=0 reset at the start of the loop. Velocity persists between frames, creating momentum. The joystick adds to velocity rather than replacing it.

## The Three Physics Parameters

Three values control the entire physics feel:

**AC (Acceleration):** How fast velocity builds when joystick held
- 0.05-0.1: Slow, heavy (tank, ship)
- 0.15-0.25: Medium (spaceship, car)
- 0.3-0.5: Fast, responsive (arcade racer)

**FR (Friction):** How quickly velocity decays when joystick released
- 0.90-0.93: High friction (ground vehicle, stops quickly)
- 0.95-0.97: Medium (ice, space with drag)
- 0.98-0.99: Low friction (space, nearly frictionless)
- 1.0: No friction (infinite drift—uncontrollable!)

**MX (Max Velocity):** Terminal velocity limit
- 1-2: Slow, methodical gameplay
- 3-4: Medium speed action
- 5-8: Fast arcade intensity

The example uses AC=0.15, FR=0.97, MX=3—balanced physics that feels like a spaceship with mild drag. Change these three numbers to transform the control feel completely.

## How Acceleration Works

**Line 1020: IF (J AND 1)=0 THEN VY=VY-AC**

Notice VY=VY-AC instead of VY=-AC. This is cumulative—each frame adds AC to velocity:

- Frame 1 (UP held): VY=0-0.15 → -0.15
- Frame 2 (UP held): VY=-0.15-0.15 → -0.30
- Frame 3 (UP held): VY=-0.30-0.15 → -0.45
- Frame 4 (UP held): VY=-0.45-0.15 → -0.60

Velocity builds gradually, creating smooth acceleration. Without max velocity clamping (lines 1070-1100), velocity would increase forever. The MX limit creates terminal velocity—a maximum speed no matter how long you hold the joystick.

## How Friction Works

**Line 2010: VX=VX*FR**

Multiplying by 0.97 removes 3% of velocity each frame:

- Frame 1 (released): VX=3.0*0.97 → 2.91
- Frame 2: VX=2.91*0.97 → 2.82
- Frame 3: VX=2.82*0.97 → 2.74
- Frame 10: VX≈2.23 (after 10 frames)
- Frame 20: VX≈1.66 (after 20 frames)
- Frame 50: VX≈0.65 (after 50 frames)

This exponential decay feels natural—fast deceleration initially, then slower as velocity drops. Eventually velocity becomes so small it's imperceptible (0.001 pixels/frame). Lines 2040-2050 detect this and snap to zero, preventing endless tiny drift.

## The Stop Threshold

**Line 2040: IF ABS(VX)&lt;0.05 THEN VX=0**

Without this, friction would never quite reach zero (0.01, 0.001, 0.0001...) and the sprite would drift imperceptibly forever. The 0.05 threshold says "close enough to zero—stop completely." This value is invisible to the player but prevents computational waste.

Why ABS()? Velocity can be negative (moving left/up). ABS(VX)&lt;0.05 catches both -0.03 and +0.03 as "stopped."

## Boundary Collision Behaviour

**Lines 3020-3050: Stopping at Walls**

Notice VX=0 after X=0 clamping. This zeros velocity when hitting screen edges, creating a hard stop. Without this, momentum would push against the wall indefinitely (position clamped but velocity still trying to move).

**Alternative: Bounce**
```basic
3020 IF X<0 THEN X=0:VX=-VX*0.8
```
Reverses velocity and removes 20% energy. Sprite bounces off wall with reduced momentum. The 0.8 multiplier prevents infinite bouncing (each bounce loses energy until sprite settles).

**Alternative: Wrap**
```basic
3020 IF X<0 THEN X=255
```
Sprite appears on opposite side (Asteroids-style). Velocity continues unchanged—creates seamless screen wrapping.

Choose boundary behaviour based on your game's physics world.

## Physics Feel Tuning Guide

Want specific control characteristics? Use these proven combinations:

**Tank (slow, grounded):**
- AC=0.08, FR=0.90, MX=1.5
- Deliberate acceleration, strong friction, low top speed

**Car (responsive, controllable):**
- AC=0.15, FR=0.93, MX=3.0
- Moderate acceleration, good deceleration, medium speed

**Spaceship (momentum-heavy):**
- AC=0.12, FR=0.98, MX=2.5
- Gradual acceleration, minimal friction, controlled drift

**Ice Skater (slippery):**
- AC=0.20, FR=0.99, MX=4.0
- Fast acceleration, almost no friction, high speed

**Arcade Racer (snappy but sliding):**
- AC=0.40, FR=0.85, MX=3.0
- Instant acceleration, strong friction, medium speed

Start with these presets then adjust to taste. Small changes to FR (±0.02) create noticeable feel differences.

## The Four-Subroutine Pattern

Momentum-based movement uses four distinct layers:

**GOSUB 1000: Input → Acceleration**
Joystick reading adds to velocity (VY=VY-AC) rather than setting it. Max velocity clamping happens here.

**GOSUB 2000: Friction → Deceleration**
Velocity multiplied by friction constant. Stop threshold detects near-zero velocity.

**GOSUB 3000: Velocity → Position**
Position accumulates velocity. Boundary collision zeros velocity at walls.

**GOSUB 4000: Position → Hardware**
Float positions convert to integers for sprite registers.

Each layer has one responsibility. To change physics feel, modify friction (GOSUB 2000). To add gravity, update GOSUB 3000. To switch to keyboard control, replace GOSUB 1000. The separation makes physics behaviour modular and adjustable.

## Common Pitfalls

**Friction too low (&gt;0.99):** Sprite takes forever to stop. Feels uncontrollable, drifts across screen with tiny joystick nudge.

**Friction too high (&lt;0.90):** Sprite stops too quickly. Loses momentum feel, plays like arcade control with slight lag.

**No max velocity:** Sprite accelerates to ridiculous speeds (10+ pixels/frame), becomes uncontrollable. Always clamp velocity.

**Forgetting velocity zero at boundaries:** Sprite pushes against wall with full momentum but can't move. Feels broken—velocity must reset.

**No stop threshold:** Sprite drifts imperceptibly forever at 0.001 pixels/frame. Wastes CPU cycles, occasionally causes unexpected collisions.

**Setting velocity instead of adding:** VY=-AC instead of VY=VY-AC destroys momentum. Sprite jumps to constant velocity rather than accelerating.

## What This Unlocks

With momentum physics in place, you can now add:

**Gravity:** VY=VY+0.1 in GOSUB 2000 (constant downward acceleration)
**Thrust button:** IF FIRE THEN AC=0.25 ELSE AC=0.15 (temporary acceleration boost)
**Directional thrust:** Next lesson—rotation-based movement for spaceship control
**Bounce physics:** VY=-VY*0.8 when hitting floor (energy-loss bouncing)
**Air resistance:** FR proportional to velocity (faster movement = more drag)
**Different friction per axis:** FRX=0.95, FRY=0.99 (slippery vertical, grippy horizontal)

All physics effects layer onto this foundation. Momentum is the engine; everything else is tuning.

## From the Vault

**Asteroids (1979):** Pure momentum physics—spaceship thrust added velocity, space had zero friction (FR=1.0). You controlled acceleration, not velocity. Mastering momentum was the core skill.

**Thrust (1986, BBC Micro):** Combined momentum with gravity and fuel management. The physics simulation was so realistic it defined the genre. Players learnt orbital mechanics through gameplay.

**Lunar Lander (1979):** Vertical momentum with gravity. Landing required bleeding off velocity gradually—too fast and you crashed. Momentum + gravity = physics puzzle.

**Elite (1984):** Space combat with momentum. Ships had mass affecting acceleration. Heavier ships accelerated slower but maintained velocity better (different AC values).

The physics pattern you've implemented powered gaming's most celebrated simulation games. You're not just moving sprites—you're creating virtual physics worlds.
