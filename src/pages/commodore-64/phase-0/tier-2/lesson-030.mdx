## Managing Failure States

Every game needs consequences. Lives systems transform abstract numbers into tangible risk—each hit matters because each heart represents survival. This lesson teaches the complete lives management cycle: tracking health, handling damage, detecting game over, and displaying visual feedback. Master these patterns and you control the tension curve of every game you create.

---

###  The One-Minute Tour

- Lives variable (LI) tracks remaining health starting at 3
- Damage subroutine decrements LI and updates display
- Game over check: `IF LI=0` triggers end state
- Screen code 83 displays heart character (♥)
- Visual display loop: POKEs hearts or spaces based on remaining lives
- Colour code 2 (red) for hearts creates visual emphasis
- Separate subroutine for lives display allows reusable updates
- Space bar triggers damage in examples (replace with collision detection)
- Game loop checks `IF LI>0` to continue or trigger game over
- Display pattern works for any icon-based counter (stars, shields, etc.)

### Example Programme

```basic
10 REM LIVES COUNTER WITH DAMAGE
20 PRINT CHR$(147):POKE 53280,0:POKE 53281,0
30 LI=3:SC=0
40 REM DRAW LIVES LABEL
50 FOR I=0 TO 4:READ D:POKE 1024+I,D:POKE 55296+I,10:NEXT
60 DATA 12,9,22,5,19
70 REM DRAW LIVES COUNTER
80 POKE 1024+6,48+LI:POKE 55296+6,10
90 REM GAME LOOP
100 GET K$:IF K$="" THEN 100
110 IF K$=" " THEN GOSUB 200
120 SC=SC+1:GOSUB 300
130 FOR I=1 TO 50:NEXT I
140 GOTO 100
200 REM TAKE DAMAGE
210 LI=LI-1
220 IF LI<0 THEN LI=0
230 POKE 1024+6,48+LI:POKE 55296+6,10
240 IF LI=0 THEN GOSUB 400
250 RETURN
300 REM DISPLAY SCORE
310 S=SC
320 FOR I=2 TO 0 STEP -1
330 POKE 1024+32+I,48+(S-INT(S/10)*10)
340 S=INT(S/10)
350 NEXT
360 RETURN
400 REM GAME OVER
410 FOR I=0 TO 8:READ D:POKE 1064+I,D:POKE 55336+I,2:NEXT
420 DATA 7,1,13,5,32,15,22,5,18
430 FOR I=1 TO 300:NEXT I
440 END
```

**Line 30** initialises lives at 3 and score at 0. **Line 50** draws "LIVES" label using screen codes from DATA (L=12, I=9, V=22, E=5, S=19). **Line 80** displays numeric lives counter converting digit with 48+ offset. **Line 110** detects spacebar press and calls damage subroutine. **Line 210** decrements lives counter. **Line 220** prevents negative values (minimum zero). **Line 230** updates screen display immediately after damage. **Line 240** triggers game over sequence when lives reach zero. **Lines 410-420** display "GAME OVER" message in red.

<img src="/images/commodore-64/phase-0/tier-2/lesson-030/example-1.png" alt="Lives counter showing game over state" />

The clamping at line 220 prevents negative lives—critical because game logic checks `LI=0` for game over. Without this, pressing space after game over would create negative values breaking the check.

### Experiment: Heart Icons with Sprite Movement

Replace numeric counter with visual hearts and combine with sprite movement:

```basic
10 REM LIVES WITH HEARTS AND SPRITE
15 REM SPRITE DATA
16 DATA 0,24,0,0,60,0,0,126,0
17 DATA 0,255,0,1,255,128,3,255,192
18 DATA 7,255,224,15,255,240,31,255,248
19 DATA 3,255,192,3,255,192,3,255,192
20 DATA 3,255,192,3,255,192,3,255,192
21 DATA 1,255,128,0,255,0,0,126,0
22 DATA 0,60,0,0,24,0,0,0,0
25 REM LIVES LABEL DATA
26 DATA 12,9,22,5,19
30 REM LOAD SPRITE DATA
31 FOR I=0 TO 62
32 READ B:POKE 832+I,B
33 NEXT
60 REM SETUP SPRITE 0
70 POKE 2040,13:POKE 53269,1:POKE 53287,14
80 X=160:Y=120:LI=3:SC=0
90 REM SETUP SCREEN
100 PRINT CHR$(147):POKE 53280,0:POKE 53281,0
110 REM DRAW LIVES LABEL
120 FOR I=0 TO 4:READ D:POKE 1024+I,D:POKE 55296+I,7:NEXT
130 GOSUB 500
140 REM MAIN LOOP
150 GET K$
160 J=PEEK(56320) AND 31:DX=0:DY=0
170 IF (J AND 1)=0 THEN DY=-2
180 IF (J AND 2)=0 THEN DY=2
190 IF (J AND 4)=0 THEN DX=-2
200 IF (J AND 8)=0 THEN DX=2
210 IF K$=" " AND LI>0 THEN GOSUB 600
220 REM UPDATE POSITION
230 X=X+DX:Y=Y+DY
240 IF X<24 THEN X=24
250 IF X>320 THEN X=320
260 IF Y<50 THEN Y=50
270 IF Y>229 THEN Y=229
280 REM UPDATE SPRITE
290 POKE 53248,X:POKE 53249,Y
300 IF X>255 THEN POKE 53264,1 ELSE POKE 53264,0
310 REM UPDATE SCORE
320 SC=SC+1:IF SC>9999 THEN SC=0
330 GOSUB 700
340 FOR D=1 TO 2:NEXT D
350 IF LI>0 THEN 150
360 GOSUB 800
370 GET K$:IF K$="" THEN 370
380 END
500 REM DRAW HEARTS
510 FOR H=0 TO 2
520 IF H<LI THEN POKE 1024+6+H,83:POKE 55296+6+H,2
530 IF H>=LI THEN POKE 1024+6+H,32:POKE 55296+6+H,0
540 NEXT
550 RETURN
600 REM TAKE DAMAGE
610 IF LI=0 THEN RETURN
620 LI=LI-1
630 GOSUB 500
640 RETURN
700 REM DISPLAY SCORE
710 S=SC
720 FOR I=3 TO 0 STEP -1
730 POKE 1024+40+I,48+(S-INT(S/10)*10)
740 S=INT(S/10)
750 NEXT
760 RETURN
800 REM GAME OVER
810 FOR I=0 TO 8:READ D:POKE 1104+I,D:POKE 55376+I,2:NEXT
820 DATA 7,1,13,5,32,15,22,5,18
830 RETURN
```

**Lines 16-26** contain DATA statements in critical order: sprite data (63 bytes) before label data (5 bytes) for sequential READ operations. **Line 130** calls heart display subroutine after drawing label. **Lines 500-550** draw hearts subroutine: loops through three positions, POKEs heart (screen code 83) in red (colour 2) if position less than remaining lives, otherwise POKEs space (32). **Line 210** checks `LI>0` before allowing damage to prevent damage after game over. **Line 350** continues main loop only while lives remain. **Line 360** calls game over subroutine when lives reach zero. **Line 610** guards against damage when already at zero lives.

The heart display pattern at lines 520-530 is reusable: change screen code 83 to any icon (shield=91, star=90, diamond=90). The loop checks each position against remaining lives, displaying icon or space accordingly.

### Hardware Details

**Screen Memory and Colour Memory:**
- Screen memory starts at 1024 (decimal), $0400 (hex)
- Colour memory starts at 55296 (decimal), $D800 (hex)
- Position calculation: 1024 + (row*40) + column
- Colour codes: 0=black, 1=white, 2=red, 5=green, 7=yellow, 14=light blue

**Screen Codes for Game Icons:**
- Heart (♥): Screen code 83, PETSCII 83
- Diamond (♦): Screen code 90, PETSCII 90
- Club (♣): Screen code 88, PETSCII 88
- Spade (♠): Screen code 65, PETSCII 65
- Filled circle (●): Screen code 81, PETSCII 81
- Space: Screen code 32, PETSCII 32

**Lives System Variables:**
- LI: Current lives remaining (typically 1-5)
- Starting value: Usually 3 (easy) or 5 (arcade difficulty)
- Minimum value: 0 (not negative to prevent logic errors)
- Maximum value: Game-dependent (9 fits single digit display)

**Display Update Timing:**
- Immediate update after damage for instant feedback
- Separate subroutine allows updates from any code location
- GOSUB pattern maintains clean code organisation
- Game loop checks lives condition each frame

### How Games Use This

**Pac-Man:** Lives displayed as small Pac-Man icons at bottom-left. Each ghost collision decrements counter, displays death animation, then checks remaining lives for game over or respawn.

**Defender:** Lives shown as tiny ship icons. Damage depletes shield first (separate counter), then loses life. Each life lost triggers respawn sequence with brief invincibility.

**Boulder Dash:** Lives counter with numeric display. Rockford dies from falling boulders, crushing walls, or time expiry. Each death decrements counter and restarts current cave.

**Impossible Mission:** Time limit acts as inverse lives system—countdown reaches zero triggers game over. Agent can fall, get shot, or run out of time, all using same death/respawn pattern.

### Quick Reference

**Screen Code Icons:**
```
Heart (♥):    83 (PETSCII 83)
Diamond (♦):  90 (PETSCII 90)
Club (♣):     88 (PETSCII 88)
Circle (●):   81 (PETSCII 81)
Space:        32 (PETSCII 32)
```

**Lives Counter Pattern:**
```basic
REM Initialise
LI=3

REM Take damage
LI=LI-1
IF LI<0 THEN LI=0
GOSUB [DISPLAY_LIVES]

REM Check game over
IF LI=0 THEN GOSUB [GAME_OVER]

REM Main loop condition
IF LI>0 THEN GOTO [MAIN_LOOP]
```

**Visual Hearts Display:**
```basic
REM Draw hearts for remaining lives
FOR H=0 TO 2
  IF H<LI THEN POKE 1024+6+H,83:POKE 55296+6+H,2
  IF H>=LI THEN POKE 1024+6+H,32
NEXT
```

**Colour Codes:**
```
0=Black   1=White     2=Red       3=Cyan
4=Purple  5=Green     6=Blue      7=Yellow
8=Orange  9=Brown    10=Lt Red   11=Dk Grey
12=Med Grey 13=Lt Green 14=Lt Blue 15=Lt Grey
```

### What You've Learnt

- Lives variable tracks player health with simple integer counter
- Damage handling decrements lives and updates display immediately
- Zero check `IF LI=0` detects game over condition reliably
- Screen code 83 displays heart character for visual feedback
- Loop-based icon display shows filled or empty positions
- Colour code 2 (red) creates emphasis for critical health information
- Separate subroutines for damage and display enable clean code structure
- Guard conditions prevent damage when lives already zero
- Same pattern applies to any icon-based counter system
- Game loop condition `IF LI>0` controls main execution flow
