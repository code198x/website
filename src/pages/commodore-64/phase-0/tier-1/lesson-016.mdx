## Dungeon Quest: Your First Complete Game

You've learnt screen control, input handling, randomness, sound effects, collision detection, scoring, and timing. Now you'll combine these skills into a complete text adventure—Dungeon Quest, a 69-line dungeon crawler with exploration, combat, treasure hunting, and win/lose conditions.

## The One-Minute Tour

- **9-room dungeon** mapped as a 3×3 grid with boundary checking
- **WASD movement** through rooms with unique descriptions
- **Random encounters** trigger with 30% probability per move
- **Three event types:** monster attacks (damage), treasure finds (progress), health potions (healing)
- **Sound effects** differentiate events: harsh noise for monsters, pleasant chime for treasure
- **Win condition:** collect 3 treasures to escape
- **Lose condition:** HP drops to zero

## The Complete Program

```basic
10 REM dungeon quest - tier 1 synthesis
20 PRINT CHR$(147):POKE 53280,0:POKE 53281,0
30 PRINT "DUNGEON QUEST":PRINT
40 PRINT "FIND 3 TREASURES TO ESCAPE!":PRINT
50 PRINT "PRESS ANY KEY TO START"
60 GET A$:IF A$="" THEN 60
70 PRINT CHR$(147)
80 X=1:Y=1:HP=10:TR=0
90 GOSUB 1000
100 GET A$:IF A$="" THEN 100
110 IF A$="W" AND Y>0 THEN Y=Y-1:GOSUB 1000
120 IF A$="S" AND Y<2 THEN Y=Y+1:GOSUB 1000
130 IF A$="A" AND X>0 THEN X=X-1:GOSUB 1000
140 IF A$="D" AND X<2 THEN X=X+1:GOSUB 1000
150 IF RND(1)<.3 THEN GOSUB 2000
160 IF HP<=0 THEN PRINT CHR$(147):PRINT "YOU DIED!":END
170 IF TR>=3 THEN PRINT CHR$(147):PRINT "YOU ESCAPED!":END
180 GOTO 100
1000 REM display room
1010 PRINT CHR$(147)
1020 PRINT "ROOM (";X;",";Y;")"
1030 PRINT "HP:";HP;" TREASURE:";TR;"/3"
1040 PRINT
1050 RM=Y*3+X
1060 IF RM=0 THEN PRINT "ENTRANCE. A DRAFT BLOWS."
1070 IF RM=1 THEN PRINT "DARK PASSAGE. WATER DRIPS."
1080 IF RM=2 THEN PRINT "ALTAR ROOM. CANDLES FLICKER."
1090 IF RM=3 THEN PRINT "ARMOURY. RUSTY WEAPONS."
1100 IF RM=4 THEN PRINT "THRONE ROOM. DUSTY SEAT."
1110 IF RM=5 THEN PRINT "TREASURY. GOLD GLINTS!"
1120 IF RM=6 THEN PRINT "DUNGEON. CHAINS RATTLE."
1130 IF RM=7 THEN PRINT "LIBRARY. OLD BOOKS."
1140 IF RM=8 THEN PRINT "EXIT. FREEDOM AWAITS!"
1150 PRINT:PRINT "WASD TO MOVE"
1160 RETURN
2000 REM random encounter
2010 EV=INT(RND(1)*3)
2020 IF EV=0 THEN GOSUB 3000
2030 IF EV=1 THEN GOSUB 4000
2040 IF EV=2 THEN GOSUB 5000
2050 RETURN
3000 REM monster attack
3010 PRINT CHR$(147):PRINT "MONSTER ATTACKS!"
3020 POKE 54296,15:POKE 54277,9:POKE 54278,0
3030 POKE 54273,50:POKE 54276,17
3040 FOR I=1 TO 10:NEXT I:POKE 54276,16
3050 DM=INT(RND(1)*3)+1
3060 HP=HP-DM
3070 PRINT "YOU LOSE";DM;"HP!"
3080 FOR I=1 TO 100:NEXT I
3090 RETURN
4000 REM find treasure
4010 PRINT CHR$(147):PRINT "TREASURE FOUND!"
4020 POKE 54296,15:POKE 54277,0:POKE 54278,240
4030 POKE 54273,100:POKE 54276,129
4040 FOR I=1 TO 20:NEXT I:POKE 54276,128
4050 TR=TR+1
4060 PRINT "YOU HAVE";TR;"TREASURES!"
4070 FOR I=1 TO 100:NEXT I
4080 RETURN
5000 REM find potion
5010 PRINT CHR$(147):PRINT "HEALTH POTION!"
5020 POKE 54296,15:POKE 54277,8:POKE 54278,8
5030 POKE 54273,80:POKE 54276,129
5040 FOR I=1 TO 15:NEXT I:POKE 54276,128
5050 HP=HP+2
5060 PRINT "YOU GAIN 2 HP!"
5070 FOR I=1 TO 100:NEXT I
5080 RETURN
```

## How It Works

**Title Screen (20-70):**
- Clear screen, set black background
- Display title and instructions
- Wait for keypress to start
- Initialize variables: position (X,Y), health (HP), treasure count (TR)

**Main Game Loop (90-180):**
- Display current room (GOSUB 1000)
- Read keyboard input (GET A$)
- Process movement with boundary checking (lines 110-140)
- 30% chance of random encounter after each move (line 150)
- Check lose condition: HP&lt;=0 (line 160)
- Check win condition: TR&gt;=3 (line 170)
- Loop back to input

**Display Room Subroutine (1000-1160):**
- Calculate room number: `RM=Y*3+X` (maps 2D grid to 0-8 range)
- Print position, HP, and treasure count
- Show room-specific description based on RM value
- Each room has unique atmospheric text
- RETURN to main loop

**Random Encounter System (2000-2050):**
- Generate random event type: `EV=INT(RND(1)*3)` (0, 1, or 2)
- GOSUB to appropriate event handler
- Monster attack (3000), treasure find (4000), or health potion (5000)

**Monster Attack (3000-3090):**
- Clear screen, print attack message
- Configure SID: harsh, brief tone
- Generate random damage 1-3: `DM=INT(RND(1)*3)+1`
- Subtract from HP
- Delay for player to read message

**Treasure Find (4000-4080):**
- Clear screen, print success message
- Configure SID: pleasant, sustained tone
- Increment treasure counter
- Display progress toward win condition

**Health Potion (5000-5080):**
- Clear screen, print healing message
- Configure SID: medium-pitched restorative sound
- Add 2 HP
- Confirm healing amount

## Design Patterns Used

**State machines:** The game tracks X, Y, HP, and TR as state variables. Each input and event modifies state, creating emergent gameplay.

**Subroutines for structure:** GOSUB breaks the 69 lines into logical sections. The main loop stays concise, calling specialized handlers for display and events.

**Data-driven room descriptions:** Instead of complex branching, room text uses RM as an index. Adding rooms means adding IF statements, not rewriting logic.

**Probability-based events:** `IF RND(1)<.3` creates uncertainty. The 30% threshold balances excitement (frequent events) with exploration (not every move).

**Sound as feedback:** Different SID configurations instantly communicate event type before the player reads text—harsh = bad, pleasant = good.

## Extending the Game

**More rooms:** Change grid size in movement boundaries and add description lines. A 4×4 grid (16 rooms) needs X&lt;3, Y&lt;3 checks and lines 1160-1310.

**Inventory system:** Add a key variable (KY=0). Set KY=1 when finding a key in room 3. Check `IF X=8 AND KY=0` to block the exit.

**Combat choices:** In the monster subroutine, add `INPUT "fight or flee (f/r)"; A$`. If flee, `IF RND(1)<.5` for 50% escape chance.

**Timer pressure:** Add `TI$="000000"` at line 70, display `INT((600-TI)/60)` in room display, check `IF TI>600` for time-up lose condition.

**Visual map:** Use screen memory to draw a simple map. `POKE 1024+Y*40+X,81` shows player position, `POKE 1024+OY*40+OX,46` marks visited rooms.

## How Commercial Games Used These Techniques

**The Hobbit (1982):** Text adventure with similar room-based structure. Each location had description text selected by room ID, with random events (Thorin appearing, trolls attacking).

**Temple of Apshai (1979):** Dungeon crawler using numbered rooms with text descriptions. Combat used random damage rolls, treasure spawned probabilistically.

**Zork (Infocom, 1980):** More sophisticated parser, but same core: room graph navigation, inventory state, random encounters, win/lose conditions.

**Adventure (1976):** The original text adventure. Two-word parser (VERB NOUN), but underneath: room connections, state tracking, treasure collection, all in BASIC.

## Challenge Ideas

Before moving to Tier 2, try extending Dungeon Quest:

1. **Add a boss fight:** Room 8 requires defeating a monster to win. Track boss HP, implement turn-based combat.

2. **Locked doors:** Some room transitions require keys found elsewhere. Check key ownership before allowing movement.

3. **Traps:** Certain rooms damage you on entry. Use room-specific IF checks to trigger trap damage and sound.

4. **Merchant NPC:** Room 4 lets you trade treasures for HP potions. Input "buy" to exchange TR for HP.

5. **Darkness mechanic:** Some rooms are dark. Display "too dark to see!" unless you've found a torch (new variable TO=0/1).

Each extension reinforces Tier 1 concepts while building toward Tier 2's data-driven design patterns.
