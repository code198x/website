Back in Lesson 4, you built a quiz game. But here's the problem: adding more questions means writing more code lines. Want 20 questions? That's 60+ lines of repetitive array initialization. Want to change a question? Hunt through the code to find it.

There's a better way. `DATA` statements let you embed lists of values directly in your program, separate from the logic. Combined with `READ`, you can build expandable quiz games where adding questions means adding one line—not twenty.

## The One-Minute Tour

- `DATA` stores values in comma-separated lists anywhere in your program
- `READ` retrieves the next value from DATA statements sequentially
- `RESTORE` resets the read pointer back to the first DATA line
- Questions and answers live separately from game logic
- Adding content doesn't require changing code structure

## First Example: Reading DATA

Here's the simplest DATA demonstration—reading names and ages:

```basic
10 REM SIMPLE DATA DEMO
20 PRINT CHR$(147);"READING DATA"
30 PRINT
40 READ N$
50 READ A
60 PRINT N$;" IS";A;" YEARS OLD"
70 PRINT
80 READ N$
90 READ A
100 PRINT N$;" IS";A;" YEARS OLD"
110 DATA ALICE,25
120 DATA BOB,30
```

**Run this** and you'll see the DATA values appear in the order they're read. Lines 110-120 contain the data, but READ pulls from them sequentially starting at line 40.

![Simple DATA/READ demonstration](/images/commodore-64/phase-0/tier-1/lesson-006/example-1.png)

Notice how the DATA lines can appear anywhere—even after the code that reads them. BASIC scans the entire program for DATA statements when it starts.

## Second Example: Complete Quiz with DATA

Now let's rebuild the quiz game using DATA. This version handles 5 questions, with the ability to replay and reset:

```basic
10 REM QUIZ MASTER PRO
20 PRINT CHR$(147);"QUIZ MASTER PRO"
30 PRINT
40 S=0
50 FOR I=1 TO 5
60 READ Q$,A
70 PRINT Q$
80 INPUT R
90 IF R=A THEN PRINT "CORRECT!":S=S+1:GOTO 110
100 PRINT "WRONG! IT'S";A
110 PRINT
120 NEXT I
130 PRINT "FINAL SCORE:";S;"OUT OF 5"
140 PRINT
150 PRINT "PLAY AGAIN? (Y/N)"
160 GET K$:IF K$="" THEN 160
170 IF K$="Y" THEN RESTORE:RUN
180 DATA WHAT IS 2+2?,4
190 DATA WHAT IS 5*3?,15
200 DATA WHAT IS 10-3?,7
210 DATA WHAT IS 8/2?,4
220 DATA WHAT IS 6+7?,13
```

**Run this** and answer the questions. When you finish, press Y to replay—notice it works perfectly because `RESTORE` on line 170 resets the DATA pointer.

![Complete quiz game using DATA statements](/images/commodore-64/phase-0/tier-1/lesson-006/example-2.png)

## How DATA and READ Work

**Lines 180-220: The DATA Statements**

Each DATA line contains a question (string) and an answer (number), separated by commas. BASIC treats these as a continuous stream of values—it doesn't matter that they're on different lines.

**Line 60: READ Q$,A**

This reads two values: the next string into `Q$`, and the next number into `A`. The first time through the loop, it reads `"WHAT IS 2+2?"` and `4`. The second time, `"WHAT IS 5*3?"` and `15`. And so on.

**Line 170: RESTORE**

`RESTORE` resets the internal pointer back to the first DATA statement. Without this, running the program again would try to read past the end of the DATA and crash with "OUT OF DATA ERROR".

**Important:** READ pulls values in the exact order they appear in DATA statements. Mix up the order or types (string vs number), and you'll get "TYPE MISMATCH ERROR".

## Why This Matters

Compare the quiz from Lesson 4 (lines 30-70 initializing arrays) to this version (lines 180-220 containing pure data). Same functionality, but now:

- **Adding a question:** One line (`DATA WHAT IS 3*7?,21`)
- **Changing a question:** Edit one DATA line
- **Removing a question:** Delete one DATA line (and update line 50's loop count)

The game logic (lines 50-120) never changes. Questions are data, not code.

## Experiments to Try

**1. Add More Questions**

Add three more DATA lines with your own questions. Change line 50 to `FOR I=1 TO 8` to include them.

**2. Multiple Choice Quiz**

Try storing four options per question:
```basic
60 READ Q$,A$,B$,C$,D$,R
DATA CAPITAL OF FRANCE?,PARIS,LONDON,BERLIN,MADRID,1
```

Then display the options and check which answer number the player chooses.

**3. Randomize Question Order**

Use `RND(1)` to read questions in random order. You'll need arrays to store them first (like Lesson 4), then shuffle the array indices.

**4. Different DATA Types**

Create a high score table using DATA:
```basic
10 DATA ALICE,1200
20 DATA BOB,950
30 DATA CAROL,850
40 FOR I=1 TO 3
50 READ N$,S
60 PRINT N$,S
70 NEXT I
```

## Quick Reference

### DATA/READ/RESTORE Commands

| Command | Purpose | Example |
|---------|---------|---------|
| `DATA val1,val2,...` | Store values in program | `DATA ALICE,25,BOB,30` |
| `READ var1,var2,...` | Retrieve next values | `READ N$,AGE` |
| `RESTORE` | Reset read pointer to first DATA | `RESTORE` |
| `RESTORE line` | Reset to specific DATA line | `RESTORE 100` |

### Common Patterns

```basic
REM READ LOOP PATTERN
10 FOR I=1 TO N
20 READ A$,B
30 REM PROCESS DATA
40 NEXT I

REM REPLAY PATTERN
10 RESTORE
20 RUN

REM MIXED DATA TYPES
10 READ NAME$,AGE,SCORE
20 DATA ALICE,25,1200
```

### DATA Rules

- Values separated by commas
- Strings don't need quotes (unless they contain commas or colons)
- DATA lines can appear anywhere in the program
- READ processes DATA sequentially regardless of line numbers
- READ past the end → "OUT OF DATA ERROR"
- READ wrong type → "TYPE MISMATCH ERROR"

## What You've Learnt

- DATA statements embed lists of values directly in your program
- READ retrieves values sequentially from all DATA lines
- RESTORE resets the read pointer for replaying or reprocessing
- Separating data from logic makes programs expandable
- Adding content doesn't require rewriting code structure
