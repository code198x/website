Every decent game needs a high score table. But there's a problem: scores don't arrive in order. Carol might get 1200 points today, Alice might get 850 tomorrow, and Bob might scrape together 620 next week. How do you keep them ranked with the highest score at the top?

The answer is **sorting**—rearranging your data into order. This lesson introduces the bubble sort algorithm, a simple technique that works perfectly for small lists like high score tables.

## The One-Minute Tour

- **Sorting** means rearranging data into a specific order (ascending or descending)
- **Bubble sort** compares adjacent pairs and swaps them if they're in the wrong order
- The **swap pattern** (`T=A:A=B:B=T`) exchanges two values using a temporary variable
- **Parallel arrays** (like scores and names) must be swapped together to stay matched
- High score tables need **descending order**—highest scores first
- Nested `FOR` loops let you repeat comparisons until everything's sorted

## First Example: The Problem

Here's a high score table that's **not** sorted. The scores are in whatever order they were entered:

```basic
10 REM UNSORTED SCORES
20 DIM SC(4),NM$(4)
30 SC(0)=850:NM$(0)="ALICE"
40 SC(1)=620:NM$(1)="BOB"
50 SC(2)=1200:NM$(2)="CAROL"
60 SC(3)=420:NM$(3)="DAVE"
70 SC(4)=950:NM$(4)="EVE"
80 PRINT CHR$(147);"HIGH SCORE HALL"
90 PRINT
100 FOR I=0 TO 4
110 PRINT I+1;". ";NM$(I);TAB(15);SC(I)
120 NEXT I
```

**Run this** and you'll see the problem immediately. Carol's winning 1200 is buried in third place, while Dave's disappointing 420 sits near the bottom. Not exactly a hall of fame, is it?

## Second Example: Bubble Sort to the Rescue

Now let's fix it with a **bubble sort**. This version rearranges the scores so the highest appears first:

```basic
10 REM SORTED HIGH SCORES
20 DIM SC(4),NM$(4)
30 SC(0)=850:NM$(0)="ALICE"
40 SC(1)=620:NM$(1)="BOB"
50 SC(2)=1200:NM$(2)="CAROL"
60 SC(3)=420:NM$(3)="DAVE"
70 SC(4)=950:NM$(4)="EVE"
80 PRINT CHR$(147);"SORTING..."
90 REM BUBBLE SORT (DESCENDING)
100 FOR I=0 TO 3
110 FOR J=0 TO 3-I
120 IF SC(J)>SC(J+1) THEN 160
130 T=SC(J):SC(J)=SC(J+1):SC(J+1)=T
140 T$=NM$(J):NM$(J)=NM$(J+1):NM$(J+1)=T$
150 REM SWAPPED
160 NEXT J
170 NEXT I
180 PRINT CHR$(147);"HIGH SCORE HALL"
190 PRINT
200 FOR I=0 TO 4
210 PRINT I+1;". ";NM$(I);TAB(15);SC(I)
220 NEXT I
```

**Run this** and watch the magic happen. After the sorting finishes, you'll see:

```
HIGH SCORE HALL

1. CAROL          1200
2. EVE             950
3. ALICE           850
4. BOB             620
5. DAVE            420
```

Perfect! The highest scores are at the top where they belong.

## How Bubble Sort Works

The bubble sort algorithm is beautifully simple. It works by comparing adjacent pairs of scores and swapping them if they're in the wrong order. Here's the process:

**Lines 100-170: The Nested Loops**

The outer loop (`FOR I=0 TO 3`) controls how many passes we make through the data. We need 4 passes to guarantee 5 items are sorted.

The inner loop (`FOR J=0 TO 3-I`) does the actual comparisons. Notice `3-I`? That's an optimization—after each pass, one more item is definitely in its final position, so we can skip checking it.

**Line 120: The Comparison**

`IF SC(J)>SC(J+1) THEN 160`

This is the crucial line. If the current score is **greater than** the next score, we skip the swap (jumping to line 160). This gives us **descending order**—highest scores first.

**Important:** For ascending order (lowest first), you'd use `IF SC(J)<SC(J+1)`. The comparison operator determines the direction.

**Lines 130-140: The Swap Pattern**

When we need to swap, we have to move both the score **and** the name together. This is called swapping **parallel arrays**.

```basic
130 T=SC(J):SC(J)=SC(J+1):SC(J+1)=T
140 T$=NM$(J):NM$(J)=NM$(J+1):NM$(J+1)=T$
```

Line 130 swaps the scores using a temporary variable `T`:
1. Save `SC(J)` in `T`
2. Copy `SC(J+1)` into `SC(J)`
3. Copy `T` (the old `SC(J)`) into `SC(J+1)`

Line 140 does the same for the names using `T$`.

**Why the temporary variable?** Try swapping without it and you'll lose data:

```basic
SC(J)=SC(J+1)  :REM SC(J) IS NOW 950
SC(J+1)=SC(J)  :REM SC(J+1) IS NOW 950 TOO!
```

Both variables end up with the same value. The temporary variable preserves the original.

## Why This Matters for Games

High score tables are standard in arcade-style games. Here's how professional titles handle them:

**Gradius (Konami, 1985)** keeps a top-10 table in memory, sorted after every game. When you beat a score, it slots your entry into the correct position and bumps the lowest score off the bottom.

**International Karate (System 3, 1985)** saves high scores to disk using bubble sort to maintain order. The algorithm's simplicity makes it reliable even when writing to unreliable 1541 disk drives.

**Thing on a Spring (Gremlin Graphics, 1985)** uses a similar approach but only tracks 5 scores—exactly like our example. For small lists, bubble sort is fast enough that you don't notice the delay.

## Experiments to Try

**1. Sort in Ascending Order**

Change line 120 to:
```basic
120 IF SC(J)<SC(J+1) THEN 160
```

Now the lowest scores appear first. Notice how one character (`<` vs `>`) completely reverses the order.

**2. Add More Scores**

Change line 20 to `DIM SC(9),NM$(9)` and add five more players with scores. Update line 100 to `FOR I=0 TO 8` and line 110 to `FOR J=0 TO 8-I`. Also change line 200 to `FOR I=0 TO 9`. Does it still work?

**3. Watch It Sort**

Add these lines to see the sorting happen step by step:
```basic
145 FOR K=0 TO 4:PRINT NM$(K),SC(K);:NEXT K:PRINT
```

Put this after line 140 and run again. You'll see each swap as it happens. (It'll scroll fast!)

**4. Sort Names Alphabetically**

Try sorting by name instead of score. Change line 120 to:
```basic
120 IF NM$(J)>NM$(J+1) THEN 160
```

String comparison works alphabetically—`"ALICE"` is less than `"BOB"`, which is less than `"CAROL"`.

## Quick Reference

### Bubble Sort Structure

| Line | Purpose | Notes |
|------|---------|-------|
| `FOR I=0 TO N-1` | Outer loop (passes) | N items need N-1 passes |
| `FOR J=0 TO N-1-I` | Inner loop (comparisons) | `-I` optimization |
| `IF A(J) op A(J+1)` | Compare adjacent | `<` ascending, `>` descending |
| `T=A:A=B:B=T` | Swap pattern | Requires temporary variable |

### Common Patterns

```basic
REM SWAP TWO NUMBERS
T=A:A=B:B=T

REM SWAP TWO STRINGS
T$=A$:A$=B$:B$=T$

REM SWAP PARALLEL ARRAYS (SCORES + NAMES)
T=SC(J):SC(J)=SC(J+1):SC(J+1)=T
T$=NM$(J):NM$(J)=NM$(J+1):NM$(J+1)=T$
```

### Sort Directions

| Comparison | Order | Use Case |
|------------|-------|----------|
| `IF A(J)<A(J+1)` | Ascending | Lowest first (times, dates) |
| `IF A(J)>A(J+1)` | Descending | Highest first (scores, ranks) |
