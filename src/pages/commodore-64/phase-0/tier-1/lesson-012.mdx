## Waiting Without Blocking

INPUT stops everything until you press RETURN. Games can't work like that—the world keeps moving while you press buttons. The GET command reads a single keypress without waiting, returning an empty string if no key is down. This turns your program into a conversation: "Anything new? No? I'll keep running then."

---

### The One-Minute Tour

- GET reads one character from keyboard buffer
- Returns empty string ("") if no key pressed
- Non-blocking: program continues immediately
- WASD keys: w=up, a=left, s=down, d=right
- Screen memory: 1024-2023 (40 columns × 25 rows)
- Colour memory: 55296-56295 (parallel to screen)
- Position formula: address = 1024 + y×40 + x
- Boundary checks prevent moving off screen edges
- GET A$ in a loop = continuous input detection

---

### Example Programme

```basic
10 REM SIMPLE GET DEMO
20 PRINT CHR$(147)
30 PRINT "PRESS ANY KEY (Q TO QUIT)"
40 GET A$
50 IF A$="" THEN 40
60 IF A$="Q" THEN END
70 PRINT "YOU PRESSED: ";A$
80 GOTO 30
```

Sample output:

```
PRESS ANY KEY (Q TO QUIT)
YOU PRESSED: A
PRESS ANY KEY (Q TO QUIT)
YOU PRESSED: 5
PRESS ANY KEY (Q TO QUIT)

READY.
```

![Screen after pressing keys](/images/commodore-64/phase-0/tier-1/lesson-012/example-1.png)

**Line 40** checks keyboard with GET. **Line 50** if nothing pressed (empty string), loop back and check again—this is the non-blocking pattern. **Line 60** quit on Q. **Line 70** shows what key was pressed. No waiting, no RETURN needed—pure immediate input.

> **Tip:** GET only reads one character at a time. Multi-character input still requires INPUT, but games almost never need that—one keypress at a time is how you control movement, firing, jumping.

### Experiment Section

Try these variations:

- **Number keys**: Press 0-9 and see them appear
- **Shift detection**: Try SHIFT+letters (you'll see shifted PETSCII characters)
- **Function keys**: Press F1, F3, F5, F7 (each has a unique code)
- **Different quit key**: Change line 60 to `IF A$=" " THEN END` (space to quit)
- **Case insensitive**: Add line 45: `A$=CHR$(ASC(A$) AND 223)` to force uppercase

Direction detection with WASD keys:

```basic
10 REM WASD KEY DETECTION
20 PRINT CHR$(147)
30 PRINT "USE WASD KEYS (Q TO QUIT)"
40 PRINT
50 GET A$
60 IF A$="" THEN 50
70 IF A$="Q" THEN END
80 IF A$="W" THEN PRINT "UP"
90 IF A$="S" THEN PRINT "DOWN"
100 IF A$="A" THEN PRINT "LEFT"
110 IF A$="D" THEN PRINT "RIGHT"
120 GOTO 50
```

![WASD key detection output](/images/commodore-64/phase-0/tier-1/lesson-012/example-2.png)

Each keypress triggers an immediate response. No waiting, no RETURN. The empty-string check (line 60) makes the loop tight—it runs thousands of times per second, checking constantly. When you finally press a key, the IF statements (lines 80-110) detect which direction.

Now the complete player control system:

```basic
10 REM MOVE @ AROUND SCREEN
20 PRINT CHR$(147)
30 X=20:Y=12
40 POKE 1024+Y*40+X,0
50 POKE 55296+Y*40+X,1
60 GET A$
70 IF A$="" THEN 60
80 IF A$="Q" THEN END
90 POKE 1024+Y*40+X,32
100 IF A$="W" AND Y>0 THEN Y=Y-1
110 IF A$="S" AND Y<24 THEN Y=Y+1
120 IF A$="A" AND X>0 THEN X=X-1
130 IF A$="D" AND X<39 THEN X=X+1
140 POKE 1024+Y*40+X,0
150 POKE 55296+Y*40+X,1
160 GOTO 60
```

![Moving @ character around screen](/images/commodore-64/phase-0/tier-1/lesson-012/example-3.png)

This is your first interactive character controller. **Line 30** sets starting position (middle of screen). **Line 40** plots the @ character (screen code 0) at position y×40+x. **Line 50** makes it white (colour 1). **Line 90** erases old position by plotting space (32). **Lines 100-130** update coordinates with boundary checks—Y ranges 0-24, X ranges 0-39. **Lines 140-150** redraw at new position. The character moves smoothly because each loop erases-move-redraw.

### Concept Expansion

**Screen memory layout.** The C64 stores what appears on screen in memory locations 1024-2023. It's a flat array of 1000 bytes (40 columns × 25 rows). To find the address of position (x, y): 1024 + y×40 + x. Row 0 starts at 1024, row 1 at 1064, row 2 at 1104, etc. Column 0 is first byte, column 39 is last byte. The values stored are PETSCII screen codes: 0=@, 1=A, 32=space, etc.

**Parallel colour memory.** Colour RAM lives at 55296-56295, one byte per screen position. Whatever colour you POKE to 55296+y×40+x becomes the colour of the character at screen position y×40+x. Colour 1=white, 2=red, 5=green, 6=blue, etc. The VIC-II chip reads both screen and colour memory simultaneously to generate the display.

**Boundary checking prevents crashes.** Without `AND Y>0`, pressing W at top edge would make Y=-1. Address 1024+(-1)×40+20 = 984, which is outside screen memory—random garbage appears or worse. The AND operator in lines 100-130 combines two conditions: "if W pressed AND not at top edge, THEN move up." This keeps coordinates valid: X stays 0-39, Y stays 0-24.

**Non-blocking input transforms programs.** INPUT A$ waits forever—program frozen until you type. GET A$ checks once and moves on—program runs continuously, checking keyboard thousands of times per second. This is the fundamental pattern of real-time software: check input → update state → render output → repeat. Games, music sequencers, communication software—anything interactive—uses this loop.

**Coordinate systems and conventions.** We use X for horizontal (0=left, 39=right) and Y for vertical (0=top, 24=bottom). This matches screen addressing but inverts mathematical convention (where Y increases upward). Games often use different conventions—some have (0,0) at bottom-left, some at top-left. What matters is consistency: pick a system and stick with it.

### Game Integration

- **Player movement**: WASD for 4-direction, add QE for diagonals
- **Shooting**: Space bar sets "bullet fired" flag
- **Menus**: Cursor up/down to select options
- **Pause**: P key toggles pause state
- **Multi-key**: Check multiple GET statements for simultaneous input
- **Joystick**: Port 2 reads from location 56320 (covered in later lessons)

Classic game control patterns:

```basic
REM SHOOT-AND-MOVE PATTERN
GET A$
IF A$="W" THEN Y=Y-1
IF A$="S" THEN Y=Y+1
IF A$=" " THEN BX=X:BY=Y:BF=1:REM FIRE BULLET AT PLAYER POSITION
```

Menu navigation:

```basic
REM MENU SELECTION
GET A$
IF A$="W" AND SEL>1 THEN SEL=SEL-1
IF A$="S" AND SEL<3 THEN SEL=SEL+1
IF A$=" " THEN GOSUB 5000:REM ACTIVATE SELECTION
```

### Quick Reference

**GET Command:**
```
GET variable$    Read single keypress (non-blocking)
                Returns "" if no key pressed
                No RETURN required
```

**Screen Memory (Text Mode):**
```
Screen RAM:   1024-2023    (1000 bytes, 40×25)
Colour RAM:   55296-56295  (1000 bytes, parallel)

Position formula:  ADDRESS = 1024 + Y×40 + X
Colour formula:    ADDRESS = 55296 + Y×40 + X

Ranges:  X = 0-39 (columns)
         Y = 0-24 (rows)
```

**Common Screen Codes:**
```
0  = @        32 = space    65 = A
1  = A        33 = !        66 = B
26 = Z        63 = ?        90 = Z
```

**Standard Colours:**
```
0=black   1=white    2=red      3=cyan
4=purple  5=green    6=blue     7=yellow
8=orange  9=brown    10=pink    11=dark grey
12=grey   13=lt green 14=lt blue 15=lt grey
```

**WASD Control Pattern:**
```basic
GET A$
IF A$="" THEN [LOOP BACK]
IF A$="W" AND Y>0 THEN Y=Y-1
IF A$="S" AND Y<24 THEN Y=Y+1
IF A$="A" AND X>0 THEN X=X-1
IF A$="D" AND X<39 THEN X=X+1
```

**Erase-Move-Redraw Pattern:**
```basic
POKE 1024+Y*40+X,32          :REM ERASE OLD POSITION
[UPDATE X AND Y]
POKE 1024+Y*40+X,[CHAR CODE]:REM DRAW NEW POSITION
```
