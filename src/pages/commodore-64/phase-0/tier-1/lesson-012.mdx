You've POKEd to screen memory, played sounds, and handled keyboard input. Now it's time to combine those skills into the core of every action game: a character you can move around the screen.

This isn't just about reading WASD keys. It's about establishing the **game loop pattern**—input, update, draw, repeat—that every game from Pac-Man to Impossible Mission uses.

## The One-Minute Tour

- **Game loop pattern**: Input → Update → Draw → Repeat forever
- **Erase-Move-Draw**: Clear old position (POKE 32), update X/Y variables, draw new position
- **Position variables** (X, Y) separate from screen display for cleaner logic
- **Bounds checking** with AND: `IF K$="W" AND Y>0` prevents crashes
- **Timing loops** slow down movement for playability

## First Example: Basic WASD Character Mover

```basic
10 REM CHARACTER MOVER
20 PRINT CHR$(147)
30 PRINT "WASD CHARACTER MOVER"
40 PRINT
50 PRINT "W=UP S=DOWN A=LEFT D=RIGHT"
60 PRINT
70 X=20:Y=12:C=81
80 POKE 1024+(Y*40)+X,C
90 REM MAIN LOOP
100 POKE 1024+(Y*40)+X,32
110 GET K$
120 IF K$="W" AND Y>0 THEN Y=Y-1
130 IF K$="S" AND Y<24 THEN Y=Y+1
140 IF K$="A" AND X>0 THEN X=X-1
150 IF K$="D" AND X<39 THEN X=X+1
160 POKE 1024+(Y*40)+X,C
170 GOTO 100
```

**Run this** and use WASD to move the character (Q) around the screen. The character leaves no trail, responds instantly, and can't escape the screen edges.

## Second Example: Smooth Movement with Colour

```basic
10 REM SMOOTH MOVER

100 REM MAIN LOOP
110 POKE 1024+(Y*40)+X,32

140 IF K$="S" AND Y<24 THEN Y=Y+1
150 IF K$="A" AND X>0 THEN X=X-1
160 IF K$="D" AND X<39 THEN X=X+1
```

This version adds **yellow colour** (7) via colour memory at 55296, plus a **timing delay** (line 190) that makes movement feel smoother and more controllable.

## How the Game Loop Works

### Line 70: Initialise Position

`X=20:Y=12:C=81`

Sets starting position to screen centre (X=20, Y=12) and character code 81 (the letter Q). These are **variables**, not hard-coded screen addresses, which makes movement logic much cleaner.

### Line 100: Erase Old Position

`POKE 1024+(Y*40)+X,32`

**Critical step**: Before moving, erase the character at its current position by POKEing 32 (space character). Without this, the character leaves a trail across the screen.

### Line 110: Get Input

`GET K$`

Checks keyboard without waiting. If no key is pressed, K$ becomes empty string (""), and we skip all the movement IFs.

### Lines 120-150: Update Position with Bounds

`IF K$="W" AND Y>0 THEN Y=Y-1`

The **AND** operator is crucial here. We check TWO things:
1. Was W pressed? (`K$="W"`)
2. Are we not at the top edge? (`Y>0`)

Only if BOTH are true do we move up (`Y=Y-1`). This prevents Y from going negative, which would cause a crash or wrap to the bottom of memory.

**Bounds for each direction:**
- **W (up)**: Y>0 (top edge is Y=0)
- **S (down)**: Y&lt;24 (bottom edge is Y=24, since screen is 25 rows)
- **A (left)**: X>0 (left edge is X=0)
- **D (right)**: X&lt;39 (right edge is X=39, since screen is 40 columns)

### Line 160: Draw New Position

`POKE 1024+(Y*40)+X,C`

Now that X and Y have been updated, draw the character at its new location. The erase-update-draw sequence happens so fast it looks like smooth movement.

### Line 170: Loop Forever

`GOTO 100`

Jump back to the erase step and repeat. This is the **game loop**: check input, update state, redraw screen, repeat forever.

## Why This Pattern Matters

Every action game follows this structure:

```
LOOP:
  Erase old positions
  Get player input
  Update positions (player, enemies, bullets)
  Check collisions
  Draw new positions
  GOTO LOOP
```

You've just built the foundation. In Lesson 13, you'll add falling objects. In Lesson 14, you'll add collision detection and scoring. By Lesson 15, you'll have a complete game.

## The Timing Delay (Line 190)

`FOR T=1 TO 15:NEXT T`

Without this delay, movement is **instant**—the character teleports across the screen faster than you can react. The delay loop wastes a tiny amount of time, making movement feel more natural.

**Experiment with different values:**
- `FOR T=1 TO 5` = faster movement
- `FOR T=1 TO 30` = slower, more deliberate movement

Games often need timing delays to make actions playable. Later you'll learn about reading the hardware clock for frame-perfect timing.

## Experiments to Try

**1. Diagonal Movement**

Can you check for two keys at once? Try adding:
```basic
125 IF K$="W" AND K2$="D" AND Y>0 AND X<39 THEN Y=Y-1:X=X+1
```
You'd need to add `GET K2$` to read a second key.

**2. Change the Character**

Replace `C=81` with different values:
- `C=42` = asterisk (*)
- `C=64` = filled circle (@)
- `C=90` = Z

**3. Add a Border**

What if you wanted the character to stop at X=5 instead of X=0?
```basic
140 IF K$="A" AND X>5 THEN X=X-1
```

**4. Wrap Around**

Instead of stopping at edges, wrap to the opposite side:
```basic
140 IF K$="A" THEN X=X-1:IF X<0 THEN X=39
```

## Quick Reference

### Game Loop Pattern

```basic
10 REM Initialize
20 X=20:Y=12:C=81
30 REM Main loop
40 POKE 1024+(Y*40)+X,32  :REM Erase
50 GET K$                 :REM Input
60 REM Update with bounds checking
70 IF K$="W" AND Y>0 THEN Y=Y-1
80 REM Draw
90 POKE 1024+(Y*40)+X,C
100 GOTO 40
```

### Screen Bounds

| Edge | Condition | Reason |
|------|-----------|--------|
| Top | Y>0 | Row 0 is top |
| Bottom | Y&lt;24 | Row 24 is bottom (25 rows total) |
| Left | X>0 | Column 0 is left |
| Right | X&lt;39 | Column 39 is right (40 columns total) |

### Common Mistakes

| Problem | Cause | Fix |
|---------|-------|-----|
| Character trails | Not erasing old position | Add `POKE 1024+(Y*40)+X,32` before moving |
| Crashes/wrapping | No bounds checking | Use AND in IF statements |
| Too fast | No timing delay | Add `FOR T=1 TO 15:NEXT T` after draw |
| Wrong character | Character code out of range | Use 32-127 for printable characters |

### Colour Memory

To colour your character, POKE to colour memory at the same offset:
```basic
POKE 55296+(Y*40)+X,7  :REM Yellow
```

**Colour codes:** 0=Black, 1=White, 2=Red, 3=Cyan, 4=Purple, 5=Green, 6=Blue, 7=Yellow, etc.
