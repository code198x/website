# Lesson 4: Quiz Master

## The One-Minute Tour

- Arrays store multiple values with one name
- `DIM` creates arrays before you use them
- Arrays use index numbers to access specific items (starts at 0)
- FOR loops iterate through arrays automatically
- This transforms repetitive code into compact, data-driven programs

## The Problem with Repetition

Last lesson built a guessing game. Now let's make a quiz with multiple questions. Here's the obvious approach:

```basic
10 REM SIMPLE QUIZ
20 PRINT CHR$(147);"QUIZ MASTER"
30 PRINT
40 PRINT "WHAT IS 2+2?"
50 INPUT A
60 IF A=4 THEN PRINT "CORRECT!":S=S+1
70 IF A<>4 THEN PRINT "WRONG! IT'S 4"
80 PRINT
90 PRINT "WHAT IS 5*3?"
100 INPUT A
110 IF A=15 THEN PRINT "CORRECT!":S=S+1
120 IF A<>15 THEN PRINT "WRONG! IT'S 15"
130 PRINT
140 PRINT "WHAT IS 10-3?"
150 INPUT A
160 IF A=7 THEN PRINT "CORRECT!":S=S+1
170 IF A<>7 THEN PRINT "WRONG! IT'S 7"
180 PRINT
190 PRINT "SCORE:";S;"OUT OF 3"
```

Type `RUN` and try it.

![Simple repetitive quiz](/images/commodore-64/phase-0/tier-1/lesson-004/example-1.png)

It works, but look at the pattern. Lines 40-70 repeat almost identically at lines 90-120 and 140-170. Only the question and answer change. 

Want 10 questions? Copy-paste those lines 10 times. Want 50? This gets absurd fast.

**The insight:** You're not writing different code for each question. You're writing the *same* code with different *data*. Separate the logic from the data.

## Arrays: Multiple Values, One Name

Arrays solve this. Instead of three variables (`Q1$`, `Q2$`, `Q3$`), use one array with three slots:

```basic
DIM Q$(2)     REM Create array with 3 slots (0, 1, 2)
Q$(0) = "WHAT IS 2+2?"
Q$(1) = "WHAT IS 5*3?"
Q$(2) = "WHAT IS 10-3?"
```

Each slot has an *index* (the number in brackets). `Q$(0)` is the first question, `Q$(1)` is the second, `Q$(2)` is the third.

**Critical:** Arrays start at 0, not 1. `DIM Q$(2)` creates slots 0, 1, and 2—that's **three** slots total.

Now add answers:

```basic
DIM AN(2)     REM Array for answers
AN(0) = 4
AN(1) = 15
AN(2) = 7
```

## The Array-Driven Quiz

Here's the same quiz, rewritten with arrays:

```basic
10 REM ARRAY QUIZ
20 DIM Q$(4),AN(4)
30 Q$(0)="WHAT IS 2+2?":AN(0)=4
40 Q$(1)="WHAT IS 5*3?":AN(1)=15
50 Q$(2)="WHAT IS 10-3?":AN(2)=7
60 Q$(3)="WHAT IS 8/2?":AN(3)=4
70 Q$(4)="WHAT IS 6+7?":AN(4)=13
80 PRINT CHR$(147);"QUIZ MASTER"
90 PRINT
100 FOR I=0 TO 4
110 PRINT Q$(I)
120 INPUT A
130 IF A=AN(I) THEN PRINT "CORRECT!":S=S+1:GOTO 150
140 PRINT "WRONG! IT'S";AN(I)
150 PRINT
160 NEXT I
170 PRINT "FINAL SCORE:";S;"OUT OF 5"
180 PRINT
190 PRINT "PLAY AGAIN? (Y/N)"
200 GET K$:IF K$="" THEN 200
210 IF K$="Y" THEN S=0:RUN
```

Type `RUN` and play.

![Array-driven quiz with 5 questions](/images/commodore-64/phase-0/tier-1/lesson-004/example-2.png)

**What changed?**

Lines 30-70 store all questions and answers in arrays.

Line 100: `FOR I=0 TO 4` loops through all five questions (indices 0-4).

Line 110: `PRINT Q$(I)` prints the current question. First time through, `I=0`, so it prints `Q$(0)`. Next time, `I=1`, so `Q$(1)`, and so on.

Line 130: `IF A=AN(I)` checks against the current answer.

**The power:** Want 10 questions? Add 5 more lines like line 30-70 and change `FOR I=0 TO 9`. Want 50? Add 45 more data lines. The quiz logic (lines 100-160) stays identical.

## Why This Matters

Every data-driven game uses arrays:
- **Levels** - Array of level layouts
- **Enemies** - Array of enemy X/Y positions, types, health
- **Inventory** - Array of items you're carrying
- **High scores** - Array of names and scores
- **Dialogue** - Array of conversation text

You've just learnt the most important pattern in game programming: separate data from logic. Write the logic once, change the data endlessly.

## How DIM Works

`DIM` stands for "dimension". It reserves memory for an array before you use it.

```basic
DIM Q$(4)     REM String array, 5 elements (0-4)
DIM AN(4)     REM Numeric array, 5 elements
DIM X(99)     REM 100 elements (0-99)
```

**Why `DIM`?** BASIC needs to know how much memory to allocate. Arrays can be huge. Without `DIM`, BASIC limits you to 11 elements (0-10).

**When to `DIM`:** Before you assign any values to the array. Put all `DIM` statements at the top of your program (lines 10-30).

## Array Index Rules

Arrays start at 0. This confuses everyone at first.

```basic
DIM A(2)      REM Creates slots: A(0), A(1), A(2)
REM That's 3 slots, not 2!
```

**Mental model:** Think of the number in `DIM` as the *highest index*, not the count.

- `DIM A(2)` → highest index is 2 → slots 0, 1, 2 → 3 total
- `DIM A(9)` → highest index is 9 → slots 0-9 → 10 total
- `DIM A(99)` → highest index is 99 → slots 0-99 → 100 total

**Formula:** `DIM A(N)` creates `N+1` slots.

## Arrays and FOR Loops

Arrays and FOR loops are partners:

```basic
10 DIM SCORE(4)
20 FOR I=0 TO 4
30 SCORE(I)=0      REM Initialize all scores to 0
40 NEXT I
```

This pattern appears constantly. Loop through array, process each element.

**Reading:**
```basic
10 FOR I=0 TO 9
20 PRINT "PLAYER ";I+1;": ";NAME$(I)
30 NEXT I
```

**Modifying:**
```basic
10 FOR I=0 TO 4
20 SCORE(I)=SCORE(I)+10     REM Add 10 to each score
30 NEXT I
```

**Searching:**
```basic
10 FOR I=0 TO 9
20 IF SCORE(I)>HIGH THEN HIGH=SCORE(I):WINNER=I
30 NEXT I
40 PRINT "WINNER IS PLAYER ";WINNER+1
```

The FOR loop's `I` variable becomes the array index. This is the standard pattern.

## String Arrays vs Numeric Arrays

You've seen both:

**String arrays:**
```basic
DIM NAME$(9)
NAME$(0)="ALICE"
NAME$(1)="BOB"
```

**Numeric arrays:**
```basic
DIM SCORE(9)
SCORE(0)=100
SCORE(1)=250
```

**You can't mix types.** `SCORE$(0)=100` is an error. String array needs string. `SCORE(0)="100"` is also an error. Numeric array needs number.

**Memory:** String arrays use less memory per slot (3 bytes + string length) than you'd expect. Numeric arrays use 5 bytes per number.

## Multi-Dimensional Arrays

Arrays can have multiple dimensions. Think: grids, tables, maps.

```basic
DIM MAP(9,9)      REM 10×10 grid (0-9 in each direction)
MAP(5,3)=1        REM Set position (5,3) to 1
```

**Use cases:**
- **Game boards:** Chess, tic-tac-toe, minesweeper
- **Tile maps:** Each position holds a tile type
- **Lookup tables:** Pre-computed values

**Example - tic-tac-toe:**
```basic
10 DIM BOARD(2,2)     REM 3×3 grid
20 BOARD(1,1)=1       REM Player 1 in center
30 BOARD(0,0)=2       REM Player 2 in top-left
```

We'll use these more in later lessons when building games with grids.

## What You Can Change

**Experiment with the array quiz:**

1. Add more questions - change `DIM Q$(9),AN(9)` and add data lines
2. Make it random order - shuffle the indices before asking
3. Track which questions you got wrong - use another array
4. Add a timer - count down from 30 seconds
5. Multiple choice - add array of wrong answers

The beauty of arrays: add data, don't rewrite logic.

## How Games Use This

**Jet Set Willy** stores all 256 rooms in arrays. Each room: platforms, enemies, items, exits. The room-drawing code doesn't change—just load different data.

**Ultima** uses 2D arrays for the world map. Each tile: terrain type, can you walk on it, encounters. One array, entire world.

**Elite** stores 256 galaxies, each with 256 star systems. All in arrays. Trade prices, ship types, government—arrays everywhere.

Your quiz uses the same technique. Five questions or five hundred—same code, different data.

## Common Array Mistakes

**1. Forgetting DIM:**
```basic
Q$(0)="TEST"      REM Error if no DIM first
```

**2. Off-by-one errors:**
```basic
DIM A(9)
FOR I=0 TO 10     REM Wrong! Only goes to 9
```

**3. Wrong index:**
```basic
DIM A(4)
PRINT A(5)        REM Error: index too high
```

**4. Mixing types:**
```basic
DIM NAME$(9)
NAME$(0)=100      REM Error: string array needs string
```

The C64 will give you `?BAD SUBSCRIPT ERROR` for index problems, `?TYPE MISMATCH ERROR` for type problems.

## Quick Reference

### Array Commands

| Command | Purpose | Example |
|---------|---------|---------|
| `DIM` | Create array | `DIM Q$(9)` |
| `DIM` multi-dimensional | Create grid/table | `DIM MAP(9,9)` |
| Array access | Get/set element | `Q$(5)="TEXT"` |
| Array in loop | Process all elements | `FOR I=0 TO 9:PRINT A(I):NEXT` |

### Array Index Rules

| Declaration | Elements | Indices | Count |
|-------------|----------|---------|-------|
| `DIM A(2)` | A(0), A(1), A(2) | 0-2 | 3 |
| `DIM A(9)` | A(0)...A(9) | 0-9 | 10 |
| `DIM A(99)` | A(0)...A(99) | 0-99 | 100 |

### Common Patterns

| Task | Pattern |
|------|---------|
| Initialize all | `FOR I=0 TO 9:A(I)=0:NEXT` |
| Find maximum | `FOR I=0 TO 9:IF A(I)>MAX THEN MAX=A(I):NEXT` |
| Search | `FOR I=0 TO 9:IF A(I)=TARGET THEN FOUND=I:I=9:NEXT` |
| Copy array | `FOR I=0 TO 9:B(I)=A(I):NEXT` |
