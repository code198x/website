## Decisions, Decisions

Games react. They cheer, warn, or punish depending on what the player does. In BASIC, that power comes from IF...THEN. You've learnt to store values in variables and repeat actions with loops—now you'll teach the C64 to make choices based on those values.

---

### The One-Minute Tour

- `IF` checks whether a condition is true
- Comparisons use operators like `=`, `<>`, `<`, `>`, `<=`, `>=`
- `THEN` tells BASIC what to do when the condition is true
- If the condition is false, BASIC skips to the next line

---

### Example Program

```basic
10 PRINT "WHAT IS 2+2?"
20 INPUT A
30 IF A=4 THEN PRINT "CORRECT!"
40 IF A<>4 THEN PRINT "NOT QUITE."
50 END
```

Sample output:

```
WHAT IS 2+2?
?4
CORRECT!
READY.
```

![Simple quiz showing correct answer](/images/commodore-64/phase-0/tier-1/lesson-004/example-1.png)

**Line 30** only executes when the answer equals 4.
**Line 40** catches every other value. Together they give instant feedback.

> **Tip:** When you use INPUT, BASIC automatically prints a `?` prompt. The user's answer is stored in variable A.

---

### Experiment Section

Try these variations:

- Change the answer: Replace 4 with another number
- Add a range check: `IF A>10 THEN PRINT "SHOW-OFF!"`
- Use GOTO: `IF A=4 THEN GOTO 100` to jump to a victory message
- Test multiple conditions with AND: `IF A>0 AND A<10 THEN PRINT "SINGLE DIGIT"`
- Test either condition with OR: `IF A=4 OR A=5 THEN PRINT "CLOSE ENOUGH"`

Build a simple number guessing game:

```basic
10 S=7
20 PRINT "GUESS A NUMBER (1-10)"
30 INPUT G
40 IF G=S THEN PRINT "YOU WIN!": GOTO 80
50 IF G<S THEN PRINT "TOO LOW!"
60 IF G>S THEN PRINT "TOO HIGH!"
70 GOTO 20
80 END
```

The program loops until you guess correctly, giving hints along the way.

### Concept Expansion

IF...THEN is the foundation of interactive programs. Combined with variables and loops, you can create menus, collision detection, win conditions, and branching stories. Later lessons will introduce GET for single-key input and RND for random conditions, making your decisions even more dynamic.

---

### Game Integration

- **Collision detection**: `IF X=EX AND Y=EY THEN GOSUB 500` (player hits enemy)
- **Health checks**: `IF HP<=0 THEN GOTO 9000` (game over)
- **Score milestones**: `IF SC>=100 THEN LV=LV+1` (level up)
- **Input validation**: `IF K$="Y" OR K$="N" THEN 100 ELSE 50` (menu choice)

### Quick Reference

| Operator | Meaning | Example | Result |
|----------|---------|---------|--------|
| `=` | Equal to | `IF A=5` | True when A is 5 |
| `<>` | Not equal to | `IF A<>5` | True when A is not 5 |
| `<` | Less than | `IF A<5` | True when A is less than 5 |
| `>` | Greater than | `IF A>5` | True when A is greater than 5 |
| `<=` | Less than or equal | `IF A<=5` | True when A is 5 or less |
| `>=` | Greater than or equal | `IF A>=5` | True when A is 5 or more |
| `AND` | Both conditions true | `IF A>0 AND A<10` | Both must be true |
| `OR` | Either condition true | `IF A=1 OR A=2` | One must be true |

**C64 BASIC stores input in uppercase by default**—compare with uppercase strings (`"Y"`, not `"y"`).

> **Note for .bas files:** The downloadable code samples use lowercase keywords (e.g., `if` instead of `IF`) for technical compatibility with the petcat converter tool.

### What You've Learnt

- IF...THEN lets BASIC make decisions instead of just following commands
- Comparison operators test relationships between values
- AND and OR combine multiple conditions
- You can branch to different lines or execute statements directly
- Decisions are essential for menus, collisions, and game logic
