# Lesson 3: Guess the Number

## The One-Minute Tour

- You've learnt INPUT, IF...THEN, and RND—now combine them into a complete game
- Games need feedback loops: guess → feedback → guess again
- Track score with a simple counter
- GET lets you check for keypresses without waiting
- This is your first proper game with replay and win conditions

## Your First Complete Game

Last lesson ended with a quiz that asked you questions. Now flip it—you pick a number, the computer tries to guess. But first, let's build the classic version: computer picks, you guess.

```basic
10 REM SIMPLE GUESS
20 PRINT CHR$(147);"GUESS MY NUMBER"
30 PRINT
40 N=INT(RND(1)*10)+1
50 PRINT "I'M THINKING OF 1-10"
60 PRINT
70 INPUT "YOUR GUESS";G
80 IF G=N THEN PRINT "YOU GOT IT!":END
90 IF G<N THEN PRINT "TOO LOW!":GOTO 70
100 IF G>N THEN PRINT "TOO HIGH!":GOTO 70
```

Type `RUN` and play.

**What's different from the quiz?** The computer picks a random number once (line 40), then you keep guessing until you're right. Lines 90 and 100 loop back to line 70 with `GOTO`—not to the start. The number stays the same.

![Simple guessing game](/images/commodore-64/phase-0/tier-1/lesson-003/example-1.png)

Try it. How many guesses does it take? Can you do better?

## Making It a Proper Game

That works, but it's not really a game yet. Games have:
- **Challenge:** Make it harder (1-100, not 1-10)
- **Score:** Track how many guesses you took
- **Replay:** Play again without retyping RUN
- **Records:** Track your best performance

Here's the complete version:

```basic
10 REM COMPLETE GAME
20 X=RND(-TI)
30 PRINT CHR$(147);"GUESS THE NUMBER"
40 PRINT
50 PRINT "BEST SCORE:";B
60 PRINT
70 N=INT(RND(1)*100)+1
80 T=0
90 PRINT "I'M THINKING OF 1-100"
100 PRINT
110 INPUT "GUESS";G
120 T=T+1
130 IF G=N THEN PRINT "YES! IN";T;"TRIES":GOTO 160
140 IF G<N THEN PRINT "HIGHER!":GOTO 110
150 IF G>N THEN PRINT "LOWER!":GOTO 110
160 IF B=0 OR T<B THEN B=T:PRINT "NEW RECORD!"
170 PRINT
180 PRINT "PLAY AGAIN? (Y/N)"
190 GET K$:IF K$="" THEN 190
200 IF K$="Y" THEN 30
210 PRINT CHR$(147);"FINAL SCORE:";B
220 PRINT "THANKS FOR PLAYING!"
```

Type `RUN` and play a few rounds.

**Key additions:**

Line 20: `X=RND(-TI)` seeds the random number generator from the system clock. Without this, you'd get the same number every time you power on.

Line 80: `T=0` resets the try counter at the start of each game.

Line 120: `T=T+1` counts each guess. This is fundamental—score, lives, bullets, enemies, everything counts this way.

Lines 140-150: Print feedback and loop back to line 110 for next guess using `GOTO`.

Line 160: Checks if you beat your best score. `B=0` catches the first game (no score yet). `T<B` checks if current tries beat previous best.

Lines 190-200: `GET K$` reads a single keypress without waiting for RETURN. The loop at 190 waits until you press something. If you press Y, jump to line 30 for a new game.

## Why This Matters

You've just written a complete game. Not a demo, not an example—a game with challenge, feedback, scoring, and replay. The structure you've built is identical to professional games:

1. **Initialize** (lines 10-60)
2. **Game loop** (lines 70-160)
3. **Win condition** (line 130)
4. **Score update** (line 170)
5. **Replay option** (lines 190-210)

Every game you'll ever write follows this pattern. Pac-Man, Space Invaders, Tetris—all use this structure. The complexity grows, but the foundation stays the same.

## How GET Works

`INPUT` waits for RETURN. Games can't wait—they need to check for input and keep running.

`GET` reads the keyboard buffer instantly:

```basic
GET K$
```

If a key is pressed, `K$` contains that character. If not, `K$` is empty (`""`).

**Common pattern:**
```basic
100 GET K$:IF K$="" THEN 100    REM Wait for keypress
110 IF K$="Y" THEN ...          REM Check what was pressed
```

This is how games check for movement, fire buttons, menu selections—anything that needs instant response.

**Important:** GET reads one character. You press SPACE, `K$` contains `" "`. You press A, `K$` contains `"A"`. No RETURN needed.

## Score Tracking Patterns

Line 120's `T=T+1` is your most important pattern. Every game uses it constantly:

```basic
S=S+10         REM Add 10 to score
L=L-1          REM Lose a life
B=B-1          REM Fire a bullet (decrement ammo)
E=E+1          REM Spawn another enemy
```

**Why `T=T+1` works:** Take current value of T, add 1, store result back in T. The computer reads T (current value), adds 1, writes the result back to T (new value).

**Other patterns:**
```basic
S=S*2          REM Double the score (power-up)
X=X+DX         REM Move by velocity (physics)
T=T-1:IF T&lt;0 THEN T=0    REM Countdown timer with floor
```

## Comparison Operators Refresher

Line 170 uses `OR` to check two conditions:

```basic
IF B=0 OR T<B THEN ...
```

**Complete set:**
- `=` equal to
- `<>` not equal to
- `<` less than
- `>` greater than
- `<=` less than or equal
- `>=` greater than or equal
- `AND` both true
- `OR` either true
- `NOT` invert

**Multiple conditions:**
```basic
IF A=5 AND B=10 THEN ...     REM Both must be true
IF A=5 OR B=10 THEN ...      REM Either can be true
IF NOT(A=5) THEN ...         REM Same as IF A<>5
```

## What You Can Change

**Experiment with the complete game:**

1. Change the range—try `RND(1)*1000` for 1-1000
2. Add lives—allow 10 wrong guesses before game over
3. Give hints—"You're getting warmer" if guess is closer than previous
4. Add difficulty levels—ask player to choose 1-10, 1-100, or 1-1000
5. Reverse it—you think of a number, computer guesses (use binary search!)

That last one's interesting. How would you make the computer guess efficiently?

## How Games Use This

**Elite** tracks hundreds of variables: fuel, missiles, cargo types, ship shields, reputation. Every action updates multiple counters using the `T=T+1` pattern.

**Jet Set Willy** checks keyboard constantly with GET-style logic. Press left? `X=X-1`. Press right? `X=X+1`. No waiting for INPUT.

**Boulder Dash** uses nested IF statements to check: Is this dirt? Can I dig? Is there a boulder above? Will it fall? Each check uses comparison operators and Boolean logic.

Your guessing game uses the same techniques, just simpler. You're learning the real tools, not toy versions.

## The Feedback Loop

Games are built on feedback loops:

```
Player action → Game responds → Player adapts → Repeat
```

Your guessing game:
- You guess → "Too high!" → You guess lower → "Too low!" → You narrow the range → "Yes!"

**This loop is everything.** Make it tight, clear, and satisfying, and you've got a game. Make it confusing or slow, and players quit.

**Elements of good feedback:**
1. **Immediate:** Response happens instantly (not after 5 more guesses)
2. **Clear:** "Higher" means something specific, not "Maybe try something else?"
3. **Useful:** Helps player improve their next action
4. **Satisfying:** Colours, sounds, text that feels good

Your game has all four. That's why it works.

## Quick Reference

### Commands You've Combined

| Pattern | Example | Use |
|---------|---------|-----|
| Random range | `INT(RND(1)*100)+1` | Pick number 1-100 |
| Counter | `T=T+1` | Track guesses, score, anything |
| Loop until condition | `GOTO 60` | Keep asking for guesses |
| Multiple IF checks | Lines 140-150 | Compare and respond |
| OR condition | `IF B=0 OR T<B` | Check either condition |
| GET keypress | `GET K$:IF K$=""` | Non-blocking input |
| END | `END` | Stop program completely |

### GET vs INPUT

| Command | Waits? | Needs RETURN? | Use Case |
|---------|--------|---------------|----------|
| INPUT | Yes | Yes | Turn-based, answers |
| GET | No | No | Real-time, movement |
