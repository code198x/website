# Lesson 2: Maths Master

## The One-Minute Tour

- `INPUT` lets the computer ask questions and wait for your answers
- `IF...THEN` makes decisions based on what you type
- `RND(1)` generates random numbers for endless variety
- `INT()` turns decimal numbers into whole numbers
- Together, these create a proper quiz game

## Your First Interactive Program

Last lesson, the computer just counted. This time, it's going to ask you questions:

```basic
10 REM SIMPLE QUIZ
20 PRINT CHR$(147);"MATHS MASTER"
30 PRINT
40 PRINT "WHAT IS 5 + 3?"
50 INPUT A
60 IF A=8 THEN PRINT "CORRECT!":GOTO 80
70 PRINT "WRONG! IT'S 8"
80 PRINT
90 PRINT "WHAT IS 10 - 4?"
100 INPUT A
110 IF A=6 THEN PRINT "CORRECT!" ELSE PRINT "WRONG! IT'S 6"
```

Type `RUN` and answer the questions.

**What's happening?** Line 50 waits for you to type a number and press RETURN. The computer stores your answer in variable `A`. Line 60 checks: is `A` equal to 8? If yes, print "CORRECT!" and jump to line 80. If no, continue to line 70 which tells you the right answer.

![Simple maths quiz](/images/commodore-64/phase-0/tier-1/lesson-002/example-1.png)

Notice line 110 shows a shortcut: `IF...THEN...ELSE` lets you handle both correct and wrong answers in one line.

## Making It Endless

That quiz gets boring fast—same questions every time. Let's make the computer generate random questions:

```basic
10 REM RANDOM QUIZ
20 PRINT CHR$(147);"MATHS MASTER"
30 PRINT
40 A=INT(RND(1)*10)+1
50 B=INT(RND(1)*10)+1
60 C=A+B
70 PRINT "WHAT IS ";A;" + ";B;"?"
80 INPUT ANS
90 IF ANS=C THEN PRINT CHR$(30);"CORRECT!":S=S+1:GOTO 110
100 PRINT CHR$(28);"WRONG! IT'S ";C
110 PRINT
120 PRINT "SCORE: ";S
130 FOR D=1 TO 500:NEXT D
140 GOTO 40
```

Type `RUN` and watch.

**What's different?** Lines 40-50 generate random numbers between 1 and 10. Line 60 calculates the answer. Line 70 prints the question using those random numbers. Line 90 adds colour (`CHR$(30)` = green) and tracks your score in variable `S`. Line 140 loops back to generate a new question.

![Random quiz with scoring](/images/commodore-64/phase-0/tier-1/lesson-002/example-2.png)

## Why This Matters

INPUT and IF...THEN are the foundation of interactive games. Every game you've ever played uses these concepts constantly:

**INPUT** waits for player action - keyboard, joystick, button press
**IF...THEN** decides what happens - hit or miss, alive or dead, win or lose

You've just written a game loop with player interaction. The structure is the same whether you're answering quiz questions or dodging asteroids.

## How INPUT Works

`INPUT` pauses your program and displays a question mark. When you type a number and press RETURN, the C64 stores that value in a variable:

```basic
INPUT A          : REM Stores number in A
INPUT N$         : REM Stores text in N$ (string variable)
INPUT "AGE";A    : REM Shows "AGE?" before waiting
```

**Important:** INPUT stops everything. The program waits. Games need to check for input *without* waiting—you'll learn that technique later when we read joysticks.

## How IF...THEN Works

`IF...THEN` checks a condition. If true, execute the command after THEN:

```basic
IF A=8 THEN PRINT "YES"           : REM Single command
IF A=8 THEN PRINT "YES":GOTO 100  : REM Multiple commands with :
IF A<>8 THEN PRINT "NO"           : REM <> means "not equal"
IF A>5 THEN PRINT "BIG"           : REM Greater than
IF A&lt;5 THEN PRINT "SMALL"         : REM Less than
```

**IF...THEN...ELSE** handles both true and false:

```basic
IF A=8 THEN PRINT "YES" ELSE PRINT "NO"
```

This saves lines compared to separate IF statements.

## How RND() Works

`RND(1)` generates a random decimal number between 0 and 0.999999:

```basic
PRINT RND(1)    : REM Might print 0.347582
```

That's not useful for dice or quiz questions. Use `INT()` to convert:

```basic
INT(RND(1)*6)+1       : REM Random 1-6 (dice)
INT(RND(1)*10)+1      : REM Random 1-10 (our quiz)
INT(RND(1)*100)       : REM Random 0-99
```

**The formula:** `INT(RND(1)*RANGE)+START`

Want random numbers 50-99? `INT(RND(1)*50)+50`

## What You Can Change

**Experiment with the random quiz:**

1. Change the range - try `*20` for harder questions
2. Add subtraction - change `C=A+B` to `C=A-B` and the question text
3. Add multiplication - `C=A*B`
4. Make it timed - add a countdown (we'll learn this properly in L15)
5. Change the colours - `CHR$(28)` is red, `CHR$(31)` is blue

Don't be afraid to break things. Type `RUN` and see what happens. The worst case: it doesn't work, you retype the line.

## How Games Use This

**Elite** uses IF...THEN to check if you can afford fuel, weapons, cargo. Every purchase decision: IF MONEY >= PRICE THEN...

**Zork** (text adventure) uses INPUT for every command - GET LAMP, OPEN DOOR, GO NORTH. Thousands of IF...THEN statements check what you typed.

**Pac-Man** uses IF...THEN hundreds of times per second - if touching ghost, if touching pill, if all pills eaten, if power-up active...

Your quiz program uses the same structure. The difference is speed and complexity, not concept.

## Understanding Variables

Variables store values. Think of them as labelled boxes:

```basic
A=5        : REM Box labelled "A" contains 5
B=10       : REM Box labelled "B" contains 10
C=A+B      : REM Box labelled "C" contains 15
```

**Variable names:**
- Single letter: `A`, `B`, `Z` (fastest)
- Letter + digit: `A1`, `X9`, `S3`
- Strings: `N$`, `NAME$`, `A$` (use $ for text)

**The `S=S+1` trick:** Line 90 does `S=S+1`. This means "take whatever's in S, add 1, store result back in S". It's how you count things. Score, lives, bullets, enemies—all use this pattern.

## From the Vault

The C64's `RND()` function uses a pseudo-random number generator - a mathematical formula that produces numbers that *look* random but follow a predictable sequence. Every time you turn on the C64, RND() starts at the same point, giving the same sequence. That's why games ask "PRESS SPACE TO START"—the delay provides enough randomness to offset the sequence.

INPUT buffers your keystrokes, storing up to 80 characters before processing. Type fast enough and you can answer several questions before the program catches up.

IF...THEN is relatively slow in BASIC - checking conditions takes time. Games that need speed (collision detection, AI) often use lookup tables or mathematical tricks instead. But for turn-based games and quizzes, IF...THEN is perfect.

## Quick Reference

### Commands You've Learnt

| Command | What It Does | Example |
|---------|--------------|---------|
| `INPUT` | Wait for user to type value | `INPUT A` |
| `INPUT "TEXT";` | Show prompt before input | `INPUT "AGE";A` |
| `IF...THEN` | Execute command if true | `IF A=5 THEN PRINT "YES"` |
| `IF...THEN...ELSE` | Handle true and false | `IF A=5 THEN PRINT "YES" ELSE PRINT "NO"` |
| `RND(1)` | Random decimal 0-0.999999 | `R=RND(1)` |
| `INT()` | Convert to whole number | `INT(3.7)` gives 3 |

### Comparison Operators

| Operator | Meaning | Example |
|----------|---------|---------|
| `=` | Equal to | `IF A=5` |
| `<>` | Not equal to | `IF A<>5` |
| `>` | Greater than | `IF A>5` |
| `<` | Less than | `IF A&lt;5` |
| `>=` | Greater than or equal | `IF A>=5` |
| `<=` | Less than or equal | `IF A&lt;=5` |

### Random Number Formulas

| Range | Formula | Example Result |
|-------|---------|----------------|
| 0-9 | `INT(RND(1)*10)` | 7 |
| 1-10 | `INT(RND(1)*10)+1` | 3 |
| 1-6 | `INT(RND(1)*6)+1` | 5 (dice) |
| 10-20 | `INT(RND(1)*11)+10` | 14 |
| 0-99 | `INT(RND(1)*100)` | 67 |
