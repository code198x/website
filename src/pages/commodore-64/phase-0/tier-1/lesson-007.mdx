## Touching the Hardware

You've been printing text and storing data—but now you're going to touch the hardware directly. The C64's screen isn't just a display; it's controlled by a chip called the VIC-II. By writing numbers to specific memory addresses, you command the chip to change colours, move graphics, and more. This is real computer control.

---

### The One-Minute Tour

- Memory addresses are numbered locations where data is stored
- `POKE address,value` writes a byte directly to memory
- Address 53280 controls the border colour (VIC-II register)
- Address 53281 controls the background colour (VIC-II register)
- Colour values range from 0 to 15 (16 colours available)

---

### Example Program

```basic
10 POKE 53280,0
20 POKE 53281,0
30 PRINT CHR$(147);"BLACK SCREEN"
40 FOR I=1 TO 2000:NEXT I
50 POKE 53280,6
60 POKE 53281,14
70 PRINT CHR$(147);"BLUE SCREEN"
80 END
```

Sample output:

```
BLACK SCREEN
(pause)
BLUE SCREEN
READY.
```

![Border and background colour changes](/images/commodore-64/phase-0/tier-1/lesson-007/example-1.png)

**Line 10** sets border to black (0). **Line 20** sets background to black (0). **Line 30** clears screen and prints text. **Lines 40** creates a delay. **Lines 50-60** change to blue border (6) and light blue background (14). **Line 70** clears and prints again.

> **Tip:** `CHR$(147)` sends the clear screen character (SHIFT+CLR/HOME on the keyboard). It's the same as pressing those keys.

### Experiment Section

Try these variations:

- **Different colours**: Try POKE 53280,2 (red) or POKE 53280,5 (green)
- **Match border and background**: `POKE 53280,1:POKE 53281,1` for all white
- **Colour cycling**: Use a FOR loop to change colours automatically
- **Random colours**: `POKE 53280,INT(RND(1)*16)` for random border
- **User choice**: INPUT a colour number, then POKE it

Build a simple colour selector:

```basic
10 PRINT CHR$(147);"COLOR SELECTOR"
20 PRINT
30 PRINT "0=BLACK   1=WHITE   2=RED"
40 PRINT "3=CYAN    4=PURPLE  5=GREEN"
50 PRINT "6=BLUE    7=YELLOW  8=ORANGE"
60 PRINT "9=BROWN  10=LT RED 11=DK GREY"
70 PRINT "12=GREY  13=LT GRN 14=LT BLUE"
80 PRINT "15=LT GREY"
90 PRINT
100 INPUT "BORDER COLOR";B
110 INPUT "BACKGROUND COLOR";BG
120 POKE 53280,B
130 POKE 53281,BG
140 PRINT CHR$(147);"YOUR CHOICE!"
150 END
```

The program displays the 16 available colours and lets you choose border and background values.

### Concept Expansion

**You're controlling the VIC-II chip.** The C64's graphics are handled by the VIC-II (Video Interface Chip II), designed by Al Charpentier and Charles Winterble at MOS Technology. When you POKE 53280, you're not "setting a variable"—you're writing directly to a hardware register inside the VIC-II. The chip reads that value 50 times per second (PAL) or 60 times per second (NTSC) and generates the border colour on your screen.

**Memory-mapped I/O:** The C64 doesn't have separate "commands" for hardware—instead, the chips are connected to specific memory addresses. POKE is your direct line to the hardware. Later lessons will use this same technique to control sprites, sound, and scrolling.

### Game Integration

- **Mood setting**: Change colours when entering dangerous areas (red) or safe zones (green)
- **Danger warnings**: Flash the border red when health is low
- **Level identification**: Each level has its own colour scheme
- **Screen transitions**: Fade between colours when changing screens
- **Visual feedback**: Border flash on collision or pickup

### Quick Reference

| Address | Controls | Values |
|---------|----------|--------|
| `53280` | Border colour | 0-15 |
| `53281` | Background colour | 0-15 |

**C64 Colour Values:**
```
 0 = Black        4 = Purple       8 = Orange      12 = Grey
 1 = White        5 = Green        9 = Brown       13 = Light Green
 2 = Red          6 = Blue        10 = Light Red   14 = Light Blue
 3 = Cyan         7 = Yellow      11 = Dark Grey   15 = Light Grey
```

**POKE syntax:** `POKE address,value` — writes value (0-255) to address

**Multiple POKEs:** `POKE 53280,1:POKE 53281,0` — use `:` to chain statements

> **Note for .bas files:** The downloadable code samples use lowercase keywords (e.g., `poke` instead of `POKE`) for technical compatibility with the petcat converter tool.
