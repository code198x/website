Every program you've written so far used PRINT and INPUT—operating system functions that handle the screen for you. But the C64's display isn't controlled by software. It's controlled by a chip called the VIC-II, and that chip has 47 registers sitting at specific memory addresses, waiting for you to write numbers into them.

`POKE 53280,5` changes the border to green instantly. You're not asking permission. You're writing directly to hardware.

## The One-Minute Tour

- Memory address **53280** controls the border colour
- `POKE address,value` writes a number to any memory location
- VIC-II chip reads these addresses 50 times per second (PAL) / 60 times (NTSC)
- Colours are numbered 0-15 (see Quick Reference below)
- Animation = loop that POKEs different values repeatedly

## First Example: Experiment with Colours

Type this and try different colour numbers:

```basic
10 REM SINGLE COLOUR
20 PRINT CHR$(147);"POKE 53280,COL"
30 PRINT
40 PRINT "TRY DIFFERENT COLOURS:"
50 INPUT "COLOUR (0-15)";C
60 POKE 53280,C
70 GOTO 50
```

**Run this** and try numbers from 0 to 15. Watch the border change instantly—no delay, no redraw. The VIC-II chip updates the border every frame, reading from memory address 53280 to see what colour it should be.

## Second Example: Rainbow Animation

Now let's create a cycling rainbow effect:

```basic
10 REM RAINBOW BORDER
20 C=0
30 POKE 53280,C
40 C=C+1
50 IF C>15 THEN C=0
60 FOR D=1 TO 50:NEXT D
70 GOTO 30
```

**Run this** and watch the border cycle through all 16 colours continuously. Press RUN/STOP + RESTORE to exit.

![Animated rainbow border effect](/images/commodore-64/phase-0/tier-1/lesson-007/example-2.png)

The border cycles smoothly through every colour. This is real hardware animation—changing what the VIC-II chip displays by writing to its memory-mapped registers.

## How POKE and Memory-Mapped Hardware Work

**Memory address 53280** isn't RAM that stores your data. It's a *register* in the VIC-II chip. When you `POKE 53280,5`, the number 5 appears in that register, and the VIC-II reads it during the next video frame to determine what colour to draw the border.

**Line 30: POKE 53280,C**

This writes the current value of variable `C` to memory address 53280. The VIC-II chip reads this address constantly (50/60 times per second), so the border changes colour immediately.

**Lines 40-50: Cycle Through Colours**

`C=C+1` increments the colour number. When it reaches 16, line 50 resets it to 0. This creates an infinite loop through all 16 colours.

**Line 60: Delay Loop**

`FOR D=1 TO 50:NEXT D` creates a small delay. Without this, the colours change so fast you'd see a flickering blur. The delay lets you see each colour briefly before moving to the next.

**Important:** Adjusting the delay value changes animation speed. `FOR D=1 TO 10` makes it faster, `FOR D=1 TO 100` makes it slower.

## Why This Matters

You've just controlled hardware directly. The VIC-II chip doesn't know or care that you're using BASIC—it just reads memory addresses and displays what it finds there. Later lessons will use the same technique to:

- Draw graphics to screen memory (lesson 8)
- Control sprites (lesson 17+)
- Create split-screen effects (lesson 54+)

Direct hardware control is what makes the C64 programmable. Everything from border colours to sprite positions works the same way: find the right memory address, POKE the right value.

## Experiments to Try

**1. Change the Background**

Try `POKE 53281,C` instead of 53280. Address 53281 controls the background colour, not the border.

**2. Both at Once**

Add this after line 30:
```basic
35 POKE 53281,15-C
```

Now the background and border cycle in opposite directions through the colour palette.

**3. Faster Animation**

Change line 60 to `FOR D=1 TO 10:NEXT D`. The colours cycle much faster. Too fast? Increase the number.

**4. Only Specific Colours**

Replace lines 20-50 with DATA and READ to cycle through only the colours you choose:
```basic
20 RESTORE
25 READ C
30 POKE 53280,C
35 FOR D=1 TO 80:NEXT D
40 GOTO 20
100 DATA 6,14,3,5,13,7
```

This cycles through the DATA colours only (blue, light blue, cyan, green, light green, yellow).

## Quick Reference

### VIC-II Colour Registers

| Address | Controls | Range |
|---------|----------|-------|
| 53280 | Border colour | 0-15 |
| 53281 | Background colour | 0-15 |

### Colour Numbers (0-15)

| # | Colour | # | Colour |
|---|--------|---|--------|
| 0 | Black | 8 | Orange |
| 1 | White | 9 | Brown |
| 2 | Red | 10 | Light red |
| 3 | Cyan | 11 | Dark grey |
| 4 | Purple | 12 | Grey |
| 5 | Green | 13 | Light green |
| 6 | Blue | 14 | Light blue |
| 7 | Yellow | 15 | Light grey |

### POKE Command

```basic
POKE address,value    REM Write value to memory address
```

**Example:** `POKE 53280,6` sets border to blue

**Rules:**
- Address must be 0-65535 (16-bit address space)
- Value must be 0-255 (8-bit value)
- Takes effect immediately (no delay)
- VIC-II reads registers every frame (50/60 Hz)

## What You've Learnt

- Memory address 53280 controls the border colour via the VIC-II chip
- POKE writes values directly to hardware registers
- VIC-II updates the display every frame by reading memory
- Animation loops change POKE values repeatedly
- Hardware control is immediate—no operating system delay

You've crossed from software to hardware. Up until now, you were asking the C64's operating system to do things for you. Now you're writing directly to the chips that generate the video signal.
