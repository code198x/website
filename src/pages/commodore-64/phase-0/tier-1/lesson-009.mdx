Lessons 1-8 taught you to create output: printing text, changing colours, drawing patterns. But games need input—they respond to what you do. The GET command reads a single keypress without stopping the program, enabling real-time keyboard control.

**This lesson builds a PETSCII drawing tool** where you move a cursor and paint characters—combining everything you've learnt into your first truly interactive program.

## The One-Minute Tour

- **GET reads keyboard input without waiting** (unlike INPUT which stops and waits)
- Returns empty string `""` if no key is pressed
- Typical pattern: `GET K$:IF K$="" THEN [loop back]`
- Enables real-time control (games, tools, animations)
- Combined with screen memory POKEs = instant visual feedback
- Main loop structure: get input → process input → update screen → repeat

## First Example: Interactive Box Designer

Type this program and run it:

```basic
10 REM BOX DESIGNER
20 PRINT CHR$(147);CHR$(5)
30 PRINT "BOX DESIGNER"
40 PRINT
50 PRINT "USE I/J/K/M TO MOVE"
60 PRINT "SPACE TO DRAW"
70 PRINT "C TO CLEAR"
80 PRINT "Q TO QUIT"
90 PRINT
100 X=20:Y=12
110 GET K$:IF K$="" THEN 110
120 IF K$="I" THEN Y=Y-1
130 IF K$="M" THEN Y=Y+1
140 IF K$="J" THEN X=X-1
150 IF K$="K" THEN X=X+1
160 IF X&lt;0 THEN X=0
170 IF X>39 THEN X=39
180 IF Y&lt;0 THEN Y=0
190 IF Y>24 THEN Y=24
200 IF K$=" " THEN POKE 1024+(Y*40)+X,160
210 IF K$="C" THEN FOR I=0 TO 999:POKE 1024+I,32:NEXT I
220 IF K$="Q" THEN END
230 GOTO 110
```

**Run this** and try the controls.

![Box Designer start screen](/images/commodore-64/phase-0/tier-1/lesson-009/example-1.png)

The program waits for keypresses and responds instantly. Press I/J/K/M to move an invisible cursor, SPACE to draw a character at that position, C to clear the screen, Q to quit. This is the core structure of every interactive C64 program.

**What you can draw:**

![Box drawn with the designer](/images/commodore-64/phase-0/tier-1/lesson-009/example-2.png)

Using the movement keys and SPACE, you can draw boxes, patterns, and simple graphics. The program tracks your X/Y position and POKEs screen codes wherever you press SPACE.

## How GET Works

**INPUT vs GET:**
- `INPUT` stops the program and waits for ENTER
- `GET` checks if a key is pressed RIGHT NOW and continues immediately
- `GET` never stops the program—perfect for games and tools

**The GET pattern:**
```basic
110 GET K$:IF K$="" THEN 110
```

Line 110 checks the keyboard. If no key is pressed (`K$=""`), it loops back to 110 and checks again. This creates a waiting loop that doesn't proceed until you press a key. Once K$ contains something, the program continues to the next line.

**Why this works:**
- C64 keyboard is memory-mapped (like screen and VIC-II)
- GET reads the keyboard buffer—a special memory location
- Returns immediately with either a character or empty string
- Doesn't echo the character to screen (unlike INPUT)

## Program Structure Breakdown

**Initialisation (lines 20-100):**
- Clear screen and set white text (`CHR$(147)` and `CHR$(5)`)
- Print instructions
- Set starting cursor position (`X=20:Y=12`—centre of screen)

**Main Loop (lines 110-230):**
- **110**: Wait for keypress
- **120-150**: Movement controls (I=up, M=down, J=left, K=right)
- **160-190**: Boundary checking (keep X and Y within 0-39 and 0-24)
- **200**: Draw command (SPACE key POKEs character 160 to screen)
- **210**: Clear command (C key fills entire screen with spaces)
- **220**: Quit command (Q key ends program)
- **230**: Loop back to get next keypress

**The address calculation:**
```basic
200 IF K$=" " THEN POKE 1024+(Y*40)+X,160
```

This converts X/Y coordinates to a screen memory address using the formula from Lesson 8. Screen code 160 is a filled block character.

## Why This Pattern Matters

Every C64 game uses variations of this structure:

**1. Get input** → `GET K$`
**2. Process input** → Check what key was pressed
**3. Update game state** → Change positions, scores, etc.
**4. Update display** → POKE to screen memory
**5. Loop** → `GOTO` back to step 1

**Space Invaders:** GET controls ship movement, SPACE fires bullets  
**Pac-Man:** GET reads joystick (via PEEK, covered later), updates position  
**Boulder Dash:** GET for direction, complex logic for game rules, POKE for graphics

This Box Designer demonstrates the pattern in its simplest form. Later lessons add:
- Collision detection (checking what's already on screen)
- Timing (making things move automatically)
- Sound effects (SID chip control)
- Joystick input (CIA chip reading)

## Experiments to Try

**1. Change the draw character:**
```basic
200 IF K$=" " THEN POKE 1024+(Y*40)+X,109
```
Try different screen codes: 109 (circle), 108 (checkerboard), 64 (horizontal line)

**2. Add an erase key:**
```basic
205 IF K$="E" THEN POKE 1024+(Y*40)+X,32
```

**3. Add colour changing:**
```basic
215 IF K$="1" THEN POKE 53280,0:REM BLACK BORDER
216 IF K$="2" THEN POKE 53280,1:REM WHITE BORDER
217 IF K$="3" THEN POKE 53280,2:REM RED BORDER
```

**4. Draw a line of characters:**
```basic
200 IF K$=" " THEN FOR I=0 TO 10:POKE 1024+(Y*40)+X+I,160:NEXT I
```

## Understanding the Main Loop

The infinite loop (`GOTO 110`) is fundamental to interactive programs:

**Without loop:**
```basic
110 GET K$
120 IF K$="i" THEN Y=Y-1
130 END
```
This checks keyboard once and quits. Useless.

**With loop:**
```basic
110 GET K$:IF K$="" THEN 110
120 IF K$="i" THEN Y=Y-1
...
230 GOTO 110
```
This checks keyboard forever. Interactive.

The loop must be fast enough that keypresses feel immediate. In BASIC, GET loops run thousands of times per second—plenty fast for keyboard input. When we move to joystick control and sprites (later lessons), we'll need assembly language for smooth 50/60 FPS animation.

## Quick Reference

### GET Command

```basic
GET variable$    REM Read single keypress
```

**Returns:**
- Empty string `""` if no key pressed
- Single character if key pressed
- Doesn't wait—continues immediately

### Common GET Patterns

**Wait for any key:**
```basic
10 GET K$:IF K$="" THEN 10
```

**Wait for specific key:**
```basic
10 GET K$
20 IF K$<>"Y" THEN 10
```

**Check multiple keys:**
```basic
10 GET K$:IF K$="" THEN 10
20 IF K$="W" THEN Y=Y-1
30 IF K$="S" THEN Y=Y+1
40 GOTO 10
```

### Key Codes

GET returns:
- Letters: `"A"` to `"Z"` (uppercase only)
- Numbers: `"0"` to `"9"`
- Space: `" "`
- RETURN: `CHR$(13)`
- Special keys: Depends on key (check with `PRINT ASC(K$)`)

### Main Loop Template

```basic
100 REM initialise variables
110 GET K$:IF K$="" THEN 110
120 REM process keypresses
...
230 GOTO 110
```
