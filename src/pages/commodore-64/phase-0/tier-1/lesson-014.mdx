## Collision and Scoring

You've learnt how to move characters around the screen, read the keyboard, play sounds, and generate random numbers. Now it's time to make these elements interact—checking when things collide, tracking scores, and creating simple game mechanics.

## The One-Minute Tour

- **Position-based collision detection** checks if two screen coordinates match
- **Score tracking** uses variables to count events and check win conditions
- **Screen code arithmetic** converts numbers to displayable digits (48-57)
- **Erase-move-redraw** creates smooth animation for falling objects
- **Game loops** combine input, logic, and display updates

## When Things Touch

The simplest form of collision detection compares positions. If the player's X and Y coordinates match an object's X and Y coordinates, they've collided.

```basic
10 REM collision detection
20 PRINT CHR$(147):POKE 53280,0:POKE 53281,0
30 PX=10:PY=10:TX=15:TY=10
40 POKE 1024+PY*40+PX,81:POKE 55296+PY*40+PX,1
50 POKE 1024+TY*40+TX,42:POKE 55296+TY*40+TX,7
60 GET A$:IF A$="" THEN 60
70 IF A$="Q" THEN END
80 POKE 1024+PY*40+PX,32
90 IF A$="W" AND PY>0 THEN PY=PY-1
100 IF A$="S" AND PY<24 THEN PY=PY+1
110 IF A$="A" AND PX>0 THEN PX=PX-1
120 IF A$="D" AND PX<39 THEN PX=PX+1
130 IF PX=TX AND PY=TY THEN PRINT "HIT!":FOR I=1 TO 500:NEXT I:END
140 POKE 1024+PY*40+PX,81:POKE 55296+PY*40+PX,1
150 GOTO 60
```

![Player (Q) hitting target (asterisk) with HIT message](/images/commodore-64/phase-0/tier-1/lesson-014/example-1.png)

**Line 30** sets starting positions: player at (10,10), target at (15,10)
**Lines 40-50** draw both characters with their colours
**Line 130** checks collision: `IF PX=TX AND PY=TY`—both coordinates must match
**Lines 80-120** handle movement, erasing the old position first

The C64 BASIC **AND** operator lets you combine conditions. Both must be true for the collision to register. Note the erase-before-move pattern: we POKE 32 (space) to clear the old position before updating PX or PY.

## Keeping Score

Games need goals. Score tracking uses a variable to count successes and check for victory.

```basic
10 REM score and win condition
20 PRINT CHR$(147)
30 SC=0:WI=10
40 PRINT "COLLECT 10 ITEMS!"
50 PRINT:PRINT "SCORE:";SC
60 PRINT "PRESS SPACE TO COLLECT"
70 GET A$:IF A$="" THEN 70
80 IF A$=" " THEN SC=SC+1
90 PRINT CHR$(147)
100 PRINT "SCORE:";SC
110 IF SC>=WI THEN PRINT:PRINT "YOU WIN!":END
120 GOTO 60
```

![Score display showing 10 with YOU WIN message](/images/commodore-64/phase-0/tier-1/lesson-014/example-2.png)

**Line 30** initialises score (`SC=0`) and win threshold (`WI=10`)
**Line 80** increments score when spacebar pressed
**Line 110** checks win condition: `IF SC>=WI`

The `>=` comparison operator checks if score has reached or exceeded the win threshold. This prevents missing the exact value if you accidentally skip it.

**Variable naming gotcha:** We use `WI` instead of `GOAL` or `TARGET` because those start with reserved keywords (`GO` and `TA`). C64 BASIC's keyword matching can cause "SYNTAX ERROR" even when the full word isn't a keyword. Short, simple variable names avoid these conflicts.

## Catch the Falling Objects

Combining movement, collision detection, and scoring creates a simple catch game.

```basic
10 REM catch falling objects
20 PRINT CHR$(147):POKE 53280,0:POKE 53281,0
30 PX=20:PY=23:SC=0:OY=0:OX=INT(RND(1)*40)
40 POKE 1024+PY*40+PX,81:POKE 55296+PY*40+PX,1
50 POKE 1024+OY*40+OX,42:POKE 55296+OY*40+OX,7
60 POKE 1024+24*40,SC+48
70 GET A$
80 IF A$="A" AND PX>0 THEN POKE 1024+PY*40+PX,32:PX=PX-1
90 IF A$="D" AND PX<39 THEN POKE 1024+PY*40+PX,32:PX=PX+1
100 POKE 1024+PY*40+PX,81:POKE 55296+PY*40+PX,1
110 FOR I=1 TO 5:NEXT I
120 POKE 1024+OY*40+OX,32
130 OY=OY+1
140 IF OY>24 THEN OY=0:OX=INT(RND(1)*40)
150 IF OY=PY AND OX=PX THEN SC=SC+1:OY=0:OX=INT(RND(1)*40)
160 POKE 1024+OY*40+OX,42:POKE 55296+OY*40+OX,7
170 POKE 1024+24*40,SC+48
180 GOTO 70
```

![Catch game with player at bottom, falling asterisk, score showing 2](/images/commodore-64/phase-0/tier-1/lesson-014/example-3.png)

**Line 30** initialises player position (PX, PY), score (SC), and object position (OX, OY)
**Lines 110-120** erase old object position, increment Y coordinate
**Line 140** resets object to top with new random X if it falls off screen
**Line 150** checks collision and increments score
**Line 170** displays score by adding 48 to convert number to screen code

The **erase-move-redraw** cycle prevents flickering and trails:
1. POKE 32 to clear old position (line 120)
2. Update coordinates (line 130)
3. POKE new character (line 160)

**Screen code arithmetic:** Screen codes 48-57 represent digits 0-9. Adding 48 to a number converts it to the corresponding digit character. So `SC=2` becomes `2+48=50`, which is screen code for "2".

**Delay loop** (line 110): `FOR I=1 TO 5:NEXT I` creates a brief pause, slowing the object's fall to a playable speed. Higher values mean slower falling.

## How Games Use This

**Elite** tracked numerous variables: fuel, missiles, cargo, credits, and legal status. Each had win/lose implications—run out of fuel in deep space, game over.

**Paradroid** used position-based collision to detect when your droid touched enemy droids, triggering the circuit-board takeover minigame.

**Boulder Dash** checked collision on every move: touching a boulder made it fall, touching a diamond collected it, touching a monster killed you. Simple position checks created complex, emergent gameplay.

**Jumpman** (1983) used the erase-move-redraw pattern for smooth character animation. The falling bomb sprites used similar logic to our falling objects—position, gravity, collision with platforms.

## Quick Reference

**Collision Detection Pattern:**
```
IF PX=TX AND PY=TY THEN [action]
```

**Score Tracking:**
```
SC=0          : Initialize score
SC=SC+1       : Increment score
IF SC>=WI     : Check win condition
```

**Screen Code Conversion:**
```
Digit 0-9 = Number + 48
POKE 1024, SC+48  : Display single-digit score
```

**Erase-Move-Redraw:**
```
POKE addr,32     : Erase old position
[update coords]  : Change X/Y values
POKE addr,char   : Draw new position
```

**C64 BASIC Operators:**
| Operator | Meaning | Example |
|----------|---------|---------|
| `=` | Equal to | `IF X=Y` |
| `<>` | Not equal | `IF X<>Y` |
| `>` | Greater than | `IF X>Y` |
| `<` | Less than | `IF X<Y` |
| `>=` | Greater/equal | `IF SC>=10` |
| `<=` | Less/equal | `IF PY<=24` |
| `AND` | Both true | `IF X=5 AND Y=10` |
| `OR` | Either true | `IF A$="W" OR A$="S"` |
