# The Clock Is Ticking

You've built a complete game with collision detection, scoring, and win/lose conditions. But something's missing—**time pressure**. Without a countdown timer, players can take as long as they like. With one, suddenly every second counts.

The C64 has a built-in clock that's perfect for game timers. It's called **TI** (short for "Time Interval"), and it counts at exactly 60 ticks per second. Every jiffy that passes, TI increases by one. You don't update it—the hardware does that automatically in the background.

## The One-Minute Tour

- **TI is a system variable** that counts jiffies (1/60th of a second)
- Jiffies tick automatically in the background—you just read them
- Store TI at game start, then calculate elapsed time as (TI - start)
- Divide jiffies by 60 to convert to seconds: `INT((TI-T1)/60)`
- TI resets to 0 after 24 hours (rare in games, but possible)
- Use TI$ to set the clock: `TI$="000000"` resets to midnight
- Countdown timer: `remaining = time_limit - elapsed`
- Common pattern: check timer in main loop, trigger events when it runs out

## Example Programme: Simple Countdown

Let's create a 30-second countdown timer that changes the border colour when time is running out:

```basic
10 REM COUNTDOWN TIMER
20 PRINT CHR$(147)
30 PRINT "COUNTDOWN TIMER DEMO"
40 PRINT
50 TL=30
60 T1=TI
70 REM MAIN LOOP
80 E=INT((TI-T1)/60)
90 R=TL-E
100 POKE 1024,32
110 PRINT CHR$(19);
120 PRINT "TIME LEFT:";R;" SECONDS"
130 IF R&lt;=0 THEN 200
140 IF R&lt;=10 THEN POKE 53280,2
150 GOTO 80
200 REM TIME UP
210 PRINT CHR$(147)
220 PRINT "TIME'S UP!"
230 END
```

![Countdown timer running](/images/commodore-64/phase-0/tier-1/lesson-015/example-1.png)

**What's happening here:**

Line 50 sets TL (Time Limit) to 30 seconds. Line 60 stores the current time in T1—this is our starting point.

Line 80 calculates how many seconds have elapsed. TI-T1 gives us the number of jiffies that have passed. Dividing by 60 converts that to seconds, and INT() removes any decimal places so we get a whole number.

Line 90 calculates how many seconds remain: total time minus elapsed time.

Line 110 uses CHR$(19), which is the "home" cursor command—it moves the cursor back to the top-left without clearing the screen. This creates a flicker-free timer display because we're overwriting the same position each frame.

Line 140 demonstrates time pressure: when 10 seconds or less remain, the border flashes red (colour 2). Visual warnings make timers feel more urgent.

## Experiment: Spawning Objects on Schedule

Rather than spawning objects as fast as possible, you can use TI to control spawn rates. Here's a simple demonstration that creates a new star every second:

```basic
10 REM SPAWN TIMER WITH DELAY
20 PRINT CHR$(147):POKE 53280,0:POKE 53281,0
30 TI$="000000"
40 LA=0
50 X=INT(RND(1)*40):Y=INT(RND(1)*25)
60 POKE 1024+Y*40+X,42:POKE 55296+Y*40+X,7
70 IF TI-LA&lt;60 THEN 70
80 LA=TI
90 GOTO 50
```

Line 30 uses TI$ to reset the clock to midnight (hour 0, minute 0, second 0). You must provide exactly 6 digits: HHMMSS. This is useful for games where you want TI to start at 0 rather than continuing from power-on.

Line 40 stores LA (Last Action time). This is the jiffy when we last spawned a star.

Line 70 is the waiting loop: it keeps checking if 60 jiffies (one second) have passed since LA. Until that happens, the program sits in this loop doing nothing.

Once a second has passed, line 80 updates LA to the current time, and we spawn another star.

**Timing control is essential for game balance.** Without the delay on line 70, stars would spawn every frame—thousands per second. With it, we get exactly one star per second, creating a steady challenge.

## Putting It Together: Timed Collection Game

Now let's combine everything you've learnt: player movement, collision detection, scoring, and countdown timers. You've got 10 seconds to collect as many stars as possible:

```basic
10 REM COUNTDOWN TIMER GAME
20 PRINT CHR$(147):POKE 53280,0:POKE 53281,0
30 SC=0:TI$="000000":LI=600
40 PRINT "COLLECT STARS! 10 SECONDS!"
50 PX=20:PY=12:OX=INT(RND(1)*40):OY=INT(RND(1)*25)
60 POKE 1024+PY*40+PX,81:POKE 55296+PY*40+PX,1
70 POKE 1024+OY*40+OX,42:POKE 55296+OY*40+OX,7
80 GET A$
90 IF A$="W" AND PY>0 THEN POKE 1024+PY*40+PX,32:PY=PY-1
100 IF A$="S" AND PY&lt;24 THEN POKE 1024+PY*40+PX,32:PY=PY+1
110 IF A$="A" AND PX>0 THEN POKE 1024+PY*40+PX,32:PX=PX-1
120 IF A$="D" AND PX&lt;39 THEN POKE 1024+PY*40+PX,32:PX=PX+1
130 POKE 1024+PY*40+PX,81:POKE 55296+PY*40+PX,1
140 IF PX=OX AND PY=OY THEN SC=SC+1:OX=INT(RND(1)*40):OY=INT(RND(1)*25)
150 POKE 1024+OY*40+OX,42:POKE 55296+OY*40+OX,7
160 RE=LI-TI
170 POKE 1024,INT(RE/60)+48:POKE 1024+1,SC+48
180 IF RE&lt;=0 THEN PRINT CHR$(147):PRINT "TIME UP! SCORE:";SC:END
190 GOTO 80
```

Line 30 sets up game state: SC (score) starts at 0, TI is reset to 0, and LI (limit in jiffies) is set to 600. Since there are 60 jiffies per second, 600 jiffies equals exactly 10 seconds.

Line 160 calculates remaining time in jiffies: LI-TI. As TI counts up, RE counts down.

Line 170 displays both the remaining seconds and the current score. We divide RE by 60 to convert jiffies to seconds, then add 48 to convert the number to its screen code digit. The score appears right next to the timer.

Line 180 checks for game over: when remaining time hits zero or below, we clear the screen, show the final score, and END.

This creates a frantic 10-second challenge. Players develop strategies: do I chase the nearest star, or go for the one that's about to be covered? Time pressure transforms a simple collection game into an exciting test of quick decision-making.

## How It Works: Jiffies and the CIA Chip

TI isn't magic—it's connected to a hardware timer in the CIA (Complex Interface Adapter) chip. This chip has its own crystal oscillator that ticks at a precise frequency. Every 1/60th of a second, the CIA triggers an interrupt that tells BASIC to increment TI by one.

**PAL vs NTSC:** European C64s (PAL) actually tick at 50Hz, not 60Hz. For game purposes, using 60 is close enough—your timer will be 20% slower on PAL machines, but games are rarely that sensitive to exact timing. If you need precision, you'd access the CIA hardware registers directly (that's Tier 2 material).

**The 24-hour rollover:** TI counts from 0 to 5,184,000 (24 hours × 60 minutes × 60 seconds × 60 jiffies). When it reaches that limit, it wraps back to 0. For games lasting under an hour, you'll never see this. For longer sessions, you'd need to detect the rollover and compensate.

**Why TI, not FOR loops?** You might think `FOR D=1 TO 100:NEXT D` would create consistent delays. It doesn't. The loop runs at whatever speed the CPU happens to be running—if something else is happening (like reading the keyboard or updating the screen), the delay changes. TI is hardware-based, so it's always exactly 1/60th of a second per jiffy.

## What Game Designers Know

**Countdown timers create urgency.** Players naturally optimise their strategy when time is limited. Without a timer, they might potter about collecting stars at leisure. With one, they suddenly care about efficiency.

**Timer warnings matter.** Line 140 in the first example turns the border red when 10 seconds remain. Professional games add sound effects too—a beep when 10 seconds are left, faster beeps as time runs out. These warnings help players judge when to take risks versus playing it safe.

**Time bonuses reward skill.** Many arcade games give extra points for finishing quickly. You could add `BONUS=R*10:SC=SC+BONUS` after the game ends—each remaining second awards 10 bonus points. This encourages players to replay levels, trying to beat their previous time.

**Consistent pacing:** Spawning enemies or power-ups at fixed intervals (every 2 seconds, every 5 seconds) creates rhythm. Players subconsciously learn these patterns and plan accordingly. Random spawns feel chaotic; timed spawns feel fair.

## From the Vault

**Real-time strategy games** use TI extensively. Building a structure might take 300 jiffies (5 seconds). Troops might move one square per 60 jiffies. Everything is measured in TI increments, creating the illusion that multiple things are happening simultaneously.

**Arcade classics:** Space Invaders (1978) speeds up enemy movement as you destroy more invaders. That's a form of adaptive timing—as TI increases, the delay between movements decreases. Pac-Man (1980) uses timers for power pill duration, scatter/chase mode cycles, and fruit spawn timing.

**The ultimate timer challenge:** Some games count up instead of down, showing elapsed time. Speedrunners love this—they compete to finish in the shortest time possible. Adding `PRINT "TIME:";INT((TI-T1)/60)` creates a stopwatch perfect for speedrun tracking.

## Quick Reference

**TI System Variable:**
```basic
TI                  :REM Read current jiffy count
TI$="000000"        :REM Reset to midnight (HHMMSS format)
```

**Timing Formulas:**
```basic
Seconds: INT((TI-T1)/60)
Minutes: INT((TI-T1)/3600)
Remaining: LIMIT - INT((TI-T1)/60)
```

**Countdown Timer Pattern:**
```basic
10 TL=30            :REM Time limit (seconds)
20 T1=TI            :REM Store start time
30 E=INT((TI-T1)/60) :REM Elapsed seconds
40 R=TL-E           :REM Remaining time
50 IF R&lt;=0 THEN [time up action]
```

**Delay Pattern:**
```basic
10 LA=TI            :REM Last action time
20 IF TI-LA&lt;60 THEN 20 :REM Wait 1 second
30 LA=TI            :REM Update last action
40 [do timed action]
```

**Common Timer Durations:**
| Duration | Jiffies | Use Case |
|----------|---------|----------|
| 0.5 sec | 30 | Quick reactions, combo windows |
| 1 sec | 60 | Spawn rate, cooldowns |
| 5 sec | 300 | Power-up duration |
| 10 sec | 600 | Challenge timer |
| 30 sec | 1800 | Level timer |
| 1 min | 3600 | Episode timer |

**Timer Warning Thresholds:**
```basic
IF R&lt;=10 THEN POKE 53280,2  :REM Red border at 10 sec
IF R&lt;=5 THEN [play warning sound]
IF R&lt;=3 THEN [flash screen]
```
