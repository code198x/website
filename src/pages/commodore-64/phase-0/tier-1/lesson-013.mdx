## Breaking the Pattern

So far, every program you've written does exactly the same thing every time you run it. PRINT "HELLO" always prints HELLO. Your @ character always starts at position 20,12. Games can't work like that—treasure appears in different locations, dice show different numbers, enemies spawn unpredictably. The RND function breaks determinism, giving your programs the power of chance.

---

### The One-Minute Tour

- RND(1) returns random decimal between 0 and 0.999...
- Never returns exactly 1.0 (always less than 1)
- Multiply and INT to get whole number ranges
- Formula: `INT(RND(1)*N)` gives 0 to N-1
- Add 1 for dice: `INT(RND(1)*6)+1` gives 1-6
- Same sequence every time unless you seed with TI
- `X=RND(-TI)` seeds randomness with system clock
- Screen positions: X=`INT(RND(1)*40)`, Y=`INT(RND(1)*25)`
- Every call to RND(1) advances the sequence

---

### Example Programme

```basic
10 REM SIMPLE RANDOM DEMO
20 PRINT CHR$(147)
30 PRINT "RANDOM NUMBERS 0-1:"
40 PRINT
50 FOR I=1 TO 10
60 PRINT RND(1)
70 NEXT I
```

Sample output:

```
RANDOM NUMBERS 0-1:
 .185564041
 .282134294
 .491004467
 .654983878
 .871002197
 .949254990
 .105674505
 .218818665
 .391132355
 .501907349

READY.
```

![Screen showing random decimal output](/images/commodore-64/phase-0/tier-1/lesson-013/example-1.png)

**Line 60** calls RND(1) which returns a random decimal between 0 and 0.999... Each call advances an internal sequence, so you get different values. But run the program again—you'll see the exact same ten numbers. The C64 uses a pseudorandom number generator that produces the same sequence unless you seed it differently.

> **Tip:** RND(1) with a positive argument advances the random sequence. RND(0) repeats the last value. RND with negative argument reseeds the generator—this is how you get different sequences.

### Experiment Section

Try these variations:

- **Watch the pattern**: Run the program 3 times and notice identical sequences
- **Different starting point**: Add line 45: `X=RND(-100)` to reseed
- **Twenty numbers**: Change line 50 to `FOR I=1 TO 20`
- **Other seed values**: Try `X=RND(-1)`, `X=RND(-500)` before the loop
- **Current last value**: Add line 75: `PRINT:PRINT "LAST: ";RND(0)`

Scaling to useful ranges—dice rolls:

```basic
10 REM SCALING RANDOM RANGES
20 PRINT CHR$(147)
30 PRINT "ROLLING DICE (1-6):"
40 PRINT
50 FOR I=1 TO 10
60 D=INT(RND(1)*6)+1
70 PRINT "ROLL ";I;": ";D
80 NEXT I
```

![Screen showing dice rolls](/images/commodore-64/phase-0/tier-1/lesson-013/example-2.png)

**Line 60** is the critical scaling formula. `RND(1)` gives 0.0-0.999..., multiply by 6 gives 0.0-5.999..., INT truncates to 0-5, adding 1 shifts to 1-6. This pattern works for any range: `INT(RND(1)*N)+1` gives 1 to N, `INT(RND(1)*N)` gives 0 to N-1.

Variations to try:

- **D100**: Change to `D=INT(RND(1)*100)+1` for 1-100 range
- **Coin flip**: `C=INT(RND(1)*2)` gives 0 (tails) or 1 (heads)
- **Random colour**: `C=INT(RND(1)*16)` then `POKE 53280,C`
- **D20**: `D=INT(RND(1)*20)+1` for fantasy gaming
- **Enemy damage**: `DMG=INT(RND(1)*10)+5` for 5-14 damage range

Now the visual payoff—random stars appearing across the screen:

```basic
10 REM RANDOM STARS APPEARING
20 PRINT CHR$(147)
30 POKE 53280,0:POKE 53281,0
40 FOR I=1 TO 50
50 X=INT(RND(1)*40)
60 Y=INT(RND(1)*25)
70 POKE 1024+Y*40+X,42
80 POKE 55296+Y*40+X,1
90 FOR D=1 TO 20:NEXT D
100 NEXT I
```

![Screen with random white stars on black background](/images/commodore-64/phase-0/tier-1/lesson-013/example-3.png)

**Line 30** sets black border and background. **Lines 50-60** generate random screen position (X: 0-39, Y: 0-24). **Line 70** places asterisk character (code 42) at that position. **Line 80** makes it white. **Line 90** tiny delay so you can see stars appear one by one. Run it multiple times—same star pattern every time. Add line 35: `X=RND(-TI)` to seed with system clock, now every run shows different stars.

### Concept Expansion

**Pseudorandom vs. true random.** The C64 doesn't generate truly random numbers—it uses a mathematical formula (linear congruential generator) that produces a deterministic sequence that appears random. Given the same seed (starting value), you always get the same sequence. This is actually useful: during development you want predictable behaviour for testing. For games, you seed with TI (jiffy clock) which changes every sixtieth of a second, making patterns unpredictable.

**The scaling formula explained.** To get random integers in range MIN to MAX: `INT(RND(1)*(MAX-MIN+1))+MIN`. For 10-20: `INT(RND(1)*11)+10`. Why? The range size is 11 (10,11,12...20), RND(1)*11 gives 0.0-10.999..., INT gives 0-10, add 10 shifts to 10-20. Most common cases simplify: 1-N is `INT(RND(1)*N)+1`, 0 to N-1 is `INT(RND(1)*N)`.

**Seeding with TI.** The system clock TI increments 60 times per second. `X=RND(-TI)` uses the current clock value (which is constantly changing) to reseed the random generator. The negative argument tells RND to restart the sequence from a new seed. After seeding, use `RND(1)` with positive argument for subsequent random values. You only need to seed once at program start, not before every random call.

**Distribution and fairness.** `INT(RND(1)*6)+1` gives equal probability for each value 1-6. Each number has exactly 1/6 chance. Adding two dice (`D1+D2`) creates non-uniform distribution—7 is most likely (six ways to make it), 2 and 12 least likely (one way each). This mirrors real dice physics. For game balance, understand whether you want uniform (all values equal chance) or weighted (some more likely) randomness.

**Collision when placing randomly.** The star program can place multiple stars at the same position (they overwrite). For 50 stars on 1000 positions (40×25), collisions are likely. Games solve this: track occupied positions in array, reroll if position taken, or accept collisions (asteroids don't need unique positions). Perfect placement without collision requires different approach covered in later lessons.

### Game Integration

- **Treasure placement**: Random X/Y for collectible items
- **Enemy spawning**: `IF RND(1)<0.1 THEN` creates 10% spawn chance per frame
- **Damage variation**: `DMG=INT(RND(1)*5)+3` for 3-7 damage range
- **Random encounters**: `IF RND(1)*100<ENCOUNTER_RATE THEN GOSUB 5000`
- **Loot drops**: `IF RND(1)<0.3 THEN` creates 30% drop chance
- **Maze generation**: Random walls, random start/end positions
- **Procedural levels**: Different layout every playthrough

Classic random game patterns:

```basic
REM ENEMY SPAWN (10% CHANCE)
IF RND(1)<0.1 THEN EX=INT(RND(1)*40):EY=0

REM RANDOM POWERUP TYPE
PT=INT(RND(1)*3):REM 0=HEALTH, 1=SPEED, 2=SHIELD

REM CRITICAL HIT (15% CHANCE FOR DOUBLE DAMAGE)
IF RND(1)<0.15 THEN DMG=DMG*2
```

Seeding pattern for games:

```basic
10 REM SEED AT START
20 PRINT CHR$(147)
30 X=RND(-TI):REM SEED WITH CLOCK
40 PRINT "STARTING RANDOM GAME..."
```

### Quick Reference

**RND Function:**
```
RND(1)    Next random number (0 to 0.999...)
RND(0)    Repeat last random number
RND(-N)   Reseed with value N, return random number
```

**Common Scaling Formulas:**
```
INT(RND(1)*N)        0 to N-1
INT(RND(1)*N)+1      1 to N
INT(RND(1)*6)+1      Dice 1-6 (D6)
INT(RND(1)*20)+1     D20
INT(RND(1)*100)+1    D100 (percentile)
INT(RND(1)*40)       Screen X (0-39)
INT(RND(1)*25)       Screen Y (0-24)
```

**Range Formula (MIN to MAX):**
```basic
VALUE = INT(RND(1)*(MAX-MIN+1))+MIN

Example: 10 to 20
VALUE = INT(RND(1)*11)+10
```

**Seeding Pattern:**
```basic
10 X=RND(-TI)        :REM SEED WITH CLOCK AT START
20 D=INT(RND(1)*6)+1 :REM USE RND(1) AFTER SEEDING
```

**Probability Checks:**
```basic
IF RND(1)<0.1 THEN ...  :REM 10% CHANCE
IF RND(1)<0.5 THEN ...  :REM 50% CHANCE (COIN FLIP)
IF RND(1)<0.75 THEN ... :REM 75% CHANCE
```

**Random Position:**
```basic
X=INT(RND(1)*40):Y=INT(RND(1)*25)
POKE 1024+Y*40+X,[CHAR CODE]
```

> **Note for .bas files:** The downloadable code samples use lowercase keywords (e.g., `rnd` instead of `RND`) for technical compatibility with the petcat converter tool.

### What You've Learnt

- RND(1) generates pseudorandom decimals 0 to 0.999...
- Same seed produces same sequence (useful for testing)
- `INT(RND(1)*N)` scales to whole number range 0 to N-1
- Add 1 for inclusive ranges like dice: `INT(RND(1)*6)+1`
- Seed with TI for variation: `X=RND(-TI)` at program start
- Random screen positions: X: 0-39, Y: 0-24
- Probability checks: `IF RND(1)<0.3 THEN` for 30% chance
- Scaling formula: `INT(RND(1)*(MAX-MIN+1))+MIN` for any range
- Multiple RND(1) calls can generate same position (collision possible)
