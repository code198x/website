You can move a character. Now it's time to fill the screen with objects that move **automatically**—stars falling from the sky, enemies advancing, bullets flying.

This isn't just about drawing more things. It's about **managing multiple independent objects** using arrays, the technique that powers every shoot-em-up from Galaga to R-Type.

## The One-Minute Tour

- **Object arrays**: Track multiple things with `FX()` and `FY()` arrays (one index = one object)
- **Automatic movement**: Objects update position without player input
- **Spawning pattern**: Generate at top with random X, respawn when reaching bottom
- **Loop-per-object**: `FOR I=1 TO 5` erases, updates, and draws each object
- **Parallel arrays**: Same index in `FX()` and `FY()` represents same object

## First Example: Five Falling Stars

```basic
10 REM FALLING STARS
20 PRINT CHR$(147)
30 PRINT "FALLING STARS DEMO"
40 PRINT
50 DIM FX(5),FY(5)
60 FOR I=1 TO 5
70 FX(I)=INT(RND(1)*40):FY(I)=INT(RND(1)*10)
80 NEXT I
90 REM MAIN LOOP
100 FOR I=1 TO 5
110 POKE 1024+(FY(I)*40)+FX(I),32
120 FY(I)=FY(I)+1
130 IF FY(I)>24 THEN FY(I)=0:FX(I)=INT(RND(1)*40)
140 POKE 1024+(FY(I)*40)+FX(I),42
150 NEXT I
160 FOR D=1 TO 20:NEXT D
170 GOTO 100
```

**Run this** and watch 5 asterisks fall from the top of the screen. When they reach the bottom, they respawn at the top in a random column.

## How Object Arrays Work

### Lines 50-80: Initialize Arrays

```basic
50 DIM FX(5),FY(5)
60 FOR I=1 TO 5
70 FX(I)=INT(RND(1)*40):FY(I)=INT(RND(1)*10)
80 NEXT I
```

`DIM` creates two arrays with 5 slots each. `FX()` holds X positions (0-39 for screen columns), `FY()` holds Y positions (0-24 for screen rows). Each star gets a random starting position.

**Parallel arrays pattern**: `FX(1)` and `FY(1)` represent the same star's X and Y. `FX(2)` and `FY(2)` are a different star. Same index = same object.

### Lines 100-150: Update All Objects

```basic
100 FOR I=1 TO 5
110 POKE 1024+(FY(I)*40)+FX(I),32
120 FY(I)=FY(I)+1
130 IF FY(I)>24 THEN FY(I)=0:FX(I)=INT(RND(1)*40)
140 POKE 1024+(FY(I)*40)+FX(I),42
150 NEXT I
```

This loops through all 5 stars:
- **Line 110**: Erase star at old position
- **Line 120**: Move down one row (`FY(I)=FY(I)+1`)
- **Line 130**: If reached bottom (Y>24), respawn at top (Y=0) with new random X
- **Line 140**: Draw star at new position

Every frame, all 5 stars move automatically. No input checking—they just fall.

## The Spawning Pattern

### Line 130: Respawn When Out of Bounds

`IF FY(I)>24 THEN FY(I)=0:FX(I)=INT(RND(1)*40)`

When a star falls past the bottom row (Y=24), we:
1. Reset Y to 0 (top of screen)
2. Give it a new random X position (0-39)

This creates the illusion of endless falling objects. The same 5 stars keep cycling, but randomization makes it feel like a constant stream.

**Why randomize X?** If we didn't (`FX(I)=INT(RND(1)*40)`), all stars would fall in vertical columns. Randomization spreads them across the screen.

## Why This Pattern Matters

Every action game uses object arrays:

```
DIM Objects(N) for each property:
  OX() = X positions
  OY() = Y positions  
  OT() = Object types (0=star, 1=asteroid, 2=coin)
  OA() = Alive/dead flags

LOOP:
  FOR I=1 TO N
    IF OA(I)=1 THEN
      Erase old position
      Update position based on OT(I)
      Check if out of bounds → respawn or deactivate
      Draw new position
    END IF
  NEXT I
  GOTO LOOP
```

You've just learned the core pattern of Space Invaders, Galaxian, and every shoot-em-up on the C64.

## From Simple to Complex Objects

### Varying Speed

Give each object its own speed:
```basic
50 DIM FX(5),FY(5),FS(5)
70 FX(I)=...:FY(I)=...:FS(I)=INT(RND(1)*3)+1
120 FY(I)=FY(I)+FS(I)
```

Now some stars fall faster than others.

### Different Object Types

Use another array to track type:
```basic
50 DIM FX(5),FY(5),FT(5)
70 FX(I)=...:FY(I)=...:FT(I)=INT(RND(1)*3)
140 IF FT(I)=0 THEN C=42:REM Star
145 IF FT(I)=1 THEN C=90:REM Asteroid (Z)
150 IF FT(I)=2 THEN C=36:REM Coin ($)
155 POKE 1024+(FY(I)*40)+FX(I),C
```

### Horizontal Movement

Add horizontal velocity:
```basic
50 DIM FX(5),FY(5),FVX(5)
70 FX(I)=...:FY(I)=...:FVX(I)=INT(RND(1)*3)-1
125 FX(I)=FX(I)+FVX(I)
126 IF FX(I)<0 THEN FX(I)=39
127 IF FX(I)>39 THEN FX(I)=0
```

Now stars drift left or right while falling.

## Experiments to Try

**1. Increase Object Count**

Change `DIM FX(5),FY(5)` to `DIM FX(10),FY(10)` and update loop bounds. How many objects can you add before it slows down?

**2. Start from Bottom**

Each star gets a random color.

Pressing space pauses until another key is pressed.

## Quick Reference

### Object Array Pattern

```basic
10 DIM OX(N),OY(N)           :REM Position arrays
20 FOR I=1 TO N              :REM Initialize
30 OX(I)=...:OY(I)=...
40 NEXT I
50 REM Main loop
60 FOR I=1 TO N
70 POKE 1024+(OY(I)*40)+OX(I),32  :REM Erase
80 REM Update position
90 IF [out of bounds] THEN [respawn]
100 POKE 1024+(OY(I)*40)+OX(I),C  :REM Draw
110 NEXT I
120 GOTO 60
```

### Spawning Patterns

| Pattern | Code | Use Case |
|---------|------|----------|
| Top spawn | `IF Y>24 THEN Y=0:X=RND...` | Falling objects |
| Bottom spawn | `IF Y&lt;0 THEN Y=24:X=RND...` | Rising objects (bullets) |
| Wrap around | `IF X&lt;0 THEN X=39` | Horizontal scrolling |
| Deactivate | `IF Y>24 THEN A(I)=0` | Limited objects (bullets) |

### Typical Object Counts

| Count | Performance | Use Case |
|-------|-------------|----------|
| 3-5 | Smooth | Learning, simple games |
| 8-10 | Good | Most action games |
| 15-20 | Noticeable lag | Bullet hell, busy screens |
| 30+ | Slow | Not recommended in BASIC |

## What You've Learnt

- **Object arrays** track multiple things with parallel arrays (same index = same object)
- **Automatic movement** updates positions every frame without player input
- **Spawning pattern** creates illusion of endless objects by recycling array slots
- **FOR loops** process all objects each frame (erase, update, draw)
- **Randomization** prevents predictable patterns and adds variety
