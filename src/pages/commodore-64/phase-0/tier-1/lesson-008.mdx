Lesson 7 taught you to change the border colour by POKEing VIC-II registers. But the screen itself—the 40×25 grid of characters you see—is also just memory. Writing a number to the right address instantly puts that character on screen.

**Memory address 1024** is the top-left corner of the screen. Write a screen code there, and you've drawn a character without using PRINT at all.

## The One-Minute Tour

- **Screen memory starts at 1024** (top-left) and extends to 2023 (bottom-right)
- Each memory location holds a **screen code** (0-255) representing a character
- Screen codes ≠ PETSCII codes (different numbering for same characters)
- POKEing screen memory is **instant** (no cursor movement, no scrolling)
- Common pattern: loop through addresses 1024-2023 to fill the entire screen

## First Example: Writing Text Directly

Type this and see what happens:

```basic
10 rem simple screen write
20 print chr$(147);"poking the screen"
30 print
40 print "screen starts at 1024"
50 print
60 poke 1024,17
70 poke 1025,23
80 poke 1026,5
90 poke 1027,18
100 poke 1028,20
110 poke 1029,25
```

**Run this** and look at the top-left corner of the screen.

![Direct screen memory write](/images/commodore-64/phase-0/tier-1/lesson-008/example-1.png)

The word "QWERTY" appears at the top. But here's what's different: the screen codes are 17, 23, 5, 18, 20, 25. Those aren't the PETSCII codes for those letters (which would be 81, 87, 69, 82, 84, 89). They're **screen codes**—the internal numbers the VIC-II chip uses to look up character shapes.

## Second Example: Random Pattern Fill

Now let's create a full-screen pattern using a loop:

```basic
10 rem screen pattern
20 print chr$(147)
30 for i=0 to 999
40 c=int(rnd(1)*4)
50 if c=0 then p=160
60 if c=1 then p=109
70 if c=2 then p=124
80 if c=3 then p=126
90 poke 1024+i,p
100 next i
```

**Run this** and watch the screen fill with random graphics.

![Random pattern filling the screen](/images/commodore-64/phase-0/tier-1/lesson-008/example-2.png)

The screen fills with a random mix of four PETSCII graphics characters. It takes a couple of seconds because BASIC is looping through 1000 iterations—but compare that to using PRINT 1000 times! Line 30 loops from 0 to 999 (1000 characters—that's 40 columns × 25 rows). Line 90 writes to `1024+i`, so the first character goes to 1024 (top-left), the next to 1025, and so on across the screen from left to right, top to bottom.

Each POKE itself is instant—the delay comes from the FOR loop, RND(), and IF statements. In assembly language, this same operation would be near-instantaneous. But even in BASIC, direct memory access is much faster than using PRINT.

## How Screen Memory Works

**The screen is a 40×25 grid = 1000 characters total.**

Each position has an address:
- **1024**: Row 0, Column 0 (top-left)
- **1063**: Row 0, Column 39 (top-right)
- **1064**: Row 1, Column 0 (second row)
- **2023**: Row 24, Column 39 (bottom-right)

**Formula:** `Address = 1024 + (row × 40) + column`

Example: Row 5, Column 10 → `1024 + (5 × 40) + 10 = 1234`

**Writing to screen memory:**
```basic
POKE 1024,17    REM Put 'Q' at top-left
POKE 1063,17    REM Put 'Q' at top-right
POKE 2023,17    REM Put 'Q' at bottom-right
```

The VIC-II chip reads this memory 50 times per second (PAL) / 60 times (NTSC) and displays whatever numbers it finds there. Change the number, change what appears on screen. No PRINT statement needed.

## Screen Codes vs PETSCII Codes

**PETSCII codes** are what you type and what CHR$() uses:
- `CHR$(65)` prints "A"
- Designed for keyboard and printing

**Screen codes** are what the VIC-II chip uses to look up character shapes in ROM:
- Screen code 1 displays "A"
- Designed for fast video display

**Common screen codes:**
- **1-26**: A-Z (uppercase letters)
- **32**: Space
- **64**: Horizontal line (─)
- **66**: Vertical line (│)
- **108**: Checkerboard
- **109**: Filled circle
- **124**: Vertical bar
- **126**: Horizontal bar
- **160**: Space (alternative)

The mismatch exists because screen memory is optimised for the VIC-II chip, not for human typing.

## Why This Matters

PRINT is slow. It:
1. Calculates where the cursor is
2. Scrolls the screen if needed
3. Handles special characters
4. Updates the cursor position

**Direct screen memory writes skip all that.** You write a number, it appears. Games use this for:
- **Status bars**: Score, lives, timer (fixed positions, instant updates)
- **Playfields**: Game boards drawn in one loop
- **Animations**: Characters moving across the screen
- **Menus**: Instant screen layouts without PRINT statements

Later lessons will use this constantly. Understanding that the screen is just 1000 memory locations is fundamental to fast C64 programming.

## Experiments to Try

**1. Draw a horizontal line:**
```basic
10 for i=0 to 39
20 poke 1024+i,64
30 next i
```

**2. Draw a vertical line:**
```basic
10 for i=0 to 24
20 poke 1024+(i*40),66
30 next i
```

**3. Fill the entire screen with one character:**
```basic
10 for i=0 to 999
20 poke 1024+i,160
30 next i
```

**4. Draw a box border:**
```basic
10 rem top and bottom
20 for i=0 to 39
30 poke 1024+i,64:poke 1984+i,64
40 next i
50 rem left and right
60 for i=0 to 24
70 poke 1024+(i*40),66:poke 1063+(i*40),66
80 next i
```

## Quick Reference

### Screen Memory Map

| Address Range | Coverage |
|---------------|----------|
| 1024-1063 | Row 0 (top line) |
| 1064-1103 | Row 1 |
| ... | ... |
| 1984-2023 | Row 24 (bottom line) |

### Address Calculation

```basic
REM Position to address
A = 1024 + (ROW * 40) + COLUMN

REM Address to position
ROW = INT((A - 1024) / 40)
COLUMN = (A - 1024) - (ROW * 40)
```

### Common Screen Codes

| Code | Character | Use |
|------|-----------|-----|
| 1 | A | Letters start at 1 |
| 17 | Q | Example: Q=17, W=23, E=5 |
| 32 | Space | Clear character |
| 64 | Horizontal line | Borders |
| 66 | Vertical line | Borders |
| 108 | Checkerboard | Patterns |
| 109 | Filled circle | Bullets, dots |
| 124 | Vertical bar | Dividers |
| 126 | Horizontal bar | Dividers |
| 160 | Space (alt) | Clear character |

### POKE Command for Screen

```basic
POKE address,screen_code    REM Write character to screen
```

**Examples:**
- `POKE 1024,17` → Write 'Q' at top-left
- `POKE 1024+40,17` → Write 'Q' one row down
- `POKE 1024+1,17` → Write 'Q' one column right

## What You've Learnt

- Screen memory occupies addresses 1024-2023 (1000 characters)
- POKEing screen memory draws instantly without PRINT
- Screen codes differ from PETSCII codes
- Address formula: 1024 + (row × 40) + column
- Loops can fill entire screen in milliseconds
- Direct memory writes bypass cursor and scrolling logic
- This technique is fundamental for fast game graphics
