You've built games with multiple enemies moving on screen. You've created AI for turn-based opponents. Now let's attempt something that seems within reach: a real-time strategy game with 10 units, each with pathfinding and combat AI.

**This lesson reveals BASIC's multi-entity complexity limitation**—when multiple objects need independent behaviour (pathfinding, target selection, collision detection), the calculations compound. Commercial RTS games like Command & Conquer manage dozens of units smoothly. When you try to replicate that in BASIC, you'll discover why: updating 10 units with pathfinding drops performance to 2-3 fps.

The key discovery: **Complexity multiplies exponentially**. One unit checking 9 others for collisions = 9 checks. Ten units each checking 9 others = 90 checks per frame. Add pathfinding and AI, and BASIC can't keep up. This isn't an optimisation problem—it's the overhead of nested loops in interpreted code.

---

## The One-Minute Tour

**RTS Game Mechanics:**
- **10 units total** 5 player-controlled, 5 enemy AI
- **Real-time movement** units navigate toward goals simultaneously
- **Pathfinding** avoid collisions with other units
- **Combat AI** automatically attack nearby enemies
- **Unit selection** pick units with number keys, give movement commands

**The Complexity Problem:**
- **2-3 fps** with all 10 units active (vs 8-12 fps in Tier 3 games)
- **90+ collision checks** per frame (10 units × 9 others each)
- **10 pathfinding calculations** every update (manhattan distance, direction)
- **10 AI target searches** scanning all enemies for nearest target

**What RTS Games Need:**
- **Spatial partitioning** only check nearby units, not all units
- **Optimised pathfinding** A* or flow fields (BASIC has linear search only)
- **Compiled loops** assembly iterates through units 100× faster
- **Hardware sprites** move sprites via VIC-II, not redraw screen

## Example: RTS with 10 Units

Here's a complete RTS demonstrating the multi-entity limitation:

```basic
100 REM REAL-TIME STRATEGY
110 REM UNIT ARRAYS (MAX 10 UNITS)
120 DIM UX(10),UY(10),UH(10),UT(10),UA(10)
130 DIM GX(10),GY(10)
140 REM X,Y,HEALTH,TEAM,ATTACK TARGET
150 REM GOAL X, GOAL Y
160 NC=0:REM NUMBER OF UNITS
170 SU=0:REM SELECTED UNIT
180 FC=0:TM=TI:REM FRAME COUNTER, TIME MARKER
190 GOSUB 9000:REM INIT
200 REM MAIN LOOP
210 GOSUB 1000:REM INPUT
220 GOSUB 2000:REM UPDATE ALL UNITS
230 GOSUB 3000:REM ENEMY AI
240 GOSUB 4000:REM COMBAT
250 GOSUB 5000:REM DRAW
260 GOSUB 6000:REM FPS COUNTER
270 GOTO 210
1000 REM PLAYER INPUT
1010 GET K$:IF K$="" THEN RETURN
1020 REM SELECT UNIT (1-5)
1030 IF K$>="1" AND K$<="5" THEN SU=VAL(K$):RETURN
1040 REM MOVE SELECTED UNIT
1050 IF SU=0 THEN RETURN
1060 IF K$="W" THEN GY(SU)=UY(SU)-40:RETURN
1070 IF K$="S" THEN GY(SU)=UY(SU)+40:RETURN
1080 IF K$="A" THEN GX(SU)=UX(SU)-40:RETURN
1090 IF K$="D" THEN GX(SU)=UX(SU)+40:RETURN
1100 RETURN
2000 REM UPDATE ALL UNITS
2010 FOR I=1 TO NC
2020 IF UH(I)<=0 THEN GOTO 2060
2030 GOSUB 2100:REM PATHFINDING
2040 GOSUB 2300:REM MOVE
2050 GOSUB 2500:REM FIND TARGET
2060 NEXT I
2070 RETURN
2100 REM PATHFINDING FOR UNIT I
2110 IF GX(I)=0 AND GY(I)=0 THEN RETURN
2120 OX=GX(I)-UX(I)
2130 OY=GY(I)-UY(I)
2140 REM NORMALIZE TO -1, 0, OR 1
2150 IF OX>0 THEN OX=1
2160 IF OX<0 THEN OX=-1
2170 IF OY>0 THEN OY=1
2180 IF OY<0 THEN OY=-1
2190 REM CHECK IF PATH BLOCKED
2200 PX=UX(I)+OX*4:PY=UY(I)+OY*4
2210 GOSUB 2250:IF BL=1 THEN OX=0:OY=0
2220 RETURN
2250 REM CHECK BLOCKED
2260 BL=0
2270 FOR J=1 TO NC
2280 IF I=J THEN GOTO 2290
2285 IF ABS(UX(J)-PX)<8 AND ABS(UY(J)-PY)<8 THEN BL=1:RETURN
2290 NEXT J
2295 RETURN
2300 REM MOVE UNIT I
2310 UX(I)=UX(I)+OX*2
2320 UY(I)=UY(I)+OY*2
2330 REM CHECK IF REACHED GOAL
2340 IF ABS(UX(I)-GX(I))<5 AND ABS(UY(I)-GY(I))<5 THEN GX(I)=0:GY(I)=0
2350 RETURN
2500 REM FIND ATTACK TARGET
2510 TG=0:MI=9999
2520 FOR J=1 TO NC
2530 IF UT(J)=UT(I) THEN GOTO 2570
2540 IF UH(J)<=0 THEN GOTO 2570
2550 OX=ABS(UX(I)-UX(J)):OY=ABS(UY(I)-UY(J))
2560 DT=OX+OY:REM MANHATTAN DISTANCE
2565 IF DT<MI THEN MI=DT:TG=J
2570 NEXT J
2580 UA(I)=TG
2590 RETURN
3000 REM ENEMY AI
3010 FOR I=6 TO 10
3020 IF UH(I)<=0 THEN GOTO 3060
3030 GOSUB 3100:REM FIND NEAREST PLAYER
3040 IF TG>0 THEN GX(I)=UX(TG):GY(I)=UY(TG)
3060 NEXT I
3070 RETURN
3100 REM FIND NEAREST PLAYER UNIT
3110 TG=0:MI=9999
3120 FOR J=1 TO 5
3130 IF UH(J)<=0 THEN GOTO 3170
3140 OX=ABS(UX(I)-UX(J)):OY=ABS(UY(I)-UY(J))
3150 DT=OX+OY
3160 IF DT<MI THEN MI=DT:TG=J
3170 NEXT J
3180 RETURN
4000 REM COMBAT
4010 FOR I=1 TO NC
4020 IF UH(I)<=0 THEN GOTO 4070
4030 IF UA(I)=0 THEN GOTO 4070
4040 OX=ABS(UX(I)-UX(UA(I)))
4050 OY=ABS(UY(I)-UY(UA(I)))
4060 IF OX<20 AND OY<20 THEN GOSUB 4100
4070 NEXT I
4080 RETURN
4100 REM EXECUTE ATTACK
4110 UH(UA(I))=UH(UA(I))-2
4120 IF UH(UA(I))<=0 THEN UA(I)=0
4130 RETURN
5000 REM DRAW SCREEN
5010 PRINT CHR$(147):REM CLEAR
5020 PRINT "=== RTS DEMO ==="
5030 PRINT ""
5040 REM COUNT ALIVE UNITS
5050 PL=0:EN=0
5060 FOR I=1 TO 5:IF UH(I)>0 THEN PL=PL+1
5070 NEXT I
5080 FOR I=6 TO 10:IF UH(I)>0 THEN EN=EN+1
5090 NEXT I
5100 PRINT "PLAYER UNITS:";PL;" ENEMY:";EN
5110 PRINT ""
5120 REM DRAW UNITS (TEXT MODE)
5130 FOR I=1 TO NC
5140 IF UH(I)<=0 THEN GOTO 5200
5150 CH$="P":IF UT(I)=2 THEN CH$="E"
5160 PX=INT(UX(I)/8):PY=INT(UY(I)/8)
5170 IF PX<0 OR PX>39 OR PY<0 OR PY>24 THEN GOTO 5200
5180 POKE 1024+PY*40+PX,ASC(CH$)
5190 CO=7:IF UT(I)=2 THEN CO=2
5195 POKE 55296+PY*40+PX,CO
5200 NEXT I
5210 REM SHOW SELECTED UNIT
5220 IF SU>0 AND UH(SU)>0 THEN PRINT CHR$(19);"SEL: UNIT";SU;" HP:";UH(SU);"  ";
5230 RETURN
6000 REM FPS COUNTER
6010 FC=FC+1
6020 IF TI-TM<60 THEN RETURN
6030 FS=FC
6040 PRINT CHR$(19);"FPS:";FS;"   ";
6050 FC=0:TM=TI
6060 RETURN
9000 REM INIT UNITS
9010 REM PLAYER UNITS (1-5)
9020 FOR I=1 TO 5
9030 UX(I)=50+I*20:UY(I)=160
9040 UH(I)=20:UT(I)=1
9050 GX(I)=0:GY(I)=0:UA(I)=0
9060 NEXT I
9070 REM ENEMY UNITS (6-10)
9080 FOR I=6 TO 10
9090 UX(I)=50+(I-5)*20:UY(I)=50
9100 UH(I)=20:UT(I)=2
9110 GX(I)=0:GY(I)=0:UA(I)=0
9120 NEXT I
9130 NC=10
9140 RETURN
```

**What happens when you run this:**

1. **2-3 fps** FPS counter shows how slow 10 active units are
2. **Visible lag** select a unit and give movement order—delay before it responds
3. **Units get stuck** pathfinding fails when units cluster (too many collision checks)
4. **Text-only display** even without graphics, complexity overwhelms BASIC

**The complexity revelation:** Each unit runs:
- **Pathfinding** (lines 2100-2220): Calculate direction, check 9 other units for collision
- **Target finding** (lines 2500-2590): Scan all enemy units for nearest target
- **Movement** (lines 2300-2350): Update position, check goal reached

With 10 units, that's 100+ checks per frame. BASIC can only manage 2-3 fps.

## Why Multi-Entity Complexity Overwhelms BASIC

**The nested loop problem:**
```basic
2000 FOR I=1 TO 10        :REM For each unit
2030   GOSUB 2100          :REM Pathfinding
2100   FOR J=1 TO 10       :REM Check every other unit
2285     IF collision...   :REM Collision detection
2290   NEXT J
2060 NEXT I
REM Result: 10 × 10 = 100 collision checks per frame
```

**Every frame, BASIC executes:**
- 10 pathfinding calls
- 90 collision checks (10 units × 9 others each)
- 10 target searches (each scanning 5-10 enemy units)
- 10 combat range checks
- Screen redraw with 10 POKE operations

**Total:** 200+ operations per frame, all interpreted. At 2 fps, each frame takes 500ms.

## The Optimisation Trap

You might try reducing complexity:

**1. Fewer units:**
```basic
NC=6:REM ONLY 6 UNITS TOTAL
```
**Result:** Improves to 4-5 fps, but still far from smooth. Half the units, but still too slow.

**2. Simpler pathfinding:**
```basic
REM REMOVE COLLISION DETECTION
2210 REM GOSUB 2250:IF BL=1 THEN OX=0:OY=0
```
**Result:** Faster (6-7 fps) but units overlap and stack on each other (looks broken)

**3. Turn-based instead:**
```basic
REM WAIT FOR INPUT BETWEEN EACH UNIT'S TURN
```
**Result:** Perfect performance, but it's no longer an RTS—it's turn-based strategy (which BASIC handles well)

**The lesson:** You can make it work by removing features or changing genres, but you can't make a real-time multi-unit strategy game run smoothly in BASIC.

## Alternative: Turn-Based Strategy Works

**What works well in BASIC:**
```basic
REM TURN-BASED TACTICS (LIKE TIER 3 LESSON 47)
```

**Result:**
- Instant response (no frame rate limit)

- BASIC's strength: turn-based logic, not real-time simulation

- Turn-based strategy: Works perfectly (Advance Wars, Fire Emblem style)

## From the Vault

**Algorithm Complexity:**
- **Linear search** checking N items takes N operations (BASIC's only option)
- **Spatial hash** checking nearby items takes ~5 operations (requires assembly)
- **A* pathfinding** optimal path in graph (complex to implement in BASIC)

**C64 Performance Reference:**
- BASIC FOR loop: ~1000 iterations/second (1ms per iteration)
- Assembly loop: ~100,000 iterations/second (0.01ms per iteration)
- 100× speed difference for same logic

**Commercial game technique:**
- Update units in batches (5 units per frame, not all 10)
- Simplified AI when units off-screen
- Pre-calculated pathfinding grids

## Quick Reference

**Collision Detection Cost:**
```basic
REM CHECK IF UNIT I COLLIDES WITH UNIT J
2285 IF ABS(UX(J)-PX)<8 AND ABS(UY(J)-PY)<8 THEN BL=1
REM 10 units checking 9 others each = 90 checks/frame
REM At 1ms per check = 90ms just for collisions
```

**Pathfinding Cost:**
```basic
2100 REM CALCULATE DIRECTION TO GOAL
2120 OX=GX(I)-UX(I)
2130 OY=GY(I)-UY(I)
2140 REM NORMALIZE
2150-2180 REM 4 IF checks
REM 10 units × 4 checks = 40 conditional evaluations/frame
```

**Performance Breakdown:**
- Collision detection: ~90ms
- Pathfinding: ~40ms
- Target finding: ~50ms
- Drawing: ~100ms
- **Total:** ~280ms per frame = 3.5 fps maximum
