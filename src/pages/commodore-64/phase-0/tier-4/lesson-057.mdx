## Lesson 57 – Making It Feel Right

A technically correct game can still feel wrong. Week 8 opens with polish: tightening movement, sampling input without jitter, and logging the values you tweak so you can iterate quickly. This is the craft layer that separates prototypes from games people want to touch twice.

> [📷 suggested: GIF showing the hoverpod accelerating and easing to a stop]

---

### The One-Minute Tour

- Clamp your update loop to a fixed cadence, but sample input every frame so quick taps still register.
- Apply easing (momentum and drag) to smooth the transition between pressed and released keys.
- Log the variables you tweak—speed, friction, gravity—so you can copy favourite sets back into the listing.

---

### Example Program

```basic
NEW
10 REM *** HOVER FEEL TEST ***
20 PRINT CHR$(147);
30 POKE 646,1
40 PRINT "ARROWS = THRUST  SPACE = RESET  T = TOGGLE TRACE"
50 GOSUB 900
60 FIX=3:FRICTION=8:MAXV=5:TRACE=0
70 PX=160:PY=120:VX=0:VY=0
80 TI$="000000":NEXTT=0
90 GET K$:IF K$<>"" THEN KEY$=K$
100 IF KEY$="T" THEN TRACE=1-TRACE:KEY$=""
110 IF KEY$=" " THEN PX=160:PY=120:VX=0:VY=0:KEY$=""
120 IF TI<NEXTT THEN 90
130 GOSUB 400
140 GOSUB 500
150 NEXTT=TI+FIX
160 IF TRACE THEN GOSUB 800
170 GOTO 90

400 REM *** HANDLE INPUT ***
410 IF KEY$=CHR$(157) THEN VX=VX-1
420 IF KEY$=CHR$(29) THEN VX=VX+1
430 IF KEY$=CHR$(17) THEN VY=VY+1
440 IF KEY$=CHR$(145) THEN VY=VY-1
450 KEY$=""
460 IF VX>MAXV THEN VX=MAXV
470 IF VX<-MAXV THEN VX=-MAXV
480 IF VY>MAXV THEN VY=MAXV
490 IF VY<-MAXV THEN VY=-MAXV
495 RETURN

500 REM *** UPDATE & DRAW ***
510 VX=VX-VX/FRICTION
520 VY=VY-VY/FRICTION
530 PX=PX+VX:PY=PY+VY
540 IF PX<24 THEN PX=24:VX=-VX/2
550 IF PX>296 THEN PX=296:VX=-VX/2
560 IF PY<40 THEN PY=40:VY=-VY/2
570 IF PY>212 THEN PY=212:VY=-VY/2
580 PRINT CHR$(19);TAB(PX/8);CHR$(81)
590 RETURN

800 REM *** TRACE HUD ***
810 PRINT CHR$(19);TAB(0);
820 PRINT "VX:";INT(VX*10)/10;" VY:";INT(VY*10)/10;
830 PRINT " FIX:";FIX;" FRI:";FRICTION;" MAX:";MAXV;"   "
840 RETURN

900 REM *** CLEAR SCREEN ***
910 FOR R=0 TO 2:PRINT: NEXT
920 RETURN
```


Sample output with trace enabled:

```
VX:1.8 VY:0  FIX:3 FRI:8 MAX:5
```

`FIX` sets the update cadence (3 jiffies ≈ 50 Hz). Keys are sampled every frame so tapping still nudges the hoverpod. Momentum comes from `FRICTION`; lowering it makes the craft drift farther after release. `TRACE` toggles a live HUD, showing the values you want to tweak. Reset with `SPACE`, adjust numbers, rerun, and note the pairings that feel best.

> **Tip:** Track your favourite parameter sets in comments (`REM FRI=6, MAX=4`) so you can roll back quickly during playtests.

---

### Experiment Section

- Swap `FRICTION` between 6 and 12 while playing to find a sweet spot, then write the favourite into the listing.
- Add vertical gravity by tweaking `VY=VY+0.2` before friction; note how different it feels.
- Record the time between `SPACE` resets using `TI` to see how long players stay alive before asking for adjustments.
- Tie colour to speed (`POKE 646,ABS(VX)+1`) to give visual feedback on how aggressive the craft feels.

### Concept Expansion

Responsiveness is iterative. Instrumentation lets you test values quickly, while easing hides the low resolution of C64 physics. Carry these tweaks into Scroll Runner or Galactic Miner so every moving piece feels deliberate.

---

### Game Integration

Keep a debug flag handy:

```basic
IF TRACE THEN GOSUB 3600
IF TRACE AND KEY$="-" THEN FRICTION=FRICTION-1
```

Park the debug HUD at line `3600` and label it with `REM DRAW DEBUG OVERLAY`. Turn it on during development, off for release. The less you dig through the listing, the faster you’ll tune your game.

- Responsiveness comes from sampling input often and smoothing velocity changes.
- HUD toggles make iteration painless and keep your best values visible.
- Feeling good is measurable—use the clock, take notes, tune again.
