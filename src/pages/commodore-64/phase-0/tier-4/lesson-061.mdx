You've spent Arc 1 discovering that BASIC can't handle 50 bullets at playable frame rates (Lesson 49 hit 3-4 fps). You've attempted particle effects that bogged down to 5 fps (Lesson 51). Throughout Tier 4, you've run into the same wall: **the C64's VIC-II chip has only 8 hardware sprites, and BASIC is too slow to simulate more**.

This lesson changes everything. You're not going to learn assembly language yet—you're going to **experience what it unlocks** by calling a pre-written machine code routine. With one `SYS` command, you'll suddenly have 20 sprites on screen at 60 fps.

The technique is called **sprite multiplexing**: rapidly repositioning the same 8 hardware sprites multiple times per frame, faster than the human eye can detect. BASIC can't do this because it requires frame-perfect timing. Assembly can.

## The One-Minute Tour

**What You'll Experience:**
- **Call assembly with `SYS 49152`** - executes machine code at memory location $C000
- **Screen clears 50x faster** - assembly's first visible demonstration
- **20+ sprites at 60 fps** - what was impossible in BASIC now runs smoothly
- **Same BASIC game logic** - you still write movement, collision, scoring

**How Sprite Multiplexing Works:**
- **Raster interrupts** - assembly code runs during screen drawing
- **Sprite repositioning** - moves sprites 0-7 to new Y coordinates mid-frame
- **Multiple appearances** - same hardware sprite shows up in different locations
- **Frame-perfect timing** - must hit exact scanlines (impossible in BASIC)

**The Revelation:**
- BASIC is perfect for game logic (variables, decisions, scoring)
- Assembly is perfect for hardware control (sprites, scrolling, timing)
- **Hybrid programming** combines both strengths

## Understanding SYS: Calling Machine Code from BASIC

**The SYS command:**
```basic
SYS 49152
```

**What this does:**
- Jumps to memory location 49152 (hex $C000)
- Executes machine code instructions stored there
- Returns to BASIC when assembly hits `RTS` (return from subroutine)

**Why 49152?**
- Decimal for $C000 (hex notation)
- Safe memory area not used by BASIC or the operating system
- Common location for machine code routines
- Easy to remember: 49152 = "assembly goes here"

**The DATA statements:**
```basic
9110 DATA 169,42:REM LDA #42
```
- Each number is one machine code instruction byte
- `169,42` means "LDA #42" (load the value 42 into accumulator)
- `96` means "RTS" (return to BASIC)
- Comments show assembly mnemonics (you'll learn these in Phase 1)

## How Sprite Multiplexing Works

**The VIC-II limitation:**
- Only 8 hardware sprites (0-7)
- Each has X/Y position registers
- Each has colour and shape data
- **Fixed limit: cannot have more than 8 simultaneously**

**The multiplexing technique:**
```
FRAME TIMING:
Scanline 50:  Show sprites 0-7 at Y=50  (player bullets)
Scanline 100: Move sprites 0-7 to Y=100 (enemies)
Scanline 150: Move sprites 0-7 to Y=150 (more enemies)
Scanline 200: Move sprites 0-7 to Y=200 (explosions)
Result: 32 apparent sprites from 8 hardware sprites
```

**Why BASIC can't do this:**
- Scanline 50 appears at 1/60th second mark
- BASIC's POKE takes ~0.001 seconds (too slow)
- By the time BASIC POKEs, scanline 50 has already drawn
- Assembly's STA takes 0.000004 seconds (hits exact scanline)

**What you get:**
- 16-24 sprites instead of 8
- Still 60 fps (no slowdown)
- No programming required (just call SYS 49152)

## From the Vault

**Memory Location $C000 (49152):**
- Start of "user RAM" safe for machine code
- Range: $C000-$CFFF (49152-53247)
- 4KB available for assembly routines
- Won't conflict with BASIC program or operating system

**SYS Command:**
- Syntax: `SYS <address>`
- Jumps to machine code at address
- Resumes BASIC after `RTS` instruction
- Can pass parameters via POKE before SYS

**Programmer's Reference Guide:**
- Page 264: "SYS - Transfer control to machine language"
- Page 265: "Control returns to BASIC after RTS"
- Page 266: "Common starting address is 49152 ($C000)"

## Quick Reference

**Loading Machine Code from BASIC:**
```basic
9000 REM LOAD ML ROUTINE
9010 AD=49152:REM START ADDRESS
9020 FOR I=1 TO 22:REM NUMBER OF BYTES
9030 READ BY:REM READ FROM DATA
9040 POKE AD,BY:REM STORE IN MEMORY
9050 AD=AD+1:REM NEXT ADDRESS
9060 NEXT I
9070 DATA 169,42,162,0,157,0,4,96:REM ML BYTES
```

**Calling Machine Code:**
```basic
100 SYS 49152:REM CALL ML AT $C000
```

**Common Assembly Entry Points:**
- **49152 ($C000):** User machine code area
- **64738 ($FCD2):** Kernal screen clear
- **65490 ($FFD2):** Kernal character output

**Performance:**
- BASIC screen clear: ~2 seconds
- Assembly screen clear: ~0.04 seconds
- Speedup: 50x
