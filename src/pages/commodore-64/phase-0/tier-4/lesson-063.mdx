In Lesson 59, you built an arcade game and tried to play background music alongside sound effects. The result was chaos: music and effects fought for the same SID voices, creating stuttering, interruptions, and awkward silences. You discovered that **BASIC can't manage three simultaneous sound channels while also running game logic**.

The SID chip has three voices. In theory, you could use voice 1 for melody, voice 2 for harmony, voice 3 for sound effects. In practice, BASIC's sequential execution means by the time you've set up voice 1, the timing for voice 2 is already wrong. Add game logic between audio updates, and everything falls apart.

This lesson solves that problem with an assembly audio engine. The assembly routine runs automatically via interrupt, managing all three SID voices independently. Your BASIC code just triggers sound effects when needed—no timing concerns, no conflicts, no complexity.

**This is how commercial C64 games do music.** Background music plays continuously, sound effects fire on demand, and everything works together seamlessly.

## The One-Minute Tour

**The SID Conflict Problem:**
- **Three voices available** (SID has voice 1, 2, 3)
- **BASIC runs sequentially** - can only update one thing at a time
- **Music needs continuous updates** - every frame, all three voices
- **Game logic causes delays** - collision checks interrupt audio timing
- **Result:** Stuttering music, missed notes, conflicting effects

**What the Assembly Audio Engine Does:**
- **Runs via interrupt** - independent of BASIC execution
- **Updates music every frame** - continuous background playback
- **Reserves channels intelligently** - voice 3 for effects, voices 1-2 for music
- **Tracks busy voices** - prevents conflicts automatically
- **BASIC triggers effects** - simple SYS call when explosion/shoot happens

**The Experience:**
- Background music plays smoothly (never stutters)
- Sound effects trigger instantly (no delays)
- No BASIC audio code needed (assembly handles everything)
- Professional audio quality (like commercial games)

## Understanding SID Voice Management

**The three-voice architecture:**
```
Voice 1: Melody (continuous, background music)
Voice 2: Harmony (continuous, background music)
Voice 3: Bass OR sound effects (shared channel)
```

**Why BASIC fails at this:**
```basic
REM ATTEMPT BACKGROUND MUSIC IN BASIC
100 POKE 54272,100:POKE 54276,33:REM VOICE 1 NOTE
110 POKE 54279,80:POKE 54283,17:REM VOICE 2 NOTE
120 GOSUB 2000:REM UPDATE GAME LOGIC (TAKES 50ms)
130 REM BY NOW, NOTES ARE WRONG DURATION!
140 POKE 54272,110:REM TRY NEXT NOTE (TOO LATE)
```

**Problems:**
1. **Sequential execution** - can only do one thing at a time
2. **Timing drift** - game logic delays cause irregular note lengths
3. **No multitasking** - can't update music while checking collisions
4. **Manual conflict resolution** - programmer must track which voice is busy

**How assembly solves this:**
```assembly
; PSEUDOCODE - IRQ HANDLER (RUNS 60 TIMES/SEC)
IRQ_MUSIC:
  Increment note counter
  Check voice 1 busy → if free, play next melody note
  Check voice 2 busy → if free, play next harmony note
  Check voice 3 busy → if free, play bass (else skip, effect playing)
  Return
```

**Benefits:**
1. **Parallel execution** - music updates independent of game logic
2. **Perfect timing** - interrupt fires exactly 60 times per second
3. **Automatic multitasking** - both music and game run "simultaneously"
4. **Automatic conflict resolution** - busy flags prevent voice collisions

## Triggering Sound Effects from BASIC

**The simple interface:**
```basic
4000 REM SHOOT SOUND EFFECT
4010 SYS 49152,1,10:REM TYPE 1, DURATION 10 FRAMES
```

**What this does:**
- Calls assembly routine at 49152 ($C000)
- Passes two parameters: type=1 (shoot), duration=10 frames
- Assembly routine handles all SID register manipulation
- Returns immediately to BASIC

**Effect types implemented:**
```basic
SYS 49152,1,10:REM SHOOT (HIGH PITCH, SHORT)
SYS 49152,2,20:REM EXPLOSION (LOW PITCH, LONG, USES 2 VOICES)
SYS 49152,3,30:REM POWERUP (RISING TONE)
```

**Voice busy tracking:**
```
Memory $C032 (49202): Voice 1 busy counter (0 = free)
Memory $C033 (49203): Voice 2 busy counter (0 = free)
Memory $C034 (49204): Voice 3 busy counter (0 = free)
```

**How it works:**
1. BASIC calls SYS 49152,2,20 (explosion)
2. Assembly sets voice 2 busy = 20, voice 3 busy = 20
3. Assembly plays explosion sound on voices 2-3
4. Every frame, assembly decrements busy counters
5. After 20 frames, voices 2-3 return to music duty

**BASIC never worries about timing** - just fire and forget.

## The Interrupt Advantage

**What's an interrupt?**
- Special signal that pauses normal code execution
- Runs a specific handler function
- Returns to normal code after handler completes
- **Happens automatically** at fixed intervals

**Music via interrupt:**
```
FRAME TIMELINE (1/60th second):
  0.00ms: Interrupt fires → music handler runs (0.2ms)
  0.20ms: Return to BASIC game logic
  5.00ms: BASIC updating player position
  10.0ms: BASIC checking collisions
  15.0ms: BASIC drawing screen
  16.6ms: Frame ends
  16.6ms: Interrupt fires → music handler runs (0.2ms)
  ... repeat 60 times per second
```

**Key insight:**
- Music handler runs **in parallel** (from BASIC's perspective)
- BASIC never explicitly calls music code
- Music plays continuously regardless of game complexity
- **This is impossible in pure BASIC** - interpreter is single-threaded

## From the Vault

**SID Chip (6581/8580) Architecture:**
- **Three independent voices** - each with frequency, waveform, ADSR
- **Base address $D400** (54272 decimal)
- **Voice 1:** $D400-$D406 (54272-54278)
- **Voice 2:** $D407-$D40D (54279-54285)
- **Voice 3:** $D40E-$D414 (54286-54292)

**Each voice registers:**
```
+0/+1: Frequency (16-bit, low/high byte)
+2:    Pulse width low byte
+3:    Pulse width high byte (bits 0-3)
+4:    Control register (waveform, gate)
+5:    Attack/Decay
+6:    Sustain/Release
```

**Typical music note frequencies:**
```
C-4: 262 Hz → SID value 4291
E-4: 330 Hz → SID value 5401
G-4: 392 Hz → SID value 6424
```

**Interrupt Setup for Music:**
- Use raster interrupt (like L62 scroller)
- Or CIA timer interrupt (more precise for music)
- Handler updates SID registers 60 times per second

**Programmer's Reference Guide:**
- Page 453: SID Register Map
- Page 456: "Music playback requires interrupt-driven code"
- Page 457: "BASIC cannot achieve consistent note timing"
