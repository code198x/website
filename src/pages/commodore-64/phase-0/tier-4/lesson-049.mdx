## Lesson 49 – Libraries in BASIC

Week 7 peels back the structure behind your games. Today we bundle screen, sound, and utility routines into a tiny **BASIC library** you can drop into any project. Commercial studios did this constantly—fireworks titles like *Uridium* reused starfield, sound, and input code across sequels. You will too.

> [📷 suggested: screenshot of a menu calling different library routines]

---

### The One-Minute Tour

- Store the entry line numbers of your routines in an array so you can call them by index.
- Keep library code in its own block (e.g., starting at line 9000) and initialise it once.
- Expose small, well-named front doors (like `LIB_CALL` and `LIB_INIT`) so your main game never cares about internals.

---

### Example Program

```basic
NEW
10 REM *** MINI LIBRARY DEMO ***
20 GOSUB 9000 : REM load library table once
30 PRINT CHR$(147);"RETRO UTILITIES"
40 PRINT "1 = STARFIELD BACKDROP"
50 PRINT "2 = SCORE CHIME"
60 PRINT "3 = CLEAR HUD"
70 PRINT "4 = QUIT"
80 INPUT "CHOICE";C
90 IF C=4 THEN END
100 IF C<1 OR C>3 THEN GOTO 80
110 L=LIB(C)
120 GOSUB L
130 GOTO 80

9000 REM *** LIBRARY INITIALISER ***
9010 DIM LIB(3)
9020 DATA 1000,2000,3000
9030 FOR I=1 TO 3:READ LIB(I):NEXT I
9040 RETURN

1000 REM *** DRAW STARFIELD ***
1010 POKE 53280,0:POKE 53281,0
1020 FOR I=1 TO 80
1030 X=INT(RND(1)*40):Y=INT(RND(1)*22)
1040 POKE 1024+Y*40+X,42
1050 NEXT I
1060 RETURN

2000 REM *** PLAY SCORE CHIME ***
2010 FOR V=1 TO 3
2020 POKE 54276,17:POKE 54277,33:POKE 54278,48
2030 POKE 54272,34+V*2:POKE 54273,6
2040 POKE 54296,15:FOR D=1 TO 80:NEXT D
2050 POKE 54272,0:POKE 54296,0
2060 NEXT V
2070 RETURN

3000 REM *** CLEAR HUD AREA ***
3010 FOR R=0 TO 2
3020 FOR C=0 TO 39
3030 POKE 1024+R*40+C,32
3040 NEXT C
3050 NEXT R
3060 RETURN
```

Sample output (starfield option):

```
RETRO UTILITIES
1 = STARFIELD BACKDROP
2 = SCORE CHIME
3 = CLEAR HUD
4 = QUIT
CHOICE? 1
```

The library lives at lines 9000+ and fills the `LIB()` table with entry line numbers. The main program never remembers where the starfield routine actually sits; it just looks up `LIB(1)` and `GOSUB`s that line. You can append new routines by adding numbers to the `DATA` line and extending the list—no need to rewrite the dispatcher.

> **Tip:** Keep library routines tight—input parameters live in variables, and each routine returns immediately. Avoid sharing working variables between library and caller unless you deliberately expose them.

### Experiment Section

- Add a fourth routine that prints a centred title banner. Update the `DATA` line and menu text.
- Turn the starfield into a scrolling attract loop by adding a `FOR` loop and random recolour each frame.
- Store routine names in a parallel `LIB$()` array and print them dynamically (`PRINT I;" = ";LIB$(I)`).
- Split the library into a separate BASIC file and `MERGE` it into new games—your own development toolkit.

### Concept Expansion

Libraries are about trust. Once a routine lives in your library block, every game can call it without rereading the listing. Over time you’ll collect drawing helpers, sound stingers, input readers, even debug tools (next lessons) that travel with you from project to project.

---

### Game Integration

Keep page numbers and line numbers in sync:

```basic
LIB_INIT=9000
LIB_STARFIELD=1
GOSUB LIB_INIT
GOSUB LIB(LIB_STARFIELD)
```

Adding constants such as `LIB_STARFIELD=1` keeps your main code readable while still pointing to the correct entry.

### Quick Reference

```basic
REM Initialise table once
DIM LIB(3)
FOR I=1 TO 3:READ LIB(I):NEXT

REM Call by index
L=LIB(choice)
GOSUB L

REM Keep library block together
9000 REM LIBRARY START
```

### What You’ve Learnt

- Arrays of line numbers let you dispatch to reusable routines like a mini toolkit.
- Keeping library code in a dedicated block lets you paste it between projects without hunting references.
- Clear entry points and immediate returns make the library predictable and safe to share.
