You've attempted smooth scrolling (L57), split-screen racing (L58), and background music with effects (L59). Each lesson revealed a specific hardware limitation. Now it's time to synthesise the pattern.

**This is a SYNTHESIS lesson**—a moment to reflect on what you've discovered across multiple attempts. Commercial C64 games achieve effects that look impossible: buttery-smooth scrolling at 60 fps, rock-solid split-screens, seamless music with rich sound effects. You've now attempted each of these in BASIC and witnessed the failures: screen tearing, wandering splits, stuttering audio.

The unifying discovery: **BASIC can access hardware but cannot synchronise with timing requirements**. Every failed effect shares the same root cause: hardware registers must be updated at precise moments (vertical blank, specific scanlines, frame boundaries), but BASIC's interpreter overhead and sequential execution make precise timing impossible.

This lesson presents a demo collection—a runnable showcase of all the broken effects. Experience them together and understand the boundary you've reached.

## Demo 1: Smooth Scroller

**Run the demo and observe:**

```basic
1000 REM DEMO 1: SMOOTH SCROLLER
1010 PRINT CHR$(147)
1020 PRINT "SMOOTH SCROLLER DEMO"
1030 PRINT "WATCH FOR TEARING/JITTER"
1040 PRINT "PRESS SPACE TO EXIT"
1050 DIM SC$(1):SC$(0)="SMOOTH SCROLLING TEXT... THIS SHOULD MOVE 1 PIXEL AT A TIME   "
1060 SO=0:FS=7
1070 REM DRAW INITIAL TEXT
1080 FOR I=0 TO 39:POKE 1024+12*40+I,ASC(MID$(SC$(0),SO+I+1,1)):NEXT I
1090 REM SCROLL LOOP
1100 FS=FS-1:IF FS<0 THEN FS=7:SO=SO+1:GOSUB 1080
1110 REM UPDATE $D016 (THIS CAUSES TEARING)
1120 POKE 53270,(PEEK(53270) AND 248) OR FS
1130 FOR I=1 TO 20:NEXT I
1140 GET K$:IF K$<>" " THEN 1100
1150 POKE 53270,(PEEK(53270) AND 248) OR 0
1160 RETURN
```

**What you see:**
- Horizontal tear line (text splits at inconsistent row)
- Tear position wanders (row 8, then row 14, then row 5)
- Jittery motion (sometimes smooth for 1-2 frames, then jumps)
- Visual "ripple" effect as tear travels down screen

**Why it fails:**
- $D016 must update during vertical blank (1ms window)
- BASIC POKEs at unpredictable times (3-15ms into frame)
- VIC-II reads $D016 while drawing screen
- Top half drawn with old value, bottom half with new value
- **Result:** Horizontal screen tearing

## Demo 2: Raster Bars

**Run the demo and observe:**

```basic
2000 REM DEMO 2: RASTER BARS
2010 PRINT CHR$(147)
2020 PRINT "RASTER BARS DEMO"
2030 PRINT "BARS SHOULD BE AT FIXED LINES"
2040 PRINT "WATCH THEM WANDER/WOBBLE"
2050 PRINT "PRESS SPACE TO EXIT"
2060 FOR I=1 TO 100:NEXT I
2070 REM BAR LOOP
2080 REM WAIT FOR LINE 80
2090 IF PEEK(53266)<80 THEN 2090
2100 POKE 53280,2
2110 REM WAIT FOR LINE 100
2120 IF PEEK(53266)<100 THEN 2120
2130 POKE 53280,7
2140 REM WAIT FOR LINE 120
2150 IF PEEK(53266)<120 THEN 2150
2160 POKE 53280,5
2170 REM WAIT FOR LINE 140
2180 IF PEEK(53266)<140 THEN 2180
2190 POKE 53280,6
2200 REM WAIT FOR LINE 200
2210 IF PEEK(53266)<200 THEN 2210
2220 POKE 53280,14
2230 GET K$:IF K$<>" " THEN 2080
2240 RETURN
```

**What you see:**
- Border colours change at wrong lines (target 80/100/120/140/200)
- Actual positions: ~115/135/155/175/235 (35-50 lines late)
- Bar positions wander (frame 1: line 115, frame 2: line 122, frame 3: line 108)
- Colours "chase" raster down screen (visible delay bars)
- Completely inconsistent frame-to-frame

**Why it fails:**
- PEEK($D012) overhead: ~5ms (5,000µs)
- IF comparison overhead: ~2ms (2,000µs)
- POKE overhead: ~3ms (3,000µs)
- Total: ~10ms = 157 scanlines of delay!
- Target line 100, actual POKE at line 100+157 = 257 (wraps to ~135)
- **Result:** Border colours appear 35-50 lines late

```basic

3060 REM FILL TOP HALF
3070 FOR I=0 TO 11*40:POKE 1024+I,160:NEXT I
3080 REM FILL BOTTOM HALF
3090 FOR I=13*40 TO 24*40:POKE 1024+I,224:NEXT I
3100 FOR I=1 TO 100:NEXT I
3110 REM SPLIT LOOP
3120 REM WAIT FOR LINE 100 (TOP)
3130 IF PEEK(53266)<100 THEN 3130
3140 POKE 53280,6
3150 REM WAIT FOR LINE 125 (SPLIT)
3160 IF PEEK(53266)<125 THEN 3160
3170 POKE 53280,2
3180 REM WAIT FOR LINE 250 (END)
3190 IF PEEK(53266)<250 THEN 3190
```

**What you see:**

- Border colours "wobble" up and down
- Nauseating visual effect (unusable for games)

**Why it fails:**
- Same 157-scanline delay problem as raster bars
- Split needs precise line 125 timing
- BASIC hits line 125+157 = line 282 (wraps to ~160-180)
- Different timing each frame (string ops, branches vary)
- **Result:** Split-screen effect wanders randomly

## Demo 4: Music + SFX

**Run the demo and observe:**

```basic
4000 REM DEMO 4: MUSIC + SFX
4010 PRINT CHR$(147)
4020 PRINT "MUSIC + SFX DEMO"
4030 PRINT "BACKGROUND MUSIC PLAYING"
4040 PRINT "PRESS SPACE FOR SFX (STUTTERS)"
4050 PRINT "PRESS Q TO EXIT"
4060 GOSUB 9000
4070 MN=0
4080 REM MUSIC LOOP
4090 REM PLAY NOTE
4100 MN=MN+1:IF MN>7 THEN MN=0
4110 F=200+MN*30
4120 POKE 54272,F AND 255:POKE 54273,F/256:POKE 54276,33
4130 G=150+MN*20
4140 POKE 54279,G AND 255:POKE 54280,G/256:POKE 54283,33
4150 H=100+MN*10
4160 POKE 54286,H AND 255:POKE 54287,H/256:POKE 54290,33
4170 FOR I=1 TO 80:NEXT I
4180 REM CHECK FOR SFX TRIGGER
4190 GET K$
4200 IF K$=" " THEN GOSUB 4300
4210 IF K$<>"Q" THEN 4090
4220 REM SILENCE
4230 POKE 54276,32:POKE 54283,32:POKE 54290,32
4240 RETURN
4300 REM SFX (INTERRUPTS MUSIC)
4310 POKE 54272,250:POKE 54273,15:POKE 54276,129
4320 FOR I=1 TO 10:NEXT I
4330 POKE 54276,128
4340 RETURN
```

**What you hear:**
- Music plays smoothly at start
- Press SPACE: gunshot fires, Voice 1 melody goes silent
- Music continues but missing melody voice
- Next music note: melody returns, gunshot cut short
- Rapid SPACE presses: rapid clicks, no full gunshot, melody completely absent
- **Confusing audio mess**

**Why it fails:**
- SID has 3 voices (Voice 1, Voice 2, Voice 3)
- Music uses all 3 (melody, harmony, bass)
- Gunshot needs Voice 1 (high-frequency noise)
- POKE 54272,250 overwrites music melody frequency
- Next music update POKE 54272,F overwrites gunshot
- **Result:** Voice conflicts, stuttering, truncated effects

## The Pattern Synthesis

**What every failed effect has in common:**

1. **Hardware register access** ✓
   - L57: Can POKE $D016 (horizontal scroll)
   - L58: Can POKE $D012 (raster position), $D020 (border colour)
   - L59: Can POKE $D400-$D413 (SID voices)
   - **BASIC can access all hardware registers**

2. **Timing precision** ✗
   - L57: Need vertical blank (1ms window), BASIC overhead 10ms
   - L58: Need exact scanline (63.5µs window), BASIC overhead 10,000µs
   - L59: Need frame-synchronised voice updates, BASIC sequential
   - **BASIC cannot achieve timing precision**

3. **Frame synchronisation** ✗
   - L57: Register updates happen mid-frame (screen tearing)
   - L58: Border POKEs happen 157 lines late (wander)
   - L59: Music/effect POKEs conflict (stuttering)
   - **BASIC cannot synchronise with frame timing**

4. **Interrupt coordination** ✗
   - Assembly: Raster interrupts at exact scanlines
   - Assembly: Music player runs independently
   - BASIC: No interrupts available
   - **BASIC has no interrupt system**

**The unified boundary:**
> BASIC can access hardware but cannot synchronise with hardware timing requirements.

## From the Vault

**Timing Numbers (PAL C64):**
- **Frame duration:** 20ms (50 Hz)
- **Scanline duration:** 63.5µs (312 lines per frame)
- **Vertical blank:** ~3.5ms (lines 250-311)
- **BASIC PEEK overhead:** ~5,000µs (5ms)
- **BASIC IF overhead:** ~2,000µs (2ms)
- **BASIC POKE overhead:** ~3,000µs (3ms)
- **Assembly register update:** 2-4µs (LDA/STA instructions)

**The maths:**
- BASIC overhead: 10,000µs ÷ 63.5µs = 157 scanlines of delay
- Assembly overhead: 4µs ÷ 63.5µs = 0.06 scanlines (instant)

**Why assembly is 2500x faster for hardware timing:**
- Not execution speed (BASIC can run game logic fine)
- Timing precision (assembly fits in scanline window, BASIC doesn't)

**VIC-II Registers:**
- **$D011 (53265):** Vertical fine scroll, raster bit 8
- **$D012 (53266):** Raster position (0-255)
- **$D016 (53270):** Horizontal fine scroll
- **$D020 (53280):** Border colour

**SID Registers:**
- **$D400-$D406:** Voice 1 (frequency, control, ADSR)
- **$D407-$D40D:** Voice 2
- **$D408-$D413:** Voice 3

## Quick Reference

**Hardware Access:**
```basic
REM BASIC CAN DO THIS:
POKE 53270,7    :REM Set horizontal scroll
POKE 53280,2    :REM Set border colour
POKE 54272,100  :REM Set Voice 1 frequency

REM BASIC CANNOT DO THIS:
"Update register during vertical blank"
"Update register at exact scanline 125"
"Coordinate Voice 1 between music and effects"
```

**Timing Windows:**
```
Vertical blank window: 1ms
BASIC overhead: 10ms
Result: Misses window by 10x

Scanline window: 63.5µs
BASIC overhead: 10,000µs
Result: Misses window by 157x

Voice coordination: Frame-synchronised
BASIC execution: Sequential
Result: Conflicts inevitable
```

```assembly
; Raster interrupt at line 250
LDA #250
STA $D012

IRQ:
  ; Update registers here (2-4µs)
  LDA SCROLL_VALUE
  STA $D016        ; Fits in 63.5µs window
  RTI
```
