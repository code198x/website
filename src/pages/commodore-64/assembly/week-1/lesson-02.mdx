## Introduction

In Lesson 1, you cleared the screen by asking the KERNAL to do it for you. That's fine for a quick test, but real games need direct control.

By the end of this lesson, you'll put a character on screen without using any KERNAL routines.

## How the C64 Screen Works

The C64 screen is a 40×25 grid of characters - 40 columns, 25 rows. That's 1,000 character positions total.

Each position displays one of 256 possible PETSCII characters. The C64 stores which character to display in **screen memory**, starting at address `$0400` (1024 in decimal).

### The Memory Layout

```
$0400 - Top-left corner (row 0, column 0)
$0401 - One position right (row 0, column 1)
$0428 - Start of second row (row 1, column 0)
...
$07E7 - Bottom-right corner (row 24, column 39)
```

<div class="note">
<div class="note-title">💡 Quick Math</div>
Each row is 40 bytes. To find the memory address for row Y, column X:

**Address = $0400 + (Y × 40) + X**
</div>

## Writing to Screen Memory

Let's put a character in the middle of the screen.

The center position is approximately row 12, column 20:
- Address = $0400 + (12 × 40) + 20
- = $0400 + 480 + 20
- = $0400 + $1E0 + $14
- = $05F4

Create a new file called `skyfall.asm` with the following code:

<div class="code-block">
<div class="code-block-header">skyfall.asm</div>

```asm
; SKYFALL - Lesson 2
; Write to screen memory

* = $0801                      ; Start at BASIC start address

; BASIC stub: SYS 2061
!byte $0c,$08,$0a,$00,$9e
!byte $32,$30,$36,$31          ; "2061" in ASCII
!byte $00,$00,$00

; Program starts here
* = $080d

    lda #$93                   ; Clear screen first
    jsr $ffd2

    lda #$51                   ; PETSCII code for filled circle
    sta $05f4                  ; Write to center of screen

    rts                        ; Return to BASIC
```
</div>

**Build and test:**
```bash
acme -f cbm -o skyfall.prg skyfall.asm
x64sc skyfall.prg
```

You should see a filled circle character in the middle of the screen.

![Filled circle in center of screen](/images/lessons/commodore-64/assembly/week-1/lesson-02/centered-circle.png)

### What Just Happened?

```asm
lda #$51                       ; Load character code into accumulator
sta $0614                      ; Store it to screen memory address
```

That's it. You're directly poking values into the memory that the video chip reads. No KERNAL, no abstraction - pure hardware control.

The video chip scans screen memory 50 times per second (60 on NTSC systems) and displays whatever characters it finds there.

## Color Memory

Screen memory controls which character to display. A separate area of memory controls what color each character is.

Color memory starts at `$D800` and follows the same layout as screen memory. Each byte is a color code (0-15).

Let's make our circle white:

<div class="code-block">
<div class="code-block-header">skyfall.asm</div>

```asm
* = $080d

    lda #$93                   ; Clear screen
    jsr $ffd2

    lda #$51                   ; PETSCII filled circle
    sta $05f4                  ; Write to screen memory

    lda #$01                   ; White color
    sta $d9f4                  ; Write to color memory (same offset as screen)

    rts
```
</div>

![White filled circle with color memory](/images/lessons/commodore-64/assembly/week-1/lesson-02/white-circle.png)

### C64 Color Codes

| Code | Color | Code | Color |
|------|-------|------|-------|
| `$00` | Black | `$08` | Orange |
| `$01` | White | `$09` | Brown |
| `$02` | Red | `$0A` | Light Red |
| `$03` | Cyan | `$0B` | Dark Grey |
| `$04` | Purple | `$0C` | Grey |
| `$05` | Green | `$0D` | Light Green |
| `$06` | Blue | `$0E` | Light Blue |
| `$07` | Yellow | `$0F` | Light Grey |

## The Full Screen

Want to fill the entire screen with a character? Loop through all 1,000 positions:

<div class="code-block">
<div class="code-block-header">skyfall.asm</div>

```asm
* = $080d

    ldx #$00                   ; X register = counter
loop:
    lda #$2a                   ; Asterisk character
    sta $0400,x                ; Write to screen + X offset
    sta $0500,x                ; Second 256 bytes
    sta $0600,x                ; Third 256 bytes
    sta $0700,x                ; Fourth 256 bytes (partial)

    inx                        ; Increment X
    bne loop                   ; Loop until X wraps to 0

    rts
```
</div>

Try it. The screen fills with asterisks.

![Screen filled with asterisks](/images/lessons/commodore-64/assembly/week-1/lesson-02/screen-filled-asterisks.png)

<div class="note">
<div class="note-title">📝 Technical Note</div>
This fills 256×4 = 1,024 positions, which is 24 more than we need. The last 24 writes spill into memory beyond the screen. For now, that's fine - we'll learn precise control later.
</div>

## New Concepts

### Opcodes Used in This Lesson

**lda #$xx / lda $xxxx** - Load Accumulator
- We saw immediate mode (#) in Lesson 1
- Now we see absolute addressing - reading from a memory address
- Example: `lda $0400` loads whatever value is stored at address $0400

**sta $xxxx** - Store Accumulator
- Writes the accumulator's value to a memory address
- This is how you poke values into memory
- Example: `sta $0614` writes A's value to address $0614

**ldx #$xx** - Load X Register
- Like lda, but loads into the X register instead
- X is often used for counters and indexing
- Example: `ldx #$00` sets X to zero

**inx** - Increment X
- Adds 1 to the X register
- Example: If X = 5, then `inx` makes X = 6

**bne label** - Branch if Not Equal (to zero)
- Jumps to a label if the last operation's result wasn't zero
- Used for loops - keeps looping until something becomes zero
- Example: `bne loop` jumps back to the "loop:" label

### The X Register

The X register is used for counting, indexing into arrays, and offset addressing. In `sta $0400,x`, the X value is added to $0400 to determine the actual write address.

When X increments from $FF to $00, it "wraps around" and sets the zero flag, which makes `bne` stop branching.
