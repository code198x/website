## Introduction

Right now, Skyfall has default C64 colors - blue background, light blue border. That's fine for testing, but real games control their visual appearance.

## The VIC-II Chip

The C64's graphics are controlled by the VIC-II chip. It has registers (special memory addresses) that control how the screen looks.

Important registers:
- `$D020` - Border color
- `$D021` - Background color
- `$D012` - Current raster line

Write a color code (0-15) to the color registers to change colors immediately.

## Syncing to the Screen Refresh

Before we set colors, we need to address something important: VICE emulator runs much faster than a real C64.

On real hardware, the CPU runs at about 1MHz. VICE runs at whatever speed your modern computer can manage - often 100x faster or more. This means code that updates the screen will run impossibly fast in VICE without proper timing.

The solution: wait for the screen refresh before doing anything visual.

The C64 screen refreshes 50 times per second (PAL) or 60 times per second (NTSC). We can read which screen line is currently being drawn from `$D012` (the raster register).

Add this subroutine:

<div class="code-block">
<div class="code-block-header">Raster Sync</div>

```asm
; Add to constants
VIC_RASTER = $d012             ; Current raster line

; Add to subroutines
wait_for_raster:
    lda VIC_RASTER             ; Read current raster line
    cmp #250                   ; Wait for line 250 (bottom of screen)
    bne wait_for_raster        ; Keep waiting if not there yet
    rts
```
</div>

<div class="note">
<div class="note-title">💡 Why Line 250?</div>
It's near the bottom of the visible screen, during "vertical blank" - when the raster beam has finished drawing and returns to the top. Updating screen memory here prevents visual artifacts like flicker or tearing.
</div>

## Setting Background and Border Colors

Now let's give Skyfall a black background and dark grey border:

<div class="code-block">
<div class="code-block-header">skyfall.asm - Init Screen</div>

```asm
init_screen:
    jsr wait_for_raster        ; Sync to screen refresh first!

    lda #BLACK
    sta VIC_BACKGROUND         ; Black background

    lda #DARK_GREY
    sta VIC_BORDER             ; Dark grey border

    jsr clear_screen
    rts
```
</div>

The `wait_for_raster` call ensures our color changes happen at the right moment.

Update your main program:

```asm
main:
    jsr init_screen
    jsr draw_player
    rts
```

Build and run. The screen should now have a black background and dark grey border.

## Clearing Screen Memory Properly

The KERNAL screen clear (`$93` + `$FFD2`) is convenient but slow. Games need to clear the screen quickly. Let's write our own:

<div class="code-block">
<div class="code-block-header">skyfall.asm - Clear Screen</div>

```asm
clear_screen:
    lda #$20                   ; Space character
    ldx #$00                   ; Counter starts at 0
clear_loop:
    sta SCREEN_RAM,x           ; Clear first 256 bytes
    sta SCREEN_RAM + $100,x    ; Clear second 256 bytes
    sta SCREEN_RAM + $200,x    ; Clear third 256 bytes
    sta SCREEN_RAM + $300,x    ; Clear fourth 256 bytes (partial)
    inx
    bne clear_loop
    rts
```
</div>

This fills all 1,000 screen positions with space characters (`$20`).

<div class="note">
<div class="note-title">💡 Note</div>
Like Lesson 2's fill example, this writes 1,024 positions (24 too many), but it's fast and simple. The extra writes don't hurt anything.
</div>

## Clearing Color Memory Too

Screen memory determines what character, color memory determines what color. We should clear both:

<div class="code-block">
<div class="code-block-header">skyfall.asm - Complete Clear</div>

```asm
clear_screen:
    lda #$20                   ; Space character
    ldx #$00
clear_screen_loop:
    sta SCREEN_RAM,x
    sta SCREEN_RAM + $100,x
    sta SCREEN_RAM + $200,x
    sta SCREEN_RAM + $300,x
    inx
    bne clear_screen_loop

    lda #WHITE                 ; Default text color
    ldx #$00
clear_color_loop:
    sta COLOR_RAM,x
    sta COLOR_RAM + $100,x
    sta COLOR_RAM + $200,x
    sta COLOR_RAM + $300,x
    inx
    bne clear_color_loop
    rts
```
</div>

Now the screen clears with white text on black, and we control it completely.

## Complete Lesson 4 Code

Here's the full program with all updates:

<div class="code-block">
<div class="code-block-header">skyfall.asm - Complete</div>

```asm
; SKYFALL - Lesson 4
; Colors and screen control

* = $0801

; BASIC stub: SYS 2061
!byte $0c,$08,$0a,$00,$9e
!byte $32,$30,$36,$31          ; "2061" in ASCII
!byte $00,$00,$00

* = $080d

; ===================================
; Constants
; ===================================
SCREEN_RAM = $0400
COLOR_RAM = $d800
VIC_BORDER = $d020
VIC_BACKGROUND = $d021
VIC_RASTER = $d012

BLACK = $00
WHITE = $01
DARK_GREY = $0b

PLAYER_CHAR = $5e
PLAYER_COLOR = WHITE
PLAYER_ROW = 23
PLAYER_START_COL = 20
PLAYER_START_POS = SCREEN_RAM + (PLAYER_ROW * 40) + PLAYER_START_COL

; ===================================
; Main Program
; ===================================
main:
    jsr init_screen
    jsr draw_player
    rts

; ===================================
; Subroutines
; ===================================

wait_for_raster:
    lda VIC_RASTER
    cmp #250
    bne wait_for_raster
    rts

init_screen:
    jsr wait_for_raster        ; Sync before changing anything

    lda #BLACK
    sta VIC_BACKGROUND

    lda #DARK_GREY
    sta VIC_BORDER

    jsr clear_screen
    rts

clear_screen:
    lda #$20                   ; Space character
    ldx #$00
clear_screen_loop:
    sta SCREEN_RAM,x
    sta SCREEN_RAM + $100,x
    sta SCREEN_RAM + $200,x
    sta SCREEN_RAM + $300,x
    inx
    bne clear_screen_loop

    lda #WHITE
    ldx #$00
clear_color_loop:
    sta COLOR_RAM,x
    sta COLOR_RAM + $100,x
    sta COLOR_RAM + $200,x
    sta COLOR_RAM + $300,x
    inx
    bne clear_color_loop
    rts

draw_player:
    lda #PLAYER_CHAR
    sta PLAYER_START_POS

    lda #PLAYER_COLOR
    sta COLOR_RAM + (PLAYER_ROW * 40) + PLAYER_START_COL
    rts
```
</div>

Build and run. Skyfall now has its own look - black background, dark grey border, white player character.

## Choosing Your Game's Palette

Every game has a visual identity. Consider:

**Dark theme** (space games, serious tone):
- Black background (`$00`)
- Dark grey or black border (`$0B` or `$00`)
- Bright colors for important elements

**Light theme** (casual games, friendly tone):
- Light blue or white background (`$0E` or `$01`)
- Lighter border colors
- Darker text colors for contrast

Skyfall uses dark because falling objects will pop visually against black.

## New Concepts

### The Raster Register

**$D012 - VIC Raster Register**
- Contains the current raster line being drawn (0-255+)
- The screen is drawn line-by-line, top to bottom
- Refreshes 50 times per second (PAL) or 60 (NTSC)
- By waiting for a specific line, we sync our code to screen refresh

### Why This Matters

In VICE emulator, without raster sync, your code runs at your PC's speed - way too fast to see anything. On real hardware, it would run fast but not impossibly so.

By syncing to the raster, we ensure:
- Code runs at consistent speed (VICE and real hardware)
- No visual artifacts (flicker, tearing)
- Proper timing for game logic

Every game you build will use this pattern.

### Hardware Registers

`$D020` and `$D021` aren't regular memory - they're hardware registers. Writing to them directly controls the VIC-II chip. This is how you control hardware on the C64: poke values into specific addresses.

### Opcodes Used in This Lesson

**bne label** - Branch if Not Equal
- We first saw this in Lesson 2
- Here: `bne wait_for_raster` creates a wait loop
- Keeps looping until the raster line equals 250

No other new opcodes - the rest uses instructions from previous lessons.
