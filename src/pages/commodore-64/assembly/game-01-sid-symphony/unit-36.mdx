Rhythm games live and die by timing feedback. When players can't feel the beat, they struggle. This unit makes the hit zones pulse to the rhythm—flashing bright on each beat and fading through the interval. A simple visual cue that transforms playability.

## Run It

Assemble and run:

```bash
acme -f cbm -o symphony.prg symphony.asm
```

![Unit 36 Screenshot](/images/commodore-64/game-01-sid-symphony/unit-36/screenshot.png)

Start a song and watch the hit zones. On each beat, they flash white and fade through light green back to yellow. This pulsing matches the music exactly, helping players internalise the rhythm.

## Leveraging Existing Infrastructure

We already have beat timing in place. The `beat_pulse` variable is set to 8 on each new beat:

```asm
            ; Trigger beat pulse on every new beat
            lda #8                  ; Pulse duration (frames)
            sta beat_pulse
```

And `update_beat_marker` already decrements this each frame, creating a countdown from 8 to 0. We simply extend this routine to also update the hit zones.

## Colour Pulse Table

We define a colour sequence that fades from bright to normal:

```asm
; Hit zone pulse colours - bright to normal
hitzone_pulse_cols:
            !byte 1                 ; White (brightest on beat)
            !byte 13                ; Light green
            !byte 7                 ; Yellow
            !byte 7                 ; Yellow (normal)
```

The sequence goes: white → light green → yellow → yellow. The final value matches the hit zone's normal colour, so the animation ends where it started.

## Calculating the Colour Index

We convert `beat_pulse` (0-8) to a colour index (0-3):

```asm
            lda beat_pulse
            lsr                     ; Divide by 2
            and #$03                ; Keep in range 0-3
            tax
            lda hitzone_pulse_cols,x
```

| beat_pulse | After LSR | After AND #$03 | Colour |
|------------|-----------|----------------|--------|
| 8 | 4 | 0 | White |
| 7 | 3 | 3 | Yellow |
| 6 | 3 | 3 | Yellow |
| 5 | 2 | 2 | Yellow |
| 4 | 2 | 2 | Yellow |
| 3 | 1 | 1 | Light green |
| 2 | 1 | 1 | Light green |
| 1 | 0 | 0 | White |
| 0 | (not pulsing) | | |

This creates a quick flash to white, then a gradual fade back through lighter colours.

## Updating All Three Hit Zones

With the colour calculated, we update all three tracks:

```asm
            sta COLRAM + (TRACK1_ROW * 40) + HIT_ZONE_COLUMN
            sta COLRAM + (TRACK2_ROW * 40) + HIT_ZONE_COLUMN
            sta COLRAM + (TRACK3_ROW * 40) + HIT_ZONE_COLUMN
```

Using constants (`TRACK1_ROW`, `HIT_ZONE_COLUMN`) rather than magic numbers makes the code self-documenting and easy to adjust if the layout changes.

## Resetting to Normal

When the pulse ends (`beat_pulse` reaches 0), we reset to the standard hit zone colour:

```asm
beat_marker_dim:
            ; Show dim marker when not pulsing
            ...

            ; Reset hit zone to normal colour
            lda #HIT_ZONE_COL       ; Yellow (7)
            sta COLRAM + (TRACK1_ROW * 40) + HIT_ZONE_COLUMN
            sta COLRAM + (TRACK2_ROW * 40) + HIT_ZONE_COLUMN
            sta COLRAM + (TRACK3_ROW * 40) + HIT_ZONE_COLUMN
```

This ensures the hit zones return to their standard appearance between beats, ready for the next pulse.

## Why This Matters

Visual rhythm cues serve several purposes:

| Benefit | Explanation |
|---------|-------------|
| Timing anticipation | Players see the beat coming |
| Rhythm internalisation | Visual + audio reinforcement |
| Accessibility | Helps players who struggle with audio-only timing |
| Professional feel | Adds polish that players expect from rhythm games |

Even players who aren't consciously watching the hit zones benefit—the peripheral visual pulse helps them feel the rhythm.

## Try This

1. **Different colour schemes** - Try red→orange→yellow for a warm pulse
2. **Intensity variation** - Brighter pulse at higher combos
3. **Track-specific colours** - Each track pulses a different colour
4. **Extended pulse** - Longer pulse duration for slower songs

## Performance Note

We're updating 3 colour RAM locations per frame during the pulse—trivially cheap. Colour RAM writes don't need VIC-II timing synchronisation, so there's no flicker concern.
