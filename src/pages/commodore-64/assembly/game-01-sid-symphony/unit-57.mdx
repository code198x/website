## The 1541 Drive Architecture

The 1541 has its own 6502 CPU and operates independently:

```
┌─────────────────────────────────────────┐
│            Commodore 64                  │
│  ┌─────────────────────────────────┐    │
│  │  Main Program                    │    │
│  │  - Sends commands to drive       │    │
│  │  - Receives data via serial bus  │    │
│  └─────────────────────────────────┘    │
└────────────────┬────────────────────────┘
                 │ Serial Bus (slow)
                 │
┌────────────────┴────────────────────────┐
│            1541 Disk Drive               │
│  ┌─────────────────────────────────┐    │
│  │  Drive CPU (6502)                │    │
│  │  - Reads from disk               │    │
│  │  - Decodes GCR encoding          │    │
│  │  - Sends data to C64             │    │
│  └─────────────────────────────────┘    │
└─────────────────────────────────────────┘
```

The serial bus is the bottleneck—not disk reading.

## Disk Track Layout

A 1541 disk has 35 tracks, with more sectors on outer tracks:

| Tracks | Sectors/Track | Total Sectors |
|--------|---------------|---------------|
| 1-17 | 21 | 357 |
| 18-24 | 19 | 133 |
| 25-30 | 18 | 108 |
| 31-35 | 17 | 85 |

Track 18 holds the directory. Outer tracks spin faster past the head, so they hold more data.

## Seek Time Matters

Moving the drive head takes time:

```
Seek from Track 1 to Track 35:
- ~3 seconds worst case

Seek to adjacent track:
- ~50 milliseconds

Sequential reads on same track:
- ~200 milliseconds per sector
```

Lesson: Keep related data together.

## Optimal Data Layout

Professional games organised files strategically:

```
Track  1-5:   Loading screen + loader
Track  6-15:  Level 1 data
Track 16-17:  Level 2 data
Track 19-25:  Graphics
Track 26-30:  Music
Track 31-35:  Extra levels
```

All level 1 data loads without track seeking.

## Interleaving

Sectors aren't read in order 0,1,2,3... The drive can't process data fast enough:

```
Without interleaving:
Sector 0 → process → miss sector 1 → wait full rotation

With interleaving (factor 10):
Read sector 0
Process while sectors 1-9 pass
Read sector 10
Process while sectors 11-19 pass
```

Optimal interleave depends on loader speed.

## Compression Techniques

Smaller data means faster loads:

### Run-Length Encoding (RLE)
```asm
; Instead of:
; $00 $00 $00 $00 $00 $00 $00 $00 (8 bytes)
; Store:
; $FF $08 $00 (3 bytes: marker, count, value)

decompress_rle:
            lda (src_ptr),y
            cmp #$FF            ; RLE marker?
            beq .run
            sta (dst_ptr),y     ; Normal byte
            ; ...
.run:
            iny
            lda (src_ptr),y     ; Count
            tax
            iny
            lda (src_ptr),y     ; Value
.expand:
            sta (dst_ptr),y
            iny
            dex
            bne .expand
            ; ...
```

### Packed Nibbles
```asm
; Two 4-bit values in one byte
; Good for colour data (0-15)

unpack_nibbles:
            lda packed_data,x
            pha
            lsr                 ; High nibble
            lsr
            lsr
            lsr
            sta colour1
            pla
            and #$0F            ; Low nibble
            sta colour2
```

## Tape Organisation

Tape is sequential—organisation is simpler but crucial:

```
Tape Layout:
┌─────────────────────────────────────┐
│ Header Block 1 (loader)              │
│ Data Block 1 (loader code)           │
│ Header Block 2 (game)                │
│ Data Block 2 (game code + data)      │
│ ...                                  │
└─────────────────────────────────────┘
```

Put most-used data first. Players won't rewind for bonus levels.

## Multi-Load Games

Large games loaded in stages:

```
Initial Load:
- Title screen
- Core engine
- Level 1

After Level 1:
- Load Level 2 (player waits)

After Level 2:
- Load Level 3
```

Each load showed a loading screen to make the wait bearable.

## Modern Tools

Today, creating optimised disk images is automated:

```bash
# c1541 - Commodore disk image tool
c1541 -format "game,id" d64 game.d64
c1541 game.d64 -write loader.prg loader
c1541 game.d64 -write main.prg main
c1541 game.d64 -write data.prg data
```

For physical distribution, track placement still matters.
