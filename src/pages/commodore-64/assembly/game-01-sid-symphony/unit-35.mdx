In arcades and shops, games needed to sell themselves. When nobody was playing, machines would demonstrate gameplay automatically—this is "attract mode." Our title screen now comes alive when idle, showing notes flowing and being hit to entice passersby.

## Run It

Assemble and run:

```bash
acme -f cbm -o symphony.prg symphony.asm
```

![Unit 35 Screenshot](/images/commodore-64/game-01-sid-symphony/unit-35/screenshot.png)

Wait on the title screen for 5 seconds without touching any controls. The game transitions to attract mode: notes spawn and move across the tracks, auto-hitting as they reach the hit zone. "PRESS ANY KEY" pulses at the bottom. Any input returns to the title screen.

## Idle Detection

The core of attract mode is detecting when the player has walked away.

### Idle Timer

We add a frame counter that resets on any input:

```asm
idle_timer       = $26          ; Frames since last input (for attract mode)
IDLE_THRESHOLD = 250            ; Frames before attract (5 seconds at 50fps)
```

At 50 frames per second (PAL), 250 frames equals 5 seconds—long enough that the player has genuinely stopped, short enough to be responsive.

### Tracking Inactivity

In the title screen update routine:

```asm
            ; No input - increment idle timer
            inc idle_timer
            lda idle_timer
            cmp #IDLE_THRESHOLD
            bcc title_no_attract

            ; Idle threshold reached - start attract mode
            jsr show_attract
            lda #STATE_ATTRACT
            sta game_state

title_no_attract:
            rts

title_fire_pressed:
            ; Reset idle timer on any input
            lda #0
            sta idle_timer
```

Every frame without input increments the timer. When it reaches the threshold, we transition to attract mode. Any input resets the timer immediately.

## New Game State

Attract mode requires a sixth game state:

```asm
STATE_ATTRACT = 5               ; Attract mode / demo
```

The main loop handles it like any other state:

```asm
            cmp #STATE_ATTRACT
            beq do_attract

do_attract:
            jsr update_attract
            jmp main_loop
```

## Setting Up the Demo

`show_attract` prepares the gameplay screen for demonstration:

```asm
show_attract:
            ; Set up for demo playback
            lda #0
            sta attract_note_idx
            sta attract_timer
            sta score_lo
            sta score_hi
            sta combo
            sta miss_count

            ; Set up screen (clear, draw tracks, hit zones)
            jsr init_screen

            ; Initialise notes array
            jsr init_notes
```

We reuse the existing `init_screen` and `init_notes` routines—no point duplicating code for the demo. After setup, we draw overlay messages:

```asm
            ; Show "- DEMO -" at top
            ldx #0
draw_demo_text:
            lda demo_overlay_text,x
            beq draw_demo_done
            sta SCREEN + (0 * 40) + 16,x
            ...
```

## Demo Playback

The heart of attract mode is simulating gameplay with pre-recorded patterns.

### Demo Pattern Data

We define which track to spawn notes on:

```asm
demo_pattern:
            !byte 1, 0, 2, 0    ; Track 1, pause, Track 2, pause
            !byte 3, 0, 1, 0    ; Track 3, pause, Track 1, pause
            !byte 1, 2, 0, 0    ; Two quick notes
            !byte 2, 3, 0, 0    ; Two more quick
            !byte 1, 0, 0, 0    ; Single notes with space
            !byte 2, 0, 0, 0
            !byte 3, 0, 0, 0
            !byte 1, 0, 0, 0
            !byte 1, 2, 3, 0    ; Rapid fire all 3 tracks
            !byte 0, 0, 0, 0    ; Pause
            !byte 2, 0, 3, 0    ; Alternate pattern
            !byte 1, 0, 2, 0
```

Values 1-3 spawn a note on that track. Zero means no note this beat. The pattern loops forever.

### Spawning Demo Notes

Every 16 frames, we check the pattern and spawn:

```asm
demo_playback:
            inc attract_timer

            ; Check if time to spawn (every 16 frames)
            lda attract_timer
            and #$0F
            bne demo_update_notes

            ; Get track from pattern
            ldx attract_note_idx
            lda demo_pattern,x
            beq demo_no_spawn   ; 0 = no note

            ; Find free slot and spawn
            ...
```

### Auto-Hitting Notes

Unlike real gameplay, the demo automatically hits notes when they reach the hit zone:

```asm
            ; Check if note reached hit zone
            lda note_col,x
            cmp #HIT_ZONE_START
            bcs demo_draw_note  ; Not there yet

            ; Auto-hit the note!
            lda #0
            sta note_track,x    ; Remove note

            ; Flash border for feedback
            lda #1              ; White
            sta $D020

            inc score_lo        ; Increment score
```

This creates the illusion of perfect play—exactly what you want to showcase.

## Exiting Attract Mode

Any input immediately returns to the title screen:

```asm
update_attract:
            ; Check joystick (any direction or fire)
            lda CIA1_PRA
            and #$1F
            cmp #$1F            ; All released?
            bne attract_exit

            ; Check space bar
            lda #$7F
            sta CIA1_PRA
            lda CIA1_PRB
            and #$10
            beq attract_exit
            ...

attract_exit:
            ; Reset idle timer
            lda #0
            sta idle_timer

            ; Return to title
            jsr show_title
            lda #STATE_TITLE
            sta game_state
            rts
```

We check both joystick and keyboard. The idle timer resets so we don't immediately re-enter attract mode.

## Pulsing "PRESS ANY KEY"

The call-to-action pulses to draw attention:

```asm
            inc title_anim_frame
            lda title_anim_frame
            and #$10
            beq attract_white
            lda #7              ; Yellow
            jmp attract_set_press
attract_white:
            lda #1              ; White
```

This uses the same animation technique from Unit 34—bit masking for timing.

## Design Considerations

Attract mode serves marketing purposes:

| Goal | Implementation |
|------|----------------|
| Show gameplay | Full screen with notes moving |
| Look impressive | Auto-perfect hits, no misses |
| Be interruptible | Any input exits immediately |
| Stay fresh | Pattern loops continuously |

The demo should make the game look fun and achievable—not too easy, not too hard.
