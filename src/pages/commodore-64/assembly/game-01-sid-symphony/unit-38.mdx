Good hits deserve recognition too—but clearly less than perfect. This unit adds "GOOD" text popups with a cooler colour scheme and shorter duration, creating visual hierarchy that communicates hit quality at a glance and motivates players to aim for perfect.

## Run It

Assemble and run:

```bash
acme -f cbm -o symphony.prg symphony.asm
```

![Unit 38 Screenshot](/images/commodore-64/game-01-sid-symphony/unit-38/screenshot.png)

Play a song and notice the difference between hit types. Perfect hits show "PERFECT!" in warm colours (white/yellow) for 12 frames. Good hits show "GOOD" in cool colours (cyan/green) for 8 frames. The visual distinction is immediate.

## Visual Hierarchy Through Design

The differences between perfect and good effects are deliberate:

| Aspect | Perfect | Good |
|--------|---------|------|
| Text | "PERFECT!" (8 chars) | "GOOD" (4 chars) |
| Duration | 12 frames | 8 frames |
| Start colour | White | Cyan |
| Colour sequence | Warm (white→yellow→green) | Cool (cyan→green→grey) |

This creates instant visual feedback about hit quality without requiring players to read the text.

## New Variables

Following the pattern from Unit 37:

```asm
good_effect      = $2B          ; Good hit effect countdown
good_track       = $2C          ; Which track showed last good (1-3)
```

## Triggering Good Effects

In the good hit section of `award_points`:

```asm
            ; Trigger "GOOD" text effect (Unit 38)
            lda #8                  ; Shorter duration than perfect
            sta good_effect
            lda key_pressed
            sta good_track
```

The 8-frame duration (versus 12 for perfect) makes good hits feel snappier—positive but not as celebratory.

## Cool Colour Palette

Good hits use cooler colours to distinguish from perfect's warm tones:

```asm
good_colours:
            !byte 3                 ; Cyan
            !byte 13                ; Light green
            !byte 5                 ; Green
            !byte 11                ; Dark grey
```

Compare to perfect's colours (white, yellow, light green, green). The cyan start and grey end create a distinctly different visual impression.

## Shorter Text, Shorter Clear

The clear routine only needs to handle 4 characters:

```asm
clear_good_text:
            ldx #3                  ; 4 characters
clear_good_loop:
            lda #CHAR_SPACE
            sta SCREEN + (TRACK1_ROW * 40) + 8,x
            sta SCREEN + (TRACK2_ROW * 40) + 8,x
            sta SCREEN + (TRACK3_ROW * 40) + 8,x
            dex
            bpl clear_good_loop
            rts
```

Less work for a lesser effect—efficient and thematically appropriate.

## Effect Ordering

The update loop processes effects in order:

```asm
            ; Update perfect hit text effect (Unit 37)
            jsr update_perfect_effect

            ; Update good hit text effect (Unit 38)
            jsr update_good_effect
```

Since both effects write to the same screen position, perfect overwrites good if both trigger simultaneously. This is correct—perfect should visually dominate.

## Why This Matters

Visual hierarchy in feedback serves game design:

- **Clear communication** - Players instantly know hit quality
- **Motivation** - Lesser feedback for good hits encourages improvement
- **Satisfaction** - Perfect feels special because good is noticeably less
- **Learning** - Different colours teach timing through play

Without this distinction, players wouldn't understand the timing system.
