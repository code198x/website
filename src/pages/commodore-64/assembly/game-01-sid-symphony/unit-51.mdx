Understanding your frame budget is essential for any real-time game. This unit analyses how many CPU cycles we have per frame, documents where those cycles go, and establishes patterns for keeping performance headroom.

## The Frame Budget

The C64 CPU runs at different speeds depending on TV standard:

| System | Clock Speed | Frame Rate | Cycles/Frame |
|--------|-------------|------------|--------------|
| PAL | 985,248 Hz | 50 Hz | 19,705 |
| NTSC | 1,022,727 Hz | 60 Hz | 17,045 |

We target PAL (the stricter standard for cycles-per-frame), giving us **19,705 cycles** to complete all game logic before the next frame.

## Current Budget Breakdown

```asm
; Current frame budget (PAL, worst case during gameplay):
; - Raster sync:     ~50 cycles (wait loop)
; - State dispatch:  ~20 cycles
; - Note updates:    ~2,000 cycles (8 notes × ~250 cycles)
; - Input handling:  ~100 cycles
; - Display updates: ~500 cycles
; - Audio updates:   ~200 cycles
; - Visual effects:  ~300 cycles
; Total: ~3,170 cycles (~16% of frame budget)
```

We're using only **16% of our frame budget**—plenty of headroom for future features.

## Hot Path Analysis

The "hot paths" are code sections executed most frequently:

| Path | Frequency | Total Cycles/Frame |
|------|-----------|-------------------|
| Main loop dispatch | 1/frame | ~20 |
| Note movement | 8/frame (per note) | ~2,000 |
| Raster sync | 1/frame | ~50 (varies) |
| Input read | 1/frame | ~100 |

Note movement dominates—it's our primary optimisation target for any future work.

## Optimisation Patterns

### 1. Early Exit

Check for conditions that skip work:

```asm
update_notes:
            ; Early exit if no notes active
            lda active_note_count
            beq un_done             ; Skip if nothing to update
            ; ... expensive work ...
un_done:
            rts
```

### 2. Branch Prediction

Put most common cases first:

```asm
            ; STATE_PLAYING is most common during gameplay
            lda game_state
            cmp #STATE_PLAYING
            beq do_playing          ; Most likely path = shortest branch
            cmp #STATE_MENU
            beq do_menu
            ; ... less common states ...
```

### 3. Loop Unrolling

Trade code size for speed in critical loops:

```asm
; Instead of:
            ldx #3
loop:       lda table,x
            sta dest,x
            dex
            bpl loop            ; 5 iterations × (4+4+2+3) = 65 cycles

; Use:
            lda table+0         ; 4 cycles each
            sta dest+0
            lda table+1
            sta dest+1
            lda table+2
            sta dest+2          ; 24 cycles total, saves 41 cycles
```

### 4. Table Lookups

Replace calculations with pre-computed tables:

```asm
; Instead of:
            ; Multiply X by 40 for screen row offset
            ; (complex multi-byte multiplication)

; Use:
            lda row_offset_lo,x     ; Pre-computed table
            sta screen_ptr
            lda row_offset_hi,x
            sta screen_ptr+1        ; 8 cycles vs ~50 for calculation
```

## What We're Not Optimising

Some optimisations aren't worth the trade-offs:

| Optimisation | Savings | Why Not |
|--------------|---------|---------|
| Self-modifying code | ~10% | Harder to debug, cache issues on modern recreations |
| Interrupt-driven main loop | Variable | Added complexity, timing sensitivity |
| Unrolling all loops | ~200 bytes | Code size vs marginal speed gain |

The remaining 84% of frame budget means we don't need aggressive optimisation.

## Cycle Counting

Knowing instruction cycles is essential:

| Instruction | Cycles | Notes |
|-------------|--------|-------|
| LDA #imm | 2 | Immediate |
| LDA zp | 3 | Zero page |
| LDA abs | 4 | Absolute |
| LDA abs,x | 4-5 | +1 if page crossed |
| STA zp | 3 | Zero page |
| STA abs | 4 | Absolute |
| JSR | 6 | Subroutine call |
| RTS | 6 | Return |
| BEQ (taken) | 3-4 | +1 if page crossed |
| BEQ (not taken) | 2 | |

## Profiling Without Tools

On the C64, we profile by changing border colour:

```asm
main_loop:
            lda #2              ; Red border
            sta $D020
            jsr update_playing  ; Code to profile
            lda #0              ; Black border
            sta $D020
            jmp main_loop
```

Wider red stripe = more cycles used. Simple but effective.
