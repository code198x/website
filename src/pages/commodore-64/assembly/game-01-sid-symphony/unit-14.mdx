Failure needs its own moment. This unit gives the game over state proper treatment.

Previously, running out of health showed "GAME OVER" overlaid on the gameplay screen. Now the game clears to a dedicated display: "GAME OVER" in red, "HEALTH DEPLETED" explaining why, the score you achieved, and how many notes you hit before failing. The red border reinforces failure, distinct from the green border of success.

Assemble and run:

```bash
acme -f cbm -o symphony.prg symphony.asm
```

## Success vs Failure

The game now has two distinct endings:

| Aspect | Results (Success) | Game Over (Failure) |
|--------|-------------------|---------------------|
| Trigger | Song completes | Health reaches 0 |
| Title | "SONG COMPLETE!" | "GAME OVER" |
| Colour | Green border | Red border |
| Stats | Full breakdown | Score + notes hit |
| Feeling | Achievement | Try again |

Players immediately know whether they succeeded or failed from the visual language.

## Colour Communicates State

The red colour scheme signals failure:

```asm
            lda #2                  ; Red for failure
            sta COLRAM + (6 * 40) + 15,x   ; Title colour

            ; ...later...

            lda #2                  ; Red border
            sta BORDER
```

Compare to the results screen's green border:

```asm
            lda #5                  ; Green border for success
            sta BORDER
```

Players don't need to read text to understand the outcome.

## Showing Partial Progress

Unlike the success screen, the game over shows simplified stats:

```asm
            ; Show score achieved
            jsr display_gameover_score

            ; Show notes hit (perfects + goods)
            lda perfect_count
            clc
            adc good_count
            jsr display_go_stat
```

We don't show accuracy or max combo - that level of detail is for success. For failure, we show what was achieved before the end.

## Try This: Retry Option

Add a quick retry option instead of returning to title:

```asm
update_gameover:
            ; Check fire for title
            lda CIA1_PRA
            and #$10
            beq go_to_title

            ; Check R key for retry
            lda #$FB
            sta CIA1_PRA
            lda CIA1_PRB
            and #$04            ; R key
            beq retry_game

            ; ... cleanup and return ...

retry_game:
            jsr init_game
            lda #STATE_PLAYING
            sta game_state
            rts
```

Quick retry keeps players in the flow.

## Try This: Continue Counter

Show how many continues have been used:

```asm
continue_count: !byte 0

retry_game:
            inc continue_count
            ; ... draw continue count on gameplay screen ...
```

Some players want to see their full history.

## What You've Learnt

- **Failure presentation** - Dedicated screen for game over
- **Colour communication** - Red for failure, green for success
- **Partial progress** - Showing achievement before failure
- **State distinction** - Visual language separating outcomes
- **Emotional design** - Failure should feel different from success
