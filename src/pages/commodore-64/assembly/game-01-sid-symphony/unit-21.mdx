## Tempo and Perception

Our existing songs run at:

| Song | BPM | Feel |
|------|-----|------|
| First Steps | 120 | Relaxed, beginner-friendly |
| Upbeat Groove | 130 | Moderate, mainstream tempo |

At 150 BPM, notes scroll 25% faster than our slowest song. The visual effect is immediately noticeable—patterns that felt comfortable at 120 BPM become demanding.

## Frames Per Beat

PAL C64 runs at 50 frames per second. We calculate scroll timing as:

```
frames_per_beat = 50 / (BPM / 60) = 3000 / BPM
```

For our three songs:

```asm
; Per-song tempo (frames per beat)
TEMPO_SONG1   = 25              ; 120 BPM (3000/120 = 25)
TEMPO_SONG2   = 23              ; 130 BPM (3000/130 ≈ 23)
TEMPO_SONG3   = 20              ; 150 BPM (3000/150 = 20)
```

Lower values mean faster beats—Song 3's 20 frames between beats is 20% faster than Song 1's 25 frames.

## Song 3 Data

Like our other songs, Song 3 has three difficulty variants:

```asm
; --- EASY: Strong beats only (8 notes) ---
song3_easy:
            !byte 0, 1, $58          ; Beat 0
            !byte 8, 2, $35          ; Beat 8
            !byte 16, 3, $1A         ; Beat 16
            ; ... 8 notes total

; --- NORMAL: Base pattern (32 notes) ---
song3_normal:
            !byte 0, 1, $58
            !byte 2, 2, $35
            !byte 4, 3, $1A
            ; ... 32 notes, every 2 beats

; --- HARD: Dense pattern (56 notes) ---
song3_hard:
            !byte 0, 1, $58
            !byte 1, 3, $1A          ; Added off-beat
            !byte 2, 2, $35
            ; ... notes on nearly every beat
```

The frequencies used ($58, $6A, $47) are higher than Song 1, giving the track a brighter, more energetic sound.

## Song Selection Logic

The transition routine now handles three songs:

```asm
transition_to_game:
            lda selected_song
            beq setup_song1
            cmp #1
            beq setup_song2
            jmp setup_song3

setup_song3:
            lda #TEMPO_SONG3
            sta frames_per_beat
            lda #LENGTH_SONG3
            sta song_length

            ; Select difficulty variant for Song 3
            lda difficulty
            cmp #DIFF_EASY
            beq load_s3_easy
            cmp #DIFF_NORMAL
            beq load_s3_normal
            jmp load_s3_hard
```

Each song sets its own tempo and selects the appropriate difficulty variant.

## Difficulty Stacking

Consider the challenge matrix:

| | Easy | Normal | Hard |
|---|---|---|---|
| Song 1 (120) | Gentle | Balanced | Demanding |
| Song 2 (130) | Moderate | Challenging | Intense |
| Song 3 (150) | Brisk | Demanding | Extreme |

Song 3 Easy provides roughly the challenge of Song 1 Normal—the faster tempo compensates for fewer notes. This gives players a natural progression path:

1. Master Song 1 Easy → Move to Song 1 Normal or Song 2 Easy
2. Master Song 2 Normal → Move to Song 2 Hard or Song 3 Easy
3. Master Song 3 Normal → Attempt Song 3 Hard

## Reaction Time Limits

At 150 BPM with 20 frames per beat, notes scroll quickly. Hard mode with notes on every beat gives players:

```
20 frames ÷ 50 fps = 400ms per note
```

400ms is at the edge of comfortable human reaction time. Beyond this, the game becomes more about anticipation than reaction—players must read patterns ahead rather than respond to what's in front of them.

## Tempo Ceiling

We could push faster (160, 180 BPM), but there are limits:

1. **Visual clarity** - Notes need to be visible long enough to read
2. **Hit detection** - Windows must remain achievable
3. **Player enjoyment** - Challenge should feel fair, not arbitrary

150 BPM tests reactions without becoming frustrating. Future songs might vary in other ways (complex rhythms, syncopation) rather than raw speed.
