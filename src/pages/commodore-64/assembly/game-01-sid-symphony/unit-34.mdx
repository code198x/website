## Frame-Based Animation

The C64 runs at approximately 50 frames per second (PAL). By counting frames and changing colours at intervals, we create smooth animation without complex timing code.

### Animation Frame Counter

We add a variable to track frames:

```asm
title_anim_frame = $25          ; Title screen animation frame counter
```

Every frame during the title state, we increment this counter:

```asm
animate_title:
    inc title_anim_frame
    ; ... animation code
    rts
```

The counter naturally wraps from 255 to 0, creating an endless cycle.

## Logo Colour Cycling

The logo cycles through four colours: light blue, blue, cyan, and back. This creates a shimmering effect.

### Timing the Cycle

We use bit masking to control timing:

```asm
lda title_anim_frame
and #$18            ; Check bits 3-4 (cycle every 8-24 frames)
lsr
lsr
lsr                 ; Now 0, 1, 2, or 3
tax
lda logo_colours,x
```

Breaking this down:
- `and #$18` isolates bits 3 and 4
- After three `lsr` (logical shift right) operations, we get values 0-3
- This changes every 8 frames, giving ~6 complete cycles per second

### Colour Table

```asm
logo_colours:
    !byte 14            ; Light blue
    !byte 6             ; Blue
    !byte 3             ; Cyan
    !byte 14            ; Light blue
```

The sequence returns to light blue at index 3, creating smooth continuity.

### Applying Colours

We update colour RAM for both logo rows:

```asm
; Apply to logo row 1 (row 4)
ldx #15
anim_logo1:
    sta COLRAM + (4 * 40) + 12,x
    dex
    bpl anim_logo1
```

The loop writes the same colour to all 16 characters of the logo row. Using `dex` and `bpl` (branch if positive) is faster than comparing to zero.

## Pulsing Text

The "PRESS FIRE TO START" text alternates between yellow and white, drawing the player's eye to the action they should take.

### Slower Pulse Rate

```asm
lda title_anim_frame
and #$10            ; Toggle every 16 frames
beq press_fire_yellow
lda #1              ; White
jmp set_press_fire_col
press_fire_yellow:
    lda #7          ; Yellow
```

The `and #$10` checks bit 4, which toggles every 16 frames. This gives a slower, more comfortable pulse than the logo animation—about 1.5 cycles per second.

### Why Different Rates?

- **Logo**: Fast cycling (8 frames) creates shimmer and energy
- **Call to action**: Slower pulse (16 frames) is attention-grabbing without being frantic

Different animation rates for different purposes. The eye naturally goes to the slower-pulsing element.

## Integration with Game Loop

The animation runs every frame while on the title screen:

```asm
update_title:
    jsr animate_title       ; Run animation first

    ; Then check for input
    lda CIA1_PRA
    and #$10
    beq title_fire_pressed
    ; ... rest of input handling
```

By calling animation before input checking, we ensure smooth visuals even while waiting for the player.

## Performance Considerations

This animation is lightweight:
- Colour RAM writes are fast (no VIC-II timing issues)
- We only update ~35 bytes per frame
- No sprites or character data modified

For title screens, performance rarely matters—the main game isn't running. But these good habits carry over to more demanding situations.

## Animation Patterns

These techniques work anywhere:

| Pattern | Mask | Result |
|---------|------|--------|
| `and #$08` | Every 8 frames | ~6 Hz (fast shimmer) |
| `and #$10` | Every 16 frames | ~3 Hz (comfortable pulse) |
| `and #$20` | Every 32 frames | ~1.5 Hz (slow fade) |
| `and #$3F` | Every 64 frames | ~0.8 Hz (very slow) |

Choose based on the feeling you want to create.
