Unit 19 gave us difficulty levels, but they only affected timing windows and health penalties. The same notes appeared regardless of difficulty.

This unit takes difficulty further: each level now has its own note pattern. Easy strips songs to strong beats only. Hard fills in off-beat notes. The song remains recognisable, but the challenge changes dramatically.

## The Pattern Problem

In Unit 19, Easy and Hard shared identical note patterns:

```
Easy:   [note]----[note]----[note]  (forgiving timing)
Normal: [note]----[note]----[note]  (balanced timing)
Hard:   [note]----[note]----[note]  (precise timing)
```

This works, but experts on Easy still face the same note density. Newcomers on Hard see the same patterns, just with stricter timing. The challenge difference isn't dramatic enough.

## The Solution: Difficulty-Variant Data

We create three versions of each song's note data:

```
Easy:   [note]--------[note]--------  (fewer notes)
Normal: [note]----[note]----[note]--  (base pattern)
Hard:   [note]-[note]-[note]-[note]-  (dense notes)
```

Same song structure, different note density. Easy players face fewer notes. Hard players face a relentless stream.

## Song Data Structure

Our note format uses three bytes per note:

```asm
; Song data format: beat, track, frequency_hi
; Terminated by $FF
song1_normal:
            !byte 0, 1, $47          ; Beat 0, track 1
            !byte 2, 2, $2C          ; Beat 2, track 2
            !byte 4, 3, $11          ; Beat 4, track 3
            ; ... more notes ...
            !byte $FF                 ; End marker
```

The beat number determines when the note appears. Lower numbers mean earlier in the song cycle.

## Easy: Strong Beats Only

For Easy difficulty, we keep only notes on multiples of 8 (strong beats):

```asm
song1_easy:
            !byte 0, 1, $47          ; Beat 0 - strong
            !byte 8, 2, $27          ; Beat 8 - strong
            !byte 16, 1, $35         ; Beat 16 - strong
            !byte 24, 3, $11         ; Beat 24 - strong
            !byte 32, 2, $2F         ; Beat 32 - strong
            !byte 40, 1, $58         ; Beat 40 - strong
            !byte 48, 3, $1A         ; Beat 48 - strong
            !byte 56, 1, $47         ; Beat 56 - strong
            !byte $FF
```

Only 8 notes instead of the normal 29. The pattern is sparse but still recognisable—you're playing the song's skeleton.

## Normal: The Base Pattern

Normal uses the original pattern from previous units:

```asm
song1_normal:
            !byte 0, 1, $47
            !byte 2, 2, $2C
            !byte 4, 3, $11
            !byte 8, 1, $3B
            !byte 10, 2, $27
            !byte 12, 3, $13
            ; ... 29 notes total ...
            !byte $FF
```

This is the "correct" song—what the composer intended.

## Hard: Off-Beat Additions

For Hard, we insert notes between existing ones:

```asm
song1_hard:
            !byte 0, 1, $47
            !byte 1, 3, $16          ; Added off-beat
            !byte 2, 2, $2C
            !byte 3, 1, $35          ; Added off-beat
            !byte 4, 3, $11
            !byte 5, 2, $2C          ; Added off-beat
            ; ... 45 notes total ...
            !byte $FF
```

The original notes remain, but new notes fill the gaps. Players must react faster and more frequently.

## Loading the Right Pattern

When the player starts a song, we select the appropriate data:

```asm
transition_to_game:
            ; ... save selected song ...
            jsr set_difficulty_params

            ; Choose song data variant
            lda selected_song
            beq setup_song1
            jmp setup_song2

setup_song1:
            lda difficulty
            cmp #DIFF_EASY
            beq load_s1_easy
            cmp #DIFF_NORMAL
            beq load_s1_normal
            jmp load_s1_hard

load_s1_easy:
            lda #<song1_easy
            sta song_data_ptr
            lda #>song1_easy
            sta song_data_ptr+1
            jmp start_game

load_s1_normal:
            lda #<song1_normal
            sta song_data_ptr
            lda #>song1_normal
            sta song_data_ptr+1
            jmp start_game

load_s1_hard:
            lda #<song1_hard
            sta song_data_ptr
            lda #>song1_hard
            sta song_data_ptr+1
            jmp start_game
```

The `song_data_ptr` zero-page variable holds the address of whichever pattern we selected. All subsequent note-reading uses this pointer.

## Design Philosophy

Difficulty-variant data follows these principles:

1. **Preserve musicality** - Easy notes should still sound like the song
2. **Recognisable structure** - Same song, different density
3. **Appropriate challenge** - Easy should feel calm; Hard should feel frantic
4. **Clear progression** - Normal sits naturally between extremes

We achieve this by:
- Easy: Keep notes on strong beats (0, 8, 16, 24, 32, 40, 48, 56)
- Normal: Use the original composed pattern
- Hard: Add notes on previously empty beats

## Memory Considerations

Each song now takes three times the space. For our small patterns, this is fine. Larger games might:

- Generate variants algorithmically at load time
- Store a base pattern plus "modifier" data
- Use compression for similar patterns

For SID Symphony, explicit data is clearest.

- **Difficulty-variant data** - Same song, different note patterns
