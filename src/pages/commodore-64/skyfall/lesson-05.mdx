## How the C64 Keyboard Works

The C64 keyboard is wired as an 8×8 matrix. The CIA chip (Complex Interface Adapter) at `$DC00` controls reading it.

You don't need to understand the full matrix - just that specific memory addresses tell you if specific keys are pressed.

Key addresses we care about:
- `$DC01` - Keyboard matrix row read
- `$DC00` - Keyboard matrix column select

By writing to `$DC00` and reading from `$DC01`, you can check any key on the keyboard.

## Reading Specific Keys

For Skyfall, we need left and right movement. Let's use:
- **A key** - Move left
- **D key** - Move right

(We'll add arrow key support later, but A/D is simpler to start with.)

Here's how to check if the A key is pressed:

<div class="code-block">
<div class="code-block-header">Check A Key</div>

```asm
; Add to constants
CIA1_PORT_A = $dc01            ; Keyboard row read
CIA1_PORT_B = $dc00            ; Keyboard column select

; Check if A key is pressed
check_a_key:
    lda #%11111101             ; Select keyboard column for A key
    sta CIA1_PORT_B
    lda CIA1_PORT_A
    and #%00000100             ; Check bit 2 for A key
    beq a_pressed              ; If zero, key is pressed
    rts

a_pressed:
    ; A key is down - we'll use this next lesson
    rts
```
</div>

How this works:
1. Write a column select value to `$DC00`
2. Read the row state from `$DC01`
3. Check specific bits with `and`
4. If the bit is 0, that key is pressed

## Testing Keyboard Input

Let's make a simple test: press A to change the border color, press D to change it back.

<div class="code-block">
<div class="code-block-header">skyfall.asm</div>

```asm
; SKYFALL - Lesson 5
; Keyboard input test

* = $0801

; BASIC stub: SYS 2061
!byte $0c,$08,$0a,$00,$9e
!byte $32,$30,$36,$31          ; "2061" in ASCII
!byte $00,$00,$00

* = $080d

; ===================================
; Constants
; ===================================
VIC_BORDER = $d020
VIC_RASTER = $d012
CIA1_PORT_A = $dc01
CIA1_PORT_B = $dc00

BLACK = $00
WHITE = $01
RED = $02
CYAN = $03

; ===================================
; Main Program
; ===================================
main:
    lda #BLACK
    sta VIC_BORDER

input_loop:
    jsr wait_for_raster        ; Sync to screen refresh
    jsr check_keys
    jmp input_loop             ; Loop forever, checking keys

; ===================================
; Subroutines
; ===================================

wait_for_raster:
    lda VIC_RASTER
    cmp #250
    bne wait_for_raster
    rts

check_keys:
    jsr check_a_key
    jsr check_d_key
    rts

check_a_key:
    lda #%11111101             ; Select column for A key
    sta CIA1_PORT_B
    lda CIA1_PORT_A
    and #%00000100             ; Check bit 2
    beq a_is_pressed           ; Branch if pressed (bit = 0)
    rts

a_is_pressed:
    lda #RED
    sta VIC_BORDER             ; Change border to red
    rts

check_d_key:
    lda #%11111101             ; Same column for D key
    sta CIA1_PORT_B
    lda CIA1_PORT_A
    and #%00010000             ; Check bit 4
    beq d_is_pressed
    rts

d_is_pressed:
    lda #CYAN
    sta VIC_BORDER             ; Change border to cyan
    rts
```
</div>

Build and run. Hold the A key - border turns red. Hold D - border turns cyan.

<div class="note">
<div class="note-title">⚠️ Important</div>
Press RUN/STOP + RESTORE to break out of the loop and return to BASIC.
</div>

## Why This Works

The program enters an infinite loop (`input_loop`) that constantly checks the keyboard. When you press A or D, it immediately changes the border color.

This is **polling** - constantly checking for input. Real games will do this 50/60 times per second inside the game loop.

## Common Keyboard Bit Patterns

Here are the values for keys you'll commonly use:

**A Key:**
- Column select: `%11111101` (write to `$DC00`)
- Bit check: `and #%00000100` (check `$DC01`)

**D Key:**
- Column select: `%11111101`
- Bit check: `and #%00010000`

**Space Bar:**
- Column select: `%01111111`
- Bit check: `and #%00010000`

**Cursor Left/Right:**
- Column select: `%11111110`
- Left: `and #%00000100`
- Right: `and #%00001000`

You don't need to memorize these - keep a reference sheet handy and copy the patterns as needed.

## New Concepts

### Opcodes Used in This Lesson

**and #$xx** - Bitwise AND
- Compares each bit of A with the immediate value
- Result: bit is 1 only if both original bits were 1
- Used to "mask" and check specific bits
- Example: `and #%00000100` checks if bit 2 is set

**beq label** - Branch if Equal (to zero)
- Opposite of `bne` from Lesson 2
- Jumps to label if last operation resulted in zero
- Example: After `and`, if the bit was 0 (key pressed), `beq` branches

**jmp label** - Jump
- Unconditional jump to a label
- Unlike `jsr`, this doesn't return
- Example: `jmp input_loop` creates an infinite loop

### The CIA Chip

The CIA (Complex Interface Adapter) handles keyboard, joystick, and some timing functions. Like the VIC-II, you control it by writing to special addresses.

`$DC00` and `$DC01` are CIA registers. You'll learn more CIA registers when we add sound and timing.

### Bit Patterns and Masks

The `%` prefix means binary notation: `%11111101` = binary = `$FD` hex = 253 decimal.

Binary is useful when working with hardware because each bit controls something specific. The `and` instruction lets you check individual bits.
