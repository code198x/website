## Lesson 38 – Collision Layers

When everything shares one collision rule, games feel unfair. By splitting collisions into layers—background tiles, collectibles, hazards—you control how each overlap behaves. The VIC-II gives us two handy status registers so we can detect walls separately from sprite encounters, then resolve each interaction cleanly.

---

### The One-Minute Tour

- `PEEK(53278)` flags sprite-vs-background collisions.
- `PEEK(53279)` flags which sprites have touched another sprite.
- React immediately, then read the registers again next frame—they clear on read.

### Example Program

```basic
NEW
10 REM *** COLLISION LAYERS ***
20 PRINT CHR$(147)
30 PRINT "SCORE:0  LIVES:3"
35 R=RND(-TI)
40 FOR C=0 TO 39
50 POKE 1024+12*40+C,160:POKE 55296+12*40+C,2
60 NEXT C
70 POKE 2040,13:POKE 2041,14:POKE 2042,15
80 POKE 53269,7
90 POKE 53287,6:POKE 53288,10:POKE 53289,2
100 PX=80:PY=200:FX=280:FY=90:HX=140:HY=80:HS=2
110 LIVES=3:SCORE=0
120 GOSUB 300
130 OLDPX=PX:OLDPY=PY
140 GET K$
150 IF K$="A" THEN PX=PX-3
160 IF K$="D" THEN PX=PX+3
170 IF K$="W" THEN PY=PY-3
180 IF K$="S" THEN PY=PY+3
190 IF PX<24 THEN PX=24
200 IF PX>320 THEN PX=320
210 IF PY<60 THEN PY=60
220 IF PY>233 THEN PY=233
230 POKE 53248,PX:POKE 53249,PY
240 COLB=PEEK(53278)
250 IF COLB AND 1 THEN PX=OLDPX:PY=OLDPY:POKE 53248,PX:POKE 53249,PY
260 COLS=PEEK(53279)
270 IF COLS AND 2 THEN SCORE=SCORE+100:GOSUB 320
280 IF COLS AND 4 THEN LIVES=LIVES-1:PX=80:PY=200:GOSUB 350:IF LIVES=0 THEN PRINT CHR$(19);"GAME OVER":END
290 HY=HY+HS:IF HY<70 OR HY>200 THEN HS=-HS:HY=HY+HS
300 POKE 53250,FX:POKE 53251,FY
310 POKE 53252,HX:POKE 53253,HY
320 GOSUB 300
330 FOR D=1 TO 4:NEXT D
340 OLDPX=PX:OLDPY=PY
350 GOTO 140
300 PRINT CHR$(19);"SCORE:";SCORE;TAB(18);"LIVES:";LIVES
310 RETURN
320 FX=60+INT(RND(1)*220):FY=70+INT(RND(1)*110)
330 POKE 53250,FX:POKE 53251,FY
340 RETURN
350 HX=40+INT(RND(1)*240):HY=70+INT(RND(1)*120)
360 POKE 53252,HX:POKE 53253,HY
370 RETURN
```

A solid wall lives on row 12 (lines 40–60). The player sprite (0) flies around, sprite 1 is a fuel cell, and sprite 2 is a prowling hazard. When the player touches the wall, line 250 spots the background collision (`COLB AND 1`) and snaps the sprite back to its previous position. Fuel pickups trigger bit 1 (`COLS AND 2`), adding 100 points and respawning elsewhere. Hazard collisions use bit 2 (`COLS AND 4`) to drain a life, reset the player, and reroll the hazard’s patrol. The scoreboard is redrawn each frame via the subroutine at line 300.

> **Tip:** Read `53278` and `53279` once per frame, store the results, and act on the stored values. Every read clears the register, so grabbing it twice will lose the data.

### Experiment Section

- Add separate `DATA` arrays for collectible positions and rebuild the map when you clear a stage.
- Replace the solid wall with a scrolling row to see how background collisions behave in motion.
- Track invincibility frames: set `HITTIME=TI` when you lose a life and ignore hazard collisions until a delay passes.
- Trigger sound effects (`POKE 54272`) for each collision type to reinforce feedback.

### Concept Expansion

Layered collisions keep your logic simple. Background hits resolve immediately by snapping positions. Collectibles alter score or inventory, then vanish. Hazards affect health or states. Once you trust each layer, you can add more—enemy projectiles, moving platforms, parallax decorations—without the whole system collapsing.

---

### Game Integration

Use layers to gate level progress:

```basic
IF COLB AND 1 THEN CAN_SCROLL=0
IF COLS AND 2 THEN CRYSTALS=CRYSTALS+1
IF CRYSTALS=TOTAL THEN CAN_SCROLL=1
```

Only when the player clears every collectible does the scroll lock release, tying collisions directly to progression.

### Quick Reference

```basic
REM Collision registers
COLB=PEEK(53278) : REM sprite vs background
COLS=PEEK(53279) : REM sprite vs sprite

REM Bit masks
1 = sprite 0
2 = sprite 1
4 = sprite 2

REM Typical responses
IF COLB AND 1 THEN RESTORE_POSITION
IF COLS AND 2 THEN COLLECT_ITEM
IF COLS AND 4 THEN TAKE_DAMAGE
```

### What You’ve Learnt

- The VIC-II separates background and sprite collisions so you can act appropriately.
- Reading the registers clears them—store once, then respond.
- Clear reactions (bounce, award, damage) keep multi-layered gameplay understandable.
