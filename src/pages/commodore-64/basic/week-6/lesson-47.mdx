## Split the Screen!

Ever noticed how **International Karate** has different coloured borders at the top and bottom? Or how **Creatures** splits the screen into multiple zones? That's **raster interrupts**!

The CRT monitor draws the screen line-by-line, top to bottom. By waiting for the beam to reach a specific line, you can change colours mid-screen—creating bars, borders, and split-screen effects that shouldn't be possible!

## Basic Example

Wait for raster line 100:

```basic
10 REM *** RASTER WAIT ***
20 PRINT CHR$(147)
30 POKE 53280,6
40 IF PEEK(53266)<>100 THEN GOTO 40
50 POKE 53280,14
60 GOTO 40
```

The border changes colour halfway down! PEEK(53266) is the current raster line (0-255). The loop waits until the beam reaches line 100, then changes the border colour. The top is blue, the bottom is light blue!

## Practical Example

Multi-coloured border bars:

```basic
10 REM *** COLOUR BARS ***
20 PRINT CHR$(147)
30 IF PEEK(53266)<>50 THEN GOTO 30
40 POKE 53280,2
50 IF PEEK(53266)<>100 THEN GOTO 50
60 POKE 53280,10
70 IF PEEK(53266)<>150 THEN GOTO 70
80 POKE 53280,7
90 IF PEEK(53266)<>200 THEN GOTO 90
100 POKE 53280,5
110 GOTO 30
```

Four colour bars! The border changes at lines 50, 100, 150, and 200—creating horizontal stripes across the screen. Each wait synchronises with the raster beam position!

## WOW Moment: Rainbow Raster Bars

```basic
NEW
10 REM *** RAINBOW BARS ***
20 PRINT CHR$(147)
30 PRINT "*** RASTER DEMO ***"
40 PRINT
50 PRINT "WATCH THE BORDER!"
60 PRINT
70 PRINT "THE SCREEN IS DRAWN"
80 PRINT "LINE BY LINE..."
90 PRINT
100 PRINT "...AND WE CHANGE"
110 PRINT "THE COLOUR AS IT DRAWS!"
120 PRINT
130 PRINT "PRESS Q TO QUIT"
140 C=0
150 L=50
160 IF PEEK(53266)<>L THEN GOTO 160
170 POKE 53280,C
180 C=C+1
190 IF C>15 THEN C=0
200 L=L+4
210 IF L>250 THEN L=50:C=0
220 GET K$:IF K$="Q" THEN END
230 GOTO 160
```

![Rainbow raster bars effect](/images/lessons/commodore-64/basic/week-6/lesson-47/raster.png)

A rainbow of colour bars! Every 4 raster lines, the border colour changes—cycling through all 16 colours. This creates smooth rainbow bars that flow down the screen!

The raster beam draws the screen top-to-bottom, 50 times per second. By changing colours as it draws, you create effects that look impossible—more colours than the hardware should allow!

This is the secret behind demo scene effects and games with elaborate borders!

## Quick Reference

```basic
REM RASTER POSITION
PEEK(53266)              Current raster line (0-255)
PEEK(53265) bit 7        Raster line bit 8 (for 256-312)

REM WAIT FOR LINE
IF PEEK(53266)<>line THEN GOTO wait
Waits until beam reaches exact line

REM SAFE ZONES
Lines 0-50               Top border area
Lines 51-250             Visible screen area
Lines 251-312            Bottom border/offscreen

REM COLOUR CHANGES
POKE 53280,colour        Border colour
POKE 53281,colour        Background colour
Do immediately after raster wait

REM TIMING
4 lines per colour       Thick bars
1 line per colour        Thin bars
Loop back to start       Continuous cycle

REM COLOUR CYCLING
C=C+1                    Next colour
IF C>15 THEN C=0         Wrap to black
Creates rainbow effect   16 colours
```

## What You've Learnt

- CRT monitor draws screen line-by-line (raster scan)
- PEEK(53266) returns current raster line number
- Wait loops synchronise code with raster position
- Changing colours during scan creates split-screen effects
- Multiple raster waits create colour bars
- Raster timing enables "impossible" effects

This is the foundation of C64 demo scene effects—professional demos use assembly language for precise timing, but BASIC can create impressive raster bars too!
