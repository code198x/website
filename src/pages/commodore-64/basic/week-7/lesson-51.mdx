## Control Your Game Flow!

Professional games move through states—**Elite**'s title→docking→trading→combat, **Paradroid**'s menu→gameplay→transfer mode→complete. Game states manage the flow from start to finish!

You'll create a state machine handling TITLE → PLAY → GAME OVER → TITLE. This is the architecture that structured every complete C64 game!

## Basic Example

Simple state variable:

```basic
10 REM *** BASIC STATES ***
20 S=0
30 IF S=0 THEN PRINT "TITLE SCREEN":S=1
40 IF S=1 THEN PRINT "PLAYING...":S=2
50 IF S=2 THEN PRINT "GAME OVER":S=0
60 GOTO 30
```

The state variable S controls which part runs! S=0 is title, S=1 is gameplay, S=2 is game over. But this runs too fast—we need proper transitions!

## Practical Example

States with transitions:

```basic
10 REM *** STATE MACHINE ***
20 S=0
30 REM *** TITLE STATE ***
40 IF S<>0 THEN GOTO 100
50 PRINT CHR$(147)
60 PRINT "*** PRESS FIRE TO START ***"
70 GET K$:IF K$="" THEN GOTO 70
80 S=1
90 GOTO 30
100 REM *** PLAY STATE ***
110 IF S<>1 THEN GOTO 160
120 PRINT CHR$(147)
130 PRINT "PLAYING... PRESS Q TO QUIT"
140 GET K$:IF K$="Q" THEN S=2
150 GOTO 110
160 REM *** GAME OVER STATE ***
170 IF S<>2 THEN GOTO 30
180 PRINT CHR$(147)
190 PRINT "GAME OVER"
200 FOR I=1 TO 2000:NEXT I
210 S=0
220 GOTO 30
```

Now each state has its own section! Line 40 checks if we're in title state (S=0), line 110 checks play state (S=1), line 170 checks game over (S=2). The game loops through states based on player input!

## WOW Moment: Complete Game State Flow

```basic
NEW
10 REM *** COMPLETE GAME STATES ***
20 S=0:SC=0:LI=3
30 REM *** STATE DISPATCHER ***
40 ON S+1 GOTO 100,200,300,400
50 REM
100 REM *** TITLE STATE ***
110 PRINT CHR$(147)
120 POKE 53280,6:POKE 53281,14
130 PRINT
140 PRINT "    *** SPACE CHASE ***"
150 PRINT
160 PRINT "      LIVES: 3"
170 PRINT "      SCORE: 0"
180 PRINT
190 PRINT "   PRESS FIRE TO START"
200 GET K$:IF K$="" THEN GOTO 200
210 SC=0:LI=3:S=1
220 GOTO 30
230 REM
300 REM *** PLAY STATE ***
310 PRINT CHR$(147)
320 POKE 53280,0:POKE 53281,0
330 PRINT "LIVES:";LI;" SCORE:";SC
340 PRINT
350 PRINT "PLAYING..."
360 PRINT "(SPACE=POINT, Q=DIE)"
370 REM *** SIMPLE GAMEPLAY ***
380 GET K$:IF K$="" THEN GOTO 380
390 IF K$=" " THEN SC=SC+10:GOTO 300
400 IF K$="Q" THEN LI=LI-1:S=2
410 GOTO 300
420 REM
500 REM *** DEAD STATE ***
510 PRINT CHR$(147)
520 POKE 53280,2:POKE 53281,8
530 PRINT
540 PRINT "       YOU DIED!"
550 PRINT
560 PRINT "    LIVES LEFT:";LI
570 FOR I=1 TO 1500:NEXT I
580 IF LI>0 THEN S=1:GOTO 30
590 S=3
600 GOTO 30
610 REM
700 REM *** GAME OVER STATE ***
710 PRINT CHR$(147)
720 POKE 53280,0:POKE 53281,0
730 PRINT
740 PRINT "      GAME OVER"
750 PRINT
760 PRINT "   FINAL SCORE:";SC
770 PRINT
780 PRINT
790 PRINT " PRESS FIRE TO RESTART"
800 FOR I=1 TO 100:NEXT I
810 GET K$:IF K$="" THEN GOTO 810
820 S=0
830 GOTO 30
```

![Complete game state machine](/images/lessons/commodore-64/basic/week-7/lesson-51/states.png)

A complete game state system! Four states with smooth transitions:

- **S=0 (TITLE)**: Show game name, press fire to start
- **S=1 (PLAY)**: Gameplay with score and lives tracking
- **S=2 (DEAD)**: Death screen, check if lives remain
- **S=3 (GAME OVER)**: Final score, press fire to restart

Line 40 uses calculated GOTO—`ON S+1 GOTO` jumps to different lines based on state value. Each state has its own colour scheme and screen layout!

If you die with lives remaining, return to PLAY state. If lives reach 0, move to GAME OVER state. This is exactly how **Paradroid**, **Uridium**, and **Impossible Mission** structured their game flow!

Try adding more states (instructions, high score entry), changing colours per state, or adding state-specific music!

## Quick Reference

```basic
REM STATE MACHINE STRUCTURE
S=0                         Current state
ON S+1 GOTO 100,200,300    Calculated jump

REM STATE PATTERN
100 REM *** STATE 0 ***
110 IF S<>0 THEN GOTO 200  Skip if not current
120 ... state code ...
130 S=1                     Transition
140 GOTO main loop

REM COMMON STATES
S=0  Title/Menu
S=1  Playing
S=2  Paused
S=3  Death/Dying
S=4  Game Over
S=5  High Score Entry

REM STATE TRANSITIONS
IF lives=0 THEN S=4         Game over
IF K$="P" THEN S=2          Pause
IF timer=0 THEN S=3         Time up
IF score>high THEN S=5      New record

REM STATE BEST PRACTICES
- One state active at a time
- Clear entry/exit points
- Track state in variable
- Use colours to distinguish states
- Reset variables on state change
```

## What You've Learnt

- State machines organise game flow
- Each state has specific purpose and visuals
- Calculated GOTO dispatches to state code
- Transitions based on game conditions
- Lives and score persist across states
- Professional games always used state systems

Every complete C64 game used state machines—now you understand the architecture!
