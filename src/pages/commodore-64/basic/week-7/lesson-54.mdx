## Lesson 54 – Debugging Retro-Style

When something goes wrong on real hardware, you can’t rely on a modern debugger. Old-school coders peppered their programs with trace prints, pauses, and quick HUDs to reveal the bug. We’ll do the same.

> [📷 suggested: screenshot showing debug HUD with velocity and collision flags]

---

### The One-Minute Tour

- Use a global `TRACE` flag to turn verbose logging on/off without deleting statements.
- Build a `DEBUGHUD` subroutine that redraws variable values at the top of the screen every frame.
- Add a pause hotkey to freeze the loop right before things go wrong.

---

### Example Program

```basic
NEW
10 REM *** DEBUGGING DEMO ***
20 GOSUB 900
30 TRACE=1:PAUSE=0
40 PX=120:PY=120:VX=3:VY=0:GRAV=1
50 PRINT CHR$(147)
60 PRINT "D = toggle debug   P = pause   SPACE = step"
70 PRINT
80 GOSUB 300
90 GET K$:IF K$="D" THEN TRACE=1-TRACE
100 IF K$="P" THEN PAUSE=1-PAUSE
110 IF K$=" " AND PAUSE THEN GOTO 140
120 IF PAUSE THEN GOTO 90
130 GOTO 140
140 VY=VY+GRAV
150 PX=PX+VX:PY=PY+VY
160 IF PY>210 THEN PY=210:VY=-INT(VY/2):CALL=1:GOSUB 400
170 GOSUB 200
180 GOSUB 300
190 FOR W=1 TO 4:NEXT W
200 GOTO 90

200 REM *** DRAW SPRITE (TEXT) ***
210 PRINT CHR$(19);TAB(0);
220 PRINT "POS:";PX;",";PY;"    "
230 PRINT TAB(0);
240 PRINT CHR$(19);TAB(PX/8);CHR$(81)
250 RETURN

300 REM *** DEBUG HUD ***
310 IF TRACE=0 THEN RETURN
320 PRINT CHR$(19);TAB(0);
330 PRINT "VX:";VX;"  VY:";VY;"  PAUSE:";PAUSE;"   "
340 RETURN

400 REM *** COLLISION TRACE ***
410 IF TRACE THEN PRINT "BOUNCE!";" VY=";VY
420 RETURN

900 REM *** INITIALISE ***
910 POKE 646,1
920 RETURN
```

Sample output (trace enabled):

```
D = toggle debug   P = pause   SPACE = step

VX:3  VY:5  PAUSE:0
POS:135,185
BOUNCE! VY=-3
```

`TRACE` controls whether the HUD prints. When `TRACE=0`, the `DEBUGHUD` subroutine (300) exits immediately, giving you instant silence. `PAUSE` freezes the update loop, while `SPACE` lets you step frame by frame until the bug appears. Collision handling (400) prints a one-line message only when `TRACE` is active, so you can see exactly when the bounce occurs.

> **Tip:** Keep debug prints short and overwrite them using `CHR$(19)` (home cursor) plus spaces so the screen stays tidy.

### Experiment Section

- Direct the trace to a log file: open `DEBUG,S,W` and `PRINT#` critical events so you can review them later.
- Track a “last safe” copy of your player position and show it in the HUD to catch teleport glitches.
- Add a frame counter and print it whenever a collision happens so you can reproduce the exact moment.
- Combine with Lesson 49 by storing debug routines in a library block you can drop into any project.

### Concept Expansion

Instrument everything: AI decisions, power-up timers, level transitions. Temporary debug code is cheap in BASIC—comment it out or toggle it off once the bug is solved. The goal is visibility without losing the feel of the running game.

---

### Game Integration

Wrap your HUD inside `IF TRACE` checks:

```basic
IF TRACE THEN GOSUB 3600
IF TRACE AND EVENT THEN PRINT "EVENT:";VALUE
```

Leave the HUD routine parked at line `3600` (label it `REM DEBUG OVERLAY`) and simply set `TRACE=0` for release builds.

### Quick Reference

```basic
REM Toggle trace
TRACE=1-TRACE

REM Pause/step
IF PAUSE THEN IF KEY$=" " THEN RUN_FRAME

REM HUD redraw
PRINT CHR$(19);TAB(0);
PRINT "VX:";VX
```

### What You’ve Learnt

- A couple of toggles and HUD prints turn opaque bugs into obvious ones.
- You can pause and single-step a BASIC loop without special hardware.
- Debug tooling belongs in your library—turn it on only when you need it.
