## Lesson 53 – Cutscenes in BASIC

A quick story between levels turns a set of mechanics into an adventure. Cutscenes are glorified text players: show a line, wait a moment, maybe play a sound, and let impatient players skip. Let’s build a reusable cutscene runner.

---

### The One-Minute Tour

- Store each beat as `(speaker$, line$, delayFrames)` so pacing lives beside text.
- Use the system clock (`TI`) to time the pause while still polling for skip input.
- Wrap the runner in a subroutine: load a new script with `RESTORE`, call `GOSUB 1000`, and you’re done.

---

### Example Program

```basic
NEW
10 REM *** CUTSCENE PLAYER ***
20 GOSUB 9000
30 PRINT CHR$(147);"LEVEL 1 COMPLETE!"
40 PRINT
50 GOSUB 1000
60 PRINT :PRINT "LOADING NEXT LEVEL..."
70 END

9000 REM *** COUNT LINES ***
9010 SCENE=0
9020 RESTORE 5000
9030 READ SPEAKER$
9040 IF SPEAKER$="END" THEN RETURN
9050 READ LINE$:READ DELAY
9060 SCENE=SCENE+1
9070 GOTO 9030

1000 REM *** PLAY CUTSCENE ***
1010 PRINT CHR$(147)
1020 PRINT "~ GALACTIC NEWSFEED ~"
1030 RESTORE 5000
1040 FOR I=1 TO SCENE
1050 READ SPEAKER$:IF SPEAKER$="END" THEN RETURN
1060 READ LINE$:READ WAITFRAMES
1070 PRINT :PRINT SPEAKER$;":"
1080 PRINT "  ";LINE$
1090 GOSUB 1200
1100 NEXT I
1110 RETURN

1200 REM *** PAUSE WITH SKIP ***
1210 FRAME=0:TI$="000000"
1220 GET K$:IF K$<>"" THEN RETURN
1230 IF TI>FRAME THEN FRAME=FRAME+1
1240 IF FRAME<WAITFRAMES THEN 1220
1250 RETURN

5000 DATA "COMMAND","Miner, you survived the collapse!",80
5010 DATA "MINER","Barely. Reactor core went critical in seconds.",90
5020 DATA "COMMAND","Next stop: Crystal Cavern. Expect seismic spikes.",100
5030 DATA "MINER","Send more juice to the drill. We're burning daylight.",80
5040 DATA "END","",0
```

Sample output:

```
~ GALACTIC NEWSFEED ~

COMMAND:
  Miner, you survived the collapse!

MINER:
  Barely. Reactor core went critical in seconds.
```

Lines 5000–5040 hold the script. The initialiser (9000) counts entries so we know how many loops to run. The player (1000) uses `RESTORE` to rewind, prints each speaker/line pair, and calls the pause routine. `WAITFRAMES` expresses how long to linger, measured in jiffies (1/60th seconds). The pause routine polls `GET`; if the player presses any key, the cutscene skips to the next line immediately.

> **Tip:** Keep dialogue short—two lines of text fit nicely on most screens and avoid pushing prompts off the bottom.

---

### Experiment Section

- Trigger a SID sting by calling your sound library whenever `SPEAKER$="COMMAND"`.
- Add staging commands such as colour changes by reading an optional fourth value from each `DATA` line.
- Use different `RESTORE` targets (`6000`, `7000`) for intro, mid-level, and ending scenes.
- Fade between lines by poking `53281` to black, printing, then restoring the previous colour before the next line.

### Concept Expansion

Cutscenes reuse your state work: play them between levels, before bosses, or to recap goals. Because they’re just data, collaborators can script dialogue without touching code. Later you can pair them with Lesson 55 speed tricks to pre-render lines faster.

---

### Game Integration

Keep a loader per scene:

```basic
RESTORE SCENE(L)
GOSUB 1000
```

Keep an array such as `SCENE(1)=5000`, `SCENE(2)=5200`, and so on. Call it before loading the next level, and again before the mini-game finale to celebrate success.

### Quick Reference

```basic
REM Data format
DATA "SPEAKER","Line of text", delay

REM Skip support
GET K$:IF K$<>"" THEN RETURN

REM Timer loop
IF TI>FRAME THEN FRAME=FRAME+1
```

### What You’ve Learnt

- Structured DATA scripts let you add story without new logic for each scene.
- Timed pauses keep pacing under your control while still allowing impatient players to skip.
- Wrapping the player in a subroutine makes cutscenes reusable anywhere in the game.
