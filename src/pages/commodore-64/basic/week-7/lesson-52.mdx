## Lesson 52 – Multiple Levels

You now have menus and systems; it’s time to move beyond a single arena. This lesson shows how to pack multiple level layouts and metadata into `DATA` blocks, load any level on demand, and reset the player to a fresh spawn.

> [📷 suggested: three different maps loaded in sequence]

---

### The One-Minute Tour

- Structure each level as `(id, rows, title$, row$, row$, …, spawnX, spawnY)` in `DATA`.
- Use `RESTORE` plus a scanning loop to skip levels you don’t need until you reach the requested one.
- Wrap the loader in a subroutine so gameplay can call `GOSUB 2000` whenever you advance.

---

### Example Program

```basic
NEW
10 REM *** MULTI-LEVEL LOADER ***
20 GOSUB 9000 : REM preload tables
30 LEVEL=1
40 GOSUB 1000
50 PRINT :PRINT "N = NEXT LEVEL  Q = QUIT"
60 GET K$:IF K$="Q" THEN END
70 IF K$="N" THEN LEVEL=LEVEL+1:GOSUB 1000
80 GOTO 50

9000 REM *** PREPARE ARRAYS ***
9010 DIM MAP$(10)
9020 RETURN

1000 REM *** LOAD LEVEL ***
1010 IF LEVEL>MAXLEVEL THEN LEVEL=1
1020 GOSUB 1100
1030 PRINT CHR$(147)
1040 PRINT "LEVEL";LEVEL;" - ";TITLE$
1050 PRINT
1060 FOR R=1 TO ROWS
1070 PRINT MAP$(R)
1080 NEXT R
1090 PRINT :PRINT "SPAWN:";SPAWNX;",";SPAWNY
1100 RETURN

1100 REM *** SCAN DATA FOR LEVEL ***
1110 RESTORE 5000
1120 MAXLEVEL=0
1130 READ ID:IF ID=0 THEN RETURN
1140 IF ID>MAXLEVEL THEN MAXLEVEL=ID
1150 READ ROWS:READ TITLE$
1160 IF ID=LEVEL THEN 1200
1170 FOR SK=1 TO ROWS+2:READ D$:NEXT SK
1180 GOTO 1130
1200 FOR R=1 TO ROWS:READ MAP$(R):NEXT R
1210 READ SPAWNX$:READ SPAWNY$
1215 SPAWNX=VAL(SPAWNX$):SPAWNY=VAL(SPAWNY$)
1220 RETURN

5000 DATA 1,6,"ORBIT DOCK"
5010 DATA "########################"
5020 DATA "#.......P............#"
5030 DATA "#..####......####....#"
5040 DATA "#..#..#......#..#....#"
5050 DATA "#..####..++..####....#"
5060 DATA "########################"
5070 DATA "24","18"
5080 DATA 2,6,"THERMAL SHAFT"
5090 DATA "########################"
5100 DATA "#..++++......++++...#"
5110 DATA "#..#..#......#..#...#"
5120 DATA "#..#..######..#..#..#"
5130 DATA "#........P........#"
5140 DATA "########################"
5150 DATA "10","20"
5160 DATA 3,6,"CRYSTAL CAVERN"
5170 DATA "########################"
5180 DATA "#....####..####....#"
5190 DATA "#..P....++++....P..#"
5200 DATA "#....####..####....#"
5210 DATA "#........##........#"
5220 DATA "########################"
5230 DATA "12","18"
5240 DATA 0,0,"END"
```

Sample output:

```
LEVEL 2 - THERMAL SHAFT

########################
#..++++......++++...#
#..#..#......#..#...#
#..#..######..#..#..#
#........P........#
########################

SPAWN: 10 , 20
```

`RESTORE 5000` rewinds the `DATA` pointer. The loader reads the level id, row count, and title. If the id doesn’t match the requested `LEVEL`, it skips `(rows + 2)` entries (the row strings plus spawn coordinates) and loops again. When it finds the match, it fills `MAP$()` and converts the stored spawn coordinates from strings to numbers (`VAL`). `MAXLEVEL` tracks the highest id so the demo can wrap around once you reach the end.

> **Tip:** Store numeric values as strings when they include leading zeros or you plan to print them directly. Here we convert them back with `VAL`. If you prefer pure numbers, drop the quotes and read them into numeric variables.

### Concept Expansion

Levels are just data. The more you separate them from logic, the easier it becomes to add, rearrange, or patch them without touching code. Later, you can load levels from disk or `READ` them from compressed strings—this scanning pattern still works.

---

### Game Integration

Trigger the loader whenever you advance:

```basic
LEVEL=LEVEL+1
GOSUB 2000
PLAYERX=SPAWNX:PLAYERY=SPAWNY
```

Reserve line `2000` for the loader routine (label it `REM LOAD LEVEL`). Your gameplay loop can unconditionally call it; the subroutine decides whether to wrap or stop.

### Quick Reference

```basic
REM Sentinel-based scan
RESTORE base
READ id:IF id=0 THEN END

REM Skip block quickly
FOR SK=1 TO rows+2:READ dummy$:NEXT

REM Load matching level
FOR R=1 TO rows:READ MAP$(R):NEXT
```

### What You’ve Learnt

- Structured DATA blocks let you pack multiple levels into a single listing.
- Scanning with `RESTORE` and `READ` lets you load any level on demand without rewriting the DATA section.
- Spawn points and metadata travel with the level so resetting the world is trivial.
