## Making Programs Interactive

So far, your programs run automatically. They display text, change colours, and count—but they don't respond to you.

The **GET** command changes that. It reads the keyboard, letting your programs react to what you type.

## Your First GET

**GET** only works inside programs, not in immediate mode. Let's write a simple program:

```basic
NEW
10 GET K$
20 PRINT K$
```

![first-get.png](/images/lessons/commodore-64/basic/week-1/lesson-06/first-get.png)
*Capture: Screen showing the program, then after RUN, nothing displayed*

RUN this program. Nothing appears! The program runs so fast that GET checks for a key before you can press one, finds nothing, and ends.

## How GET Works

**GET** tries to read a single keypress **right now**:

```basic
GET variable$
```

- **Doesn't wait** for you to press a key
- **Doesn't show** what you type (no cursor, no echo)
- Stores the keypress in a string variable (must use `$`)
- **Only works inside programs** (not immediate mode)

If **no key is pressed** when GET runs, the variable becomes **empty** (`""`).

## Checking for Empty Input

Let's create a program that shows what GET finds:

```basic
NEW
10 PRINT "PRESS A KEY"
20 GET K$
30 PRINT "KEY: "; K$; "END"
40 GOTO 20
```

![checking-for-key.png](/images/lessons/commodore-64/basic/week-1/lesson-06/checking-for-key.png)
*Capture: Screen showing "PRESS A KEY" followed by "KEY: END" repeating multiple times, then "KEY: AEND" when A is pressed*

RUN this. Press **A**.

**Result:**
```
PRESS A KEY
KEY: END
KEY: END
KEY: END
KEY: AEND
KEY: END
...
```

The program keeps checking. Most of the time, no key is pressed (`K$=""`) so it shows `END` immediately. When you press A, it catches it once (`K$="A"`), then goes back to empty.

## The Empty String Test

How do you know if GET found a key? Test if `K$=""` (empty):

```basic
NEW
10 PRINT "PRESS A KEY"
20 GET K$
30 IF K$="" THEN GOTO 20
40 PRINT "YOU PRESSED: "; K$
```

![empty-test.png](/images/lessons/commodore-64/basic/week-1/lesson-06/empty-test.png)
*Capture: Screen showing "PRESS A KEY", then after pressing A, "YOU PRESSED: A"*

This program:
1. Displays "PRESS A KEY"
2. Tries to GET a keypress
3. If no key pressed (`K$=""`), loop back to line 20
4. If a key was pressed, display it

(Don't worry about `IF...THEN` yet—we'll learn that properly in Lesson 7. For now, just know it **checks** if something is true.)

## A Key Waiting Loop

The standard pattern for waiting for a keypress:

```basic
GET K$: IF K$="" THEN 100
```

This means: "Get a keypress. If nothing pressed, go back to this line."

Here's a program that waits:

```basic
NEW
10 PRINT CHR$(147)
20 PRINT "PRESS ANY KEY TO START"
30 GET K$: IF K$="" THEN 30
40 PRINT CHR$(147)
50 PRINT "YOU PRESSED A KEY!"
```

![waiting-for-key.png](/images/lessons/commodore-64/basic/week-1/lesson-06/waiting-for-key.png)
*Capture: Screen showing "PRESS ANY KEY TO START", then after keypress, "YOU PRESSED A KEY!"*

The program **stops** at line 30 until you press a key. This is how you create "Press any key to continue" prompts!

## Reading Different Keys

GET can detect which key was pressed:

```basic
NEW
10 PRINT CHR$(147)
20 PRINT "PRESS ANY KEY"
30 GET K$: IF K$="" THEN 30
40 PRINT "YOU PRESSED: "; K$
50 FOR I=1 TO 200: NEXT I
60 GOTO 10
```

![different-keys.png](/images/lessons/commodore-64/basic/week-1/lesson-06/different-keys.png)
*Capture: Screen showing "PRESS ANY KEY" followed by "YOU PRESSED: A" (or other keys)*

Try pressing different keys. The program shows what you pressed!

## Special Keys

Some keys produce special characters:

![special-keys-table.png](/images/lessons/commodore-64/basic/week-1/lesson-06/special-keys-table.png)
*Capture: Screen showing a program that displays key codes, with examples of special keys*

| Key | What GET Returns |
|-----|------------------|
| Letters | `"A"`, `"B"`, `"C"`, etc. |
| Numbers | `"1"`, `"2"`, `"3"`, etc. |
| SPACE | `" "` (space character) |
| RETURN | `CHR$(13)` |
| Cursor keys | Special CHR$ values |
| Commodore key | Special codes |

You can test for specific keys:

```basic
NEW
10 PRINT CHR$(147)
20 PRINT "PRESS SPACE TO CONTINUE"
30 GET K$
40 IF K$="" THEN 30
50 IF K$<>" " THEN 30
60 PRINT "SPACE PRESSED!"
```

![space-key.png](/images/lessons/commodore-64/basic/week-1/lesson-06/space-key.png)
*Capture: Screen showing "PRESS SPACE TO CONTINUE" then "SPACE PRESSED!"*

This program **only continues** when you press the SPACE key. Pressing other keys does nothing.

(Line 50 means: "If K$ is not space, go back to line 30")

## A Simple Menu

Let's combine what you've learned:

```basic
NEW
10 PRINT CHR$(147)
20 PRINT "MAIN MENU"
30 PRINT
40 PRINT "1 = HELLO"
50 PRINT "2 = GOODBYE"
60 PRINT "3 = QUIT"
70 PRINT
80 PRINT "CHOOSE: ";
90 GET K$: IF K$="" THEN 90
100 PRINT K$
110 PRINT
120 IF K$="1" THEN PRINT "HELLO, FRIEND!"
130 IF K$="2" THEN PRINT "GOODBYE!"
140 IF K$="3" THEN PRINT "QUITTING...": END
150 PRINT
160 PRINT "PRESS ANY KEY"
170 GET K$: IF K$="" THEN 170
180 GOTO 10
```

![simple-menu.png](/images/lessons/commodore-64/basic/week-1/lesson-06/simple-menu.png)
*Capture: Screen showing the menu with options, user pressing 1, displaying "HELLO, FRIEND!"*

This creates a working menu! Press 1, 2, or 3 to see different responses.

**How it works:**
- Lines 10-80: Display menu
- Line 90: Wait for keypress
- Line 100: Show what you pressed
- Lines 120-140: Respond based on key
- Line 170: Wait before redrawing menu

## Responding to Letters

You can build programs that react to specific letters:

```basic
NEW
10 PRINT CHR$(147)
20 PRINT "PRESS:"
30 PRINT "R = RED BORDER"
40 PRINT "G = GREEN BORDER"
50 PRINT "B = BLUE BORDER"
60 PRINT "Q = QUIT"
70 PRINT
80 GET K$: IF K$="" THEN 80
90 IF K$="R" THEN POKE 53280,2
100 IF K$="G" THEN POKE 53280,5
110 IF K$="B" THEN POKE 53280,6
120 IF K$="Q" THEN END
130 GOTO 80
```

![colour-chooser.png](/images/lessons/commodore-64/basic/week-1/lesson-06/colour-chooser.png)
*Capture: Screen showing the menu, with border changed to red*

Press R, G, or B to change the border colour! Press Q to quit.

This is the foundation of interactive programs—reading keys and responding to them.

## A Simple Counter You Control

Combining variables with GET:

```basic
NEW
10 SC=0
20 PRINT CHR$(147)
30 PRINT "SC: "; SC
40 PRINT
50 PRINT "SPACE = ADD POINT"
60 PRINT "Q = QUIT"
70 PRINT
80 GET K$: IF K$="" THEN 80
90 IF K$=" " THEN SC=SC+1: GOTO 20
100 IF K$="Q" THEN END
110 GOTO 80
```

![controlled-counter.png](/images/lessons/commodore-64/basic/week-1/lesson-06/controlled-counter.png)
*Capture: Screen showing "SC: 5" after pressing SPACE multiple times*

Press SPACE to increase the score! This is how game inputs work—tracking variables based on keypresses.

## GET vs INPUT

You've seen `INPUT` in other programs. How is GET different?

| GET | INPUT |
|-----|-------|
| Reads one key instantly | Waits for text + RETURN |
| Doesn't echo keypress | Shows what you type |
| Doesn't wait | Always waits |
| For interactive control | For entering data |

**GET** is for fast, immediate responses (games, menus).
**INPUT** is for entering numbers or names (we'll learn this in Week 2).

## Common Patterns

**Wait for any key:**
```basic
100 GET K$: IF K$="" THEN 100
```

**Wait for specific key:**
```basic
100 GET K$: IF K$<>"Q" THEN 100
```

**Check multiple keys:**
```basic
100 GET K$: IF K$="" THEN 100
110 IF K$="Y" THEN [do something]
120 IF K$="N" THEN [do something else]
130 GOTO 100
```

## Common Mistakes

**Forgetting the $ for GET:**
```basic
GET K     ❌ WRONG - GET requires string variable
GET K$    ✅ CORRECT
```

**Not checking for empty:**
```basic
GET K$
PRINT K$    ❌ Might print nothing

GET K$: IF K$="" THEN 10
PRINT K$    ✅ Only prints when key pressed
```

**Using GET for text input:**
```basic
10 PRINT "ENTER YOUR NAME:"
20 GET N$    ❌ Gets only one character
20 INPUT N$  ✅ Correct for text entry
```

## Why GET Matters

GET is essential for:
- **Games** (moving characters, firing, jumping)
- **Menus** (selecting options)
- **Interactive programs** (responding to user choices)
- **Real-time control** (no need to press RETURN)

Without GET, all programs run automatically. With GET, programs become **interactive**—they respond to **you**.
