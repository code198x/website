## The Game: Number Hunter

**Goal:** Guess the hidden number before you run out of guesses.

**Features:**
- Random target number (1-100)
- 7 guesses to find it
- Hints after each guess (higher/lower)
- Scoring system
- Colour feedback
- Play again option

Let's build it step by step.

## Step 1: The Title Screen

```basic
NEW
10 REM *** NUMBER HUNTER ***
20 PRINT CHR$(147)
30 POKE 53280,0: POKE 53281,0
40 PRINT
50 PRINT "  NUMBER HUNTER"
60 PRINT "  ============="
70 PRINT
80 PRINT "GUESS THE NUMBER 1-100"
90 PRINT
100 PRINT "PRESS ANY KEY TO START"
110 GET K$: IF K$="" THEN 110
120 GOTO 200
```

![title-screen.png](/images/lessons/commodore-64/basic/week-1/lesson-08/title-screen.png)
*Capture: Black screen with "NUMBER HUNTER" title and "PRESS ANY KEY" prompt*

**What's happening:**
- Lines 20-30: Clear screen, set black border/background
- Lines 40-90: Display title and instructions
- Lines 100-110: Wait for keypress
- Line 120: Jump to game start (line 200)

## Step 2: Initialize Variables

```basic
200 REM *** SETUP GAME ***
210 SC=0: LI=7
220 TA=INT(RND(1)*100)+1
230 GOTO 300
```

**What's happening:**
- **SC**: Score (starts at 0)
- **LI**: Lives/guesses (starts at 7)
- **TA**: Target number (random 1-100)
- **Line 220**: `INT(RND(1)*100)+1` generates random number

<div class="note">
<div class="note-title">🎲 Random Numbers</div>

`RND(1)` generates a random decimal between 0 and 1 (e.g., 0.847362).

To get a number from 1-100:
1. `RND(1) * 100` → 0 to 99.999...
2. `INT(...)` → 0 to 99 (whole number)
3. `+ 1` → 1 to 100

We'll learn more about RND() in Week 2!
</div>

## Step 4: Check the Guess

```basic
500 REM *** PROCESS GUESS ***
510 IF GU<1 THEN GOTO 600
520 IF GU>100 THEN GOTO 600
530 IF GU=TA THEN GOTO 700
540 REM WRONG GUESS
550 LI=LI-1
560 IF LI<1 THEN GOTO 800
570 REM GIVE HINT
580 IF GU<TA THEN PRINT "TOO LOW!"
590 IF GU>TA THEN PRINT "TOO HIGH!"
595 FOR I=1 TO 300: NEXT I
597 GOTO 300
600 REM INVALID INPUT
610 PRINT "ENTER 1-100 ONLY!"
620 FOR I=1 TO 300: NEXT I
630 GOTO 300
```

![guess-feedback.png](/images/lessons/commodore-64/basic/week-1/lesson-08/guess-feedback.png)
*Capture: Screen showing "TOO LOW!" after entering 30*

**What's happening:**
- Lines 510-520: Validate input (must be 1-100)
- Line 530: Check if correct → jump to win (line 700)
- Line 550: Deduct a guess
- Line 560: Check if out of guesses → game over (line 800)
- Lines 580-590: Give hint (higher/lower)
- Line 595: Delay so player can read hint
- Line 597: Loop back to redisplay

```basic
700 REM *** WIN ***
```

```basic

940 IF K$="Y" THEN 200
```

## Understanding Program Structure

This program uses a **state machine** approach:

```
   START (10)
      ↓
   TITLE (20)
      ↓
   SETUP (200)
      ↓
   GAME LOOP (300)
      ↓
   PROCESS (500) → VALIDATE (600)
      ↓              ↓
   WIN (700)    LOSE (800)
      ↓              ↓
   PLAY AGAIN (900)
      ↓
   QUIT (1000)
```

Each section has a clear purpose. Line numbers are organized in blocks:
- **10-100**: Title screen
- **200-299**: Setup
- **300-499**: Main game
- **500-699**: Processing/validation
- **700-899**: Win/lose states
- **900-999**: Play again logic
- **1000+**: Quit

This organization makes the program **readable** and **maintainable**.

## REM Statements

Notice the `REM` lines:

```basic
200 REM *** SETUP GAME ***
500 REM *** PROCESS GUESS ***
700 REM *** WIN ***
```

**REM** means "remark"—a comment that BASIC ignores. They help you (and others) understand what each section does.

Comments are good practice in any program!

## Variable Naming Strategy

We used short names (2 characters) because of the C64 limitation:

| Variable | Full Name | Purpose |
|----------|-----------|---------|
| `SC` | Score | Points earned |
| `LI` | Lives | Guesses remaining |
| `TA` | Target | Number to guess |
| `GU` | Guess | Player's input |
| `K$` | Key | Keypress storage |

This keeps code compact while staying clear.
