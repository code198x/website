## From Commands to Programs

So far, you've been typing commands that execute immediately. But real programs need to:
- Store multiple commands
- Run them in sequence
- Repeat actions automatically

Let's write your first proper BASIC program.

## Line Numbers

In BASIC, programs are made of numbered lines. Type this:

```basic
10 PRINT "HELLO"
20 PRINT "WORLD"
```

Notice something? When you press RETURN, the line doesn't execute immediately. Instead, it's stored in memory with its line number.

![Line Numbers Stored](/images/lessons/commodore-64/basic/week-1/lesson-03/line-numbers-stored.png)

Now type:

```basic
LIST
```

![LIST Command](/images/lessons/commodore-64/basic/week-1/lesson-03/list-command.png)

**LIST** displays your stored program:
```basic
10 PRINT "HELLO"
20 PRINT "WORLD"

READY.
```

To run it, type:

```basic
RUN
```

![RUN Command Output](/images/lessons/commodore-64/basic/week-1/lesson-03/run-command-output.png)

**Result:**
```
HELLO
WORLD

READY.
```

The computer executed line 10, then line 20, then stopped.

## How Line Numbers Work

**Key concepts:**

- **Line numbers tell BASIC the order** to execute commands
- **Lines are stored, not executed**, until you type RUN
- **Numbers don't have to be consecutive** - you can use 10, 20, 30, etc.
- **This leaves gaps** for adding new lines later

Why gaps? If you need to insert a line between 10 and 20, you can use 15:

```basic
10 PRINT "HELLO"
15 PRINT "BEAUTIFUL"
20 PRINT "WORLD"
```

![Inserted Line](/images/lessons/commodore-64/basic/week-1/lesson-03/inserted-line.png)

Now when you RUN, you see:
```
HELLO
BEAUTIFUL
WORLD
```

## The GOTO Command

Here's where it gets exciting. Type this program:

```basic
NEW
10 PRINT "HELLO"
20 GOTO 10
```

**Important:** `NEW` clears any previous program from memory. Always start fresh with NEW.

Now type:

```basic
RUN
```

![Infinite Loop](/images/lessons/commodore-64/basic/week-1/lesson-03/infinite-loop.png)

**Whoa!** The screen fills with "HELLO" and doesn't stop!

```
HELLO
HELLO
HELLO
HELLO
HELLO
...
```

**Press the RUN/STOP key** (top-left of keyboard) to halt the program.

You'll see:
```
BREAK IN 10
READY.
```

This means the program was interrupted at line 10.

## What Just Happened?

**GOTO** tells BASIC: "Jump to this line number and continue from there."

Your program:
1. Line 10: Print "HELLO"
2. Line 20: Go back to line 10
3. Line 10: Print "HELLO" again
4. Line 20: Go back to line 10
5. (Repeat forever)

This is called an **infinite loop**—it never stops on its own.

## Why Loops Are Powerful

Loops let you repeat actions without typing them multiple times. Compare:

**Without loops (tedious):**
```basic
10 PRINT "HELLO"
20 PRINT "HELLO"
30 PRINT "HELLO"
40 PRINT "HELLO"
50 PRINT "HELLO"
```

**With loops (elegant):**
```basic
10 PRINT "HELLO"
20 GOTO 10
```

Same result (well, infinite HELLOs), but the second version is shorter and more powerful.

## Clearing the Screen in a Loop

Let's make something more interesting:

```basic
NEW
10 PRINT CHR$(147)
20 PRINT "FLASHING SCREEN"
30 GOTO 10
```

RUN this program. The screen clears and displays the text repeatedly, creating a flashing effect. You'll see "FLASHING SCREEN" appear briefly, then clear, then appear again - over and over very quickly!

Press RUN/STOP when you've had enough!

## Counting

Let's make the computer count:

```basic
NEW
10 PRINT 1
20 PRINT 2
30 PRINT 3
40 PRINT 4
50 PRINT 5
60 GOTO 10
```

![Counting Loop](/images/lessons/commodore-64/basic/week-1/lesson-03/counting-loop.png)

This counts 1, 2, 3, 4, 5, then starts over. Forever.

We'll learn a better way to count in later lessons (using variables and FOR loops), but this shows how GOTO creates patterns.

## Animated Text

Here's a fun one:

```basic

30 PRINT CHR$(147)
40 PRINT "WORLD"

```

![Animated Text](/images/lessons/commodore-64/basic/week-1/lesson-03/animated-text.png)

This alternates between displaying "HELLO" and "WORLD", creating a simple animation!

## Why GOTO Gets a Bad Reputation

In modern programming, GOTO is considered poor practice because it creates "spaghetti code"—programs where the flow jumps all over the place, making them hard to understand.

**But for learning**, GOTO is perfect because:
- It's simple to understand
- It creates immediate, visible effects
- It teaches program flow concepts
- The C64 doesn't have better alternatives yet (we'll learn them later)

Once you understand loops with GOTO, you'll appreciate more structured approaches like FOR/NEXT (coming soon).

## Common Mistakes

**Forgetting line numbers:**
```basic
PRINT "HELLO"    ❌ Executes immediately
10 PRINT "HELLO" ✅ Stored as part of program
```

**GOTOing to a line that doesn't exist:**
```basic
10 PRINT "HELLO"
20 GOTO 30       ❌ No line 30!
```

Result: `UNDEF'D STATEMENT ERROR` (undefined statement)

**Forgetting to NEW before a new program:**
- Old program lines remain in memory
- Can cause confusing behaviour
- Always start with NEW

## Stopping Programs Properly

**RUN/STOP key** - Pauses the program (you can continue with GO)
**RUN/STOP + RESTORE** - Immediately stops and resets

![Break In Message](/images/lessons/commodore-64/basic/week-1/lesson-03/break-in-message.png)

## Why This Matters

Loops are fundamental to all programming:
- Games use loops to update the screen every frame
- Programs use loops to wait for user input
- Animations use loops to create motion

You've just learned one of the most important programming concepts—and you can already create interesting effects with it!
