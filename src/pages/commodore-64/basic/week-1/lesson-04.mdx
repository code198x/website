## Making Things Colourful

You've been staring at that blue screen with a blue border long enough. Let's change it!

The C64 has 16 colours, and you can change the border colour with a single command.

## Your First POKE

Type this:

```basic
POKE 53280,0
```

![Border Colour Black](/images/lessons/commodore-64/basic/week-1/lesson-04/border-colour-black.png)

**Boom!** The border turned black.

Now try:

```basic
POKE 53280,2
```

![Border Colour Red](/images/lessons/commodore-64/basic/week-1/lesson-04/border-colour-red.png)

Red border!

```basic
POKE 53280,5
```

![Border Colour Green](/images/lessons/commodore-64/basic/week-1/lesson-04/border-colour-green.png)

Green border!

You're directly changing the C64's display hardware with POKE.

## What is POKE?

**POKE** writes a value directly into a specific memory location.

```basic
POKE address, value
```

- **address** - Where in memory to write (a number from 0 to 65535)
- **value** - What to write there (a number from 0 to 255)

Think of the C64's memory like a massive array of numbered boxes. Each box can hold one number (0-255). POKE lets you put a number in any box.

## Memory Address 53280

**53280** is the memory address that controls the border colour.

The C64's video chip (called the VIC-II) reads this address constantly. Whatever number is there determines the border colour:

| Value | Colour |
|-------|--------|
| 0 | Black |
| 1 | White |
| 2 | Red |
| 3 | Cyan |
| 4 | Purple |
| 5 | Green |
| 6 | Blue (default) |
| 7 | Yellow |
| 8 | Orange |
| 9 | Brown |
| 10 | Light Red |
| 11 | Dark Grey |
| 12 | Grey |
| 13 | Light Green |
| 14 | Light Blue |
| 15 | Light Grey |

## Why 53280?

This seems like a random number, but it's deliberate. The VIC-II chip's registers (its control settings) are mapped to memory addresses starting at 53248 (or $D000 in hexadecimal).

Address 53280 is specifically: **VIC-II register 32** (border colour register).

You don't need to memorise these addresses—just know they exist and refer to reference tables when needed.

<div class="note">
<div class="note-title">💡 Hexadecimal Note</div>

Many C64 references use hexadecimal (base-16) notation:
- 53280 in decimal = $D020 in hexadecimal
- Both refer to the same memory location
- BASIC uses decimal by default
- Assembly often uses hexadecimal

For now, stick with decimal numbers in BASIC.

## Colour Cycling Program

Let's create a visual effect with what you've learned:

```basic
NEW
10 POKE 53280,0
20 POKE 53280,1
30 POKE 53280,2
40 POKE 53280,3
50 POKE 53280,4
60 POKE 53280,5
70 POKE 53280,6
80 POKE 53280,7
90 GOTO 10
```

![Colour Cycling](/images/lessons/commodore-64/basic/week-1/lesson-04/colour-cycling.gif)

RUN this program. The border rapidly cycles through all the colours!

**Press RUN/STOP** to halt it.

## Adding Delays

The cycling happens so fast you can barely see the colours. Let's slow it down with a FOR loop (we'll explain these properly in a later lesson):

```basic
NEW
10 POKE 53280,0
15 FOR I=1 TO 100: NEXT I
20 POKE 53280,2
25 FOR I=1 TO 100: NEXT I
30 POKE 53280,5
35 FOR I=1 TO 100: NEXT I
40 POKE 53280,7
45 FOR I=1 TO 100: NEXT I
50 GOTO 10
```

![Colour Cycling Delayed](/images/lessons/commodore-64/basic/week-1/lesson-04/colour-cycling-delayed.gif)

Now you can actually see each colour change! The FOR loops create a small delay.

(Don't worry about understanding FOR loops yet—just know they create pauses.)

## Background Colour

The background (where the text appears) has its own address: **53281**

```basic
POKE 53281,0
```

![Background Colour Black](/images/lessons/commodore-64/basic/week-1/lesson-04/background-colour-black.png)

**Oops!** If your text is black (colour 0) and your background is black, you can't see anything!

Let's fix that:

```basic
POKE 53281,6
```

Back to blue background.

## Matching Border and Background

Try this for a dramatic look:

```basic
POKE 53280,0
POKE 53281,0
```

![All Black Screen](/images/lessons/commodore-64/basic/week-1/lesson-04/all-black-screen.png)

All black! Only the text is visible.

Or go bright:

```basic
POKE 53280,1
POKE 53281,1
```

![All White Screen](/images/lessons/commodore-64/basic/week-1/lesson-04/all-white-screen.png)

All white!

## A Colour Change Program

Let's combine what you've learned:

```basic
NEW
10 PRINT CHR$(147)
20 PRINT "BORDER COLOUR DEMO"
30 PRINT
40 PRINT "1 = BLACK"
50 PRINT "2 = WHITE"
60 PRINT "3 = RED"
70 PRINT "4 = GREEN"
80 PRINT "5 = BLUE"
90 PRINT
100 POKE 53280,0
110 FOR I=1 TO 200: NEXT I
120 POKE 53280,1
130 FOR I=1 TO 200: NEXT I
140 POKE 53280,2
150 FOR I=1 TO 200: NEXT I
160 POKE 53280,5
170 FOR I=1 TO 200: NEXT I
180 POKE 53280,6
190 FOR I=1 TO 200: NEXT I
200 GOTO 100
```

![Colour Demo Program](/images/lessons/commodore-64/basic/week-1/lesson-04/colour-demo-program.gif)

This creates a colour menu, then cycles the border through the colours listed!

## Why POKE Matters

POKE gives you **direct hardware access**. You're not asking the operating system to change something—you're directly controlling the video chip.

This is incredibly powerful:
- No permission needed
- Instant response
- Full control
- The foundation for everything (graphics, sound, input)

As you progress, you'll POKE many different addresses to control:
- Individual screen characters
- Sprite positions
- Sound chip registers
- Joystick input
- Hardware timers

## Common Mistakes

**Values too high:**
```basic
POKE 53280,255   ❌ Results in weird colour
POKE 53280,7     ✅ Stays within 0-15 range
```

Technically, 255 won't crash anything, but only values 0-15 produce expected results.

**Wrong address:**
```basic
POKE 53820,2     ❌ Wrong address (typo)
POKE 53280,2     ✅ Correct border address
```

**Forgetting the comma:**
```basic
POKE 53280 2     ❌ Syntax error
POKE 53280,2     ✅ Comma required
```

## Memory Safety

A common worry: "Can POKE crash the computer?"

**Yes, technically**, if you POKE random addresses, you could corrupt BASIC or the operating system and cause a crash.

**But**, in practice:
- The C64 is resilient
- Worst case: Turn it off and on again
- The addresses we're using are safe
- Experimenting is encouraged!

Don't be afraid to try things. The C64 is designed for exploration.
