## Why Subroutines Matter

You've learnt to write programs from top to bottom. But what if you need to do the same thing multiple times? Drawing an explosion, playing a sound, clearing a section of screen - you don't want to write the same code over and over. Subroutines let you write it once and call it whenever needed.

## Basic Subroutine

The simplest example:

```basic
NEW
10 PRINT "BEFORE SUBROUTINE"
20 GOSUB 1000
30 PRINT "AFTER SUBROUTINE"
40 END
1000 REM *** SUBROUTINE ***
1010 PRINT "INSIDE SUBROUTINE"
1020 RETURN
```

**Run it!** The program jumps to line 1000, executes the code, then RETURN sends it back to line 30.

**Key points:**
- `GOSUB 1000` jumps to line 1000
- `RETURN` jumps back to the line after GOSUB
- `END` at line 40 stops the program falling through into the subroutine

## Line Number Organisation

Professional C64 programmers used ranges:

- **0-999**: Main program
- **1000-1999**: Graphics subroutines
- **2000-2999**: Sound subroutines
- **3000-3999**: Game logic subroutines

This keeps code organised and easy to find!

## Calling a Subroutine Multiple Times

```basic
NEW
10 PRINT CHR$(147)
20 GOSUB 1000
30 FOR I=1 TO 500:NEXT I
40 GOSUB 1000
50 FOR I=1 TO 500:NEXT I
60 GOSUB 1000
70 END
1000 REM *** FLASH BORDER ***
1010 POKE 53280,INT(RND(1)*16)
1020 RETURN
```

The border flashes three times with a delay between each flash. We wrote the flash code once (line 1010) and called it three times.

## Using Variables as "Parameters"

BASIC V2 doesn't have proper function parameters, but we can use variables:

```basic
NEW
10 PRINT CHR$(147)
20 X=10:Y=5:GOSUB 1000
30 X=20:Y=10:GOSUB 1000
40 X=15:Y=15:GOSUB 1000
50 END
1000 REM *** DRAW STAR ***
1010 POKE 1024+Y*40+X,42
1020 POKE 55296+Y*40+X,7
1030 RETURN
```

![Three stars at different positions](/images/lessons/commodore-64/basic/week-2/lesson-10/lesson10-stars.png)

Three stars (`*` character, colour yellow) appear at different positions. We set X and Y before each GOSUB, and the subroutine uses those values.

## WOW Moment: Explosion Effect

Let's create an explosion that we can trigger at any position:

```basic
NEW
10 PRINT CHR$(147)
20 X=10:Y=5:GOSUB 1000
30 X=25:Y=15:GOSUB 1000
40 X=15:Y=20:GOSUB 1000
50 X=30:Y=8:GOSUB 1000
60 X=5:Y=18:GOSUB 1000
70 END
1000 REM *** EXPLOSION ***
1010 FOR R=0 TO 3
1020 FOR A=0 TO 7
1030 DX=INT(COS(A*0.785)*R)
1040 DY=INT(SIN(A*0.785)*R)
1050 PX=X+DX:PY=Y+DY
1060 IF PX<0 OR PX>39 OR PY<0 OR PY>24 THEN 1100
1070 POKE 1024+PY*40+PX,42
1080 POKE 55296+PY*40+PX,2
1090 FOR D=1 TO 20:NEXT D
1100 NEXT A
1110 NEXT R
1120 FOR A=0 TO 7
1130 FOR RR=0 TO 3
1140 DX=INT(COS(A*0.785)*RR)
1150 DY=INT(SIN(A*0.785)*RR)
1160 PX=X+DX:PY=Y+DY
1170 IF PX<0 OR PX>39 OR PY<0 OR PY>24 THEN 1210
1180 POKE 1024+PY*40+PX,32
1190 FOR D=1 TO 10:NEXT D
1200 REM *** SKIP TO NEXT ***
1210 NEXT RR
1220 NEXT A
1230 RETURN
```

![Explosion effect at multiple positions](/images/lessons/commodore-64/basic/week-2/lesson-10/lesson10-explosions.png)

Watch explosions appear at five different locations! Each explosion expands outward in a circular pattern, then clears itself.

## How the Explosion Works

**Lines 20-60**: Set X,Y position and call the explosion subroutine five times

**Lines 1010-1110**: Expansion phase
- Outer loop (R): Radius from 0 to 3
- Inner loop (A): 8 angles around the circle
- Calculate DX,DY offsets using trigonometry (COS/SIN)
- Draw `*` character in red, with a small delay

**Lines 1120-1220**: Clear phase
- Same pattern but reversed order (angle first, then radius)
- Replace `*` with space character (32)

**Line 1060, 1170**: Boundary check - don't draw off-screen

## Subroutine Best Practices

1. **Use REM at the start** - document what the subroutine does
2. **Group by function** - graphics in 1000s, sound in 2000s, etc.
3. **Always END before first subroutine** - prevents fall-through
4. **Use variables for "parameters"** - set them before GOSUB
5. **Keep subroutines focused** - one job per subroutine

## Common Pattern: Nested GOSUB

You can call a subroutine from within another subroutine:

```basic
NEW
10 PRINT "MAIN"
20 GOSUB 1000
30 END
1000 REM *** SUB 1 ***
1010 PRINT "SUBROUTINE 1"
1020 GOSUB 2000
1030 RETURN
2000 REM *** SUB 2 ***
2010 PRINT "SUBROUTINE 2"
2020 RETURN
```

Output:
```
MAIN
SUBROUTINE 1
SUBROUTINE 2
```

BASIC keeps track of the return stack - RETURN always goes back to the right place.

## Quick Reference

```basic
GOSUB 1000        REM Call subroutine at line 1000
RETURN            REM Return to line after GOSUB

REM Line ranges:
REM 0-999:   Main program
REM 1000s:   Graphics
REM 2000s:   Sound
REM 3000s:   Logic
```

## What You've Learnt

- GOSUB calls a subroutine, RETURN comes back
- Organise code by line number ranges (1000s, 2000s, etc.)
- Reuse code by calling the same subroutine multiple times
- Pass "parameters" by setting variables before GOSUB
- Always END before first subroutine to prevent fall-through
- Subroutines make complex effects manageable
