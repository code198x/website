## Why Multiple Conditions Matter

Real games need complex logic: "Is the player touching a wall AND moving right?" or "Has time run out OR lives reached zero?" C64 BASIC V2 has AND and OR operators for exactly this.

## Using OR - Check if ANY Condition is True

```basic
NEW
10 INPUT "ENTER KEY (1-3)";K
20 IF K=1 OR K=2 OR K=3 THEN PRINT "VALID KEY"
30 IF K<1 OR K>3 THEN PRINT "INVALID KEY"
```

The `OR` operator succeeds if **any** condition is true.

## Using AND - Check if ALL Conditions are True

```basic
NEW
10 INPUT "ENTER AGE";AG
20 INPUT "HAVE TICKET (1=YES)";TK
30 IF AG>=18 AND TK=1 THEN PRINT "WELCOME!"
40 IF AG<18 THEN PRINT "TOO YOUNG"
50 IF TK=0 THEN PRINT "NEED A TICKET"
```

The `AND` operator requires **all** conditions to be true.

## Boundary Checking

Keep values in range:

```basic
NEW
10 X=20:Y=12
20 PRINT CHR$(147)
30 GET K$
40 IF K$="W" THEN Y=Y-1
50 IF K$="S" THEN Y=Y+1
60 IF K$="A" THEN X=X-1
70 IF K$="D" THEN X=X+1
80 REM *** CHECK BOUNDARIES ***
90 IF X<0 THEN X=0
100 IF X>39 THEN X=39
110 IF Y<0 THEN Y=0
120 IF Y>24 THEN Y=24
130 POKE 1024+Y*40+X,81
140 GOTO 20
```

![Bounded movement](/images/lessons/commodore-64/basic/week-2/lesson-13/lesson13-bounds.png)

Move with WASD - the character (Q) can't go off-screen. Lines 90-120 enforce the boundaries.

## Checking Ranges with AND

Check if a value is within a range:

```basic
NEW
10 INPUT "GUESS NUMBER (1-10)";G
20 IF G>=1 AND G<=10 THEN GOTO 50
30 PRINT "OUT OF RANGE"
40 GOTO 10
50 IF G=7 THEN PRINT "CORRECT!":END
60 PRINT "WRONG, TRY AGAIN"
70 GOTO 10
```

Line 20 uses AND to check both ends of the range.

## WOW Moment: Collision Detection

Move a player and detect wall collisions:

```basic
NEW
10 PRINT CHR$(147)
20 X=5:Y=5
30 REM *** DRAW WALLS ***
40 FOR I=0 TO 39
50 POKE 1024+I,160:POKE 1024+24*40+I,160
60 NEXT I
70 FOR I=0 TO 24
80 POKE 1024+I*40,160:POKE 1024+I*40+39,160
90 NEXT I
100 REM *** DRAW OBSTACLE ***
110 FOR I=10 TO 30
120 POKE 1024+12*40+I,160
130 NEXT I
140 REM *** MAIN LOOP ***
150 GET K$
160 NX=X:NY=Y
170 IF K$="W" THEN NY=Y-1
180 IF K$="S" THEN NY=Y+1
190 IF K$="A" THEN NX=X-1
200 IF K$="D" THEN NX=X+1
210 REM *** CHECK COLLISION ***
220 C=PEEK(1024+NY*40+NX)
230 IF C<>160 THEN X=NX:Y=NY
240 REM *** DRAW PLAYER ***
250 POKE 1024+Y*40+X,81
260 POKE 55296+Y*40+X,7
270 FOR D=1 TO 30:NEXT D
280 POKE 1024+Y*40+X,32
290 GOTO 150
```

![Collision detection](/images/lessons/commodore-64/basic/week-2/lesson-13/lesson13-collision.png)

Move with WASD - you can't pass through walls! The program checks the character at your destination (line 220), and if it's a wall (160), it cancels the move.

## How Collision Detection Works

**Lines 40-90**: Draw border walls (character 160)

**Lines 110-130**: Draw horizontal obstacle

**Lines 160-200**: Calculate proposed position (NX, NY)

**Line 220**: PEEK what's at the destination

**Line 230**: Only move if it's not a wall

**Lines 250-280**: Draw player, delay, erase

This is the foundation of every C64 game's collision system!

## Combining AND and OR

You can mix them (parentheses help make it clear):

```basic
NEW
10 INPUT "ENTER SCORE";SC
20 INPUT "ENTER LIVES";LV
30 IF (SC>=100 AND LV>0) OR SC>=500 THEN PRINT "BONUS!"
40 IF LV=0 AND SC<100 THEN PRINT "GAME OVER"
```

Line 30: Bonus if you have 100+ points with lives remaining, OR 500+ points regardless.

## Comparison Operators Quick Reference

```basic
=     Equal to
<>    Not equal to
<     Less than
>     Greater than
<=    Less than or equal to
>=    Greater than or equal to

AND   All conditions must be true
OR    Any condition can be true
```

## Common Patterns

**Stay in bounds:**
```basic
IF X<0 THEN X=0
IF X>39 THEN X=39
```

**Check range:**
```basic
IF N>=1 AND N<=10 THEN PRINT "VALID"
```

**Multiple valid inputs:**
```basic
IF K$="Y" OR K$="YES" THEN GOSUB 1000
```

**Collision check:**
```basic
C=PEEK(1024+Y*40+X)
IF C=WALL THEN PRINT "BLOCKED"
```

## What You've Learnt

- AND checks if all conditions are true
- OR checks if any condition is true
- Boundary checking keeps values in range
- PEEK checks what's at a screen position
- Collision detection compares character codes
- Real game movement needs collision checks
- Check destination before moving!
