## Why State Machines Matter

Games have different modes: title screen, playing, game over, high scores. You could use lots of IF/THEN statements, but there's a better way: **ON/GOTO**. It jumps to different line numbers based on a value.

## Simple ON/GOTO

```basic
NEW
10 INPUT "PICK 1, 2, OR 3";N
20 ON N GOTO 100,200,300
30 PRINT "INVALID CHOICE"
40 GOTO 10
100 PRINT "YOU CHOSE ONE"
110 END
200 PRINT "YOU CHOSE TWO"
210 END
300 PRINT "YOU CHOSE THREE"
310 END
```

**Line 20**: `ON N GOTO 100,200,300`
- If N=1, jump to line 100
- If N=2, jump to line 200
- If N=3, jump to line 300
- If N is anything else, continue to next line (30)

## Menu System

```basic
NEW
10 PRINT CHR$(147)
20 PRINT "1) START GAME"
30 PRINT "2) HIGH SCORES"
40 PRINT "3) INSTRUCTIONS"
50 PRINT "4) QUIT"
60 PRINT
70 GET K$:IF K$="" THEN 70
80 N=VAL(K$)
90 ON N GOTO 1000,2000,3000,4000
100 GOTO 10
1000 PRINT "STARTING GAME...":END
2000 PRINT "HIGH SCORES...":END
3000 PRINT "INSTRUCTIONS...":END
4000 PRINT "GOODBYE!":END
```

Press 1-4 to jump to different sections.

## WOW Moment: Complete Game State Machine

A full game with three states:

```basic
NEW
10 PRINT CHR$(147)
20 ST=1:SC=0:LV=3
30 REM *** STATE MACHINE ***
40 ON ST GOTO 1000,2000,3000
50 REM *** TITLE SCREEN (ST=1) ***
1000 PRINT CHR$(147)
1010 PRINT "SPACE DODGE"
1020 PRINT
1030 PRINT "PRESS SPACE TO START"
1040 GET K$:IF K$<>" " THEN 1040
1050 ST=2:GOTO 40
2000 REM *** GAME (ST=2) ***
2010 PRINT CHR$(147)
2020 PRINT "SCORE:";SC;"  LIVES:";LV
2030 PRINT
2040 PRINT "PLAYING..."
2050 FOR I=1 TO 100:NEXT I
2060 SC=SC+10:LV=LV-1
2070 IF LV=0 THEN ST=3:GOTO 40
2080 GOTO 2000
3000 REM *** GAME OVER (ST=3) ***
3010 PRINT CHR$(147)
3020 PRINT "GAME OVER"
3030 PRINT
3040 PRINT "FINAL SCORE:";SC
3050 PRINT
3060 PRINT "PLAY AGAIN? (Y/N)"
3070 GET K$:IF K$="" THEN 3070
3080 IF K$="Y" THEN ST=1:GOTO 40
3090 PRINT:PRINT "THANKS FOR PLAYING!"
3100 END
```

![Game state machine](./lesson16-states.png)

Watch it cycle: TITLE → GAME → GAME OVER → back to TITLE!

## How the State Machine Works

**Line 20**: Initialize state (ST=1 for title), score, lives
**Line 40**: **The core** - jump to different sections based on ST
**Lines 1000-1050**: Title screen (ST=1), wait for space, set ST=2
**Lines 2000-2080**: Game loop (ST=2), increase score, lose life, check game over
**Lines 3000-3100**: Game over (ST=3), show score, play again or quit

This pattern is used in **every commercial game**!

## ON/GOSUB for Subroutines

You can also use ON with GOSUB:

```basic
NEW
10 INPUT "CHOOSE ACTION (1-3)";A
20 ON A GOSUB 100,200,300
30 PRINT "DONE"
40 END
100 PRINT "ATTACK!":RETURN
200 PRINT "DEFEND!":RETURN
300 PRINT "RUN!":RETURN
```

The subroutine runs, then returns to line 30.

## Common Patterns

**Three-state game:**
```basic
ST=1          REM 1=Title, 2=Play, 3=Over
ON ST GOTO 1000,2000,3000
```

**AI decision:**
```basic
AI=INT(RND(1)*3)+1
ON AI GOSUB 100,200,300  REM Random behaviour
```

**Difficulty levels:**
```basic
ON LEVEL GOTO 1000,1100,1200  REM Easy, Med, Hard
```

## Quick Reference

```basic
ON <value> GOTO <line1>,<line2>,...   REM Jump to line
ON <value> GOSUB <line1>,<line2>,...  REM Call subroutine

REM Examples:
ON N GOTO 100,200,300                 REM 3-way branch
ON LEVEL GOSUB 1000,2000,3000         REM Call by level
ON STATE GOTO 100,200,300,400         REM 4 states
```

## Important Notes

- If the value is **less than 1**, no jump happens (continues to next line)
- If the value is **greater than list length**, no jump happens
- Values are rounded down: `ON 1.9` acts like `ON 1`
- Use a variable for state, not a constant

## What You've Learnt

- ON/GOTO jumps based on a value
- ON/GOSUB calls subroutines based on a value
- State machines control game flow
- ST (or STATE) typically holds current state
- Jump to different line numbers for each state
- This is how all games manage screens
- Cleaner than chains of IF/THEN
- Professional game structure
