## Lesson 62 – Looking Below

You just called machine code from BASIC. Now let’s dig deeper: we’ll take a BASIC loop that moves a sprite, translate it to machine code, install it, and compare timings. Seeing the two side by side demystifies assembly.

> [📷 suggested: side-by-side listing of BASIC and machine code with a timing table]

---

### The One-Minute Tour

- Profile the BASIC version so you know how long it takes.
- Translate the logic into assembly and embed it via `DATA`.
- Call both from the same harness and print the timings so you see the payoff.

---

### Example Program

```basic
NEW
10 REM *** BASIC VS ASM SPRITE MOVE ***
20 GOSUB 8000:REM install machine code mover
30 POKE 2040,13:POKE 53269,1:POKE 53287,7
40 POKE 254,160:POKE 253,0
50 PRINT CHR$(147);"LEFT/RIGHT TO MOVE SPRITE"
60 PRINT "PRESS B FOR BASIC, A FOR ASM, RETURN TO EXIT"
70 GET K$:IF K$="" THEN 70
80 IF K$="B" THEN GOSUB 100
90 IF K$="A" THEN GOSUB 200
100 IF K$=CHR$(13) THEN END
110 GOTO 60

100 REM *** BASIC LOOP ***
110 PX=160:TI$="000000"
120 GET K$:IF K$=CHR$(29) THEN PX=PX+3
130 IF K$=CHR$(157) THEN PX=PX-3
140 IF PX<24 THEN PX=24
150 IF PX>232 THEN PX=232
160 POKE 53248,PX
170 IF TI<600 THEN 120
180 PRINT "BASIC LOOP:";TI;" jiffies"
190 RETURN

200 REM *** ASM LOOP ***
210 POKE 254,160:POKE 253,0:TI$="000000"
220 GET K$:IF K$=CHR$(29) THEN POKE 253,3
230 IF K$=CHR$(157) THEN POKE 253,253
240 SYS 8200
250 IF TI<600 THEN 220
260 PRINT "ASM LOOP:";TI;" jiffies"
270 RETURN

8000 REM *** INSTALL MACHINE CODE ***
8010 RESTORE 8100
8020 FOR I=0 TO 32
8030 READ B:POKE 8200+I,B
8040 NEXT I
8050 RETURN

8100 DATA 165,254,24,101,253,133,254,201,24,176,2,169,24
8110 DATA 133,254,201,232,144,2,169,232,133,254,165,254
8120 DATA 141,0,208,169,0,133,253,96
```

Sample timing (varies by hardware):

```
BASIC LOOP: 182 jiffies
ASM LOOP: 58 jiffies
```

Both loops clamp movement between pixel 24 and 232 and step by three pixels per key press. The BASIC version updates `PX`; the assembly version reads the step from zero page, adds it to the current position, clamps to range, writes to the sprite register, and clears the step. Same logic—different instruction set.

> **Tip:** Prototype the logic in BASIC first, then translate one line at a time. The constants and structure carry straight across.

### Experiment Section

- Extend both loops to handle vertical movement and compare timings again.
- Drop the machine-code mover into Scroll Runner and measure the speed-up.
- Keep the BASIC listing as comments above the `DATA` block for future maintenance.
- Try calling the machine-code routine from a tight BASIC `FOR/NEXT` to see how little overhead `SYS` adds compared to dozens of `POKE`s.

### Concept Expansion

Seeing both versions together removes the mystery from assembly. You already understand the logic—assembly just expresses it byte by byte. Prototype in BASIC, profile, then migrate hotspots to 6502 when the budget demands it.

---

### Game Integration

Keep both versions around during development:

```basic
IF DEBUG THEN GOSUB 2000 ELSE SYS ASMADDR
```

Keep the BASIC version parked at line `2000` (tag it with `REM BASIC MOVE ROUTINE`). Store the machine-code start address in a constant such as `ASMADDR=8200`. Switch back to BASIC whenever you need to verify correctness; ship with assembly for speed.

- Profiling first tells you whether a machine-code rewrite is worth the effort.

- Maintaining both versions helps you debug as you transition to full assembly.
