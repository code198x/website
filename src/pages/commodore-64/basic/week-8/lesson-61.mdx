## Lesson 61 – POKE the Future

Here’s the handshake between BASIC and assembly. We’ll type a tiny machine-code routine into memory, let BASIC feed it parameters, and call it with `SYS`. The routine cycles the border colour with almost no overhead—proof that a few bytes of assembly can supercharge familiar games.

> [📷 suggested: border flashing smoothly when the routine runs]

---

### The One-Minute Tour

- Store machine-code bytes in `DATA`, then `POKE` them into a safe block of RAM (we’ll use `$C000`, decimal 49152).
- Share state via zero-page addresses (`$FC–$FE`); BASIC writes delay and colour values, assembly updates them.
- Call the routine inside a BASIC loop with `SYS address` to get the best of both worlds.

---

### Example Program

```basic
NEW
10 REM *** BORDER CYCLER HYBRID ***
20 START=49152:REM $C000
30 GOSUB 9000:REM install machine code
40 FOR I=0 TO 15:POKE 53760+I,I:NEXT :REM colour table at $D200
50 PRINT CHR$(147);"MACHINE CODE DEMO"
60 PRINT "SPACE = TOGGLE COLOR CYCLER"
70 PRINT "D = CHANGE DELAY  RETURN = QUIT"
80 ACTIVE=0:POKE 252,0:POKE 253,0:POKE 254,6
90 GET K$
100 IF K$=" " THEN ACTIVE=1-ACTIVE
110 IF K$="D" THEN POKE 254,PEEK(254)+2:PRINT "DELAY:";PEEK(254)
120 IF K$=CHR$(13) THEN 190
130 IF ACTIVE THEN SYS START
140 GOTO 90
190 PRINT CHR$(147);"RESTORED"
200 POKE 53280,0:POKE 53281,6
210 END

9000 REM *** INSTALL MACHINE CODE ***
9010 RESTORE 9100
9020 FOR I=0 TO 38
9030 READ B:POKE START+I,B
9040 NEXT I
9050 RETURN

9100 DATA 165,252,24,105,1,133,252,197,254,208,27
9110 DATA 169,0,133,252,165,253,24,105,1,201,16,208,2,169,0
9120 DATA 133,253,168,185,0,210,141,32,208,141,33,208,96
```

```
Sample session:

MACHINE CODE DEMO
SPACE = TOGGLE COLOR CYCLER
D = CHANGE DELAY  RETURN = QUIT
```

Press `SPACE` and the border cycles colours smoothly; press it again to stop. `D` increases the delay (stored at zero-page `$FE`), slowing the pulse. `RETURN` exits and restores the default colours.

How it works:

- Zero-page `$FC` holds the delay counter; `$FD` holds the current colour index; `$FE` holds the reload delay. `PEEK/POKE` these from BASIC to change behaviour live.
- The machine-code routine increments the delay; when it matches `$FE` it wraps, advances the colour index, reads the actual colour from the table at `$D200`, and pokes the border/background registers. It then returns to BASIC.
- BASIC merely toggles a flag and calls `SYS START` each loop while the routine is active.

> **Tip:** Keep your machine-code table (here at `$D200`) outside BASIC’s text/variable space. `$C000–$CFFF` and `$D200–$D2FF` are convenient experiment zones.

### Experiment Section

- Rewrite the colour table to use only two or three colours for a subtler pulse.
- Expose a “reverse” toggle in BASIC by subtracting instead of adding when a key is pressed.
- Call the routine from Scroll Runner whenever the player grabs a power-up.
- Measure how fast the colour changes if you call the routine from inside a tight `FOR` loop compared to a BASIC-only colour cycler.

### Concept Expansion

You just executed assembly from BASIC. This hybrid trick—BASIC controlling flow, tiny routines handling heavy lifting—appears everywhere in commercial software. You tune in BASIC, then hand critical jobs to machine code once you know what you need.

---

### Game Integration

Drop the installer into your library block:

```basic
GOSUB 9000 : REM INSTALL FLASHER
FLASHER_START=49152
IF ALERT THEN SYS FLASHER_START
```

Keep the installer routine at line `9000` inside your library block (label it with a `REM FLASHER INSTALLER`). `FLASHER_START` should be a numeric constant set to the routine's entry address—for example `FLASHER_START=49152`. BASIC continues to orchestrate states and menus, while assembly delivers instant feedback effects.

### What You’ve Learnt

- BASIC can install and call assembly helpers with just `DATA`, `POKE`, and `SYS`.
- Zero-page memory provides a convenient bridge for passing parameters.
- A tiny routine can replace dozens of BASIC statements while keeping your main program readable.
