## Lesson 25 – Sprite Primer

Week 4 begins with hardware sprites—the C64’s smooth, hardware-accelerated graphics objects. You’ll define a sprite, point to it, give it a colour, and enable it on screen.

> [📷 suggested: screenshot showing a single sprite positioned on screen]

---

### The One-Minute Tour

- Sprite data lives in 64-byte blocks (63 bytes used, rounded up).  
- Sprite pointers (2040–2047) point to those blocks.  
- Enable register `53269` turns sprites on (bit per sprite).  
- Position registers `53248/53249` (sprite 0) set the screen location (0–255).

---

### Memory Map Quick Facts

- Sprite 0 data default block: `832`–`894` (block 13).  
- Pointer value = block number (`address / 64`).  
- Colour register `53287` controls sprite 0 colour.

---

### Example: Solid Sprite

```basic
NEW
10 REM --- SPRITE PRIMER ---
20 PRINT CHR$(147)
30 FOR I=832 TO 894:POKE I,255:NEXT I      : REM fill block with solid pixels
40 POKE 2040,13                              : REM sprite 0 pointer -> block 13 (832/64)
50 POKE 53287,1                              : REM colour = white
60 POKE 53248,120:POKE 53249,100            : REM position (X,Y)
70 POKE 53269,1                              : REM enable sprite 0
```

- **Lines 30–32** fill the sprite data with `255` (all bits on).  
- **Line 40** points sprite 0 to block 13.  
- **Line 50** sets sprite 0 colour to white.  
- **Line 60** positions the sprite.  
- **Line 70** enables sprite 0.

Run the program—your first hardware sprite appears instantly.

---

### Experiment Section

- Change colour with `POKE 53287,COL` using the 16 colour codes.  
- Move the sprite around by updating `POKE 53248` and `POKE 53249`.  
- Define a custom shape: replace the `FOR` loop with `DATA` statements containing your own sprite pattern.  
- Try using block 12 or 14 (pointer value 12 or 14) to keep sprite data separated in memory.

---

### Concept Expansion

Sprites are independent of the character grid and can be moved, scaled, and coloured at runtime without redrawing the screen. Everything in Week 4 builds on this foundation.

---

### Game Integration

- Plan your sprite memory layout: one block per sprite you intend to display.  
- Create placeholder shapes now; you can replace the DATA later with detailed art.  
- Keep a sprite initialisation subroutine so your mini-game can reset sprites quickly.

---

### Quick Reference

```basic
832-894          : REM sprite 0 data block (default)
POKE 2040,block  : REM sprite pointer (block = address/64)
POKE 53287,col   : REM sprite colour
POKE 53248,x     : REM sprite X position (0-255)
POKE 53249,y     : REM sprite Y position (0-255)
POKE 53269,1     : REM enable sprite 0
```
