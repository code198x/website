## Code Organisation Review

Before building the final ROM, let's verify our code structure is clean:

**Zero Page Variables** (fast access):
- Input state: `buttons`, `buttons_prev`
- Player state: `player_x`, `player_y`, `lives`, `invuln_timer`
- Enemy state: `enemy_x[]`, `enemy_y[]`, `enemy_dir[]`
- Item state: `item_x`, `item_y`
- Score state: `score[]`, `high_score[]`, `new_high`
- Game state: `game_state`, `screen_drawn`, `pause_flag`
- Timing: `frame_counter`, `flash_timer`, `gameover_delay`
- Sound: `sfx_timer`, `sfx_type`, `sfx_pitch`
- Gameplay: `difficulty`, `temp`

**Constants**:
- Hardware addresses grouped together
- Button masks defined as bit patterns
- Game constants (speeds, sizes, timings) named clearly
- Tile indices for text display

**Subroutines**:
- Each routine does one thing well
- Clear entry and exit points
- Shared utilities (`div10`, `respawn_item`) factored out

## The Complete Game Loop

Let's trace through the final game flow:

1. **Power On / Reset**
   - Clear RAM, initialise hardware
   - Load palette, hide sprites
   - Enter TITLE state

2. **Title Screen**
   - Display "NEON NEXUS", "PRESS START", "V1.0"
   - Wait for START press
   - Transition to PLAYING

3. **Gameplay**
   - Player moves with d-pad (bounded)
   - Enemies scroll and bounce
   - Collect items for points
   - Difficulty increases with score
   - Take damage, lose lives
   - Pause with START
   - Game over when lives = 0

4. **Game Over**
   - Screen flash effect
   - Display high score
   - Show "NEW" if applicable
   - Wait, then accept START
   - Return to gameplay (high score persists)

## Build the Release ROM

```bash
ca65 nexus.asm -o nexus.o
ld65 -C nes.cfg nexus.o -o nexus.nes
```

If you want a release build with version tagging:

```bash
ca65 nexus.asm -o nexus.o
ld65 -C nes.cfg nexus.o -o neon-nexus-v1.0.nes
```

Test in your emulator of choice. If everything passes the checklist, you've got a release ROM!
