## Bounding Box Collision

Two rectangles collide if they overlap on both axes. For 8×8 sprites:

```
Collision occurs when ALL of these are true:
  player_x < item_x + 8   (player left edge < item right edge)
  item_x < player_x + 8   (item left edge < player right edge)
  player_y < item_y + 8   (player top edge < item bottom edge)
  item_y < player_y + 8   (item top edge < player bottom edge)
```

If any condition is false, there's no collision.

In assembly, we check each condition and bail out if any fails:

<CodeFromFile src="nintendo-entertainment-system/game-01-neon-nexus/unit-05/snippets/05-bounding-box-collision.asm" lang="asm" />

**`clc`** — "Clear Carry." Ensures the carry flag is 0 before addition. Without this, a leftover carry from previous operations would add an extra 1.

**`adc #8`** — "Add with Carry." Adds 8 to A plus the carry flag. After `clc`, it simply adds 8.

The logic: after `cmp A, B`, the carry flag is **set** if A >= B, **clear** if A < B. We use `bcc` (branch if carry clear) to skip when there's no overlap on that axis.

**`asl a`** — "Arithmetic Shift Left." Shifts all bits left, putting 0 into bit 0. This doubles the value. Four shifts multiply by 16.

This creates a simple pattern: items appear at different X positions based on the score, alternating between high and low Y positions. It's not random, but it gives variety.

## What You've Learnt

- **Bounding boxes** check rectangular overlap on both axes
- **`clc` + `adc`** perform clean addition
- **`asl`** doubles values (shift left = multiply by 2)
- **Carry flag after `cmp`** indicates greater-than/less-than
- **Sequential condition checks** with early exit for efficiency
