## What You're Building

Right now, one touch from an enemy means instant game over. That's brutal. Real arcade games give players multiple chances—three lives is the classic convention.

This unit adds:
- A lives counter starting at 3
- Lives display in the HUD
- Life loss on enemy collision (not instant game over)
- Brief invulnerability after respawning
- Game over only when all lives are gone

The difference between "unfair" and "challenging" often comes down to whether players feel they had a fair chance.

## The Plan

1. Add a `lives` variable initialised to 3
2. Add an `invuln_timer` for post-respawn protection
3. Display lives count in the HUD alongside score
4. Modify collision to lose a life instead of instant game over
5. Respawn player at starting position with invulnerability
6. Only trigger game over when lives reach zero

## Build It. Run It.

Assemble and run:

```bash

ld65 -C nes.cfg nexus.o -o nexus.nes
```

Test by:
1. Starting the game—you should see "3" on the right of the HUD
2. Colliding with an enemy—lives drops to 2, player respawns, sprite flickers
3. During flicker, enemies pass through harmlessly
4. Lose all lives—game over state activates
5. Press Start—full restart with 3 lives again

## What You've Built

Your game now has a proper life system. Players get three chances, respawn safely after death, and only face game over when truly defeated. The flickering invulnerability gives clear feedback about the protection window.

## What You've Learnt

- **Invulnerability timers**: Preventing instant re-death after respawn
- **Conditional collision**: Skipping checks based on game state
- **Visual feedback**: Using bit manipulation for sprite flickering
- **Underflow prevention**: Checking before decrementing to avoid wrap-around
- **HUD extension**: Adding more information to the display
