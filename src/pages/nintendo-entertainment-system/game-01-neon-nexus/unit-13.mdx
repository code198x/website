## What You're Building

All enemies currently move identically—straight left across the screen. That's predictable and quickly becomes boring. Real arcade games vary enemy behaviour to keep players alert.

This unit adds:
- Vertical movement for some enemies (bouncing up/down)
- Per-enemy movement flags to differentiate behaviour
- Screen boundary bouncing for vertical movers

## The Plan

1. Add `enemy_dir` array to track vertical direction
2. Give enemies 0-1 horizontal-only movement
3. Give enemies 2-3 combined horizontal and vertical movement
4. Implement vertical boundary bouncing

## Enemy Direction Tracking

Each enemy needs a direction flag for vertical movement:

```asm
.segment "ZEROPAGE"
enemy_dir:      .res 4      ; vertical direction: 0=down, 1=up
```

## Initialising Enemy Directions

Set initial directions when spawning enemies:

```asm
init_enemies:
    ; Enemy 0: top-left, moves down
    lda #30
    sta enemy_x
    lda #50
    sta enemy_y
    lda #0              ; direction: down
    sta enemy_dir

    ; Enemy 1: top-right, moves up
    lda #200
    sta enemy_x+1
    lda #50
    sta enemy_y+1
    lda #1              ; direction: up
    sta enemy_dir+1

    ; Enemy 2: bottom-left (horizontal only)
    lda #30
    sta enemy_x+2
    lda #180
    sta enemy_y+2

    ; Enemy 3: bottom-right (horizontal only)
    lda #200
    sta enemy_x+3
    lda #180
    sta enemy_y+3

    rts
```

## Differentiating Enemy Movement

Modify `move_enemies` to add vertical movement for enemies 0 and 1:

```asm
move_enemies:
    ; Get horizontal speed from difficulty
    ldx difficulty
    lda enemy_speeds, x
    sta temp                ; horizontal speed

    ldx #0                  ; enemy index

@loop:
    ; --- Horizontal movement (all enemies) ---
    lda enemy_x, x
    sec
    sbc temp
    sta enemy_x, x

    ; Check horizontal wrap
    cmp #250
    bcc @check_vertical
    lda #248
    sta enemy_x, x

@check_vertical:
    ; Only enemies 0-1 move vertically
    cpx #2
    bcs @next               ; enemies 2-3 skip vertical

    ; --- Vertical movement ---
    lda enemy_dir, x
    beq @move_down
    ; Moving up
    lda enemy_y, x
    sec
    sbc #1                  ; move up 1 pixel
    cmp #24                 ; top boundary (below HUD)
    bcs @store_y
    ; Hit top - reverse to down
    lda #0
    sta enemy_dir, x
    lda #24
    jmp @store_y

@move_down:
    lda enemy_y, x
    clc
    adc #1                  ; move down 1 pixel
    cmp #216                ; bottom boundary
    bcc @store_y
    ; Hit bottom - reverse to up
    lda #1
    sta enemy_dir, x
    lda #215

@store_y:
    sta enemy_y, x

@next:
    inx
    cpx #NUM_ENEMIES
    bne @loop

    rts
```

## Understanding the Logic

The key insight is using `CPX #2` to differentiate enemy types:
- Enemies 0 and 1 (X < 2): Move both horizontally and vertically
- Enemies 2 and 3 (X >= 2): Move only horizontally

For vertical movement:
- `enemy_dir = 0` means moving down (Y increases)
- `enemy_dir = 1` means moving up (Y decreases)
- When hitting a boundary, we flip the direction

## Boundary Values

The vertical boundaries account for:
- **Top (Y = 24)**: Below the HUD row to avoid visual overlap
- **Bottom (Y = 216)**: Above the screen edge, leaving room for the 8-pixel sprite

## Frame Counter for Slower Vertical Movement

If vertical movement feels too fast, we can use a frame counter to slow it:

```asm
.segment "ZEROPAGE"
frame_counter:  .res 1      ; counts frames
```

Increment it each frame and check before vertical movement:

```asm
@check_vertical:
    cpx #2
    bcs @next

    ; Only move vertically every other frame
    lda frame_counter
    and #%00000001
    bne @next               ; skip on odd frames

    ; ... vertical movement code ...
```

This halves the vertical speed relative to horizontal, creating a more diagonal movement pattern.

## Updating Frame Counter

In the main loop, increment the frame counter:

```asm
playing_state:
    inc frame_counter       ; count frames

    lda invuln_timer
    beq @no_invuln
    ; ...
```

## Visual Result

With these changes:
- Enemies 0 and 1 move diagonally, bouncing between top and bottom
- Enemies 2 and 3 move straight across like before
- The mix creates more dynamic gameplay requiring varied dodging strategies
