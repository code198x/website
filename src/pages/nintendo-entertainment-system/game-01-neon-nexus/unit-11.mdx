## What You're Building

Right now enemies move at a constant speed. The game starts easy and stays easy—not very compelling. Classic arcade games ramp up difficulty as the player progresses, creating tension and challenge.

This unit adds:
- A difficulty level that increases with score
- Enemies that move faster at higher difficulty
- A frame skip system to control speed without floating-point maths

## The Plan

1. Add a `difficulty` variable that tracks current level
2. Increase difficulty every 50 points
3. Modify enemy movement to move faster at higher difficulty
4. Cap difficulty at a maximum level

## The Challenge of Variable Speed

The 6502 doesn't have floating-point numbers or easy multiplication. We can't simply multiply speed by 1.5. Instead, we use a frame-skip approach: at low difficulty, enemies move every frame. At high difficulty, enemies move twice per frame (or skip frames less often).

Another approach: instead of moving 1 pixel per frame, we can move 2 pixels per frame at higher difficulty. This is simpler and works well for our game.

## Difficulty Variable

Add a difficulty level to zero page:

```asm
.segment "ZEROPAGE"
difficulty:     .res 1      ; current difficulty level (0-5)
```

Difficulty starts at 0 and increases as score rises. We'll define constants:

```asm
MAX_DIFFICULTY  = 5         ; cap at level 5
SCORE_PER_LEVEL = 50        ; increase difficulty every 50 points
```

## Updating Difficulty

After collecting an item, check if we should increase difficulty:

```asm
update_difficulty:
    ; Check if already at max
    lda difficulty
    cmp #MAX_DIFFICULTY
    bcs @done               ; already at max

    ; Check score thresholds
    ; difficulty 1 at 50, 2 at 100, 3 at 150, etc.
    ; Target score = (difficulty + 1) * 50
    lda difficulty
    clc
    adc #1                  ; target level
    tax                     ; save in X

    ; Multiply by 50: (X * 50) = (X * 32) + (X * 16) + (X * 2)
    ; Or simpler: compare score against lookup table
    lda score
    cmp difficulty_thresholds, x
    bcc @done               ; score below threshold

    ; Score reached threshold - increase difficulty
    inc difficulty

@done:
    rts

; Score thresholds for each difficulty level
difficulty_thresholds:
    .byte 0                 ; level 0 (start)
    .byte 50                ; level 1
    .byte 100               ; level 2
    .byte 150               ; level 3
    .byte 200               ; level 4
    .byte 250               ; level 5 (max)
```

## Difficulty-Based Enemy Speed

Modify `move_enemies` to move enemies faster at higher difficulty:

```asm
move_enemies:
    ldx #0

@loop:
    ; Base movement
    lda enemy_x, x
    sec
    sbc #ENEMY_SPEED        ; always move at least 1 pixel
    sta enemy_x, x

    ; Extra movement at higher difficulty
    lda difficulty
    beq @check_wrap         ; difficulty 0 = no extra speed

    ; At difficulty 1+, move extra pixel
    lda enemy_x, x
    sec
    sbc #1                  ; extra pixel
    sta enemy_x, x

    ; At difficulty 3+, move another extra pixel
    lda difficulty
    cmp #3
    bcc @check_wrap
    lda enemy_x, x
    sec
    sbc #1
    sta enemy_x, x

@check_wrap:
    ; Check for screen wrap
    lda enemy_x, x
    cmp #250
    bcc @next

    ; Respawn on right side
    lda #248
    sta enemy_x, x

@next:
    inx
    cpx #NUM_ENEMIES
    bne @loop

    rts
```

This gives us:
- Difficulty 0: 1 pixel/frame
- Difficulty 1-2: 2 pixels/frame
- Difficulty 3-5: 3 pixels/frame

## Alternative: Speed Table

For finer control, use a lookup table:

```asm
; Pixels to move per frame at each difficulty
enemy_speeds:
    .byte 1, 1, 2, 2, 3, 3   ; difficulty 0-5

move_enemies:
    ; Get speed for current difficulty
    ldx difficulty
    lda enemy_speeds, x
    sta temp                ; store speed to use

    ldx #0                  ; enemy index

@loop:
    lda enemy_x, x
    sec
    sbc temp                ; subtract speed
    sta enemy_x, x

    ; Check wrap
    cmp #250
    bcc @next
    lda #248
    sta enemy_x, x

@next:
    inx
    cpx #NUM_ENEMIES
    bne @loop

    rts
```

This is cleaner and makes balancing easier—just adjust the table values.

## Calling Update Difficulty

Call `update_difficulty` after collecting an item:

```asm
collect_item:

    clc
    adc #10
    sta score
    lda score+1
    adc #0
    sta score+1

    jsr update_difficulty   ; <-- Check if we level up
    jsr play_collect_sound

```

    lda #0

    lda #0
    sta APU_PULSE1_SWEEP

    lda #%00001000

update_sound:
    lda sfx_timer
    beq @done

    lda sfx_timer
    and #%00000011
    bne @done

    ldx sfx_pitch
    cpx #5
    bcs @done
    lda collect_pitches, x
    sta APU_PULSE1_TIMER_LO
    rts

@update_death:
    lda sfx_timer
    and #%00000011
    bne @done
    inc sfx_pitch
    ldx sfx_pitch
    cpx #5
    bcs @done
    lda death_pitches, x
    sta APU_PULSE1_TIMER_LO
    rts

@end_sound:
    lda #%00110000
    sta APU_PULSE1_CTRL
    lda #SFX_NONE
    sta sfx_type
@done:
    rts

    .byte 200, 150, 100, 75, 50

death_pitches:
    .byte 100, 150, 200, 230, 254

    lda #SPAWN_Y
    sta player_y

    lda #50
    sta enemy_y

    lda #180
    sta enemy_y+2
