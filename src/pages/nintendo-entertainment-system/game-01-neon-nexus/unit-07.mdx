- A score display in the top-left corner

## The Plan

Here's what we need to add:

1. **Digit tiles** — Graphics for 0-9 in CHR ROM
2. **Score display position** — Where on the nametable to write
3. **Draw score routine** — Convert score to digits and write to PPU
4. **Vblank update** — Draw the score in NMI when safe

## The PPU Timing Challenge

Here's the problem: we can only write to PPU memory during **vblank** — the brief pause between frames when the screen isn't being drawn. Writing to PPUDATA while rendering is active causes graphical corruption.

We've been writing to the PPU during setup (before enabling rendering) and during DMA (which happens automatically). But the score changes during gameplay. We need to update background tiles mid-game.

The solution: update the score display inside the NMI handler, where we're guaranteed to be in vblank.

## Score Display Position

The NES nametable is 32×30 tiles. The background fills the whole screen. We'll put the score in the top-left corner.

Nametable 0 starts at PPU address $2000. Each row is 32 bytes. To write at row 1, column 2:

```
Address = $2000 + (row × 32) + column
        = $2000 + (1 × 32) + 2
        = $2000 + 32 + 2
        = $2022
```

We'll display 3 digits (up to 255) at positions $2022, $2023, $2024.

## What You've Learnt

- **Vblank timing** is critical for PPU updates
- **Division by repeated subtraction** works when there's no divide instruction
- **Tile indices** map graphics to displayable characters
- **Scroll reset** is required after PPUADDR/PPUDATA operations
- **NMI is safe** for PPU writes since rendering is paused
