## What You're Building

Every game needs a pause feature. Players need to answer the phone, grab a drink, or simply take a break. But implementing pause correctly requires understanding **edge detection**—responding to a button press only once, not continuously.

This unit adds:
- Edge-triggered START button detection
- A pause flag that freezes gameplay
- Visual feedback showing "PAUSED" on screen
- Proper state management across game transitions

## The Plan

1. Add variables for previous button state and pause flag

3. Gate all gameplay updates behind the pause flag
4. Draw/clear "PAUSED" text when toggling

## Understanding EOR for Toggle

The `EOR #1` instruction is perfect for toggling a flag:

| pause_flag | EOR #1 | Result |
|------------|--------|--------|
| 0          | 1      | 1      |
| 1          | 1      | 0      |

The exclusive-OR flips bit 0, toggling between 0 and 1.

## Why Edge Detection Matters

Without edge detection, the pause would flicker rapidly while START is held. The player would have to release and press START with frame-perfect timing. Edge detection makes the input feel natural and responsive.

This technique applies to any "toggle" or "trigger once" input:
- Pause/unpause
- Menu selection
- Jump initiation (so holding jump doesn't auto-jump repeatedly)
- Weapon firing (for semi-automatic weapons)
