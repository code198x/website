Ball bounces off walls—but sails past paddles. This lesson implements AABB (Axis-Aligned Bounding Box) collision detection: test if ball rectangle overlaps paddle rectangle by checking X overlap AND Y overlap independently. Ball is 8×8 pixels, paddle is 8×16 pixels. When collision detected, reverse ball X velocity and snap ball outside paddle to prevent tunneling.

This is pixel-perfect collision—the foundation of responsive gameplay.

## The One-Minute Tour

- **AABB collision**—Rectangle overlap test (ball vs paddle boxes)
- **Two-stage test**—X overlap AND Y overlap (both must be true)
- **Edge calculation**—Add width/height to get right/bottom edges
- **Sprite sizes**—Ball 8×8, Paddle 8×16 (different hitboxes)
- **Bounce response**—Reverse ball_vx, snap ball outside paddle
- **Two paddles**—Check both P1 and P2 independently
- **Order matters**—Check collision BEFORE updating ball position

## Your Collision Detection

```nasm
.segment "ZEROPAGE"
; Ball entity
ball_x:  .res 1
ball_y:  .res 1
ball_vx: .res 1
ball_vy: .res 1

; Paddle entities (from L11-16)
paddle1_x: .res 1
paddle1_y: .res 1
paddle2_x: .res 1
paddle2_y: .res 1

; Collision sizes
BALL_WIDTH = 8
BALL_HEIGHT = 8
PADDLE_WIDTH = 8
PADDLE_HEIGHT = 16

.segment "CODE"
; Check if ball collides with paddle 1
CheckBallPaddle1:
    ; ===== X AXIS OVERLAP TEST =====
    ; Ball right edge > Paddle left edge?
    LDA ball_x
    CLC
    ADC #BALL_WIDTH         ; Ball right edge
    CMP paddle1_x           ; Compare to paddle left
    BCC @no_collision       ; Branch if ball_right < paddle_left

    ; Paddle right edge > Ball left edge?
    LDA paddle1_x
    CLC
    ADC #PADDLE_WIDTH       ; Paddle right edge
    CMP ball_x              ; Compare to ball left
    BCC @no_collision       ; Branch if paddle_right < ball_left

    ; X axes overlap! Now check Y...

    ; ===== Y AXIS OVERLAP TEST =====
    ; Ball bottom edge > Paddle top edge?
    LDA ball_y
    CLC
    ADC #BALL_HEIGHT        ; Ball bottom edge
    CMP paddle1_y           ; Compare to paddle top
    BCC @no_collision       ; Branch if ball_bottom < paddle_top

    ; Paddle bottom edge > Ball top edge?
    LDA paddle1_y
    CLC
    ADC #PADDLE_HEIGHT      ; Paddle bottom edge
    CMP ball_y              ; Compare to ball top
    BCC @no_collision       ; Branch if paddle_bottom < ball_top

    ; Both axes overlap = COLLISION!
    JSR HandlePaddle1Hit
    LDA #$01                ; Return collision flag
    RTS

@no_collision:
    LDA #$00                ; No collision
    RTS

; Check if ball collides with paddle 2
CheckBallPaddle2:
    ; Same logic as paddle 1, use paddle2_x/y
    LDA ball_x
    CLC
    ADC #BALL_WIDTH
    CMP paddle2_x
    BCC @no_collision

    LDA paddle2_x
    CLC
    ADC #PADDLE_WIDTH
    CMP ball_x
    BCC @no_collision

    LDA ball_y
    CLC
    ADC #BALL_HEIGHT
    CMP paddle2_y
    BCC @no_collision

    LDA paddle2_y
    CLC
    ADC #PADDLE_HEIGHT
    CMP ball_y
    BCC @no_collision

    JSR HandlePaddle2Hit
    LDA #$01
    RTS

@no_collision:
    LDA #$00
    RTS

; Handle paddle 1 collision (basic bounce)
HandlePaddle1Hit:
    ; Reverse ball X velocity (bounce away from paddle)
    JSR NegateBallVX

    ; Snap ball outside paddle (prevent sticking)
    LDA paddle1_x
    CLC
    ADC #PADDLE_WIDTH       ; Paddle right edge
    STA ball_x              ; Place ball just right of paddle

    RTS

; Handle paddle 2 collision
HandlePaddle2Hit:
    ; Reverse ball X velocity
    JSR NegateBallVX

    ; Snap ball outside paddle (left side)
    LDA paddle2_x
    SEC
    SBC #BALL_WIDTH         ; Place ball just left of paddle
    STA ball_x

    RTS

; Main game loop integration
MainLoop:
    ; ... wait for VBlank ...

    JSR ReadController
    JSR UpdatePaddle

    ; Check collisions BEFORE updating ball position
    JSR CheckBallPaddle1
    JSR CheckBallPaddle2

    JSR UpdateBallPhysics   ; Ball movement and boundary checks

    JSR UpdatePaddleSprites
    JSR UpdateBallSprite

    JMP MainLoop
```

**Run this**—ball bounces off paddles! Simple bounce (angle control comes in L22).

## How This Works

### AABB Collision Theory

Two rectangles overlap if they overlap on *both* X and Y axes:

```
Rectangle A overlaps Rectangle B if:
  A.left < B.right  AND
  A.right > B.left  AND
  A.top < B.bottom  AND
  A.bottom > B.top
```

**Why both axes?** Rectangles can be aligned on one axis but not the other:

```
Aligned on Y, but not X (no collision):
  Paddle     Ball
  ┌────┐     ┌──┐
  │    │     │  │
  │    │     │  │
  └────┘     └──┘

Aligned on X, but not Y (no collision):
  ┌────┐
  │Ball│
  └────┘

  ┌──────┐
  │Paddle│
  │      │
  └──────┘

Aligned on BOTH (collision!):
  ┌────┐
  │ ┌──│──┐
  │ │Pa│ll│
  │ └──│──┘
  └────┘
```

### Edge Calculation

Sprite position is top-left corner. Calculate other edges:

```nasm
; Ball left edge = ball_x (position)
; Ball right edge = ball_x + BALL_WIDTH

LDA ball_x
CLC
ADC #BALL_WIDTH     ; Right edge = left + width
```

**Four edges per sprite:**
- Left: position
- Right: position + width
- Top: position
- Bottom: position + height

### X-Axis Overlap Test

Check if ball and paddle overlap horizontally:

```nasm
; Test 1: Ball right edge > Paddle left edge?
LDA ball_x
CLC
ADC #BALL_WIDTH     ; Ball right
CMP paddle1_x       ; Paddle left
BCC no_overlap      ; Branch if ball_right < paddle_left

; Test 2: Paddle right edge > Ball left edge?
LDA paddle1_x
CLC
ADC #PADDLE_WIDTH   ; Paddle right
CMP ball_x          ; Ball left
BCC no_overlap      ; Branch if paddle_right < ball_left

; Both tests passed = X overlap!
```

**Why two tests?** Each test catches one failure case:
- Test 1 fails: Ball entirely to left of paddle
- Test 2 fails: Ball entirely to right of paddle
- Both pass: Ball somewhere between paddle edges (overlap!)

### Y-Axis Overlap Test

Same logic, vertical axis:

```nasm
; Test 3: Ball bottom edge > Paddle top edge?
LDA ball_y
CLC
ADC #BALL_HEIGHT
CMP paddle1_y
BCC no_overlap

; Test 4: Paddle bottom edge > Ball top edge?
LDA paddle1_y
CLC
ADC #PADDLE_HEIGHT
CMP ball_y
BCC no_overlap

; Both tests passed = Y overlap!
```

**Combined result:** If X overlap AND Y overlap, rectangles collide!

### Position Snapping (Critical!)

After detecting collision, snap ball outside paddle:

```nasm
; Paddle 1 (ball hits from left)
LDA paddle1_x
CLC
ADC #PADDLE_WIDTH       ; Paddle right edge
STA ball_x              ; Ball left edge = paddle right edge

; Paddle 2 (ball hits from right)
LDA paddle2_x
SEC
SBC #BALL_WIDTH         ; Paddle left - ball width
STA ball_x              ; Ball right edge = paddle left edge
```

**Why snap?** Without it, ball gets stuck:
1. Ball overlaps paddle
2. Reverse velocity
3. Next frame: still overlapping (velocity too small to escape)
4. Detect collision again, reverse velocity again
5. Ball oscillates inside paddle forever

**With snapping:**
1. Ball overlaps paddle
2. **Snap ball outside** (guaranteed non-overlap)
3. Reverse velocity
4. Next frame: ball moving away from paddle
5. Clean bounce!

### Collision Order Matters

Check collisions BEFORE updating ball position:

```nasm
; CORRECT order:
JSR CheckBallPaddle1    ; Check at current position
JSR CheckBallPaddle2
JSR UpdateBallPhysics   ; Then move ball

; WRONG order:
JSR UpdateBallPhysics   ; Move ball first
JSR CheckBallPaddle1    ; Check at new position
; Problem: Fast ball can tunnel through paddle!
```

**Why?** Ball moving 4 pixels/frame can skip past paddle if paddle only 8 pixels wide. Checking before movement catches collision at entry point.

### Different Sprite Sizes

Ball: 8×8 pixels
Paddle: 8×16 pixels (two 8×8 tiles stacked)

**Hitboxes match sprite size:**
```nasm
BALL_WIDTH = 8
BALL_HEIGHT = 8
PADDLE_WIDTH = 8
PADDLE_HEIGHT = 16      ; Twice as tall
```

This creates natural Pong feel—paddle is vertical barrier, ball is small projectile.

## Common Pitfalls

**Testing collision after movement:**
- Ball tunnels through paddle at high speed
- Solution: Check collision before UpdateBallPhysics

**Wrong comparison operators:**
- Using BEQ/BNE instead of BCC
- Solution: BCC for unsigned less-than after CMP

**Not snapping ball position:**
- Ball gets stuck oscillating in paddle
- Solution: Always snap ball outside paddle after detection

**Forgetting ADC for edges:**
- Testing position instead of right/bottom edges
- Collision misses or triggers early
- Solution: Add width/height to calculate far edges

**Same bounce for both paddles:**
- Both paddles push ball same direction
- Solution: Paddle 1 snaps ball to right, Paddle 2 to left

## Quick Reference

### AABB Test Pattern
```nasm
; X overlap:
LDA obj1_x
CLC
ADC obj1_width      ; Right edge
CMP obj2_x          ; Compare to obj2 left
BCC no_overlap

LDA obj2_x
CLC
ADC obj2_width      ; Right edge
CMP obj1_x          ; Compare to obj1 left
BCC no_overlap

; Y overlap (same pattern with y and height)
; ...

; If reach here = collision!
```

### Collision Response Order
```
1. Detect collision (AABB test)
2. Snap position (place ball outside paddle)
3. Reverse velocity (bounce direction)
4. Optional: Modify velocity (angle control, next lesson)
```

### Sprite Hitboxes
```
Ball:   8×8  pixels
Paddle: 8×16 pixels

Ball edges:
  Left   = ball_x
  Right  = ball_x + 8
  Top    = ball_y
  Bottom = ball_y + 8

Paddle edges:
  Left   = paddle_x
  Right  = paddle_x + 8
  Top    = paddle_y
  Bottom = paddle_y + 16
```
