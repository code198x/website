Static sprites displayed on screen—but games need movement. This lesson implements velocity-based animation: position changes automatically each frame based on a velocity variable. Add boundary detection to create bouncing behaviour.

Previous lesson showed DMA for efficient sprite updates. This lesson adds the movement system that changes positions every frame.

## The One-Minute Tour

- **Velocity variable**—pixels per frame, signed (positive/negative)
- **Automatic movement**—add velocity to position each frame
- **Signed arithmetic**—two's complement: $FF = -1, $01 = +1
- **Boundary detection**—check position limits, reverse velocity on collision
- **Two's complement negation**—EOR #$FF, then ADC #$01
- **60fps consistency**—VBlank synchronization ensures smooth motion

## Your First Animated Sprite

```asm
.segment "ZEROPAGE"
paddle_y:  .res 1
paddle_vy: .res 1   ; Velocity (signed)

.segment "CODE"
Reset:
    ; [PPU warmup, etc.]

    LDA #100
    STA paddle_y
    LDA #2           ; Move down at 2 pixels/frame
    STA paddle_vy

MainLoop:
    ; Wait for VBlank
:   LDA nmi_ready
    BEQ :-
    LDA #$00
    STA nmi_ready

    ; Apply velocity to position
    LDA paddle_y
    CLC
    ADC paddle_vy    ; Works for positive AND negative
    STA paddle_y

    ; Check top boundary
    CMP #8
    BCS :+           ; Branch if Y >= 8
    LDA #8
    STA paddle_y
    ; Negate velocity (bounce)
    LDA paddle_vy
    EOR #$FF         ; Flip all bits
    CLC
    ADC #$01         ; Add 1
    STA paddle_vy

    ; Check bottom boundary
:   LDA paddle_y
    CMP #200
    BCC :+           ; Branch if Y < 200
    LDA #200
    STA paddle_y
    ; Negate velocity
    LDA paddle_vy
    EOR #$FF
    CLC
    ADC #$01
    STA paddle_vy

:   JSR UpdateOAM
    JMP MainLoop
```

**Run this**—paddle moves smoothly and bounces off top/bottom edges!

## How This Works

### Velocity-Based Movement

**Velocity = pixels per frame**. Positive values move down/right. Negative values move up/left.

```asm
paddle_vy: .res 1   ; Velocity

; Each frame
LDA paddle_y
CLC
ADC paddle_vy       ; Add velocity (signed addition)
STA paddle_y
```

**Example:**
- Y=100, velocity=2 → next frame Y=102 (moved down 2 pixels)
- Y=100, velocity=$FE (-2) → next frame Y=98 (moved up 2 pixels)

**ADC handles signed values automatically** through two's complement arithmetic.

### Signed Arithmetic on 6502

**Two's complement representation:**
```
$00 = 0
$01 = 1
$02 = 2
...
$7F = 127 (largest positive)
$80 = -128 (smallest negative)
...
$FE = -2
$FF = -1
```

**Why it works:** Binary addition wraps naturally. $FE + $05 = $03 (carries out). From CPU perspective: -2 + 5 = 3.

**Range:** -128 to +127 in single byte. Perfect for sprite velocities (typically ±1 to ±5 pixels/frame).

### Two's Complement Negation

To reverse velocity direction (create bouncing):

```asm
LDA paddle_vy
EOR #$FF         ; Flip all bits (one's complement)
CLC
ADC #$01         ; Add 1 (two's complement)
STA paddle_vy
```

**Example:**
- $02 (velocity = +2)
- EOR #$FF → $FD
- Add 1 → $FE (velocity = -2)

**Pattern:** EOR flips bits, add 1 completes negation. Standard two's complement formula.

**Alternative:** Could use subtraction ($00 - velocity), but EOR/ADC is more efficient (no need to load zero).

### Boundary Detection

Check position AFTER movement, clamp if exceeded, negate velocity:

```asm
; Top boundary (Y < 8)
LDA paddle_y
CMP #8
BCS within       ; Branch if >= 8 (carry set)
; Exceeded boundary
LDA #8
STA paddle_y     ; Clamp to boundary
; [Negate velocity code]
within:
```

**CMP mechanics:**
- CMP #8 subtracts 8 from A (doesn't store result)
- If A >= 8: Carry flag SET
- If A < 8: Carry flag CLEAR
- BCS = Branch if Carry Set = Branch if A >= 8

**Two boundaries:**
1. **Top (Y < 8):** Clamp to 8, negate velocity (now positive)
2. **Bottom (Y > 200):** Clamp to 200, negate velocity (now negative)

### Frame-Rate Synchronization

Main loop waits for `nmi_ready` flag. NMI sets flag once per VBlank. Result: movement code runs exactly 60 times per second (NTSC).

```asm
MainLoop:
    ; Wait for VBlank flag
:   LDA nmi_ready
    BEQ :-           ; Loop until flag set
    LDA #$00
    STA nmi_ready    ; Clear flag

    ; Movement code runs exactly once per frame
    LDA paddle_y
    CLC
    ADC paddle_vy
    STA paddle_y
```

**Velocity meaning:** Pixels per frame. Velocity=2 means 2 pixels per 1/60th second = 120 pixels/second.

**Consistent motion:** No matter how fast CPU runs, sprite moves at same speed. VBlank gates execution rate.

## Quick Reference

### Velocity Values

| Value | Decimal | Direction | Speed |
|-------|---------|-----------|-------|
| $01 | +1 | Down/right | 1 pixel/frame (60px/sec) |
| $02 | +2 | Down/right | 2 pixels/frame (120px/sec) |
| $03 | +3 | Down/right | 3 pixels/frame (180px/sec) |
| $FF | -1 | Up/left | 1 pixel/frame |
| $FE | -2 | Up/left | 2 pixels/frame |
| $FD | -3 | Up/left | 3 pixels/frame |

### Two's Complement Negation

```asm
; Negate value in A
EOR #$FF         ; Flip all bits
CLC
ADC #$01         ; Add 1
; A now contains negated value
```

### Boundary Check Patterns

**Check minimum (less than):**
```asm
CMP #min
BCS within       ; Branch if >= min
; Handle: below minimum
within:
```

**Check maximum (greater than):**
```asm
CMP #max
BCC within       ; Branch if < max
; Handle: above maximum
within:
```

### Common Speeds

| Speed | Screen Traverse Time | Feel |
|-------|---------------------|------|
| 1 px/frame | 4 seconds (240 frames) | Very slow |
| 2 px/frame | 2 seconds (120 frames) | Slow |
| 3 px/frame | 1.3 seconds (80 frames) | Moderate |
| 4 px/frame | 1 second (60 frames) | Fast |
| 5 px/frame | 0.8 seconds (48 frames) | Very fast |
