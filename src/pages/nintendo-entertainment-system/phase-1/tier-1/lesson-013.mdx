Games need player input to respond to button presses. The NES reads controllers through two memory-mapped registers that return button states serially—one button per read. This lesson implements the ReadController routine that captures all 8 buttons into a single byte.

Previous lesson animated sprites automatically. This lesson adds player control through controller input.

## The One-Minute Tour

- **Controller registers**—$4016 (controller 1), $4017 (controller 2)
- **Strobe sequence**—write $01 then $00 to latch current button states
- **Serial reading**—8 reads return buttons in order: A, B, Select, Start, Up, Down, Left, Right
- **Button format**—bit 0 of each read = pressed (1) or not (0)
- **LSR/ROL pattern**—shift button bit into carry, rotate into result byte
- **60 times per second**—read controller every frame for responsive input

## Your First Controller Read

```asm
.segment "ZEROPAGE"
buttons: .res 1      ; Current button states

.segment "CODE"
ReadController:
    ; Strobe controller (latch current button states)
    LDA #$01
    STA $4016
    LDA #$00
    STA $4016

    ; Read 8 buttons
    LDX #$08
:   LDA $4016        ; Read one button (bit 0)
    LSR              ; Shift bit 0 into carry
    ROL buttons      ; Rotate carry into buttons variable
    DEX
    BNE :-
    RTS

MainLoop:
:   LDA nmi_ready
    BEQ :-
    LDA #$00
    STA nmi_ready

    JSR ReadController

    ; Test if A button pressed
    LDA buttons
    AND #%10000000   ; Bit 7 = A button
    BEQ :+           ; Branch if not pressed

    ; A button pressed - do something
    LDA paddle_y
    CLC
    ADC #2
    STA paddle_y

:   JSR UpdateOAM
    JMP MainLoop
```

**Run this**—press A button to move paddle down!

## How This Works

### Controller Registers

**$4016** = Controller port 1 (player 1)
**$4017** = Controller port 2 (player 2)

Both registers work identically. Each read returns one button state in bit 0. Other bits contain "open bus" values (undefined).

**Memory-mapped I/O:** Reading $4016 doesn't return RAM contents—it returns hardware state from physical controller port.

### The Strobe Sequence

Before reading buttons, must "strobe" the controller to latch current button states:

```asm
LDA #$01
STA $4016        ; Strobe on (controller latches button states)
LDA #$00
STA $4016        ; Strobe off (ready for reading)
```

**Why strobe?** Controller hardware is a shift register. Strobe pulse captures snapshot of all button states. Subsequent reads shift out buttons one at a time.

**Timing:** Strobe takes ~1μs. Button states captured atomically—won't change mid-read even if player releases button.

### Serial Button Reading

After strobe, 8 consecutive reads of $4016 return buttons in fixed order:

1. **Read 1:** A button
2. **Read 2:** B button
3. **Read 3:** Select
4. **Read 4:** Start
5. **Read 5:** Up
6. **Read 6:** Down
7. **Read 7:** Left
8. **Read 8:** Right

Each read returns button state in **bit 0 only**:
- Bit 0 = 1: Button pressed
- Bit 0 = 0: Button not pressed
- Bits 1-7: Undefined (open bus)

**Must read all 8:** Controller shift register advances on each read. Can't skip buttons or read out of order.

### LSR and ROL Magic

Build result byte with all 8 button states using LSR/ROL pattern:

```asm
LDX #$08         ; Counter: 8 buttons
:   LDA $4016    ; Read one button
    LSR          ; Shift bit 0 into carry flag
    ROL buttons  ; Rotate carry into buttons variable
    DEX
    BNE :-
```

**Step-by-step for first iteration (A button):**
1. LDA $4016 → A = $xx (bit 0 = A button state)
2. LSR → shifts A right, bit 0 goes to carry flag
3. ROL buttons → shifts buttons left, carry goes into bit 0
4. After 8 iterations, buttons contains all button states

**Result format in `buttons` variable:**
```
Bit 7: A button
Bit 6: B button
Bit 5: Select
Bit 4: Start
Bit 3: Up
Bit 2: Down
Bit 1: Left
Bit 0: Right
```

**Why this order?** First button read goes through LSR/ROL 8 times, ending up in bit 7. Last button read goes through once, ending up in bit 0.

### Testing Individual Buttons

Use AND with bit mask to isolate specific button:

```asm
LDA buttons
AND #%10000000   ; Mask bit 7 (A button)
BEQ not_pressed  ; Z flag set if result is zero
; Button is pressed
not_pressed:
```

**Z flag behavior:**
- AND result = $00 (button not pressed) → Z flag SET → BEQ branches
- AND result = $80 (button pressed) → Z flag CLEAR → BEQ doesn't branch

**Alternative test with BNE:**
```asm
LDA buttons
AND #%10000000
BNE pressed      ; Branch if NOT zero (button pressed)
; Button not pressed
```

### Polling Rate

Main loop calls ReadController once per frame (60 times per second). Fast enough for responsive gameplay.

**No interrupts:** Controller reading happens in main loop, not NMI. Keeps timing predictable.

**Consistent rate:** VBlank synchronization ensures controller polled at exactly 60Hz regardless of CPU speed variations.
