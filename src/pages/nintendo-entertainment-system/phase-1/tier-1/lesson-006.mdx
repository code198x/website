The NES has a 64-colour master palette, but each tile can only use 4 colours at a time. Background palettes stored at $3F00-$3F0F define which 4 colours each tile uses. Understanding palette memory structure and loading colours during initialization is essential to creating colourful NES graphics.

Previous lessons created tile graphics in CHR-ROM. This lesson adds colour by loading background palettes, explaining the universal background colour, and designing colour schemes for the Pong playfield.

## The One-Minute Tour

- **Palette memory**—$3F00-$3F1F (16 bytes background, 16 bytes sprites)
- **4 background palettes**—each palette contains 4 colours ($3F00-$3F0F)
- **Universal background**—$3F00 colour shows through all transparent pixels
- **64-colour master palette**—colours indexed $00-$3F (hexadecimal)
- **Colour 0 is transparent**—tile pixels with value 0 show universal background
- **Loading pattern**—write $3F00 to PPUADDR, then write 16 bytes to PPUDATA
- **Attribute table**—selects which palette each 16×16 pixel area uses

## Your First Palette

Create `palettes.asm`:

```asm
.segment "HEADER"
    .byte "NES", $1A
    .byte 2
    .byte 1
    .byte $01, $00

.segment "CODE"
Reset:
    SEI
    CLD
    BIT $2002
:   BIT $2002
    BPL :-
:   BIT $2002
    BPL :-
    LDX #$FF
    TXS

    ; Load background palettes
    LDA #$3F
    STA $2006
    LDA #$00
    STA $2006

    ; Universal background colour
    LDA #$0F                ; Black
    STA $2007

    ; Palette 0 (Pong classic: black/white/grey)
    LDA #$00                ; Black (transparent)
    STA $2007
    LDA #$30                ; White
    STA $2007
    LDA #$10                ; Light grey
    STA $2007

    ; Palette 1 (unused for now)
    LDA #$00
    STA $2007
    LDA #$00
    STA $2007
    LDA #$00
    STA $2007

    ; Palette 2 (unused)
    LDA #$00
    STA $2007
    LDA #$00
    STA $2007
    LDA #$00
    STA $2007

    ; Palette 3 (unused)
    LDA #$00
    STA $2007
    LDA #$00
    STA $2007
    LDA #$00
    STA $2007

    LDA #%10000000
    STA $2000
    LDA #%00001000
    STA $2001

Forever:
    JMP Forever

NMI:
    RTI

IRQ:
    RTI

.segment "VECTORS"
    .word NMI
    .word Reset
    .word IRQ

.segment "CHARS"
    .res 8192, $00
```

This loads a classic Pong colour scheme: black background, white and grey for tiles.

## How This Works

### Palette Memory Structure

The PPU palette RAM is 32 bytes at $3F00-$3F1F:

```
$3F00-$3F0F: Background palettes (16 bytes)
$3F10-$3F1F: Sprite palettes (16 bytes)
```

**Background palettes** (this lesson) are divided into 4 palettes of 4 colours each:

```
$3F00: Universal background colour
$3F01-$3F03: Palette 0, colours 1-3
$3F04: Unused (mirrors $3F00)
$3F05-$3F07: Palette 1, colours 1-3
$3F08: Unused (mirrors $3F00)
$3F09-$3F0B: Palette 2, colours 1-3
$3F0C: Unused (mirrors $3F00)
$3F0D-$3F0F: Palette 3, colours 1-3
```

**Important:** $3F04, $3F08, $3F0C are mirrors of $3F00. Writing to these addresses actually writes to $3F00. The universal background colour is always shared.

### Universal Background Colour

**$3F00 is special**—this colour appears behind everything:

- Shows through transparent pixels (colour 0) in all tiles
- Appears in areas with no tiles
- Seen as letterbox bars if screen doesn't fill display

**Colour 0 in tiles is transparent:** When a tile pixel has value 0 (both plane bits = 0), that pixel shows the universal background colour from $3F00, not colour 0 from the tile's palette.

**Typical choice:** Black ($0F) or dark colour. Creates clean background for gameplay.

### The 64-Colour Master Palette

The NES master palette contains 64 colours indexed $00-$3F. Each palette entry selects one of these 64 colours.

**Common colours for Pong:**

```
$0F: Black (darkest)
$00: Dark grey
$10: Light grey
$20: White
$30: Bright white (lightest)
$2C: Cyan (light blue)
$16: Red
$1A: Green
```

**Palette entries are indices:** Palette memory stores colour indices, not RGB values. $3F01 = $30 means "palette 0, colour 1 is bright white."

**No RGB control:** Unlike modern systems, you can't create custom colours. Choose from the 64 provided by the NES hardware.

### Loading Palettes During Initialization

**Standard pattern:**

1. Reset PPU address latch with `BIT $2002`
2. Write $3F00 to PPUADDR (high byte $3F, low byte $00)
3. Write 16 bytes to PPUDATA (auto-increments address)

**Example:**

```asm
LDA #$3F
STA $2006               ; High byte of $3F00
LDA #$00
STA $2006               ; Low byte of $3F00

LDA #$0F
STA $2007               ; $3F00: Universal background (black)
LDA #$00
STA $2007               ; $3F01: Palette 0, colour 1
LDA #$30
STA $2007               ; $3F02: Palette 0, colour 2 (white)
LDA #$10
STA $2007               ; $3F03: Palette 0, colour 3 (grey)
; ... continue for all 16 bytes ...
```

**PPUDATA auto-increment:** After each write to $2007, the PPU address increments by 1 (default mode). Write 16 consecutive bytes to load all background palettes.

### 4-Colour Limit Per Tile

Each 8×8 tile can only use 4 colours (2 bits per pixel). The tile data stores pixel values 0-3, which index into the assigned palette.

**Example: Tile uses palette 0**

```
Tile pixel values:  0, 1, 2, 3
Palette 0 colours:  $0F (from $3F00), $00 (from $3F01), $30 (from $3F02), $10 (from $3F03)
Resulting colours:  Black, dark grey, white, light grey
```

**Palette selection:** The attribute table (next lesson) determines which palette each tile uses. Attribute table entries select palette 0, 1, 2, or 3 for each 16×16 pixel area.

### Pong Colour Schemes

**Classic Pong (black and white):**

```
$3F00: $0F (black universal background)
Palette 0: $00 (black), $30 (white), $10 (light grey)
```

All tiles use palette 0. Simple, high contrast, authentic retro look.

**Modern variant (colour accents):**

```
$3F00: $0F (black universal background)
Palette 0: $00, $30, $10 (playfield: black/white/grey)
Palette 1: $00, $2C, $30 (borders: black/cyan/white)
Palette 2: $00, $16, $30 (center line: black/red/white)
```

Different screen areas use different palettes for visual variety.

## Loading From Data Tables

Repeatedly writing `LDA #$XX / STA $2007` is tedious. Load from a table instead:

```asm
.segment "CODE"
Reset:
    ; ... initialization ...

    ; Load background palettes from table
    LDA #$3F
    STA $2006
    LDA #$00
    STA $2006

    LDX #$00
LoadPalettes:
    LDA PongPalettes,X
    STA $2007
    INX
    CPX #$10                ; 16 bytes total
    BNE LoadPalettes

    ; ... enable rendering ...

.segment "RODATA"
PongPalettes:
    ; Universal background
    .byte $0F               ; Black

    ; Palette 0: Playfield (black/white)
    .byte $00, $30, $10

    ; Palette 1: Borders (black/cyan/white)
    .byte $00, $2C, $30

    ; Palette 2: Center line (black/red/white)
    .byte $00, $16, $30

    ; Palette 3: Unused
    .byte $00, $00, $00
```

**How this works:**

- `LDX #$00` starts index at 0
- `LDA PongPalettes,X` loads byte from table (indexed addressing)
- `STA $2007` writes to PPUDATA (address auto-increments)
- `INX` increments index
- `CPX #$10` checks if 16 bytes loaded
- `BNE LoadPalettes` loops until done

**Advantages:** Easy to update colours, reusable code, cleaner to read.

### RODATA Segment

```asm
.segment "RODATA"
PongPalettes:
    .byte $0F, $00, $30, $10, ...
```

**RODATA = Read-Only Data.** This segment places data in PRG-ROM alongside code. The data is constant—can't change at runtime.

**Alternative:** Could use `.segment "CODE"` for data. RODATA makes intent clear and helps linker organize memory.

## Choosing Colours From the Master Palette

The NES 64-colour palette is fixed by hardware. Reference charts show all colours:

**Greyscale column ($00, $10, $20, $30):**
- $0F/$00: Black/dark grey
- $10: Medium grey
- $20: Light grey
- $30: Bright white

**Colour columns:** Each column ($01-$0C) has 4 shades:
- Row 0 ($X0): Darkest shade
- Row 1 ($X1-$XC): Dark shade
- Row 2 ($X1-$XC): Medium shade
- Row 3 ($X1-$XC): Light shade

**Example: Blue column**
- $01: Dark blue
- $02: Medium blue (commonly used)
- $0C: Cyan (light blue)

**Pong typically uses:** Greyscale ($0F, $00, $10, $20, $30) for classic look. Colour accents ($16 red, $2C cyan, $1A green) for visual interest.

## Palette Gotchas

**$3F04/$3F08/$3F0C are mirrors:** Writing to these addresses updates $3F00. Don't use them for different colours—they always mirror the universal background.

**Colour 0 is transparent:** Tile pixel value 0 shows $3F00, not the palette's colour 0. Some guides confuse this.

**No palette updates during rendering:** Updating palettes mid-frame causes visual glitches. Load palettes during initialization or in VBlank (NMI handler).

**PPUSTATUS clears address latch:** Always `BIT $2002` before setting PPUADDR. If the latch is in wrong state, PPUADDR writes go to wrong bytes (high/low byte swapped).

**Palette entries are colour indices:** Don't confuse palette RAM ($3F00-$3F1F) with the master palette. Palette RAM stores indices into the master palette.

## Quick Reference: Palettes

### Background Palette Memory

| Address | Contents |
|---------|----------|
| $3F00 | Universal background colour (shows through colour 0) |
| $3F01-$3F03 | Palette 0, colours 1-3 |
| $3F04 | Mirror of $3F00 (unused) |
| $3F05-$3F07 | Palette 1, colours 1-3 |
| $3F08 | Mirror of $3F00 (unused) |
| $3F09-$3F0B | Palette 2, colours 1-3 |
| $3F0C | Mirror of $3F00 (unused) |
| $3F0D-$3F0F | Palette 3, colours 1-3 |

### Common NES Colours

| Index | Colour |
|-------|--------|
| $0F | Black |
| $00 | Dark grey |
| $10 | Light grey |
| $20 | White |
| $30 | Bright white |
| $16 | Red |
| $2C | Cyan |
| $1A | Green |
| $02 | Dark blue |

### Loading Pattern

```asm
; Reset PPU latch
BIT $2002

; Set address to $3F00
LDA #$3F
STA $2006
LDA #$00
STA $2006

; Write 16 bytes (auto-increments)
LDX #$00
LoadPalettes:
    LDA PaletteData,X
    STA $2007
    INX
    CPX #$10
    BNE LoadPalettes
```

### Palette Selection

- **Tile data:** Stores pixel values 0-3 (2 bits per pixel)
- **Attribute table:** Selects palette 0-3 for each 16×16 pixel area
- **Resulting colour:** Tile pixel value indexes into selected palette

Example: Tile pixel = 2, attribute = palette 1 → colour from $3F06
