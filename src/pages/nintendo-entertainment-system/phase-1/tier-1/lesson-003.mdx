The NES has 2KB of RAM—far less than modern systems, but carefully organized for efficiency. The 6502 CPU provides special addressing modes that make certain memory regions faster to access. Understanding NES memory layout and using zero page effectively is crucial for performant game code.

Last lesson controlled the PPU. This lesson focuses on the CPU side: where to store variables, how memory is organized, what makes zero page special, and managing game state within tight constraints.

## The One-Minute Tour

- **6502 CPU** runs at 1.79 MHz with three registers: A, X, Y
- **Zero page** ($00-$FF) provides fastest memory access—use for hot variables
- **Stack** at $0100-$01FF for subroutine calls and temporary storage
- **OAM buffer** conventionally at $0200-$02FF for sprite data
- **General RAM** at $0300-$07FF for game state
- **PRG-ROM** at $8000-$FFFF holds program code (read-only)
- `.segment "ZEROPAGE"` declares variables in fast zero page memory

## Your First Variables

Create `variables.asm`:

```asm
.segment "HEADER"
    .byte "NES", $1A
    .byte 2
    .byte 1
    .byte $01, $00

.segment "ZEROPAGE"
counter: .res 1             ; Reserve 1 byte at $00
colour:  .res 1             ; Reserve 1 byte at $01

.segment "CODE"
Reset:
    SEI
    CLD

    ; PPU warmup
    BIT $2002
:   BIT $2002
    BPL :-
:   BIT $2002
    BPL :-

    ; Initialize variables
    LDA #$00
    STA counter
    LDA #$12                ; Blue
    STA colour

    ; Use variable to set background
    LDA #$3F
    STA $2006
    LDA #$00
    STA $2006
    LDA colour              ; Load from variable
    STA $2007

    ; Enable rendering
    LDA #%00001000
    STA $2001

Forever:
    INC counter             ; Increment each loop
    JMP Forever

NMI:
    RTI

IRQ:
    RTI

.segment "VECTORS"
    .word NMI
    .word Reset
    .word IRQ

.segment "CHARS"
    .res 8192, $00
```

**Assemble and run**—displays blue screen like before, but now using variables!

## How This Works

### 6502 CPU Architecture

The 6502 is an 8-bit processor with minimal internal state:

**Accumulator (A):** Primary register for arithmetic, logic, memory operations. Most instructions involve A.

**Index Register X:** Counter, array index, offset calculations.

**Index Register Y:** Counter, array index, different addressing modes than X.

**Stack Pointer (SP):** Points into $0100-$01FF. Grows downward (decrements with push).

**Program Counter (PC):** Current instruction address. Modified by jumps, branches, subroutines.

**Status Register (P):** Flags: Negative, oVerflow, Break, Decimal, Interrupt, Zero, Carry.

That's it. No caches, no floating point, no multiplication/division, no registers for general data storage. **Everything uses RAM.**

### NES Memory Map

The 6502 can address 64KB ($0000-$FFFF). The NES organizes this space:

```
$0000-$07FF: 2KB Internal RAM
  $0000-$00FF: Zero Page (256 bytes)
  $0100-$01FF: Stack (256 bytes)
  $0200-$02FF: OAM Buffer (256 bytes, conventional)
  $0300-$07FF: General Purpose (1280 bytes)

$0800-$1FFF: Mirrors of $0000-$07FF

$2000-$2007: PPU Registers
$2008-$3FFF: Mirrors of $2000-$2007

$4000-$4017: APU and I/O Registers
$4018-$401F: APU and I/O (disabled)

$4020-$5FFF: Cartridge Expansion ROM

$6000-$7FFF: Cartridge SRAM (battery-backed save RAM)

$8000-$FFFF: PRG-ROM (program code from cartridge)
  $8000-$BFFF: First 16KB bank
  $C000-$FFFF: Second 16KB bank (contains vectors)
```

**Key insight:** Only $0000-$07FF is RAM you can write to. Everything else is read-only ROM, hardware registers, or mirrors.

### Why Zero Page is Special

The 6502 has two main addressing modes for memory:

**Absolute addressing:** 3-byte instruction specifying full 16-bit address.
```asm
LDA $0300               ; 4 cycles
```

**Zero page addressing:** 2-byte instruction with 8-bit address (implies $00XX).
```asm
LDA $00                 ; 3 cycles
```

Zero page instructions are **smaller** (save 1 byte) and **faster** (save 1 cycle). With a 1.79 MHz CPU, every cycle matters. Zero page access happens 25% faster than absolute addressing.

**Real impact:** In a game loop running 60 times per second, accessing player X/Y position from zero page instead of general RAM saves thousands of cycles per frame. That's time for more enemies, better AI, smoother animation.

### Declaring Zero Page Variables

The `.segment "ZEROPAGE"` directive tells ca65 to allocate these variables in zero page:

```asm
.segment "ZEROPAGE"
counter: .res 1             ; Reserve 1 byte
colour:  .res 1             ; Reserve 1 byte
playerX: .res 1
playerY: .res 1
enemyX:  .res 1
enemyY:  .res 1
```

`.res N` reserves N bytes without initializing them. The assembler assigns sequential zero page addresses starting from $00. `counter` gets $00, `colour` gets $01, etc.

**Access them by name:**

```asm
LDA counter             ; Load from $00
INC counter             ; Increment $00
LDA colour
STA $2007               ; Use colour value in PPU write
```

The assembler translates `counter` to `$00` automatically. You write readable code; the assembler generates efficient zero page instructions.

### Initializing Variables

Variables in zero page contain random values at power-on. Initialize them in Reset before use:

```asm
Reset:
    ; ... PPU warmup ...

    LDA #$00
    STA counter             ; counter = 0
    LDA #$12
    STA colour              ; colour = $12 (blue)
```

**Don't assume zero.** Real hardware, flash carts, and some emulators power on with random RAM contents. Always initialize.

### The Stack

The stack at $0100-$01FF handles subroutine calls, interrupts, and temporary storage:

```asm
JSR Subroutine          ; Push return address to stack, jump
; ...
RTS                     ; Pull return address, return
```

**Push/pull manually:**

```asm
PHA                     ; Push A to stack
TXA
PHA                     ; Push X (via A)
; ... do work ...
PLA
TAX                     ; Pull X
PLA                     ; Pull A
```

The stack grows downward. Each push decrements SP; each pull increments SP. Stack overflow (too many pushes) wraps to $01FF and corrupts RAM. **Avoid deep recursion** and balance pushes with pulls.

### OAM Buffer

$0200-$02FF is conventionally reserved for the OAM (Object Attribute Memory) buffer—sprite data copied to the PPU via DMA. This is **convention**, not hardware requirement, but every NES tutorial and library uses this location.

```asm
; Sprite 0 at $0200-$0203
LDA #$80
STA $0200               ; Y position
LDA #$00
STA $0201               ; Tile index
LDA #$00
STA $0202               ; Attributes
LDA #$80
STA $0203               ; X position
```

Later lessons cover sprites. For now, know that $0200-$02FF is reserved—don't use it for general variables.

### General Purpose RAM

$0300-$07FF (1280 bytes) stores game state: levels, enemy data, buffers, temporary calculations.

```asm
.segment "BSS"
levelData: .res 256     ; 256 bytes for level tiles
enemyList: .res 128     ; 16 enemies × 8 bytes each
scoreBuffer: .res 16    ; Score display buffer
```

`.segment "BSS"` places variables outside zero page. Slower access (4 cycles instead of 3) but plenty of space for large arrays and buffers.

**When to use BSS vs ZEROPAGE:**

- **Zero page:** Frequently accessed variables (player position, frame counter, temporary calculations)
- **BSS:** Large arrays, level data, infrequently accessed state

### PRG-ROM

$8000-$FFFF contains your program code. On NROM (mapper 0), this is 32KB of read-only cartridge ROM. Code, lookup tables, graphics data, text—all live here.

```asm
.segment "CODE"
Reset:
    ; Code here is at $8000+ in ROM
```

You can read from ROM but not write to it. Constants and lookup tables:

```asm
.segment "RODATA"
ColourTable:
    .byte $0F, $12, $16, $27, $29, $1A, $21, $30
```

```asm
LDX #$03
LDA ColourTable,X       ; Load 4th colour from table
```

### Memory Access Patterns

**Fastest to slowest:**

1. **Immediate:** `LDA #$12` (2 cycles) - loads constant
2. **Zero page:** `LDA $00` (3 cycles) - loads from $00-$FF
3. **Absolute:** `LDA $0300` (4 cycles) - loads from any address
4. **Indexed:** `LDA $0300,X` (4-5 cycles) - loads from address + X

Choose zero page for variables accessed in inner loops. Use absolute addressing for less critical data.

## The INC Instruction

```asm
Forever:
    INC counter
    JMP Forever
```

`INC` increments a memory location directly—no need to load into A, increment, and store back:

```asm
; Slow way
LDA counter
CLC
ADC #$01
STA counter

; Fast way
INC counter
```

**INC** modifies memory in place (5 cycles for zero page). Supports zero page and absolute addressing, not immediate (can't `INC #$12`—that doesn't make sense).

**Variants:**

- `INC addr` - increment memory
- `INX` - increment X register
- `INY` - increment Y register
- `DEC addr` - decrement memory
- `DEX` - decrement X register
- `DEY` - decrement Y register

## Memory-Mapped Hardware

Addresses $2000-$2007 (PPU) and $4000-$4017 (APU/IO) aren't RAM—they're hardware registers. Writing to them controls hardware; reading from them reports hardware state.

**Example: PPU registers**

```asm
STA $2006               ; Write to PPU address register (hardware)
LDA $2002               ; Read PPU status (hardware reports VBlank flag)
```

This is called **memory-mapped I/O**. The 6502 has no special I/O instructions—everything uses LDA/STA. Hardware appears as memory locations.

**RAM mirrors:** $0800-$1FFF mirrors $0000-$07FF. Writing to $0800 is the same as writing to $0000. This exists because the NES only decodes 11 address bits for RAM, so the high bits are ignored. **Use $0000-$07FF**—mirrors waste address space and confuse debugging.

## Quick Reference: NES Memory

### Memory Map

| Address Range | Purpose | Access |
|---------------|---------|--------|
| $0000-$00FF | Zero page | Fast RAM (3 cycles) |
| $0100-$01FF | Stack | RAM |
| $0200-$02FF | OAM buffer | RAM (conventional) |
| $0300-$07FF | General RAM | Slower RAM (4 cycles) |
| $2000-$2007 | PPU registers | Hardware |
| $4000-$4017 | APU/IO registers | Hardware |
| $8000-$FFFF | PRG-ROM | Read-only code |

### 6502 Registers

| Register | Purpose |
|----------|---------|
| A | Accumulator (arithmetic/logic) |
| X | Index register |
| Y | Index register |
| SP | Stack pointer ($0100-$01FF) |
| PC | Program counter |
| P | Status flags (NVBDIZC) |

### Variable Declaration

```asm
.segment "ZEROPAGE"
varName: .res 1             ; 1 byte in zero page

.segment "BSS"
arrayName: .res 256         ; 256 bytes in general RAM

.segment "RODATA"
tableData: .byte 1,2,3,4    ; Read-only data in ROM
```

### Memory Instructions

| Instruction | Example | Cycles | Purpose |
|-------------|---------|--------|---------|
| LDA | `LDA #$12` | 2 | Load A (immediate) |
| LDA | `LDA $00` | 3 | Load A (zero page) |
| LDA | `LDA $0300` | 4 | Load A (absolute) |
| STA | `STA $00` | 3 | Store A (zero page) |
| INC | `INC $00` | 5 | Increment memory |
| DEC | `DEC $00` | 5 | Decrement memory |

- **6502 CPU architecture**—A, X, Y registers, minimal internal state

- **Zero page advantages**—faster access (3 vs 4 cycles), smaller code
- **Variable declaration**—`.segment "ZEROPAGE"` and `.res` directives
- **Memory-mapped I/O**—hardware registers appear as memory addresses
- **Stack usage**—$0100-$01FF for subroutines and temporary storage
- **OAM buffer convention**—$0200-$02FF reserved for sprite data
- **PRG-ROM**—$8000-$FFFF holds read-only code and data
