The NES displays backgrounds using a 32×30 grid of tiles called the nametable. Each byte in the nametable selects which 8×8 tile from the pattern table appears at that position. Understanding nametable addressing, writing tiles efficiently, and using the attribute table for palette selection is essential to creating game graphics.

Previous lessons loaded palettes and created tile graphics. This lesson shows how to assemble tiles into visible backgrounds by writing to nametable memory at $2000-$23BF.

## The One-Minute Tour

- **Nametable**—32 columns × 30 rows = 960 tiles at $2000-$23BF
- **Each byte**—tile index (0-255) selecting pattern table tile
- **Addressing formula**—Address = $2000 + (row × 32) + column
- **PPUDATA auto-increment**—write consecutive tiles efficiently
- **Attribute table**—$23C0-$23FF assigns palettes to 16×16 pixel areas
- **4 nametables**—$2000, $2400, $2800, $2C00 (mirroring depends on cartridge)
- **Visible area**—32×30 tiles = 256×240 pixels

## Your First Nametable

Create `nametable.asm`:

```nasm
.segment "HEADER"
    .byte "NES", $1A
    .byte 2
    .byte 1
    .byte $01, $00

.segment "CODE"
Reset:
    SEI
    CLD
    BIT $2002
:   BIT $2002
    BPL :-
:   BIT $2002
    BPL :-
    LDX #$FF
    TXS

    ; Load palettes
    LDA #$3F
    STA $2006
    LDA #$00
    STA $2006
    LDA #$0F
    STA $2007
    LDA #$00
    STA $2007
    LDA #$30
    STA $2007
    LDA #$10
    STA $2007

    ; Write tiles to nametable
    LDA #$20
    STA $2006
    LDA #$00
    STA $2006

    ; Fill first row with solid tiles (tile $01)
    LDX #$00
FirstRow:
    LDA #$01
    STA $2007
    INX
    CPX #$20                ; 32 tiles per row
    BNE FirstRow

    ; Write tile at row 2, column 2
    LDA #$20
    STA $2006
    LDA #$42                ; Address $2042
    STA $2006
    LDA #$01                ; Solid tile
    STA $2007

    LDA #%10000000
    STA $2000
    LDA #%00001010          ; Show background
    STA $2001

Forever:
    JMP Forever

NMI:
    RTI

IRQ:
    RTI

.segment "VECTORS"
    .word NMI
    .word Reset
    .word IRQ

.segment "CHARS"
    ; Tile $00: Blank
    .byte $00,$00,$00,$00,$00,$00,$00,$00
    .byte $00,$00,$00,$00,$00,$00,$00,$00

    ; Tile $01: Solid block
    .byte $FF,$FF,$FF,$FF,$FF,$FF,$FF,$FF
    .byte $FF,$FF,$FF,$FF,$FF,$FF,$FF,$FF

    .res 510*16, $00
```

**Run this**—the first row fills with white tiles, and one additional tile appears at row 2, column 2.

## How This Works

### Nametable Memory Structure

The nametable starts at $2000 and contains 960 bytes (32×30):

```
$2000-$23BF: Tile indices (960 bytes)
$23C0-$23FF: Attribute table (64 bytes)
```

**Each byte is a tile index:** Value at $2000 selects which tile appears at top-left of screen. Value $00 displays tile $00, value $01 displays tile $01, etc.

**32 columns, 30 rows:** The visible screen is 256 pixels wide (32 tiles × 8 pixels) and 240 pixels tall (30 tiles × 8 pixels).

**Linear layout:** Tiles are stored row by row. First row is $2000-$201F (32 bytes), second row is $2020-$203F, etc.

### Addressing Tiles by Coordinates

To write a tile at row R, column C:

```
Address = $2000 + (R × 32) + C
```

**Example: Row 0, column 0** (top-left)
```
Address = $2000 + (0 × 32) + 0 = $2000
```

**Example: Row 0, column 31** (top-right)
```
Address = $2000 + (0 × 32) + 31 = $2000 + 31 = $201F
```

**Example: Row 1, column 0** (second row, left edge)
```
Address = $2000 + (1 × 32) + 0 = $2000 + 32 = $2020
```

**Example: Row 5, column 10**
```
Address = $2000 + (5 × 32) + 10
      = $2000 + 160 + 10
      = $2000 + 170
      = $20AA
```

**Example: Row 29, column 31** (bottom-right, last tile)
```
Address = $2000 + (29 × 32) + 31
      = $2000 + 928 + 31
      = $2000 + 959
      = $23BF
```

**Why 32?** Each row contains 32 tiles. Multiplying row by 32 gives the byte offset to the start of that row.

### Writing Specific Tiles

To write tile $01 at row 5, column 10:

```nasm
; Calculate address: $2000 + (5 × 32) + 10 = $20AA
LDA #$20
STA $2006               ; High byte
LDA #$AA
STA $2006               ; Low byte
LDA #$01                ; Tile index
STA $2007               ; Write to nametable
```

**Manual calculation:** Convert row/column to address, then write high byte and low byte to PPUADDR.

**PPUDATA auto-increment:** After writing to $2007, the address increments by 1. Next write goes to $20AB (row 5, column 11).

### Filling Rows Efficiently

To fill an entire row with the same tile, use auto-increment:

```nasm
; Set address to start of row 0
LDA #$20
STA $2006
LDA #$00
STA $2006

; Write 32 tiles (one full row)
LDX #$00
FillRow:
    LDA #$01            ; Tile index
    STA $2007           ; Write and auto-increment
    INX
    CPX #$20            ; 32 tiles ($20 hex = 32 decimal)
    BNE FillRow
```

**How this works:**
- Set PPUADDR to $2000 (start of nametable)
- Write tile index to PPUDATA ($2007)
- Address auto-increments to $2001, $2002, ..., $201F
- Loop 32 times to fill entire row

**Efficient:** One PPUADDR setup, then 32 consecutive writes.

### PPUSTATUS ($2001) Bits

```nasm
LDA #%00001010
STA $2001
```

**Bit 1 (value $02):** Show background in leftmost 8 pixels
**Bit 3 (value $08):** Show background

Value `%00001010` = $0A enables background rendering (bits 1 and 3 set).

**Bit 0:** Greyscale mode (0 = colour)
**Bit 2:** Show sprites in leftmost 8 pixels
**Bit 4:** Show sprites
**Bits 5-7:** Colour emphasis

For now, `%00001010` displays the background. Later lessons enable sprites (bit 4).

### Four Nametables

The PPU has address space for 4 nametables:

```
$2000-$23FF: Nametable 0
$2400-$27FF: Nametable 1
$2800-$2BFF: Nametable 2
$2C00-$2FFF: Nametable 3
```

**But:** The NES has only 2KB of VRAM. Cartridge hardware determines which nametables are real and which are mirrors.

**Horizontal mirroring:** Nametables arranged horizontally (0=2, 1=3). Used for vertical scrolling games.
**Vertical mirroring:** Nametables arranged vertically (0=1, 2=3). Used for horizontal scrolling games.

**Pong uses one nametable:** Static playfield, no scrolling. Write to $2000-$23FF (nametable 0).

**Byte 6 of iNES header** ($01 in this lesson) sets vertical mirroring. Not important for Pong.

### The Attribute Table

After the 960 nametable bytes comes the attribute table at $23C0-$23FF (64 bytes).

**Purpose:** Assigns palettes to tiles. Each attribute byte controls palette selection for a 16×16 pixel area (4×4 tiles).

**Structure:** Each byte divided into 2-bit fields:

```
Bits 0-1: Top-left 2×2 tiles
Bits 2-3: Top-right 2×2 tiles
Bits 4-5: Bottom-left 2×2 tiles
Bits 6-7: Bottom-right 2×2 tiles
```

**Values 0-3:** Select palette 0, 1, 2, or 3 for that quadrant.

**Example:** Attribute byte = `%00011011` (hex $1B)
- Top-left 2×2 tiles: palette 3 (bits 0-1 = 11)
- Top-right 2×2 tiles: palette 2 (bits 2-3 = 10)
- Bottom-left 2×2 tiles: palette 1 (bits 4-5 = 01)
- Bottom-right 2×2 tiles: palette 0 (bits 6-7 = 00)

**Addressing attribute table:**

The screen is divided into 8×8 grid of 4×4 tile areas. Each area has one attribute byte.

```
Attribute address = $23C0 + (row / 4) × 8 + (column / 4)
```

For tiles at row 5, column 10:
```
Attribute address = $23C0 + (5/4) × 8 + (10/4)
                  = $23C0 + 1 × 8 + 2
                  = $23C0 + 10
                  = $23CA
```

**Default:** Attribute table bytes start at $00 (all tiles use palette 0). Next lesson demonstrates setting attribute bytes to use different palettes.

### Clearing the Nametable

To fill entire nametable with blank tiles:

```nasm
; Set address to $2000
LDA #$20
STA $2006
LDA #$00
STA $2006

; Write 960 blank tiles
LDX #$00
LDY #$00
ClearNametable:
    LDA #$00            ; Blank tile
    STA $2007
    INX
    BNE ClearNametable  ; Loop 256 times
    INY
    CPY #$04            ; 4 × 256 = 1024 bytes (covers nametable + attribute)
    BNE ClearNametable
```

**Loops 1024 times:** Clears nametable ($2000-$23BF, 960 bytes) and attribute table ($23C0-$23FF, 64 bytes).

**Nested loops:** X register counts 0-255 (inner loop), Y register counts 0-3 (outer loop). 256 × 4 = 1024 writes.

**Alternative:** Write exactly 960 bytes for nametable, then 64 for attribute table. Above code is simpler (slight overwrite of $23C0-$23FF is harmless).

## Coordinate Addressing Example

Demonstrate writing tiles at calculated addresses:

```nasm
; Write tile at row 10, column 15
; Address = $2000 + (10 × 32) + 15
;         = $2000 + 320 + 15
;         = $2000 + 335
;         = $214F

LDA #$21
STA $2006
LDA #$4F
STA $2006
LDA #$01                ; Solid tile
STA $2007
```

**Manual calculation:** 10 × 32 = 320 (decimal) = $140 (hex). $140 + 15 = $14F. $2000 + $14F = $214F.

**Verification:** Row 10 starts at $2000 + (10 × 32) = $2000 + $140 = $2140. Column 15 adds $0F, giving $214F. Correct!

## Quick Reference: Nametables

### Memory Layout

| Address Range | Contents |
|---------------|----------|
| $2000-$23BF | Nametable 0 tiles (960 bytes, 32×30) |
| $23C0-$23FF | Nametable 0 attribute table (64 bytes) |
| $2400-$27FF | Nametable 1 (or mirror of nametable 0) |
| $2800-$2BFF | Nametable 2 (or mirror of nametable 0) |
| $2C00-$2FFF | Nametable 3 (or mirror of nametable 1) |

### Tile Addressing

```
Address = $2000 + (row × 32) + column

Row 0-29 (30 rows total)
Column 0-31 (32 columns total)
```

### Example Addresses

| Position | Calculation | Address |
|----------|-------------|---------|
| Row 0, Col 0 | $2000 + 0 | $2000 |
| Row 0, Col 31 | $2000 + 31 | $201F |
| Row 1, Col 0 | $2000 + 32 | $2020 |
| Row 15, Col 15 | $2000 + (15×32) + 15 = $2000 + 495 | $21EF |
| Row 29, Col 31 | $2000 + (29×32) + 31 = $2000 + 959 | $23BF |

### Attribute Table

```
Address = $23C0 + (row / 4) × 8 + (column / 4)

Each byte controls 4×4 tiles (16×16 pixels):
  Bits 0-1: Top-left 2×2 tiles
  Bits 2-3: Top-right 2×2 tiles
  Bits 4-5: Bottom-left 2×2 tiles
  Bits 6-7: Bottom-right 2×2 tiles

Value 0-3 selects palette 0-3 for that quadrant.
```

### Filling Patterns

**Fill entire row:**
```nasm
LDA #$20
STA $2006
LDA #$00
STA $2006
LDX #$00
:   LDA #$01
    STA $2007
    INX
    CPX #$20
    BNE :-
```

**Fill entire nametable:**
```nasm
LDA #$20
STA $2006
LDA #$00
STA $2006
LDX #$00
LDY #$00
:   LDA #$00
    STA $2007
    INX
    BNE :-
    INY
    CPY #$04
    BNE :--
```

### PPUMASK ($2001) Bits

| Bit | Mask | Purpose |
|-----|------|---------|
| 0 | $01 | Greyscale mode |
| 1 | $02 | Show background in leftmost 8 pixels |
| 2 | $04 | Show sprites in leftmost 8 pixels |
| 3 | $08 | Show background |
| 4 | $10 | Show sprites |
| 5-7 | $E0 | Colour emphasis (red, green, blue) |

**Common value:** `%00001010` ($0A) = show background (bits 1 and 3)
