## Your Polished Control System

```asm
.segment "ZEROPAGE"
buttons:    .res 1
paddle_y:   .res 1

PADDLE_TOP = 8
PADDLE_BOTTOM = 216
PADDLE_SPEED = 3

.segment "CODE"
MainLoop:
:   LDA nmi_ready
    BEQ :-
    LDA #$00
    STA nmi_ready

    JSR ReadController
    JSR UpdatePaddle
    JSR UpdateOAM
    JMP MainLoop

UpdatePaddle:
    ; Save original position
    LDA paddle_y
    PHA

    ; Handle Up button
    LDA buttons
    AND #%00001000
    BEQ :+
    LDA paddle_y
    SEC
    SBC #PADDLE_SPEED
    STA paddle_y

    ; Handle Down button
:   LDA buttons
    AND #%00000100
    BEQ :+
    LDA paddle_y
    CLC
    ADC #PADDLE_SPEED
    STA paddle_y

    ; Check for Up+Down conflict
:   LDA buttons
    AND #%00001100   ; Mask both Up and Down
    CMP #%00001100   ; Both set?
    BNE :+
    ; Conflict detected - restore original position
    PLA
    STA paddle_y
    JMP :++

    ; No conflict - apply boundaries
:   PLA              ; Discard saved position

    ; Top boundary
    LDA paddle_y
    CMP #PADDLE_TOP
    BCS :+
    LDA #PADDLE_TOP
    STA paddle_y

    ; Bottom boundary
:   LDA paddle_y
    CMP #PADDLE_BOTTOM
    BCC :+
    LDA #PADDLE_BOTTOM
    STA paddle_y

:   RTS
```

**Run this**—paddle handles all inputs cleanly, including edge cases!

## How This Works

### The Save/Restore Pattern

Save position before processing input, restore if conflict detected:

```asm
; Save original position on stack
LDA paddle_y
PHA              ; Push A to stack

; Process input (might move up, down, or both)
; [Input handling code]

; Check for conflict
LDA buttons
AND #%00001100   ; Both Up and Down bits
CMP #%00001100   ; Both set?
BNE no_conflict

; Conflict - restore original
PLA              ; Pull from stack
STA paddle_y
JMP done

no_conflict:
PLA              ; Discard saved value (no longer needed)
; [Boundary clamping]
done:
```

**Why save/restore?** If both Up and Down pressed, we've already modified paddle_y twice. Restoring original position makes net movement = 0 (no movement).

**Stack operations:**
- PHA: Push A register onto stack (store for later)
- PLA: Pull from stack into A register (retrieve stored value)
- Stack grows downward from $01FF

### Conflict Detection

Detect when both Up and Down pressed simultaneously:

```asm
LDA buttons
AND #%00001100   ; Mask bits 3 and 2 (Up and Down)
CMP #%00001100   ; Compare to both bits set
BEQ both_pressed ; Branch if both pressed
```

**Bit positions:**
- Up = bit 3 = %00001000
- Down = bit 2 = %00000100
- Both = %00001100

**Why CMP not BNE after AND?** AND gives us masked bits. CMP checks if result matches "both bits set" pattern. More explicit than just checking non-zero.

### Alternative: Priority System

Instead of save/restore, could prioritize one direction:

```asm
; Up takes priority
LDA buttons
AND #%00001000   ; Check Up first
BNE handle_up
; Only check Down if Up not pressed
LDA buttons
AND #%00000100
BEQ no_input
; Handle Down
```

**Trade-offs:**
- Save/restore: Neutral (no movement if both pressed)
- Priority: Predictable (Up always wins)
- For Pong: Save/restore feels more natural

### Comprehensive Boundary Checking

Apply boundaries AFTER conflict resolution:

```asm
; Discard saved position (no conflict)
PLA

; Check top
LDA paddle_y
CMP #PADDLE_TOP
BCS :+           ; Branch if >= top (in bounds)
LDA #PADDLE_TOP
STA paddle_y

; Check bottom
: LDA paddle_y
CMP #PADDLE_BOTTOM
BCC :+           ; Branch if < bottom (in bounds)
LDA #PADDLE_BOTTOM
STA paddle_y
```

**Why after conflict check?** Conflict resolution might change paddle_y. Always clamp final position, regardless of how it was calculated.

**Catches all violations:** Even if bug in input code pushes paddle way off-screen, clamping brings it back to valid range.

### Order of Operations Deep Dive

Critical sequence for bug-free behavior:

1. **Save position** (PHA)
2. **Apply Up input** (might change position)
3. **Apply Down input** (might change position again)
4. **Check conflict** (both inputs applied?)
   - If yes: restore saved position (PLA + STA)
   - If no: continue to step 5
5. **Discard saved position** (PLA - not needed anymore)
6. **Clamp top boundary**
7. **Clamp bottom boundary**
8. **Render** (UpdateOAM uses final position)

**Why this works:** Handles every case:
- Up only: applied, clamped
- Down only: applied, clamped
- Neither: position unchanged, clamped (redundant but safe)
- Both: reverted to original, clamped
- Invalid position: clamped regardless of cause

### Stack Management

Stack pointer starts at $01FF, grows downward. Each PHA decrements stack pointer:

```
Initial: SP = $01FF
PHA:     SP = $01FE, [$01FF] = A
PHA:     SP = $01FD, [$01FE] = A
PLA:     A = [$01FE], SP = $01FE
PLA:     A = [$01FF], SP = $01FF
```

**Balanced stack:** Every PHA must have matching PLA (eventually). Unbalanced stack corrupts return addresses → crash.

**Our code:** Single PHA, guaranteed single PLA (either in conflict branch or no-conflict branch). Stack always balanced before RTS.
