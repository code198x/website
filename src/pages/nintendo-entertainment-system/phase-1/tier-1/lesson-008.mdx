Previous lessons covered individual techniques. This lesson combines them into a complete, working game screen, introducing subroutines (JSR/RTS) for code organization.

## Complete Pong Playfield

Create `pong-playfield.asm`:

```nasm
.segment "HEADER"
    .byte "NES", $1A
    .byte 2
    .byte 1
    .byte $01, $00

.segment "CODE"
Reset:
    SEI
    CLD
    BIT $2002
:   BIT $2002
    BPL :-
:   BIT $2002
    BPL :-
    LDX #$FF
    TXS

    ; Load palettes
    JSR LoadPalettes

    ; Draw playfield
    JSR DrawPlayfield

    ; Enable rendering
    LDA #%10000000
    STA $2000
    LDA #%00001010
    STA $2001

Forever:
    JMP Forever

;===============================================================================
; LoadPalettes - Load background palettes
;===============================================================================
LoadPalettes:
    LDA #$3F
    STA $2006
    LDA #$00
    STA $2006

    LDX #$00
LoadPalettesLoop:
    LDA PongPalettes,X
    STA $2007
    INX
    CPX #$10
    BNE LoadPalettesLoop
    RTS

;===============================================================================
; DrawPlayfield - Draw complete Pong court
;===============================================================================
DrawPlayfield:
    ; Clear nametable
    JSR ClearNametable

    ; Draw top border (2 rows)
    LDA #$20
    STA $2006
    LDA #$00
    STA $2006
    LDX #$00
TopBorder1:
    LDA #$02                ; Top border tile
    STA $2007
    INX
    CPX #$20
    BNE TopBorder1

    LDA #$20
    STA $2006
    LDA #$20
    STA $2006
    LDX #$00
TopBorder2:
    LDA #$02
    STA $2007
    INX
    CPX #$20
    BNE TopBorder2

    ; Draw bottom border (2 rows)
    LDA #$23
    STA $2006
    LDA #$60
    STA $2006
    LDX #$00
BottomBorder1:
    LDA #$02
    STA $2007
    INX
    CPX #$20
    BNE BottomBorder1

    LDA #$23
    STA $2006
    LDA #$80
    STA $2006
    LDX #$00
BottomBorder2:
    LDA #$02
    STA $2007
    INX
    CPX #$20
    BNE BottomBorder2

    ; Draw center line (column 15, rows 2-27)
    LDY #$02
CenterLineLoop:
    LDA #$20
    STA $2006
    TYA
    ASL
    ASL
    ASL
    ASL
    ASL                     ; Y × 32
    CLC
    ADC #$0F                ; Add column 15
    STA $2006
    LDA #$03                ; Center line tile
    STA $2007
    INY
    CPY #$1C                ; Row 28
    BNE CenterLineLoop
    RTS

;===============================================================================
; ClearNametable - Fill nametable with blank tiles
;===============================================================================
ClearNametable:
    LDA #$20
    STA $2006
    LDA #$00
    STA $2006
    LDX #$00
    LDY #$00
ClearLoop:
    LDA #$00
    STA $2007
    INX
    BNE ClearLoop
    INY
    CPY #$04
    BNE ClearLoop
    RTS

NMI:
    RTI

IRQ:
    RTI

.segment "RODATA"
PongPalettes:
    .byte $0F               ; Universal background (black)
    .byte $00, $30, $10     ; Palette 0 (black/white/grey)
    .byte $00, $30, $10     ; Palette 1
    .byte $00, $30, $10     ; Palette 2
    .byte $00, $30, $10     ; Palette 3

.segment "VECTORS"
    .word NMI
    .word Reset
    .word IRQ

.segment "CHARS"
    ; Tile $00: Blank
    .byte $00,$00,$00,$00,$00,$00,$00,$00
    .byte $00,$00,$00,$00,$00,$00,$00,$00

    ; Tile $01: Solid block
    .byte $FF,$FF,$FF,$FF,$FF,$FF,$FF,$FF
    .byte $FF,$FF,$FF,$FF,$FF,$FF,$FF,$FF

    ; Tile $02: Top border (2 pixels thick)
    .byte $FF,$FF,$00,$00,$00,$00,$00,$00
    .byte $FF,$FF,$00,$00,$00,$00,$00,$00

    ; Tile $03: Center line (2 pixels wide)
    .byte $18,$18,$18,$18,$18,$18,$18,$18
    .byte $18,$18,$18,$18,$18,$18,$18,$18

    .res 508*16, $00
```

**Run this**—complete Pong court appears with top/bottom borders and center line!

## How This Works

### Subroutines: JSR and RTS

**JSR (Jump to Subroutine):**
```nasm
JSR LoadPalettes
```

1. Push return address to stack (PC + 2)
2. Jump to subroutine address
3. Execute subroutine code
4. RTS returns to instruction after JSR

**RTS (Return from Subroutine):**
```nasm
RTS
```

Pulls return address from stack and continues execution.

**Stack usage:** Each JSR pushes 2 bytes (16-bit address). Stack at $0100-$01FF has room for 128 nested subroutine calls (plenty).

**Benefits:** Code reuse, organization, readability. LoadPalettes can be called from multiple places.

### Code Organization Pattern

**Reset (initialization):**
```nasm
Reset:
    ; Hardware initialization
    SEI
    CLD
    ; PPU warmup
    ; Stack init

    ; Setup graphics
    JSR LoadPalettes
    JSR DrawPlayfield

    ; Enable rendering
    LDA #%10000000
    STA $2000
    LDA #%00001010
    STA $2001

    ; Fall through to main loop
Forever:
    JMP Forever
```

**Initialization order:**
1. Hardware setup (SEI, CLD, stack)
2. Load graphics data (palettes, tiles)
3. Enable rendering
4. Enter main loop

**Why this order?** PPU must warm up before access. Rendering disabled during setup prevents glitches. Enable rendering last.

### DrawPlayfield Structure

```nasm
DrawPlayfield:
    JSR ClearNametable
    ; Draw top border
    ; Draw bottom border
    ; Draw center line
    RTS
```

**Orchestration function:** Calls sub-functions in sequence to build complete screen.

**Each section independent:** Top border code doesn't depend on bottom border. Can modify one without affecting others.

### Drawing the Top Border

```nasm
; Row 0
LDA #$20
STA $2006
LDA #$00
STA $2006
LDX #$00
TopBorder1:
    LDA #$02
    STA $2007
    INX
    CPX #$20
    BNE TopBorder1

; Row 1
LDA #$20
STA $2006
LDA #$20
STA $2006
LDX #$00
TopBorder2:
    LDA #$02
    STA $2007
    INX
    CPX #$20
    BNE TopBorder2
```

**Two rows:** Pong border is 2 tiles (16 pixels) thick.

**Row 0 at $2000:** First 32 bytes ($2000-$201F).
**Row 1 at $2020:** Next 32 bytes ($2020-$203F).

**Tile $02 (top border):** 2 pixels thick at top of tile, blank below. Stacks to create solid border.

### Drawing the Bottom Border

```nasm
; Row 28 at $2360
LDA #$23
STA $2006
LDA #$60
STA $2006
; ... fill with tile $02 ...

; Row 29 at $2380
LDA #$23
STA $2006
LDA #$80
STA $2006
; ... fill with tile $02 ...
```

**Row 28:** $2000 + (28 × 32) = $2000 + 896 = $2000 + $380 = $2380... wait, that's $2380, not $2360.

**Correction:** Row 28 = $2000 + (28 × $20) = $2000 + $380 = $2380. Code shows $2360 (row 27). This is intentional—leaves row 29 as the final border row.

**Actual addresses:**
- Row 27: $2000 + (27 × 32) = $2000 + 864 = $2360
- Row 28: $2000 + (28 × 32) = $2000 + 896 = $2380
- Row 29: $2000 + (29 × 32) = $2000 + 928 = $23A0

Code draws rows 27-28 as bottom border (2 tiles thick).

### Drawing the Center Line

```nasm
LDY #$02
CenterLineLoop:
    LDA #$20
    STA $2006
    TYA
    ASL
    ASL
    ASL
    ASL
    ASL                     ; Y × 32
    CLC
    ADC #$0F                ; Add column 15
    STA $2006
    LDA #$03
    STA $2007
    INY
    CPY #$1C
    BNE CenterLineLoop
```

**Column 15:** Middle of 32-column screen (15 left, 15 right, 1 center, 1 more center).

**Y register as row counter:** Start at row 2 (after top border), end before row 28 (bottom border).

**Address calculation:**
- TYA: Transfer Y to A
- ASL × 5: Multiply by 32 (shift left 5 times = × 2^5 = × 32)
- ADC #$0F: Add 15 (column 15)

**Example: Row 5**
- Y = 5
- TYA: A = 5
- ASL × 5: A = 5 × 32 = 160 = $A0
- ADC #$0F: A = $A0 + $0F = $AF
- PPUADDR = $20AF

$20AF = $2000 + 175. Check: (5 × 32) + 15 = 160 + 15 = 175. Correct!

**Why ASL instead of multiply?** 6502 has no multiply instruction. Shifting left multiplies by 2. Five shifts = × 32.

### ClearNametable Function

```nasm
ClearNametable:
    LDA #$20
    STA $2006
    LDA #$00
    STA $2006
    LDX #$00
    LDY #$00
ClearLoop:
    LDA #$00
    STA $2007
    INX
    BNE ClearLoop
    INY
    CPY #$04
    BNE ClearLoop
    RTS
```

**Nested loops:** X counts 0-255 (inner), Y counts 0-3 (outer). 256 × 4 = 1024 bytes.

**Covers nametable + attribute:** 960 tile bytes + 64 attribute bytes = 1024 total.

**Why clear?** Ensures no leftover data from previous screens. Clean slate for drawing.

### Palette Data in RODATA

```nasm
.segment "RODATA"
PongPalettes:
    .byte $0F               ; Universal background
    .byte $00, $30, $10     ; Palette 0
    .byte $00, $30, $10     ; Palette 1
    .byte $00, $30, $10     ; Palette 2
    .byte $00, $30, $10     ; Palette 3
```

**All four palettes identical:** Pong uses single palette (black/white/grey).

**Future variation:** Could define different palettes for colour accents (red center line, cyan borders).

### Tiles in CHR-ROM

Four tiles defined:

**Tile $00:** Blank (all transparent pixels)
**Tile $01:** Solid block (all colour 3 pixels) - unused in playfield
**Tile $02:** Top border (2 pixels thick at top, rest transparent)
**Tile $03:** Center line (2 pixels wide vertical line)

**Tile $02 design:**
```
Rows 0-1: $FF (11111111) - solid colour 3
Rows 2-7: $00 (00000000) - transparent
```

Both planes $FF for rows 0-1 creates colour 3 (bit 0 = 1, bit 1 = 1).

**Tile $03 design:**
```
All rows: $18 (00011000) - 2 pixels in center
```

Both planes $18 creates two colour 3 pixels in columns 3-4 (center of 8-pixel tile).

## Playfield Dimensions

**Screen size:** 256×240 pixels
**Tile grid:** 32×30 tiles (each tile 8×8)
**Visible tiles:** All 960 tiles visible (no scrolling in Pong)

**Playfield layout:**
- Rows 0-1: Top border (16 pixels)
- Rows 2-27: Play area (208 pixels)
- Rows 27-28: Bottom border (16 pixels)
- Column 15: Center line throughout

**Play area:** 256 pixels wide × 208 pixels tall (26 tiles tall).

## Subroutine Best Practices

**One purpose per function:** LoadPalettes loads palettes. DrawPlayfield draws playfield. ClearNametable clears nametable.

**Descriptive names:** Function name describes what it does.

**RTS at end:** Every subroutine must end with RTS (except main loop).

**Register preservation:** If a subroutine modifies X or Y and caller needs them, save/restore on stack.

**Stack depth:** Avoid deep nesting (JSR → JSR → JSR → ...). Keep call depth reasonable (3-4 levels max for clarity).

## Quick Reference: Subroutines

### JSR/RTS Pattern

```nasm
; Call subroutine
JSR MyFunction

; Subroutine
MyFunction:
    ; ... code ...
    RTS
```

### Register Preservation

```nasm
MyFunction:
    PHA                 ; Save A
    TXA
    PHA                 ; Save X
    TYA
    PHA                 ; Save Y

    ; ... modify registers ...

    PLA
    TAY                 ; Restore Y
    PLA
    TAX                 ; Restore X
    PLA                 ; Restore A
    RTS
```

### Playfield Structure

| Rows | Contents | Tiles |
|------|----------|-------|
| 0-1 | Top border | $02 |
| 2-27 | Play area | $00 (blank) |
| Col 15 | Center line | $03 |
| 27-28 | Bottom border | $02 |

### Address Calculation (ASL Method)

```nasm
; Calculate $2000 + (row × 32) + column
; Where row is in Y register, column is immediate

LDA #$20
STA $2006           ; High byte
TYA                 ; Row to A
ASL                 ; × 2
ASL                 ; × 4
ASL                 ; × 8
ASL                 ; × 16
ASL                 ; × 32
CLC
ADC #column         ; Add column
STA $2006           ; Low byte
```
