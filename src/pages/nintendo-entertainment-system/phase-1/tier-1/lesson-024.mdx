Paddle collision works—but edge cases create bugs. Ball can hit both paddles same frame, get stuck oscillating in paddle, or trigger collision while moving away. This synthesis lesson implements collision cooldown (prevents re-triggering for N frames), direction checks (ignore collision if ball moving away), priority system (only one paddle per frame), and extra clearance. The collision system is now bulletproof.

This completes the Paddle-Ball Collision arc—physics is feature-complete!

## The One-Minute Tour

- **Collision cooldown**—Prevent re-collision for 10 frames after hit
- **Direction check**—Only collide if ball moving *toward* paddle
- **Priority system**—Check paddle 1 first, paddle 2 only if P1 missed
- **Extra clearance**—Snap ball 2 pixels beyond paddle (guaranteed escape)
- **Stuck ball prevention**—Multiple safety layers
- **Double-hit protection**—Ball can't hit both paddles same frame
- **Complete synthesis**—All L21-23 features plus edge case handling

## Your Complete Collision System

```asm
.segment "ZEROPAGE"
collision_cooldown: .res 1  ; Frames until collision re-enabled

COOLDOWN_FRAMES = 10        ; No collision for 10 frames after hit

.segment "CODE"
; Complete collision check with all refinements
CheckAllCollisions:
    ; Skip collision if in cooldown
    LDA collision_cooldown
    BEQ :+                  ; Branch if cooldown expired

    ; Decrement cooldown
    DEC collision_cooldown
    RTS                     ; Skip collision checks this frame

    ; Check paddle 1 collision
:   JSR CheckBallPaddle1
    BNE @paddle1_hit        ; Branch if collision detected

    ; Check paddle 2 collision (only if paddle 1 didn't hit)
    JSR CheckBallPaddle2
    BNE @paddle2_hit

    RTS                     ; No collisions

@paddle1_hit:
    ; Ensure ball is moving toward paddle
    LDA ball_vx
    BMI :+                  ; Branch if already moving left (away)

    ; Ball moving right (toward paddle 1) - valid hit
    JSR HandlePaddle1Complete
    LDA #COOLDOWN_FRAMES
    STA collision_cooldown
    RTS

    ; Ball moving away - ignore collision
:   RTS

@paddle2_hit:
    ; Ensure ball is moving toward paddle
    LDA ball_vx
    BPL :+                  ; Branch if already moving right (away)

    ; Ball moving left (toward paddle 2) - valid hit
    JSR HandlePaddle2Complete
    LDA #COOLDOWN_FRAMES
    STA collision_cooldown
    RTS

:   RTS

; Complete paddle 1 hit handler (all features from L21-23)
HandlePaddle1Complete:
    ; 1. Calculate hit angle
    JSR CalculateHitAngle
    STA temp

    ; 2. Add paddle momentum
    LDA temp
    CLC
    ADC paddle1_vy
    STA ball_vy

    ; 3. Clamp Y velocity
    JSR ClampBallVY

    ; 4. Reverse X velocity
    JSR NegateBallVX

    ; 5. Speed boost for moving paddle
    LDA paddle1_vy
    BEQ :+
    JSR BoostBallSpeed

    ; 6. Snap ball outside paddle with extra clearance
:   LDA paddle1_x
    CLC
    ADC #PADDLE_WIDTH
    CLC
    ADC #2                  ; Extra 2-pixel clearance
    STA ball_x

    RTS

; Complete paddle 2 hit handler
HandlePaddle2Complete:
    JSR CalculateHitAngle
    STA temp

    LDA temp
    CLC
    ADC paddle2_vy
    STA ball_vy

    JSR ClampBallVY
    JSR NegateBallVX

    LDA paddle2_vy
    BEQ :+
    JSR BoostBallSpeed

    ; Snap ball outside paddle 2 (left side)
:   LDA paddle2_x
    SEC
    SBC #BALL_WIDTH
    SEC
    SBC #2                  ; Extra 2-pixel clearance
    STA ball_x

    RTS

; Main game loop integration
MainLoop:
    ; Wait for VBlank
:   LDA nmi_ready
    BEQ :-
    LDA #$00
    STA nmi_ready

    ; Game logic
    JSR ReadControllers
    JSR UpdatePaddle1
    JSR UpdatePaddle2

    ; Collision detection (BEFORE ball movement)
    JSR CheckAllCollisions

    ; Ball physics
    JSR UpdateBallPhysics
    JSR CheckBallBoundaries

    ; Update sprites
    JSR UpdatePaddleSprites
    JSR UpdateBallSprite

    JMP MainLoop
```

## How This Works

### Collision Cooldown

Prevent re-collision by counting frames:

```asm
; On collision:
LDA #COOLDOWN_FRAMES
STA collision_cooldown

; Each frame:
LDA collision_cooldown
BEQ ready               ; 0 = ready for collision
DEC collision_cooldown  ; Count down
RTS                     ; Skip collision check
```

**Why needed?** Ball snapped outside paddle moves back toward it. Without cooldown, triggers collision again next frame.

**Duration:** 10 frames = 1/6 second. Enough time for ball to move clear away.

### Direction Check

Only collide if ball moving toward paddle:

```asm
; Paddle 1 (right side):
LDA ball_vx
BMI ignore          ; Moving left (away), ignore
; Moving right (toward), valid collision

; Paddle 2 (left side):
LDA ball_vx
BPL ignore          ; Moving right (away), ignore
; Moving left (toward), valid collision
```

**Why needed?** Ball overlaps paddle but moving away = already bounced. Checking again causes double-bounce.

### Priority System

Check paddles in order, stop at first hit:

```asm
JSR CheckBallPaddle1
BNE paddle1_hit     ; If hit, handle and exit

; Only check paddle 2 if paddle 1 missed
JSR CheckBallPaddle2
BNE paddle2_hit
```

**Why needed?** Ball can technically overlap both paddles in corner case. Only one should respond.

### Extra Clearance

Add 2 pixels to snap distance:

```asm
LDA paddle1_x
ADC #PADDLE_WIDTH
ADC #2              ; Extra clearance
STA ball_x
```

**Why needed?** Exact edge placement might still overlap due to rounding. Extra clearance guarantees escape.

### Edge Cases Handled

**1. Corner Collision:**
- Ball approaches corner where paddles might meet
- Priority system: Paddle 1 checked first
- Only one collision possible per frame

**2. Ball Stuck in Paddle:**
- Cooldown prevents re-triggering
- Extra clearance ensures escape
- Direction check rejects invalid collisions

**3. Double-Hit:**
- Cooldown prevents both paddles colliding same frame
- Ball must escape one paddle before hitting another

**4. Fast Ball Tunneling:**
- Position snapping catches ball even at max speed
- Ball placed outside paddle regardless of velocity

## Common Pitfalls

**No cooldown:**
- Ball bounces multiple times from single hit
- Solution: Always set cooldown after collision

**Checking collision after movement:**
- Ball tunnels through paddle
- Solution: Check before UpdateBallPhysics

**No clearance:**
- Ball still overlaps after snap
- Solution: Add 2-pixel clearance to snap distance

**Both paddles checked every frame:**
- Wastes cycles, creates conflicts
- Solution: Use priority system (stop at first hit)
