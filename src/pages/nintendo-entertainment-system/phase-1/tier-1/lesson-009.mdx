The NES sprite system provides 64 hardware-accelerated objects independent from the background. Sprites can be 8×8 or 8×16 pixels, use their own palettes, and move freely without redrawing backgrounds. This lesson introduces sprite graphics by creating paddle and ball tiles in CHR-ROM.

Previous lessons built the static playfield. This lesson adds moveable game objects using the NES sprite system.

## The One-Minute Tour

- **64 hardware sprites**—rendered independently from background
- **8×8 or 8×16 pixels**—PPUCTRL bit 5 selects size
- **Pattern table 1**—sprites use $1000-$1FFF (second 4KB bank)
- **Colour 0 is transparent**—background shows through
- **Sprite palettes**—$3F10-$3F1F, separate from background
- **8×16 mode**—two tiles form vertical sprite (even + odd tile numbers)
- **Hardware limit**—8 sprites per scanline max

## Your First Sprite Graphics

Add to CHR-ROM segment (after background tiles):

```nasm
.segment "CHARS"
    ; Background tiles (pattern table 0)
    ; [Previous border and line tiles]
    .res 256*16, $00

    ; Sprite tiles (pattern table 1)
    ; Tile $00: Paddle top half
    .byte $3C,$3C,$3C,$3C,$3C,$3C,$3C,$3C
    .byte $3C,$3C,$3C,$3C,$3C,$3C,$3C,$3C

    ; Tile $01: Paddle bottom half
    .byte $3C,$3C,$3C,$3C,$3C,$3C,$3C,$3C
    .byte $3C,$3C,$3C,$3C,$3C,$3C,$3C,$3C

    ; Tile $02: Ball
    .byte $00,$18,$3C,$7E,$7E,$3C,$18,$00
    .byte $00,$18,$3C,$7E,$7E,$3C,$18,$00

    .res 253*16, $00
```

This creates paddle (8×16) and ball (8×8) graphics.

## How This Works

### NES Sprite System

The NES PPU can render 64 sprites simultaneously. Each sprite:
- Uses one or two 8×8 tiles from pattern table 1
- Has independent X/Y position (0-255, 0-239)
- Selects from 4 sprite palettes
- Can flip horizontally/vertically
- Renders in front of or behind background

**Hardware rendering:** PPU draws sprites automatically. CPU just updates sprite data (position, tile, attributes) each frame.

**Transparency:** Pixel value 0 in sprite tiles shows background through the sprite. Only colours 1-3 are visible.

### Pattern Table 1 for Sprites

CHR-ROM has two 4KB pattern tables:
- $0000-$0FFF: Pattern table 0 (background tiles)
- $1000-$1FFF: Pattern table 1 (sprite tiles)

**PPUCTRL bit 3** selects which table sprites use. Typically: table 0 for background, table 1 for sprites (cleaner organization).

**Same tile format:** Sprites use identical 16-byte, 2-bit encoding as background tiles. Each tile is 8×8 pixels.

### 8×16 Sprite Mode

**PPUCTRL bit 5 = 1:** Enables 8×16 sprites. Each sprite uses two consecutive tiles stacked vertically:
- Even tile number = top half
- Odd tile number = bottom half (automatically selected)

**Example:** Specify tile $00 for sprite → PPU draws tile $00 (top) and tile $01 (bottom).

**Why 8×16?** Taller game objects (characters, paddles) with fewer sprite slots. Pong paddles are 8 pixels wide, 16 pixels tall—perfect for 8×16 mode.

### Paddle Tile Design

Paddle needs 4-pixel wide vertical bar:

```
Pixel pattern:
. . 3 3 3 3 . .   (4 pixels wide, centred)
```

**Binary encoding:**
```
Plane 0: 00111100 = $3C
Plane 1: 00111100 = $3C
```

Both planes $3C creates colour 3 pixels in middle 4 columns. Columns 0-1 and 6-7 are colour 0 (transparent).

**Top and bottom halves identical:** Paddle is uniform vertical bar, so tile $00 and tile $01 use same pattern ($3C for all 8 rows).

### Ball Tile Design

Ball needs circular shape in 8×8 pixels:

```
Row 0: . . . . . . . .   $00
Row 1: . . . 3 3 . . .   $18
Row 2: . . 3 3 3 3 . .   $3C
Row 3: . 3 3 3 3 3 3 .   $7E
Row 4: . 3 3 3 3 3 3 .   $7E
Row 5: . . 3 3 3 3 . .   $3C
Row 6: . . . 3 3 . . .   $18
Row 7: . . . . . . . .   $00
```

**Diamond shape:** Creates circular appearance with limited 8×8 resolution. Both planes use same values (colour 3 throughout).

**Symmetry:** Rows mirror vertically for balanced look.

### Sprite Palettes

Sprite palettes are separate from background palettes:
- $3F00-$3F0F: Background palettes
- $3F10-$3F1F: Sprite palettes (4 palettes × 4 colours)

**Same structure:** Each sprite palette has 4 colours (0-3). Colour 0 is transparent (shows background).

**Loading sprite palettes:**
```nasm
LDA #$3F
STA $2006
LDA #$10        ; Start of sprite palettes
STA $2006

; Write 16 bytes (4 palettes)
LDX #$00
:   LDA SpritePalettes,X
    STA $2007
    INX
    CPX #$10
    BNE :-
```

**Typical Pong sprite palette:** Black ($0F) transparent, white ($30) for paddles/ball, grey ($10) for shadows.

## Quick Reference

### Sprite System

| Feature | Details |
|---------|---------|
| Max sprites | 64 total |
| Per scanline | 8 sprites (hardware limit) |
| Sizes | 8×8 or 8×16 (PPUCTRL bit 5) |
| Pattern table | 0 ($0000) or 1 ($1000) selected by PPUCTRL bit 3 |
| Transparency | Colour 0 shows background |

### Pattern Table Layout

```
$0000-$0FFF: Pattern table 0 (256 tiles, typically background)
$1000-$1FFF: Pattern table 1 (256 tiles, typically sprites)
```

### Sprite Palette Memory

```
$3F10: Sprite palette 0, colour 0 (unused, mirrors $3F00)
$3F11-$3F13: Sprite palette 0, colours 1-3
$3F14: Unused (mirrors $3F00)
$3F15-$3F17: Sprite palette 1, colours 1-3
$3F18: Unused (mirrors $3F00)
$3F19-$3F1B: Sprite palette 2, colours 1-3
$3F1C: Unused (mirrors $3F00)
$3F1D-$3F1F: Sprite palette 3, colours 1-3
```

### 8×16 Sprite Mode

- Tile number must be even ($00, $02, $04, ...)
- PPU automatically uses tile+1 for bottom half
- Example: Specify tile $00 → draws $00 (top) + $01 (bottom)
