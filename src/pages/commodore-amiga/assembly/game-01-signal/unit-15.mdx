## What You're Building

Game flow.

A game isn't complete without proper presentation. Players need a title screen to start, gameplay to enjoy, and a game over screen to reflect on their performance. This unit adds a state machine that manages these three states.

By the end of this unit:
- Title screen with "SIGNAL"
- Press fire to start
- Gameplay until game over
- Game over screen with score
- Press fire to return to title

## Game Over Screen

When the player loses their last life, we transition to game over:

```asm
.enter_gameover:
            move.w  #GSTATE_OVER,game_state
            bsr     show_gameover
            bra     mainloop
```

The game over screen overlays "GAME OVER" on the frozen gameplay, letting players see their final score:

```asm
show_gameover:
            ; Draw "GAME OVER" text over the game screen
            lea     screen_plane,a2
            add.l   #120*SCREEN_W+15,a2

            lea     gameover_text,a1
            ; ... draw each letter
```

## State Transitions

The complete flow:

1. **Start**: Game begins in GSTATE_TITLE
2. **Title → Playing**: Fire button triggers init_game
3. **Playing → Game Over**: Last life lost (frog_state = STATE_GAMEOVER)
4. **Game Over → Title**: Fire button returns to title

```
    ┌─────────┐      fire       ┌─────────┐
    │  TITLE  │───────────────►│ PLAYING │
    └─────────┘                 └────┬────┘
         ▲                           │
         │           fire            │ no lives
         │      ┌──────────┐         │
         └──────│GAME OVER │◄────────┘
                └──────────┘
```

## Initialisation Changes

The startup code now shows the title screen instead of jumping straight into gameplay:

```asm
            ; Start at title screen
            move.w  #GSTATE_TITLE,game_state
            bsr     show_title
```

The game only initialises when the player presses fire on the title screen.

## Key Takeaways

- **State machine** separates game flow from game logic
- **High-level states** (title/playing/over) vs animation states (idle/hopping/dying)
- **Edge detection** prevents button bouncing
- **Font extension** reuses digit rendering for letters
- **Overlay text** keeps final score visible on game over
- **Clean transitions** between all states
