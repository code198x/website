# Lesson 009: Sprite Gallery

Build an interactive sprite viewer using the `Bob` command for automatic BOB management. This is the final lesson in the BOB Graphics arc - a synthesis of everything you've learnt!

## The One-Minute Tour

- **Bob command** - Automatic BOB management (vs manual Paste Bob)
- **Multiple BOBs** - Create sprite library with numbered instances
- **Bob Update** - Refresh all BOBs on screen at once
- **Wait Vbl** - Synchronize with vertical blank (50Hz PAL)
- **Interactive control** - Cursor keys and keyboard input
- **Sprite library** - 6 different sprite designs

## Example Programme

Here's a simplified interactive sprite display:

```amos
' Sprite Gallery Demo
Screen Open 0,320,256,32,Lowres
Curs Off: Flash Off: Cls 0

' Create 3 sprites
Ink 2: Bar 0,0 To 15,15
Get Bob 1,0,0 To 16,16: Cls 0

Ink 3: Circle 8,8,7
Get Bob 2,0,0 To 16,16: Cls 0

Ink 4: Box 0,0 To 15,15
Get Bob 3,0,0 To 16,16: Cls 0

' Display with Bob command
current=1
Do
  Cls 0
  Print "Sprite: ";current

  ' Show current sprite
  Bob 1,152,120,current

  ' Refresh
  Bob Update
  Wait Vbl

  ' Check input
  k$=Inkey$
  If k$=" " Then Add current,1
  If current>3 Then current=1
Loop Until k$="q"
```

**Run it:**
1. Load AMOS Professional
2. Load `sprite-gallery.amos`
3. Press F1 to run
4. Use cursor keys to change sprite
5. Press SPACE to cycle
6. Press Q to quit

## Understanding Bob vs Paste Bob

### Paste Bob - Manual Control

```amos
' YOU do everything:
Cls 0                    ' Erase screen
Paste Bob 100,100,1      ' Draw BOB
' No automatic background save
' No collision detection
' No sprite management
```

**Use when:**
- Static display only
- You want complete control
- Simple one-time display
- No sprite interaction needed

### Bob Command - Automatic Management

```amos
' AMOS does everything:
Bob 1,100,100,1          ' Position BOB #1 using image #1
Bob Update               ' AMOS handles: background save, erase, redraw, collisions
```

**Use when:**
- Moving sprites
- Need collision detection
- Multiple BOBs on screen
- Game development
- Interactive graphics

### The Two Numbers

```amos
Bob number,x,y,image
    ↓          ↓
    |          └─ Which graphic to display (1,2,3...)
    └─ Which BOB instance (1,2,3...)
```

**Example:**
```amos
' Create two images
Get Bob 1,0,0 To 16,16    ' Image #1: circle
Get Bob 2,0,0 To 16,16    ' Image #2: square

' Display with Bob command
Bob 1,50,50,1      ' BOB #1 shows image #1 (circle)
Bob 2,100,50,2     ' BOB #2 shows image #2 (square)
Bob 3,150,50,1     ' BOB #3 shows image #1 (circle again!)
Bob Update
```

You can have hundreds of BOB instances, each showing any captured image!

## Understanding Bob Update

### Why Bob Update?

```amos
' Set BOB positions
Bob 1,100,100,1
Bob 2,150,100,2
Bob 3,200,100,3

' Nothing appears yet!

Bob Update          ' NOW they all display at once
```

**What Bob Update does:**
1. Save background where each BOB will appear
2. Erase old BOB positions (restore backgrounds)
3. Draw all BOBs at new positions
4. Update collision data

**Efficiency:** One `Bob Update` refreshes all BOBs. Much faster than updating individually!

### Update Pattern

```amos
Do
  ' 1. Process input / game logic
  If Joyright(0) Then Add x,2
  If Joyleft(0) Then Add x,-2

  ' 2. Update BOB positions
  Bob 1,x,y,1

  ' 3. Refresh display (once per frame)
  Bob Update
  Wait Vbl
Loop
```

**Critical:** Always call `Bob Update` after setting BOB positions, before `Wait Vbl`.

## Understanding Wait Vbl

### Vertical Blank Synchronization

```amos
Wait Vbl           ' Wait for next frame
```

**VBL (Vertical Blank):** The brief period when the display stops drawing and returns to top of screen.

**Why synchronize?**

**Without Wait Vbl (tearing):**
```
Screen updating mid-frame → split image, artifacts
```

**With Wait Vbl (smooth):**
```
Wait for frame end → update during blank → next frame shows complete image
```

### Frame Rate

**PAL (Europe, Australia):**
- 50 frames per second (50Hz)
- Each Wait Vbl = 20 milliseconds
- 256 visible lines

**NTSC (North America, Japan):**
- 60 frames per second (60Hz)
- Each Wait Vbl = 16.7 milliseconds
- 200 visible lines

**Your programme runs at display refresh rate automatically!**

### Timing Pattern

```amos
' Game loop at 50fps (PAL)
Do
  ' Update positions (instant)
  Bob 1,x,y,1

  ' Refresh (instant)
  Bob Update

  ' Wait for next frame (20ms)
  Wait Vbl
Loop
```

**Each loop iteration = exactly one frame.** Perfect for games!

## Understanding Interactive Input

### Inkey$ - Keyboard Detection

```amos
k$=Inkey$

If k$<>"" Then
  ' Key was pressed
  If k$=" " Then Print "Space!"
  If k$="q" Then Exit
End If
```

**Inkey$ returns:**
- Empty string `""` if no key pressed
- Character string if key pressed
- Special keys return ASCII codes:
  - Cursor up: `Chr$(30)`
  - Cursor down: `Chr$(31)`
  - Cursor left: `Chr$(29)`
  - Cursor right: `Chr$(28)`

### Cursor Key Pattern

```amos
k$=Inkey$

If k$=Chr$(28) Then Add x,2      ' Right
If k$=Chr$(29) Then Add x,-2     ' Left
If k$=Chr$(30) Then Add y,-2     ' Up
If k$=Chr$(31) Then Add y,2      ' Down
```

### Input Handling Pattern

```amos
current=1
Do
  ' Get input
  k$=Inkey$

  ' Process input
  If k$=" " Then
    Add current,1
    If current>maxSprites Then current=1
  End If

  If k$="q" or k$="Q" Then Exit

  ' Update display
  Bob 1,x,y,current
  Bob Update
  Wait Vbl
Loop
```

## Programme Structure

### Complete Interactive Gallery

```amos
' 1. INITIALIZE
Screen Open 0,320,256,32,Lowres
Curs Off: Flash Off: Cls 0

' 2. CREATE SPRITE LIBRARY
For i=1 To 6
  DrawSprite[i]
  Get Bob i,0,0 To 16,16
  Cls 0
Next i

' 3. SETUP VARIABLES
current=1
x=152: y=120

' 4. MAIN LOOP
Do
  ' Clear and redraw UI
  Cls 0
  Print "Current: ";current

  ' Display selected sprite
  Bob 1,x,y,current

  ' Gallery thumbnails
  For i=1 To 6
    Bob i+1,i*40,200,i
  Next i

  ' Update display
  Bob Update

  ' Get input
  k$=Inkey$
  ProcessInput[k$]

  ' Synchronize
  Wait Vbl
Loop Until k$="q"
```

## Experiments

### Experiment 1: Animated Sprites

Create animation by cycling through images:

```amos
' Create 4 animation frames
' (different poses/rotations)
Get Bob 1,... ' Frame 1
Get Bob 2,... ' Frame 2
Get Bob 3,... ' Frame 3
Get Bob 4,... ' Frame 4

' Animate
frame=1
Do
  Bob 1,160,120,frame
  Bob Update
  Wait Vbl

  Add frame,1
  If frame>4 Then frame=1
Loop
```

### Experiment 2: Multiple Moving Sprites

Display several BOBs at once:

```amos
' Store positions
Dim x(10),y(10),dx(10),dy(10)

' Initialize
For i=1 To 10
  x(i)=Rnd(304)
  y(i)=Rnd(240)
  dx(i)=Rnd(5)-2
  dy(i)=Rnd(5)-2
Next i

' Animate
Do
  Cls 0
  For i=1 To 10
    Add x(i),dx(i)
    Add y(i),dy(i)

    ' Bounce off edges
    If x(i)<0 or x(i)>304 Then dx(i)=-dx(i)
    If y(i)<0 or y(i)>240 Then dy(i)=-dy(i)

    Bob i,x(i),y(i),1
  Next i

  Bob Update
  Wait Vbl
Loop Until Inkey$<>""
```

### Experiment 3: Collision Detection

Use Bob Col to detect collisions:

```amos
' Player sprite
Bob 1,playerX,playerY,1

' Enemy sprites
For i=2 To 10
  Bob i,enemyX(i),enemyY(i),2
Next i

Bob Update

' Check collisions
collision=Bob Col(1)
If collision>0 Then
  Print "Hit enemy ";collision;"!"
End If
```

**Technical Specifications:**

**Bob Command Performance:**
- Manages up to 64 BOBs efficiently
- Background save/restore automatic
- Hardware collision detection
- Sprite priority system
- Memory managed by AMOS

**VBL Timing:**
- PAL: 50Hz (20ms per frame)
- NTSC: 60Hz (16.7ms per frame)
- Copper interrupt-driven
- Synchronized with display hardware

**Historical Context:**

The Amiga's BOB system (1985) was revolutionary:
- **C64 sprites:** 8 hardware sprites, 24×21 pixels, no background save
- **Atari ST sprites:** Software-based, slow, CPU-intensive
- **Amiga BOBs:** Hardware blitter, unlimited count, automatic management, collision detection

Combined with Wait Vbl synchronization, this enabled smooth 50fps games that looked impossible on other home computers.

## Quick Reference

### Bob Commands

| Command | Purpose | Example |
|---------|---------|---------|
| `Bob n,x,y,img` | Position BOB | `Bob 1,100,100,1` |
| `Bob Update` | Refresh all BOBs | `Bob Update` |
| `Bob Off` | Hide BOB | `Bob Off 1` |
| `Bob Off` (no param) | Hide all BOBs | `Bob Off` |
| `Bob Col(n)` | Check collision | `hit=Bob Col(1)` |

### Timing Commands

| Command | Purpose | Example |
|---------|---------|---------|
| `Wait Vbl` | Wait for vertical blank | `Wait Vbl` |
| `Wait n` | Wait n 50ths of second | `Wait 50` |

### Bob vs Paste Bob

| Feature | Paste Bob | Bob Command |
|---------|-----------|-------------|
| Background save | Manual | Automatic |
| Collision detect | Manual | Built-in |
| Multiple BOBs | Manual tracking | Auto-managed |
| Performance | Direct | Optimized |
| Best for | Static display | Games/animation |

### Main Loop Pattern

```amos
Do
  ' 1. Input
  k$=Inkey$

  ' 2. Logic
  Process_Input
  Update_Positions

  ' 3. Display
  Bob 1,x,y,image
  Bob Update

  ' 4. Sync
  Wait Vbl
Loop
```
