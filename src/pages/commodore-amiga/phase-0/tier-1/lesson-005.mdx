# Lesson 005: Knowledge Master

Menu-driven quiz system with multiple categories, procedure organisation, and persistent high score tracking.

## The One-Minute Tour

- **Menu systems** - Do...Loop with choice input
- **Procedure parameters** - Pass data to procedures
- **High score tracking** - Variable persists across quiz attempts
- **Restore with labels** - Jump to specific data sections
- **Multiple categories** - Separate data banks for different topics
- **Exit statement** - Clean loop termination

## Example Programme

Here's a simplified two-category quiz with high score:

```amos
' Simple Knowledge Master
highscore=0

Do
  Cls 0
  Locate 5,10: Print "KNOWLEDGE MASTER"
  Locate 8,8: Print "1. History"
  Locate 10,8: Print "2. Science"
  Locate 12,8: Print "3. View High Score"
  Locate 14,8: Print "4. Quit"

  Input choice

  If choice=1 Then HistoryQuiz
  If choice=2 Then ScienceQuiz
  If choice=3 Then ShowScore
  If choice=4 Then Exit
Loop

End

Procedure HistoryQuiz
  Restore HistoryData
  QuizCategory["History"]
End Proc

Procedure ScienceQuiz
  Restore ScienceData
  QuizCategory["Science"]
End Proc

Procedure QuizCategory[category$]
  score=0
  For i=1 To 3
    Read question$,answer
    Print question$
    Input guess
    If guess=answer Then Add score,1
  Next i

  Print "Score: ";score;"/3"
  If score>highscore Then highscore=score
  Wait Key
End Proc

Procedure ShowScore
  Cls 0
  Print "High Score: ";highscore
  Wait Key
End Proc

HistoryData:
Data "Year moon landing?",1969
Data "US states?",50
Data "WWII end year?",1945

ScienceData:
Data "Planets?",8
Data "Boiling point (°C)?",100
Data "Speed of light (100k)?",3
```

**Run it:**
1. Load AMOS Professional
2. Load `knowledge-master.amos`
3. Press F1 to run
4. Choose category from menu (1-2)
5. Answer 3 questions
6. Try to beat your high score!

## Understanding Menu Systems

### The Main Loop Pattern

Menu-driven programmes follow this structure:

```amos
Do
  ' 1. Display menu
  Cls 0
  Print "=== MENU ==="
  Print "1. Option One"
  Print "2. Option Two"
  Print "3. Quit"

  ' 2. Get choice
  Input choice

  ' 3. Branch to procedure
  If choice=1 Then DoOptionOne
  If choice=2 Then DoOptionTwo
  If choice=3 Then Exit
Loop
```

**Key features:**
- `Do...Loop` runs forever until `Exit`
- Clear screen and redisplay menu each time
- Input validates and branches
- `Exit` breaks from loop cleanly

### Why Exit Instead of End?

```amos
' With Exit - returns to loop
Do
  Input choice
  If choice=4 Then Exit    ' Breaks loop, continues to End
Loop
Print "Thanks!"
End

' With End - terminates immediately
Do
  Input choice
  If choice=4 Then End     ' Programme stops here
Loop
Print "Thanks!"            ' Never executes
```

Use `Exit` when you want to break from a loop but continue programme execution. Use `End` when you want to terminate the entire programme.

## Understanding Procedures with Parameters

### Passing Data to Procedures

AMOS procedures can accept parameters:

```amos
Procedure PrintGreeting[name$]
  Print "Hello, ";name$;"!"
End Proc

PrintGreeting["Alice"]     ' Prints: Hello, Alice!
PrintGreeting["Bob"]       ' Prints: Hello, Bob!
```

**Syntax:**
- Define parameter in square brackets: `[name$]`
- Pass value in square brackets when calling: `["Alice"]`
- Use parameter like a variable inside procedure
- Parameters can be strings (`name$`) or numbers (`score`)

### Multiple Parameters

```amos
Procedure ShowScore[name$,score,total]
  Print name$;" scored ";score;"/";total
End Proc

ShowScore["Alice",15,20]   ' Alice scored 15/20
```

Parameters are separated by commas.

### Why Use Parameters?

**Without parameters (repetitive):**
```amos
Procedure HistoryQuiz
  category$="History"
  Restore HistoryData
  ' Quiz code here...
End Proc

Procedure ScienceQuiz
  category$="Science"
  Restore ScienceData
  ' Quiz code here...
End Proc
```

**With parameters (reusable):**
```amos
Procedure RunQuiz[category$]
  ' Same quiz code works for any category!
  Print "=== ";category$;" QUIZ ==="
End Proc

HistoryQuiz: RunQuiz["History"]
ScienceQuiz: RunQuiz["Science"]
```

One procedure handles multiple categories.

## Understanding High Score Tracking

### Persistent Variables

Variables declared outside procedures persist across procedure calls:

```amos
highscore=0              ' Global variable

Procedure UpdateHighScore[score]
  If score>highscore Then
    highscore=score      ' Updates global variable
  End If
End Proc

UpdateHighScore[5]       ' highscore = 5
UpdateHighScore[3]       ' highscore = 5 (no change)
UpdateHighScore[7]       ' highscore = 7 (new record!)
```

**Key concept:** Variables outside procedures are "global" - visible everywhere. Variables inside procedures are "local" - only exist during that procedure call.

### High Score Pattern

```amos
highscore=0

Do
  ' Take quiz
  score=AskQuestions[]

  ' Check for new record
  If score>highscore Then
    highscore=score
    Print "NEW HIGH SCORE!"
  End If

  ' Menu continues
Loop
```

The `highscore` variable survives each loop iteration, maintaining the best score across multiple quiz attempts.

## Understanding Restore with Labels

### Why Labels?

Data statements store questions for different categories. We need to tell `Read` which category to read from:

```amos
MathQuestions:
Data "2+2?",4
Data "3*3?",9

ScienceQuestions:
Data "Planets?",8
Data "Oceans?",5
```

**Without Restore (wrong):**
```amos
Read q$,a$      ' Gets "2+2?",4
Read q$,a$      ' Gets "3*3?",9
Read q$,a$      ' Gets "Planets?",8  (mixed categories!)
```

**With Restore (correct):**
```amos
Restore MathQuestions
Read q$,a$      ' Gets "2+2?",4
Read q$,a$      ' Gets "3*3?",9

Restore ScienceQuestions
Read q$,a$      ' Gets "Planets?",8
Read q$,a$      ' Gets "Oceans?",5
```

### Label Syntax

```amos
LabelName:           ' Label definition (colon at end)
Data "value",123

Restore LabelName    ' Jump to label (no colon)
Read variable        ' Read from that position
```

**Important:** Labels can be placed anywhere in your programme, but they're typically used to mark data sections at the end.

## Programme Structure

### Complete Menu-Driven Quiz

```amos
' 1. INITIALIZATION
highscore=0

' 2. MAIN MENU LOOP
Do
  ' Display menu
  ' Get choice
  ' Branch to category procedure
Loop

' 3. PROGRAM END
Cls 0
Print "Thanks for playing!"
End

' 4. CATEGORY PROCEDURES
Procedure HistoryQuiz
  Restore HistoryData
  QuizCategory["History"]
End Proc

' 5. GENERIC QUIZ PROCEDURE
Procedure QuizCategory[category$]
  ' Quiz logic works for any category
End Proc

' 6. UTILITY PROCEDURES
Procedure ShowHighScore
  ' Display high score
End Proc

' 7. DATA SECTIONS
HistoryData:
Data "question","answer"
```

This structure keeps the programme organized:
- Initialization at top
- Main logic in middle
- Procedures after main programme
- Data at bottom

**Design Pattern: Menu-Driven Architecture**

In 1990, menu systems were the standard interface for applications:
- **Before menus:** Linear programmes with fixed flow
- **With menus:** User chooses what to do, when to do it
- **Benefit:** Flexible, user-controlled experience

Modern equivalent: CLI tools with subcommands (`git status`, `npm run build`). Same concept: menu of operations.

**Why Separate Data from Code?**

Having `HistoryData:` labels makes it easy to:
- Add new questions (just add Data lines)
- Change questions (edit Data lines)
- Reuse quiz engine (same code, different data)
- Create question editors (read/write Data)

This is "data-driven programming" - separating what the programme does (code) from what it operates on (data).

## Quick Reference

### Menu System Commands

| Command | Purpose | Example |
|---------|---------|---------|
| `Do` | Start infinite loop | `Do` |
| `Loop` | End of loop, repeat | `Loop` |
| `Exit` | Break from loop | `If choice=4 Then Exit` |
| `End` | Terminate programme | `End` |

### Procedure Commands

| Command | Purpose | Example |
|---------|---------|---------|
| `Procedure Name[param$]` | Define procedure with parameter | `Procedure Quiz[cat$]` |
| `End Proc` | End procedure definition | `End Proc` |
| `ProcedureName[value]` | Call procedure with parameter | `Quiz["History"]` |

### Data Commands

| Command | Purpose | Example |
|---------|---------|---------|
| `LabelName:` | Define label | `MathData:` |
| `Restore LabelName` | Jump to label | `Restore MathData` |
| `Read variable` | Get next data value | `Read q$,a` |
