# Lesson 013: Collision Master

**Detect when sprites touch.** Use the Amiga's hardware collision detection to create pickup mechanics, implement Bob Off to hide collected items, and manage multiple BOBs simultaneously.

## The One-Minute Tour

- **Col function detects collisions** - `Col(1)` returns BOB number that touched BOB 1
- **Returns 0 for no collision** - Easy to check with If statement
- **Hardware detection** - Blitter chip checks pixel overlap automatically
- **Bob Off hides sprites** - More efficient than moving off-screen
- **Bob On restores them** - Toggle BOB visibility
- **Multiple BOBs** - Use For loops to create and manage many sprites
- **Pickup pattern** - Col detection → Bob Off → increment score

## Example: Collect the Coins

```amos
Screen Open 0,320,256,32,Lowres
Curs Off: Flash Off: Cls 0

' Create player sprite (blue square)
Ink 2
Bar 0,0 To 15,15
Get Bob 1,0,0 To 16,16
Cls 0

' Create collectible sprite (yellow circle)
Ink 3
Circle 8,8,7
Get Bob 2,0,0 To 16,16
Cls 0

' Player starting position
px=50: py=120
Bob 1,px,py,1

' Create 5 collectibles at random positions
For i=2 To 6
  Bob i,Rnd(280)+20,Rnd(220)+20,2
Next i

score=0

Do
  ' Player movement
  If Jleft(1) Then Dec px,2
  If Jright(1) Then Add px,2
  If Jup(1) Then Dec py,2
  If Jdown(1) Then Add py,2

  ' Boundary checking
  If px&lt;0 Then px=0
  If px>304 Then px=304
  If py&lt;0 Then py=0
  If py>240 Then py=240

  Bob 1,px,py,1

  ' Check for collision
  hit=Col(1)
  If hit>1 Then
    Bob Off hit      ' Hide collected item
    Add score,10
    Sam Play 0,1     ' Collection sound
  End If

  ' Display score
  Locate 0,0
  Print "Score: ";score;" "

  Wait Vbl
  Bob Update
Loop Until Inkey$<>""
```

**What's happening:**
1. **BOB 1** is the player (blue square)
2. **BOBs 2-6** are collectibles (yellow circles) placed randomly
3. **Col(1)** checks if player touched anything
4. **hit>1** verifies it's a collectible (not player itself)
5. **Bob Off** hides the collected item immediately
6. **Score updates** and sound plays for feedback

**Try it:** Move around collecting all 5 items. Notice instant collision detection and smooth gameplay.

## How Col Works (Hardware Detection)

**The Col function:**
```amos
result = Col(bob_number)
' Returns:
'   0 = No collision
'   N = Hit BOB number N
```

**Blitter collision detection:**
1. Each frame, Blitter compares BOB pixel positions
2. If any non-transparent pixels overlap → collision detected
3. Returns BOB number of first collision found
4. All happens in hardware (zero CPU cost)

**Multiple collisions:**
```amos
' Col only returns FIRST collision per frame
hit=Col(1)
' If BOB 1 touches BOBs 3 AND 5 simultaneously,
' Col returns 3 (lowest number)
' Next frame (after 3 is hidden), returns 5
```

**Why check hit>1?**
```amos
hit=Col(1)
If hit>0 Then  ' WRONG: Would trigger on BOB 1 itself
If hit>1 Then  ' CORRECT: Ignores self, checks others
```

## Bob Off vs Moving Off-Screen

**Bob Off (efficient):**
```amos
Bob Off 5        ' BOB 5 stops updating, invisible
' Advantages:
' - Instant
' - Frees BOB slot
' - No boundary calculations
' - Blitter ignores it
```

**Moving off-screen (inefficient):**
```amos
Bob 5,500,500,2  ' BOB 5 still updates, just invisible
' Disadvantages:
' - Still processed each frame
' - Wastes Blitter time
' - Could still collide
' - Harder to track state
```

**Always use Bob Off for disabled sprites.**

## Bob On: Restoring Visibility

```amos
Bob Off 5        ' Hide BOB 5
' ... gameplay ...
Bob On 5         ' Show BOB 5 again
Bob 5,100,100,2  ' Set position
```

**Use cases:**
- **Power-up respawn** - Hide for 5 seconds, then Bob On
- **Invincibility** - Bob Off player briefly after hit
- **Blinking effect** - Bob Off/On alternating creates flash

**Example: Item respawn timer:**
```amos
If itemTimer&lt;=0 Then
  Bob On 5
  Bob 5,Rnd(280)+20,Rnd(220)+20,2
  itemTimer=50*5  ' 5 seconds
End If
```

## Multiple BOBs Management Pattern

**Creation with For loop:**
```amos
' BOB 1 = player (reserved)
' BOBs 2-10 = enemies/items

For i=2 To 10
  Bob i,Rnd(280)+20,Rnd(220)+20,2
Next i
```

**Tracking state with arrays:**
```amos
Dim active(10)    ' Is BOB active? (1=yes, 0=no)

For i=2 To 10
  active(i)=1
  Bob i,Rnd(280)+20,Rnd(220)+20,2
Next i

' On collision:
hit=Col(1)
If hit>1 and active(hit)=1 Then
  active(hit)=0
  Bob Off hit
End If
```

**Why track state?** Prevents double-collection and enables complex game logic (respawn timers, point values, types).

## Game Loop Architecture

**Standard pattern:**
```amos
Do
  ' 1. INPUT
  Read joystick/keyboard

  ' 2. MOVEMENT
  Update positions
  Boundary checking

  ' 3. COLLISION
  hit=Col(player)
  Process hit

  ' 4. DISPLAY
  Update HUD
  Show status

  ' 5. SYNCHRONIZE
  Wait Vbl
  Bob Update
Loop Until game_over
```

**Why this order?**
- Input before movement (responsive controls)
- Collision after movement (detect current frame)
- Display after collision (show updated state)
- Synchronize last (smooth 50fps)

## In Game Use: Power-Ups

**Pickup system with effects:**
```amos
' Different BOB numbers = different items
hit=Col(1)

If hit=2 Then
  ' Speed boost
  Bob Off hit
  playerSpeed=4
  boostTimer=50*10  ' 10 seconds
End If

If hit=3 Then
  ' Extra life
  Bob Off hit
  Add lives,1
  Sam Play 1,5
End If

If hit>=4 and hit&lt;=8 Then
  ' Regular coins
  Bob Off hit
  Add score,10
End If
```

**BOB numbering strategy:**
- **1** = Player
- **2-3** = Power-ups
- **4-10** = Collectibles
- **11-20** = Enemies

Clear ranges prevent collision logic errors.

## Advanced: Collision Filtering

**Selective collision checking:**
```amos
hit=Col(1)

' Only process enemy collisions (BOBs 11-20)
If hit>=11 and hit&lt;=20 Then
  ' Enemy hit logic
  Dec lives,1
  Sam Play 2,10
End If

' Ignore collectibles (BOBs 4-10)
' Separate check later:
hit=Col(1)
If hit>=4 and hit&lt;=10 Then
  ' Pickup logic
  Bob Off hit
  Add score,10
End If
```

**Why separate checks?** Different collision types have different responses (damage vs collection).

## From the Vault

**Blitter collision hardware:**
- **Sprite registers** track all BOB positions automatically
- **Comparison logic** checks pixel-perfect overlap
- **Priority system** determines which BOB number returns first
- **DMA access** means zero CPU overhead

**Historical arcade:**
- **Early arcade games** used software collision (CPU expensive)
- **Atari 2600** had hardware collision (2 sprites only)
- **Amiga Blitter** supports 8 hardware sprites + unlimited BOBs
- **Result:** Amiga games match arcade collision complexity

**AMOS optimization:**
- Col function is instant (hardware read)
- Bob Off is instant (register write)
- Use these freely without performance concern

## Quick Reference

### Collision Detection
| Command | Returns | Purpose |
|---------|---------|---------|
| `Col(n)` | BOB number or 0 | Check collision |
| `Bob Off n` | - | Hide BOB |
| `Bob On n` | - | Show BOB |

### Collision Patterns
| Pattern | Code | Use Case |
|---------|------|----------|
| Simple pickup | `If Col(1)>1 Then...` | Any collision |
| Type check | `If Col(1)>=4 and Col(1)&lt;=10` | Specific range |
| State tracking | `If active(hit)=1 Then...` | Respawn logic |

### BOB State
| State | Visibility | Collision | Updates |
|-------|-----------|-----------|---------|
| Normal | Visible | Detects | Yes |
| Bob Off | Hidden | Ignores | No |
| Off-screen | Hidden | Detects | Yes |
