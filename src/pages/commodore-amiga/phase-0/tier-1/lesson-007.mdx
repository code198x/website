# Lesson 007: First BOB

Welcome to the Amiga's secret weapon: hardware-accelerated graphics. BOBs (Blitter OBjects) let you create and move sprites instantly using dedicated hardware.

## The One-Minute Tour

- **BOBs** - Blitter OBjects for hardware-accelerated sprites
- **Screen Open** - Initialize graphics display with modes
- **Get Bob** - Capture screen area as reusable sprite image
- **Paste Bob** - Display BOB at any position instantly
- **Hardware blitter** - Dedicated chip for graphics operations
- **32 colours** - Full palette available in low-res mode

## Example Programme

Here's a simple BOB creation and display:

```amos
' First BOB Demo
Screen Open 0,320,256,32,Lowres
Curs Off: Flash Off: Cls 0

' Draw a sprite (16x16)
Ink 2: Bar 0,0 To 15,15      ' Green box
Ink 14: Circle 8,8,6          ' Yellow circle

' Capture as BOB #1
Get Bob 1,0,0 To 16,16

' Display it
Cls 0
Paste Bob 100,100,1
Paste Bob 150,100,1
Paste Bob 200,100,1

Wait Key
```

**Run it:**
1. Load AMOS Professional
2. Load `first-bob.amos`
3. Press F1 to run
4. Watch BOB creation process
5. See hardware-accelerated display

## Understanding BOBs

### What Are BOBs?

BOBs (Blitter OBjects) are AMOS's sprite system that uses the Amiga's hardware blitter chip:

**Not the same as:**
- Amiga's 8 hardware sprites (different system)
- Software sprites (CPU-drawn)
- C64 sprites (hardware but limited)

**BOB advantages:**
- Hardware-accelerated (dedicated chip)
- Any size (16x16, 32x32, 64x64, or custom)
- Hundreds on screen simultaneously
- Instant copying (parallel to CPU)
- Built-in collision detection
- Full colour depth (32 colours in low-res)

### How BOBs Work

```
1. Draw graphics          CPU/Blitter draws to screen
   ↓
2. Get Bob               Blitter captures to memory
   ↓
3. Paste Bob             Blitter copies to screen
   ↓
4. Reuse anywhere        Instant copying
```

**The magic:** Once captured, displaying a BOB takes microseconds. The blitter does all the work while your CPU continues running your programme.

## Understanding Screen Open

### Screen Modes

```amos
Screen Open id,width,height,colours,mode
```

**Common configurations:**

| Mode | Width | Height | Colours | Usage |
|------|-------|--------|---------|-------|
| Lowres | 320 | 256 | 32 | Games, demos, graphics |
| Hires | 640 | 256 | 16 | Applications, text |
| Lowres | 320 | 512 | 16 | Interlaced display |
| Hires | 640 | 512 | 4 | High-res interlaced |

**Parameters explained:**
- **ID**: Screen number (0-7, can have multiple screens)
- **Width**: Horizontal resolution (320 or 640 typical)
- **Height**: Vertical resolution (256 PAL standard, 200 NTSC)
- **Colours**: Palette size (2, 4, 8, 16, or 32)
- **Mode**: `Lowres` or `Hires`

### Screen Setup Commands

```amos
Screen Open 0,320,256,32,Lowres   ' Create screen
Curs Off                           ' Hide text cursor
Flash Off                          ' Disable cursor flash
Cls 0                              ' Clear to colour 0
```

**Why these commands?**
- `Curs Off`: Text cursor interferes with graphics
- `Flash Off`: Blinking cursor wastes display time
- `Cls 0`: Start with clean black screen

### PAL vs NTSC

**PAL (Europe, Australia):**
- 256 lines visible (312 total)
- 50Hz refresh rate
- Slightly taller display

**NTSC (North America, Japan):**
- 200 lines visible (262 total)
- 60Hz refresh rate
- Slightly faster refresh

AMOS automatically handles both. Most games supported both modes.

## Understanding Get Bob

### Capturing Graphics

```amos
Get Bob number,x1,y1 To x2,y2
```

**Parameters:**
- `number`: BOB ID (1-255)
- `x1,y1`: Top-left corner of capture area
- `x2,y2`: Bottom-right corner

**Example:**
```amos
' Draw at 0,0
Ink 2
Bar 0,0 To 15,15

' Capture as BOB #1
Get Bob 1,0,0 To 16,16    ' Note: 16,16 = 16 pixels wide/tall
```

**Important:** The capture includes the end coordinates, so `To 16,16` captures 0-16 = 17 pixels. For exact 16x16, use `To 15,15`.

### BOB Size Considerations

```amos
' Small BOB (16x16) - characters, bullets
Get Bob 1,0,0 To 15,15

' Medium BOB (32x32) - player sprites
Get Bob 2,0,0 To 31,31

' Large BOB (64x64) - bosses, effects
Get Bob 3,0,0 To 63,63

' Custom size (48x24) - any size works
Get Bob 4,0,0 To 47,23
```

**Memory usage:** Larger BOBs use more chip RAM. Plan accordingly.

## Understanding Paste Bob

### Displaying BOBs

```amos
Paste Bob x,y,number
```

**Parameters:**
- `x,y`: Screen position (top-left corner)
- `number`: Which BOB to display

**Examples:**
```amos
Paste Bob 100,100,1    ' Display BOB #1 at (100,100)
Paste Bob 150,150,1    ' Display same BOB elsewhere
Paste Bob 200,200,2    ' Display different BOB
```

### Multiple Displays

```amos
' Create pattern
For x=0 To 304 Step 16
  For y=0 To 240 Step 16
    Paste Bob x,y,1
  Next y
Next x
```

This displays BOB #1 in a grid pattern. The blitter handles all copying - incredibly fast!

### Paste Bob vs Bob Command

**Paste Bob (this lesson):**
- Manual positioning
- No automatic management
- Direct blitter copy
- You handle everything

**Bob command (lesson 009):**
- Automatic management
- Background save/restore
- Collision detection
- AMOS handles details

We'll learn `Bob` command in lesson 009. `Paste Bob` teaches the fundamentals.

## Understanding the Hardware

### The Amiga Chipset

**Agnus (Address GeNerator Unit):**
- Memory management
- Blitter control
- DMA coordination

**Denise (Display ENabler):**
- Video output
- Palette display
- Sprite priorities

**Blitter (Block Image TransferER):**
- Copies graphics blocks
- Fills areas
- Line drawing
- Operates parallel to CPU

### Why This Matters

**Without blitter (C64, ZX Spectrum):**
```
CPU draws each pixel → slow, blocks other work
```

**With blitter (Amiga):**
```
CPU: "Blitter, copy this sprite here"
Blitter: "On it!" (copies while CPU continues)
CPU: Does other game logic
```

True parallel processing. This is why Amiga games look so smooth.

## Programme Structure

### BOB Creation Workflow

```amos
' 1. INITIALIZE SCREEN
Screen Open 0,320,256,32,Lowres
Curs Off: Flash Off: Cls 0

' 2. DRAW SPRITE GRAPHICS
Ink 2
Bar 0,0 To 15,15
Circle 8,8,6

' 3. CAPTURE AS BOB
Get Bob 1,0,0 To 16,16

' 4. CLEAR SCREEN (optional)
Cls 0

' 5. USE BOB
Paste Bob x,y,1
```

This pattern repeats for each unique sprite you need.

**Technical Specifications:**

**Blitter Performance:**
- 7.16 MHz operation (PAL)
- Can move 1 megabyte per second
- Three channels: source A, source B, destination
- Supports logic operations (AND, OR, XOR)

**BOB Memory:**
- Stored in chip RAM (512KB standard)
- Each BOB uses: width × height × bitplanes bytes
- Example: 16×16×5 (32 colours) = 1,280 bytes

**Why "Blitter OBjects"?**

In 1985, Commodore wanted to differentiate Amiga sprites from competition:
- Not "VIC sprites" (C64's 8 hardware sprites)
- Not "software sprites" (CPU-drawn, slow)
- **Blitter OBjects** - hardware-accelerated, unlimited

The name emphasizes the key advantage: dedicated hardware acceleration.
