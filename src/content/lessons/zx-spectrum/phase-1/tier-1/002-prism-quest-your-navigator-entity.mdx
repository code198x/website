# Lesson 2: Prism Quest - Your Navigator Entity

**Your color-shifting maze needs an explorer!** In the last lesson, you created the stunning visual foundation of Prism Quest. ## Your Navigator Appears

Let's start with the magic - adding your controllable navigator to the dimensional maze:

```nasm
; Prism Quest - Navigator Entity Creation
    ORG 32768

start:
    ; Set up color-shifting maze from Lesson 1
    LD HL, $4000        ; Point to screen memory
    LD A, 143           ; Wall block character
    LD (HL), A          ; Place wall at top-left
    
    INC HL              ; Move to next position
    LD A, 32            ; Space character (corridor)
    LD (HL), A          ; Create passageway
    
    INC HL
    LD A, 143           ; Another wall block
    LD (HL), A
    
    ; Create navigator entity at starting position
    LD BC, $0205        ; Navigator position: B=X(2), C=Y(5)
    LD DE, $4000        ; Screen memory base in DE
    
    ; Calculate navigator screen position
    CALL calc_position
    
    ; Place navigator character (dimensional traveler)
    LD A, 234           ; Navigator character (diamond with center)
    LD (HL), A          ; Place navigator on screen
    
    ; Set spectacular dimensional colors
    LD HL, $5800        ; Point to color memory
    LD A, %01000111     ; Bright white walls
    LD (HL), A
    
    INC HL
    LD A, %01000001     ; Bright blue corridor
    LD (HL), A
    
    INC HL
    LD A, %01000100     ; Bright green walls
    LD (HL), A
    
    ; Navigator gets special shifting color
    LD HL, $5805        ; Navigator color position
    LD A, %01001110     ; Bright yellow - dimensional energy
    LD (HL), A
    
    ; Game loop - infinite for now
loop:
    JR loop

; Calculate screen position from B,C coordinates
calc_position:
    ; Start with screen base
    LD H, D             ; Copy screen base to HL
    LD L, E
    
    ; Add Y offset (32 * Y position for Spectrum)
    LD A, C             ; Get Y coordinate
    OR A                ; Check if zero
    JR Z, add_x         ; Skip Y calculation if zero
    
calc_y_loop:
    LD DE, 32           ; 32 characters per row on Spectrum
    ADD HL, DE          ; Add row offset
    DEC C               ; Decrease Y counter
    JR NZ, calc_y_loop  ; Continue until Y=0
    
add_x:
    ; Add X offset
    LD A, B             ; Get X coordinate
    LD E, A             ; Put in E
    LD D, 0             ; Clear D
    ADD HL, DE          ; Add X offset to final position
    
    RET

; Store navigator position in memory for tracking
store_position:
    LD ($5C00), BC      ; Store navigator coordinates
    RET
```

## What Just Happened? The Magic Behind Your Navigator

Now that you've seen your navigator appear, let's understand how the Z80 made it happen through **dimensional navigation management**.

### The HL Register Pair: Your Dimensional Positioning System

The most important thing to understand: **the HL register pair is perfect for navigating dimensional space**. In your navigator code:

```nasm
LD HL, $4000        ; Point to screen memory base
LD BC, $0205        ; Navigator coordinates: X=2, Y=5
CALL calc_position  ; Calculate dimensional position
LD A, 234           ; Navigator character (dimensional entity)
LD (HL), A          ; Place navigator in calculated position
```

This sequence:
1. Loads the screen memory base address ($4000) into the **HL register pair**
2. Stores navigator coordinates in **BC register pair** (B=X, C=Y)
3. Calculates the exact dimensional position using Z80's powerful addressing
4. Places the navigator character at the calculated location

### ZX Spectrum's Dimensional Memory Layout

Understanding the Spectrum's memory layout is crucial for dimensional navigation:

**Memory Map - Your Dimensional Control System:**
- **$0000-$3FFF**: ROM - The dimensional constants and system rules
- **$4000-$57FF**: Screen memory - Your visible dimensional space (what you see)
- **$5800-$5AFF**: Attribute memory - Dimensional color energy information  
- **$5B00-$FFFF**: Navigator RAM - Your dimensional state and navigation data

When you write `LD (HL), A`, you're placing your navigator directly into dimensional space!

### The LD Instruction: Your Dimensional Manipulation Tool

The Z80's **LD instruction** is your primary tool for dimensional navigation and entity management:

```nasm
LD A, 234           ; Load navigator character into A register
LD (HL), A          ; Place navigator at dimensional position HL points to
LD BC, $0205        ; Load navigator coordinates (X=2, Y=5)
LD ($5C00), BC      ; Store coordinates in dimensional memory
```

**Why this matters for dimensional games**: The LD instruction handles both 8-bit values (characters, colors) and 16-bit values (positions, addresses) seamlessly.

### Quick Reference: Today's Dimensional Programming Instructions

- **LD HL, address**: Load 16-bit address into HL register pair for positioning
- **LD BC, coordinates**: Load X,Y coordinates into BC register pair
- **LD (HL), A**: Place character/entity at position HL points to
- **LD (address), HL**: Store 16-bit coordinates to dimensional memory
- **INC HL**: Move to next dimensional position
