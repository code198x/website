# Lesson 11: ZX Spectrum Screen Memory Layout

The ZX Spectrum's screen memory has a unique and clever organization that sets it apart from other computers. Understanding this layout is crucial for graphics programming and will help you create efficient display routines. Let's explore how the Spectrum stores what you see on screen!

## The ZX Spectrum Display System

The ZX Spectrum uses a **character-cell based** display system with some unique twists:

- **Resolution**: 256 × 192 pixels (32 × 24 character cells)
- **Character cells**: 8 × 8 pixel blocks
- **Memory split**: Pixels and colors stored separately
- **Total screen memory**: 6,912 bytes (6KB pixel + 768 bytes attribute)

## Screen Memory Map Overview

```
$4000-$57FF: Pixel data (6144 bytes) - actual pixel patterns
$5800-$5AFF: Attribute data (768 bytes) - colors for each 8×8 cell
```

This split design was a clever compromise to save memory while providing color graphics!

**Understanding the ZX Spectrum Memory Layout:**
- **Screen Pixels** ($4000-$57FF) highlighted in yellow show the three memory sections 
- **Color Attributes** ($5800-$5AFF) in orange control colors for each 8×8 character cell

- **ROM** ($0000-$3FFF) in red contains the BASIC interpreter and operating system

## Pixel Memory Layout ($4000-$57FF)

The pixel memory is organized in a non-linear fashion that might seem strange at first:

### The "Thirds" System
The screen is divided into three vertical sections of 64 pixels (8 character rows) each:

```
Top third:    $4000-$47FF (rows 0-7)
Middle third: $4800-$4FFF (rows 8-15)  
Bottom third: $5000-$57FF (rows 16-23)
```

### Within Each Third
Each third contains 8 character rows, and each character row is 32 bytes wide:

```
Row 0: $4000-$401F (32 bytes)
Row 1: $4020-$403F (32 bytes)
Row 2: $4040-$405F (32 bytes)
...
Row 7: $40E0-$40FF (32 bytes)
```

**Basic Screen Memory Access:**

```assembly
; Draw on the top-left character cell
LD HL, $4000     ; Point to top-left of screen
LD A, %11111111  ; All pixels on
LD (HL), A       ; Draw top line of character cell

; Draw on next line of same character cell  
LD HL, $4020     ; Second pixel row of first character cell
LD A, %10000001  ; Border pattern
LD (HL), A       ; Draw second line
```

## Understanding Character Cells

Each character cell is 8 pixels wide × 8 pixels tall:

```
Character cell at position (0,0):
$4000: ████████ (pixel row 0)
$4020: █      █ (pixel row 1)  
$4040: █      █ (pixel row 2)
$4060: █      █ (pixel row 3)
$4080: █      █ (pixel row 4)
$40A0: █      █ (pixel row 5)
$40C0: █      █ (pixel row 6)
$40E0: ████████ (pixel row 7)
```

Notice how the addresses jump by $20 (32 bytes) for each pixel row within a character cell!

## Screen Address Calculation

To find the screen address for any pixel position:

**For character position (X, Y) where X=0-31, Y=0-23:**

1. **Find the third**: Y ÷ 8
2. **Find the row within third**: Y mod 8  
3. **Calculate address**: $4000 + (third × $800) + (row × $20) + X

**Drawing at Specific Character Positions:**

```assembly
; Draw at character position (5, 3)
; Y=3, so third=0, row=3, X=5
; Address = $4000 + (0 × $800) + (3 × $20) + 5 = $4065
LD HL, $4065     ; Character position (5,3)
LD A, %01111110  ; Rounded rectangle pattern
LD (HL), A

; Draw at character position (10, 12)  
; Y=12, so third=1, row=4, X=10
; Address = $4000 + (1 × $800) + (4 × $20) + 10 = $488A
LD HL, $488A     ; Character position (10,12)
LD A, %11000011  ; Different pattern
LD (HL), A
```

## Drawing Complete Characters

To draw a complete 8×8 character, you need to set 8 consecutive pixel rows:

```text
; Draw a simple smiley face at position (1,1)
LD IX, $4021     ; Base address for position (1,1)

LD (IX+$00), %00111100  ; Row 0:   ████  
LD (IX+$20), %01000010  ; Row 1:  █    █
LD (IX+$40), %10100101  ; Row 2: █ █  █ █
LD (IX+$60), %10000001  ; Row 3: █      █
LD (IX+$80), %10100101  ; Row 4: █ █  █ █
LD (IX+$A0), %10011001  ; Row 5: █  ██  █
LD (IX+$C0), %01000010  ; Row 6:  █    █
LD (IX+$E0), %00111100  ; Row 7:   ████  
```

**Drawing a Complete Character:**

```assembly
; Draw a diamond pattern at position (2,2)
LD IX, $4042     ; Base address for position (2,2)

LD (IX+$00), %00010000  ; Row 0:    █    
LD (IX+$20), %00111000  ; Row 1:   ███   
LD (IX+$40), %01111100  ; Row 2:  █████  
LD (IX+$60), %11111110  ; Row 3: ███████ 
LD (IX+$80), %11111110  ; Row 4: ███████ 
LD (IX+$A0), %01111100  ; Row 5:  █████  
LD (IX+$C0), %00111000  ; Row 6:   ███   
LD (IX+$E0), %00010000  ; Row 7:    █
```

## Attribute Memory ($5800-$5AFF)

While pixel memory defines what pixels are on/off, attribute memory defines their colors. Each attribute byte controls the color of one 8×8 character cell:

### Attribute Byte Format
```
Bit 7: FLASH (0=steady, 1=flashing)
Bit 6: BRIGHT (0=normal, 1=bright)
Bits 5-3: PAPER color (background)
Bits 2-0: INK color (foreground)
```

### Color Values
```
0: Black    4: Green
1: Blue     5: Cyan  
2: Red      6: Yellow
3: Magenta  7: White
```

## Attribute Address Calculation

Attribute addresses are much simpler than pixel addresses:

**For character position (X, Y):**
- **Address** = $5800 + (Y × 32) + X

**Setting Character Colors:**

```assembly
; Set colors for character at position (5,3)
; Attribute address = $5800 + (3 × 32) + 5 = $5865
LD HL, $5865     ; Attribute for position (5,3)
LD A, %00111001  ; Bright yellow ink on blue paper
LD (HL), A

; Set colors for character at position (10,12)
; Attribute address = $5800 + (12 × 32) + 10 = $5A0A  
LD HL, $5A0A     ; Attribute for position (10,12)
LD A, %01000010  ; Bright red ink on black paper
LD (HL), A
```

## Creating Colored Graphics

Let's draw a colored character with both pixels and attributes:

```text
; Draw a colored block at position (8,8)
; First, draw the pixels
LD IX, $4908     ; Pixel address for (8,8) - middle third
LD (IX+$00), %11111111  ; Solid block
LD (IX+$20), %11111111  ; All 8 rows
LD (IX+$40), %11111111
LD (IX+$60), %11111111  
LD (IX+$80), %11111111
LD (IX+$A0), %11111111
LD (IX+$C0), %11111111
LD (IX+$E0), %11111111

; Then set the color
LD HL, $5908     ; Attribute address for (8,8)
LD A, %00100100  ; Green ink on black paper
LD (HL), A
```

**Colored Character Block:**

```assembly
; Draw colored character at position (4,4)
; Pixel address calculation: Y=4, third=0, row=4, X=4
; Address = $4000 + (0 × $800) + (4 × $20) + 4 = $4084
LD IX, $4084     ; Pixel base for position (4,4)

; Draw checkerboard pattern
LD (IX+$00), %10101010  ; Row 0: █ █ █ █ 
LD (IX+$20), %01010101  ; Row 1:  █ █ █ █
LD (IX+$40), %10101010  ; Row 2: █ █ █ █ 
LD (IX+$60), %01010101  ; Row 3:  █ █ █ █
LD (IX+$80), %10101010  ; Row 4: █ █ █ █ 
LD (IX+$A0), %01010101  ; Row 5:  █ █ █ █
LD (IX+$C0), %10101010  ; Row 6: █ █ █ █ 
LD (IX+$E0), %01010101  ; Row 7:  █ █ █ █

; Set bright cyan ink on black paper
LD HL, $5884     ; Attribute address = $5800 + (4×32) + 4
LD A, %01000101  ; Bright cyan on black
LD (HL), A
```

## Screen Memory Efficiency Tips

### Use Index Registers for Characters
```text
LD IX, $4000     ; Base pixel address
LD IY, $5800     ; Base attribute address
; Now you can draw complete characters efficiently
```

### Sequential Access for Full Screen
```text
LD HL, $4000     ; Start of screen
LD BC, 6144      ; All pixel bytes
; Use LDIR or loops for full screen operations
```

### Character Cell Optimization
```text
; To move to next character cell in same row:
INC HL           ; Move one byte right

; To move to same character cell, next pixel row:
LD DE, $20       ; 32 bytes per row
ADD HL, DE       ; Move down one pixel row
```

## Common Screen Memory Mistakes

**Wrong address calculation:**
```text
; Wrong - this isn't how screen memory works
LD HL, $4000
LD DE, 256       ; Wrong! Not 256 bytes per row
ADD HL, DE

; Correct - account for the thirds system
LD HL, $4000     ; Top third start
LD DE, $800      ; Jump to middle third
ADD HL, DE       ; Now pointing to middle third
```

**Forgetting attributes:**
```text
; Drawing pixels without setting colors results in random colors
LD (HL), %11111111  ; Draw pixels
; Missing: Set attribute byte for proper colors
```

## The Attribute Color Clash

The ZX Spectrum's attribute system has a famous limitation: **color clash**. Since each 8×8 character cell can only have two colors (ink and paper), you can't have multiple foreground colors within a single character cell. This constraint influenced ZX Spectrum game design and art style!

## Fun Fact

The ZX Spectrum's unusual screen memory layout wasn't random - it was carefully designed to make the computer cheaper to manufacture! By organizing memory in thirds, Sinclair could use simpler address decoding logic, reducing the chip count and cost. The separate attribute memory saved even more memory compared to storing full color information for each pixel. This clever engineering allowed the ZX Spectrum to offer color graphics at a much lower price than competitors, contributing to its massive success. Many programmers initially found the layout confusing, but once mastered, it enabled very efficient graphics routines!
