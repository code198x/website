# Lesson 1: Byte Blaster - Your First Game World

Welcome to NES game development! In this lesson, you'll create your first game world using 6502 assembly language for the Nintendo Entertainment System. You'll learn the PPU graphics system and build a tile-based arena with sprites.

## Understanding the NES

The NES has unique characteristics for game development:

1. **6502 CPU** - 8-bit processor running at ~1.79MHz
2. **PPU** - Dedicated graphics processor with tiles and sprites
3. **Memory layout** - Separate CPU and PPU address spaces
4. **Background** - 32×30 tiles using pattern tables
5. **Sprites** - 64 sprites, 8×8 or 8×16 pixels each
6. **Colors** - 52 colors total, 4 colors per palette

## Step 1: NES Program Structure

Let's create the basic NES program framework:

```asm6502
; Byte Blaster - Lesson 1
; NES 6502 Assembly

; iNES header for emulators
.segment "HEADER"
        .byte "NES", $1A    ; Magic number
        .byte 2             ; 2 × 16KB PRG ROM banks
        .byte 1             ; 1 × 8KB CHR ROM bank  
        .byte $01           ; Mapper 0, vertical mirroring
        .byte $00, $00, $00, $00, $00, $00, $00, $00

; Include standard NES definitions
.include "nes.inc"

; Variables in zero page (fast access)
.segment "ZEROPAGE"
player_x:       .res 1
player_y:       .res 1
scroll_x:       .res 1
scroll_y:       .res 1
frame_counter:  .res 1

; Main program code
.segment "CODE"

RESET:
        ; Initialize the NES
        SEI             ; Disable interrupts
        CLD             ; Clear decimal mode
        LDX #$40
        STX $4017       ; Disable APU frame IRQ
        LDX #$FF
        TXS             ; Set up stack
        INX             ; X = 0
        STX $2000       ; Disable NMI
        STX $2001       ; Disable rendering
        STX $4010       ; Disable DMC IRQ

        ; Wait for PPU to stabilize
        BIT $2002       ; Clear VBlank flag
vblankwait1:
        BIT $2002       ; Wait for VBlank
        BPL vblankwait1

        ; Clear RAM
        LDA #0
        STA $0000, X
        STA $0100, X
        STA $0200, X
        STA $0300, X
        STA $0400, X
        STA $0500, X
        STA $0600, X
        STA $0700, X
        INX
        BNE clrmem

        ; Wait for second VBlank
vblankwait2:
        BIT $2002
        BPL vblankwait2

        ; Initialize game
        JSR load_palettes
        JSR load_background
        JSR init_sprites
        
        ; Enable rendering
        LDA #%10000000  ; Enable NMI
        STA $2000
        LDA #%00011110  ; Enable sprites and background
        STA $2001

game_loop:
        ; Wait for NMI to set vblank_flag
        LDA vblank_flag
        BEQ game_loop
        LDA #0
        STA vblank_flag

        ; Game logic goes here
        JSR read_controller
        JSR update_player
        JSR update_sprites

        JMP game_loop

vblank_flag: .byte 0
```

## Step 2: PPU Graphics Setup

Configure the PPU for tile-based graphics:

```asm6502
load_palettes:
        ; Set PPU address to palette RAM
        LDA $2002       ; Read to reset address latch
        LDA #$3F        ; High byte of palette address
        STA $2006
        LDA #$00        ; Low byte
        STA $2006

        ; Load background palettes
        LDX #0
load_bg_pal:
        LDA background_palette, X
        STA $2007       ; Write to PPU data
        INX
        CPX #16         ; 4 palettes × 4 colors
        BNE load_bg_pal

        ; Load sprite palettes  
        LDX #0
load_spr_pal:
        LDA sprite_palette, X
        STA $2007
        INX
        CPX #16
        BNE load_spr_pal

        RTS

background_palette:
        .byte $0F, $21, $11, $01    ; Palette 0: blacks and blues
        .byte $0F, $27, $17, $07    ; Palette 1: browns and oranges
        .byte $0F, $30, $21, $0F    ; Palette 2: whites and grays
        .byte $0F, $29, $19, $09    ; Palette 3: greens

sprite_palette:
        .byte $0F, $16, $27, $18    ; Player palette: reds and yellows
        .byte $0F, $1A, $30, $27    ; Enemy palette: greens and whites  
        .byte $0F, $12, $23, $27    ; Item palette: blues and whites
        .byte $0F, $0F, $0F, $0F    ; Unused

load_background:
        ; Load nametable (background tiles)
        LDA $2002       ; Reset address latch
        LDA #$20        ; Nametable 0 address
        STA $2006
        LDA #$00
        STA $2006

        ; Draw background pattern
        LDX #0          ; Row counter
        LDY #0          ; Column counter

bg_row_loop:
        LDA background_data, X
        STA $2007       ; Write tile
        INY
        CPY #32         ; 32 tiles per row
        BNE bg_row_loop
        
        LDY #0          ; Reset column
        INX
        CPX #30         ; 30 rows total
        BNE bg_row_loop

        ; Load attribute table (palette assignments)
        LDX #0
attr_loop:
        LDA attribute_data, X
        STA $2007
        INX
        CPX #64         ; 8×8 attribute grid
        BNE attr_loop

        RTS

; Simple background pattern
background_data:
        ; Row 0 - top border
        .byte $01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01
        .byte $01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01
        ; Rows 1-28 - playfield with borders
        .repeat 28
        .byte $01,$00,$00,$00,$00,$00,$00,$00,$00,$00,$00,$00,$00,$00,$00,$00
        .byte $00,$00,$00,$00,$00,$00,$00,$00,$00,$00,$00,$00,$00,$00,$00,$01
        .endrepeat
        ; Row 29 - bottom border
        .byte $01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01
        .byte $01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01,$01

attribute_data:
        ; Each byte controls palette for 4×4 tile area
        .repeat 64
        .byte $00       ; Use palette 0 for everything initially
        .endrepeat
```

## Step 3: Sprite System

Create and animate sprites for game entities:

```asm6502
init_sprites:
        ; Clear all sprites off-screen
        LDX #0
        LDA #$FF        ; Y position off-screen
clear_sprites:
        STA $0200, X    ; Sprite Y position
        INX
        INX
        INX
        INX
        BNE clear_sprites

        ; Initialize player sprite
        LDA #120        ; Y position
        STA $0200       ; Sprite 0 Y
        LDA #$10        ; Tile number (player character)
        STA $0201       ; Sprite 0 tile
        LDA #%00000000  ; Attributes (palette 0, no flip)
        STA $0202       ; Sprite 0 attributes  
        LDA #128        ; X position
        STA $0203       ; Sprite 0 X

        ; Initialize player position variables
        LDA #128
        STA player_x
        LDA #120  
        STA player_y

        RTS

update_sprites:
        ; Copy sprite data to PPU during VBlank
        LDA #$00        ; Low byte of sprite RAM
        STA $2003       ; Set OAM address
        LDA #$02        ; High byte ($0200)
        STA $4014       ; Start DMA transfer

        RTS
```

## Step 4: Controller Input

Read the NES controller for player movement:

```asm6502
; Controller bit patterns
BUTTON_A        = %10000000
BUTTON_B        = %01000000  
BUTTON_SELECT   = %00100000
BUTTON_START    = %00010000
BUTTON_UP       = %00001000
BUTTON_DOWN     = %00000100
BUTTON_LEFT     = %00000010
BUTTON_RIGHT    = %00000001

read_controller:
        ; Strobe controller to latch button states
        LDA #1
        STA $4016
        LDA #0
        STA $4016

        ; Read 8 buttons
        LDX #8
controller_loop:
        LDA $4016       ; Read button state
        LSR A           ; Shift right, button in carry
        ROL buttons     ; Rotate into buttons variable
        DEX
        BNE controller_loop

        RTS

update_player:
        ; Check for movement input
        LDA buttons
        AND #BUTTON_UP
        BEQ check_down
        
        ; Move up
        LDA player_y
        SEC
        SBC #2          ; Move 2 pixels up
        CMP #16         ; Top boundary
        BCC no_move_up  ; Don't move if too high
        STA player_y
        STA $0200       ; Update sprite Y
no_move_up:

check_down:
        LDA buttons
        AND #BUTTON_DOWN
        BEQ check_left
        
        ; Move down
        LDA player_y
        CLC
        ADC #2          ; Move 2 pixels down
        CMP #208        ; Bottom boundary
        BCS no_move_down ; Don't move if too low
        STA player_y
        STA $0200       ; Update sprite Y
no_move_down:

check_left:
        LDA buttons
        AND #BUTTON_LEFT
        BEQ check_right
        
        ; Move left
        LDA player_x
        SEC
        SBC #2          ; Move 2 pixels left
        CMP #8          ; Left boundary
        BCC no_move_left ; Don't move if too far left
        STA player_x
        STA $0203       ; Update sprite X
no_move_left:

check_right:
        LDA buttons
        AND #BUTTON_RIGHT
        BEQ movement_done
        
        ; Move right
        LDA player_x
        CLC
        ADC #2          ; Move 2 pixels right
        CMP #248        ; Right boundary
        BCS no_move_right ; Don't move if too far right
        STA player_x
        STA $0203       ; Update sprite X
no_move_right:

movement_done:
        RTS

buttons: .byte 0
```

## Step 5: VBlank Interrupt Handler

Handle the NMI interrupt for timing and graphics updates:

```asm6502
NMI:
        ; Save registers
        PHA
        TXA
        PHA
        TYA
        PHA

        ; Set VBlank flag for main loop
        LDA #1
        STA vblank_flag

        ; Update sprite positions
        JSR update_sprites

        ; Update scrolling if needed
        LDA scroll_x
        STA $2005       ; Set X scroll
        LDA scroll_y  
        STA $2005       ; Set Y scroll

        ; Increment frame counter
        INC frame_counter

        ; Restore registers
        PLA
        TAY
        PLA
        TAX
        PLA
        RTI

IRQ:
        ; IRQ not used in this example
        RTI
```

## Understanding NES Architecture

### CPU and PPU

The NES has two processors:
- **CPU (2A03)**: Runs game logic, handles input
- **PPU (2C02)**: Dedicated graphics processor

### Memory Layout

**CPU Address Space:**
- $0000-$07FF: Internal RAM (2KB)
- $2000-$2007: PPU registers
- $4000-$4017: APU and I/O registers
- $6000-$7FFF: Battery-backed RAM (if present)
- $8000-$FFFF: Program ROM

**PPU Address Space:**
- $0000-$1FFF: Pattern tables (character data)
- $2000-$2FFF: Nametables (background layout)
- $3000-$3EFF: Mirrors of nametables
- $3F00-$3FFF: Palette RAM

### Graphics System

**Backgrounds:**
- Tile-based: 32×30 tiles (256×240 pixels)
- 2 pattern tables holding 256 tiles each
- 4 palettes of 4 colors each

**Sprites:**
- 64 sprites maximum
- 8×8 or 8×16 pixels each  
- 8 sprites maximum per scanline
- 4 palettes of 4 colors each

## Common Issues

**Black screen:** Verify PPU setup and VBlank timing.

**Garbled graphics:** Check pattern table data and palette loading.

**No sprites:** Ensure DMA transfer and sprite data are correct.

**Controls not working:** Verify controller reading sequence.
