## Your First Parallax World

Let's build an Amiga program step by step, exploring the magic of bitplane graphics.

### Step 1: The Minimal Amiga Program

Create a new file called `crystal1.s` with the absolute basics:

```m68k
; Crystal Cascade - Lesson 1
; Your first Amiga parallax world

        SECTION CODE,CODE

start:
        ; Basic Amiga program structure
        move.l  #0,d0           ; Exit code 0
        rts                     ; Return to AmigaDOS
```

**What's happening:**
- `SECTION CODE,CODE` defines our program code section
- `move.l #0,d0` puts exit code 0 in data register D0
- `rts` returns to the AmigaDOS operating system

Build and test:
```bash
vasm68k_mot -Fhunkexe -o crystal1 crystal1.s
```

**To run in FS-UAE:**
1. Start FS-UAE with Workbench disk
2. Copy `crystal1` to the virtual Amiga
3. Open Shell and type `crystal1`
4. Program runs and exits cleanly

### Step 2: Initialize the Graphics System

Now let's take control of the Amiga's graphics hardware. **Replace your `start:` section:**

```m68k
start:
        ; Save system state
        move.l  $4.w,a6         ; Get ExecBase  
        move.l  #gfxname,a1     ; Graphics library name
        moveq   #0,d0           ; Any version
        jsr     -552(a6)        ; OpenLibrary()
        move.l  d0,gfxbase      ; Store graphics.library base
        
        ; Take over the display
        move.l  gfxbase,a6      ; Graphics library base
        jsr     -456(a6)        ; OwnBlitter()
        jsr     -228(a6)        ; WaitTOF() - wait for frame
        
        ; Set up our custom display
        bsr     setup_display
        
        ; Wait for user input (simplified)
        move.l  #1000000,d0     ; Simple delay counter
delay_loop:
        subq.l  #1,d0
        bne     delay_loop
        
        ; Restore system
        move.l  gfxbase,a6      ; Graphics library base  
        jsr     -458(a6)        ; DisownBlitter()
        
        ; Clean exit
        move.l  #0,d0
        rts

; Data section
        SECTION DATA,DATA
gfxname:
        dc.b    'graphics.library',0
        even

        SECTION BSS,BSS
gfxbase:
        ds.l    1               ; Graphics library base pointer
```

**New concepts:**
- `move.l $4.w,a6` - Get ExecBase (Amiga system base)
- `jsr -552(a6)` - Call OpenLibrary() system function
- `OwnBlitter()` and `DisownBlitter()` - Control graphics hardware
- `WaitTOF()` - Synchronize with video frame

### Step 3: Set Up Custom Bitplanes

The Amiga's magic comes from bitplanes - separate memory areas that combine to create rich graphics. **Add this subroutine:**

```m68k
setup_display:
        ; Disable display during setup
        move.w  #$0000,$dff096  ; DMACON - disable all DMA
        
        ; Set up bitplane pointers for 3 layers
        ; Background layer (bitplane 0)
        move.l  #background_data,$dff0e0    ; BPL1PTH/L
        
        ; Middle layer (bitplane 1)  
        move.l  #midground_data,$dff0e4     ; BPL2PTH/L
        
        ; Foreground layer (bitplane 2)
        move.l  #foreground_data,$dff0e8    ; BPL3PTH/L
        
        ; Configure display parameters
        move.w  #$3000,$dff100  ; BPLCON0 - 3 bitplanes, color mode
        move.w  #$0000,$dff102  ; BPLCON1 - no horizontal scroll yet
        move.w  #$0000,$dff104  ; BPLCON2 - standard priority
        
        ; Set display window  
        move.w  #$2c81,$dff08e  ; DIWSTRT - display window start
        move.w  #$2cc1,$dff090  ; DIWSTOP - display window stop
        
        ; Set data fetch window
        move.w  #$0038,$dff092  ; DDFSTRT - data fetch start  
        move.w  #$00d0,$dff094  ; DDFSTOP - data fetch stop
        
        ; Set up color palette for parallax layers
        move.w  #$0000,$dff180  ; COLOR00 - background (black)
        move.w  #$0004,$dff182  ; COLOR01 - background layer (dark blue)
        move.w  #$0048,$dff184  ; COLOR02 - middle layer (medium blue)
        move.w  #$008f,$dff186  ; COLOR03 - foreground layer (bright blue)
        move.w  #$0fff,$dff188  ; COLOR04 - crystals (white)
        move.w  #$0f80,$dff18a  ; COLOR05 - energy (yellow)
        move.w  #$0f08,$dff18c  ; COLOR06 - danger (red)
        move.w  #$00f0,$dff18e  ; COLOR07 - power (green)
        
        ; Enable display with bitplane DMA
        move.w  #$8380,$dff096  ; DMACON - enable display, bitplane, copper DMA
        
        rts
```

**Understanding Amiga Graphics:**
- `$dff0e0-$dff0e8` - Bitplane pointers (where graphics data lives)
- `$dff100` - BPLCON0 (bitplane control - how many planes, what mode)
- `$dff180-$dff18e` - Color palette registers
- `$dff096` - DMACON (DMA control - enables graphics hardware)

### Step 4: Create Parallax Background Data

Now we need graphics data for our three parallax layers. **Add this to your DATA section:**

```m68k
        SECTION DATA,DATA

; Background layer - distant crystals (slowest parallax)
background_data:
        dc.w    $0000,$0000,$0000,$0000,$0000,$0000,$0000,$0000  ; Empty row
        dc.w    $0100,$0000,$0000,$0000,$0000,$0000,$0000,$0080  ; Sparse crystals
        dc.w    $0000,$0000,$0000,$0000,$0000,$0000,$0000,$0000  ; Empty
        dc.w    $0000,$0000,$0200,$0000,$0000,$0040,$0000,$0000  ; More crystals
        dc.w    $0000,$0000,$0000,$0000,$0000,$0000,$0000,$0000  ; Pattern continues...
        ; ... (repeat pattern for full screen height)
        dcb.w   256*8,0         ; Fill rest with zeros (256 lines * 8 words/line)

; Middle layer - medium crystals (medium parallax speed)  
midground_data:
        dc.w    $0000,$0000,$0000,$0000,$0000,$0000,$0000,$0000
        dc.w    $0000,$0400,$0000,$0000,$0000,$0000,$0020,$0000  ; Larger crystals
        dc.w    $0000,$0000,$0000,$0000,$0000,$0000,$0000,$0000
        dc.w    $0800,$0000,$0000,$0100,$0000,$0000,$0000,$0010  ; Spread out
        dc.w    $0000,$0000,$0000,$0000,$0000,$0000,$0000,$0000
        dcb.w   256*8,0         ; Fill with pattern

; Foreground layer - large crystals (fastest parallax)
foreground_data:  
        dc.w    $0000,$0000,$0000,$0000,$0000,$0000,$0000,$0000
        dc.w    $0000,$0000,$0000,$0000,$0000,$0000,$0000,$0000
        dc.w    $1000,$0000,$0000,$0000,$0000,$0000,$0000,$0008  ; Big crystals
        dc.w    $0000,$0000,$0000,$0000,$0000,$0000,$0000,$0000
        dc.w    $0000,$0000,$2000,$0000,$0000,$0004,$0000,$0000  ; Sparse but visible
        dcb.w   256*8,0         ; Pattern continues
```

**Understanding Bitplane Data:**
- Each `dc.w` defines 16 pixels across the screen
- Multiple words per line create wider displays
- Each bitplane contributes one bit per pixel to the final color
- Different layers will scroll at different speeds for parallax effect

### Step 5: Add Crystal Animation

Let's make our world come alive with animated crystals. **Add this subroutine:**

```m68k
animate_crystals:
        ; Simple crystal pulse animation
        ; Cycle through crystal colors to create "energy" effect
        
        move.l  animation_counter,d0
        addq.l  #1,d0
        move.l  d0,animation_counter
        
        ; Change crystal colors based on frame counter
        andi.l  #$0f,d0         ; Keep in range 0-15
        
        ; Calculate color intensity
        move.w  d0,d1
        cmpi.w  #8,d1
        bcc     fade_down
        
        ; Fade up (0-7)
        lsl.w   #4,d1           ; Multiply by 16 for intensity
        ori.w   #$0f00,d1       ; Keep other color components
        move.w  d1,$dff188      ; COLOR04 - crystal color
        bra     crystal_done
        
fade_down:
        ; Fade down (8-15)  
        subi.w  #8,d1           ; Convert to 0-7 range
        neg.w   d1              ; Reverse: 7-0
        addq.w  #1,d1           ; Make 8-1
        lsl.w   #4,d1           ; Multiply by 16
        ori.w   #$0f00,d1       ; Maintain color base
        move.w  d1,$dff188      ; COLOR04 - crystal color
        
crystal_done:
        rts

        SECTION BSS,BSS
animation_counter:
        ds.l    1               ; Frame counter for animation
```

### Step 6: Create the Main Display Loop

Now let's put it all together with a proper display loop. **Replace your simple delay with:**

```m68k
        ; Set up our custom display
        bsr     setup_display
        
        ; Main display loop
main_loop:
        ; Wait for vertical blank (smooth 50Hz animation)
        move.l  gfxbase,a6
        jsr     -228(a6)        ; WaitTOF()
        
        ; Animate crystal effects
        bsr     animate_crystals
        
        ; Check for exit (simplified - just run for a while)
        move.l  animation_counter,d0
        cmpi.l  #500,d0         ; Run for ~10 seconds at 50Hz
        blt     main_loop
        
        ; Continue to cleanup...
```

### Step 7: Add Parallax Movement

The final touch - make our layers scroll at different speeds for true parallax! **Add this subroutine:**

```m68k
update_parallax:
        ; Update scroll positions for each layer
        move.l  scroll_bg,d0
        addq.l  #1,d0           ; Background scrolls 1 pixel per frame
        andi.l  #$0f,d0         ; Wrap at 16 pixels
        move.l  d0,scroll_bg
        
        move.l  scroll_mid,d1   
        addq.l  #2,d1           ; Midground scrolls 2 pixels per frame
        andi.l  #$0f,d1         ; Wrap at 16 pixels  
        move.l  d1,scroll_mid
        
        move.l  scroll_fg,d2
        addq.l  #4,d2           ; Foreground scrolls 4 pixels per frame
        andi.l  #$0f,d2         ; Wrap at 16 pixels
        move.l  d2,scroll_fg
        
        ; Apply scroll values to hardware
        ; Combine scroll values into BPLCON1 register
        move.w  d0,d3           ; Background scroll (bits 3-0)
        lsl.w   #4,d1           ; Middle scroll to bits 7-4
        or.w    d1,d3
        lsl.w   #4,d2           ; Foreground scroll to bits 11-8  
        or.w    d2,d3
        
        move.w  d3,$dff102      ; BPLCON1 - horizontal scroll register
        
        rts

        SECTION BSS,BSS
scroll_bg:      ds.l    1       ; Background scroll position
scroll_mid:     ds.l    1       ; Midground scroll position  
scroll_fg:      ds.l    1       ; Foreground scroll position
```

**Update your main loop to use parallax:**

```m68k
main_loop:
        ; Wait for vertical blank
        move.l  gfxbase,a6
        jsr     -228(a6)        ; WaitTOF()
        
        ; Update parallax scrolling
        bsr     update_parallax
        
        ; Animate crystal effects
        bsr     animate_crystals
        
        ; Check for exit
        move.l  animation_counter,d0
        cmpi.l  #500,d0
        blt     main_loop
```

## Understanding What We Built

### Amiga Hardware Architecture

The Amiga's graphics prowess comes from custom chips:

| Chip | Purpose |
|------|---------|
| **Agnus** | Controls DMA, memory access, bitplane data |
| **Denise** | Processes bitplane data into pixels and colors |
| **Paula** | Handles audio, disk, and some I/O |

### Bitplane Graphics System

The Amiga uses **bitplanes** instead of direct pixel data:
- Each bitplane contributes 1 bit per pixel
- 3 bitplanes = 8 colors (2³ combinations)
- Multiple layers can scroll independently
- Hardware combines bitplanes into final image

### 68000 Assembly Syntax

| Instruction | Purpose | Example |
|-------------|---------|---------|
| `move.l` | Move 32-bit data | `move.l #0,d0` |
| `move.w` | Move 16-bit data | `move.w d0,$dff096` |
| `jsr` | Jump to subroutine | `jsr -228(a6)` |
| `bsr` | Branch to subroutine | `bsr setup_display` |
| `rts` | Return from subroutine | `rts` |

### Custom Chip Registers

Key hardware addresses we used:

| Register | Address | Purpose |
|----------|---------|---------|
| `DMACON` | `$dff096` | DMA control (enables graphics) |
| `BPLCON0` | `$dff100` | Bitplane configuration |
| `BPLCON1` | `$dff102` | Horizontal scroll control |
| `BPLxPTH/L` | `$dff0e0+` | Bitplane data pointers |
| `COLORxx` | `$dff180+` | Color palette registers |
