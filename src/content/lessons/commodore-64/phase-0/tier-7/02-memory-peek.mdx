# Memory Peek

**See exactly what the VIC-II and SID are doing under the hood.**

<PrerequisiteBox system="commodore-64" phase={0} lessonNumber={98} />

## Build a live monitor

<TryItNow>
```basic
10 REM MEMORY PEEK MONITOR
20 PRINT CHR$(147)
30 PRINT "SPRITE0 X:";PEEK(53248);"  Y:";PEEK(53249)
40 PRINT "BORDER:";PEEK(53280);"  BACK:";PEEK(53281)
50 JOY = PEEK(56320)
60 PRINT "JOYSTICK RAW:";JOY
70 OFFSET = 1024 + 10*40 + 15
80 CHARCODE = PEEK(OFFSET)
90 COLORCODE = PEEK(55296 + 10*40 + 15)
100 PRINT "SCREEN(10,15) CHAR:";CHARCODE;" COLOR:";COLORCODE
110 FOR I=1 TO 200: NEXT
120 GOTO 30
```
</TryItNow>

The loop reads sprite coordinates, background colors, joystick input, and screen RAM values. Watching these numbers change helps you diagnose gameplay bugs without instrumenting loads of print statements.

<InfoBox>
Remember: screen RAM lives at `$0400` (1024 decimal), color RAM at `$D800` (55296). Combine row and column to compute offsets whenever you need to peek tiles or update HUDs efficiently.
</InfoBox>
