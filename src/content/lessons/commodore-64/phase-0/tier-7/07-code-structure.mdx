## Build a state dispatcher

<TryItNow>
```basic
10 REM STRUCTURED MAIN LOOP
20 GOSUB 9000 : REM init
30 DO
40 ON STATE GOSUB 2000,3000,4000,5000
50 LOOP

2000 REM STATE 1 - TITLE
2010 GOSUB 6000 : REM draw logo
2020 IF KEY$="SPACE" THEN STATE=2
2030 RETURN

3000 REM STATE 2 - DUNGEON
3010 GOSUB 6100 : REM render room
3020 GOSUB 6200 : REM handle input
3030 IF EXITFLAG THEN STATE=3
3040 RETURN

4000 REM STATE 3 - PAUSE
4010 GOSUB 6300 : REM show menu
4020 IF KEY$="C" THEN STATE=2
4030 IF KEY$="Q" THEN STATE=4
4040 RETURN

5000 REM STATE 4 - GAME OVER
5010 GOSUB 6400
5020 END
```
</TryItNow>

Each state gets its own line-number block, while shared routines live in the 6000+ range. The main loop never bloats, because it simply dispatches on `STATE` and loops. Debugging becomes easier since you know exactly where to look for title, dungeon, pause, and game-over logic.

<InfoBox>
Document your numbering scheme at the top of the listing. When team members add features—AI, inventory, events—they know where to slot their routines without stepping on existing code.
</InfoBox>
