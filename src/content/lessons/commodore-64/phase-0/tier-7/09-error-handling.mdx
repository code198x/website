# Error Handling

**Make crashes informative, not catastrophic.**

<PrerequisiteBox system="commodore-64" phase={0} lessonNumber={105} />

## Trap and recover

<TryItNow>
```basic
10 REM ERROR HANDLER DEMO
20 ON ERROR GOTO 9000
30 INPUT "ENTER UNITS";U
40 IF U < 0 THEN ERROR 21
50 PRINT "PROCESSING";U
60 END

9000 REM ERROR TRAP
9010 PRINT "*** RUNTIME ERROR";ERR;" AT LINE";ERL
9020 IF ERR = 21 THEN PRINT "NEGATIVE UNITS NOT ALLOWED"
9030 PRINT "(R)ETRY OR (Q)UIT?"
9040 GET K$ : IF K$="" THEN 9040
9050 IF K$="R" THEN RESUME
9060 IF K$="Q" THEN END
9070 RESUME
```
</TryItNow>

The trap reports the BASIC error code (`ERR`) and the offending line (`ERL`). Custom errors (like code 21 in this example) let you unify validation across the game: throw `ERROR 21` when trades go wrong, then present a friendly message here.

<InfoBox>
Remember to `RESUME` or `RESUME NEXT`; otherwise the program remains in the handler indefinitely. For disk routines, log the file name and slot as well so testers can reproduce the issue.
</InfoBox>
