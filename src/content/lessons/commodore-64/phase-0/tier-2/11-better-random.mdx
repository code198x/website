## The Problem with "Random"

Without proper seeding, the C64's RND function generates the same sequence of "random" numbers every time you run the program. This was a major issue for early games - players could memorize patterns! Let's fix this:

<TryItNow>
```basic
10 REM ENHANCED RANDOM - TRUE RANDOMIZATION
15 DATA "TRY THE MIDDLE!", "NARROW YOUR RANGE!", "GETTING CLOSER!"
20 WHITE$ = CHR$(5): RED$ = CHR$(28): GREEN$ = CHR$(30)
25 PURPLE$ = CHR$(156): YELLOW$ = CHR$(158): OFF$ = CHR$(159)
30 REM DEMONSTRATE BAD RANDOMIZATION
35 PRINT CHR$(147)
40 PRINT WHITE$; "PREDICTABLE RANDOM DEMO"; OFF$
45 PRINT STRING$(30, "─")
50 PRINT "WITHOUT RANDOMIZE (SAME EVERY TIME):"
55 FOR I = 1 TO 5
60 SECRET = INT(RND(1)*100) + 1
65 PRINT "NUMBER"; I; ":", SECRET
70 NEXT I
75 PRINT: PRINT "PRESS ENTER TO SEE IMPROVED VERSION": INPUT A$
80 REM NOW WITH PROPER RANDOMIZATION
85 RANDOMIZE TI REM SEED WITH TIMER!
90 PRINT: PRINT YELLOW$; "WITH RANDOMIZE TI (UNPREDICTABLE):"; OFF$
95 FOR I = 1 TO 5
100 SECRET = INT(RND(1)*100) + 1
105 PRINT "NUMBER"; I; ":", SECRET
110 NEXT I
115 PRINT: PRINT GREEN$; "MUCH BETTER!"; OFF$
120 PRINT "TI VALUE USED FOR SEED:", TI
125 END
```
</TryItNow>

**The Magic of RANDOMIZE TI:**
- **Line 85:** RANDOMIZE TI uses the current timer value as a seed
- **Every run is different** because TI is always changing
- **No more predictable patterns** - true randomness!

<InfoBox>
TI (Timer Interrupt) counts constantly in the background, so it's different every time you run your program. This makes it perfect for seeding the random number generator with an unpredictable value!
</InfoBox>

## Weighted Random Systems

Sometimes you want certain outcomes to be more likely than others. Let's create intelligent probability systems:

<TryItNow>
```basic
10 REM WEIGHTED RANDOM PROBABILITY
15 WHITE$ = CHR$(5): RED$ = CHR$(28): GREEN$ = CHR$(30)
20 PURPLE$ = CHR$(156): YELLOW$ = CHR$(158): OFF$ = CHR$(159)
25 RANDOMIZE TI REM ALWAYS SEED FIRST!
30 PRINT CHR$(147)
35 PRINT WHITE$; "WEIGHTED PROBABILITY DEMO"; OFF$
40 PRINT STRING$(30, "═")
45 REM DEMONSTRATE DIFFERENT PROBABILITY RANGES
50 PRINT: PRINT YELLOW$; "TESTING 100 RANDOM EVENTS:"; OFF$
55 EASY_COUNT = 0: MEDIUM_COUNT = 0: HARD_COUNT = 0: BONUS_COUNT = 0
60 FOR I = 1 TO 100
65 ROLL = INT(RND(1)*100) + 1 REM 1-100
70 REM WEIGHTED OUTCOMES
75 IF ROLL <= 50 THEN EASY_COUNT = EASY_COUNT + 1: GOTO 95
80 IF ROLL <= 80 THEN MEDIUM_COUNT = MEDIUM_COUNT + 1: GOTO 95
85 IF ROLL <= 95 THEN HARD_COUNT = HARD_COUNT + 1: GOTO 95
90 BONUS_COUNT = BONUS_COUNT + 1 REM 5% CHANCE
95 NEXT I
100 REM SHOW RESULTS
105 PRINT: PRINT "PROBABILITY RESULTS:"
110 PRINT GREEN$; "EASY (50%)    :"; EASY_COUNT; "/100"; OFF$
115 PRINT YELLOW$; "MEDIUM (30%)  :"; MEDIUM_COUNT; "/100"; OFF$
120 PRINT RED$; "HARD (15%)    :"; HARD_COUNT; "/100"; OFF$
125 PRINT PURPLE$; "BONUS (5%)    :"; BONUS_COUNT; "/100"; OFF$
130 PRINT: PRINT "PRESS ENTER FOR GAME APPLICATION": INPUT A$
135 REM GAME APPLICATION
140 GOSUB 1000 REM SMART DIFFICULTY SELECTION
145 END
1000 REM SMART RANDOM DIFFICULTY
1005 PRINT CHR$(147)
1010 PRINT WHITE$; "SMART DIFFICULTY SELECTION"; OFF$
1015 PRINT "GENERATING 10 CHALLENGES..."
1020 PRINT STRING$(30, "─")
1025 FOR I = 1 TO 10
1030 CHANCE = INT(RND(1)*100) + 1
1035 IF CHANCE <= 40 THEN DIFF$ = GREEN$ + "EASY" + OFF$: RANGE = 50
1040 IF CHANCE > 40 AND CHANCE <= 70 THEN DIFF$ = YELLOW$ + "MEDIUM" + OFF$: RANGE = 100
1045 IF CHANCE > 70 AND CHANCE <= 90 THEN DIFF$ = RED$ + "HARD" + OFF$: RANGE = 200
1050 IF CHANCE > 90 THEN DIFF$ = PURPLE$ + "EXPERT" + OFF$: RANGE = 500
1055 SECRET = INT(RND(1)*RANGE) + 1
1060 PRINT "CHALLENGE"; I; ":", DIFF$, "NUMBER 1-" + STR$(RANGE), "SECRET:" + STR$(SECRET)
1065 NEXT I
1070 RETURN
```
</TryItNow>

**Weighted Probability Breakdown:**
- **50% Easy** (rolls 1-50): Beginner-friendly challenges
- **30% Medium** (rolls 51-80): Standard gameplay
- **15% Hard** (rolls 81-95): Increased difficulty
- **5% Expert** (rolls 96-100): Rare, extreme challenges

This creates natural difficulty curves that feel balanced!

## Advanced Random Algorithms

Let's build even smarter random systems that avoid boring repetition:

<TryItNow>
```basic
10 REM ADVANCED SMART RANDOM
15 DATA "TRY THE MIDDLE!", "NARROW YOUR RANGE!", "GETTING CLOSER!"
20 WHITE$ = CHR$(5): RED$ = CHR$(28): GREEN$ = CHR$(30)
25 PURPLE$ = CHR$(156): YELLOW$ = CHR$(158): OFF$ = CHR$(159)
30 RANDOMIZE TI
35 PRINT CHR$(147)
40 PRINT WHITE$; "SMART RANDOM ALGORITHMS"; OFF$
45 PRINT STRING$(30, "═")
50 REM AVOID REPETITION SYSTEM
55 DIM RECENT(5) REM TRACK LAST 5 NUMBERS
60 RECENT_COUNT = 0: SECRET = 0
65 GOSUB 2000 REM GENERATE SMART NUMBER
70 PRINT "SMART RANDOM NUMBER:", SECRET
75 PRINT "PRESS ENTER FOR DEMO": INPUT A$
80 REM DEMONSTRATE 20 SMART NUMBERS
85 PRINT: PRINT YELLOW$; "20 SMART NUMBERS (NO RECENT REPEATS):"; OFF$
90 FOR I = 1 TO 20
95 GOSUB 2000 REM SMART GENERATION
100 PRINT SECRET;
105 IF I MOD 10 = 0 THEN PRINT REM NEW LINE EVERY 10
110 NEXT I
115 PRINT: PRINT: PRINT GREEN$; "NOTICE: NO IMMEDIATE REPETITION!"; OFF$
120 END
2000 REM SMART NUMBER GENERATOR
2005 ATTEMPTS = 0
2010 REM GENERATE CANDIDATE
2015 NEW_SECRET = INT(RND(1)*50) + 1
2020 ATTEMPTS = ATTEMPTS + 1
2025 REM CHECK IF TOO RECENT
2030 FOR J = 1 TO RECENT_COUNT
2035 IF NEW_SECRET = RECENT(J) THEN 2010 REM TRY AGAIN
2040 NEXT J
2045 REM ACCEPT THIS NUMBER
2050 SECRET = NEW_SECRET
2055 REM ADD TO RECENT LIST
2060 RECENT_COUNT = RECENT_COUNT + 1
2065 IF RECENT_COUNT > 5 THEN RECENT_COUNT = 5
2070 REM SHIFT ARRAY DOWN
2075 FOR K = RECENT_COUNT TO 2 STEP -1
2080 RECENT(K) = RECENT(K-1)
2085 NEXT K
2090 RECENT(1) = SECRET REM NEW NUMBER AT FRONT
2095 RETURN
```
</TryItNow>

**Smart Algorithm Features:**
- **Anti-repetition system** prevents boring repeated numbers
- **Sliding window** of 5 recent numbers
- **Automatic retry** if number was used recently
- **Natural variety** without true duplicates

Early computer games had a reputation for being "too predictable" because programmers forgot to seed their random number generators.
