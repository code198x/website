## State Management

Pause isn't just stopping - it's elegant state management that preserves everything while allowing menus to function:

<TryItNow>
```basic
10 REM PAUSE SYSTEM WITH STATE MANAGEMENT
15 WHITE$ = CHR$(5): YELLOW$ = CHR$(158): CYAN$ = CHR$(159)
20 OFF$ = CHR$(144): BLINK$ = CHR$(15): NOBLINK$ = CHR$(143)
25 PRINT CHR$(147)
30 PRINT WHITE$; "PAUSE SYSTEM DEMO"; OFF$
35 PRINT STRING$(40, "═")
40 REM GAME STATE VARIABLES
45 PAUSED = 0: PAUSE_DEBOUNCE = 0
50 SCORE = 0: LEVEL = 1: LIVES = 3
55 REM MOVING OBJECTS
60 DIM OBJ_X(5), OBJ_Y(5), OBJ_VX(5), OBJ_VY(5)
65 FOR I = 1 TO 5
70   OBJ_X(I) = RND(1) * 36 + 2
75   OBJ_Y(I) = RND(1) * 15 + 6
80   OBJ_VX(I) = (RND(1) - 0.5) * 2
85   OBJ_VY(I) = (RND(1) - 0.5) * 2
90 NEXT I
95 FRAME = 0: PAUSE_FRAME = 0
100 REM MAIN GAME LOOP
105 FRAME = FRAME + 1
110 REM HANDLE PAUSE TOGGLE
115 GET KEY$
120 IF KEY$ = "P" AND PAUSE_DEBOUNCE = 0 THEN
125   PAUSED = 1 - PAUSED: REM TOGGLE PAUSE
130   PAUSE_DEBOUNCE = 10
135   IF PAUSED = 1 THEN PAUSE_FRAME = 0
140 END IF
145 IF PAUSE_DEBOUNCE > 0 THEN PAUSE_DEBOUNCE = PAUSE_DEBOUNCE - 1
150 REM CHECK PAUSE STATE
155 IF PAUSED = 1 THEN GOTO 400
160 REM NORMAL GAME UPDATE
165 REM CLEAR SCREEN
170 FOR Y = 5 TO 23: PRINT CHR$(19);
175   FOR Z = 1 TO Y: PRINT CHR$(17);: NEXT Z
180   PRINT STRING$(40, " ")
185 NEXT Y
190 REM UPDATE OBJECTS (ONLY WHEN NOT PAUSED)
195 FOR I = 1 TO 5
200   OBJ_X(I) = OBJ_X(I) + OBJ_VX(I)
205   OBJ_Y(I) = OBJ_Y(I) + OBJ_VY(I)
210   REM BOUNCE OFF WALLS
215   IF OBJ_X(I) < 1 OR OBJ_X(I) > 38 THEN OBJ_VX(I) = -OBJ_VX(I)
220   IF OBJ_Y(I) < 5 OR OBJ_Y(I) > 23 THEN OBJ_VY(I) = -OBJ_VY(I)
225   REM DRAW OBJECT
230   PRINT CHR$(19);: FOR Z = 1 TO INT(OBJ_Y(I)): PRINT CHR$(17);: NEXT Z
235   PRINT TAB(INT(OBJ_X(I))); CYAN$; "●"; OFF$
240 NEXT I
245 REM UPDATE SCORE
250 SCORE = SCORE + 1
255 REM DRAW HUD
260 PRINT CHR$(19); CHR$(19); TAB(2);
265 PRINT "SCORE: "; SCORE; "  LEVEL: "; LEVEL;
270 PRINT "  LIVES: "; LIVES
275 PRINT CHR$(17); TAB(2); "PRESS [P] TO PAUSE"
280 REM HANDLE OTHER CONTROLS
285 IF KEY$ = "Q" THEN END
290 IF KEY$ = "+" AND LIVES < 9 THEN LIVES = LIVES + 1
295 IF KEY$ = "-" AND LIVES > 1 THEN LIVES = LIVES - 1
300 GOTO 350
400 REM PAUSE MODE
405 PAUSE_FRAME = PAUSE_FRAME + 1
410 REM DRAW PAUSE OVERLAY
415 PRINT CHR$(19);: FOR Z = 1 TO 12: PRINT CHR$(17);: NEXT Z
420 PRINT TAB(15);
425 IF (PAUSE_FRAME / 10) MOD 2 = 0 THEN
430   PRINT BLINK$; YELLOW$; "* PAUSED *"; OFF$; NOBLINK$
435 ELSE
440   PRINT YELLOW$; "* PAUSED *"; OFF$
445 END IF
450 REM SHOW PAUSE MENU
455 PRINT CHR$(19);: FOR Z = 1 TO 14: PRINT CHR$(17);: NEXT Z
460 PRINT TAB(12); WHITE$; "[P] - RESUME GAME"; OFF$
465 PRINT CHR$(17); TAB(12); "[Q] - QUIT GAME"
470 REM HANDLE PAUSE CONTROLS
475 GET KEY$
480 IF KEY$ = "P" AND PAUSE_DEBOUNCE = 0 THEN
485   PAUSED = 0: PAUSE_DEBOUNCE = 10
490 END IF
495 IF KEY$ = "Q" THEN END
500 IF PAUSE_DEBOUNCE > 0 THEN PAUSE_DEBOUNCE = PAUSE_DEBOUNCE - 1
350 REM FRAME DELAY
355 FOR D = 1 TO 50: NEXT D
360 GOTO 105
```
</TryItNow>

**Pause Features:**
- **State preservation** (200-240) - Objects freeze in place
- **Toggle with debounce** (120-145) prevents double-triggers
- **Visual feedback** (425-445) with blinking "PAUSED" text
- **Pause menu** (450-465) shows available options
- **Score continues counting** only when unpaused

`★ Insight ─────────────────────────────────────`
**The debounce mechanism prevents pause flickering** - without it, a single keypress might toggle pause multiple times per second. This pattern appears everywhere in game programming: button presses, menu navigation, and state changes all need this "cooldown" period.
