## Consistent Frame Rate

Professional games run at the same speed whether there's one asteroid or twenty. Here's how to achieve that consistency:

<TryItNow>
```basic
10 REM FRAME RATE CONTROL SYSTEM
15 WHITE$ = CHR$(5): GREEN$ = CHR$(30): YELLOW$ = CHR$(158)
20 RED$ = CHR$(28): CYAN$ = CHR$(159): OFF$ = CHR$(144)
25 PRINT CHR$(147)
30 PRINT WHITE$; "FRAME RATE CONTROL"; OFF$
35 PRINT STRING$(40, "═")
40 REM TIMING VARIABLES
45 TI$ = "000000": REM RESET TIMER
50 FPS = 30: REM TARGET FRAMES PER SECOND
55 FRAME_TIME = 60 / FPS: REM TICKS PER FRAME
60 NEXT_FRAME = TI + FRAME_TIME
65 REM PERFORMANCE MONITORING
70 FRAME_COUNT = 0: ACTUAL_FPS = 0
75 FPS_TIMER = TI + 60: REM UPDATE FPS EVERY SECOND
80 REM GAME OBJECTS
85 DIM OBJ_X(20), OBJ_Y(20), OBJ_VX(20), OBJ_VY(20)
90 FOR I = 1 TO 20
95   OBJ_X(I) = RND(1) * 38 + 1
100   OBJ_Y(I) = RND(1) * 18 + 5
105   OBJ_VX(I) = (RND(1) - 0.5) * 2
110   OBJ_VY(I) = (RND(1) - 0.5) * 2
115 NEXT I
120 REM DIFFICULTY CONTROL
125 NUM_OBJECTS = 5: MODE$ = "EASY"
130 REM MAIN GAME LOOP
135 FRAME_START = TI
140 REM CLEAR SCREEN
145 FOR Y = 5 TO 23: PRINT CHR$(19);
150   FOR Z = 1 TO Y: PRINT CHR$(17);: NEXT Z
155   PRINT STRING$(40, " ")
160 NEXT Y
165 REM UPDATE OBJECTS
170 FOR I = 1 TO NUM_OBJECTS
175   REM APPLY VELOCITY WITH DELTA TIME
180   DELTA = (TI - FRAME_START) / 60
185   OBJ_X(I) = OBJ_X(I) + OBJ_VX(I)
190   OBJ_Y(I) = OBJ_Y(I) + OBJ_VY(I)
195   REM BOUNCE OFF WALLS
200   IF OBJ_X(I) < 1 OR OBJ_X(I) > 38 THEN OBJ_VX(I) = -OBJ_VX(I)
205   IF OBJ_Y(I) < 5 OR OBJ_Y(I) > 23 THEN OBJ_VY(I) = -OBJ_VY(I)
210   REM DRAW OBJECT
215   PRINT CHR$(19);: FOR Z = 1 TO INT(OBJ_Y(I)): PRINT CHR$(17);: NEXT Z
220   PRINT TAB(INT(OBJ_X(I)));
225   IF I <= 5 THEN PRINT GREEN$; "o"; OFF$
230   IF I > 5 AND I <= 10 THEN PRINT YELLOW$; "*"; OFF$
235   IF I > 10 THEN PRINT RED$; "×"; OFF$
240 NEXT I
245 REM DRAW FPS COUNTER
250 PRINT CHR$(19); CHR$(19); TAB(2);
255 PRINT "FPS: "; ACTUAL_FPS; "/"; FPS
260 PRINT CHR$(17); TAB(2); "MODE: "; MODE$;
265 PRINT " OBJECTS: "; NUM_OBJECTS
270 REM UPDATE FPS COUNTER
275 FRAME_COUNT = FRAME_COUNT + 1
280 IF TI >= FPS_TIMER THEN
285   ACTUAL_FPS = FRAME_COUNT
290   FRAME_COUNT = 0
295   FPS_TIMER = TI + 60
300 END IF
305 REM CONTROLS
310 GET KEY$: IF KEY$ = "" THEN 355
315 IF KEY$ = "1" THEN NUM_OBJECTS = 5: MODE$ = "EASY"
320 IF KEY$ = "2" THEN NUM_OBJECTS = 10: MODE$ = "MEDIUM"
325 IF KEY$ = "3" THEN NUM_OBJECTS = 20: MODE$ = "HARD"
330 IF KEY$ = "F" THEN FPS = 60: FRAME_TIME = 1: REM FAST
335 IF KEY$ = "N" THEN FPS = 30: FRAME_TIME = 2: REM NORMAL
340 IF KEY$ = "S" THEN FPS = 15: FRAME_TIME = 4: REM SLOW
345 IF KEY$ = "Q" THEN END
355 REM WAIT FOR NEXT FRAME
360 IF TI < NEXT_FRAME THEN 360
365 REM HANDLE FRAME SKIP
370 IF TI > NEXT_FRAME + FRAME_TIME THEN
375   REM WE'RE RUNNING BEHIND - SKIP RENDERING
380   NEXT_FRAME = TI + FRAME_TIME
385 ELSE
390   NEXT_FRAME = NEXT_FRAME + FRAME_TIME
395 END IF
400 GOTO 135
```
</TryItNow>

**Timing Features:**
- **Fixed frame rate** (50-60) maintains consistent speed
- **Delta time** (180) compensates for processing variations
- **Frame skipping** (370-385) handles heavy load gracefully
- **FPS monitoring** (275-300) shows actual performance
- **Adjustable targets** (330-340) for testing different speeds

`★ Insight ─────────────────────────────────────`
**The frame skip logic is crucial** - when the game can't keep up, it's better to skip rendering than let the game slow down. This "temporal resolution" trade-off keeps gameplay responsive even under stress. Modern games still use this technique, choosing between 30 and 60 FPS dynamically.
