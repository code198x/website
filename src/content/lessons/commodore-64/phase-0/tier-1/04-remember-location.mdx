# String Variables

**Words have power! Learn to store text in variables and give your adventure game a voice that remembers what it says**

<PrerequisiteBox system="commodore-64" phase={0} lessonNumber={4} />

## Beyond Numbers: Storing Text

So far we've used variables to store numbers like room numbers and scores. But games need to remember text too - things like player names, room descriptions, and messages. That's where string variables come in!

A string variable stores text instead of numbers. In C64 BASIC, string variables are just like regular variables, but they end with a dollar sign ($).

<TryItNow>
```basic
10 REM MYSTERY CAVE - A TEXT ADVENTURE
20 N$ = "BRAVE ADVENTURER"
30 L$ = "MYSTERIOUS CAVE ENTRANCE"
40 PRINT "HELLO, "; N$; "!"
50 PRINT "YOU ARE AT THE "; L$
```
</TryItNow>

Notice how the text in string variables must be enclosed in quotation marks when we assign it, but not when we use it in PRINT!

## String Variable Rules

String variables follow the same naming rules as numeric variables, plus one special requirement:

**String Variable Naming:**
- Same length rules: 1 or 2 characters
- Must end with a dollar sign ($)
- Examples: `N$`, `A$`, `RM$`, `X1$`

**Valid String Variable Names:**
- `N$` - Name
- `RM$` - Room description
- `A$` - Action or answer
- `M1$` - Message 1

<InfoBox>
**Why the Dollar Sign?** In the 1970s and early 1980s, many programming languages used special characters to indicate variable types. The $ for strings was borrowed from older computer systems and became standard in many BASIC dialects.
</InfoBox>

## Building Our Cave's Voice

Let's create string variables to store different room descriptions:

<TryItNow>
```basic
10 REM MYSTERY CAVE - A TEXT ADVENTURE
20 REM STRING VARIABLES FOR DESCRIPTIONS
30 R1$ = "CAVE ENTRANCE - MOSS-COVERED OPENING"
40 R2$ = "DARK TUNNEL - WATER DRIPS CONSTANTLY"
50 R3$ = "UNDERGROUND CHAMBER - STRANGE ECHOES"
60 PRINT CHR$(147)
70 PRINT "==============================="
80 PRINT "       MYSTERY CAVE"
90 PRINT "==============================="
100 PRINT
110 PRINT "ROOM 1: "; R1$
120 PRINT "ROOM 2: "; R2$
130 PRINT "ROOM 3: "; R3$
```
</TryItNow>

Now our cave is starting to have personality! Each room has its own unique description stored in a string variable.

## Combining Strings and Numbers

The real magic happens when you combine string variables with the numeric variables we learned yesterday:

<TryItNow>
```basic
10 REM MYSTERY CAVE - A TEXT ADVENTURE
20 REM GAME VARIABLES
30 RM = 1: HP = 100: SC = 0
40 N$ = "ADVENTURER"
50 L$ = "ENTRANCE TO MYSTERY CAVE"
60 S$ = "EXPLORING THE DEPTHS"
70 PRINT CHR$(147)
80 PRINT "PLAYER: "; N$
90 PRINT "STATUS: "; S$
100 PRINT "LOCATION: "; L$
110 PRINT "ROOM NUMBER: "; RM
120 PRINT "HEALTH: "; HP; " POINTS"
130 PRINT "SCORE: "; SC; " POINTS"
```
</TryItNow>

Perfect! Now our game can track both numbers (room, health, score) and text (name, location, status).

## String Operations

You can do some interesting things with strings:

<TryItNow>
```basic
10 REM STRING EXPERIMENTS
20 F$ = "MYSTERY"
30 L$ = "CAVE"
40 PRINT F$; " "; L$        : REM PRINTS: MYSTERY CAVE
50 PRINT F$ + " " + L$      : REM SAME RESULT USING +
60 G$ = "HELLO, " + N$ + "!"
70 N$ = "BRAVE EXPLORER"
80 PRINT G$                 : REM PRINTS: HELLO, BRAVE EXPLORER!
```
</TryItNow>

The + sign with strings joins them together - this is called "concatenation."

## Try These Experiments

1. **Create character variables:** Make `C1$`, `C2$`, `C3$` for different characters the player might meet
2. **Message variables:** Create `M1$`, `M2$`, `M3$` for different game messages
3. **Mix and match:** Combine a string with a number: `"ROOM " + STR$(RM)`
4. **Create atmosphere:** Make variables for sounds: `SD1$ = "DRIP... DRIP... DRIP"`

## Your Challenge
