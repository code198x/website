# Sound Priority

**Make sure explosions aren’t drowned out by coin pickups.**

<PrerequisiteBox system="commodore-64" phase={0} lessonNumber={78} />

## Simple priority queue

<TryItNow>
```basic
10 REM SID SFX PRIORITY
20 ACTIVEPRI = 0 : TIMER = 0
30 RESTORE 40
40 DATA 1,40, 3,80, 2,50, 4,90, 1,40
50 FOR STEP = 0 TO 4
60 READ PRI,LEN
70 GOSUB 200
80 GOSUB 260
90 NEXT
100 END

200 REM REQUEST SFX
210 IF PRI <= ACTIVEPRI AND TIMER > 0 THEN RETURN
220 ACTIVEPRI = PRI
230 TIMER = LEN
240 GOSUB 300
250 RETURN

260 REM COUNTDOWN BETWEEN FRAMES
270 IF TIMER > 0 THEN TIMER = TIMER - 10
280 IF TIMER <= 0 THEN ACTIVEPRI = 0
290 RETURN

300 REM PLAY EFFECT ON VOICE 2
310 BASE = 54272 + 7
320 POKE BASE+5,0*16+2 : POKE BASE+6,0*16+2
330 FREQ = 60 + PRI*50
340 POKE BASE+1,FREQ : POKE BASE,3
350 POKE BASE+4,129 : FOR T=1 TO LEN : NEXT
360 POKE BASE+4,128
370 RETURN
```
</TryItNow>

Each request includes a priority and duration. Higher-priority effects interrupt the current sound immediately; lower ones wait until the active timer expires. Tick routine 260 runs each frame to release the channel when the timer falls to zero.

<InfoBox>
Extend this pattern by buffering low-priority cues in an array, then retrying them once the channel frees up. The important part: keep a single source of truth (`ACTIVEPRI`, `TIMER`) so voices never fight.
</InfoBox>
