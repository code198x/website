# Sprite System

## Manage a sprite pool

<TryItNow>
```basic
10 REM SPRITE MANAGER CORE
20 MAX=15
30 DIM SX(MAX),SY(MAX),FRAME(MAX),STATE(MAX)
40 DIM ACTIVE(MAX)
50 REM spawn example
60 IDX=FREEIDX()
70 IF IDX>=0 THEN GOSUB SPAWNPLAYERBOLT
80 GOSUB UPDATESPRITES
90 GOSUB RENDERSPRITES
100 END

200 REM FIND FREE SLOT
210 FUNCTION FREEIDX()
220 FOR I=0 TO MAX
230 IF ACTIVE(I)=0 THEN ACTIVE(I)=1: FREEIDX=I: RETURN
240 NEXT
250 FREEIDX=-1: RETURN

300 REM SPAWN BOLT
310 SX(IDX)=PLAYERX
320 SY(IDX)=PLAYERY-12
330 FRAME(IDX)=0
340 STATE(IDX)=BOLT
350 RETURN

400 REM UPDATE LOOP
410 FOR I=0 TO MAX
420 IF ACTIVE(I)=0 THEN NEXT
430 SY(I)=SY(I)-4
440 IF SY(I)<0 THEN ACTIVE(I)=0
450 NEXT
460 RETURN

500 REM RENDER + MULTIPLEX
510 CALLMULTIPLEX SX(),SY(),FRAME(),STATE()
520 RETURN
```
</TryItNow>

The pool reuses sprite slots instead of creating new variables each time. Use `STATE()` to store type-specific data (enemy, bolt, debris) and tie into the multiplex routine assembled in Tier 7.

<InfoBox>
Pack frequently accessed attributes (x, y, frame, color) into contiguous arrays to help assembly helpers. Keep high-level state (HP, timers) in separate arrays or tables referenced by index.
</InfoBox>

Ensure this system runs before your raster split so all sprite X/Y values are ready when the interrupt fires.
