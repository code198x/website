# Multiple Choice Logic: Jump Tables and Decision Trees
**Build sophisticated menu systems and AI behavior using elegant multi-way branching**

You've learned to make simple either/or decisions with branches and comparisons. But real games need to handle complex choices: main menus with multiple options, AI characters that can choose from several behaviors, weapon selection systems, difficulty settings, and game mode selection. Today you'll discover how to build elegant decision trees that can handle any number of choices efficiently and maintainably.

## Conceptual Overview

### Understanding Multiple Choice Logic

When you walk into a restaurant, you don't just decide "eat" or "don't eat" - you choose from many options on the menu. Similarly, games need to handle multiple choices efficiently. There are two main approaches: **decision chains** (like asking "is it choice A? No, is it choice B? No, is it choice C?") and **jump tables** (like having a direct index to each choice).

Decision chains are simple but can be slow with many options. Jump tables are lightning-fast but require more setup. The key is choosing the right tool for each situation.

### How It Works on the Commodore 64

The 6502 provides several techniques for multi-way branching:

**Decision Chains** - Sequential comparisons with branches:
```asm
    lda choice
    cmp #1
    beq option_1
    cmp #2
    beq option_2
    cmp #3
    beq option_3
    jmp default_option
```

**Jump Tables** - Direct indexing into address tables:
```asm
    lda choice        ; Get choice (0-3)
    asl               ; Multiply by 2 (addresses are 2 bytes)
    tax               ; Use as index
    lda jump_table,x  ; Get low byte of address
    sta jump_address
    lda jump_table+1,x ; Get high byte
    sta jump_address+1
    jmp (jump_address) ; Indirect jump to chosen routine
```

```asm
    cmp #'2'
    beq select_two_player
    cmp #'3'
    beq select_options
    cmp #'4'
    beq select_high_scores
    cmp #'5'
    beq select_quit
    ; Invalid key - ignore
    jmp no_key_main

select_single_player:
    lda #1
    sta game_mode
    jsr show_class_selection
    rts

select_two_player:
    lda #2
    sta game_mode
    jsr show_class_selection
    rts

select_options:
    jsr show_options_menu
    rts

select_high_scores:
    jsr show_high_scores
    rts

select_quit:
    jsr show_quit_message
    rts

no_key_main:
    rts

; Example 2: Jump Table for Class Selection
show_class_selection:
    jsr clear_screen
    jsr display_class_menu

class_loop:
    jsr scan_keyboard
    lda key_pressed
    beq class_loop      ; Wait for key

    ; Validate choice (1-4)
    cmp #'1'
    bcc invalid_class   ; Less than '1'
    cmp #'5'
    bcs invalid_class   ; Greater than '4'

    ; Convert ASCII to index (0-3)
    sec
    sbc #'1'
    sta player_class

    ; Use jump table for efficiency
    asl                 ; Multiply by 2 (addresses are 2 bytes)
    tax                 ; Use as index
    lda class_jump_table,x
    sta jump_address
    lda class_jump_table+1,x
    sta jump_address+1
    jmp (jump_address)  ; Indirect jump

invalid_class:
    ; Flash red for invalid choice
    lda #RED
    sta $d020
    jsr wait_frame
    lda #BLUE
    sta $d020
    jmp class_loop

; Class selection handlers
select_warrior:
    lda #'W'
    sta SCREEN+800      ; Show selection
    lda #RED
    sta COLOR+800
    jsr start_game
    rts

select_mage:
    lda #'M'
    sta SCREEN+800
    lda #BLUE
    sta COLOR+800
    jsr start_game
    rts

select_archer:
    lda #'A'
    sta SCREEN+800
    lda #GREEN
    sta COLOR+800
    jsr start_game
    rts

select_rogue:
    lda #'R'
    sta SCREEN+800
    lda #PURPLE
    sta COLOR+800
    jsr start_game
    rts
```

## Common Pitfalls

Watch out for these common mistakes:

1. **Forgetting to validate input ranges**: Always check that jump table indices are within bounds before using them, or you'll jump to random memory locations.

2. **Not handling the default case**: Every decision chain needs a "catch-all" case for unexpected inputs. Don't assume users will only press valid keys.

3. **Index calculation errors**: Remember that addresses are 2 bytes, so multiply your index by 2 before using it with jump tables. Also, convert ASCII digits to numeric values correctly.

## Deep Dive: State Machines with Jump Tables

For those who want to understand more deeply:

Complex games often implement state machines where each game state (menu, playing, paused, game over) has its own update and input handling routines. Jump tables make this elegant:

```asm
; State machine with jump tables
game_state: !byte 0  ; 0=menu, 1=playing, 2=paused, 3=gameover

update_game:
    lda game_state
    asl                 ; Multiply by 2
    tax
    lda update_table,x  ; Get handler address
    sta jump_address
    lda update_table+1,x
    sta jump_address+1
    jmp (jump_address)  ; Call state handler

; State handler jump table
update_table:
    !word update_menu
    !word update_playing
    !word update_paused
    !word update_gameover

; Each state can have its own complex logic
update_playing:
    jsr update_player
    jsr update_enemies
    jsr check_collisions
    jsr check_pause_key
    rts

update_paused:
    jsr check_unpause_key
    jsr flash_pause_message
    rts
```

```
┌─────────────────┐       ┌─────────────────┐

```

## Quick Reference

### Key Commands Used
- `CMP`: Compare value for decision chains
- `BEQ`: Branch if equal (for each choice)
- `ASL`: Shift left to multiply index by 2
- `TAX`: Transfer A to X for indexing
- `JMP`: Direct jump to chosen routine
- `JMP (address)`: Indirect jump using address in memory

### Memory Locations
- `$0400`: Screen memory for menus
- `$D800`: Color memory for highlighting
- `$DC00/$DC01`: Keyboard matrix scanning

### Patterns
- **Decision Chain**: CMP + BEQ sequence with default
- **Jump Table**: ASL + TAX + indirect JMP
- **Input Validation**: Range check before table lookup
- **Menu Navigation**: Visual feedback + state management
