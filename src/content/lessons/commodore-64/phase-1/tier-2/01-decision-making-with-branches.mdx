## Conceptual Overview

### Understanding Conditional Logic

Think of branching like a road junction. When you reach the junction, you check a sign (the condition) and choose which path to take. In assembly, we check processor flags and branch to different parts of our code based on their values.

In high-level languages, you'd write:
```
if (joystick == UP) {
    move_player_up()
}
```

In 6502 assembly, we achieve the same thing with compare and branch instructions. The processor automatically sets flags based on operations, and we use those flags to make decisions.

### How It Works on the Commodore 64

The 6502 processor has a status register with several flags that get set or cleared based on the results of operations:

- **Zero Flag (Z)**: Set when a result is zero
- **Carry Flag (C)**: Set for arithmetic overflow/underflow
- **Negative Flag (N)**: Set when bit 7 (sign bit) is 1

These flags are your decision-making tools. Every arithmetic and logical operation affects them, and branch instructions test them.

```asm
; Basic branching pattern
LDA $DC00       ; Read joystick port
AND #%00000001  ; Test bit 0 (up)
BEQ joy_up      ; Branch if Equal to zero (bit was 0 = pressed)
; Code continues here if NOT up
```

## Hands-On Implementation

### Setting Up

Let's create a simple program that reads the joystick and changes the border color based on input:

```asm
; Decision Making Demo - Joystick Response
; Assembled with ACME

        * = $0801
        !byte $0c,$08,$00,$00,$9e,$32,$30,$36,$34,$00,$00,$00

        * = $0810
start:
        ; Main loop
main_loop:
        JSR check_joystick
        JMP main_loop

check_joystick:
        LDA $DC00       ; Read joystick port 2
        ; Bit pattern: 0 = pressed, 1 = not pressed

        ; Check for UP (bit 0)
        LSR             ; Shift bit 0 into carry flag
        BCS not_up      ; Branch if Carry Set (not pressed)

        ; Joystick is UP - make border white
        LDA #$01
        STA $D020
        RTS

not_up:
        ; Check for DOWN (now in bit 0 after shift)
        LSR
        BCS not_down

        ; Joystick is DOWN - make border red
        LDA #$02
        STA $D020
        RTS

not_down:
        ; No input - make border blue
        LDA #$06
        STA $D020
        RTS
```

### Core Implementation

Now let's expand this to create a security guard AI that makes decisions:

```asm
; Smart Security Guard AI
; Uses branching to create intelligent behavior

guard_x:    !byte 20    ; Guard X position
guard_y:    !byte 12    ; Guard Y position
player_x:   !byte 10    ; Player X position
alert_level: !byte 0    ; 0=patrol, 1=suspicious, 2=alert

update_guard:
        ; First decision: Check alert level
        LDA alert_level
        BEQ patrol_mode      ; If 0, patrol normally
        CMP #$01
        BEQ suspicious_mode  ; If 1, investigate
        ; Otherwise, chase mode

chase_mode:
        ; Move directly toward player
        LDA player_x
        CMP guard_x
        BEQ check_y         ; X matches, check Y
        BCS move_right      ; Player is to the right
        DEC guard_x         ; Move left
        JMP check_y
move_right:
        INC guard_x         ; Move right

check_y:
        LDA player_y
        CMP guard_y
        BEQ caught_player   ; Positions match!
        BCS move_down       ; Player is below
        DEC guard_y         ; Move up
        RTS
move_down:
        INC guard_y         ; Move down
        RTS

caught_player:
        ; Game over condition
        LDA #$02
        STA $D020           ; Flash border red
        RTS

patrol_mode:
        ; Simple back-and-forth patrol
        LDA guard_x
        CMP #30             ; Right boundary?
        BEQ turn_left
        CMP #10             ; Left boundary?
        BEQ turn_right
        ; Continue in current direction
        RTS

turn_left:
        DEC guard_x
        RTS
turn_right:
        INC guard_x
        RTS

suspicious_mode:
        ; Look around but don't chase yet
        ; More complex behavior here
        RTS
```

## Common Pitfalls

Watch out for these common mistakes:

1. **Forgetting Flag State**: Remember that EVERY operation affects flags. A seemingly innocent LDA between CMP and branch will change the flags!
   - Solution: Keep CMP and branch instructions adjacent

2. **Branch Range Limits**: Branch instructions can only jump -128 to +127 bytes
   - Solution: Use JMP for longer jumps, or reorganize your code

3. **Inverted Logic**: The BEQ/BNE logic can be confusing with bit tests
   - Solution: Comment clearly what condition triggers the branch

## Deep Dive: The Flag Register in Detail

For those who want to understand more deeply:

The 6502's processor status register (P) contains 7 flags:
```
Bit 7: N - Negative flag
Bit 6: V - Overflow flag
Bit 5: - - Unused, always 1
Bit 4: B - Break flag
Bit 3: D - Decimal mode
Bit 2: I - Interrupt disable
Bit 1: Z - Zero flag
Bit 0: C - Carry flag
```

Each branch instruction tests specific flags:
- BEQ/BNE: Test Zero flag
- BCS/BCC: Test Carry flag
- BMI/BPL: Test Negative flag
- BVS/BVC: Test Overflow flag

You can even save and restore the entire flag state:
```asm
PHP         ; Push processor status to stack
; Do operations that change flags
PLP         ; Pull processor status from stack
; Flags are restored!
```

## Complete Working Example

Here's the full code bringing everything together:

```asm
; Complete Decision Making Demo
; Joystick-controlled player vs smart guard

        * = $0801
        !byte $0c,$08,$00,$00,$9e,$32,$30,$36,$34,$00,$00,$00

        * = $0810

; Constants
SCREEN_RAM = $0400
COLOR_RAM  = $D800
PLAYER_CHAR = $01   ; Smiley face
GUARD_CHAR = $02    ; Inverse smiley

; Variables
player_x:   !byte 10
player_y:   !byte 10
guard_x:    !byte 30
guard_y:    !byte 10
alert_level: !byte 0

init:
        ; Clear screen
        LDX #$00
        LDA #$20
clear:
        STA SCREEN_RAM,x
        STA SCREEN_RAM+256,x
        STA SCREEN_RAM+512,x
        STA SCREEN_RAM+768,x
        INX
        BNE clear

main_loop:
        JSR read_joystick
        JSR update_guard_ai
        JSR draw_characters

        ; Small delay
        LDX #$40
delay:  DEX
        BNE delay

        JMP main_loop

read_joystick:
        LDA $DC00       ; Read port 2

        ; Test each direction with branches
        LSR             ; UP into carry
        BCS test_down
        DEC player_y

test_down:
        LSR             ; DOWN into carry
        BCS test_left
        INC player_y

test_left:
        LSR             ; LEFT into carry
        BCS test_right
        DEC player_x

test_right:
        LSR             ; RIGHT into carry
        BCS test_fire
        INC player_x

test_fire:
        LSR             ; FIRE into carry
        BCS no_fire
        ; Fire pressed - increase alert!
        LDA #$02
        STA alert_level

no_fire:
        RTS

update_guard_ai:
        ; Check distance for alert level
        LDA player_x
        SEC
        SBC guard_x
        BPL positive_x  ; Branch if positive
        ; Negative - make positive
        EOR #$FF
        CLC
        ADC #$01

positive_x:
        CMP #$05        ; Within 5 spaces?
        BCS far_away    ; No, too far

        ; Close enough - become suspicious
        LDA #$01
        STA alert_level
        JMP check_alert

far_away:
        LDA #$00
        STA alert_level

check_alert:
        ; Now act based on alert level
        LDA alert_level
        BEQ patrol      ; 0 = patrol
        CMP #$01
        BEQ investigate ; 1 = investigate
        ; Must be 2 = chase

chase:
        ; Move toward player
        LDA player_x
        CMP guard_x
        BEQ check_vert
        BCC guard_left
        INC guard_x
        JMP check_vert
guard_left:
        DEC guard_x

check_vert:
        LDA player_y
        CMP guard_y
        BEQ done_guard
        BCC guard_up
        INC guard_y
        RTS
guard_up:
        DEC guard_y
        RTS

patrol:
        ; Simple movement pattern
        INC guard_x
        LDA guard_x
        CMP #35
        BNE done_guard
        LDA #5
        STA guard_x

investigate:
        ; Look around randomly
        LDA $DC04       ; Timer for randomness
        AND #$03        ; 0-3
        BEQ done_guard  ; Don't move
        CMP #$01
        BEQ inv_up
        CMP #$02
        BEQ inv_down
        INC guard_x
        RTS
inv_up:
        DEC guard_y
        RTS
inv_down:
        INC guard_y

done_guard:
        RTS

draw_characters:
        ; Clear old positions (simplified)
        ; ...

        ; Draw player
        LDA player_y
        ASL
        TAX
        LDA screen_line_lo,x
        STA $FB
        LDA screen_line_hi,x
        STA $FC

        LDY player_x
        LDA #PLAYER_CHAR
        STA ($FB),y

        ; Draw guard (with alert color)
        LDA guard_y
        ASL
        TAX
        LDA screen_line_lo,x
        STA $FB
        LDA screen_line_hi,x
        STA $FC

        LDY guard_x
        LDA #GUARD_CHAR
        STA ($FB),y

        ; Color based on alert
        LDA color_line_lo,x
        STA $FB
        LDA color_line_hi,x
        STA $FC

        LDA alert_level
        BEQ guard_blue
        CMP #$01
        BEQ guard_yellow
        LDA #$02        ; Red for alert
        JMP set_guard_color
guard_blue:
        LDA #$06
        JMP set_guard_color
guard_yellow:
        LDA #$07
set_guard_color:
        STA ($FB),y
        RTS

; Screen line tables (partial)
screen_line_lo:
        !byte <SCREEN_RAM, <(SCREEN_RAM+40), <(SCREEN_RAM+80)
        ; ... continue for 25 lines

screen_line_hi:
        !byte >SCREEN_RAM, >(SCREEN_RAM+40), >(SCREEN_RAM+80)
        ; ... continue for 25 lines

color_line_lo:
        !byte <COLOR_RAM, <(COLOR_RAM+40), <(COLOR_RAM+80)
        ; ... continue for 25 lines

color_line_hi:
        !byte >COLOR_RAM, >(COLOR_RAM+40), >(COLOR_RAM+80)
        ; ... continue for 25 lines
```

## Visual Guide

The program flow with branching looks like a decision tree:

```
       [Read Input]
            |
        [Compare]
         /     \
    [BEQ]       [Continue]
      |            |
   [Action A]   [Action B]
      |            |
      └────┬───────┘
           |
       [Continue]
```

Each branch point creates a new path through your code, making it dynamic and responsive.

## Quick Reference

### Key Commands Used
- `CMP`: Compare accumulator with memory/value
- `BEQ`: Branch if Equal (Zero flag set)
- `BNE`: Branch if Not Equal (Zero flag clear)
- `BCS`: Branch if Carry Set
- `BCC`: Branch if Carry Clear
- `BMI`: Branch if Minus (Negative flag set)
- `BPL`: Branch if Plus (Negative flag clear)

### Memory Locations
- `$DC00`: Joystick port 2 (and keyboard)
- `$D020`: Border color register

### Important Values
- Joystick bits: 0 = pressed, 1 = not pressed
- Branch range: -128 to +127 bytes from branch instruction
