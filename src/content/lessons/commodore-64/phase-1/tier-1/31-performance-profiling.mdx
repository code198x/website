# Performance Profiling

Measure, analyze, and optimize your code's performance. Learn to identify bottlenecks and squeeze every cycle from the C64.

## Raster Time Visualization

See where your cycles go:

```asm
; Visual profiler using border color
profile_routines:
    lda #0          ; Black border
    sta $D020
    
    lda #1          ; White = sprite code
    sta $D020
    jsr update_sprites
    
    lda #2          ; Red = collision
    sta $D020
    jsr check_collisions
    
    lda #3          ; Cyan = AI
    sta $D020
    jsr update_ai
    
    lda #5          ; Green = rendering
    sta $D020
    jsr render_screen
    
    lda #0          ; Black = idle
    sta $D020
    
    ; Border shows time distribution
    rts
```

## Cycle Counting

Precise performance measurement:

```asm
; CIA timer-based profiling
start_profile:
    ; Set CIA 2 Timer A to count cycles
    lda #$FF
    sta $DD04       ; Timer low
    sta $DD05       ; Timer high
    
    lda #$11        ; Start timer
    sta $DD0E
    rts

end_profile:
    ; Stop timer
    lda #$00
    sta $DD0E
    
    ; Calculate cycles used
    lda #$FF
    sec
    sbc $DD04
    sta cycles_low
    lda #$FF
    sbc $DD05
    sta cycles_high
    
    ; Display result
    jsr show_cycles
    rts

cycles_low:  .byte 0
cycles_high: .byte 0

; Profile specific routine
profile_function:
    jsr start_profile
    
    jsr function_to_test
    
    jsr end_profile
    rts
```

## Hot Spot Analysis

Find your performance bottlenecks:

```asm
; Sampling profiler
sample_counter: .res 256  ; Count samples per page

profile_interrupt:
    pha
    
    ; Get return address from stack
    tsx
    lda $0102,x     ; High byte of return address
    
    ; Increment counter for this page
    tax
    inc sample_counter,x
    
    pla
    rti

show_hotspots:
    ; Find pages with most samples
    ldx #0
    ldy #0          ; Max count
find_max:
    lda sample_counter,x
    cmp max_samples
    bcc not_max
    
    sta max_samples
    stx hottest_page
    
not_max:
    inx
    bne find_max
    
    ; Display hottest code page
    lda hottest_page
    jsr show_hex
    rts

max_samples:  .byte 0
hottest_page: .byte 0
```

## Memory Access Patterns

Optimize cache behavior:

```asm
; Measure memory access efficiency
measure_access:
    jsr start_profile
    
    ; Sequential access (fast)
    ldx #0
sequential:
    lda data_array,x
    inx
    bne sequential
    
    jsr end_profile
    lda cycles_low
    sta sequential_time
    
    jsr start_profile
    
    ; Random access (slower)
    ldx #0
random_access:
    txa
    eor #$55        ; Pseudo-random
    tay
    lda data_array,y
    inx
    bne random_access
    
    jsr end_profile
    lda cycles_low
    sta random_time
    
    ; Compare times
    rts

sequential_time: .byte 0
random_time:     .byte 0
data_array:      .res 256
```

Performance profiling reveals the truth about your code. Every measurement guides you toward faster, smoother games!
