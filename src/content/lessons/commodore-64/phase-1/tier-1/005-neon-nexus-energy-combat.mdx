# Lesson 5: Neon Nexus - Energy Combat

Time to arm your player with energy weapons! In this lesson, you'll add projectile combat to Neon Nexus, transforming it from a chase game into a full arcade shooter. You'll learn essential techniques for managing multiple moving objects and creating satisfying combat mechanics.

## Understanding Projectile Systems

Before we start coding, let's understand what makes a good projectile system:

1. **Bullet Pool**: Pre-allocated memory for multiple bullets
2. **State Management**: Track which bullets are active/inactive
3. **Movement Logic**: Update positions each frame
4. **Collision Detection**: Check hits against all enemies
5. **Visual Feedback**: Show impacts and destruction

## Step 1: Single Bullet System

Let's start simple - one bullet at a time:

```asm6502
; Add to your variable section:
bullet_active:  !byte 0    ; 0=inactive, 1=active
bullet_x:       !byte 0    ; Bullet X position
bullet_y:       !byte 0    ; Bullet Y position
```

Now add shooting to your keyboard handler:

```asm6502
check_space:
        ; Check for SPACE key (fire)
        lda #$7f        ; Row 7
        sta $dc00
        lda $dc01
        and #$10        ; Bit 4 = SPACE
        bne done_keys
        
        ; Check if bullet already active
        lda bullet_active
        bne done_keys   ; Can't shoot if bullet exists
        
        ; Fire bullet from player position
        lda #$01
        sta bullet_active
        lda player_x
        sta bullet_x
        lda player_y
        sec
        sbc #1          ; Start above player
        sta bullet_y
```

## Step 2: Bullet Movement

Add bullet update logic to your game loop:

```asm6502
update_bullet:
        ; Check if bullet is active
        lda bullet_active
        beq bullet_done
        
        ; Move bullet up
        dec bullet_y
        
        ; Check if bullet left screen
        lda bullet_y
        bpl bullet_still_visible
        
        ; Deactivate bullet
        lda #$00
        sta bullet_active
        
bullet_still_visible:
        ; Draw bullet at new position
        jsr draw_bullet
        
bullet_done:
        rts

draw_bullet:
        ; Calculate screen position for bullet
        lda bullet_x
        sta player_x    ; Reuse calculation routine
        lda bullet_y
        sta player_y
        
        jsr calculate_screen_pos
        
        ; Draw bullet character
        lda #$2e        ; Period/dot character
        ldy #$00
        sta ($fb),y
        
        ; Set bullet color
        ; (Calculate color RAM position similarly)
        lda #$01        ; White
        sta $d800,x     ; Simplified - use proper calculation
        
        rts
```

## Step 3: Multiple Bullets

Now let's support multiple bullets using arrays:

```asm6502
; Bullet array system
MAX_BULLETS = 3

bullet_active:  !fill MAX_BULLETS, 0
bullet_x:       !fill MAX_BULLETS, 0
bullet_y:       !fill MAX_BULLETS, 0

; Find inactive bullet slot for firing
find_bullet_slot:
        ldx #0
find_loop:
        lda bullet_active,x
        beq found_slot      ; Found inactive bullet
        inx
        cpx #MAX_BULLETS
        bne find_loop
        
        ; No free slots
        ldx #$ff
        rts
        
found_slot:
        ; X contains free slot index
        rts
```

Update the firing code:

```asm6502
fire_bullet:
        jsr find_bullet_slot
        cpx #$ff
        beq cant_fire       ; No free bullet slots
        
        ; Activate bullet in slot X
        lda #$01
        sta bullet_active,x
        
        lda player_x
        sta bullet_x,x
        
        lda player_y
        sec
        sbc #1
        sta bullet_y,x
        
cant_fire:
        rts
```

## Step 4: Bullet-Enemy Collision

Add collision detection between bullets and enemies:

```asm6502
check_bullet_collisions:
        ldx #0
bullet_collision_loop:
        ; Check if this bullet is active
        lda bullet_active,x
        beq next_bullet
        
        ; Check collision with enemy
        lda bullet_x,x
        cmp enemy_x
        bne next_bullet
        
        lda bullet_y,x
        cmp enemy_y
        bne next_bullet
        
        ; Hit detected!
        jsr handle_enemy_hit
        
        ; Deactivate bullet
        lda #$00
        sta bullet_active,x
        
next_bullet:
        inx
        cpx #MAX_BULLETS
        bne bullet_collision_loop
        rts

handle_enemy_hit:
        ; Flash effect
        lda #$01        ; White
        sta $d020       ; Border flash
        
        ; Move enemy to new position
        lda #5
        sta enemy_x
        lda #5
        sta enemy_y
        
        ; Could add score here
        rts
```

## Step 5: Visual Polish

Let's improve the bullet clearing to avoid trails:

```asm6502
update_all_bullets:
        ldx #0
update_bullet_loop:
        lda bullet_active,x
        beq skip_bullet
        
        ; Store current position for clearing
        lda bullet_x,x
        sta old_bullet_x
        lda bullet_y,x
        sta old_bullet_y
        
        ; Move bullet
        dec bullet_y,x
        
        ; Check screen boundary
        lda bullet_y,x
        bpl bullet_on_screen
        
        ; Deactivate off-screen bullet
        lda #$00
        sta bullet_active,x
        
        ; Clear the old position
        jsr clear_old_bullet
        jmp skip_bullet
        
bullet_on_screen:
        ; Clear old position
        jsr clear_old_bullet
        
        ; Draw at new position
        lda bullet_x,x
        sta player_x
        lda bullet_y,x
        sta player_y
        jsr draw_bullet
        
skip_bullet:
        inx
        cpx #MAX_BULLETS
        bne update_bullet_loop
        rts

clear_old_bullet:
        ; Use stored old position
        lda old_bullet_x
        sta player_x
        lda old_bullet_y
        sta player_y
        jsr calculate_screen_pos
        lda #$20        ; Space
        ldy #$00
        sta ($fb),y
        rts
```

## Understanding Combat Mechanics

### Bullet Pool Pattern

The bullet pool is a classic game programming pattern:

```asm6502
; Instead of creating/destroying bullets:
; We reuse a fixed pool of bullet slots
bullet_active:  !fill MAX_BULLETS, 0  ; Status flags
bullet_x:       !fill MAX_BULLETS, 0  ; X positions
bullet_y:       !fill MAX_BULLETS, 0  ; Y positions
```

Benefits:
- **Fixed memory usage** - No dynamic allocation
- **Predictable performance** - Always same number of checks
- **Simple management** - Just toggle active flags

### Collision Detection Optimization

For many objects, consider spatial partitioning:

```asm6502
; Simple optimization: early exit on Y mismatch
check_collision:
        lda bullet_y,x
        cmp enemy_y
        bne no_collision    ; Different rows - can't collide
        
        lda bullet_x,x
        cmp enemy_x
        bne no_collision
        
        ; Collision confirmed
```

### State Management

Each bullet has a simple state machine:
1. **Inactive** - Available for firing
2. **Active** - Moving and checking collisions
3. **Return to Inactive** - When hitting or leaving screen

## Common Issues and Solutions

**Bullets disappearing:** Make sure you're properly clearing old positions before drawing new ones.

**Collision detection missing:** Remember that screen positions must match exactly - consider making hit boxes larger than one character.

**Performance problems:** Limit the number of active objects and optimize your loops.
