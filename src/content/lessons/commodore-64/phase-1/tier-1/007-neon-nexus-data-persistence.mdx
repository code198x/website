# Lesson 7: Neon Nexus - Data Persistence

Time to make your game remember! In this lesson, you'll add session-based high scores and password systems to track progress without writing to disk. This is how most commercial games actually worked - they preserved data during play sessions and used passwords for longer-term progress.

## Understanding 1980s Data Persistence

C64 games avoided disk writes for good reasons:

1. **Write-protected disks** - Original games were often protected
2. **Risk of corruption** - One bad write could destroy the game
3. **Single disk systems** - No separate data disk
4. **Limited disk space** - Every byte mattered
5. **User expectations** - Games shouldn't modify themselves

Instead, games used clever alternatives:

1. **Session-based high scores** - Preserved during play, lost on power-off
2. **Password systems** - Player writes down codes for later use  
3. **RAM-based settings** - Changed during gameplay only
4. **Screen displays** - Show achievements without storing them

## Step 1: Session High Scores

Let's create a RAM-based high score table that persists during gameplay:

```asm6502
; Session high score table (lost on power-off)
HIGH_SCORE_ENTRIES = 5

high_score_data:
        ; Entry 1: Score (3 bytes BCD) + Name (3 chars)
        !byte $05, $00, $00, $4e, $58, $53    ; 50000 "NXS"
        ; Entry 2
        !byte $04, $00, $00, $43, $36, $34    ; 40000 "C64"
        ; Entry 3
        !byte $03, $00, $00, $41, $53, $4d    ; 30000 "ASM"
        ; Entry 4
        !byte $02, $00, $00, $52, $41, $4d    ; 20000 "RAM"
        ; Entry 5
        !byte $01, $00, $00, $43, $50, $55    ; 10000 "CPU"

init_high_scores:
        ; Initialize high scores with default values
        ; (Called once at game start)
        
        ldx #0
init_loop:
        lda default_scores,x
        sta high_score_data,x
        inx
        cpx #(HIGH_SCORE_ENTRIES * 6)
        bne init_loop
        
        rts

display_high_scores:
        ; Show high score table on screen
        jsr clear_screen
        
        ; Title
        lda #<($0400 + 3*40 + 15)
        sta $fb
        lda #>($0400 + 3*40 + 15)
        sta $fc
        
        ldy #0
title_loop:
        lda high_score_title,y
        beq show_scores
        sta ($fb),y
        
        ; Rainbow colors for title
        tya
        and #$07
        tax
        lda title_colors,x
        sta $d800 + 3*40 + 15,y
        
        iny
        bne title_loop
        
show_scores:
        ; Display each high score entry
        ldx #0          ; Entry number
        ldy #0          ; Data offset
        
score_display_loop:
        ; Calculate screen position (row 6 + entry number)
        lda #6
        clc
        adc #0          ; Entry number (will be replaced)
        asl
        asl
        asl             ; Multiply by 8 for spacing
        clc
        adc #6          ; Start at row 6
        sta temp_row
        
        ; Display rank number
        lda #<($0400)
        sta $fb
        lda #>($0400)
        sta $fc
        
        ; Add row offset
        lda temp_row
        jsr add_row_to_pointer
        
        ; Show "1." "2." etc
        txa
        clc
        adc #$31        ; Convert to "1", "2", etc
        ldy #2
        sta ($fb),y
        lda #$2e        ; Period
        iny
        sta ($fb),y
        
        ; Display score (3 BCD bytes = 6 digits)
        ldy #6
        ldx #0          ; Start with high byte
score_digit_loop:
        lda high_score_data,x  ; Get score byte
        pha
        
        ; High nibble
        lsr
        lsr
        lsr
        lsr
        ora #$30
        sta ($fb),y
        iny
        
        ; Low nibble
        pla
        and #$0f
        ora #$30
        sta ($fb),y
        iny
        
        inx
        cpx #3
        bne score_digit_loop
        
        ; Display name (3 characters)
        ldx #3          ; Name starts after score
name_loop:
        lda high_score_data,x
        sta ($fb),y
        iny
        inx
        cpx #6
        bne name_loop
        
        ; Move to next entry
        ; ... (continue with next high score)
        
        rts

high_score_title: !text "HIGH SCORES", 0
title_colors:     !byte 2, 8, 7, 1, 3, 14, 6, 4

default_scores:
        !byte $05, $00, $00, $4e, $58, $53    ; 50000 "NXS"
        !byte $04, $00, $00, $43, $36, $34    ; 40000 "C64"
        !byte $03, $00, $00, $41, $53, $4d    ; 30000 "ASM"
        !byte $02, $00, $00, $52, $41, $4d    ; 20000 "RAM"
        !byte $01, $00, $00, $43, $50, $55    ; 10000 "CPU"
```

## Step 2: High Score Display and Management

Instead of file operations, we manage high scores purely in RAM:

```asm6502
display_session_message:
        ; Show that high scores are session-only
        lda #<($0400 + 1*40 + 5)
        sta $fb
        lda #>($0400 + 1*40 + 5)
        sta $fc
        
        ldy #0
session_loop:
        lda session_message,y
        beq session_done
        sta ($fb),y
        
        ; Subtle color
        lda #$0f        ; Light gray
        sta $d800 + 1*40 + 5,y
        
        iny
        bne session_loop
        
session_done:
        rts

add_row_to_pointer:
        ; Add A*40 to screen pointer
        ; Multiply A by 40 and add to $fb/$fc
        
        ldx #0          ; Counter
        cmp #0
        beq row_done
        
row_multiply:
        ; Add 40 to pointer
        clc
        lda $fb
        adc #40
        sta $fb
        bcc no_row_carry
        inc $fc
no_row_carry:
        
        inx
        cpx temp_row
        bne row_multiply
        
row_done:
        rts

reset_high_scores:
        ; Reset to defaults (called from options menu)
        jsr init_high_scores
        
        ; Show confirmation message
        jsr clear_screen
        
        lda #<($0400 + 12*40 + 10)
        sta $fb
        lda #>($0400 + 12*40 + 10)
        sta $fc
        
        ldy #0
reset_loop:
        lda reset_message,y
        beq wait_reset_key
        sta ($fb),y
        iny
        bne reset_loop
        
wait_reset_key:
        jsr wait_for_space
        rts

session_message:  !text "SESSION HIGH SCORES", 0
reset_message:    !text "HIGH SCORES RESET!", 0
temp_row:         !byte 0
```

## Step 3: High Score Entry

Create a name entry system for new high scores:

```asm6502
check_new_high_score:
        ; Compare current score with high scores
        ldx #0
score_check_loop:
        ; Compare with entry X
        ldy #0          ; Start with highest byte
        
compare_bytes:
        lda score+2,y   ; Current score (high to low)
        cmp high_score_data,x
        bcc not_high_score      ; Current < high score
        bne found_high_score    ; Current > high score
        
        ; Equal, check next byte
        inx
        iny
        cpy #3
        bne compare_bytes
        
        ; Scores equal, check next entry
        inx
        inx
        inx              ; Skip name bytes
        cpx #(HIGH_SCORE_ENTRIES * 6)
        bcc score_check_loop
        
not_high_score:
        rts
        
found_high_score:
        ; Found position for new high score
        ; X contains the position (multiple of 6)
        stx new_score_position
        
        jsr enter_name
        jsr insert_new_score
        jsr save_high_scores
        
        rts

enter_name:
        ; Display name entry screen
        jsr clear_screen
        
        ; Show "NEW HIGH SCORE!"
        lda #<($0400 + 8*40 + 12)
        sta $fb
        lda #>($0400 + 8*40 + 12)
        sta $fc
        
        ldy #0
new_score_loop:
        lda new_score_text,y
        beq show_score_value
        sta ($fb),y
        iny
        bne new_score_loop
        
show_score_value:
        ; Display the score
        jsr display_final_score
        
        ; Show "ENTER NAME:"
        lda #<($0400 + 12*40 + 14)
        sta $fb
        lda #>($0400 + 12*40 + 14)
        sta $fc
        
        ldy #0
enter_loop:
        lda enter_name_text,y
        beq get_name_input
        sta ($fb),y
        iny
        bne enter_loop
        
get_name_input:
        ; Get 3-character name
        lda #<($0400 + 14*40 + 18)
        sta $fb
        lda #>($0400 + 14*40 + 18)
        sta $fc
        
        ldx #0          ; Name position
        
name_input_loop:
        ; Show cursor
        lda #$5f        ; Underscore
        ldy #0
        sta ($fb),y
        
wait_key:
        jsr $ffe4       ; GETIN
        beq wait_key
        
        ; Check for valid character (A-Z)
        cmp #$41        ; 'A'
        bcc wait_key
        cmp #$5b        ; 'Z'+1
        bcs wait_key
        
        ; Store character
        sta player_name,x
        
        ; Display character
        ldy #0
        sta ($fb),y
        
        ; Move to next position
        inx
        cpx #3
        beq name_complete
        
        ; Advance cursor
        inc $fb
        bne name_input_loop
        inc $fc
        jmp name_input_loop
        
name_complete:
        rts

player_name:    !byte 0, 0, 0
new_score_text: !text "NEW HIGH SCORE!", 0
enter_name_text: !text "ENTER NAME:", 0
```

## Step 4: Password System

Create a password system for game progress:

```asm6502
; Password encoding for game state
generate_password:
        ; Encode current game state into 4-character password
        ; Format: WXYZ where:
        ; W = Wave number (1-5) + base char
        ; X = Lives (0-5) + base char  
        ; Y = Score high byte + base char
        ; Z = Checksum + base char
        
        lda wave_number
        clc
        adc #$41        ; 'A' + wave (A-E)
        sta password,0
        
        lda player_lives
        clc
        adc #$41        ; 'A' + lives (A-F) 
        sta password,1
        
        lda score+2     ; High score byte
        and #$1f        ; Limit to 0-31
        clc
        adc #$41        ; 'A' + score portion
        sta password,2
        
        ; Simple checksum
        lda password,0
        eor password,1
        eor password,2
        and #$1f
        clc
        adc #$41
        sta password,3
        
        rts

validate_password:
        ; Check if entered password is valid
        
        ; Recalculate checksum
        lda password,0
        eor password,1
        eor password,2
        and #$1f
        clc
        adc #$41
        
        cmp password,3
        bne invalid_password
        
        ; Password valid - decode state
        lda password,0
        sec
        sbc #$41
        cmp #5
        bcs invalid_password
        sta wave_number
        
        lda password,1
        sec
        sbc #$41
        cmp #6
        bcs invalid_password
        sta player_lives
        
        lda password,2
        sec
        sbc #$41
        sta score+2
        
        ; Clear other score bytes
        lda #0
        sta score
        sta score+1
        
        ; Success
        lda #1
        sta password_valid
        rts
        
invalid_password:
        lda #0
        sta password_valid
        rts

display_password:
        ; Show current password on screen
        jsr clear_screen
        
        ; Generate current password
        jsr generate_password
        
        ; Display title
        lda #<($0400 + 8*40 + 15)
        sta $fb
        lda #>($0400 + 8*40 + 15)
        sta $fc
        
        ldy #0
pass_title_loop:
        lda password_title,y
        beq show_password_chars
        sta ($fb),y
        iny
        bne pass_title_loop
        
show_password_chars:
        ; Display the 4-character password
        lda #<($0400 + 12*40 + 18)
        sta $fb
        lda #>($0400 + 12*40 + 18)
        sta $fc
        
        ldy #0
pass_char_loop:
        lda password,y
        sta ($fb),y
        
        ; Set color
        lda #$07        ; Yellow
        sta $d800 + 12*40 + 18,y
        
        iny
        cpy #4
        bne pass_char_loop
        
        ; Wait for key
        jsr wait_for_space
        
        rts

password_title: !text "PASSWORD:", 0
password:       !byte 0, 0, 0, 0
password_valid: !byte 0
```

## Step 5: In-Game Settings

```asm6502
; Game settings structure (session-only)
game_settings:
sound_enabled:  !byte 1         ; 0=off, 1=on
music_enabled:  !byte 1         ; 0=off, 1=on
difficulty:     !byte 1         ; 0=easy, 1=normal, 2=hard
controls:       !byte 0         ; 0=WASD, 1=arrows
screen_border:  !byte 6         ; Border color

init_settings:
        ; Initialize settings to defaults
        lda #1
        sta sound_enabled
        sta music_enabled
        sta difficulty
        
        lda #0
        sta controls
        
        lda #6
        sta screen_border
        
        jsr apply_settings
        rts

toggle_sound:
        ; Toggle sound on/off
        lda sound_enabled
        eor #1
        sta sound_enabled
        
        jsr apply_settings
        jsr show_settings_message
        rts

cycle_difficulty:
        ; Cycle through difficulty levels
        inc difficulty
        lda difficulty
        cmp #3
        bne apply_new_difficulty
        lda #0
        sta difficulty
        
apply_new_difficulty:
        jsr apply_settings
        jsr show_settings_message
        rts

cycle_border_color:
        ; Cycle through border colors
        inc screen_border
        lda screen_border
        cmp #16
        bne apply_new_border
        lda #0
        sta screen_border
        
apply_new_border:
        jsr apply_settings
        rts

apply_settings:
        ; Apply current settings to hardware/game
        lda screen_border
        sta $d020
        
        ; Adjust SID volume based on sound setting
        lda sound_enabled
        bne sound_on
        
        ; Mute SID
        lda #0
        sta $d418
        rts
        
sound_on:
        lda #15
        sta $d418
        rts

show_settings_message:
        ; Display current settings on screen
        lda #<($0400 + 23*40 + 2)
        sta $fb
        lda #>($0400 + 23*40 + 2)
        sta $fc
        
        ; Clear the line first
        ldy #0
        lda #$20
clear_settings_line:
        sta ($fb),y
        iny
        cpy #36
        bne clear_settings_line
        
        ; Show sound status
        ldy #0
        ldx #0
sound_status_loop:
        lda sound_text,x
        beq show_sound_value
        sta ($fb),y
        iny
        inx
        bne sound_status_loop
        
show_sound_value:
        lda sound_enabled
        bne show_on

        sta ($fb),y
        iny
        lda #$46        ; 'F'
        sta ($fb),y
        iny
        lda #$46        ; 'F'
        sta ($fb),y
        jmp show_difficulty
        
show_on:
        lda #$4f        ; 'O'
        sta ($fb),y
        iny
        lda #$4e        ; 'N'
        sta ($fb),y
        
show_difficulty:
        ; Add spacing
        iny
        iny
        iny
        
        ; Show difficulty
        ldx #0
diff_text_loop:
        lda diff_text,x
        beq show_diff_value
        sta ($fb),y
        iny
        inx
        bne diff_text_loop
        
show_diff_value:

        asl
        asl
        asl             ; Multiply by 8
        tax
        ldy #0
diff_value_loop:

        beq settings_display_done

        inx
        iny
        cpy #8

        !text "NORMAL  ", 0
```

```asm6502

progress_data:
waves_completed: !byte 0        ; Bit field: 11111 = all 5 waves
bonus_unlocked:  !byte 0        ; Bonus features unlocked
best_time:       !byte 0, 0     ; Best completion time (BCD)

update_progress:
        ; Mark current wave as completed
        ldx wave_number
        dex                     ; Convert to 0-4
        
        lda #1

        cpx #0

        asl
        dex
        bne wave_bit_loop
        
set_wave_bit:
        ora waves_completed

        lda #1

        ; Award achievement
        lda achievements

        sta achievements
        
progress_updated:

        ldy #0
        ldx #0

        lda waves_text,x
        beq show_wave_status
        sta ($fb),y
        iny
        inx
        bne waves_text_loop
        
show_wave_status:
        ; Show completion for each wave (✓ or -)
        ldx #0          ; Wave counter
        
wave_status_loop:
        lda waves_completed
        and wave_masks,x
        bne wave_complete
        
        ; Wave not complete

wave_complete:

        sta ($fb),y
        
next_wave_status:

        inx
        cpx #5

        ; Show bonus status if unlocked

        ldx #0
bonus_text_loop:

        beq progress_display_done
        sta ($fb),y
        iny
        inx
        bne bonus_text_loop
        
progress_display_done:

reset_progress:
        ; Reset all session progress
        lda #0
        sta waves_completed
        sta bonus_unlocked
        sta achievements
        sta best_time
        sta best_time+1
        
        jsr display_progress
        rts

check_achievements:
        ; Check for special achievements
        
        ; Perfect game (no lives lost)
        lda player_lives
        cmp #3
        bne check_speed_run
        
        lda achievements
        ora #$02                ; Perfect game flag
        sta achievements
        
check_speed_run:
        ; Speed run (under certain time)
        ; (This would need a timer implementation)
        
        ; Display any new achievements
        jsr display_achievements
        rts

display_achievements:
        ; Show achieved accomplishments
        lda achievements
        beq no_achievements
        
        ; Display achievement notification
        ; (Implementation would show popup or status)
        
no_achievements:
        rts

waves_text:      !text "WAVES:", 0
bonus_text:      !text "BONUS!", 0

wave_masks:      !byte $01, $02, $04, $08, $10
```

## Understanding Authentic 1980s Persistence

### Why No Disk Writes?

In the 1980s, games avoided writing to disks because:

- **Copy protection** - Disks were often write-protected
- **Single disk systems** - No room for separate data disks  
- **Reliability concerns** - A bad write could destroy the game
- **User expectations** - Games shouldn't modify themselves

### Password System Benefits

Passwords were the preferred method because:

- **User controlled** - Players write them down safely
- **No hardware requirements** - Works on any system
- **Shareable** - Players could trade progress codes
- **Reliable** - No disk corruption possible

### RAM-Based Data

Session data works well because:

- **Fast access** - No disk delays during gameplay
- **Simple implementation** - Just memory operations
- **Temporary nature** - Matches arcade game expectations

**Password validation:** Always verify checksums to catch typos.

**Session length:** Consider how long players typically play.
