# Grid Position System

**Wonder Moment**: "My sprite knows where it is on the grid!"

## Why Grid Coordinates?

While pixel movement gives smooth control, games need logical positions for gameplay. A grid system provides discrete positions for collision detection, level design, and game logic.

## Position Calculation

Convert pixel coordinates to grid coordinates using division:

<InteractiveExample
  title="Calculate Grid Position"
  description="Convert pixels to grid coordinates"
>
```asm
calculate_grid_position:
        ; Calculate grid X from sprite X
        ; grid_x = sprite_x / 32
        lda sprite_x
        lsr                    ; Divide by 2
        lsr                    ; Divide by 4
        lsr                    ; Divide by 8
        lsr                    ; Divide by 16
        lsr                    ; Divide by 32
        sta grid_x
        
        ; Calculate grid Y from sprite Y
        ; grid_y = (sprite_y - 50) / 32
        lda sprite_y
        sec
        sbc #50                ; Subtract Y offset for screen position
        lsr                    ; Divide by 2
        lsr                    ; Divide by 4
        lsr                    ; Divide by 8
        lsr                    ; Divide by 16
        lsr                    ; Divide by 32
        sta grid_y
        
        rts
```
</InteractiveExample>

## Efficient Division

The 6502 lacks division instructions, but dividing by powers of 2 is simple:

<VisualConcept
  title="Bit Shifting for Division"
  description="How LSR divides by 2"
>
```
Original value:  10101000 (168)
After 1 LSR:     01010100 (84)  ÷ 2
After 2 LSRs:    00101010 (42)  ÷ 4
After 3 LSRs:    00010101 (21)  ÷ 8
After 4 LSRs:    00001010 (10)  ÷ 16
After 5 LSRs:    00000101 (5)   ÷ 32
```
</VisualConcept>

## Display Grid Information

Show the current grid position on screen:

<InteractiveExample
  title="Display Grid Position"
  description="Show current coordinates"
>
```asm
display_current_position:
        ; Display "POS: X,Y"
        ldx #0
display_pos_label:
        lda pos_label,x
        beq pos_label_done
        sta $0400 + 40*5 + 2,x ; Row 5, column 2
        inx
        jmp display_pos_label
pos_label_done:

        ; Display grid X
        lda grid_x
        clc
        adc #48                ; Convert to ASCII ('0' = 48)
        sta $0400 + 40*5 + 7   ; After "POS: "
        
        ; Display comma
        lda #44                ; ASCII comma
        sta $0400 + 40*5 + 8
        
        ; Display grid Y
        lda grid_y
        clc
        adc #48                ; Convert to ASCII
        sta $0400 + 40*5 + 9
        
        rts

pos_label:
        !text "POS: "
        !byte 0                ; Null terminator
```
</InteractiveExample>

## Integration with Movement

The grid system works alongside pixel movement:

<InteractiveExample
  title="Game Loop Integration"
  description="Update both position systems"
>
```asm
game_loop:
        jsr read_joystick          ; Get input
        jsr move_sprite            ; Move by pixels
        jsr calculate_grid_position ; Update grid position
        jsr update_sprite_position ; Update hardware
        jsr display_current_position ; Show grid coords
        jsr wait_frame
        jmp game_loop
```
</InteractiveExample>

## Understanding the Mapping

Key relationships in our grid system:
- **Pixel 0-31** → Grid position 0
- **Pixel 32-63** → Grid position 1
- **Pixel 64-95** → Grid position 2
- And so on...

## Practice Exercises

1. **Different Grid Sizes**: Try 10×8 or 16×12 grids
2. **Grid Visualization**: Draw grid lines on screen
3. **Center Display**: Show sprite at grid cell center
4. **Grid Highlighting**: Change border color based on grid position

## Debugging Tips

- Display both pixel and grid positions
- Use different colors for each grid cell
- Add sound when crossing grid boundaries
- Draw markers at grid intersections

## Key Takeaways

- Grid systems provide logical game positions
- Bit shifting efficiently divides by powers of 2
- Dual tracking allows smooth movement with discrete logic
- Grid size should match game design needs
- Always validate grid calculations with display
