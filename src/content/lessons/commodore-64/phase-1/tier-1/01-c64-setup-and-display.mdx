# Grid Protocol: Terminal Activation
**"Welcome to the Grid, Operator"**

The year is 2085. Few now remember the days before the Collapse, but rumours speak of a virus that spread rapidly through the Internet, corrupting system after system, rendering them and their data useless, leaving destruction in its wake. Nobody knows who released the virus; nobody knows what they hoped to achieve by doing so. Some believe that the virus is still out there, laying dormant in isolated nodes, waiting for an unwary hacker to release it.

In the wake of the virus, humanity returned to proven technologies from a previous age, and formed them into the Grid. The legendary Commodore 64 terminals - immune to the corruption that destroyed modern systems - became the foundation of our new digital civilization. 

Today, you begin your training as a Grid Operator. Your first task: activate a C64 terminal and establish direct hardware control. No abstractions. No layers. Just you, the machine, and pure 6502 assembly - the language that survived the Collapse.

Operators now navigate through the Grid, keeping data streams clean and secure. And it all starts here, with your first terminal activation.

## Learning From the Survivors

**"Those who understood the hardware survived the Collapse"**

When the virus swept through the networks in 2057, it took less than 48 hours to destroy thirty years of digital progress. But in the ruins, the old-school programmers discovered something remarkable: the ancient machines still worked. The C64s, pulled from basements and museums, were immune.

No operating system to infect. No network stack to corrupt. Just pure, direct hardware control through 6502 assembly - a language so fundamental that the virus simply had no attack surface.

These survivors spent the next decade building the Grid from these proven machines. Now, nearly thirty years later, their knowledge has been codified into the training you're about to receive. The first generation of Grid Operators are gone, but their methods live on.

### The VIC-II: Why It Survived

Your C64 terminal contains the VIC-II (Video Interface Chip II) - hardware so robust it still functions perfectly after 40 years in storage. The virus couldn't corrupt what it couldn't reach: hard-wired silicon pathways, fixed-function circuits, and deterministic behavior.

The VIC-II's capabilities, primitive by pre-Collapse standards, are now our foundation:
- **16 colors** - Each mapped to specific memory values (no corruption possible)
- **Hardware sprites** - Eight independent objects, perfect for Grid navigation
- **40×25 character display** - 1000 bytes of screen memory, directly addressable
- **Raster interrupts** - Precise timing that can't be hijacked

### Understanding Terminal Memory

Before the Collapse, programmers relied on operating systems to manage memory. Now, as a Grid Operator, you'll control every byte directly:

```
$0000-$00FF: Zero Page (fastest access - critical operations)
$0400-$07E7: Screen Memory (1000 bytes - what you see)
$D800-$DBE7: Color Memory (1000 bytes - how it looks)
$D020-$D021: Border/Background (terminal appearance)
```

This isn't abstraction - these are physical addresses in silicon. When you write to $D020, you're sending electrons through circuits older than you are.

### Why Direct Control Matters

Most survivors fear technology after the Collapse. They use Grid terminals but don't understand
them. As an Operator, you're different. You know that if another virus emerges, you'll see it
coming. A corrupted abstraction layer can hide malicious code. But at the hardware level? Every
unauthorized write to memory is visible. There are no hidden processes. No background tasks.
Every byte you write, every colour you change - you can see it happen. This is why the Grid
works - absolute transparency. Only Operators learn the skills necessary to keep the Grid safe; to
maintain, repair and expand it. This knowledge - how to make dead silicon come alive with nothing
but assembly code - makes you invaluable.

## Activating Your Terminal

Time to bring your C64 terminal online. Each step builds on the last, establishing your connection to the Grid.

### Step 1: The Gateway Protocol (BASIC Stub)
**"Every byte counts in the Grid"**

Every Grid terminal requires a gateway - the minimal BASIC code that transfers control to your assembly. We build it byte by byte, wasting nothing:

```text
; Gateway protocol - pure bytes forming BASIC program
*=$0801                        ; BASIC starts here

        !byte $0b,$08          ; Next line pointer: $080b
        !byte $0a,$00          ; Line number: 10
        !byte $9e              ; SYS token
        !byte $32,$30,$36,$31  ; "2061" as PETSCII
        !byte $00              ; End of line
        !byte $00,$00          ; End of program

; Grid code begins immediately after
*=$080d                        ; 2061 decimal - earliest safe entry

grid_init:
        ; Activate terminal border (cyan - Grid signature color)
        lda #$03               ; Cyan frequency
        sta $d020              ; Border activation register
        
        ; Set data stream background (black void)
        lda #$00               ; Black - absence of data
        sta $d021              ; Background activation register
```

These 12 bytes create the most minimal gateway possible: `10 SYS 2061`. Not a single wasted byte - this is how Grid Operators maximize their terminal resources.

**Activation Moment**: Run this and watch your terminal respond - cyan border materializes from the void!

### Step 3: Clearing the Data Matrix
**"Purge the old data, prepare for Grid streams"**

Before establishing Grid communications, we must clear the terminal of any residual data. This requires precision - every byte must be accounted for:

```text
        ; Clear screen matrix - 1000 bytes exactly
        ldx #0                 ; Initialize scan position
clear_matrix:
        lda #$20               ; Space character (empty cell)
        sta $0400,x            ; Screen page 1 (256 bytes)
        sta $0500,x            ; Screen page 2 (256 bytes)
        sta $0600,x            ; Screen page 3 (256 bytes)
        
        ; Set corresponding colors to cyan
        lda #$03               ; Cyan frequency
        sta $d800,x            ; Color page 1
        sta $d900,x            ; Color page 2
        sta $da00,x            ; Color page 3
        
        inx                    ; Next position
        bne clear_matrix       ; Loop until X wraps to 0
        
        ; Handle remaining 232 bytes (1000 - 768 = 232)
        ldx #0
clear_final:
        lda #$20               ; Space character
        sta $0700,x            ; Screen page 4 (partial)
        lda #$03               ; Cyan frequency
        sta $db00,x            ; Color page 4 (partial)
        
        inx
        cpx #232               ; Stop at exactly 1000 total
        bne clear_final
```

**Grid Protocol**: We clear exactly 1000 bytes - not one more, not one less. This precision prevents contamination of sprite pointers at $07F8-$07FF.

### Step 4: Broadcasting Your Identification
**"Announce your presence to the Grid"**

Now we display your operator identification. This confirms successful terminal activation:

```text
        ; Display Grid identification message
        ldx #0                 ; Message index
display_id:
        lda grid_message,x     ; Load character
        beq id_complete        ; Zero = end of message
        sta $0400+12*40+10,x   ; Row 12, Column 10 (centered)
        inx
        jmp display_id         ; Next character
        
id_complete:
        ; Terminal activation complete - enter idle loop
idle_loop:
        jmp idle_loop          ; Maintain terminal power

; Grid identification data (screen codes, not PETSCII)
grid_message:
        !byte 7,18,9,4,32     ; "GRID "
        !byte 16,18,15,20,15,3,15,12,32  ; "PROTOCOL "
        !byte 1,3,20,9,22,5   ; "ACTIVE"
        !byte 0                ; Terminator
```

**Screen Codes**: Unlike PETSCII, screen codes map directly to screen memory:
- A-Z = 1-26
- Space = 32
- Numbers = 48-57

### Step 5: Complete Terminal Activation

Put it all together for your first Grid terminal:

```text
; GRID PROTOCOL: Terminal Activation
; Lesson 1 - Establishing first contact with the Grid

*=$0801
        ; Gateway protocol (minimal BASIC stub)
        !byte $0b,$08,$0a,$00,$9e,$32,$30,$36,$31,$00,$00,$00

*=$080d
grid_init:
        ; Activate terminal visuals
        lda #$03               ; Cyan border
        sta $d020
        lda #$00               ; Black background
        sta $d021
        
        ; Clear data matrix
        ldx #0
clear_matrix:
        lda #$20
        sta $0400,x
        sta $0500,x
        sta $0600,x
        lda #$03
        sta $d800,x
        sta $d900,x
        sta $da00,x
        inx
        bne clear_matrix
        
        ldx #0
clear_final:
        lda #$20
        sta $0700,x
        lda #$03
        sta $db00,x
        inx
        cpx #232
        bne clear_final
        
        ; Display identification
        ldx #0
display_id:
        lda grid_message,x
        beq idle_loop
        sta $0400+12*40+10,x
        inx
        jmp display_id
        
idle_loop:
        jmp idle_loop

grid_message:
        !byte 7,18,9,4,32,16,18,15,20,15,3,15,12,32
        !byte 1,3,20,9,22,5,0
```

## Terminal Configuration Protocols

Your basic terminal is active. Now learn to configure it for different Grid operations.

### Protocol 1: Emergency Alert State
**"When contamination is detected"**

Grid terminals must signal emergencies instantly. Modify your border to red ($02) to indicate alert status:

```text
lda #$02               ; Red = contamination alert
sta $d020              ; Emergency border activation
```

Red borders warn other operators that your sector has detected anomalies. Practice switching between cyan (normal) and red (alert).

### Protocol 2: Secure Channel Access
**"Not all Grid data flows through public channels"**

Different Grid channels use different color signatures. Try these classified configurations:

- **Green/Black** ($05/$00): Agricultural data streams - food production status
- **White/Blue** ($01/$06): Weather monitoring - storm tracking systems  
- **Yellow/Black** ($07/$00): Power grid status - critical infrastructure

Change both border and background to match the channel you're monitoring.

### Protocol 3: Operator Identification
**"Your callsign is your reputation"**

Replace the generic "GRID PROTOCOL ACTIVE" with your operator credentials. Every Grid Operator has a unique identifier:

```text
; Example: "OPERATOR: NOVA-5"
operator_id:
        !byte 15,16,5,18,1,20,15,18,58,32  ; "OPERATOR: "
        !byte 14,15,22,1,45,53,0            ; "NOVA-5"
```

Screen code reference for common callsigns:
- Numbers: 48-57 (0-9)
- Hyphen: 45
- Colon: 58
- Letters: 1-26 (A-Z)

Position your ID at `$0400+10*40+13` (row 10, column 13) for standard Grid placement.

### Protocol 4: Signal Degradation Test
**"Can your terminal survive data corruption?"**

Test your terminal's resilience by simulating Grid interference:

```text
        ; Contamination simulation
        ldx #0
corrupt_test:
        txa                    ; Use X as pseudo-random value
        sta $0400,x            ; Random characters
        and #$0f               ; Limit to 16 colors
        sta $d800,x            ; Random colors
        inx
        bne corrupt_test
```

After 2 seconds, run your clear routine to purge the contamination. This simulates recovering from a virus probe - a critical Grid Operator skill.

## Technical Reference

### 6502 Instructions Mastered
- **LDA**: Load accumulator with value
- **STA**: Store accumulator to memory
- **LDX**: Load X register
- **INX**: Increment X register
- **BNE**: Branch if not equal (zero flag clear)
- **BEQ**: Branch if equal (zero flag set)
- **CPX**: Compare X register with value
- **JMP**: Jump to address

### Critical Memory Locations
- **$0801-$080C**: Gateway protocol (BASIC stub)
- **$080D+**: Grid operation code
- **$0400-$07E7**: Screen matrix (1000 bytes)
- **$D800-$DBE7**: Color matrix (1000 bytes)
- **$D020**: Border control register
- **$D021**: Background control register

### Screen Code Reference
```
A-Z: 1-26       0-9: 48-57
Space: 32       Colon: 58
Hyphen: 45      Period: 46
```

Remember: In the Grid, precision isn't just good practice - it's survival.
