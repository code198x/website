# Background Scrolling: Moving Worlds
**The technique that defined a generation of games**

In 1984, "Boulder Dash" proved the C64 could scroll. Not the jerky, character-by-character scrolling of earlier computers, but smooth, pixel-perfect movement. When "Uridium" flew across metallic dreadnoughts in 1986, when "The Last Ninja" explored vast isometric landscapes in 1987, when "Turrican" created worlds that seemed to go on forever in 1990 - they all built on one fundamental C64 capability: hardware scrolling.

This lesson unlocks the VIC-II's scrolling magic. You'll learn how two simple registers - $D011 and $D016 - transform the C64's fixed 40×25 character screen into a window onto infinite worlds. These techniques powered every scrolling game on the platform, from the simplest platformer to the most ambitious adventure.

## The Revolution of Smooth Scrolling

Before the C64, most home computers could only scroll by redrawing the entire screen - a process so slow it created visible judder. The VIC-II changed everything with dedicated scroll registers that could shift the display by individual pixels in hardware, instantly, with zero CPU cost.

Andrew Braybrook, programmer of "Uridium" and "Paradroid," called it "the feature that made the C64 special." While competitors struggled to move backgrounds smoothly, C64 programmers were creating scrolling masterpieces that felt arcade-perfect.

## Understanding Hardware Scrolling

The VIC-II provides pixel-precise scrolling through two registers:

```asm
; The magic registers that move worlds
; $D011: Vertical scroll (bits 0-2) plus control bits
; $D016: Horizontal scroll (bits 0-2) plus control bits

; Each register scrolls 0-7 pixels in hardware
; Beyond that, you shift characters in memory

basic_hardware_scroll:
    ; Smooth horizontal scroll demonstration
    ldx #0
scroll_demo:
    txa
    and #$07        ; Keep in 0-7 pixel range
    sta $d016       ; Hardware does the scrolling!
    
    ; Let player see the movement
    jsr wait_frame
    jsr wait_frame
    
    inx
    jmp scroll_demo ; Endless smooth scroll
```

Those three bits in $D016 shift the entire screen horizontally by 0-7 pixels. No CPU work, no copying memory - the hardware handles everything. But what happens when you need to scroll beyond 7 pixels?

## The Fine/Coarse Scrolling Dance

Professional scrolling combines hardware "fine" scrolling (0-7 pixels) with software "coarse" scrolling (shifting characters):

```asm
; Professional scrolling engine structure
scroll_x_fine:   .byte 0    ; Current pixel offset (0-7)
scroll_x_coarse: .word 0    ; Character position in world
world_data:      .word level_map ; Pointer to level data

smooth_scroll_right:
    ; Increment fine scroll
    inc scroll_x_fine
    lda scroll_x_fine
    cmp #8              ; Crossed character boundary?
    bne just_fine_scroll
    
    ; Reset fine scroll and shift screen
    lda #0
    sta scroll_x_fine
    
    ; Shift entire screen left by one character
    jsr shift_screen_left
    
    ; Draw new column on the right
    inc scroll_x_coarse
    jsr draw_right_column
    
just_fine_scroll:
    ; Update hardware scroll register
    lda scroll_x_fine
    sta $d016
    rts
```

This is the fundamental scrolling algorithm. "Super Mario Bros" on NES uses the same principle. "Sonic the Hedgehog" on Genesis uses it. Every smoothly scrolling game ever made combines fine hardware scrolling with coarse software shifting.

## Shifting the Screen

The coarse scroll - shifting all characters - is where optimization matters:

```asm
; Optimized screen shifting for horizontal scroll
shift_screen_left:
    ; Method 1: Unrolled loop (fastest, uses more memory)
    ; Each line explicitly copied for maximum speed
    
    ; Row 0
    ldx #38         ; 39 characters to move
.row0:
    lda $0401,x     ; Read from position+1
    sta $0400,x     ; Write to position
    lda $d801,x     ; Don't forget color RAM!
    sta $d800,x
    dex
    bpl .row0
    
    ; Row 1 (40 bytes further)
    ldx #38
.row1:
    lda $0429,x     ; $0401 + 40
    sta $0428,x     ; $0400 + 40
    lda $d829,x
    sta $d828,x
    dex
    bpl .row1
    
    ; ... continue for all 25 rows
    ; In production, generate this with a macro
    
shift_screen_left_compact:
    ; Method 2: Compact loop (slower, saves memory)
    ldx #0
    ldy #0
.shift_loop:
    ; Screen memory
    lda $0401,x     ; Source: column 1
    sta $0400,x     ; Dest: column 0
    
    ; Color memory  
    lda $d801,x
    sta $d800,x
    
    inx
    cpx #999        ; 40×25-1 (don't copy last column)
    bne .shift_loop
    rts
```

"Ghosts 'n Goblins" used unrolled loops for speed. "The Last Ninja" used compact loops to save memory for its large levels. Choose based on your game's needs.

## Drawing New Content

As the screen scrolls, new content appears at the edges:

```asm
; Draw new column on the right edge after shifting left
draw_right_column:
    ; Calculate source data position
    lda scroll_x_coarse
    sta map_index
    lda scroll_x_coarse+1
    sta map_index+1
    
    ; Draw 25 characters vertically
    ldx #0              ; Screen row
    ldy #0              ; Offset in screen RAM
.draw_column:
    ; Calculate map position for this row
    txa
    pha                 ; Save row number
    
    ; Get tile from map
    lda map_index
    sta temp_lo
    lda map_index+1
    sta temp_hi
    
    ; Add row offset (each map row might be wider than screen)
    txa
    clc
    adc temp_lo
    sta temp_lo
    lda #0
    adc temp_hi
    sta temp_hi
    
    ; Read tile
    ldy #0
    lda (temp_lo),y
    
    ; Convert tile ID to character
    tax
    lda tile_charset,x
    
    ; Store in rightmost column
    ldy screen_offset
    sta $0427,y         ; Column 39 of current row
    
    ; Set color
    lda tile_colors,x
    sta $d827,y
    
    ; Next row
    pla
    tax
    inx
    
    ; Move screen pointer down one row
    lda screen_offset
    clc
    adc #40
    sta screen_offset
    
    cpx #25             ; All rows done?
    bne .draw_column
    rts

; Tile definitions
tile_charset:
    .byte $20  ; 0 = empty space
    .byte $e0  ; 1 = solid block
    .byte $5f  ; 2 = platform
    .byte $66  ; 3 = brick pattern
    .byte $a0  ; 4 = solid fill
    
tile_colors:
    .byte $06  ; 0 = blue (sky)
    .byte $0b  ; 1 = dark gray (rock)
    .byte $05  ; 2 = green (grass)
    .byte $02  ; 3 = red (brick)
    .byte $0f  ; 4 = light gray (metal)

screen_offset: .byte 0
map_index:     .word 0
temp_lo:       .byte 0
temp_hi:       .byte 0
```

This tile-based approach is how "Super Mario Bros" works, how "Mega Man" works, how virtually every scrolling game works. The map data defines the world; the scrolling engine reveals it.

## Vertical Scrolling

Vertical scrolling uses the same principles but with $D011:

```asm
; Smooth vertical scrolling
scroll_y_fine:   .byte 0
scroll_y_coarse: .word 0

smooth_scroll_down:
    ; Increment fine scroll
    inc scroll_y_fine
    lda scroll_y_fine
    and #$07
    sta scroll_y_fine
    
    ; Check for coarse scroll
    cmp #0              ; Wrapped to 0?
    bne just_fine_vert
    
    ; Shift screen up
    jsr shift_screen_up
    
    ; Draw new row at bottom
    inc scroll_y_coarse
    jsr draw_bottom_row
    
just_fine_vert:
    ; Update $D011 with vertical scroll
    lda scroll_y_fine
    ora #$1b            ; Default $D011 bits (screen on, 25 rows)
    sta $d011
    rts

shift_screen_up:
    ; Copy from row 1 to row 0, row 2 to row 1, etc.
    ldx #0
.copy_loop:
    lda $0428,x         ; Row 1 (40 chars after row 0)
    sta $0400,x         ; Row 0
    lda $d828,x         ; Color RAM too
    sta $d800,x
    inx
    cpx #960            ; 24 rows × 40 chars
    bne .copy_loop
    rts

draw_bottom_row:
    ; Draw new content at row 24
    lda scroll_y_coarse
    asl                 ; Multiply by 64 (map width)
    rol scroll_y_coarse+1
    asl
    rol scroll_y_coarse+1
    asl
    rol scroll_y_coarse+1
    asl
    rol scroll_y_coarse+1
    asl
    rol scroll_y_coarse+1
    asl
    rol scroll_y_coarse+1
    
    clc
    adc #<map_data
    sta map_ptr
    lda scroll_y_coarse+1
    adc #>map_data
    sta map_ptr+1
    
    ; Draw 40 characters
    ldy #0
.draw_row:
    lda (map_ptr),y
    tax
    lda tile_charset,x
    sta $07c0,y         ; Row 24
    lda tile_colors,x
    sta $dbc0,y
    iny
    cpy #40
    bne .draw_row
    rts

map_ptr: .word 0
```

"Commando" and "1942" mastered vertical scrolling. The technique is identical to horizontal scrolling, just moving in a different direction.

## Eight-Direction Scrolling

True omnidirectional scrolling combines both techniques:

```asm
; Professional 8-way scrolling engine
scroll_state:
    .byte 0         ; Bit flags for current scroll direction
SCROLL_UP    = %00000001
SCROLL_DOWN  = %00000010  
SCROLL_LEFT  = %00000100
SCROLL_RIGHT = %00001000

update_8way_scroll:
    ; Read joystick and update scroll direction
    lda $dc00
    eor #$ff        ; Invert bits (0=pressed)
    and #$0f        ; Keep direction bits
    sta scroll_state
    
    ; Handle each direction
    lsr scroll_state
    bcc .not_up
    jsr scroll_up
.not_up:
    lsr scroll_state
    bcc .not_down
    jsr scroll_down
.not_down:
    lsr scroll_state
    bcc .not_left
    jsr scroll_left
.not_left:
    lsr scroll_state
    bcc .not_right
    jsr scroll_right
.not_right:
    
    ; Update hardware registers with combined scroll
    lda scroll_x_fine
    ora #$08        ; Multicolor off
    sta $d016
    
    lda scroll_y_fine
    ora #$1b        ; Screen on
    sta $d011
    rts

scroll_right:
    inc scroll_x_fine
    lda scroll_x_fine
    cmp #8
    bne .done_right
    
    lda #0
    sta scroll_x_fine
    jsr shift_screen_left
    inc scroll_x_coarse
    jsr draw_right_edge
.done_right:
    rts

scroll_left:
    dec scroll_x_fine
    lda scroll_x_fine
    cmp #$ff        ; Wrapped negative?
    bne .done_left
    
    lda #7
    sta scroll_x_fine
    jsr shift_screen_right
    dec scroll_x_coarse
    jsr draw_left_edge
.done_left:
    rts

scroll_up:
    dec scroll_y_fine
    lda scroll_y_fine
    cmp #$ff
    bne .done_up
    
    lda #7
    sta scroll_y_fine
    jsr shift_screen_down
    dec scroll_y_coarse
    jsr draw_top_edge
.done_up:
    rts

scroll_down:
    inc scroll_y_fine
    lda scroll_y_fine
    cmp #8
    bne .done_down
    
    lda #0
    sta scroll_y_fine
    jsr shift_screen_up
    inc scroll_y_coarse
    jsr draw_bottom_edge
.done_down:
    rts
```

"Gauntlet" used 8-way scrolling for its dungeon exploration. "Ikari Warriors" used it for battlefield navigation. The complexity comes from handling corner cases - literally, the corners where you need to update both new row and new column data.

## Parallax Scrolling

Multiple layers moving at different speeds create the illusion of depth:

```asm
; Three-layer parallax scrolling system
; Used by games like "Shadow of the Beast" and "Turrican"

parallax_layers:
bg_scroll:   .byte 0    ; Far background (mountains)
mg_scroll:   .byte 0    ; Midground (trees)
fg_scroll:   .byte 0    ; Foreground (platforms)
speed:       .byte 0    ; Current movement speed

update_parallax:
    lda speed           ; Player movement speed
    beq .no_parallax
    
    ; Foreground moves at full speed
    clc
    adc fg_scroll
    sta fg_scroll
    
    ; Check for foreground wrap
    cmp #8
    bcc .check_midground
    lda #0
    sta fg_scroll
    jsr shift_foreground
    
.check_midground:
    ; Midground at half speed
    lda speed
    lsr                 ; Divide by 2
    clc
    adc mg_scroll
    sta mg_scroll
    
    cmp #8
    bcc .check_background
    lda #0
    sta mg_scroll
    jsr shift_midground
    
.check_background:
    ; Background at quarter speed
    lda speed
    lsr
    lsr                 ; Divide by 4
    clc
    adc bg_scroll
    sta bg_scroll
    
    cmp #8
    bcc .update_hardware
    lda #0
    sta bg_scroll
    jsr shift_background
    
.update_hardware:
    ; Use foreground scroll for hardware register
    lda fg_scroll
    sta $d016
    
.no_parallax:
    rts

shift_foreground:
    ; Shift main play area (rows 5-22)
    ldx #5*40           ; Start at row 5
.fg_loop:
    lda $0401,x
    sta $0400,x
    lda $d801,x
    sta $d800,x
    inx
    cpx #22*40          ; End at row 22
    bne .fg_loop
    
    ; Draw new foreground column
    jsr draw_fg_column
    rts

shift_midground:
    ; Shift middle layer (rows 2-4)
    ldx #2*40
.mg_loop:
    lda $0401,x
    sta $0400,x
    lda $d801,x
    sta $d800,x
    inx
    cpx #5*40
    bne .mg_loop
    
    jsr draw_mg_column
    rts

shift_background:
    ; Shift far background (rows 0-1)
    ldx #0
.bg_loop:
    lda $0401,x
    sta $0400,x
    lda $d801,x
    sta $d800,x
    inx
    cpx #2*40
    bne .bg_loop
    
    jsr draw_bg_column
    rts

draw_fg_column:
    ; Draw gameplay elements
    ldx #5*40+39        ; Row 5, column 39
.fg_draw:
    lda fg_map,x
    sta $0400,x
    ; ... continue for each row
    rts

draw_mg_column:
    ; Draw midground scenery
    lda mg_position
    and #$1f            ; 32-char pattern
    tax
    lda tree_pattern,x
    sta $0400+2*40+39   ; Row 2, column 39
    ; ... continue pattern
    rts

draw_bg_column:
    ; Draw distant mountains
    lda bg_position
    and #$3f            ; 64-char pattern
    tax
    lda mountain_pattern,x
    sta $0400+39        ; Row 0, column 39
    ; ... continue pattern
    rts

; Parallax patterns
mountain_pattern:
    .byte $20,$20,$e9,$df,$20,$20,$20,$20  ; Mountain silhouette
    .byte $20,$e9,$a0,$a0,$df,$20,$20,$20
    ; ... more mountain data

tree_pattern:
    .byte $20,$20,$55,$20,$20,$51,$20,$20  ; Tree shapes
    .byte $20,$4d,$5d,$4d,$20,$20,$20,$20
    ; ... more tree data
```

"Shadow of the Beast" on the Amiga popularized parallax scrolling, but C64 games like "Turrican" and "First Samurai" proved the technique worked beautifully on 8-bit hardware.

## Split-Screen Scrolling

Different parts of the screen can scroll independently:

```asm
; Raster interrupt for split scrolling
; Top = status area (static)
; Bottom = game area (scrolling)

setup_split_scroll:
    ; Install raster interrupt
    sei
    lda #<split_irq
    sta $0314
    lda #>split_irq
    sta $0315
    
    ; Set raster line for split
    lda #50             ; Split at line 50
    sta $d012
    lda $d011
    and #$7f            ; Clear high bit of raster
    sta $d011
    
    ; Enable raster interrupt
    lda #$01
    sta $d01a
    cli
    rts

split_irq:
    ; Top of screen - no scroll
    lda #$08            ; Normal horizontal position
    sta $d016
    lda #$1b            ; Normal vertical position
    sta $d011
    
    ; Wait for game area
.wait_split:
    lda $d012
    cmp #58             ; 8 lines after split
    bne .wait_split
    
    ; Bottom of screen - scrolling
    lda game_scroll_x
    sta $d016
    lda game_scroll_y
    ora #$18            ; Keep screen on
    sta $d011
    
    ; Acknowledge interrupt
    lda #$01
    sta $d019
    
    jmp $ea81           ; Return to kernel

game_scroll_x: .byte 0
game_scroll_y: .byte 0
```

"International Karate +" used split-screen scrolling for its fighting arenas. "Mayhem in Monsterland" created multiple scrolling zones. The raster interrupt makes it possible.

## Color RAM Scrolling

Don't forget that color RAM must scroll too:

```asm
; Efficient color RAM scrolling
scroll_with_color:
    ; Method 1: Inline with screen scroll
    ldx #0
.scroll_both:
    ; Screen and color in same loop
    lda $0401,x         ; Screen memory source
    sta $0400,x         ; Screen memory dest
    lda $d801,x         ; Color RAM source
    sta $d800,x         ; Color RAM dest
    inx
    cpx #999
    bne .scroll_both
    rts

    ; Method 2: Separate color scroll (if needed)
scroll_color_only:
    ldx #0
.color_loop:
    lda $d801,x
    sta $d800,x
    inx
    cpx #999
    bne .color_loop
    rts

    ; Method 3: Lazy color update
    ; Only update color when tile changes
draw_new_tile:
    lda new_tile_id
    cmp last_tile_id    ; Same as before?
    beq .skip_color     ; Skip color update
    
    tax
    lda tile_colors,x
    sta $d800,y         ; Only update when needed
    
.skip_color:
    lda new_tile_id
    sta last_tile_id
    rts

last_tile_id: .byte $ff
new_tile_id:  .byte 0
```

Color RAM is separate from screen RAM and must be scrolled independently. Many games used static colors or repeated patterns to avoid scrolling color RAM entirely.

## Advanced Technique: VSP Scrolling

Variable Screen Positioning (VSP) is an advanced hardware trick:

```asm
; VSP - Hardware trick for fast coarse scrolling
; Moves the entire screen by manipulating VIC timing
; Warning: Can cause crashes on some C64 models

vsp_scroll:
    ; Wait for exact raster position
    lda #$1a
.wait_line:
    cmp $d012
    bne .wait_line
    
    ; Critical timing section
    nop
    nop
    
    ; Manipulate $D011 to confuse VIC
    lda $d011
    and #$f7            ; Clear bit 3
    sta $d011
    
    ; Wait exactly 40 cycles
    ldx #8
.delay:
    dex
    bne .delay
    
    ; Restore
    lda $d011
    ora #$08
    sta $d011
    
    ; Screen has now shifted by hardware!
    rts
```

VSP was discovered by demo coders and used in games like "Mayhem in Monsterland" for incredibly fast scrolling. It's tricky and hardware-dependent, but when it works, it's magic.

## Complete Scrolling Game Framework

Here's everything integrated into a working example:

```asm
* = $0801
    .byte $0c,$08,$0a,$00,$9e,$32,$30,$36,$31,$00,$00,$00

* = $080d
main:
    jsr init_system
    jsr init_level
    
game_loop:
    ; Wait for raster
    lda #$fa
.wait:
    cmp $d012
    bne .wait
    
    ; Update game
    jsr read_input
    jsr update_player
    jsr update_enemies
    jsr update_scrolling
    jsr check_collisions
    jsr update_animations
    
    ; Check game state
    lda game_over
    beq game_loop
    
    jmp show_game_over

init_system:
    ; Set up VIC for scrolling
    lda #$08
    sta $d016           ; Normal X scroll
    lda #$1b  
    sta $d011           ; Normal Y scroll
    
    ; Clear scroll positions
    lda #0
    sta scroll_x_fine
    sta scroll_y_fine
    sta scroll_x_coarse
    sta scroll_x_coarse+1
    sta scroll_y_coarse
    sta scroll_y_coarse+1
    
    ; Set up display
    lda #$18
    sta $d018           ; Character set
    
    rts

update_scrolling:
    ; Auto-scroll based on player position
    lda player_x
    cmp #30             ; Near right edge?
    bcc .check_left
    jsr scroll_right
    jmp .done_scroll
    
.check_left:
    cmp #10             ; Near left edge?
    bcs .done_scroll
    jsr scroll_left
    
.done_scroll:
    ; Update hardware registers
    lda scroll_x_fine
    sta $d016
    lda scroll_y_fine
    ora #$18
    sta $d011
    rts

scroll_right:
    inc scroll_x_fine
    lda scroll_x_fine
    cmp #8
    bne .done
    
    ; Reset and shift
    lda #0
    sta scroll_x_fine
    
    ; Shift screen left
    ldx #0
.shift:
    lda $0401,x
    sta $0400,x
    lda $d801,x
    sta $d800,x
    inx
    cpx #999
    bne .shift
    
    ; Add new column
    inc scroll_x_coarse
    jsr draw_column_right
    
    ; Move player left to compensate
    dec player_x
    
.done:
    rts

draw_column_right:
    ; Get level data
    lda scroll_x_coarse
    and #$3f            ; 64-tile wide pattern
    tax
    
    ldy #0
.draw:
    lda level_data,x
    sta $0427,y         ; Rightmost column
    
    ; Color based on tile
    cmp #$20
    beq .sky
    lda #$0b            ; Ground color
    jmp .set_color
.sky:
    lda #$06            ; Sky color
.set_color:
    sta $d827,y
    
    ; Next row
    tya
    clc
    adc #40
    tay
    
    ; Next tile in pattern
    inx
    txa
    and #$3f
    tax
    
    cpy #25*40
    bcc .draw
    rts

; Game data
game_over:      .byte 0
player_x:       .byte 20
player_y:       .byte 20

; Level data - simple repeating pattern
level_data:
    .byte $20,$20,$20,$20,$20,$20,$20,$20  ; Sky
    .byte $20,$20,$20,$20,$20,$20,$20,$20
    .byte $20,$20,$a0,$20,$20,$20,$e0,$20  ; Platforms
    .byte $e0,$e0,$e0,$e0,$e0,$e0,$e0,$e0  ; Ground
    ; ... repeating pattern
```

This framework provides everything needed for a scrolling game. Add your own graphics, levels, and gameplay!

## Quick Reference

### Scroll Register Bits
**$D011 (Vertical)**
- Bits 0-2: Fine scroll (0-7 pixels)
- Bit 3: 24/25 row display
- Bit 4: Screen blank
- Bit 5: Bitmap mode
- Bit 6: Extended color mode
- Bit 7: Raster bit 8

**$D016 (Horizontal)**
- Bits 0-2: Fine scroll (0-7 pixels)
- Bit 3: 38/40 column display

### Common Issues and Solutions
- **Glitches at edges**: Draw new content before it's visible
- **Color corruption**: Always scroll color RAM with screen RAM
- **Tearing**: Synchronize scrolling with raster beam
- **Memory bandwidth**: Use unrolled loops for speed
- **Corner updates**: Handle diagonal scrolling carefully
