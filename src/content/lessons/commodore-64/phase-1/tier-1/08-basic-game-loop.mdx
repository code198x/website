# Basic Game Loop

**Wonder Moment**: "The game runs smoothly and tracks everything automatically!"

## Why Structure Matters

Professional games separate initialization from the main loop, update in a consistent order, and track timing for smooth gameplay. This structure makes complex games manageable.

<VisualConcept
  title="Game Loop Structure"
  description="The heartbeat of every game"
>
```
INITIALIZATION
     ↓
┌─→ Wait Frame ←─┐
│       ↓        │
│  Read Input    │
│       ↓        │
│  Update Game   │
│       ↓        │
│ Update Display │
│       ↓        │
└────────────────┘
```
</VisualConcept>

## Game States

Define clear states for game flow:

<InteractiveExample
  title="State Management"
  description="Control game flow with states"
>
```asm
; Game states
STATE_INIT = 0                 ; Initialization
STATE_PLAYING = 1              ; Main game
STATE_PAUSED = 2               ; Paused (future)
STATE_GAME_OVER = 3            ; Game over (future)

; Main entry point
main:
        ; Initialize game state
        lda #STATE_INIT
        sta game_state
        
        ; Jump to initialization
        jsr game_init
        
        ; Set playing state
        lda #STATE_PLAYING
        sta game_state
        
        ; Enter main loop
        jmp game_loop
```
</InteractiveExample>

## Initialization Phase

Set up everything before the game starts:

<InteractiveExample
  title="Game Initialization"
  description="Prepare all game systems"
>
```asm
game_init:
        ; Initialize hardware
        jsr init_screen        ; Colors and clear
        jsr init_sprites       ; Sprite setup
        
        ; Initialize game variables
        jsr init_game_vars     ; Positions, counters
        
        ; Display game UI
        jsr display_game_ui    ; Title, instructions
        
        ; Setup complete
        rts

init_game_vars:
        ; Starting position
        lda #4
        sta grid_x
        lda #3
        sta grid_y
        
        ; Reset counters
        lda #0
        sta frame_counter
        sta seconds_counter
        sta move_count
        
        ; Update sprite
        jsr grid_to_sprite_position
        jsr update_sprite_position
        
        rts
```
</InteractiveExample>

## Main Game Loop

The continuous update cycle:

<InteractiveExample
  title="Update Cycle"
  description="Consistent frame processing"
>
```asm
game_loop:
        ; Wait for frame start
        jsr wait_frame_start
        
        ; Update timing
        jsr update_timing
        
        ; Check game state
        lda game_state
        cmp #STATE_PLAYING
        bne skip_game_update
        
        ; Game update cycle
        jsr read_input         ; Get player input
        jsr update_game        ; Update game logic
        jsr update_display     ; Update screen
        
skip_game_update:
        ; Continue forever
        jmp game_loop
```
</InteractiveExample>

## Frame Timing

Synchronize with display refresh:

<InteractiveExample
  title="Frame Synchronization"
  description="Consistent 50Hz timing (PAL)"
>
```asm
wait_frame_start:
        ; Wait for specific raster line
wait_top:
        lda $d012              ; Current raster line
        cmp #251               ; Bottom of screen
        bne wait_top
        
        ; Wait for it to pass
wait_pass:
        lda $d012
        cmp #252
        bne wait_pass
        
        rts

update_timing:
        ; Count frames
        inc frame_counter
        
        ; Check for second elapsed
        lda frame_counter
        cmp #50                ; PAL = 50fps
        bne timing_done
        
        ; Reset frame counter
        lda #0
        sta frame_counter
        
        ; Increment seconds
        inc seconds_counter
        
timing_done:
        rts
```
</InteractiveExample>

## Game Statistics

Track player progress:

<InteractiveExample
  title="Statistics Display"
  description="Show time and moves"
>
```asm
update_game_stats:
        ; Display "TIME: XXX"
        ldx #0
display_time:
        lda time_label,x
        beq time_done
        sta $0400 + 40*22 + 2,x
        inx
        jmp display_time
time_done:

        ; Convert seconds to decimal
        lda seconds_counter
        jsr display_byte_decimal
        
        ; Display "MOVES: XXX"
        ldx #0
display_moves:
        lda moves_label,x
        beq moves_done
        sta $0400 + 40*22 + 20,x
        inx
        jmp display_moves
moves_done:

        ; Display move count
        lda move_count
        ldx #27                ; Position
        jsr display_byte_at_x
        
        rts
```
</InteractiveExample>

- Display frame counter to verify timing
- Show game state on screen
- Use border color for visual timing
- Track maximum frame time

## Key Takeaways

- Separate initialization from main loop
- Update in consistent order every frame
- Synchronize with display refresh
- Track statistics for player feedback
- Use states for game flow control
