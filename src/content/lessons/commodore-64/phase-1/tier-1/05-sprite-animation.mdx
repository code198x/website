## Understanding Sprite Animation

The C64's sprite system allows us to switch between different sprite patterns instantly. By organizing multiple sprite frames and switching between them, we create the illusion of animation.

### Animation Concepts

1. **Sprite Pointers**: Each sprite points to 63 bytes of pattern data
2. **Frame Storage**: Multiple frames stored in different memory locations
3. **Pointer Switching**: Change pointer to change displayed frame
4. **Timing Control**: Animation speed independent of movement

## Code Implementation

Let's add animation to our grid-based movement system:

<InteractiveExample
  title="Sprite Animation System"
  description="Complete animation and direction system"
>
```asm
; Direction constants
DIR_UP = 0
DIR_DOWN = 1
DIR_LEFT = 2
DIR_RIGHT = 3

; Animation constants
ANIM_SPEED = 8                 ; Frames between animation updates
FRAMES_PER_DIR = 2             ; Number of animation frames per direction

; Update sprite frame based on direction and animation
update_sprite_frame:
        ; Calculate which sprite frame to display
        ; sprite_index = (facing_direction * FRAMES_PER_DIR) + animation_frame
        
        lda facing_direction   ; Get current direction (0-3)
        asl                    ; Multiply by 2 (FRAMES_PER_DIR)
        clc
        adc animation_frame    ; Add current animation frame
        
        ; Add base sprite pointer ($0d)
        clc
        adc #$0d
        
        ; Set sprite pointer
        sta $07f8              ; Sprite 0 pointer
        
        rts
```
</InteractiveExample>

### Directional Movement Integration

Each movement direction now updates the facing direction:

<InteractiveExample
  title="Direction Tracking"
  description="Update facing direction on movement"

```asm
try_move_up:
        ; Set facing direction
        lda #DIR_UP
        sta facing_direction
        
        ; Check if we can move up
        lda grid_y             ; Get current Y position
        beq cannot_move        ; If at top (Y=0), can't move up
        
        ; Move up one grid position
        dec grid_y             ; Decrease Y position
        jsr start_movement     ; Start movement animation
        
cannot_move:
        rts
```
</InteractiveExample>

### Animation Timing

The animation system runs independently of movement:

<InteractiveExample
  title="Animation Update Loop"
  description="Frame timing and cycling"
>
```asm
update_animation:
        ; Increment animation counter
        inc animation_counter
        
        ; Check if it's time to update frame
        lda animation_counter
        cmp #ANIM_SPEED
        bcc no_anim_update     ; If less than ANIM_SPEED, don't update
        
        ; Reset counter
        lda #0
        sta animation_counter
        
        ; Update animation frame
        inc animation_frame
        lda animation_frame
        cmp #FRAMES_PER_DIR    ; Check if we've exceeded frame count
        bcc update_sprite      ; If not, update sprite
        
        ; Reset to frame 0
        lda #0
        sta animation_frame
        
update_sprite:
        jsr update_sprite_frame
        
no_anim_update:
        rts
```
</InteractiveExample>

## Creating Your Own Sprites

When designing directional sprites:

1. **Consistency**: Keep character recognizable in all directions
2. **Clear Silhouettes**: Each direction should be distinct
3. **Animation Differences**: Make frames visually different
4. **Pixel Economy**: Use every pixel purposefully

### Sprite Design Tips

- **Walking Animation**: Alternate leg positions between frames
- **Facing Direction**: Clear front/back/side distinctions
- **Character Details**: Add personality with small touches
- **Color Usage**: Consistent palette across all frames

## Debugging Animation

Common animation issues and solutions:

1. **Flickering**: Check sprite pointer calculations
2. **Wrong Frames**: Verify frame ordering in memory
3. **No Animation**: Check animation counter and timing
4. **Direction Confusion**: Verify direction constants match sprite order

## Performance Considerations

- **Pre-load All Frames**: No copying during gameplay
- **Pointer Switching**: Fastest way to change frames
- **Simple Math**: Use shifts for multiplication when possible
- **State Caching**: Only update when state changes

## Practice Exercises

1. **Add More Frames**: Extend to 4 frames per direction
2. **Idle Animation**: Animate character when standing still
3. **Speed Variation**: Different animation speeds for walk/run
4. **Diagonal Sprites**: Add 4 more directions (8-way movement)

## Key Takeaways

- Sprite animation creates life and personality
- Direction facing provides visual feedback
- Animation timing should be independent of movement
- Pre-loading frames enables smooth switching
- State management is crucial for complex animations
