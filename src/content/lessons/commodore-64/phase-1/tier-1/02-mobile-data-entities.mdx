## Understanding Mobile Data Entities

**"Why sprites survived the Collapse"**

The VIC-II chip provides eight hardware sprites - independent visual entities that move without affecting the background. During the Collapse, operators discovered these crucial properties:

### Hardware Independence
- **No CPU overhead**: Sprites move via hardware, not software loops
- **Collision detection**: Hardware reports when entities meet
- **Priority system**: Automatic layering without calculation
- **Fixed memory**: 63 bytes per entity, uncorruptible

### Entity Specifications
Each Mobile Data Entity consists of:
- **24x21 pixels**: Compact but visible
- **Independent color**: Entity signature identification  
- **X/Y positioning**: 0-511 horizontal, 0-255 vertical
- **Collision flags**: Hardware-detected interactions

### The Eight Guardians
Your terminal can deploy up to 8 entities simultaneously:
```
Entity 0-7: $D000-$D00F (position registers)
Colors: $D027-$D02E (signature colors)
Enable: $D015 (deployment register)
```

### Step 2: Initialize Entity Deployment
**"Activate your scout"**

Configure and deploy your entity into the Grid sector:

```assembly
deploy_entity:
        ; Set entity data pointer
        lda #$0d               ; Data at $0340 (13 * 64)
        sta $07f8              ; Entity 0 data pointer
        
        ; Copy pattern to entity memory
        ldx #0
load_pattern:
        lda entity_pattern,x   ; Load pattern byte
        sta $0340,x            ; Store in entity memory
        inx
        cpx #63                ; Full pattern loaded?
        bne load_pattern
        
        ; Enable entity deployment
        lda #$01               ; Activate entity 0
        sta $d015              ; Deployment register
        
        ; Set entity signature color
        lda #$03               ; Cyan (standard scout)
        sta $d027              ; Entity 0 color
        
        ; Initial position (center of sector)
        lda #160               ; X position
        sta $d000              ; Entity 0 X
        lda #0                 ; Clear X MSB
        sta $d010              
        
        lda #120               ; Y position  
        sta $d001              ; Entity 0 Y
        
        rts
```

### Step 3: Autonomous Movement Protocol
**"Let your entity patrol"**

Entities need movement patterns to patrol effectively. This basic protocol moves the entity horizontally across your sector:

```assembly
entity_patrol:
        ; Read current position
        lda $d000              ; Entity 0 X position
        clc
        adc #1                 ; Move right
        sta $d000              ; Update position
        
        ; Check sector boundary
        cmp #$40               ; Right edge approach
        bcc patrol_continue
        
        ; Check extended position bit
        lda $d010              ; X position MSB
        and #$01               ; Entity 0 MSB
        beq patrol_continue
        
        ; Reset to left sector edge
        lda #24                ; Left boundary
        sta $d000
        lda #0
        sta $d010              ; Clear MSB
        
patrol_continue:
        rts
```

## Entity Configuration Protocols

### Protocol 1: Signature Colors
**"Identify your entities"**

Different entity colors indicate different functions:
- **Cyan ($03)**: Standard scout
- **Green ($05)**: Data collector
- **Yellow ($07)**: Warning beacon
- **Red ($02)**: Combat unit

```assembly
lda #$03               ; Cyan for scout
sta $d027              ; Entity 0 color
```

### Protocol 2: Formation Deployment
**"Multiple entities in pattern"**

Deploy multiple entities in formation:
```assembly
lda #$07               ; Enable entities 0,1,2
sta $d015              ; Deploy all three
```

### Protocol 3: Speed Variation
**"Different patrol speeds"**

Modify movement increments for different speeds:
```assembly
; Fast patrol
lda #2
; Slow patrol  
lda #1
```

## Technical Reference

### Sprite Registers
- **$D000-$D001**: Entity 0 X/Y position
- **$D010**: X position MSB for all entities
- **$D015**: Entity enable register
- **$D027**: Entity 0 color

### Memory Layout
- **$0340-$037F**: Entity 0 pattern data (63 bytes)
- **$07F8**: Entity 0 data pointer

### Critical Values
- Screen width: 320 pixels (plus 192 extended)
- Screen height: 200 pixels
- Entity size: 24x21 pixels
- Pattern size: 63 bytes
