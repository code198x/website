# Lesson 2: Neon Nexus - Your Game Entity

**Your neon grid world needs a player!** In the last lesson, you created the striking visual foundation of Neon Nexus. Today, you'll add the most important element - a controllable geometric entity that moves smoothly through your world. Get ready to see your first interactive game come to life!

## Your Player Entity Appears

Let's start with the magic - adding your controllable player to the neon world:

```nasm
; Neon Nexus - Player Entity Creation
* = $0801

; BASIC stub to make program runnable
!byte $0c, $08, $0a, $00, $9e, $20, $32, $30, $36, $34, $00, $00, $00

start:
    ; Set up neon grid from Lesson 1
    lda #$93        ; Clear screen
    sta $0400
    lda #$2d        ; Horizontal lines  
    sta $0401
    sta $0402
    sta $0403
    lda #$7c        ; Vertical lines
    sta $0428
    sta $0450
    
    ; Create player entity at starting position
    ldx #$05        ; Player X position (5)
    ldy #$03        ; Player Y position (3)
    
    ; Store player position in memory for tracking
    stx $80         ; Save X position to Zero Page
    sty $81         ; Save Y position to Zero Page
    
    ; Calculate screen position and place player
    jsr place_player
    
    ; Set neon colors for world and player
    lda #$0e        ; Neon cyan for grid
    sta $d800
    sta $d801
    sta $d802
    sta $d803
    
    lda #$07        ; Bright yellow for player
    sta $d805       ; Player color
    
    ; Game loop - infinite for now
loop:
    jmp loop

; Subroutine: Place player on screen at current X,Y position
place_player:
    ; Calculate screen address from X,Y coordinates
    lda #$00        ; Start with screen base
    sta $fb         ; Low byte of screen address
    lda #$04        ; High byte ($0400)
    sta $fc
    
    ; Add Y offset (40 * Y position)
    ldy $81         ; Load Y position
    beq no_y_offset ; If Y=0, skip Y calculation
y_loop:
    lda $fb
    clc
    adc #40         ; Add 40 for each row
    sta $fb
    bcc no_carry
    inc $fc         ; Handle carry to high byte
no_carry:
    dey
    bne y_loop
    
no_y_offset:
    ; Add X offset
    lda $fb
    clc
    adc $80         ; Add X position
    sta $fb
    bcc no_x_carry
    inc $fc
no_x_carry:
    
    ; Place player character (geometric entity)
    lda #$51        ; Player character (diamond shape)
    ldy #$00
    sta ($fb),y     ; Store player at calculated position
    
    rts
```

## What Just Happened? The Magic Behind Your Game Entity

Now that you've seen your player appear, let's understand how the 6502 made it happen through **game object management**.

### X and Y Registers: Your Position Tracking System

The most important thing to understand: **the X and Y registers are perfect for tracking game object positions**. In your player entity code:

```nasm
ldx #$05        ; Player X position (5)
ldy #$03        ; Player Y position (3)
stx $80         ; Save X position to Zero Page
sty $81         ; Save Y position to Zero Page
```

This sequence:
1. Loads the player's starting X coordinate (5) into the **X register**
2. Loads the player's starting Y coordinate (3) into the **Y register**
3. Stores both positions in **Zero Page memory** for fast access

### Memory as Your Game's Data Storage

**Zero Page memory** ($00-$FF) is your game's high-speed data area:
- **$80**: Player X position (horizontal)
- **$81**: Player Y position (vertical)  
- **$82-$8F**: Available for enemy positions, scores, health, etc.

This is like your game's "clipboard" - fast memory for frequently accessed data.

### The STA Family: Your Game Object Placement Tools

You now have three powerful instructions for game object management:

```nasm
STA $0400       ; Store A register to screen memory
STX $80         ; Store X register to memory (player X position)
STY $81         ; Store Y register to memory (player Y position)
```

**Why this matters for games**: You can track multiple objects simultaneously using different registers and memory locations.

### Screen Coordinate System

Understanding the C64's screen layout is crucial for game development:

```
Screen = 40 characters wide × 25 characters tall

Memory Address = $0400 + (Y * 40) + X

Examples:
Position (0,0) = $0400 + (0 * 40) + 0 = $0400  (top-left)
Position (5,3) = $0400 + (3 * 40) + 5 = $0479  (your player!)
Position (39,24) = $0400 + (24 * 40) + 39 = $07E7 (bottom-right)
```

Your `place_player` subroutine calculates this automatically!

## Practice: Create Multiple Entities

Let's expand your neon world with multiple game objects:

```nasm
    ; Create second entity (enemy or power-up)
    ldx #$10        ; Enemy X position (16)
    ldy #$08        ; Enemy Y position (8)
    stx $82         ; Store enemy X in memory
    sty $83         ; Store enemy Y in memory
    
    ; Place enemy on screen
    jsr calc_screen_pos  ; Calculate screen address
    lda #$2a        ; Enemy character (star shape)
    sta ($fb),y     ; Place enemy
    
    ; Set enemy color
    lda #$02        ; Red color for enemy
    sta $d810       ; Enemy color position
    
calc_screen_pos:
    ; Calculate screen position from X,Y in $82,$83
    lda #$00
    sta $fb
    lda #$04
    sta $fc
    
    ; Add Y offset
    ldy $83
    beq done_y
enemy_y_loop:
    lda $fb
    clc
    adc #40
    sta $fb
    bcc no_enemy_carry
    inc $fc
no_enemy_carry:
    dey
    bne enemy_y_loop
    
done_y:
    ; Add X offset
    lda $fb
    clc
    adc $82
    sta $fb
    bcc done_pos
    inc $fc
done_pos:
    rts
```

### Quick Reference: Today's Game Programming Instructions

- **LDX #value**: Load X register with position coordinate
- **LDY #value**: Load Y register with position coordinate  
- **STX address**: Store X register (position) to memory
- **STY address**: Store Y register (position) to memory
- **STA ($fb),Y**: Store character to calculated screen position

Save this reference - you'll use these instructions to manage all your game entities!
