## Your First Game Screen

Let's start with the magic. Here's the code that creates your neon game world:

```nasm
; Neon Nexus - Game World Creation
* = $0801

; BASIC stub to make program runnable
!byte $0c, $08, $0a, $00, $9e, $20, $32, $30, $36, $34, $00, $00, $00

start:
    ; Create the neon grid world
    lda #$93        ; Clear screen character
    sta $0400       ; Top-left corner of screen
    
    lda #$2d        ; Horizontal line character  
    sta $0401       ; Create grid line
    sta $0402
    sta $0403
    
    lda #$7c        ; Vertical line character
    sta $0428       ; Next row down
    sta $0450       ; Two rows down
    
    ; Set neon colors
    lda #$0e        ; Light blue (neon cyan)
    sta $d800       ; Color memory for grid
    sta $d801
    sta $d802
    sta $d803
    
    ; Infinite loop to admire your creation
loop:
    jmp loop
```

## What Just Happened? The Magic Behind Your Game

Now that you've seen something cool happen, let's understand the magic. This is how the **6502 processor** - the brain of your C64 - made your game world appear.

### The Screen is Memory

The most important thing to understand: **everything you see on the C64 screen is stored in memory**. When you want graphics in your game, you're actually writing data to specific memory locations.

```nasm
lda #$93        ; Load the "clear screen" character
sta $0400       ; Store it at screen position 0,0
```

This simple instruction:
1. Loads character $93 (a special character) into the **A register**
2. Stores it at memory location $0400 (the top-left corner of the screen)

### The A Register: Your Graphics Tool

The **A register** (accumulator) is like the processor's primary hand. When you want to put something on screen:

### Screen Memory: Your Game Canvas

The C64 screen is a 40×25 grid of characters. Each position has a memory address:

```
$0400 = Row 0, Column 0 (top-left)
$0401 = Row 0, Column 1 (one space right)
$0428 = Row 1, Column 0 (one row down)
$0450 = Row 2, Column 0 (two rows down)
```

**For games**, this means you can put anything anywhere on screen by writing to the right memory address!

### Color Memory: Making It Glow

But wait - there's more! The C64 has separate **color memory** starting at $D800:

```nasm
lda #$0e        ; Light blue color
sta $d800       ; Color for screen position 0,0
```

Each screen position has two values:
- **Character** (what shape/symbol): stored at $0400-$07E7
- **Color** (what color): stored at $D800-$DBE7

This is why C64 graphics can be so vibrant and distinctive!

## Understanding Game Programming

### Why Assembly for Games?

You might wonder: "Why not use BASIC?" Here's why assembly makes better games:

**BASIC Version** (slow, limited):
```basic
FOR I = 1 TO 100
  POKE 1024 + I, 45
NEXT I
```

**Assembly Version** (fast, powerful):
```nasm
ldx #100
loop:
  lda #45
  sta $0400,x
  dex
  bne loop
```

The assembly version is **orders of magnitude faster** and gives you direct control over the hardware.

### Your Game Architecture

In **Neon Nexus**, you'll use these same concepts to create:
- **Player entities** (characters moving on screen)
- **Enemy entities** (AI-controlled opponents)  
- **Visual effects** (explosions, trails, particles)
- **User interface** (scores, health, status)
- **Sound effects** (electronic beeps and music)

All using the same fundamental principle: **store the right values in the right memory locations**.

### Quick Reference: Today's Assembly Instructions

- **LDA #value**: Load a value into the A register
- **STA address**: Store A register contents to memory address  
- **$0400**: Start of screen memory (top-left corner)
- **$D800**: Start of color memory
- **JMP label**: Jump to a program location (infinite loop)

Save this reference - you'll use these instructions in every game you create!
