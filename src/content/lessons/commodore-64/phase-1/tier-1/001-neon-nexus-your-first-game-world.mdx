# Lesson 1: Neon Nexus - Your First Game World

Welcome to assembly programming on the Commodore 64! Today, you'll create the foundation of **Neon Nexus**, a fast-paced action game set in a glowing electronic arena. But we'll start small - just getting something on screen.

## Setting Up Your Development Environment

Before we can write any code, we need to install our tools. We'll use **CC65**, a modern, cross-platform toolchain that includes the CA65 assembler.

### Windows Setup

1. **Download CC65:**
   - Go to https://cc65.github.io/
   - Download the Windows snapshot (cc65-win32.zip)
   - Extract to `C:\cc65`

2. **Add to PATH:**
   - Right-click "This PC" → Properties → Advanced system settings
   - Click "Environment Variables"
   - Under System Variables, find "Path" and click Edit
   - Add new entry: `C:\cc65\bin`
   - Click OK to save

3. **Test installation:**
   - Open Command Prompt (cmd)
   - Type: `ca65 --version`
   - Should show: CA65 version info

4. **Get VICE emulator:**
   - Download from https://vice-emu.sourceforge.io/
   - Install to default location
   - VICE includes `x64sc` - the accurate C64 emulator

### macOS Setup

1. **Using Homebrew (recommended):**
   ```bash
   # Install Homebrew if you don't have it
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   
   # Install cc65
   brew install cc65
   
   # Install VICE
   brew install --cask vice
   ```

2. **Manual installation:**
   - Download cc65 from https://cc65.github.io/
   - Extract and add to PATH in ~/.zshrc or ~/.bash_profile:
   ```bash
   export PATH="$PATH:/path/to/cc65/bin"
   ```

3. **Test installation:**
   ```bash
   ca65 --version
   ```

### Linux Setup

**Ubuntu/Debian:**
```bash
# Install cc65
sudo apt-get update
sudo apt-get install cc65

# Install VICE
sudo apt-get install vice
```

**Arch Linux:**

**Other distros:**

## Your First Assembly Program

Let's start with the absolute minimum - a program that does nothing but runs.

Create a new file called `neon1.s` (the `.s` extension is standard for assembly source files) and type:

```asm
; Neon Nexus - Lesson 1
; Our first C64 program

.segment "LOADADDR"
.word $c000             ; Tell C64 to load at $c000 (49152)

.segment "CODE"
start:
        rts             ; Return to BASIC
```

**What's happening here?**
- `.segment "LOADADDR"` creates the PRG file header
- `.word $c000` tells the C64 to load our program at address $c000 (49152)
- `.segment "CODE"` contains our actual program
- `start:` is a label marking where our code begins
- `rts` (Return from Subroutine) gives control back to BASIC
- We'll run this with `SYS 49152` after loading

## Assembling Your First Program

Now let's turn this source code into a program the C64 can run.

### Simple Assembly with CA65

For C64 programs, we need two files: our assembly source and a simple memory configuration. 

First, create `c64.cfg` with this content:

```
MEMORY {
    ZP: start = $0002, size = $001A, type = rw, define = yes;
    LOADADDR: start = $0000, size = $0002, type = ro;
    RAM: start = $c000, size = $3000, type = rw, define = yes;
}

SEGMENTS {
    LOADADDR: load = LOADADDR, type = ro;
    CODE: load = RAM, type = ro, start = $c000;
}

FILES {
    %O: format = bin;
}
```

Now build with these commands:

```bash
ca65 -o neon1.o neon1.s
ld65 -C c64.cfg -o neon1.prg neon1.o
```

The config file tells LD65 to create a proper C64 PRG file with load address header.

### Step 3: Run in VICE

**Windows:**
```bash
"C:\Program Files\VICE\x64sc.exe" neon1.prg
```

**macOS/Linux:**
```bash
x64sc neon1.prg
```

You'll see "LOADING" then "READY." - but the program hasn't run yet! 

**Type `RUN` and press Enter** to actually execute your program.

Nothing visible happens with this first version - but it worked!

## Troubleshooting

**"Command not found" errors?**
- Check that cc65 is in your PATH
- Try using the full path to ca65/ld65
- Restart your terminal after PATH changes

**Assembly errors?**
- Check for typos - assembly is very picky!
- Make sure you saved the file
- Use `.s` extension for source files

**VICE won't start?**
- Check VICE is installed correctly
- Try running VICE without a program first
- On Linux, you might need `x64` instead of `x64sc`

## Adding Our First Visual Effect

Now let's make something happen. Create a new file called `neon-red.s`:

```asm
; Neon Nexus - Lesson 1
; Adding color to our first C64 program

.segment "LOADADDR"
.word $c000             ; Tell C64 to load at $c000 (49152)

.segment "CODE"
start:
        lda #$02        ; Load 2 (red) into accumulator  
        sta $d020       ; Store it to border color register
        rts             ; Return to BASIC
```

**New concepts:**
- `lda` (Load Accumulator) puts a value into the A register
- `#$02` means the literal number 2 (in hex)
- `sta` (Store Accumulator) saves the A register to memory
- `$d020` is the C64's border color register

Assemble and run this version:
```bash
ca65 -o neon-red.o neon-red.s
ld65 -C c64.cfg -o neon-red.prg neon-red.o
x64sc neon-red.prg
```

After loading, **type `SYS 49152`** and press Enter.

Your border should turn red! 

**If the border didn't change:**

1. First test VICE works: `POKE 53280,2` and press Enter
   - This should turn the border red - if it doesn't, VICE has an issue
   
2. Check our program loaded: `PRINT PEEK(49152)` 
   - Should show 169 (the LDA #$02 instruction)

3. Try the SYS command again: `SYS 49152`

**Alternative test version with a visible effect - create `neon-increment.s`:**
```asm
; Neon Nexus - Lesson 1
; Increment test version

.segment "LOADADDR"
.word $c000

.segment "CODE"
start:
        inc $d020       ; Increment border color
        inc $d020       ; Do it twice for visible change
        rts
```

This should definitely change the border color by adding 2 to whatever it was.

Try changing `#$02` to other values:
- `#$00` = black
- `#$01` = white
- `#$02` = red  
- `#$05` = green
- `#$0e` = light blue

## Creating the Neon Arena

Let's expand our program to set up a proper game screen. Create `neon-arena.s`:

```asm
; Neon Nexus - Lesson 1
; Creating our neon arena

.segment "LOADADDR"
.word $c000

.segment "CODE"
start:
        ; Set border color to dark blue
        lda #$06     
        sta $d020       ; Border color register
        
        ; Set background color to black
        lda #$00
        sta $d021       ; Background color register
        
        ; Clear the screen
        lda #$93        ; Clear screen character (147 in decimal)
        jsr $ffd2       ; Call KERNAL CHROUT routine
        
        rts
```

**What's new:**
- `$d021` controls the background color
- `jsr` (Jump to Subroutine) calls built-in C64 routines
- `$ffd2` is CHROUT - it prints the character in A register
- Character 147 ($93) clears the screen

## Making Assembly Easier with a Build Script

Typing commands every time gets old. Let's create a robust build script:

**Windows (build-c64.bat):**
```batch
@echo off
if "%1"=="" (
    echo Usage: %0 filename (without .s extension)
    exit /b 1
)
echo Building %1 for C64...
ca65 -o %1.o %1.s
if %errorlevel% neq 0 exit /b %errorlevel%
ld65 -C c64.cfg -o %1.prg %1.o
if %errorlevel% neq 0 exit /b %errorlevel%
echo Success! Created %1.prg
echo To run in VICE: x64sc %1.prg then type: SYS 49152
```

**macOS/Linux (build-c64.sh):**
```bash
#!/bin/bash
if [ -z "$1" ]; then
    echo "Usage: $0 filename (without .s extension)"
    exit 1
fi
echo "Building $1 for C64..."
ca65 -o "$1.o" "$1.s" || exit 1
ld65 -C c64.cfg -o "$1.prg" "$1.o" || exit 1
echo "Success! Created $1.prg"
echo "To run in VICE: x64sc $1.prg then type: SYS 49152"
```

Make it executable (macOS/Linux):
```bash
chmod +x build-c64.sh
```

Now you can build with:
- Windows: `build-c64 neon1`  
- macOS/Linux: `./build-c64.sh neon1`

## Adding Your Arena Title

Let's display "NEON NEXUS" on screen to complete our foundation. Create `neon-title.s`:

```asm
; Neon Nexus - Lesson 1
; Adding title to our arena

.segment "LOADADDR"
.word $c000

.segment "CODE"
start:
        ; Color setup from previous example
        lda #$06     
        sta $d020
        lda #$00
        sta $d021
        lda #$93
        jsr $ffd2
        
        ; Position cursor for title
        lda #$13        ; HOME character (19 decimal)
        jsr $ffd2       ; Cursor to top-left
        
        ; Print each letter of "NEON"
        lda #'N'        ; ASCII letter N
        jsr $ffd2       ; Print it
        lda #'E'     
        jsr $ffd2
        lda #'O'
        jsr $ffd2
        lda #'N'
        jsr $ffd2
        
        rts
```

## Complete Lesson 1 Program

Here's our complete first program with proper comments. Create `neon-complete.s`:

```asm
;===============================================
; NEON NEXUS - Lesson 1: First Game World
; A simple start to our assembly game
;===============================================

.segment "LOADADDR"
.word $c000             ; Load at $c000 (49152)

.segment "CODE"
;-----------------------------------------------
; Main Program Entry Point
;-----------------------------------------------
start:
        ; Set up neon color scheme
        lda #$06        ; Dark blue border
        sta $d020       ; VIC-II border color
        lda #$00        ; Black background
        sta $d021       ; VIC-II background color
        
        ; Clear and prepare screen
        lda #$93        ; Clear screen character
        jsr $ffd2       ; KERNAL CHROUT routine
        
        ; Position cursor home
        lda #$13        ; HOME character
        jsr $ffd2       ; Move cursor to top-left
        
        ; Display title
        lda #'N'
        jsr $ffd2
        lda #'E'  
        jsr $ffd2
        lda #'O'
        jsr $ffd2
        lda #'N'
        jsr $ffd2
        
        ; Done - return to BASIC
        rts

; End of program
```

## Bonus: Auto-Running Version

Want your program to run automatically when loaded? Create `neon-autorun.s`:

```asm
;===============================================
; NEON NEXUS - Lesson 1: Auto-Running Version
; Runs automatically when loaded!
;===============================================

.segment "LOADADDR" 
.word $0801             ; Load at BASIC program area

.segment "CODE"
; BASIC program: 10 SYS 2064
.word $080b             ; Next line pointer
.word 10                ; Line number 10  
.byte $9e               ; SYS token
.byte " 2064", 0        ; Address to call (our machine code)
.word 0                 ; End of BASIC program

; Our machine code starts here (at address 2064)
start:
        ; Set up neon color scheme
        lda #$06        ; Dark blue border
        sta $d020       ; VIC-II border color
        lda #$00        ; Black background
        sta $d021       ; VIC-II background color
        
        ; Clear and prepare screen
        lda #$93        ; Clear screen character
        jsr $ffd2       ; KERNAL CHROUT routine
        
        ; Position cursor home
        lda #$13        ; HOME character
        jsr $ffd2       ; Move cursor to top-left
        
        ; Display title
        lda #'N'
        jsr $ffd2
        lda #'E'  
        jsr $ffd2
        lda #'O'
        jsr $ffd2
        lda #'N'
        jsr $ffd2
        
        ; Done - return to BASIC
        rts

; End of program
```

This version includes a BASIC program stub that automatically runs your assembly code!

Build and run your complete program:
```bash
ca65 -o neon-complete.o neon-complete.s
ld65 -C c64.cfg -o neon-complete.prg neon-complete.o
x64sc neon-complete.prg
```

Remember: after loading, **type `SYS 49152`** to execute!

For the auto-running version:
```bash
ca65 -o neon-autorun.o neon-autorun.s
ld65 -C c64.cfg -o neon-autorun.prg neon-autorun.o
x64sc neon-autorun.prg
```

The auto-run version executes immediately when loaded - **just type `RUN`** and press Enter!
