**Learn how the C64 reads player input through the CIA chip**

Interactive programs need to respond to player input. The C64's joystick ports connect directly to the CIA (Complex Interface Adapter) chip, which converts physical switch presses into data your program can read. This direct hardware access enables the instant response that made C64 games so playable.

## Understanding Joystick Input

In 1982, the joystick was revolutionary. While other computers required keyboard commands, the C64 offered immediate, intuitive control. Just grab the stick and push - no typing required. This accessibility helped create the gaming revolution.

The Atari-standard joysticks that plugged into the C64 weren't complex devices - they were brilliantly simple. Inside that black plastic shell were just five switches and no electronics at all. When you pushed the stick, metal contacts touched, completing a circuit. This simplicity meant they were cheap, reliable, and responsive.

### The CIA Chip: Your Input Gateway

The CIA (Complex Interface Adapter) chips are the C64's connection to the outside world. CIA #1 handles the keyboard and joystick ports. It constantly monitors these ports, updating memory locations with the current state 60 times per second. You don't need to worry about timing or debouncing - the CIA handles it all.

The C64 has two 9-pin joystick ports that can read:
- **4 cardinal directions** (up, down, left, right)
- **1 fire button** (sometimes two on special controllers)
- **Diagonal combinations** for true 8-way movement
- **Paddle controllers** (analog input - we'll cover these later)

### How Joysticks Work: The Beauty of Simplicity

The joystick is beautifully simple - it's just switches that connect pins to ground:
- **Each direction is a bit in memory** - one bit per switch
- **Pressed = 0** (grounded, current flows)
- **Released = 1** (pulled high by internal resistors)

This inverted logic (0 = pressed) might seem backwards, but it's actually clever engineering. The CIA chip has internal "pull-up" resistors that keep all lines at logic 1 (high voltage) by default. When you press the joystick, it connects that line to ground (logic 0). This design prevents floating voltages and ensures reliable readings.

This same principle is used in modern controllers - your PlayStation or Xbox controller still uses switches and ground connections, just with more complexity layered on top.

### Step 2: Reading Joystick Values

**Understanding bit operations:** To check individual joystick directions, we use:
- **AND** - Masks out all bits except the one we want to test
- **LSR** (Logical Shift Right) - Moves bits right, putting the rightmost bit into the carry flag
- **BNE/BEQ** - Branch if not equal/equal to zero (tests if bit was set)

The key to joystick reading is checking individual bits:

<CodeBlock title="Reading Joystick Input - Bit Testing Method" language="asm" code={`main_loop:
        ; Wait for raster (smooth movement)
        lda #250
wait:   cmp $d012
        bne wait
        
        ; Read joystick port 2
        lda $dc00              ; Get joystick value
        sta joystick_state     ; Store for checking
        
        ; Check each direction
        lda joystick_state
        and #%00000001         ; Test UP bit
        bne check_down         ; If 1, not pressed
        
        ; Move up
        dec $d001              ; Decrease Y position
        
check_down:
        lda joystick_state
        and #%00000010         ; Test DOWN bit
        bne check_left
        
        ; Move down
        inc $d001              ; Increase Y position
        
check_left:
        lda joystick_state
        and #%00000100         ; Test LEFT bit
        bne check_right
        
        ; Move left
        dec $d000              ; Decrease X position
        
check_right:
        lda joystick_state
        and #%00001000         ; Test RIGHT bit
        bne check_fire
        
        ; Move right
        inc $d000              ; Increase X position
        
check_fire:
        lda joystick_state
        and #%00010000         ; Test FIRE bit
        bne done_input
        
        ; Fire pressed - start the game!
        ; For now, flash the screen to show it works
        lda $d020              ; Get current border
        eor #$01               ; Toggle between 0 and 1
        sta $d020              ; Flash border
        
        ; In lesson 7, this will transition to gameplay!
        
done_input:
        jmp main_loop

joystick_state:
        !byte 0`} />

### Step 3: Improving Response

The basic version works but can be improved:

<CodeBlock title="Improved Movement - Shift Register Method" language="asm" code={`; Better movement with speed control
move_sprite:
        ; Read joystick
        lda $dc00
        sta joystick_state
        
        ; Vertical movement
        lda joystick_state
        lsr                    ; Shift UP bit to carry
        bcs no_up              ; If 1, not pressed
        ldy $d001
        dey                    ; Move up 1 pixel
        dey                    ; Move up 2 pixels (faster!)
        sty $d001
no_up:
        
        lsr                    ; Shift DOWN bit to carry
        bcs no_down
        ldy $d001
        iny
        iny                    ; Move down 2 pixels
        sty $d001
no_down:
        
        ; Horizontal movement
        lsr                    ; Shift LEFT bit to carry
        bcs no_left
        ldy $d000
        dey
        dey                    ; Move left 2 pixels
        sty $d000
no_left:
        
        lsr                    ; Shift RIGHT bit to carry
        bcs no_right
        ldy $d000
        iny
        iny                    ; Move right 2 pixels
        sty $d000
no_right:
        rts`} />

### Acceleration and Inertia

Make movement feel more natural:

<CodeBlock title="Acceleration and Inertia Physics" language="asm" code={`x_velocity:     !byte 0
y_velocity:     !byte 0

apply_physics:
        ; Add acceleration from joystick
        lda joystick_state
        lsr
        bcs no_accel_up

        lsr
        bcs no_accel_down
        inc y_velocity         ; Accelerate down

        jmp no_y_friction

        rts`} />

## Common Problems and Solutions

### "Sprite moves too fast"
- Add a frame counter to slow movement
- Move by 1 pixel instead of 2
- Add acceleration/deceleration

### "Diagonal movement is too fast"
- Check if moving diagonally and reduce speed
- Use proper vector math (advanced)

### "Sprite flickers"
- Always wait for raster before moving
- Keep movement code efficient
- Don't update position multiple times per frame

### "Controls feel sluggish"
- Check you're reading joystick every frame
- Reduce any delays in main loop
- Increase movement speed
