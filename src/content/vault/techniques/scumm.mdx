SCUMM was never meant to outlive the game it was named after. "When I was first building that engine, I never thought it would be used beyond *Maniac Mansion*," [Ron Gilbert](/vault/people/ron-gilbert) told *Retro Gamer* in 2013. "It was just a tool to get that game done." He had started writing *[Maniac Mansion](/vault/games/maniac-mansion)* in 6502 assembly language for the Commodore 64, found it "just too complex", and spent "a good year" building a scripting language instead. The Script Creation Utility for Maniac Mansion went on to run every [LucasArts](/vault/companies/lucasarts) adventure for the next ten years, from *Zak McKracken* to *The Curse of Monkey Island*, and its scripts were still driving the *Monkey Island* special editions on the Xbox 360 and iPhone a quarter of a century later.

## Fast facts

- **Name:** Script Creation Utility for Maniac Mansion.
- **Built by:** Ron Gilbert at Lucasfilm Games, with Aric Wilmunder, who moved the system to the PC; Chip Morningstar wrote the first compiler.
- **First game:** *Maniac Mansion* (1987), on the Commodore 64.
- **Last LucasArts game:** *The Curse of Monkey Island* (1997). *[Grim Fandango](/vault/games/grim-fandango)* (1998) moved to a new engine.
- **Also used by:** Humongous Entertainment, Gilbert's later company, for its children's adventures.
- **Today:** ScummVM, an open-source reimplementation of the interpreter, started in 2001.

## Why it was built

Gilbert's complaint was the text parser. "I played the King's Quest games right as I was starting out thinking of *Maniac Mansion*," he recalled, "and the thing that always bothered me was the parser because I didn't like to type." He called the result a game of "second guess the parser": you could see the thing on the screen you wanted to use, but had to guess what the programmer had called it. "It just made more sense to me to just point at an object and 'touch' it." Lucasfilm's *Labyrinth* (1986) had been a first step, Gilbert said, but it "still had a parser".

The other insight was about where the work went. Chip Morningstar, the Lucasfilm programmer who helped Gilbert at the start, explained it in 2013: the delicate, performance-tuned code, "mainly graphics rendering", was written once and then left alone, while the game logic, which changed constantly during development, was "not terribly performance sensitive". That part could go into a language that was easy to write, update and debug. Gilbert specified the language and its byte code, and Morningstar wrote a compiler to translate one into the other. Aric Wilmunder, then working on the animation and walking code for Lucasfilm's online world *Habitat*, joined because a version of that code went into *Maniac Mansion*.

## How it worked

Gilbert described SCUMM as two things: "a programming language which you type in with an editor and compile with a compiler", and a set of in-house tools for animation, sound, fonts and rooms. Only the graphics were drawn in an outside program, first [Deluxe Paint](/vault/tools/deluxe-paint) and later Photoshop.

The program the player actually ran was a separate interpreter. During development it was called SPUTM, the "Scumm Presentation Utility (TM)"; it set up the graphics and sound, read the game files from disk, and ran the scripts and data inside them. For release it was renamed after the game, as `MONKEY.EXE` or `DIG.EXE`. SCUMM itself was the tool that tokenised the scripts and packed them, with the art and sound, into the files that shipped. The team named its other tools in the same spirit, after bodily fluids: SPIT was the font editor, FLEM managed rooms, and BYLE animated the characters.

Several features set the language apart:

- **Multi-tasking.** Many scripts ran at once, one for each character, each timed event and each piece of background business. *START* magazine described SCUMM in 1989 as "a hybrid language" with "a C-like structure" that "allows multi-tasking, ie multiple parallel scripts to follow the actions of more than one character". David Fox, who programmed on *Maniac Mansion*, said its brilliance was that it handled "the characters onscreen, the game logic, multitasking and more, while still working with a high-level language, one that let us write using near-English commands".
- **Readable scripts.** [Tim Schafer](/vault/people/tim-schafer), whose first job at Lucasfilm was programming in SCUMM, said the language "goes out of its way not to have unnecessary brackets, strange symbols or weird naming conventions"; a script reads as "Guybrush walk to window, say this line". Gilbert's aim had been a language that non-programmers could use, though he doubted it "ever fulfilled that ultimate goal".
- **Cut-scenes.** *Maniac Mansion*'s scenes of Dr Fred plotting elsewhere in the house ran on timers, and the game "would literally just cut away" to them. SCUMM had a command, `cutscene`, that saved the game state, played the scene and restored the state afterwards. Gilbert believed that is how "cut-scene" became a general term in games.

## One script, many machines

Because the game lived in data files, moving it to another computer meant rewriting only the interpreter. "All you had to re-write was SPUTM," Schafer said, "and then the SCUMM files were all totally identical." Fox made the same point in 2005: "because we were working in a high-level language, it was much easier to port to other platforms." Gilbert compared it with Infocom's Z-machine, which had done the same for text adventures.

The first game shows what that meant in practice. *Maniac Mansion* was a Commodore 64 disk game, and ZZAP! 64 reviewed it in December 1987, awarding 93%. The review describes the system in action: a horizontally scrolling view of the chosen teenager, with a list of verbs and the inventory below, and commands built by moving a joystick cursor from verb to object to inventory item until the message line reads "unlock door with key". The game switched between the three characters on the function keys and cut away to "a cameo scene happening elsewhere around the house". ZZAP!'s reviewers judged that "the control method is a doddle to use, and makes the action incredibly easy to get into".

The system grew with the hardware. *START* reported in 1989 that *Zak McKracken* (1988) had been made with SCUMM version 2.0, at 160 by 200 pixels with character-based graphics, and that *Indiana Jones and the Last Crusade* used version 3.0, at 320 by 200 with pixel-based graphics and smoother animation. "We've left the Commodore 64 world behind," Lucasfilm's Red Redmer told the magazine. The games went on to the PC, Amiga and Atari ST, and *Maniac Mansion* was translated for the Nintendo Entertainment System. That port had its own cost: Nintendo's content rules forced the LucasArts programmer Douglas Crockford and his team to cut dialogue and imagery, and even references to "NES SCUMM". *The Secret of Monkey Island* later appeared on Sega's CD add-on.

## From one game to a house engine

SCUMM became a general tool because of the second game. David Fox wanted to make his own adventure, *Zak McKracken and the Alien Mindbenders*, and was used to the system. "I had to make a few changes because there were parts of SCUMM that were very hard-coded for *Maniac*," Gilbert said, "and I had to remove all that stuff. Once I did that the system became very generic." Wilmunder estimated that the version used for *Maniac Mansion* shared "80% or more of the commands" with games as late as *Full Throttle* (1995).

New arrivals learned it at what the staff called SCUMM University. Schafer remembered Gilbert coming in every afternoon to teach one thing, such as "how you add a room to the game", while the trainees, the "Scummlets", built improvised games of their own from borrowed art.

Gilbert thought the system mattered to the company's direction. Lucasfilm Games could not make Star Wars games in its early years because the licence was held elsewhere, and SCUMM "gave us this easy way to do these games that were predominantly about story".

## iMUSE

In 1991 *Monkey Island 2: LeChuck's Revenge* added iMUSE, a music system built into SCUMM by the composers Michael Land and Peter McConnell. The magazines of 1992 gave its name as Interactive Music and Sound Effects; later accounts expand it as Interactive Music Streaming Engine. Instead of starting a new piece of music in each location, the score changed as the player moved, without a break. *Game Informer* explained that each part of the game had a theme which "changes slightly" from area to area, and that when Guybrush was feeling romantic "the tenor saxophone takes over".

It was not seamless at first. *PC Review*, reviewing *Indiana Jones and the Fate of Atlantis*, iMUSE's second outing, in 1992, found that in *Monkey Island 2* "you could often force the changes by moving from one part of the screen to the other. To be blunt, you could see the joins." In *Fate of Atlantis*, it said, it was "a lot harder to see where one score ends". The system also needed a sound card; the magazine recommended a Roland.

By *Full Throttle*, *Retro Gamer* noted, LucasArts had built INSANE, the video engine first written for *Rebel Assault*, into SCUMM, so real-time animation could be mixed with pre-rendered video. *The Curse of Monkey Island* was the last LucasArts adventure on the system. Schafer explained why *Grim Fandango* did not use it: "Ron and Aric had left and we really needed someone keeping up the engine side of SCUMM", while the company's strongest programmers were working on 3D games such as *Jedi Knight*. The team built a new engine instead, using the Lua scripting language.

Gilbert had taken the system with him. When he left in 1992 to found Humongous Entertainment, the new company licensed SCUMM and, he said, "used that engine for all the kids games we built".

## ScummVM

When DOS gave way to Windows, the SCUMM games grew harder to run. In 2001 Ludvig Strigeus and Vincent Hamm started ScummVM, which *Wireframe* describes as a rewrite of each game's original executable, in C++, worked out by reverse engineering. It is not an emulator: the player still needs the original game's data files, and ScummVM replaces only the interpreter, which is the same split SCUMM itself was built on. Hamm, who began by working through *Maniac Mansion* and *Zak McKracken*, joined Strigeus after finding his notes on *Monkey Island 2*. The project is released under the GNU General Public Licence, version 2, and grew to run many non-LucasArts adventures, including Sierra's games. *Retro Gamer* noted in 2013 that Gilbert had endorsed ScummVM while LucasArts "always taken a more negative stance on the project".

Gilbert and Gary Winnick, *Maniac Mansion*'s co-designers, returned to the style in *Thimbleweed Park* (2017), a new adventure funded on Kickstarter and made to look and play like their games of 1987.
