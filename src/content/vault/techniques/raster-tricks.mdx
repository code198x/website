In December 1986 a disk arrived at *[ZZAP!64](/vault/magazines/zzap-64)* from "some 'Dutch 64 freaks' called the [1001 Crew](/vault/groups/1001-crew)". On it was a full-screen picture made of 58 or 112 expanded sprites, "some of which are 'in' the top and side borders". The magazine's Compunet columnist was baffled: "I've no idea how it's done, but I hope someone puts the effect to good use in a game!" Four months later Andrew Braybrook, writing his diary of *Morpheus* in the same magazine, was "unhappy about using sprites in the border as it could be exploiting a video-chip bug. This may not work on some machines or it could cause damage."

Neither the columnist nor Braybrook knew yet how the trick worked. What the 1001 Crew had found was a register write made at a moment the [VIC-II](/vault/hardware/vic-ii)'s designers had not planned for. That is what this entry means by a **raster trick**: not changing a colour or a scroll value partway down the screen, which is an ordinary [raster effect](/vault/techniques/raster-effects), but timing a write so that the chip skips or repeats one of its own internal steps.

## Why the chip can be fooled

The registers involved are all in Commodore's manual. What the manual does not describe is the logic behind them, and the tricks depend on that logic. The VIC-II switches its border on and off by comparing the beam's position with a few fixed values, and Christian Bauer's 1996 description of the chip explains the weakness: "The comparisons only match if the values are reached precisely. There is no comparison with an interval." Change the screen height between the two possible bottom lines and neither comparison matches, so the border never starts. In the same way, the chip decides whether a raster line is a *badline*, the line on which it fetches a new row of characters, by comparing the low three bits of the line number with the vertical scroll value in `$D011`. Change the scroll value and a program can make a badline happen early, late, twice or not at all.

The price is timing. A PAL C64 line lasts 63 processor cycles and the chip draws 8 pixels in each one, so a write a cycle late lands 8 pixels further along. Most tricks need a [stable raster](/vault/techniques/stable-raster) routine first, to remove the few cycles of jitter in a raster interrupt.

## The tricks

Each has its own entry. The dates are from the demo scene's own list of first appearances, a community record open to correction.

| Trick | The write | What it gives | First listed |
|---|---|---|---|
| [Open borders](/vault/techniques/open-borders) | Switch to 24 rows on line 248, 249 or 250; for the side borders, switch to 38 columns in exactly cycle 56 of each line | Sprites shown in the border | Top and bottom 1985, sides 1986 |
| [FLD](/vault/techniques/fld) | Keep moving the vertical scroll value so the next badline never comes | A gap of blank lines that pushes the screen down | 1986 |
| [Linecrunch](/vault/techniques/linecrunch) | Cancel a badline after one line of a character row | The screen moves up without copying memory | 1987 |
| [VSP](/vault/techniques/vsp) | Start a badline late in the line with a write to `$D011` | The whole screen moves sideways a character per cycle of delay | 1987 |
| [AGSP](/vault/techniques/agsp) | VSP for the horizontal position plus linecrunch for the vertical | The whole screen placed anywhere without copying memory | 1988 |
| [FLI](/vault/techniques/fli) | Force a badline on every line and switch screen memory with `$D018` | New screen-memory colours on every pixel line instead of every eighth | 1989 |
| [Sprite stretching](/vault/techniques/sprite-stretching) | Clear and set a sprite's Y-expansion bit in `$D017` on each line | The same row of sprite data shown again, so a sprite can be any height | 1989 |

The names were not fixed. VSP, short for Variable Screen Positioning, is also called HSP and DMA delay, and Bauer's document describes it as DMA delay.

Later picture modes stacked these tricks with others. Crossbow and DeeKay of the German group [Crest](/vault/groups/crest) are credited with a series of them, from UFLI in 1996, which puts a layer of sprites under an FLI picture, to NUFLI in 2009.

## What they cost

Every trick takes processor time, and some take most of it. The VIC-II stops the processor for 40 to 43 cycles on each badline, so FLI, which makes every line a badline, leaves little time for anything else while the picture is on screen. Some leave marks. FLI's forced badlines come too late for the chip's first three reads of screen memory on each line, which return `$FF`, and the result is a stripe three character cells wide down the left of the picture, 12 multicolour pixels, where two of the four colour choices show light grey. FLI pictures leave it blank or design around it. VSP corrupts memory on some C64s, a fault traced to the machine's DRAM in 2013.

The tricks also depend on the chip. The PAL 6569 has 312 lines of 63 cycles, the NTSC 6567R8 263 lines of 65 cycles and the early 6567R56A 262 lines of 64, so a routine counted out for one machine can be out of step on another.
