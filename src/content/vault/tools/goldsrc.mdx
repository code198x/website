**GoldSrc** is the engine family behind Valve’s [Half-Life](/vault/games/half-life) and related games and modifications. It grew from licensed [Quake](/vault/games/quake) technology, with Valve’s own work supporting Half-Life’s environments, characters and game behaviour.

The distinction between the engine and the game becomes visible in Valve’s software development kit, or *SDK*. It exposes code for game rules, entities, weapons and client behaviour. Mod authors could change those parts while continuing to use the shared engine.

## Give a level things that work

A door is more than a textured shape. In the SDK’s door code, an entity can receive configuration values, respond to being used, react when blocked and preserve its state in a saved game. The mapper places and configures it; the game code determines how it behaves.

That arrangement supports a useful division of work. A level designer can connect named objects and set their properties without writing a fresh door implementation for every room. A programmer can improve the behaviour used by many instances.

[Worldcraft](/vault/tools/worldcraft), later known as Hammer, supplies the editing side of this workflow. GoldSrc supplies the runtime in which the compiled map and its entities operate. The editor and engine work together, but they have different jobs.

## A platform for modifications

[Counter-Strike](/vault/games/counter-strike) shows how far a modification could move from Half-Life’s original single-player adventure. Shared technology supplied a starting point for different rules, maps and ways of playing.

Valve’s SDK repository makes substantial game code inspectable, but it is not a release of the entire GoldSrc engine. Its own licence also differs from the GPL release of id’s Quake code.

The engine family has continued to change. Valve’s 2023 anniversary update records new community maps and compatibility work for Half-Life, connecting the original game to a later audience without making every later feature part of the 1998 release.
