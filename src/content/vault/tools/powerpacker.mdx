**PowerPacker**, written by **Nico François**, compresses files on the [Amiga](/vault/systems/commodore-amiga). It can turn an executable command into a smaller program which unpacks when run, or produce packed data for a reader or application to decode.

The distinction explains why compression needed supporting software. An ordinary text viewer does not understand a compressed document because its filename looks familiar. PowerPacker’s manual points to tools such as **PPMore**, and a shared **powerpacker.library** lets other programs use its facilities.

## Commands and data take different routes

The **Professional 4.0a** manual, dated 7 March 1992, describes command, data and LoadSeg file choices. The latter supports files loaded through AmigaDOS’s program-loading function, with the separate PPLoadSeg utility. The choice concerns how the file will be used after packing.

There are several compression effort settings and different search-buffer sizes. More effort or workspace can help the search, but the manual cautions that the setting called “Best” does not produce the smallest result for every small file. It also supplies a HunkLab for examining and altering the sections of executable files.

## Applications learned the format

The independently written **AMCAF** extension for [AMOS](/vault/languages/amos) documents PowerPacker support in its disk commands. It identifies the `PP20` marker at the start of packed data and supplies commands to load and unpack it into a memory bank. Its packing command uses powerpacker.library and offers a choice of compression effort.

That gives a game author a practical path: prepare compact data, load it, then restore the bytes before using them. It is an example of a format becoming useful through the applications around it.

François’s 4.0a preface also records a commercial edition following earlier shareware. The version matters when describing both features and distribution terms. [Turbo Imploder](/vault/tools/turbo-imploder) addressed many of the same disk-space pressures through a different executable-loading design.
