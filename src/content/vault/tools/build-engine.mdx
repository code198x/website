The **Build engine**, written by **Ken Silverman**, supplies the rendering and world-building foundation used by [Duke Nukem 3D](/vault/games/duke-nukem-3d), *Shadow Warrior* and *Blood*. Its editor lets an author draw a plan, then enter a three-dimensional view to adjust the place it describes.

## Sectors, walls and sprites

A Build map is organised around *sectors*: areas with a floor, ceiling and surrounding walls. Neighbouring sectors can connect through openings. Each sector has its own floor and ceiling heights, surface pictures and shading.

The source also defines sprites. These can face the viewer or align with a wall or floor, allowing pictures to represent things within the geometry. The combination offers much more flexibility than the uniform wall grid of [Wolfenstein 3D](/vault/games/wolfenstein-3d), while still using a deliberately structured representation of space.

The original editor documentation explains both the plan and 3D editing views. That pairing matters: the plan helps establish how areas connect, while the view from inside helps judge texture placement, height and the impression a room makes.

## The engine is part of the game

Silverman’s source-page FAQ draws an important boundary. Features such as Duke Nukem 3D’s sector effects belong to the game’s code. An engine can expose floors, walls, movement and drawing routines without deciding what a particular switch should do.

The released archive includes the engine, editor and Silverman’s example game. It is not the complete source for every commercial game that licensed Build. Their own programming and artwork remain separate contributions.

Silverman released this source in June 2000. His later **Polymost** renderer is another stage in Build’s history, rather than a description of how the original software renderer worked. Reading the archive means keeping those versions distinct: the same family of tools can support different ways of drawing the world.
