The **Motorola DSP56001** is a programmable processor built for repeated arithmetic on streams of values. It has 24-bit data words, a multiplier and two wide accumulators. In the [Atari Falcon030](/vault/systems/atari-falcon030), it works beside the main 68030 rather than replacing the computer’s general-purpose CPU.

“Digital signal processor”, or **DSP**, describes the job its architecture makes convenient. A program might filter sound or transform other numerical data. The chip is not a fixed collection of instrument voices that starts playing music as soon as the host sends a note number.

## Multiply, then add

Many signal operations repeatedly multiply a sample by a coefficient and add the result to a running total. Motorola’s data ALU combines a 24-by-24-bit multiplier with accumulation. The product is 48-bit, and the A and B accumulators are 56-bit, leaving room for intermediate results before they are reduced to an output format. (Motorola, *DSP56000 Family Manual*, data ALU.)

That extra working precision matters when several products are added. It is a property of the arithmetic path, rather than the number of bits a speaker or microphone connection can reproduce.

The architecture separates program memory from two data spaces, **X** and **Y**. Suitable instructions can combine arithmetic with data movement and address updates. A filter can keep samples and coefficients available through different data paths, reducing the instructions needed to feed the calculation. The permitted combinations still depend on the instruction and memory arrangement; this is not a promise that every possible group of operations happens simultaneously.

## A second program needs data

Using the DSP means supplying a DSP program and arranging communication with the host. The main CPU and DSP have different instruction sets and memory views. A 68030 routine does not become DSP code by being copied into another address range.

The Falcon’s manuals describe the DSP alongside the machine’s audio and other hardware. That surrounding system determines how data arrives, where results go and which transfers can overlap. Measuring one arithmetic operation does not establish the speed of a complete application that must also move buffers and coordinate two processors.

## Twenty-four-bit arithmetic, separate converters

The Falcon’s DSP word size is often mistaken for an audio-output specification. Its service guide documents **16-bit stereo audio conversion**. The DSP’s 24-bit words and 56-bit accumulators describe internal processing; the converters have their own format and limits.

This is the same distinction that matters with the [SPC700 and S-DSP](/vault/hardware/spc700-s-dsp): identify the processor, its stored data and the output hardware separately. Both systems can delegate sound work, but their programmable resources and the work their software must do differ.
