The **Acorn Electron** offered BBC BASIC in a smaller, cheaper home computer than the [BBC Micro](/vault/systems/bbc-micro). Neil Cryer's September 1983 *Your Computer* review listed its price as £199 and described a proper typing keyboard, with a function-key option for entering BASIC keywords. Owners could also type commands normally.

The language retained useful building blocks: named procedures, local variables and `REPEAT` loops helped a program grow beyond an uninterrupted sequence of numbered statements. Familiar BASIC, however, did not mean that every BBC Micro hardware facility was inside the Electron. ([Contemporary review](https://retroisle.com/others/acornelectron/Articles/yourcomputer_sep1983.php).)

## Pictures without teletext

The Electron provided bitmap display modes numbered 0 to 6. They traded horizontal resolution, colour choices and memory use against one another. Mode 0 supplied 640 by 256 pixels with two colours; Mode 2 supplied 160 by 256 pixels with a larger palette selection. These are different arrangements of the display, rather than a single resolution with an optional colour switch.

It did not provide the BBC Micro's Mode 7 teletext display. Software expecting that hardware needed another approach. A program written with the shared BASIC drawing commands had a different compatibility problem from one that directly manipulated a BBC-specific display controller. ([Acorn's user guide](https://8bs.com/othrdnld/manuals/essentials/electron_user_guide_pdf.zip); Cryer's review.)

## A familiar command can reach different hardware

The Electron used a large uncommitted logic array, or ULA, to gather functions that other computers spread across several chips. The machine's graphics and sound facilities therefore need to be understood on their own terms.

Sound is a useful example. The BASIC `SOUND` command could look familiar to a BBC programmer, but the Electron could produce only one tone at a time. Requests and priorities did not turn it into the BBC's multi-voice sound hardware. Cryer's review explicitly describes the limitation; the manual explains how programs request sounds.

## Software had to meet the actual machine

The shared language and operating-system vocabulary made the Electron a practical relative of the BBC Micro. Missing facilities still mattered to games, machine-code routines and peripherals. Compatibility depended on what a particular program used, not only which BASIC dialect its author knew.
