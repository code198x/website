## Use it in a project

Three weights describe half-open intervals; zero excludes an outcome. Their sum must be 1–255 and ROLL must be below that sum. CHOICE is 0–2 on success, 255 on failure. TOTAL reports the sum only when it fits a byte. The caller supplies a uniformly distributed bounded roll; this routine does not generate randomness.

Include `component.inc` once (MOS callers include the shared 6502 implementation through it). Reserve the public fields in this exact order: **WEIGHT0, WEIGHT1, WEIGHT2, ROLL, CHOICE, TOTAL, VALID**. They occupy 7 contiguous bytes. Also reserve the private workspace: **T0, T1** (2 bytes). Array names in the explanation refer to the numbered consecutive bindings, such as C0, C1 and so on.

Call `weighted_choice_init` once at the intended reset boundary. It clears inputs as well as outputs and workspace. Set your starting state and configuration afterwards, then call `weighted_choice_step` whenever the described event occurs. The helper reads no device, waits for no frame and installs no interrupt handler.

| Ownership | Fields |
|---|---|
| Retain between calls | none between choices |
| Supply before service | WEIGHT0–WEIGHT2 and ROLL |
| Read after service | CHOICE, TOTAL and VALID |

Lay the weights end to end as intervals. A roll names a position in that combined interval. The outcome containing it wins; an outcome with zero weight has no positions and cannot be selected.

## Machine contract

A/X/status may change; Y is preserved. The 2A03 has no decimal arithmetic mode. A direct JSR needs two return-address stack bytes. The helper makes no nested calls and adds no other stack use. Its named scratch is private workspace, not a pointer, a ROM variable or shared zero-page space that the game may borrow concurrently. Scope or rename routine and field labels and allocate a separate block for each independent instance. Give each block one mutation owner.

The NROM caller owns PPU setup and background display, with NMI and DMC disabled. Table and packet sizes are bounded to fit the cartridge caller and internal RAM; the helper owns no PPU registers.

## Adapt the caller

`demo.asm` supplies the bindings and include order. `exercise.inc` first runs table cases, then a separate client retaining state between calls. A game can call the public step entry directly and remove the diagnostic packet and display. Do not copy the diagnostic's hardware takeover into an existing game loop.

Build with `make ASM198X=/path/to/asm198x`. The Makefile produces normal, custom, deliberately wrong and repaired programs. Tools must already be installed; the sample downloads nothing.

## Customise it

## Mistake and repair

The wrong caller replaces every supplied ROLL with zero. Positive weight zero always wins and the intended variation disappears. Keep the supplied bounded roll; checking its range cannot establish that it was random.

The BROKEN branch lives in the sequential client, not the reusable helper. `wrong.asm` selects it; `repaired.asm` restores the normal call sequence. The repaired executable matches the normal program (for Spectrum, compare loaded CODE rather than the tape filename).

## Cost and alternatives

The measured helper extent is 164 code bytes; public state is 7 bytes and private scratch is 2 bytes. There are no immutable helper tables. Caller data, the test cases, return-address stack, alignment and display buffers cost additional space. These are assembled sizes, not cycle measurements.

Constant work for three choices. A linear scan grows with outcome count; cumulative tables and binary search repay their storage on larger distributions.

Reducing an arbitrary random byte modulo TOTAL can bias the choice. Use rejection sampling or an appropriate bounded generator if equal interval positions matter. Three fixed weights are readable; larger tables favour cumulative totals and search.

## Execution evidence

Four variants run on NTSC NROM, background only, DMC/NMI disabled, using Asm198x 0.0.72, Emu198x 0.44.2. Each executes 64 boundary/varied/error table cases, dirty initialisation and the separate retained-state client. An independent mathematical/container model checks every public byte after every call. This is bounded example coverage, not exhaustive correctness for every possible state.

The records retain loaded immutable code, completion, register sentinels, full packets, source/tool/firmware hashes and captures. The public gate validates these retained observations and rejects altered evidence; it does not run restricted firmware. No firmware is distributed. The eight displayed bytes are the first eight public fields, zero-padded when shorter; the packet includes every field.
