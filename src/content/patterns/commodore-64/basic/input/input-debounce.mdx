A noisy sample should settle before it changes a game's logical state. This routine waits for a run of identical bytes, then emits a change pulse once. The threshold is a count of samples, not a promise about elapsed time.

## Include and initialise

Reserve S/P/C/R/X/T/O and lines **3000–3220**. There are no arrays or private scratch variables. Combine routines.bas with the caller using build.py, with END, STOP or a jump before the helper. C64/BBC use GOSUB; Spectrum uses GO SUB.

Call **3000** at the intended reset boundary. It clears all public fields. Set threshold T afterwards. S is the accepted stable byte, C the current candidate and R the retained run length. Supply each raw sample in X.

## Service one sample

Call **3100**. A new candidate starts a run of one. A repeated candidate grows R up to 255. When the run reaches T, a value different from S replaces it and returns P=1. Repeated acceptance of the same stable value returns P=0.

| Fields | Use |
|---|---|
| S / C / R | Stable value / candidate / consecutive run |
| X / T | Raw sample / required run length |
| P / O | Fresh changed pulse / valid-input flag |

All state and inputs must be integral bytes. Invalid input clears P/O and preserves S/C/R/X/T. T=0 is a valid disabled state: it clears R without accepting X and preserves S/C. O=1 reports valid service. T=1 accepts a new sample immediately. X/T survive each call.

## Compare two thresholds

The caller feeds 1,0,1,1,1,1,0,0,0. Threshold three accepts the sustained one at index four and zero at eight. The custom threshold two accepts them at indices three and seven. Both produce two change pulses and finish with a run of three; the complete traces show their different timing.

Line 2000, AA/BB/NN/JJ and the mailbox are observations. A game obtains real samples, retains S/C/R and acts on P or the accepted S. This proof verifies the logical filter in each interpreter; it does not establish physical switch behaviour or a device sampling rate.

## Choose the right granularity

This accepts a complete byte as one value. If one button bit chatters, the whole candidate byte changes. Independent per-button filtering needs separate histories or a bit-oriented filter. For already stable game controls, a simple press-edge detector can give a more responsive result.

Increasing T suppresses short runs but adds acceptance delay. Irregular service changes the physical delay. Changing T does not discard existing history; reset R deliberately, or use disabled service, when the policy requires a fresh run. A timed filter needs an explicit clock and elapsed-time rule.

## Mistake and repair

The wrong caller clears R before every sample. Neither the normal threshold three nor custom threshold two can accumulate enough history, so no changes are accepted. Both saved pulse-count and final-run checks fail. Retain the run between samples. The final stable zero alone would hide the mistake because zero was also the initial value. Repaired source and loaded program match normal exactly.

## Cost and Maths for Games

Each call uses fixed validation and a bounded state update, with no input read, wait or allocation. Run saturation prevents a long unchanged signal wrapping back to a short run. Filtering is a trade-off between suppression and latency, not an automatic improvement for every input source.

## Global names and line numbers

BASIC numeric names, arrays and numbered lines are global. To combine helpers, rename public and private fields and renumber the helper together with every GO SUB/GO TO reference. Keep each state block under one owner. The maintained build.py rejects duplicate line numbers; it does not automatically namespace or renumber routines.

## Machine and measured size

C64 BASIC V2 recognises only the first two significant characters of numeric variable names. Short names make the ownership visible; check for collisions before including another component. Array element zero exists but is unused here. The diagnostic uses a mailbox at $C000, outside the normal BASIC heap.

The numbered helper occupies **363 tokenised program bytes** on this interpreter, including line headers. This excludes the caller, test tables, numeric scalar/array storage, interpreter stacks and ROM. Tokenised size is not machine-code size or a hardware-cycle count. No real-time or whole-game performance budget is inferred from the diagnostic. The caller’s AA/BB, JJ/KK and RAM mailbox are observation machinery, not required game state.

## Execution evidence

Working, custom, deliberately wrong and exact repaired callers executed through C64's stock BASIC interpreter under Emu198x 0.44.2. Build198x 0.2.9 tokenises C64 PRG and Spectrum TAP programs. C64 enters stock RUN, Spectrum uses ROM tape loading, and BBC enters every numbered source line through MOS/BASIC. Actual loaded program bytes, complete state packets, positive completion/count/guards and visible result pixels are checked. After the positive completion marker, the observer advances two complete display frames before capturing, so a partially scanned final character cannot masquerade as a finished picture. Firmware is not distributed.

An independent mathematical/order model checks the trace and rejects altered source, configuration, loaded program, state, completion and image evidence. Host exhaustive checks complement the native boundary/sequential examples; those host ranges are not claimed as natively exhaustive. The supplied diagnostic callers deliberately end with STOP; the interpreter report is expected. The wrong caller prints 0,0 and the normal/custom/repaired callers print 1,1.
