Press Space: one turn. Wait: the world waits with you. Now press T and leave the keyboard alone. Four seconds later, the next turn arrives by itself. Your adventure might give a player time to escape a flooding room; your board game might put a limit on a move. The turn rule can stay the same while its timing changes.

## Try the complete caller

Run `make -C commodore-64/patterns/basic/framework/turn-deadline` in code-samples. Enter the generated `build/demo.bas` as one numbered program, then type RUN. Space advances, T switches timing on or off, and Q ends the example. Use brief taps at first. The status shows the turn, expiry count and active flag; it is not a live countdown.

Use a PAL C64 with stock BASIC V2 and KERNAL. The caller clears the normal text display and reserves $C000–$C013 (49152–49171) for an optional diagnostic observer. Keep sprites, machine code and other owners out of that area. Q leaves the screen and observer behind.

## Take the reusable helper

The helper does no input, drawing or turn advancement. It accepts two samples of a clock, subtracts the elapsed ticks and reports whether time ran out.

<CodeFromFile src="commodore-64/patterns/basic/framework/turn-deadline/routines.bas" lang="basic" title="Initialise, start and poll a deadline" />

Set `DU` to your duration and `DC` to the current clock, then call **3000 once**. This initialises disabled state and its previous sample. Call **3100** to start or restart: it copies duration into remaining time. Zero duration leaves it disabled.

Each service iteration, including while disabled, set `DC` and call **3200**. Read `DX` immediately afterwards: 1 means this poll expired. The helper disables that deadline and clamps remaining to zero; the next poll clears the event. Your caller decides whether to spend a turn or start another deadline.

| Global | Contract |
| --- | --- |
| DU | Caller duration: whole ticks, 0..5183999; 0 disables |
| DC | Caller current clock: whole ticks, 0..5183999 |
| DP | Helper-owned previous sample |
| DR | Helper-owned remaining ticks, saturated at zero |
| DA | Helper-owned active flag, 0 or 1 |
| DX | Helper-owned expiry event, 0 or 1 |
| DE | Helper-owned elapsed ticks from this poll |

These are BASIC globals. Rename them consistently to avoid collisions. Only the first two characters distinguish C64 names. These ordinary numeric variables use five-byte floating-point values; all the whole numbers in the stated ranges are represented exactly. The helper reserves no fixed RAM, IRQ vector, hardware timer, array or string. It uses BASIC GOSUB/RETURN frames and is one mutable context, rather than a re-entrant service.

Starting preserves the most recent sampled baseline. Poll immediately before starting if that instant matters. Disable by setting `DA=0`. There is no preserved pause state: the demo clears remaining on disable and gives a fresh duration on re-enable.

## Read a clock without waiting for a command

<CodeFromFile src="commodore-64/patterns/basic/framework/turn-deadline/clock.bas" lang="basic" title="The machine-specific clock adapter" />

TI reads the KERNAL jiffy clock: nominal **60 ticks per second**, resetting after **5,184,000 ticks (24 hours)**. A PAL video field is not a TI tick. Keep the normal KERNAL interrupt service running. Tape I/O stops this timer, and assigning TI$ changes the shared clock; neither is harmless while a deadline depends on it.

Poll before one whole clock cycle passes. 5,183,994 → 5 is eleven ticks; missing an entire extra cycle would give the same samples. A clock reset is not a rollover. Reinitialise your context after another owner changes the clock. This adapter never resets it.

`GET K$` reads without waiting for Return. It consumes characters delivered by firmware, including typeahead and repeat. A held key is not promised to count once. The [untimed command loop](/patterns/commodore-64/basic/framework/command-loop/) can use blocking INPUT because its world is allowed to wait. Putting blocking INPUT into this caller would also stop deadline service. A clock does not make BASIC run two tasks at once.

The caller polls, reads one character, then handles expiry. **Expiry wins** if both arrive in the same iteration, discarding that character, including T or Q. Otherwise Space advances once and restarts an already active deadline. An untimed action stays untimed. An overdue deadline produces one turn; it does not replay every turn that might have happened during a delay.

## What does it cost?

The routine performs bounded work per poll; it does not loop once per elapsed tick. Interpretation, GOSUB lookup and your other work still determine how often you can service it. A native clock accumulates time while BASIC draws or calculates, but expiry is noticed only when you poll again. Restarting at observation time also introduces drift.

The native interpreter stored **191 bytes of tokenised helper lines**, including line headers. The complete diagnostic caller occupies **1030 tokenised program bytes**. Its observed scalar variable table occupies **133 bytes** after the checked interactions; this is a snapshot, not a peak-memory promise. String contents and interpreter workspace/stack are additional. The optional observer reserves another **20 bytes**. In the recorded disabled-idle snapshot, successive service samples were **20 jiffies** apart with the observer present; that includes interpreted caller/diagnostic work and is not the cost of the helper alone.

The optional 20-byte observer adds six scratch/monitor globals and several byte writes every iteration. Remove GOSUB 9000, its guards, MB/LC initialisation and `monitor.bas` when you do not need it. It is deliberately readable, rather than a fast game implementation. The caller redraws only on actions, toggles and expiry. No whole-game frame budget follows from these measurements.

## What was checked

**Code status: emulator-executed BASIC.** Four cold stock-firmware runs cover the public caller, half-duration customisation, baseline-reset fault and repaired adapter. The verifier types the complete program, observes guarded native state, and checks untimed idle/action, no-input expiry, restart and disable. Native captures above show the real text display.

A second BASIC caller executes twelve synthetic-clock boundary cases through the same interpreter: no elapsed time, wrap, exact/overshot expiry and zero/maximum duration. An independent arithmetic oracle checks the returned bytes. These establish arithmetic behaviour; they are not a wall-clock run across an entire rollover. Retained-record checks reject missing variants, changed source and falsified native observations. No original-hardware, other-ROM or other-region claim is made.
