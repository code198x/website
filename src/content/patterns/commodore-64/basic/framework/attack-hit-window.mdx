A sword swing can overlap the same enemy for several updates. That should not automatically mean several hits. Give the attack an active interval and remember which targets it has already hit; the collision routine can still report contact every time.

## Include and initialise

Include routines.bas, reserving lines **3000–3240**, public H/O/M/F/A/B/T/C/N and private P. Call **3000** at an intended reset boundary. It clears all public fields. Keep a STOP, END or jump before the helper so ordinary execution cannot fall into it. Call **3100** for each candidate contact.

F is the attack frame; A and B are the start and exclusive end of its active interval. T is a stable target index from zero to seven. C is a contact flag and N signals a new attack; any nonzero byte means true. M is the retained eight-target hit mask. H reports a newly accepted hit and O reports valid inputs.

<CodeFromFile src="commodore-64/patterns/basic/framework/attack-hit-window/routines.bas" lang="basic" title="Reusable numbered routines" />

All state and inputs must be integral bytes, T must be at most seven, and A must be less than B. Invalid input returns H/O=0 without changing M or the other inputs. A valid query returns O=1. With N nonzero it first clears M, even outside the active interval. Clear N after the first query of the new attack, including when processing several targets in one update.

## Open the window, then remember

A hit is accepted only when F is at least A and less than B, contact is nonzero, and T is not already in M. H becomes one and that target's bit is added. A repeated contact returns H=0 while retaining the complete mask. Target IDs must keep their meaning throughout an attack: recycling an ID during the swing needs an explicit policy.

The default caller opens frames two through four. It accepts target one, ignores another contact with that target, then accepts target two. Its mask is six, with bits one and two set. The custom caller opens frames one and two and hits targets seven and zero, producing129. The saved checks cover both repeat rejection and retention of the earlier target.

A later query at B is outside the window. Starting a new attack explicitly clears the remembered targets. AA/BB, the boundary table and mailbox belong to the diagnostic. A real game supplies its animation clock and collision results, applies damage when H=1, and keeps M until the next attack. The helper owns neither collision geometry nor damage, animation or time.

## Customise the attack

Choose a short active interval for a sharp strike or a longer one for a sweep. Use a different hit mask for each simultaneous attacker. An eight-bit target set keeps the example small; more targets need a wider bitset or a bounded identity list. A byte end frame cannot represent256. Longer animations need wider frame fields or a documented local phase counter.

Repeated damage from fire or a beam is a different policy: it can use a per-target cooldown rather than a permanent per-attack mark. A contact-pair cache avoids duplicate pair processing during one traversal; this helper deliberately retains hit history across updates.

## Mistake and repair

The wrong caller asserts N before every query. That clears the hit set each time: repeated contact hits again and switching targets discards the earlier mark. Both saved checks fail. Assert the reset once when the attack starts, then retain the mask. Repaired source and loaded programs match the normal caller exactly.

## Cost and Maths for Games

The query validates seven byte fields and uses powers of two and integer division to inspect a bit without a machine-specific bitwise BASIC operator. There are no arrays or heap allocations in the helper. A machine-code version can use native bit operations; a larger identity list trades memory and search time for more targets and richer identities. No measured cycle budget is inferred.

## Global names and line numbers

BASIC numeric names, arrays and numbered lines are global. To combine helpers, rename public and private fields and renumber the helper together with every GO SUB/GO TO reference. Keep each state block under one owner. The maintained build.py rejects duplicate line numbers; it does not automatically namespace or renumber routines.

## Machine and measured size

C64 BASIC V2 recognises only the first two significant characters of numeric variable names. Short names make the ownership visible; check for collisions before including another component. Array element zero exists but is unused here. The diagnostic uses a mailbox at $C000, outside the normal BASIC heap.

The numbered helper occupies **455 tokenised program bytes** on this interpreter, including line headers. This excludes the caller, test tables, numeric scalar/array storage, interpreter stacks and ROM. Tokenised size is not machine-code size or a hardware-cycle count. No real-time or whole-game performance budget is inferred from the diagnostic. The caller’s AA/BB, JJ/KK and RAM mailbox are observation machinery, not required game state.
