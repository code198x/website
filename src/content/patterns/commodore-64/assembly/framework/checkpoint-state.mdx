## Use it in a project

MODE=0 captures the three live byte fields, XOR checksum and SAVED=1. MODE=1 restores only if SAVED is exactly 1 and the saved bytes match CHECKSUM. RESULT=1 reports a completed capture or restore; other modes, absent snapshots or checksum mismatch return zero and leave live fields unchanged. Coordinates and resource counts have no additional game-specific range policy.

Include `component.inc` once (MOS callers include the shared 6502 implementation through it). Reserve the public fields in this exact order: **RESULT, SAVED, LIVE_X, LIVE_Y, LIVE_RESOURCE, MODE, SAVED_X, SAVED_Y, SAVED_RESOURCE, CHECKSUM**. They occupy 10 contiguous bytes. Also reserve the private workspace: **T0** (1 bytes). Array names in the explanation refer to the numbered consecutive bindings, such as C0, C1 and so on.

Call `checkpoint_state_init` once at the intended reset boundary. It clears inputs as well as outputs and workspace. Set your starting state and configuration afterwards, then call `checkpoint_state_step` whenever the described event occurs. The helper reads no device, waits for no frame and installs no interrupt handler.

| Ownership | Fields |
|---|---|
| Retain between calls | SAVED, SAVED_X, SAVED_Y, SAVED_RESOURCE and CHECKSUM |
| Supply before service | MODE and the live fields before capture |
| Read after service | RESULT and the live fields after successful restore |

Restoration validates the complete saved record before touching any live field. That makes a failed restore a no-op on the player state rather than a partial rollback.

## Machine contract

A/X/status may change; Y and decimal mode are preserved. Use CLD for binary arithmetic. A direct JSR needs two return-address stack bytes. The helper makes no nested calls and adds no other stack use. Its named scratch is private workspace, not a pointer, a ROM variable or shared zero-page space that the game may borrow concurrently. The samples use fixed symbol bindings. Scope or rename every label and binding, including the component_end measurement marker, and allocate a separate block for each independent instance. Different helpers can also use common field names, so combining them needs separate namespaces or explicitly renamed bindings. Give each block one mutation owner.

The diagnostic PRG owns screen, font and colour RAM and disables interrupts; it does not return to BASIC. The reusable helper does none of those things.

## Adapt the caller

`demo.asm` supplies the bindings and include order. `exercise.inc` first runs table cases, then a separate client retaining state between calls. A game can call the public step entry directly and remove the diagnostic packet and display. Do not copy the diagnostic's hardware takeover into an existing game loop.

Build with `make ASM198X=/path/to/asm198x`. The Makefile produces normal, custom, deliberately wrong and repaired programs. Tools must already be installed; the sample downloads nothing.

## Mistake and repair

The wrong caller overwrites a saved field before restoring. The checksum rejects the damaged snapshot and preserves the current live state. Keep snapshot ownership with the capture/restore routine.

The BROKEN branch lives in the sequential client, not the reusable helper. `wrong.asm` selects it; `repaired.asm` restores the normal call sequence. The repaired executable matches the normal program (for Spectrum, compare loaded CODE rather than the tape filename).

## Cost and alternatives

The measured helper extent is 154 code bytes; public state is 10 bytes and private scratch is 1 bytes. There are no immutable helper tables. Caller data, the test cases, return-address stack, alignment and display buffers cost additional space. These are assembled sizes, not cycle measurements.

Constant work for three fields. Larger games need an explicit snapshot schema, versioning and ownership; copying an entire object pool may cost much more RAM than a small checkpoint.

This is an in-memory checkpoint, not disk persistence or interrupt-safe saving. XOR can miss multi-byte changes that cancel; it is a small accidental-damage guard, not authentication. Use stronger checksums and an atomic storage protocol for durable saves.

## Execution evidence

Four variants run on PAL stock-ROM PRG, using Asm198x 0.0.72, Emu198x 0.44.2. Each executes 64 boundary/varied/error table cases, dirty initialisation and the separate retained-state client. An independent mathematical/container model checks every public byte after every call. This is bounded example coverage, not exhaustive correctness for every possible state.

The records retain loaded immutable code, completion, register sentinels, full packets, source/tool/firmware hashes and captures. The public gate validates these retained observations and rejects altered evidence; it does not run restricted firmware. No firmware is distributed. The eight displayed bytes are the first eight public fields, zero-padded when shorter; the packet includes every field.
