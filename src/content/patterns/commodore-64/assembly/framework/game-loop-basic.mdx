The border changes as the update counter advances. Hold Fire on joystick port 2 and the colour changes slow down: we have deliberately given the CPU more work than fits in a frame. Release it and the normal pace returns.

## Use the wait in your project

No clock initialisation is needed for the wait itself. Call `wait_frame` once per update. It changes flags and preserves A/X/Y. It first waits for raster bit 8 to be low, then for it to become high. Both phases matter: a short update cannot consume the same high interval repeatedly.

## Start the complete example

This caller takes over CIA1 and the border, disables IRQs, banks out the ROMs and supplies a minimal NMI return. Keep I/O visible and keyboard keys released. Reset to leave. The joystick reader is the existing maintained routine, not another incompatible input format.

With Asm198x available, keep the sample folders together and run:

```sh
make -C commodore-64/patterns/assembly/framework/game-loop
```
The Amiga Makefile also needs Build198x. Open the generated file under build using the machine’s normal loading route.

The loop keeps four jobs visible: wait, read input, update state, draw. `expensive_work` is an optional CPU workload to expose missed deadlines; remove it when building your own game. The changing colour or digit is a small observable result, not a rendering engine.

## What happens when work runs late

This is a fixed-step loop. Work that overruns a display interval reduces the update rate; missed updates are not replayed. The sample checks PAL only. NTSC has different timing and needs its own measurements. Reaching the lower part of the screen does not guarantee that arbitrary drawing will avoid tearing.
