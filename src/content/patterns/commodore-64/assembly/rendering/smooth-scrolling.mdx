## A pixel at a time, then a whole column

The VIC-II's fine offset moves the display within a character cell. Once those eight positions run out, the character map must move too. Otherwise the world jumps back instead of continuing to scroll.

Include `scroll.inc` once, call `init_scroll`, then call `scroll_left` once per chosen update. It applies the initial offset immediately, uses 38-column mode to hide the side edges, and preserves the other `$D016` bits. Prepare 25 bytes in `next_column` and 25 colours in `next_colour` before each coarse step; those become column 39.

## Integration contract

This version owns zero-page `$FB`, screen RAM `$0400–$07E7`, colour RAM `$D800–$DBE7`, and the two 25-byte column buffers. Your VIC bank and `$D018` must display that screen. Use text mode with matching colour semantics. Clear decimal mode before calling. A, X and flags change; Y survives. Interrupts must preserve the routine's working registers and must not change its state while it runs.

On the coarse step it copies 975 character bytes and 975 colours, then fills 25 edge cells of each. That is substantial work. Calling it after a raster wait alone does not make those writes fit safely before the beam reaches them. Budget the whole update, reduce the playfield, or use a separately designed buffering scheme. The routine supplies a correct memory shift, not an entire map streamer or a promise of smooth presentation under every workload.
