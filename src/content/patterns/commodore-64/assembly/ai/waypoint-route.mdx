## Use it in a project

Up to four caller-owned byte positions form a one-dimensional route. COUNT=1–4, TARGET_INDEX below COUNT and SPEED=1–255 are required. Move towards the current target by at most SPEED, snap on arrival, pulse ARRIVED and advance the target. At the final waypoint LOOP wraps; otherwise FINISHED latches. The caller owns starting position and route data.

Include `component.inc` once (MOS callers include the shared 6502 implementation through it). Reserve the public fields in this exact order: **POSITION, TARGET_INDEX, COUNT, SPEED, LOOP, ARRIVED, FINISHED, VALID, P0, P1, P2, P3**. They occupy 12 contiguous bytes. Also reserve the private workspace: **T0, T1** (2 bytes). Array names in the explanation refer to the numbered consecutive bindings, such as C0, C1 and so on.

Call `waypoint_route_init` once at the intended reset boundary. It clears inputs as well as outputs and workspace. Set your starting state and configuration afterwards, then call `waypoint_route_step` whenever the described event occurs. The helper reads no device, waits for no frame and installs no interrupt handler.

| Ownership | Fields |
|---|---|
| Retain between calls | POSITION, TARGET_INDEX and FINISHED |
| Supply before service | COUNT, SPEED, LOOP and P0–P3 |
| Read after service | ARRIVED and VALID |

Approach one target without overshoot. Once it is reached, pulse arrival and select the next target for a later update. The helper never skips across several coincident waypoints in one call.

## Machine contract

A/X/status may change; Y and decimal mode are preserved. Use CLD for binary arithmetic. A direct JSR needs two return-address stack bytes. The helper makes no nested calls and adds no other stack use. Its named scratch is private workspace, not a pointer, a ROM variable or shared zero-page space that the game may borrow concurrently. Scope or rename routine and field labels and allocate a separate block for each independent instance. Give each block one mutation owner.

The diagnostic PRG owns screen, font and colour RAM and disables interrupts; it does not return to BASIC. The reusable helper does none of those things.

## Adapt the caller

`demo.asm` supplies the bindings and include order. `exercise.inc` first runs table cases, then a separate client retaining state between calls. A game can call the public step entry directly and remove the diagnostic packet and display. Do not copy the diagnostic's hardware takeover into an existing game loop.

Build with `make ASM198X=/path/to/asm198x`. The Makefile produces normal, custom, deliberately wrong and repaired programs. Tools must already be installed; the sample downloads nothing.

## Customise it

Loop the route instead of latching at its end. The maintained custom caller changes its inputs or client sequence rather than hiding a different implementation behind the same label. Compare every state of the two clients, not only their final display.

## Mistake and repair

The wrong caller rewinds TARGET_INDEX before each update. The actor keeps targeting the first waypoint. Retain the route cursor until a real restart or route replacement.

The BROKEN branch lives in the sequential client, not the reusable helper. `wrong.asm` selects it; `repaired.asm` restores the normal call sequence. The repaired executable matches the normal program (for Spectrum, compare loaded CODE rather than the tape filename).

## Cost and alternatives

The measured helper extent is 271 code bytes; public state is 12 bytes and private scratch is 2 bytes. There are no immutable helper tables. Caller data, the test cases, return-address stack, alignment and display buffers cost additional space. These are assembled sizes, not cycle measurements.

Constant work per update. Only one target can be completed per call, bounding work even when several route points coincide.

This extends target approach into a route, but it is not pathfinding or collision avoidance. Two-dimensional paths need paired coordinates and an explicit movement metric. A waypoint equal to the current position still consumes one call.

## Execution evidence

Four variants run on PAL stock-ROM PRG, using Asm198x 0.0.72, Emu198x 0.44.2. Each executes 64 boundary/varied/error table cases, dirty initialisation and the separate retained-state client. An independent mathematical/container model checks every public byte after every call. This is bounded example coverage, not exhaustive correctness for every possible state.

The records retain loaded immutable code, completion, register sentinels, full packets, source/tool/firmware hashes and captures. The public gate validates these retained observations and rejects altered evidence; it does not run restricted firmware. No firmware is distributed. The eight displayed bytes are the first eight public fields, zero-padded when shorter; the packet includes every field.
