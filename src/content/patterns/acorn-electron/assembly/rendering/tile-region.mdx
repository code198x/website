A door opens, and one map cell changes. This routine redraws its picture without rebuilding the whole screen. The same call can paint a room or the strip of scenery revealed by a camera: choose a source rectangle and a destination, then let the machine's renderer do the copying.

## Eight lines together

Electron MODE 4 gives you 320×256 logical pixels: forty 8×8 cells across and thirty-two down. The bitmap occupies `$5800–$7FFF`. Eight scanlines of a cell sit together; the next cell starts eight bytes later. Move down a character row and the address advances by 320 bytes.

The low/high scanline tables therefore hold `$5800 + (y/8)*320 + (y mod 8)`. Set `CELL_BYTES=1` and `X_STEP=8`. This is the same maintained 6502 bitmap renderer used on other machines, with Electron's addresses made explicit. Its two 256-byte tables cost 512 bytes.

The original caller copies four eight-byte pictures to `$0800`, sets ULA mode/base/palette, and then draws. A zero tile is an opaque blank picture, so it erases a cell. A different screen base, mode or hardware-scroll layout needs matching tables; changing just one address constant is insufficient.

## Reserve your workspace

Put all 32 bytes of `NR` in zero page and clear decimal mode before calling. Define the map, tile table, dimensions and scanline tables before including `bitmap-regions/6502.inc` once. The map has twelve byte IDs per row and eight rows; this readable bitmap variant allows 1–16 tile pictures. Allocations must fit accessible memory without wrapping or aliasing the destination.

A/X/Y and flags are clobbered. Four stack bytes cover the direct JSR and its paint helper, beyond your caller and interrupt needs. The six request bytes survive; scratch may change. No context initialisation call is needed.

A 5×3 patch copies 120 bitmap bytes, plus a complete ID preflight and address work. Cached map rows or longer span copies can save work; masks and clipping change the job. The native capture duplicates pixels horizontally into 640×256 output, while game coordinates remain 320×256. These counts are not measured cycle budgets.

## Draw the rectangle

The constants belong to the original caller's working memory plan. Choose allocations which fit your own project, keeping setup and drawing separate.

Supply six unsigned bytes at `NR+0..5`: source column, source row, destination column, destination row, width and height. Call `region_draw`; `NR+6` is one for completion or zero for rejection. The six request bytes survive.

The result store after the call belongs to the diagnostic. In a game, read the completion flag and carry on with your own logic. The routine rejects zero sizes, invalid starts, source/destination overruns and IDs outside the configured table. Every selected ID is checked before painting begins, so a bad tile cannot leave half a patch behind. This variant rejects rather than clips.

## Keep the routine

The context is private and non-re-entrant. Keep the request, map, descriptors or picture data, and display configuration stable throughout the call. Your caller owns video setup, allocations and interrupt policy; the routine does not disable interrupts or negotiate with an OS. Interrupt handlers must preserve the used registers and must not change those resources halfway through drawing.

## What was checked

All **18 calls** completed: three accepted draws and fifteen map/bounds/ID rejections. Each rejected request also ran **in isolation** after the same three accepted draws, preserving complete destination allocations and both mapped guards. The source selection crosses a CPU page boundary.

The observer compares every destination byte, including all bitmap bytes, with an independent model. It compares every native capture pixel with a separate composition, including borders and scaling. Completed wrong-layout and unsafe-destination controls fail the same memory checks; wrong-layout pictures also fail the pixel check.

These results qualify the selected Emu198x 0.39.0 configuration with Asm198x 0.0.71 and the original reset fixture. They do not establish stock-OS loading, original-hardware timing, interrupt coexistence, tear-free updates or throughput.
