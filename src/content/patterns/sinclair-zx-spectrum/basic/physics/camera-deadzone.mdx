A camera that follows every step can make the whole scene feel restless. A quiet zone lets the player move a little without scrolling. Push past its edge and the camera moves only far enough to bring the player back to that threshold.

## Include and initialise

Reserve public C/P/L/R/M/S/O and private T/A. Reserve lines **3000–3230**, combine routines.bas with a caller using build.py and keep END, STOP or a jump before the helper. C64/BBC use GOSUB; Spectrum uses GO SUB. Private T/A belong to the call.

Call **3000** at a reset boundary. It clears all public fields. Set retained camera C, world-space player P, quiet-zone thresholds L/R and maximum camera coordinate M afterwards. All are integral byte values in one consistent set of units.

## Update after player movement

Call **3100**. The helper examines the non-wrapping difference P-C. Within inclusive thresholds L..R it leaves C alone. Beyond either threshold it moves just enough to put the player on that edge, then clamps the camera to 0..M. S=1 only when C changes; O=1 reports a valid request.

| Field | Use |
|---|---|
| C | Retained world-space camera |
| P / L / R / M | World player, screen-relative thresholds and scroll limit |
| S / O | Camera shifted / valid-input flags |

Require `L <= R` and current `C <= M`, in addition to byte/integer inputs. Invalid input clears S/O and preserves C. Player and bounds always survive. If changing M would put the current camera outside the new limit, establish a valid starting camera deliberately rather than expecting this query to repair invalid state.

Equal thresholds make a zero-width quiet zone, not an invalid one. World edges can prevent the player remaining at the preferred screen position; clamping takes precedence.

## Supply world coordinates each time

With thresholds 40..80, player positions 90 then 100 move the camera from zero to ten, then twenty. The custom caller sets both thresholds to 60 and finishes at camera 40. Further calls exercise world clamps and invalid bounds.

Line 2000, AA/BB/JJ/KK (Z/Q on Spectrum) and the mailbox are diagnostics. A game services this query after movement, then passes C to a renderer's coordinate conversion or scrolling backend. The helper does not upload tiles, shift a bitmap or install a timer.

## Customise the view

Choose thresholds for the actual viewport and the player's preferred space. Logical coordinates can be pixels, tiles or another consistent unit; the byte example is not a claim to cover every full hardware screen width. Wider worlds require wider inputs/results and renewed range verification.

A dead zone is not smoothing. Easing, look-ahead or camera shake adds a different policy, and should not silently change the retained world coordinate used here. An ordinary real-valued BASIC camera may also suit a game better than this byte-facing contract.

## Mistake and repair

The wrong caller subtracts C from P before calling an API that expects world P. Its first call looks correct because C starts at zero; the second mixes coordinate spaces and stops following properly. Both saved checks fail. Subtract the camera only in the rendering path. Repaired source and loaded program match normal.

## Global names and line numbers

BASIC numeric names, arrays and numbered lines are global. To combine helpers, rename public and private fields and renumber the helper together with every GO SUB/GO TO reference. Keep each state block under one owner. The maintained build.py rejects duplicate line numbers; it does not automatically namespace or renumber routines.

## Machine and measured size

Spectrum FOR variables must be single letters: this diagnostic uses Z/Q instead of the other callers’ JJ/KK. Numeric arrays start at one. AND/OR in these listings join comparisons; neither is being used as a bitwise operator. The diagnostic reserves its mailbox above CLEAR 59999.

The numbered helper occupies **434 tokenised program bytes** on this interpreter, including line headers. This excludes the caller, test tables, numeric scalar/array storage, interpreter stacks and ROM. Tokenised size is not machine-code size or a hardware-cycle count. No real-time or whole-game performance budget is inferred from the diagnostic. The caller’s AA/BB, JJ/KK and RAM mailbox are observation machinery, not required game state.
