A round pickup should not behave like a square. A box can reject obviously distant points cheaply; this query follows that coarse test with the circular boundary, including points exactly on its edge.

## Include and initialise

Reserve public F/D/E/X/Y/A/B/R/O. There are no arrays or private scratch fields. Reserve lines **3000–3190**, combine routines.bas and your caller using build.py and keep END, STOP or a jump before the helper. C64/BBC use GOSUB; Spectrum uses GO SUB.

Call **3000** at a reset boundary. It clears every public field. Supply point X/Y, centre A/B and radius R afterwards. Each is an integral byte in the same non-wrapping coordinate space.

## Test the round boundary

Call **3100**. Valid input sets O=1. D/E are absolute horizontal/vertical differences, and F=1 when `D*D+E*E <= R*R`. The boundary is included. Radius zero accepts only the centre. Inputs survive.

| Field | Use |
|---|---|
| X / Y / A / B / R | Point, centre and radius; preserved |
| D / E | Absolute coordinate differences |
| F / O | Inside-or-on-boundary / valid flag |

Invalid numeric input returns F=D=E=O=0. Valid outside points still return their real D/E with O=1,F=0. This validity guard is an explicit BASIC addition to the assembly helper's byte-valued input contract.

A point farther than R on either axis is immediately outside. Otherwise the helper compares squared distances. It needs no square root and writes no screen or collision response. The BASIC numeric intermediates safely cover the largest byte-coordinate sum, 130,050; an unsigned 16-bit sum alone would not.

## Keep both axes

The normal caller tests differences 4 and 4 against radius 5: the point is outside even though it passes the box test. The custom caller uses the familiar 3–4–5 boundary and reports inside. Later queries cover radius zero and opposite corners.

The saved summary checks verify the intended coordinate differences and original point; the complete native trace separately verifies the hit result after every query.

## Customise shape and space

Use one coordinate origin for point and centre. This is ordinary non-wrapping geometry: zero and 255 are 255 units apart, not one. A toroidal world needs a different shortest-wrapped-distance rule before applying the circle test.

A box-only test is cheaper but accepts corner points outside the circle. Combining a cheap box rejection with this exact round test can save multiplication for distant candidates. Ellipses, circles against rectangles and pixel masks need their own shape-specific rules. Wider coordinates need a sufficiently wide squared intermediate and separate range checks/tests.

## Mistake and repair

The wrong caller replaces Y with the centre's vertical coordinate. The outside point is tested as though it lay on the horizontal axis, so it becomes a false hit. Both saved checks fail because the vertical difference and supplied point have changed. Preserve both axes in the same space. Repaired source and loaded program match the normal caller.

## Cost and Maths for Games

There are fixed input checks and two absolute differences. The circular stage uses three multiplications only when the axis checks survive. At differences D=255, E=255 and radius 255, the sum must remain 130,050; wrapping it to sixteen bits could create a false hit. The qualified BASIC interpreters retain the required integer precision. No native-cycle or frame-time claim is made.

## Global names and line numbers

BASIC numeric names, arrays and numbered lines are global. To combine helpers, rename public and private fields and renumber the helper together with every GO SUB/GO TO reference. Keep each state block under one owner. The maintained build.py rejects duplicate line numbers; it does not automatically namespace or renumber routines.

## Machine and measured size

Spectrum FOR variables must be single letters: this diagnostic uses Z instead of the other callers’ JJ. The helper uses scalar numeric fields and allocates no arrays. AND/OR in these listings join comparisons; neither is being used as a bitwise operator. The diagnostic reserves its mailbox above CLEAR 59999.

The numbered helper occupies **417 tokenised program bytes** on this interpreter, including line headers. This excludes the caller, test tables, numeric scalar/array storage, interpreter stacks and ROM. Tokenised size is not machine-code size or a hardware-cycle count. No real-time or whole-game performance budget is inferred from the diagnostic. The caller’s AA/BB, Z and RAM mailbox are observation machinery, not required game state.

## Execution evidence

Working, custom, deliberately wrong and exact repaired callers executed through Spectrum's stock BASIC interpreter under Emu198x 0.44.2. Build198x 0.2.9 tokenises C64 PRG and Spectrum TAP programs. C64 enters stock RUN, Spectrum uses ROM tape loading, and BBC enters every numbered source line through MOS/BASIC. Actual loaded program bytes, complete state packets, positive completion/count/guards and visible result pixels are checked. After the positive completion marker, the observer advances two complete display frames before capturing, so a partially scanned final character cannot masquerade as a finished picture. Firmware is not distributed.

An independent mathematical/order model checks the trace and rejects altered source, configuration, loaded program, state, completion and image evidence. Host exhaustive checks complement the native boundary/sequential examples; those host ranges are not claimed as natively exhaustive. The supplied diagnostic callers deliberately end with STOP; the interpreter report is expected. The wrong caller prints 0,0 and the normal/custom/repaired callers print 1,1.
