Put a direction beside a flag and you have the beginnings of a compact record. The difficult part is changing one field without damaging its neighbours. This writer checks the whole request before changing a destination bit.

## Include and initialise

Reserve B(4), public O/C/N/V and private I/J/K/P/T/H. Reserve lines **3000–3240**, combine routines.bas and your caller with build.py, and put END, STOP or a jump before the helper. Use GOSUB on C64/BBC and GO SUB on Spectrum. Private scratch must not double as an outer loop variable.

Call **3000** at a new-block boundary. It clears the destination bytes, cursor C, inputs N/V and result O. Load any existing destination bytes after init. Retain C and B between field writes.

## Write one field

Supply width N=0..8 and value V=0..255, then call **3100**. The helper writes the **low N bits** of V, most significant selected bit first, starting at bit C. B(1)'s most significant bit is offset zero. O=1 reports success and C advances by N. A zero-width write succeeds without changing any byte or the cursor.

| Field | Use |
|---|---|
| B(1)..B(4) | Retained destination; other bits are preserved |
| C | Retained next-bit offset, 0..32 |
| N / V | Requested width / unsigned source value |
| O | Fresh valid flag after the call |

C, N, V and every destination byte must be integral and in range. The complete span must fit within 32 bits. A failure sets O=0 and preserves C, N, V and all destination bytes. Success retains N/V too. This is all-or-nothing span validation under one mutation owner; it installs no interrupt exclusion or hardware upload.

## The reusable routine

For each target bit, the routine finds the old bit and the required bit, then adds their difference multiplied by that bit's place value. Surrounding bits stay intact. The selected source width matters: V=255 with N=4 writes 15, not an error. Enforce a narrower game-specific value range before calling if truncation is inappropriate.

## Pack a retained record

The normal caller starts with four bytes of 85, writes two nibbles followed by three bytes, and obtains 171,205,239,1. The initial nonzero destination makes preserving and replacing existing bits observable.

The diagnostic's line 2000, mailbox, AA/BB and JJ/KK (Z/Q on Spectrum) are removable. Your game retains its own B/C, sets N/V and consumes O. The complete native trace checks every destination value after each write, including cross-byte requests and rejected spans.

## Customise the layout

The custom caller builds the same bytes with four eight-bit writes. Changing field widths changes your local record layout; update its reader too. This routine accepts no file header or implicit terminator and introduces no project-wide format.

A byte-aligned record is simpler and faster to edit. Native bit masks or a reservoir can reduce hot-loop work, while buffered file output adds cursor/refill ownership of its own. Choose compactness where it helps storage or transfer; packing is not automatically faster.

## Mistake and repair

The wrong caller resets C before every field, repeatedly overwriting the start. Its returned O flags remain valid, but C and the completed record are wrong. The repair keeps C/B between writes. The retained trace checks each returned O. Repaired source and loaded program match the normal caller exactly.

## Cost and Maths for Games

A call validates four bytes and visits at most eight bits. Powers, division and range checks cost interpreter work; the helper has no measured hardware-cycle budget. Its globals and arrays occupy interpreter-managed numeric storage.

[Maths for Games](/craft/maths-for-games/) connects bit positions, powers of two and masks to compact state. ## Machine and measured size

Spectrum FOR variables must be single letters: this diagnostic uses Z/Q instead of the other callers’ JJ/KK. Numeric arrays start at one. AND/OR in these listings join comparisons; neither is being used as a bitwise operator. The diagnostic reserves its mailbox above CLEAR 59999.

The numbered helper occupies **566 tokenised program bytes** on this interpreter, including line headers. This excludes the caller, test tables, numeric scalar/array storage, interpreter stacks and ROM. Tokenised size is not machine-code size or a hardware-cycle count. No real-time or whole-game performance budget is inferred from the diagnostic. The caller’s AA/BB, Z/Q and RAM mailbox are observation machinery, not required game state.

## Execution evidence

Working, custom, deliberately wrong and exact repaired callers executed through Spectrum's stock BASIC interpreter under Emu198x 0.44.2. Build198x 0.2.9 tokenises C64 PRG and Spectrum TAP programs. C64 enters stock RUN, Spectrum uses ROM tape loading, and BBC enters every numbered source line through MOS/BASIC. Actual loaded program bytes, complete state packets, positive completion/count/guards and visible result pixels are checked. After the positive completion marker, the observer advances two complete display frames before capturing, so a partially scanned final character cannot masquerade as a finished picture. Firmware is not distributed.

An independent mathematical/order model checks the trace and rejects altered source, configuration, loaded program, state, completion and image evidence. Host exhaustive checks complement the native boundary/sequential examples; those host ranges are not claimed as natively exhaustive. The supplied diagnostic callers deliberately end with STOP; the interpreter report is expected. The wrong caller prints 0,0 and the normal/custom/repaired callers print 1,1.
