Two nearby doors should not make the interaction prompt flicker whenever the player moves a fraction closer to one of them. Choose an eligible target, then give the current target a small retention margin. The player gets a stable prompt without making a distant object impossible to leave.

## Include and initialise

Include routines.bas, reserving lines **3000–3330**. Public fields are S/O/C/A/R/M/D/E/F/G; private scratch names are I/K/P/U/V/T/B. Call **3000** at a chosen reset boundary. It clears public fields. Put a STOP, END or jump before the helper; call **3100** to choose focus.

C is the current target index, zero through three, or255 for none. A is a four-bit active mask. D/E/F/G are the four target distances, R the maximum allowed distance and M the retention margin. All these values must be integral bytes, and A cannot exceed15. Supply every distance, even for inactive targets.

S is the selected index;255 means none. O=1 means a valid query, including an empty eligible set. Invalid input returns S=255/O=0 and preserves all inputs. The routine does not change C: after a valid query the caller decides when to commit C=S. That includes clearing C when S=255.

## Prefer the nearest, retain the current

A target is eligible only when its active bit is set and its distance is at most R. Without eligible current focus, the nearest eligible target wins; equal distances favour the lower index. With eligible current focus, retain it while its distance is no greater than the best distance plus M. An inactive or out-of-range current target gets no grace from the margin.

The normal caller starts with target one at distance ten and target zero at nine, using margin two. Target one remains selected. At distance eight, target zero is still only two closer, so focus stays. At seven it is three closer, and focus switches to zero.

The custom caller starts with target three and four equal distances. Even with margin zero, an eligible current target wins a tie. Moving target zero nearer switches focus; removing every active target returns a valid none. A later invalid mask returns O=0. Saved checks verify the first selection and the unchanged input C; diagnostics observe state before the caller's commit.

## Choose what distance means

The helper compares numbers supplied by the game. They might be Manhattan distance, a screen-space score or another consistent metric. R and M must use the same units. If using squared distances to avoid a square root, a fixed score margin is not a fixed physical distance margin. Choose and explain that behaviour deliberately.

Use separate state for separate players. Target identities must remain stable between queries. This four-target interface is useful for a small interaction set; a larger game can gather a bounded shortlist from a spatial query and translate stable identities explicitly. Recycling shortlist indices without translating C would silently change which object owns focus.

## Mistake and repair

The wrong caller sets C to255 before every query. The helper keeps choosing the nearest or lowest tied index because it never receives the old focus. Both saved first-selection/current-input checks fail. Retain the committed current index between queries and replace it only through the intended game policy. Repaired source and loaded programs match normal exactly.

## Cost and Maths for Games

The helper validates eight inputs and examines exactly four candidates. It uses no arrays, display access or timer. The best distance starts at256, outside the valid byte range. Best distance plus margin can reach510 and deliberately stays wide in BASIC; narrowing that sum to a byte would change the rule near its limit.

Nearest-target selection without memory is cheaper in state and may be exactly right for a single shot. Retention adds deliberate hysteresis. A dwell timer or separate enter/leave radii offer different stability and response costs; they are alternatives, not automatic upgrades.

[Maths for Games](/craft/maths-for-games/) connects ordering, tie rules, distance measures and hysteresis. [The Craft](/craft/) connects predictable prompts and the balance between stability and responsiveness.

## Global names and line numbers

BASIC numeric names, arrays and numbered lines are global. To combine helpers, rename public and private fields and renumber the helper together with every GO SUB/GO TO reference. Keep each state block under one owner. The maintained build.py rejects duplicate line numbers; it does not automatically namespace or renumber routines.

## Machine and measured size

Spectrum FOR variables must be single letters: this diagnostic uses Z/Q instead of the other callers’ JJ/KK. Numeric arrays start at one. AND/OR in these listings join comparisons; neither is being used as a bitwise operator. The diagnostic reserves its mailbox above CLEAR 59999.

The numbered helper occupies **792 tokenised program bytes** on this interpreter, including line headers. This excludes the caller, test tables, numeric scalar/array storage, interpreter stacks and ROM. Tokenised size is not machine-code size or a hardware-cycle count. No real-time or whole-game performance budget is inferred from the diagnostic. The caller’s AA/BB, JJ/KK and RAM mailbox are observation machinery, not required game state.

Working, custom, deliberately wrong and exact repaired callers executed through Spectrum's stock BASIC interpreter under Emu198x 0.44.2. Build198x 0.2.9 tokenises C64 PRG and Spectrum TAP programs.
