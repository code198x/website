An urgent event should not wait behind three routine ones. But two equally urgent events should not swap places unpredictably either. This small queue gives priority and fairness a precise rule: higher priority first, earlier insertion first when tied.

## Include and initialise

Reserve A(4) for events, B(4) for priorities, public V/P/R/O/N/M/E/D and private J/K. Reserve lines **3000–3460**, including the separated insertion and removal branches. Combine routines.bas with your caller using build.py and keep END, STOP or a jump before the helper. C64/BBC use GOSUB; Spectrum uses GO SUB. Private J/K must not be outer loop variables.

Call **3000** for a new queue. It clears all public fields and both arrays. N is the active count from zero to four. Retain N/A/B between requests. Active pairs must be sorted by descending priority; the helper checks that precondition before changing them.

## Insert or remove one event

Set M=0, new event E and new priority D, then call **3100** to insert. Set M=1 and call 3100 to remove the highest-priority pair. Supply byte-valued events and priorities;255 is a valid event, so use the result flag rather than treating the returned event as an absence test.

| Field | Use |
|---|---|
| N, A(1)..A(4), B(1)..B(4) | Retained count, events and priorities |
| M / E / D | Mode, new event and priority |
| V / P / R / O | Returned event, priority, changed flag and valid flag |

O=0 rejects invalid count/mode, active pairs, ordering or insertion inputs. The queue survives unchanged. Valid requests return O=1. R=1 reports a change and V/P describes the inserted or removed pair. A full insertion or empty removal is a valid no-op: R=0,V=255,P=0. A full queue rejects a new event even if its priority is higher; it does not evict an existing one.

Removal shifts the remaining active pairs and clears the vacated pair to zero. Insertion keeps existing equal priorities first. Inputs M/E/D survive. Removal ignores E/D because they are not inputs to that operation. This BASIC port explicitly checks numeric/ordering preconditions that byte-valued assembly callers must also respect.

## Service a retained queue

The normal caller inserts events 11, 22, 33, 44 with priorities 1, 9, 9, 3. Removal returns 22, 33, 44, 11. The equal-priority 22 and 33 keep their insertion order. A fifth removal exercises the empty no-op.

Line 2000, AA/BB/JJ/KK (Z/Q on Spectrum) and the mailbox are observation machinery. A game keeps its own queue, sets M/E/D, calls 3100 and checks both O and R. The complete native trace checks all fields and array cells after every request.

## Customise urgency

The custom caller mixes priorities 0 and 255, keeping ties stable at the maximum too. Choose what those numbers mean for your game; the queue does not decide whether a sound, collision or scene change is urgent.

A plain FIFO is simpler when urgency is unnecessary. A binary heap can suit a much larger queue. High-priority traffic can starve routine work, so a game needing service guarantees must add an explicit budget or scheduling policy. The adjacent round-robin technique provides a different fairness rule, not an automatic replacement.

## Mistake and repair

The wrong caller discards each requested priority by setting D=0. All events now tie, so the queue behaves as a FIFO and returns 11 before urgent 22. Both saved checks fail. Preserve priority alongside each event; the repair matches the normal source and loaded program exactly.

## Cost and Maths for Games

The routine validates and searches at most four pairs. Insertion moves at most three existing pairs; removal moves at most three and clears one vacated pair. There is no allocation, clock or display upload. BASIC array cells carry interpreter-managed numeric storage, not a packed sixteen-byte structure.

## Machine and measured size

Spectrum FOR variables must be single letters: this diagnostic uses Z/Q instead of the other callers’ JJ/KK. Numeric arrays start at one. AND/OR in these listings join comparisons; neither is being used as a bitwise operator. The diagnostic reserves its mailbox above CLEAR 59999.

The numbered helper occupies **1011 tokenised program bytes** on this interpreter, including line headers. This excludes the caller, test tables, numeric scalar/array storage, interpreter stacks and ROM. Tokenised size is not machine-code size or a hardware-cycle count. No real-time or whole-game performance budget is inferred from the diagnostic. The caller’s AA/BB, JJ/KK and RAM mailbox are observation machinery, not required game state.
