Sometimes you just want to see part of the level. This routine prints a rectangular slice of a map as digits. It is a useful room display for a text game, or a quick view of the collision data while a graphical game is being built.

It prints at the current text cursor. It does not position a hardware tile window, choose colours or draw bitmap artwork. The map array is one-based, so the query adds one to the zero-based logical offset.

## Include and call it

Include `query.bas` at lines 1000–1360 and `region.bas` at 1400–1580. Copy the allocation and map initialisation from the caller before your game loop. If your program already contains the same map-query routines, keep one copy and check every entry number.

<CodeFromFile src="sinclair-zx-spectrum/patterns/basic/rendering/text-region/caller.bas" lang="basic" title="Choose and print a three-by-two map region" />

The example prints `000` followed by `020`. Q/U are zero-based source column/row; A/B are width/height in cells. They must be integers, the dimensions positive, and the whole rectangle must fit inside W by H. L is the highest permitted tile ID; this digit adapter requires 0–9. The map must remain unchanged during the call.

<CodeFromFile src="sinclair-zx-spectrum/patterns/basic/rendering/text-region/region.bas" lang="basic" title="Validate the complete source region, then print it" />

Call 1400 with `GOSUB` (`GO SUB` on Spectrum), then check E. E=1 means the complete region was printed; E=0 means nothing was printed. The routine first checks bounds and every tile ID, then makes a second pass to print. A malformed last tile cannot leave the first rows on screen. This costs an extra lookup per cell, which is a deliberate trade for predictable failure.

## What it owns

Keep the caller-owned map M() (MM() on Atom), W/H/L and its query inputs valid. The complete supplied query file also uses P()/PP() and S for its separate property/world-position calls. Region drawing uses Q/U/A/B and overwrites E/C/R/T/D/J/K/Z. Do not surround it with a loop that needs J or K preserved. Calls are synchronous, global-state routines, not re-entrant components.

Output uses character code 48+T and a newline after each row. Leave enough text columns and rows at the cursor. Wrapping and scrolling belong to the interpreter; source-map bounds do not prevent the display scrolling. A successful call does not promise to leave the screen cursor where it started.

## Make it yours

Change Q/U to inspect another room, or A/B to make a small moving view. A one-cell region is a useful first test before drawing a larger area. Change the character conversion at line 1540 to choose different glyphs, preserving the ID preflight and the newline behaviour. For a custom alphabet, use a table rather than assuming every ID is a character code.

If the second row is displaced, check the map stride: it is W, not the region width A. The executed `wrong-stride` example shows the difference. If a bad tile leaves a partial picture, validation has moved into the printing pass; put the complete preflight back before the first PRINT. If calling this inside another loop breaks that loop, check its variable names against J/K/Z and the query scratch.

[Map queries](/patterns/sinclair-zx-spectrum/basic/rendering/tile-map/) explain the row-major index and world-to-cell conversion. [Maths for Games](/craft/maths-for-games/) provides the wider context for coordinates and units. The same logical rectangle can feed a native renderer later; its screen layout and timing need their own implementation.
