## Overview

Draw large seven-segment style digits using PLOT and DRAW. Each digit is 40×56 pixels (5×7 character cells), cell-aligned with a 1-pixel outline around each segment. Digit shapes defined as 10 compact DATA strings — each character represents one segment (1=lit, 0=off). Reusable across any game needing a large numeric display: countdowns, scores, timers.

## Calling and replacing a digit

Set integer `d` in 0–9, `px` in 0–216 and `py` in 55–175 before `GO SUB 2000`. Sinclair BASIC's PLOT coordinates start at the lower-left of its 256 × 176 graphics area. For the advertised cell separation, use multiples of eight for both `px` and `py`—for example, 104 and 168. Arbitrary positions can share attribute cells with neighbouring artwork.

Set INK, PAPER, BRIGHT, FLASH, OVER and INVERSE deliberately; normal drawing uses OVER 0 and INVERSE 0. The routine changes `i`, `s$`, the graphics cursor and the shared DATA pointer. It uses DATA lines 9000–9009; another data reader must RESTORE its own data before continuing.

It **adds the lit segments**. Drawing 1 over 8 does not erase the other six segments. Start with a clear rectangle, clear the old owned rectangle before replacing a digit, or redraw the relevant background. The standalone example can use CLS; a game should avoid clearing unrelated artwork.

## Why cell-aligned?

The 1-pixel inset on every segment isn't decorative — it makes each segment fit *inside* its own character cell. Because the Spectrum's attribute system stores one INK/PAPER pair per 8×8 cell, two segments touching at a cell boundary would share an attribute byte and **clash colours**. The cell-aligned design keeps every segment in its own cell, so the digit can be redrawn in any colour by setting INK before calling — the segments occupy separate attribute cells under the stated alignment. Artwork outside that rectangle still shares the screen and needs its own colour plan.

PLOT and DRAW honour the current INK colour: the segment pixels light up in whatever ink you set before `GO SUB 2000`. The cell's PAPER colour stays whatever it was; segments effectively paint on top.

## Trade-offs

| Aspect | Detail |
|--------|--------|
| Speed | ~7 FOR loops per digit, fast enough for scores/countdowns |
| Memory | 10 DATA lines + 10 code lines = minimal |
| Limitation | Fixed size (40×56 px). Resize by changing DRAW/PLOT offsets |
| Attribute | Segment separation requires the stated eight-pixel alignment |

**When to use:** Large digit displays — countdowns, scores, timers, PIN entry.

**When to avoid:** Small text — use PRINT for anything under 16px tall.
