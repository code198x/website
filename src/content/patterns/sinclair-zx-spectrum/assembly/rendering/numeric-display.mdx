## Overview

Convert a binary number to decimal digits for display. Uses repeated subtraction to extract the tens digit (no division instruction on Z80). Print both digits using the character printing routine. Perfect for scores, lives counters, and timers.


## Calling the routines

Supply `print_char`: A is an ASCII character, B is the row and C is the column. It must preserve BC, DE and HL. The [character printer](/patterns/sinclair-zx-spectrum/assembly/rendering/character-printing/) meets that contract. Include `numeric.inc` once and allocate one writable `score_bcd` byte if using its BCD helpers.

`print_two_digits` accepts A = 0–99 and writes two digits, including a leading zero. `print_three_digits` accepts HL = 0–999 and writes three. Both return C immediately after their digits and preserve B/DE; the three-digit routine also changes HL. `print_number` accepts A = 0–99, suppresses the leading zero and advances C by one or two. It preserves B/DE/HL. AF is working state.

Choose a start column that leaves enough room: C ≤ 30 for two digits and C ≤ 29 for three. B is 0–23 for the bitmap printer. Invalid numeric values are outside these contracts. Call once after a value changes; doing the same division and drawing every update is unnecessary.

The BCD helpers accept a valid packed decimal byte, from `$00` to `$99`. Adding ten wraps 90–99 to 00–09 and sets the processor's carry; inspect that carry before another instruction changes it if the game needs an overflow signal. The BCD printer advances C by two. A change from two visible digits to one also needs the caller to clear the old second cell.

For example, after establishing the documented stack, state and data:

```z80
    ld a,42
    ld b,10
    ld c,3
    call print_two_digits  ; prints 42; C is now5
    ; Include numeric.inc and characters.inc once; allocate score_bcd if used.
```

## Trade-offs

| Aspect | Cost |
|--------|------|
| CPU | ~250 cycles |
| Memory | ~30 bytes |
| Limitation | Simple version limited to 0-99 |

**When to use:** Displaying scores, lives, timers, level numbers.

**When to avoid:** Very large numbers (use BCD or lookup tables for speed).

## How It Works

The Z80 has no division instruction, so we use repeated subtraction:

1. Start with tens counter = 0
2. While number >= 10: subtract 10, increment counter
3. Counter = tens digit, remainder = units digit
4. Add `'0'` ($30) to convert to ASCII

## BCD alternative (DAA)

For score counters that increment frequently, **BCD** (Binary Coded Decimal) avoids the repeated-subtraction loop entirely. Store the score with each digit in 4 bits (so $99 holds 99, $123 spans two bytes), and use the Z80's `DAA` instruction after every add to keep the BCD encoding intact:



BCD pays for itself when the score updates many times per frame (combos, time bonuses) — no division loop, just one `DAA` per add. The trade-off is that BCD overflow needs explicit handling for scores beyond $99 / $9999.
