## Use it in a project

Maintain up to four descending unsigned byte scores with associated byte tags. Insert after existing equal scores. Return RANK 0–3 and INSERTED=1 when retained; otherwise RANK=255. COUNT>4 is invalid. Entries beyond COUNT are unused; the existing prefix must be sorted.

Include `component.inc` once (MOS callers include the shared 6502 implementation through it). Reserve the public fields in this exact order: **RANK, INSERTED, VALID, SCORE, TAG, COUNT, S0, S1, S2, S3, I0, I1, I2, I3**. They occupy 14 contiguous bytes. Also reserve the private workspace: **T0, T1, T2, T3, EXPR_SAVE** (5 bytes). Array names in the explanation refer to the numbered consecutive bindings, such as C0, C1 and so on.

Call `high_score_insertion_init` once at the intended reset boundary. It clears inputs as well as outputs and workspace. Set your starting state and configuration afterwards, then call `high_score_insertion_step` whenever the described event occurs. The helper reads no device, waits for no frame and installs no interrupt handler.

| Ownership | Fields |
|---|---|
| Retain between calls | COUNT, S0..S3 and I0..I3 |
| Supply before service | SCORE and TAG |
| Read after service | RANK, INSERTED and VALID |

Find the first strictly smaller score, then move the tail backwards so no source entry is overwritten before it has been copied.

## Machine contract

AF/BC/DE/HL may change; IX/IY are preserved. A direct CALL needs two return-address stack bytes. The helper makes no nested calls and adds no other stack use. Its named scratch is private workspace, not a pointer, a ROM variable or shared zero-page space that the game may borrow concurrently. The samples use fixed symbol bindings. Scope or rename every label and binding, including the component_end measurement marker, and allocate a separate block for each independent instance. Different helpers can also use common field names, so combining them needs separate namespaces or explicitly renamed bindings. Give each block one mutation owner.

The 48K diagnostic boots through ROM tape loading and USR, disables interrupts and owns the screen. The helper performs no port or screen writes.

## Adapt the caller

`demo.asm` supplies the bindings and include order. `exercise.inc` first runs table cases, then a separate client retaining state between calls. A game can call the public step entry directly and remove the diagnostic packet and display. Do not copy the diagnostic's hardware takeover into an existing game loop.

Build with `make ASM198X=/path/to/asm198x`. The Makefile produces normal, custom, deliberately wrong and repaired programs. Tools must already be installed; the sample downloads nothing.

## Customise it

Retain the highest possible byte score and a zero score. The maintained custom caller changes its inputs or client sequence rather than hiding a different implementation behind the same label. Compare every state of the two clients, not only their final display.

The custom diagnostic row is **01 01 01 00 05 02 FF 00**. The full client trace in the source explains how it gets there.

## Mistake and repair

The wrong caller clears the achieved score before inserting it. The ordering routine cannot recover that lost value. Pass the completed score before resetting gameplay state.

The BROKEN branch lives in the sequential client, not the reusable helper. `wrong.asm` selects it; `repaired.asm` restores the normal call sequence. The repaired executable matches the normal program (for Spectrum, compare loaded CODE rather than the tape filename).

## Cost and alternatives

The measured helper extent is 352 code bytes; public state is 14 bytes and private scratch is 5 bytes. There are no immutable helper tables. Caller data, the test cases, return-address stack, alignment and display buffers cost additional space. These are assembled sizes, not cycle measurements.

Four comparisons and at most three pair moves. Insertion is easier to audit than sorting the whole table after every result.

Scores are one byte and tags are identifiers, not name strings. Wider scores need a multi-byte comparison; permanent storage is a separate concern.

## Execution evidence

Four variants run on 48K PAL ROM tape load and USR, using Asm198x 0.0.72, Emu198x 0.44.2. Each executes 64 boundary/varied/error table cases, dirty initialisation and the separate retained-state client. An independent mathematical/container model checks every public byte after every call. This is bounded example coverage, not exhaustive correctness for every possible state.

The records retain loaded immutable code, completion, register sentinels, full packets, source/tool/firmware hashes and captures. The public gate validates these retained observations and rejects altered evidence; it does not run restricted firmware. No firmware is distributed. The eight displayed bytes are the first eight public fields, zero-padded when shorter; the packet includes every field.
