## Use it in a project

Zero count requires kind zero; a nonempty stack requires a nonzero kind. Both counts must be at most CAPACITY. AMOUNT requests up to that many items from source into destination. A nonempty destination accepts only the same kind. MOVED reports the actual minimum of requested, available and free space; zero is a valid refusal. On success clear an emptied source kind and assign the source kind to an empty destination. Invalid stack representation or capacity sets VALID=0 without changing either stack.

Include `component.inc` once (MOS callers include the shared 6502 implementation through it). Reserve the public fields in this exact order: **MOVED, VALID, SOURCE_KIND, SOURCE_COUNT, DEST_KIND, DEST_COUNT, CAPACITY, AMOUNT**. They occupy 8 contiguous bytes. Also reserve the private workspace: **T0** (1 bytes). Array names in the explanation refer to the numbered consecutive bindings, such as C0, C1 and so on.

Call `inventory_transfer_init` once at the intended reset boundary. It clears inputs as well as outputs and workspace. Set your starting state and configuration afterwards, then call `inventory_transfer_step` whenever the described event occurs. The helper reads no device, waits for no frame and installs no interrupt handler.

| Ownership | Fields |
|---|---|
| Retain between calls | source and destination kinds/counts |
| Supply before service | CAPACITY and AMOUNT |
| Read after service | updated stacks, MOVED and VALID |

Validate both representations before writing, calculate the complete accepted amount, then commit both counts and kinds. Conservation of the total item count is the central invariant.

## Machine contract

AF/BC/DE/HL may change; IX/IY are preserved. A direct CALL needs two return-address stack bytes. The helper makes no nested calls and adds no other stack use. Its named scratch is private workspace, not a pointer, a ROM variable or shared zero-page space that the game may borrow concurrently. The samples use fixed symbol bindings. Scope or rename every label and binding, including the component_end measurement marker, and allocate a separate block for each independent instance. Different helpers can also use common field names, so combining them needs separate namespaces or explicitly renamed bindings. Give each block one mutation owner.

The 48K diagnostic boots through ROM tape loading and USR, disables interrupts and owns the screen. The helper performs no port or screen writes.

## Adapt the caller

`demo.asm` supplies the bindings and include order. `exercise.inc` first runs table cases, then a separate client retaining state between calls. A game can call the public step entry directly and remove the diagnostic packet and display. Do not copy the diagnostic's hardware takeover into an existing game loop.

Build with `make ASM198X=/path/to/asm198x`. The Makefile produces normal, custom, deliberately wrong and repaired programs. Tools must already be installed; the sample downloads nothing.

## Mistake and repair

The wrong client clears the transfer request before service. Both stacks remain unchanged and MOVED is zero. Keep the requested amount until it has been consumed.

The BROKEN branch lives in the sequential client, not the reusable helper. `wrong.asm` selects it; `repaired.asm` restores the normal call sequence. The repaired executable matches the normal program (for Spectrum, compare loaded CODE rather than the tape filename).

## Cost and alternatives

The measured helper extent is 364 code bytes; public state is 8 bytes and private scratch is 1 bytes. There are no immutable helper tables. Caller data, the test cases, return-address stack, alignment and display buffers cost additional space. These are assembled sizes, not cycle measurements.

Constant work with no array search. Full inventory placement can scan candidate stacks first and invoke this transaction under the same mutation owner.

One source and one destination are borrowed exclusively during a call. This does not find stacks, merge an entire inventory, reserve network transactions or support different per-item caps. The capacity is shared by these two stacks; use a larger transaction for several destinations.

## Execution evidence

Four variants run on 48K PAL ROM tape load and USR, using Asm198x 0.0.72, Emu198x 0.44.2. Each executes 64 boundary/varied/error table cases, dirty initialisation and the separate retained-state client. An independent mathematical/container model checks every public byte after every call. This is bounded example coverage, not exhaustive correctness for every possible state.

The records retain loaded immutable code, completion, register sentinels, full packets, source/tool/firmware hashes and captures. The public gate validates these retained observations and rejects altered evidence; it does not run restricted firmware. No firmware is distributed. The eight displayed bytes are the first eight public fields, zero-padded when shorter; the packet includes every field.
