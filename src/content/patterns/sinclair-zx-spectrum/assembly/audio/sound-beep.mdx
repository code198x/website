## A delay and a count

The Spectrum's beeper needs the processor to change bit 4 of output port `$FE`. Set it, wait, clear it, wait, and we have one cycle. Repeating that cycle makes a tone. The delay between changes controls **pitch**; the number of complete cycles controls **length**.

This example targets a stock **48K PAL Spectrum**, with code at `$8000` and the stack at `$FF00`. It provides short blocking feedback. During a sound, the game cannot update or read its controls. [Meteor Storm's impact lesson](/systems/sinclair-zx-spectrum/assembly/meteor-storm/unit-24/) uses that trade-off after the run ends; a game that needs movement throughout the sound needs a different scheduling arrangement.

## The routine's contract

Before calling `sound_beep`, put the half-period delay in **H**, the number of cycles in **L**, and the border/MIC output in **A**. H and L must each be **1–255**. Zero wraps to 256 loop iterations; it does not mean silence.

The caller disables maskable interrupts for the sound and decides when to enable them again. Otherwise an interrupt handler can interrupt the timing. The routine leaves the interrupt state alone and returns with the speaker bit clear.

It changes AF, B, D and L. C, E and H are preserved. It also needs an ordinary working stack for CALL and RET.

<CodeFromFile src="sinclair-zx-spectrum/patterns/assembly/audio/sound-beep/sound-beep.inc" lang="z80" />

Each `ld b,h` loads the same delay. `djnz` reduces B until it reaches zero. `dec l` counts whole high/low cycles. H is never reduced by the inner loop, so changing L changes length without changing the period.

Port `$FE` also controls the border in bits 0–2 and MIC in bit 3. D keeps those four bits for both writes. With A=1, the writes alternate between 17 and 1: blue border throughout. With A=9, they alternate between 25 and 9: the same border and a preserved high MIC bit. That preserves the chosen digital output; it does not isolate the analogue cassette connection.

In a game, all code writing this port must share a maintained output byte. Reading `$FE` reads the keyboard and EAR input, not the previous output value.

## Predict the pitch and length

At a nominal 3.5 MHz, ignoring contention and interrupts, the interval from one rising speaker write to the next is `26×H+51` T-states. The two halves differ slightly because the low half also counts cycles and jumps back. These are approximate tuning values for this routine, not a table for every beeper engine.

| H | L | Approximate pitch | Approximate length |
|---|---|---|---|
| 255 | 105 | 524 Hz | 200 ms |
| 127 | 105 | 1044 Hz | 100 ms |
| 127 | 210 | 1044 Hz | 201 ms |
| 255 | 20 | 524 Hz | 38 ms |

`DJNZ` takes 13 T-states when it jumps and 8 on its final iteration. Counting the surrounding instructions gives the period above. The 48K ULA can delay port accesses, so a capture will differ slightly from this calculation. Moving the code or stack into contended memory changes the assumption too.

<Question prompt="If we halve H but leave L alone, which changes: pitch, length, or both?">

Both change. The shorter period raises pitch, and the same number of shorter cycles finishes sooner. Approximately doubling L restores the length while retaining the higher pitch.

</Question>

## Rising, falling and click effects

These wrappers use `ula_output` as their border/MIC state. The success effect plays sixteen cycles at each of eight delays, reducing H from 200 to 88. The error effect uses the same delays in reverse. Each higher note is shorter because its cycle count stays fixed. The click uses twelve cycles at H=127.

`push hl` and `pop hl` recover the note's parameters after the beep has consumed L. The labels are distinct global names, so no call relies on another routine's local-label scope. Include these files once; the wrapper contract is the same blocking/interrupt contract, with H also changed.

## Run the complete example

Turn on **Sound**, then assemble and run. You should hear the fixed tone, the rising effect, the falling effect and the click, separated by half-second gaps. The border should stay blue. The demonstration enables the ROM interrupt during the gaps and after playback; it disables it for each sound.
