Four voices can turn one small waveform into a tune. The useful next step after [playing a sample](/patterns/commodore-amiga/assembly/audio/playing-a-sample/) is to give each voice its own sequence of pitches, then advance those sequences on a clock.

This caller is deliberately small: eight rows, four word-sized note indices per row, one shared looping waveform and six updates between row starts. A zero holds the previous note. It does not mean silence. The complete data is included, so the player never wanders past an unfinished pattern.

## Run and connect it

Target: A500 OCS PAL with Kickstart 1.3, booted from the sample's ADF. Press Fire on physical joystick port 2 to start. Reset to leave; this caller does not return to AmigaOS.

Build the sample with Asm198x and Build198x:

```sh
make -C commodore-amiga/patterns/assembly/audio/four-channel-music BUILD198X=/path/to/build198x
```

The caller owns the custom chips, all four audio channels and their DMA/interrupt requests. It disables audio modulation. Samples must be word-aligned in Chip RAM and stay there while DMA can read them. Before reusing `music_init` in another caller, turn audio DMA off and allow at least two sample periods for it to settle. A program sharing AmigaOS uses its audio facilities instead of this exclusive caller.

The main loop calls the existing vertical-blank wait, then `music_tick`. This is a subroutine returning with `RTS`, not an interrupt handler. An IRQ dispatcher would have to preserve working registers, acknowledge its interrupt and return with `RTE` itself.

## One channel block, four copies

Paula's channel blocks start at custom offsets `$A0`, `$B0`, `$C0` and `$D0`. Within each block, location is at +0, word length at +4, period at +6 and volume at +8. Using one consistent base avoids accidentally writing disk or display registers.

`music_init` configures **every** channel before enabling DMA. `music_tick` changes period and volume on a note; it leaves the looping sample running. A held row leaves that voice alone. There is no attack envelope, instrument retrigger or effect command hidden behind a note number.

`music_init` changes A2/A5/D5 and condition codes. `music_tick` changes A0/A1/A2/D0/D5/D7 and condition codes. The wait also changes D6. The pattern and period table are read-only after loading; `music_row` and `music_timer` are writable words. Include each routine once and keep competing writers out of that state and those channels.

## What its numbers mean

At 50 updates per second, six intervals between rows give about 8.3 rows per second. At 60, the same counter gives 10. A missed update stretches the music; a different clock requires a deliberate timing choice.

The period table uses familiar tracker period values, but they do not give an absolute pitch independently of the sample. Here each waveform cycle has 16 samples: nominal PAL pitch is approximately `3546895 / (period × 16)`. A recorded instrument with a different cycle length will tune differently. Lower periods play the data faster.

The four hardware channels have fixed stereo routing: 0/3 left and 1/2 right. Another voice needs a different resource plan, such as software mixing; it is not a fifth independent Paula channel.

## Verification and limits

**Code status: assembled and emulator-executed on the named configuration.** The check cold-boots the ADF, starts through real joystick input, observes all four channels over every row and verifies holds, six-update timing and wrap. It also checks actual stereo PCM. A caller with the DMA enable deliberately removed must fail the same audio guard, despite still writing plausible period and volume registers.
