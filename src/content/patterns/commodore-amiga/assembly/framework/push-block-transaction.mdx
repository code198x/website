## Use it in a project

CELL is the player’s separate index in a 4×4 row-major map and must point at tile zero. Tiles are 0 empty, 2 crate, and any other value blocking. REQUEST is 1 left, 2 right, 3 up or 4 down. Return RESULT=0 blocked, 1 walked or 2 pushed. Validate the complete push before changing either map cell; invalid player/request returns VALID=0 and no movement. A boundary-blocked move is a valid no-op.

Include `component.inc` once (MOS callers include the shared 6502 implementation through it). Reserve the public fields in this exact order: **CELL, RESULT, VALID, REQUEST, C0, C1, C2, C3, C4, C5, C6, C7, C8, C9, C10, C11, C12, C13, C14, C15**. They occupy 20 contiguous bytes. Also reserve the private workspace: **T0, T1, T2, T3, T4, T5, EXPR_SAVE** (7 bytes). Array names in the explanation refer to the numbered consecutive bindings, such as C0, C1 and so on.

Call `push_block_transaction_init` once at the intended reset boundary. It clears inputs as well as outputs and workspace. Set your starting state and configuration afterwards, then call `push_block_transaction_step` whenever the described event occurs. The helper reads no device, waits for no frame and installs no interrupt handler.

| Ownership | Fields |
|---|---|
| Retain between calls | CELL and C0..C15 |
| Supply before service | REQUEST |
| Read after service | CELL, map cells, RESULT and VALID |

Inspect the adjacent tile, then the tile beyond a crate. Both bounds and occupancy checks finish before the first write, so a failed push cannot leave half a move behind.

## Machine contract

D0–D3/A0–A1/CCR may change; D4–D7/A2–A6 are preserved. A direct BSR/JSR needs four return-address stack bytes. The helper makes no nested calls and adds no other stack use. Its named scratch is private workspace, not a pointer, a ROM variable or shared zero-page space that the game may borrow concurrently. The samples use fixed symbol bindings. Scope or rename every label and binding, including the component_end measurement marker, and allocate a separate block for each independent instance. Different helpers can also use common field names, so combining them needs separate namespaces or explicitly renamed bindings. Give each block one mutation owner.

The A500 OCS diagnostic cold-boots an OFS disk, owns the Copper and bitplane and disables interrupt/DMA sources. The helper does not take over hardware or allocate Chip RAM.

## Adapt the caller

`demo.asm` supplies the bindings and include order. `exercise.inc` first runs table cases, then a separate client retaining state between calls. A game can call the public step entry directly and remove the diagnostic packet and display. Do not copy the diagnostic's hardware takeover into an existing game loop.

Build with `make ASM198X=/path/to/asm198x` and `BUILD198X=/path/to/build198x`. The Makefile produces normal, custom, deliberately wrong and repaired programs. Tools must already be installed; the sample downloads nothing.

## Mistake and repair

The wrong caller writes a wall into the crate’s destination before service. The push correctly refuses the altered map, so the player appears stuck. Keep the authoritative map unchanged until the move is validated.

The BROKEN branch lives in the sequential client, not the reusable helper. `wrong.asm` selects it; `repaired.asm` restores the normal call sequence. The repaired executable matches the normal program (for Spectrum, compare loaded CODE rather than the tape filename).

## Cost and alternatives

The measured helper extent is 774 code bytes; public state is 20 bytes and private scratch is 7 bytes. There are no immutable helper tables. Caller data, the test cases, return-address stack, alignment and display buffers cost additional space. These are assembled sizes, not cycle measurements.

At most two neighbouring tile reads. Larger pushes need a complete validation pass before a commit pass, or an explicitly reversible journal.

Only one crate can be pushed. This is a deliberately bounded logical puzzle grid; animation, several linked crates, goals and undo use separate state. Reserve exclusive ownership while committing the two map writes.

## Execution evidence

Four variants run on A500 OCS PAL, Kickstart1.3 OFS cold boot, using Asm198x 0.0.72, Emu198x 0.44.2 and Build198x 0.2.9. Each executes 50 boundary/varied/error table cases, dirty initialisation and the separate retained-state client. An independent mathematical/container model checks every public byte after every call. This is bounded example coverage, not exhaustive correctness for every possible state.

The records retain loaded immutable code, completion, register sentinels, full packets, source/tool/firmware hashes and captures. The public gate validates these retained observations and rejects altered evidence; it does not run restricted firmware. No firmware is distributed. The eight displayed bytes are the first eight public fields, zero-padded when shorter; the packet includes every field.
