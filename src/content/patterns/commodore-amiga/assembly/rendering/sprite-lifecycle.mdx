## Include it and provide the buffers

Include `bob.inc` once. Each live object needs its previous rectangle address and a packed background buffer. The module allocates no save slots.

For all three calls, D0 is width in **16-bit words**, D1 is height, and D2 is the screen stride in **bytes**. Zero width or height does nothing. Otherwise width is 1–64, height 1–1024, and the even stride must be at least 2×width and at most 32766. Every accessed address must be even, in owned chip RAM and within its valid allocation; buffers must not overlap code, stack, sources or each other.

| Routine | Pointers |
| --- | --- |
| `bob_save` | A0=screen rectangle, A1=packed save buffer |
| `bob_restore` | A0=packed save buffer, A1=screen rectangle at its old position |
| `bob_draw` | A0=opaque mask, A1=image, A2=screen rectangle |

Packed source/save rows contain 2×width bytes. The mask uses 1 for the image and 0 for the background, unlike the Spectrum/BBC keep-mask convention. Images and masks are separate sources, not interleaved byte pairs.

D0, D3–D5, A5 and flags change; D1/D2/A0–A2 survive. **Reload D0 before the next operation** rather than chaining calls on its previous value. Each non-empty operation waits before programming the blitter and before returning. The caller enables DMA and excludes other blitter users; separate buffers do not make concurrent calls safe.

The copy path transfers A to D with minterm `$F0`. Drawing uses A=mask, B=image, C=old screen and D=screen with `$CA`. Modulos bridge packed rows and the screen stride. Software zero-size checks happen before encoding the blitter's maximum-size zero fields. See the *Amiga Hardware Reference Manual*, [chapter 6](https://www.theflatnet.de/pub/cbm/amiga/AmigaDevDocs/hard_6.html), for channels, modulos and size encoding.

## A complete two-object caller

`make` creates `build/demo.adf`. Boot it on the named A500 configuration. The caller owns the custom chips, copper list, bitplane and chip-RAM assets, uses the existing VERTB polling wait, and resets to leave. It is a takeover demo; integration with AmigaOS needs its blitter ownership protocol instead of this startup.

A and B are 32×16 objects. Main restores old B, then old A, changes A's position, saves/draws A, then saves/draws B. Every call reloads the geometry. Movement is in 16-pixel steps because this version is word aligned.

## What is qualified, and what comes next

Checks cover empty operations, ordinary rectangles, different strides, width 64 and height 1024 as separate small-memory cases, surrounding guards, packed saves and independent expected restoration. A two-object fixture compares the full composed and restored region and checks unchanged image/mask sources. Broken-mask and wrong-order variants must fail those same comparisons. The complete displayed caller progresses separately.

The normal screen example is one bitplane. A colour bob needs a save/draw/restore operation and saved background per changed plane; the silhouette mask can be shared. This is extra work and storage, not a colour flag you can turn on for free.

There is no clipping, arbitrary-X shift or asynchronous queue here. The existing [cookie-cut listing](/patterns/commodore-amiga/assembly/rendering/cookie-cut-blit/) explores shifting and remains illustrative. Saved backgrounds also become stale if scenery changes: remove objects before updating or scrolling their background, or redraw dirty tiles from world state. See the [shared lifecycle](/patterns/cross-platform/rendering/sprite-lifecycle/) before expanding the object count.

When an object can leave the screen, [clip its visible rectangle](/patterns/commodore-amiga/assembly/rendering/clipped-sprites/) before saving or drawing it. Keep its old clipped address and dimensions for the next restoration.
