## Put it in your project

Run `make` in the [source folder](https://github.com/code198x/code-samples/tree/21575697a26c624fc94ad0bb03eb818bcfe84d76/commodore-amiga/patterns/blitz/framework/object-pool). Insert `build/working.asc` into a blank **Blitz BASIC 2.10 / Ted 1.1** project, then compile and run with Amiga-X. Q closes the result window. Use a fresh blank project for each complete variant so labels do not collide. These are ASCII source imports, not compiled executables or native editor saves.

<CodeFromFile src="commodore-amiga/patterns/blitz/framework/object-pool/caller.bb2" lang="blitz" />

The builder joins settings, caller and helper routines. Keep dot-prefixed helper labels after the owner's `End`. Calls use `Gosub PL_OP_INIT`, `Gosub PL_OP_ACQUIRE` and `Gosub PL_OP_RELEASE`, without the label's dot. Reserve the `PL_OP_` names and occupancy array for one owner and one mutable pool. It is not reentrant.

The caller allocates `Dim PL_OP_LIVE.l(8)`: **nine long elements**, with slots 0..7 usable at maximum capacity eight and element 8 acting as an external guard. Allocate and retain that storage before calling the helper. It cannot detect a missing or undersized array. Payload and optional lifetime arrays belong to the owner and use matching indices.

## Initialise, acquire and release

<CodeFromFile src="commodore-amiga/patterns/blitz/framework/object-pool/routines.bb2" lang="blitz" />

| Long field | Contract |
| --- | --- |
| `PL_OP_CAP` | Init input: integer capacity 1..8 |
| `PL_OP_SIZE` | Private configured extent; zero disables |
| `PL_OP_SLOT` | Acquisition result or release input |
| `PL_OP_OK` | One on success, zero otherwise |
| `PL_OP_ERROR` | Zero valid/full, one invalid context/init, two invalid or already-free release |
| `PL_OP_I` | Private scan index |

The `.l` declarations make these signed longs. Occupancy is zero for free and nonzero for occupied; the helper writes zero or one. Valid init clears only the configured occupancy slots, preserving payload and lifetime data. Invalid init disables the context without writing occupancy, even after an earlier valid configuration. Changing capacity takes effect through another init; keep private size and scan state private.

Acquire selects the lowest free index and marks it occupied. **Check `PL_OP_OK` before subscripting an array.** Full returns slot equal to size, success zero and error zero. The bounded search completes its `For`/`Next` before returning.

To release, supply the slot and call Release. Context and both index bounds are checked before any subscript. Releasing an already-free slot is rejected. Payload is not erased. An active object keeps its index until release; after reuse, an old saved index can refer to a different object. Generation counters and stale-handle detection are outside this component.

## Let the owner decide when an object expires

<CodeFromFile src="commodore-amiga/patterns/blitz/framework/object-pool/age.bb2" lang="blitz" />

This separate owner starts four objects with lifetimes 1, 2, 1 and 3. Each pass visits occupied slots, reduces lifetime and releases expired objects. Only after the first complete traversal does it acquire slot 0 again with lifetime two. Spawning during traversal would let index order decide whether a new object ages immediately.

Native observations give live counts 3, 2, 0 and expiry counts 2, 1, 2. Every occupancy, lifetime and payload element remains observable, including unused elements and guards. One pass means your game's chosen unit, not automatically one second. Keep clocks, input, drawing and spawning outside the occupancy helper; the [loop choices](/patterns/cross-platform/framework/game-loop-choices/) explain where that ownership fits.

## Costs and native checks

Six scalar longs hold **24 bytes of numeric payload**. Nine occupancy elements add 36 bytes; the caller's optional payload and lifetime arrays each add 36 more. Compiled instructions, descriptors, runtime bookkeeping, call-stack use, editor, screen and window storage are additional and have not been isolated. These are not total-heap, executable-size, minimum-memory or peak-stack measurements. ASCII lengths measure source text.

The small owner opens a 420×180 Workbench window and reserves no bank. Normal Q exit restores default input/output and closes its window. This does not qualify arbitrary interruption or cleanup of another owner's resources. Diagnostic programs separately reserve bank 0 and free it on normal exit; coordinate that bank number with other code.

Three full mask runs each use a **380,936-byte diagnostic bank**: 768 records of 496 bytes plus two final long guards. Each record contains inputs, five complete snapshots of all six helper longs and every occupancy/payload element, then a row guard. Compact native loops generate masks without a large DATA table consuming the original compiler's object buffer.

Separate native bank-size observations confirm 5,344 bytes for 46 domain boundaries, 704 for six signed-minimum records and 464 for three lifetime passes. Those allocations belong to diagnostics. Headers are additional; completion gives no frame-time or throughput budget.

All twelve imports ran through original **Blitz BASIC 2.10 / Ted 1.1**, compiled using **Emu198x 0.44.1**, a PAL A1200 with 2 MiB chip RAM and no fast RAM. Six usable owners cover default, custom, single-slot, wrong and repaired behaviour. Full working/wrong/repaired diagnostics cover every byte occupancy mask at capacities one, four and eight, including init, acquire, release, repeated release and invalid release.

Boundaries include invalid capacities and contexts, invalid init followed by another call, and negative or oversized indices. The guest constructs -2147483648 by subtracting one from -2147483647. Full longs expose upper-bit corruption; payload 65537, unused flags and guard 99 expose writes outside helper ownership. These checks qualify the named software and workload, not another compiler, NTSC, original hardware or smaller machines.
