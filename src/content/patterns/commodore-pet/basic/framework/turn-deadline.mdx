Press Space: one turn. Wait: the world waits with you. Now press T and leave the keyboard alone. After 240 firmware ticks, the next turn arrives by itself. Your adventure might give a player time to escape a flooding room; your board game might put a limit on a move. The turn rule can stay the same while its timing changes.

## Try the complete caller

Run `make -C commodore-pet/patterns/basic/framework/turn-deadline` in code-samples. Enter the generated `build/demo.bas` as one numbered program, then type RUN. Space advances, T switches timing on or off, and Q ends the example. Use brief taps at first. The status shows the turn, expiry count and active flag; it is not a live countdown.

Use a **32 KiB 40-column upgrade-ROM PET**, with the default PAL timing and the recorded stock firmware. The optional diagnostic observer borrows **$033A–$034D (826–845)**, part of the inactive second-cassette buffer. The native arithmetic fixture borrows ninety-nine bytes from the same buffer; both fit its 192-byte allocation. **Do not perform tape I/O or share that buffer while using the observer.** It is outside the BASIC program/variable/string heap. Q leaves the screen and observer bytes behind. The reusable helper itself needs no fixed RAM reservation.

## Take the reusable helper

The helper does no input, drawing or turn advancement. It accepts two samples of a clock, subtracts the elapsed ticks and reports whether time ran out.

<CodeFromFile src="commodore-64/patterns/basic/framework/turn-deadline/routines.bas" lang="basic" title="Initialise, start and poll a deadline" />

Set `DU` to your duration and `DC` to the current clock, then call **3000 once**. This initialises disabled state and its previous sample. Call **3100** to start or restart: it copies duration into remaining time. Zero duration leaves it disabled.

Each service iteration, including while disabled, set `DC` and call **3200**. Read `DX` immediately afterwards: 1 means this poll expired. The helper disables that deadline and clamps remaining to zero; the next poll clears the event. Your caller decides whether to spend a turn or start another deadline.

| Global | Contract |
| --- | --- |
| DU | Caller duration: whole ticks, 0..5183999; 0 disables |
| DC | Caller current clock: whole ticks, 0..5183999 |
| DP | Helper-owned previous sample |
| DR | Helper-owned remaining ticks, saturated at zero |
| DA | Helper-owned active flag, 0 or 1 |
| DX | Helper-owned expiry event, 0 or 1 |
| DE | Helper-owned elapsed ticks from this poll |

These are BASIC globals. Rename them consistently to avoid collisions. Only the first two characters distinguish PET names. These ordinary numeric variables use five-byte floating-point values; all the whole numbers in the stated ranges are represented exactly. The helper reserves no fixed RAM, IRQ vector, hardware timer, array or string. It uses BASIC GOSUB/RETURN frames and is one mutable context, rather than a re-entrant service.

Starting preserves the most recent sampled baseline. Poll immediately before starting if that instant matters. Disable by setting `DA=0`. There is no preserved pause state: the demo clears remaining on disable and gives a fresh duration on re-enable.

## Read a clock without waiting for a command

<CodeFromFile src="commodore-64/patterns/basic/framework/turn-deadline/clock.bas" lang="basic" title="The machine-specific clock adapter" />

TI reads the firmware clock. In the released 40-column default PET, retained samples count one tick per roughly 50 Hz field: **240 ticks are about 4.8 seconds** here. The manual’s nominal sixtieth-second conversion is not the observed conversion for this named configuration. See the [assembly entry](/patterns/commodore-pet/assembly/framework/turn-deadline/) for the independent adapter and timing evidence. The firmware counter resets at **5,184,000 ticks**. Keep its normal interrupt service running. Tape I/O can interfere with timing and also conflicts with this observer’s buffer; assigning TI$ changes the shared clock. This adapter never resets it.

Poll before one whole clock cycle passes. 5,183,994 → 5 is eleven ticks; missing an entire extra cycle would give the same samples. A clock reset is not a rollover. Reinitialise your context after another owner changes the clock. This adapter never resets it.

`GET K$` reads without waiting for Return. It consumes characters delivered by firmware, including typeahead and repeat. A held key is not promised to count once. The [untimed command loop](/patterns/commodore-pet/basic/framework/command-loop/) can use blocking INPUT because its world is allowed to wait. Putting blocking INPUT into this caller would also stop deadline service. A clock does not make BASIC run two tasks at once.

The caller polls, reads one character, then handles expiry. **Expiry wins** if both arrive in the same iteration, discarding that character, including T or Q. Otherwise Space advances once and restarts an already active deadline. An untimed action stays untimed. An overdue deadline produces one turn; it does not replay every turn that might have happened during a delay.

## What does it cost?

The routine performs bounded work per poll; it does not loop once per elapsed tick. Interpretation, GOSUB lookup and your other work still determine how often you can service it. A native clock accumulates time while BASIC draws or calculates, but expiry is noticed only when you poll again. Restarting at observation time also introduces drift.

The native interpreter stored **191 bytes of tokenised helper lines**, including line headers. The complete instrumented program occupies **1,016 tokenised bytes**. Its observed scalar table occupies **133 bytes**, with **four string bytes** at the checked snapshot; the free BASIC gap is **30,590 bytes**. These are native pointers and allocations, not peak heap/stack measurements. The helper’s seven numeric globals occupy seven seven-byte variable entries, **49 bytes** including names and values.

The optional observer accounts for **274 tokenised bytes** inside that program plus its borrowed **20-byte buffer**. The recorded instrumented idle caller commonly samples intervals around **17–18 ticks**. That includes input and serialisation work; it is not the cost of the helper alone. The shorter-duration program has the same size; the deliberately wrong baseline adapter adds six tokenised bytes.

The optional 20-byte observer adds six scratch/monitor globals and several byte writes every iteration. Remove GOSUB 9000, its guards, MB/LC initialisation and `monitor.bas` when you do not need it. It is deliberately readable, rather than a fast game implementation. The caller redraws only on actions, toggles and expiry. No whole-game frame budget follows from these measurements.

## What was checked

**Code status: emulator-executed BASIC on the named configuration.** Six independent stock-firmware boots cover working, half-duration, wrong baseline, repair, boundaries and wrong equality. Source is typed through the real keyboard path. The observer checks coherent guarded state, idle/action, no-input expiry, active restart and disable; it also records the complete native tokenised program, line inventory, BASIC pointers and variable entries.

A second caller supplies twelve DATA cases to the same helper, including zero/one/maximum duration, exact and overdue expiry, an ordinary low-word crossing and the firmware clock modulus. Changing > to >= completes the fixture but fails the independent oracle. Those supplied samples qualify arithmetic, not a real-time wait across a whole rollover.

The retained checker independently decodes the visible native digits and rejects **28 falsified records** across PET and VIC-20.
