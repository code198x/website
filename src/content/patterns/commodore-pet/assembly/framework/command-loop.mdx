Press **A**. **TURN 0** becomes **TURN 1**. Do it again for **TURN 2**. Walk away for a cup of tea and the world waits for you. That is a useful game loop for an adventure, a board game or any other untimed decision.

**X** leaves the count alone. **Q** returns to BASIC. The counter stands in for the world update: spend a move, change a room or let the opponents respond only when the command earns it.

## Start the complete caller

This entry uses a **40-column PET with the pinned BASIC, editor and KERNAL ROMs**. Keep its normal firmware running: the keyboard reader depends on the firmware interrupt service and default keyboard channel. These are delivered characters, rather than a test for one fresh physical press.

Keep `demo.asm`, `caller.inc`, `routines.inc` and `presentation.inc` together. With Asm198x available:

```sh
make -C commodore-pet/patterns/assembly/framework/command-loop ASM198X=/path/to/asm198x
```

The output is `build/demo.prg`, loaded at **$0401**. `RUN` executes its `SYS 1040` stub. The verified emulator route imports the PRG through its program slot and lets the ROM execute RUN/SYS. That proves the imported program's execution, not a tape or disk transfer.

`GETIN` at `$FFE4` returns a queued character in A, or zero when none is available. The zero case goes back to reading without updating the world. `Q` returns through the original SYS call stack. Do not reset the stack or replace the firmware IRQ as if this were a standalone cartridge.

## Reuse the command update

Include `routines.inc` in your own program. Clear decimal mode with `CLD`, initialise the two state bytes once, place the command's PETSCII value in A and `JSR apply_command`.

<CodeFromFile src="commodore-pet/patterns/assembly/framework/command-loop/routines.inc" lang="6502" title="Byte state and a rule with no I/O" />

| Resource | Contract |
| --- | --- |
| A on entry | PETSCII command; `$41` is A |
| `turn_count` | Persistent byte, updated modulo 256 for A |
| `turn_step` | Byte amount to add; preserved |
| `turn_accepted` | Replaced: 1 for A, 0 otherwise |
| Registers | X/Y preserved; A and flags changed; D must be clear |

The routine uses three state bytes and the normal hardware stack, with no zero-page scratch. `CLC` supplies the starting carry for `ADC`; byte arithmetic discards overflow past 255. The `CLD` in the caller matters because decimal-mode arithmetic would change that meaning.

The labelled bytes move with your code. Keep their allocation and contents intact between calls. The complete PRG occupies BASIC program RAM; reserve that loaded range if you combine it with BASIC, and relocate it deliberately when combining assembly modules.

## Keep presentation separate

`presentation.inc` clears the screen and prints three decimal digits. It uses firmware `CHROUT` at `$FFD2`, two scratch bytes, A/X/Y and flags. It assumes the default screen output channel. Its repeated-subtraction conversion is easy to follow and bounded by the byte-sized count; a larger score needs a different conversion.

<CodeFromFile src="commodore-pet/patterns/assembly/framework/command-loop/presentation.inc" lang="6502" title="Caller-owned screen output, separate from the rule" />

This is why the same rule can serve two different interfaces. You can retain `apply_command` while replacing the screen clear with a status-field update. Firmware keyboard scanning, screen workspace and stack use still belong to the firmware. A takeover loop that disables IRQs or hides ROM cannot keep this reader unchanged.

## Common mistake: resetting persistent state

**The following caller is deliberately broken.** It saves the incoming command, clears the count, restores the command and then calls the rule.

<CodeFromFile src="commodore-pet/patterns/assembly/framework/command-loop/mistakes/reset-each-command.inc" lang="6502" title="Broken: erase the count before interpreting every command" />
<Figure src="/images/commodore-pet/patterns/assembly-command-loop/reset-mistake.png" alt="PET faulty assembly caller showing TURN 001 after its second A." caption="The rule works with the state it receives. The caller erased the previous result." />

A, X, A produces **001 → 000 → 001**. The smallest repair is to remove that reset from the loop and restore the original caller; its startup initialisation remains. The repaired path is checked separately. Forgetting `CLD` or replacing firmware services would be different faults; these captures demonstrate the reset mistake only.

## When the world cannot wait

This caller consumes CPU while polling the firmware buffer. Neither approach supplies a turn deadline. The machine's clocks continue, but the rule state waits. For a countdown, animated cursor or sound service that needs regular calls, retain the rule and replace the waiting policy. Decide what happens if a valid command and an expired deadline arrive together.

The [loop comparison](/patterns/cross-platform/framework/game-loop-choices/) separates progression, time, input and presentation. These choices can be combined; they are not a compulsory ladder from BASIC to assembly.

The [PET basic caller](/patterns/commodore-pet/basic/framework/command-loop/) implements the same small rule with its own language contract. Assembly owns its bytes and calls the firmware directly.

## Take the source and evidence

**Code status: native-emulator executed**, using Emu198x **0.44.1** and the named configuration above. The assembly build uses Asm198x **0.0.71** and the PRG/ROM launch route described above. No host write supplies the counter state.

The [source folder](https://github.com/code198x/code-samples/tree/1438dfea461624ed7aafc472de236ff1c954774f/commodore-pet/patterns/assembly/framework/command-loop) keeps the caller, routine, customisation, deliberately broken caller and [native record](https://github.com/code198x/code-samples/blob/1438dfea461624ed7aafc472de236ff1c954774f/commodore-pet/patterns/assembly/framework/command-loop/verification/reusable/results.json) together. The source, ROM hashes and released tool identities are bound in that record.

Six separately started variants cover normal use, step three, the reset fault and repair, byte wraparound and a nonzero start with step 255. Each waits 120 native fields before and after an action, submits X and two As, checks the visible counter and returns to BASIC with Q. The retained checker decodes screen RAM and compares it with independent arithmetic; altered counts, blank screens, absent observations and changed image hashes must fail. The figures are actual framebuffer captures.

These checks establish this small workload. They do not qualify original hardware, every firmware/display variant, a full parser, or the whole emulator.
