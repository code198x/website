## Include it and make a call

Reserve **48 zero-page bytes at BP**; the caller uses $70. Define `PIXEL_WIDTH=228` and `PIXEL_HEIGHT=200` and include `oric.inc` once. Keep the complete caller's `bitmap_lo/hi` tables too. Code, tables, stack, bitmap and BP must not alias. Scratch needs no initialisation; public inputs do.

After video setup, this is a normal direct call. Your game does not need the diagnostic mailbox that follows it.

Read BP+9 for acceptance. Call again with another request; no drawing list or hidden game loop is retained.

## The calling contract

Words are unsigned little-endian. Origin is top left, Y downwards. Call `bp_pixel`, `bp_read`, `bp_hspan`, `bp_vspan`, `bp_fill` or `bp_box`.

| BP offset | Supply or read |
| --- | --- |
| 0,2 | x0,y0 words |
| 4,6 | Exclusive x1,y1 words |
| 8 | 0 set, 1 clear, 2 XOR; read requires 0 |
| 9 | Output: accepted 1, rejected 0 |
| 10 | Output: stored bit for read; otherwise 0 |
| 11 | Ignored and preserved |
| 12–39,42–47 | Private scratch |
| 40 | Output word: destination-byte writes |

Pixel/read ignore both ends; hspan ignores y1; vspan ignores x1. Fill and box use [x0,x1)×[y0,y1). A box [5,13)×[20,24) is eight pixels wide and four high. The entire effective rectangle must be nonempty, ordered and within 228×200. Bad requests reject before destination writes, with zero read/write outputs. Public inputs 0–8 and 11 survive. This is strict rejection, not clipping; intersect with the display first when partial shapes are wanted.

Spans mask their edges and write full interior bytes. Outlines visit corners once, including a 1×1 box, so XOR does not erase a shared corner. Reading does not change memory.

## Six pixels per byte, with room for control codes

HIRES is 240×200, but the first two bytes of every forty-byte row carry paper-black 16 and ink-white 7. Keep those attributes out of your drawing allocation. The routine therefore exposes **228×200** logical pixels; logical x=0 starts at physical x=12.

`address = $A002 + 40*y + (x div 6)`; `mask = 32 >> (x mod 6)`. At logical (13,20), that is **$A324**, mask **$10**. Six data bits hold the picture, bit 7 inverts its ink/paper presentation, and the component requires bit 6 set throughout the selected rectangle.

That last rule is a safe allocation policy, not a complete description of the ULA decoder. Effective byte values $20–$3F can carry pixel patterns even with bit 6 clear. This routine rejects them too: clearing/XORing such a byte could create a serial attribute ($00–$1F). Initialise drawable bytes to $40, or $C0 for inverse cells, and leave the two attribute columns alone.

Before any write, preflight checks every byte in the request's bounding rectangle, even the interior of an outline. A bad byte on a later row cannot leave a partial box behind. The extra reads buy that guarantee. Set/clear/XOR preserve bits 6 and 7. Clear means zero stored pixels: inside an inverse cell those bits appear as ink, so “clear” does not universally mean black. Read returns the stored bit.

The caller owns HIRES memory $A000–$BF3F, its serial-attribute policy and the 50 Hz HIRES mode code $1E at $BFDF. A mixed attribute/text renderer needs a different explicit ownership policy.


## The maths under the call

Division chooses a byte; remainder chooses a bit. Six pixels share that byte, so a point must preserve the other five. OR sets the mask, AND with its inverse clears it, and XOR toggles it. Writing only the mask over the old byte would erase neighbours.

[Place a point](/craft/maths-for-games/unit-06/) connects the coordinates to position; [Draw with integer error](/craft/maths-for-games/unit-12/) explains how pixels and spans build larger shapes. The current clipped geometry adapters have their own qualified backends; adding these primitive entries does not silently qualify geometry or text on these machines.

## Resources and proof

The backend is **547 assembled bytes**, plus 400 bytes of CPU row tables and 48 zero-page context bytes. Reset setup, bitmap and stack are additional. The reserved attribute columns are within the 8,000-byte HIRES bitmap. Full-byte spans save repeated per-pixel addressing. Preflight also costs reads across the whole bounding rectangle. These are storage/write counts, not cycles or a frame-budget promise.

Clobbers A/X/Y/P; clears decimal mode. Reserve a conservative 64-byte stack budget beyond your own calls/interrupts. BP is non-re-entrant; the routine does not change interrupt enables, arrange OS ownership or synchronise display access.

**143 calls completed** with Asm198x 0.0.71 and native Emu198x 0.39.0. Each compares full bitmap, guards, public inputs, acceptance, read and write counts against an independent selected-pixel model. Inverse cells, control codes and noncanonical $20 rejection are included. Selected whole native frames match independently composed pixels. Two faulty builds completed accepted draws and failed both memory and picture checks. Real-hardware timing, stock firmware loading and live-rendering coexistence remain separate checks.
