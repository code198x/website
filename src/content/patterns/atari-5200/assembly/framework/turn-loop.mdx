Press fire and the background changes colour. Keep holding it: nothing more happens. Release and press again, and the first colour returns. The game has accepted two actions, while the display has kept running throughout.

That small difference is worth getting right. A player waiting for their next move should not accidentally stop the picture, and a held button should not become hundreds of moves.

## Build and try it

```sh
make -C atari-5200/patterns/assembly/framework/turn-loop
```

Start `build/demo.bin` in Emu198x for Atari 5200. The qualified configuration is **NTSC 32 KiB cartridge handed over by the identified 5200 BIOS**. Reset to leave. The caller is a deliberately small backdrop demonstration, not a complete display engine.

## Include and initialise the reusable state

Copy `turn.inc` and its neighbouring `edge-filter.inc` together, and include the routine once after your main code. Define `T` as seven private, consecutive RAM bytes. The caller uses **$1000–$1006**; choose another valid allocation if your game owns that memory already.

Call `init_turn` with the starting progress counter in A. It clears the previous/current samples, accepted flag and 16-bit service count, and sets the step to 1. Change `T+5` after initialisation when you want another step. These routines require **decimal mode clear**; the complete reset caller uses `CLD`.

<CodeFromFile src="cross-platform/patterns/framework/atari-turn-loops/turn.inc" lang="6502" title="Rule progression and display service are separate routines" />

<CodeFromFile src="cross-platform/patterns/framework/atari-turn-loops/edge-filter.inc" lang="6502" title="Keep only bits that became pressed since the last sample" />

| Entry or state | Contract |
| --- | --- |
| `init_turn` | A is the initial 8-bit counter; initialises all seven bytes |
| `sample_turn` | A is the active-high button mask; accepts newly pressed bits |
| `T+0` | Progress counter, increased by `T+5` on acceptance; wraps modulo 256 |
| `T+1`, `T+4` | Previous/current samples; keep the same bit convention each call |
| `T+2`, `T+3` | Little-endian 16-bit service count, independent of turns |
| `T+5`, `T+6` | Step size and the current call’s accepted flag (1 or 0) |
| `service_tick` | Increment the service count once per accepted display field |

The init/sample routines change A and flags; `service_tick` changes flags. All preserve X/Y. A direct `JSR` needs two stack bytes, plus your surrounding caller and interrupt depth. The routines have no nested calls, hardware access, frame wait, private stack or interrupt masking. Their shared context is not re-entrant.

Use one primary-button bit as the caller does. With a multi-bit mask, any newly pressed bit commits one update, even if another bit remains held; this routine does not queue separate actions for each button. A zero step can still report an accepted action without changing progress. Neither helper decides your game rules or imposes a deadline.

## Fit it into the machine’s caller

`sample_turn` reports acceptance only for that call. Read `T+6` before another sample replaces it, then let your own rules respond. `service_tick` does not change that flag. The two counters have different meanings: one counts accepted progress, the other counts serviced fields.

The guards immediately outside the seven-byte allocation are diagnostic caller state, not part of the reusable routine. The reset caller takes over the stack and display interfaces. Keep its ownership separate from other routines that scan input, alter interrupt enables or own the same video registers.

## Let ANTIC keep time

This machine does not need a TIA-style program that emits every scanline. ANTIC supplies a running vertical counter. The caller disables display-list DMA for a background-only picture and uses a small polling wait to accept one field boundary.

<CodeFromFile src="atari-5200/patterns/assembly/framework/turn-loop/frame.inc" lang="6502" title="Wait out the current high interval, then accept the next one" />

**VCOUNT at `$D40B` counts in two-line units.** This NTSC wait first leaves any interval with bit 7 set, then waits for the next one. A call made while that bit is already high cannot immediately count the same interval twice. This is a useful field announcement, not a general-purpose clock that remembers missed fields.

The primary trigger is **GTIA TRIG0 bit 0 at `$C010`**. The caller converts its active-low state before `sample_turn`. That is a different address and bit from the 2600’s fire input. It does not read the analogue stick, keypad, Start or second fire button.

The BIOS hands control to the cartridge’s vector at `$BFFE`. The caller then disables ANTIC NMI and display-list DMA; IRQ remains disabled. It owns that takeover. A BIOS service or your own interrupt-driven display needs a separately agreed arrangement. Background colour is written to GTIA COLBK at `$C01A`.

The measured service count advances **30 times in 30 native frames**. Long work can miss a counter interval; it does not produce an unlimited backlog. Add an ANTIC display list through its own setup and ownership contract when a game needs more than this backdrop.

## Common mistake: held means new

**The next fragment is deliberately broken.** It replaces `edge-filter.inc` and treats every held sample as another press.

In the native run, holding fire for a further 30 frames changes the faulty counter again. The working counter remains at **1**. Its picture may alternate too quickly for a still to explain the error: the measured state transition is the evidence. Restore the previous-sample filter above. Keep the update of `T+1` on every call, including releases, so another press can be recognised.

## Common mistake: a plausible picture, the wrong clock

Replacing the field wait with `RTS` makes the service counter a count of CPU iterations, even though its name still says “fields”. The background may look unchanged.

The native observation is **8,090 service ticks in 30 frames**, against **30** for the working wait. The counter is 16-bit and wraps; this measured interval is not a universal maximum speed. Restore `frame.inc` above and the original rate check passes again.
