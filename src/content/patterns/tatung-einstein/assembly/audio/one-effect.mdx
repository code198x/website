## Take the effect

<CodeFromFile src="tatung-einstein/patterns/assembly/input/read-action/sound.inc" lang="z80" title="The reusable effect" />

AY channel A, duration $8005. The routine sets mixer $7E, preserving the required port-A-output/port-B-input configuration. Trigger preserves AF/B; service changes AF. Both keyboard and sound share the AY address latch.

Include sound.inc once with the caller’s constants and duration byte. Initialise the duration byte to zero before the first service call. Call trigger_sound for an accepted action, then call service_sound exactly once per accepted display update. The eighth service call mutes the effect. Because the supplied caller services in the triggering iteration too, this is a count of service calls, not eight complete elapsed frame intervals. Triggering again restarts the duration; there is no queue.

The complete initialiser also mutes other channels. To reuse just this effect beside music, agree channel ownership and remove unrelated global setup only after providing a replacement. Device latches, power, routing and master volume may affect more than one voice.

## Change it and recognise a mistake

Change tone A’s period/volume without changing keyboard port directions. A shared audio driver must coordinate with keyboard scanning.

The omitted-trigger control still accepts the action but fails the same audio guard as the working caller. Keyboard clicks or other machine output are not enough: the BASIC checks compare against a separate rejected-command recording.

The working implementation above repairs that omission. If an effect instead drones on, check the mute/service path and that its state is initialised. Servicing twice makes a counted effect shorter; servicing only after input can leave it running while the player waits. Those are lifecycle decisions to test when adapting it.

## Run the caller

Build the complete caller with `make -C tatung-einstein/patterns/assembly/input/read-action`. Press **Space** once, keep it held, then release and press again. The piece moves on each new press and returns to its starting position after two; holding does not repeat the action. Attach `build/demo.dsk` and use Control-BREAK to let MOS boot it. This is a disk-boot program, not a CP/M or BASIC loader.

## Verification and sources

Target: **TC-01 PAL, MOS 1.2, Ctrl-BREAK disk boot**. These callers were executed with released Emu198x **0.44.1**; assembly uses Asm198x **0.0.71**. The [sample folder](https://github.com/code198x/code-samples/tree/d385b67e471a8d9e8b6c452c9e090fa22576adaf/tatung-einstein/patterns/assembly/input/read-action) contains reproduction instructions and [retained observations](https://github.com/code198x/code-samples/blob/d385b67e471a8d9e8b6c452c9e090fa22576adaf/tatung-einstein/patterns/assembly/input/read-action/verification/results.json). The independent checker binds source, native captures and actual output; its rejection tests exercise wrong state, missing files and false audio claims.

This qualifies the named emulator/firmware path. Pitch accuracy, original hardware and other peripherals require their own observations.
