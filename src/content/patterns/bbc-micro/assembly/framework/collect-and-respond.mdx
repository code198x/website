Move onto the star. The count changes from **0 to 1**, and you hear a short sound. Stay there: the star has gone, so it cannot score again. Press restart and it returns.

Those few seconds bring several useful routines together. Here is the BBC Micro version, with each part kept small enough to lift into a project of your own.

## Run it first

Target: **BBC Model B, MOS 1.20 and BASIC II**. Controls: **Q/A/O/P; Space restarts**. Reset the machine to leave.

With Asm198x available, keep the code-sample folders together and build:

```sh
make -C bbc-micro/patterns/assembly/framework/collect-and-respond
```

Type the generated `build/loader.bas` listing into BASIC, then `RUN`. The [sample folder](https://github.com/code198x/code-samples/tree/e8e445b7d51e7292edb1a8503db467f032a1fee1/bbc-micro/patterns/assembly/framework/collect-and-respond) contains the complete program, build recipe and integration notes. The [comparison](/patterns/cross-platform/framework/collect-and-respond/) explains the choices across all five versions.

The player moves one cell per six accepted updates. Hold a direction to keep moving. Restart reacts to a **new press**, so holding it will not trap the player at the starting position.

This program owns the MODE 6 screen, program memory from $3000 and MOS SOUND channel 1. The loader lowers HIMEM before writing program bytes; MOS keeps its IRQ services. The routines together change A/X/Y and flags. Keep competing writers out of those resources; adding a music player or IRQ handler requires an explicit agreement about who writes what.

## Move, test and consume

The playfield is **16 × 10 cells**. The player begins at (2,5); the star occupies (10,5). The rules keep X between 0 and 15 and Y between 0 and 9. Diagonals move on both axes. Opposing directions are processed left/right, then up/down; choose cancellation or last-direction priority if that better suits your game.

`previous`, `pressed` and `released` belong to input sampling. `player_x/player_y`, `move_delay`, `item_active` and `score` belong to the rules. Reset preserves input history: clearing it while a button is held would invent another press.

The collision uses half-open boxes. A cell at (x,y) has edges (x,y,x+1,y+1), so merely touching the star's edge leaves it alone. The routine can also compare larger rectangles or pixel coordinates, provided both boxes use the same units and edge arithmetic does not wrap.

## Show the new state

This version uses MOS cursor positioning and text characters. `old_x/old_y` remember which cell to erase. The item is drawn before the player, so the player wins the draw order when they overlap.

<CodeFromFile src="bbc-micro/patterns/assembly/framework/collect-and-respond/draw.inc" lang="6502" title="Draw, erase and show the count" />

Painting a blank over the old position works because the background is empty. With a map behind the player, restore its tile. With overlapping objects, redraw the affected scene or choose another renderer. Keep that decision in the drawing routine so the rules can stay useful.

## Take it into your game

Copy the routine you need, its state and its maintained includes. Read the declaration and caller together: the caller shows initialisation, call frequency and ownership. The sample README lists register effects and resource limits. Preserve the relative include layout, or update those paths deliberately when moving files.

These examples use whole-cell movement and a frame-based repeat counter. Fractional motion, scrolling, multiple items and sound priorities are useful next steps when a game needs them. A 50 Hz and a 60 Hz machine give this counter different wall-clock speeds.

**Code status: assembled and emulator-executed for the named configuration.** Checks drive real input, exercise all four bounds, reject edge-only contact, collect once, restart while held and capture the picture and PCM.
