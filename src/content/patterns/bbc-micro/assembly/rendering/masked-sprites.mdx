An object moves across a patterned strip without leaving its previous image behind. There is no sprite engine doing that job: the CPU saves the eight background bytes, combines the image with them, and restores them before moving.

## The useful small case

MODE4 is a 320×256 two-colour bitmap at `&5800–&7FFF`. Its eight scanlines within one character cell are consecutive bytes. This routine draws one 8×8 object at a byte-aligned character-cell position; it does not pretend that arbitrary pixel positions have the same addressing.

Include `masked.inc` once. Set `screen_ptr` (`&70/&71`) to a complete cell in that bitmap, and `pairs_ptr` (`&72/&73`) to 16 readable mask/image bytes. Keep source data separate from the destination, saved state and stack. Clear decimal mode. A/Y/flags change; X survives. IRQ code must preserve the owned zero-page and working registers.

```asm
    ; Set screen_ptr and pairs_ptr first.
    jsr save_background
    jsr draw_masked_cell
    ; Before moving the object:
    jsr restore_background
    ; Set the NEW screen_ptr, save it, and draw there.
```

A mask bit of one preserves background. A mask bit of zero clears that position before the image is ORed into it. Image bits must be zero wherever the mask preserves scenery. The component owns one saved address, eight saved bytes and two scratch bytes; one save slot means one live saved object.

`restore_background` also restores the saved address into `screen_ptr`. Choose the next address after restoring, rather than accidentally restoring at the new position.

## Build and run the example

`make` creates `build/loader.bas`. Load or type it into BBC BASIC and `RUN`. It selects MODE4, reserves `HIMEM=&3000`, installs the original machine code and moves the object one cell per eight vertical syncs. MOS IRQ remains active; OSBYTE19 provides the sync. Reset to leave.

## Grow it without losing the background

The checks draw and restore at five cell addresses, including the bitmap's first and last cells. They compare the rendered and restored bytes independently, check that the source survives and reject a broken mask operation. The running caller is checked separately; this is not an original-hardware or frame-budget certification.

For several saved objects, restore them in reverse drawing order before saving and drawing the next frame. If scenery changed, old saved pixels can undo that change; redraw affected tiles from the world instead. The [shared sprite guide](/patterns/cross-platform/rendering/sprites/) explains the choice.

Further versions can add larger rectangles, clipping, pre-shifted images and arbitrary Y positions. CRTC start-address scrolling also changes how logical positions map into physical screen RAM, including wrap. This primitive requires the ordinary MODE4 mapping; a scrolling renderer must supply its own correct mapping.

The source manual is the *BBC Microcomputer Advanced User Guide*, the chapter on the screen display and its MODE4 memory organisation. The routine itself uses no MOS drawing calls; the demo uses MOS only for synchronisation.
