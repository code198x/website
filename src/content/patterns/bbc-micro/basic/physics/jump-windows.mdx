Press Jump just before landing and it feels poor when the press disappears. Leave a ledge a fraction before pressing and a little forgiveness may still feel fair. These two windows let a game make those choices without turning its input reader into a movement system.

## Include and initialise

Reserve public J/C/B/G/P/W/X/O. There are no arrays or private scratch fields. Reserve lines **3000–3230**, combine routines.bas and a caller with build.py and keep END, STOP or a jump before the helper. C64/BBC use GOSUB; Spectrum uses GO SUB.

Call **3000** at a session/reset boundary. It clears every public field, including configuration. Set coyote reload W and buffer reload X afterwards, each from one through 255 service calls. The normal caller uses four for both, the custom caller two.

## Supply ground state and a new press

G is grounded state; P must mean a **new press**, not the held button level. Use 0/1 for flags. Any nonzero byte is treated as true; if a dialect's comparison returns −1, ABS can normalise that numeric result to 1. Normalising a held level does not turn it into a new-press edge.

Call **3100** once per simulation update. It first decrements positive C/B, then reloads C from W while grounded and B from X on a new press. If both are now positive, J=1 grants one jump and consumes both timers. Otherwise J=0. O=1 reports valid input; G/P/W/X survive.

| Field | Use |
|---|---|
| C / B | Retained coyote / buffered-press counters |
| G / P | Grounded state / new-press byte |
| W / X | Positive reload values |
| J / O | Fresh jump pulse / valid-input flag |

C/B and inputs must be integral bytes, with positive W/X. Invalid input clears J/O and preserves both timers and request/configuration fields. A timer of one expires at the **start** of this call unless the corresponding current input reloads it. A one-call window therefore does not promise an extra future update of forgiveness.

## Observe pulses, not just the final row

The maintained caller runs three short traces: one press while continually grounded, a press three calls before landing, and a press after leaving a ledge. Four-call windows preserve the two forgiving opportunities; two-call windows have expired in those traces. Both configurations accept the fresh grounded press once.

Line 2000, AA/BB/NN/SS/JJ (Z on Spectrum) and the mailbox are diagnostics. Their counts record earlier pulses that a final J=0 would not reveal. The first trace deliberately keeps G true to isolate the new-press contract. A real game applies the jump and updates movement/grounded state when J grants it.

## Customise forgiveness

Choose W/X in simulation calls, not seconds. Physical duration depends on the caller's update rate. Changing reload values does not retroactively resize an already retained timer; reset or adjust that state deliberately if the design needs it.

A double jump, variable held-jump height, release-cut velocity and wall jumps need extra state or distinct policies. Keep those choices separate from a forgiving first jump. The input reader still supplies edges; the collision/movement code still supplies G and applies the result.

## Mistake and repair

The wrong caller supplies P=1 on every call as though a held button were a new press. Permission is repeatedly granted on grounded updates and the saved pulse counts fail. Retain timers and feed a genuine press edge; also update the caller's movement state when accepting a grant. The repair matches normal source and loaded program exactly.

## Cost and Maths for Games

Each call performs fixed validation, two bounded decrements, possible reloads and one grant decision. There is no clock read, input polling or allocation. BASIC numeric variables are not eight packed native bytes, and no frame-time budget is claimed.

## Global names and line numbers

BASIC numeric names, arrays and numbered lines are global. To combine helpers, rename public and private fields and renumber the helper together with every GO SUB/GO TO reference. Keep each state block under one owner. The maintained build.py rejects duplicate line numbers; it does not automatically namespace or renumber routines.

## Machine and measured size

This helper uses scalar numeric fields and allocates no arrays. Its diagnostic uses MODE 7 and HIMEM=&6000 to separate program storage, mailbox and screen. The helper itself changes neither mode nor HIMEM.

The numbered helper occupies **409 tokenised program bytes** on this interpreter, including line headers. This excludes the caller, test tables, numeric scalar/array storage, interpreter stacks and ROM. Tokenised size is not machine-code size or a hardware-cycle count. No real-time or whole-game performance budget is inferred from the diagnostic. The caller’s AA/BB/NN/SS, JJ and RAM mailbox are observation machinery, not required game state.

## Execution evidence

Working, custom, deliberately wrong and exact repaired callers executed through BBC Micro's stock BASIC interpreter under Emu198x 0.44.2. Build198x 0.2.9 tokenises C64 PRG and Spectrum TAP programs. C64 enters stock RUN, Spectrum uses ROM tape loading, and BBC enters every numbered source line through MOS/BASIC. Actual loaded program bytes, complete state packets, positive completion/count/guards and visible result pixels are checked. After the positive completion marker, the observer advances two complete display frames before capturing, so a partially scanned final character cannot masquerade as a finished picture. Firmware is not distributed.

An independent mathematical/order model checks the trace and rejects altered source, configuration, loaded program, state, completion and image evidence. Host exhaustive checks complement the native boundary/sequential examples; those host ranges are not claimed as natively exhaustive. The supplied diagnostic callers deliberately end with STOP; the interpreter report is expected. The wrong caller prints 0,0 and the normal/custom/repaired callers print 1,1.
