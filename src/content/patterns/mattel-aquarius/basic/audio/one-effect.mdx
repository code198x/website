## Take the effect

<CodeFromFile src="mattel-aquarius/patterns/basic/input/read-command/sound.bas" lang="basic" title="The reusable effect" />

The caller creates all its scalar variables before DIM Z(16), locates that array storage and installs a 22-byte Z80 helper plus USR vector. GOSUB 2000 calls it. It toggles output port $FC with a CPU delay and returns, preserving AF/BC. The routine blocks and uses W/J/B/X plus the Z array and USR vector.

Copy the 2000-range subroutine and call GOSUB 2000 when the game accepts an action. Keep its global scratch variables and any DATA/setup lines with it. A sound call is a consequence of an action, not a substitute for input validation.

## Change it and recognise a mistake

Keep the array/vector setup with the sound routine. Adding variables or changing array layout can move its storage; do not reuse a stale pointer. A ROM-independent allocator/driver would need a different storage contract.

The omitted-trigger control still accepts the action but fails the same audio guard as the working caller. Keyboard clicks or other machine output are not enough: the BASIC checks compare against a separate rejected-command recording.

<CodeFromFile src="mattel-aquarius/patterns/basic/input/read-command/mistakes/no-sound.bas" lang="basic" title="Deliberately omitted sound trigger" />

The working implementation above repairs that omission. If an effect instead drones on, check the mute/service path and that its state is initialised. Servicing twice makes a counted effect shorter; servicing only after input can leave it running while the player waits. Those are lifecycle decisions to test when adapting it.

## Run the caller

Enter the complete `demo.bas` in Mattel Aquarius BASIC and RUN. Submit **GO**, then Return. One accepted command advances the displayed turn; another gives two.

Target: **stock Aquarius BASIC with an array-backed USR sound helper**. These callers were executed with released Emu198x **0.44.1**; assembly uses Asm198x **0.0.71**.
