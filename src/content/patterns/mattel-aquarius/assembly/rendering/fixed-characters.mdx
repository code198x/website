## Include, set up, call

Copy `characters.inc` into your project and include it once. Reserve **24 private bytes** at `FC`. The selected display layout is fixed in this machine-specific include. The first maintained call places a six-character span; the full caller below shows allocations and inclusion:

Put a source pointer at `FC+0..1` (low byte first), column at +2, row at +3 and nonzero count at +4. Set the foreground/background byte at +7 too. Call `character_span`. Byte +5 returns 1 when accepted, 0 when rejected; +6 returns the number of character writes, or 0. Inputs +0..4 and +7 survive. Scratch/status +5..23 belong to the routine.

A request stays on one row. Zero counts, invalid starts and horizontal overruns reject before any display write. A start at (0,0) also rejects to protect the surround. This variant rejects rather than clips: shorten a label deliberately if that is the behaviour you want.

Keep the source long enough, readable, stable, non-wrapping and separate from anything the call can overwrite. Contexts are not re-entrant. AF/BC/DE/HL and flags are clobbered; IX/IY survive. Reserve two stack bytes for the direct call and its helpers, plus your caller and interrupts.  The routine changes no interrupt state or display mode.

## Use the actual display

Aquarius stores character names at $3000–$33E7 and matching colours at $3400–$37E7. Cell (2,3) has index 122, so its addresses are `$307A` and `$347A`. Each plane has an unchanged 24-byte tail.

Attribute `$1F` means red foreground on white background: high nibble is foreground, low nibble background. A six-character label writes six names and six colours. The fixed ROM supplies the pictures; this is not character RAM.

Cell zero repeats into the surround. This routine rejects requests starting at (0,0), keeping a label from repainting the border. A game can deliberately own that cell outside the routine. BASIC normally uses rows 1–24; the reset driver owns all 25 rows and both planes.

Caller ownership matters: the OS cursor, scrolling code and an interrupt cannot independently redraw these allocations without coordination. Keep gameplay tiles as logical IDs and translate them into screen codes only when drawing.

For a room rectangle, reuse the existing [native region renderer](/patterns/mattel-aquarius/assembly/rendering/tile-region/). This smaller span is useful for labels or a changed row. It does not upload a font or turn a character cell into arbitrary pixels.

## Connect cells, shapes and maths

At an 8×8 character grid, cell (2,3) begins at active pixel (16,24). That multiplication places a whole glyph; it does not let you change one of its dots. Border coordinates are a separate matter.

Block characters can supply a coarser drawing grid. With a genuine 2×2 block repertoire, coarse point (5,7) belongs to cell (2,3), quadrant (1,1): divide by two for the cell and take the remainders for the quadrant. You still need a lookup from the desired block mask to this ROM's actual codes. This routine accepts those codes; it does not invent a universal semigraphics table.

[Place a point](/craft/maths-for-games/unit-06/) develops local/grid coordinates. [Move a glyph](/craft/maths-for-games/unit-13/) connects codes and stored shapes. A fixed font makes the distinction especially clear: a code can select a picture without giving the CPU writable picture memory. Use larger cell pictures or an approximation when the ROM lacks the shape; a high-resolution extension needs its own named configuration.

## Pay for the work

The component is **103 code bytes**, excluding caller and source, with 24 reserved context bytes. A six-character label needs six source bytes and **twelve destination writes**. Aquarius writes both the name and its colour. Those are storage/work counts, not measured cycles or a promise to fit one frame.

PRINT is simpler when the ROM owns formatting, placement and scrolling. Direct spans suit a game that owns its cells. Cached row pointers or a trusted fast path can reduce work, but their validity depends on allocation lifetime and validated inputs. Clipping, transparent cells, proportional text and arbitrary-size lettering each change the contract.

## What was verified

The caller is an original reset diagnostic with a local stock character ROM and no RAM expansion. Context, results and stack fit the mapped working RAM. It does not establish coexistence with the BASIC editor.

Three builds per machine complete every call, including boundary and rejection cases. Completed wrong-stride controls fail the same memory and visible-output checks. A second control bypasses the horizontal bound and is rejected by the independent destination and image checks.

The full native frame, padding and border are compared against a separate compositor using the local stock font. Retained CI checks source/image/memory hashes, call markers and independent destinations. Fresh execution needs separately supplied firmware. These observations do not establish original-hardware timing, tear-free updates or OS coexistence.
