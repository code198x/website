## ANTIC decides where a line begins

ANTIC F gives this example a 320×192 monochrome picture: forty **8×8** cells across, twenty-four down. Each picture takes eight bytes, with the leftmost pixel in bit 7. The CPU can copy those bytes directly, but the display must read the same addresses.

ANTIC's screen-memory counter wraps at a **4 KB boundary**. Simply placing all 7,680 display bytes in one consecutive block would let the CPU and display disagree. Here the first block holds 102 complete forty-byte scanlines; line 102 starts at `$5000`. The tables use `$4000 + (y/102)*4096 + (y mod 102)*40`.

The diagnostic uses an explicit LMS address for every scanline. That is deliberately readable rather than a minimal display list. Its active 582 bytes fit within a single 1 KB display-list page at `$3000`; the driver reserves and copies 768 bytes. The bitmap allocation is `$4000–$5FFF`, with 7,680 used bytes and 512 gap/tail bytes which drawing must preserve.

## Make it part of your project

Reserve all 32 bytes of `NR` in zero page, clear decimal mode, define the map, tile and screen constants, and include the shared 6502 routine once. `CELL_BYTES=1` and `X_STEP=1`. Supply low/high scanline tables matching your actual display list. A new mode, width or buffer address needs matching tables and ANTIC setup.

The example map has twelve byte IDs per row and eight rows. Four tile pictures take eight bytes each; ID zero is an opaque blank. No scratch initialisation call is needed. A/X/Y and flags are clobbered; allow four stack bytes for the direct JSR and paint helper, beyond your caller and interrupt needs.

The address tables cost 384 bytes. One cell copies eight bytes, or 120 for the 5×3 patch, plus ID preflight and address work. Cached source rows or span copying can save work in a larger scene. Character-mode rendering offers a different memory/copy trade-off; it is not a drop-in change of screen address.

The original reset driver owns DMA, interrupts, display list and colours. An OS-loaded game must arrange ownership and memory with the OS rather than treating this reset setup as a loader.

Supply six unsigned bytes: source column, source row, destination column, destination row, width and height. Then call `region_draw`. `NR+6` is one for a completed draw or zero for rejection. The six request bytes survive.

<CodeFromFile src="atari-800xl/patterns/assembly/rendering/tile-region/demo.asm" from="case_0:" to="case_1:" lang="6502" title="Draw a 5×3 patch from map cell (2,1) at display cell (4,3)" />

The result store after the call belongs to the diagnostic. In a game, inspect the completion flag and continue with your own logic. The routine rejects zero sizes, invalid starts, source/destination overruns and IDs outside the configured tile set. It checks every selected ID before writing any destination bytes, so a bad ID cannot leave half a patch behind. It rejects rather than clips.

The context is non-re-entrant. Your caller owns its memory, video setup and interrupt policy. Keep all inputs and display resources stable throughout the call. Drawing an opaque zero tile erases a cell; transparent sprites need masking or background restoration instead.

## What was checked

All **18 calls** completed on this machine in the original reset diagnostic. Fifteen rejected map/bounds/ID requests were also executed **in isolation**, each after the same three accepted draws. The complete destination and both mapped guards were compared with an independent model, and every native capture pixel was compared with a separate composition. Completed wrong-layout and unsafe-destination controls fail those checks.

The source selection crosses a CPU page boundary. Reserved attributes and allocation gaps are included in the memory comparison.

These results qualify the selected Emu198x 0.39.0 configuration and Asm198x 0.0.71 fixture. They do not establish original-hardware timing, stock-OS loading, interrupt coexistence or a whole-game frame budget. The complete caller keeps reset setup separate from reusable drawing. Copy counts above are not measured timing claims.
