## Take the effect

<CodeFromFile src="dragon-32/patterns/basic/input/read-command/sound.bas" lang="basic" title="The reusable effect" />

SOUND 100,2 uses the ROM sound routine and blocks while it generates the tone. Those operands are BASIC pitch/duration units, not frequency and seconds.

Copy the 2000-range subroutine and call GOSUB 2000 when the game accepts an action. Keep its global scratch variables and any DATA/setup lines with it. A sound call is a consequence of an action, not a substitute for input validation.

## Change it and recognise a mistake

Change the SOUND operands using the language manual’s ranges. A non-blocking player would need to take over the audio path and its timing.

The omitted-trigger control still accepts the action but fails the same audio guard as the working caller. Keyboard clicks or other machine output are not enough: the BASIC checks compare against a separate rejected-command recording.

<CodeFromFile src="dragon-32/patterns/basic/input/read-command/mistakes/no-sound.bas" lang="basic" title="Deliberately omitted sound trigger" />

The working implementation above repairs that omission. If an effect instead drones on, check the mute/service path and that its state is initialised. Servicing twice makes a counted effect shorter; servicing only after input can leave it running while the player waits. Those are lifecycle decisions to test when adapting it.

## Run the caller

Enter the complete `demo.bas` in Dragon 32 BASIC and RUN. Submit **1**, then Return. One accepted command advances the displayed turn; another gives two.

## Verification and sources

Target: **Dragon 32 PAL, stock Extended Colour BASIC**. These callers were executed with released Emu198x **0.44.1**; assembly uses Asm198x **0.0.71**. The [sample folder](https://github.com/code198x/code-samples/tree/d385b67e471a8d9e8b6c452c9e090fa22576adaf/dragon-32/patterns/basic/input/read-command) contains reproduction instructions and [retained observations](https://github.com/code198x/code-samples/blob/d385b67e471a8d9e8b6c452c9e090fa22576adaf/dragon-32/patterns/basic/input/read-command/verification/results.json). The independent checker binds source, native captures and actual output; its rejection tests exercise wrong state, missing files and false audio claims.

This qualifies the named emulator/firmware path. Pitch accuracy, original hardware and other peripherals require their own observations.
