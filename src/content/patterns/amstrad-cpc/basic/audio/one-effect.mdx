## Take the effect

<CodeFromFile src="amstrad-cpc/patterns/basic/input/read-command/sound.bas" lang="basic" title="The reusable effect" />

SOUND 1,100,10,15 submits a channel-A note to the firmware sound system. This routine returns after submission, subject to the firmware queue being able to accept the command. Firmware owns subsequent playback.

Copy the 2000-range subroutine and call GOSUB 2000 when the game accepts an action. Keep its global scratch variables and any DATA/setup lines with it. A sound call is a consequence of an action, not a substitute for input validation.

## Change it and recognise a mistake

Change the SOUND period, duration or volume operands. Adding envelopes changes the duration contract; filling the firmware queue can make submission wait.

The omitted-trigger control still accepts the action but fails the same audio guard as the working caller. Keyboard clicks or other machine output are not enough: the BASIC checks compare against a separate rejected-command recording.

<CodeFromFile src="amstrad-cpc/patterns/basic/input/read-command/mistakes/no-sound.bas" lang="basic" title="Deliberately omitted sound trigger" />

The working implementation above repairs that omission. If an effect instead drones on, check the mute/service path and that its state is initialised. Servicing twice makes a counted effect shorter; servicing only after input can leave it running while the player waits. Those are lifecycle decisions to test when adapting it.

## Run the caller

Enter the complete `demo.bas` in Amstrad CPC BASIC and RUN. Submit **GO**, then Return. One accepted command advances the displayed turn; another gives two.

## Verification and sources

Target: **CPC464 PAL, Locomotive BASIC, MODE 1**. These callers were executed with released Emu198x **0.44.1**; assembly uses Asm198x **0.0.71**. The [sample folder](https://github.com/code198x/code-samples/tree/d385b67e471a8d9e8b6c452c9e090fa22576adaf/amstrad-cpc/patterns/basic/input/read-command) contains reproduction instructions and [retained observations](https://github.com/code198x/code-samples/blob/d385b67e471a8d9e8b6c452c9e090fa22576adaf/amstrad-cpc/patterns/basic/input/read-command/verification/results.json). The independent checker binds source, native captures and actual output; its rejection tests exercise wrong state, missing files and false audio claims.

This qualifies the named emulator/firmware path. Pitch accuracy, original hardware and other peripherals require their own observations.
