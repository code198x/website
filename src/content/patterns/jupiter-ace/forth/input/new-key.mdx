## Take the reader

Compile `new-key.fth` before a word that calls NEWKEY. It adds one character to the data stack. Compare or consume that result exactly once; the caller keeps its running total underneath. Compile `click.fth` before using CLICK. The complete file shows the definition order.

<CodeFromFile src="jupiter-ace/patterns/forth/input/new-key/new-key.fth" lang="forth" title="The reusable reader" />

NEWKEY has stack effect ( -- c ). It waits for INKEY to return zero, then waits for a nonzero character. A key held at entry must be released before it can become a new action. It preserves everything already below its result on the data stack.

NEWKEY blocks while it waits. It uses the ROM keyboard path and the ordinary data stack; it has no private variable or frame timer. It deliberately waits for release before another press.


## Change it and recognise a mistake

Change the character comparison after NEWKEY. Keep release-then-press when an action must happen once per physical press; raw INKEY is useful for held-state controls instead.

The broken word fabricates its first key instead of waiting. The count changes before you press anything. Restore NEWKEY to keep the input decision with the player.
