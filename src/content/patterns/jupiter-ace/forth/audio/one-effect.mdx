## Take the effect

<CodeFromFile src="jupiter-ace/patterns/forth/input/new-key/click.fth" lang="forth" title="The reusable effect" />

CLICK has stack effect ( -- ). It supplies 478 and 120 to ROM BEEP, which consumes both operands and blocks for the generated tone. The running turn count below them stays on the stack.

Compile CLICK before the caller. Its stack effect is ( -- ): the two BEEP operands are pushed and consumed inside the word. The manual defines the lower operand as a period in eight-microsecond units and the upper as milliseconds; this requests 120 ms. The PCM check establishes changing output, not a pitch or duration calibration.

## Change it and recognise a mistake

Change CLICK’s two BEEP operands using the manual’s pitch/duration rules. Their units are not interchangeable with BASIC SOUND on other machines.

The omitted-trigger control still accepts the action but fails the same audio guard as the working caller. Keyboard clicks or other machine output are not enough: the BASIC checks compare against a separate rejected-command recording.

<CodeFromFile src="jupiter-ace/patterns/forth/input/new-key/mistakes/no-sound.fth" lang="forth" title="Deliberately omitted sound trigger" />

The working implementation above repairs that omission. If an effect instead drones on, check the mute/service path and that its state is initialised. Servicing twice makes a counted effect shorter; servicing only after input can leave it running while the player waits. Those are lifecycle decisions to test when adapting it.

## Run the caller

Compile `demo.fth` in its listed order. Its final TURNS starts the caller. Press **1**, let go, and press it again: the count reaches two.
