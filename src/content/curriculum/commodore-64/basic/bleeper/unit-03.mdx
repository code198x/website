A memory game needs something to remember: a *sequence*. You met arrays in Tally as counters;
here an array does a different job — it holds an **ordered list**, panel after panel, that the
machine plays back in turn. Store the sequence as data, and one loop performs it.

Line 100 stores the sequence: `S(1)=1`, `S(2)=4`, `S(3)=2` — red, then yellow, then cyan. Then
lines 110–140 *play* it: a `FOR I = 1 TO 3` loop sets `P = S(I)` and calls the same flash-and-tone
routine from last unit, with a short pause between steps. The array names which panel; the
routine lights it.

The important shift is that the sequence is now **data, not code**. The playback loop doesn't
know or care what's in the array — it just flashes whatever each slot names. Put a different list
in `S()` and the machine performs a different tune, with not a line of the playback changed. That
separation — a list of *what*, a loop that does the *how* — is exactly what lets the next unit
grow the sequence without rewriting the player.

## Try this

- **Compose.** Change the three values in line 100 to any panels you like — `S(1)=3:S(2)=3:S(3)=1`
  — and watch the machine play your sequence.
- **Make it longer.** Add `S(4)` and `S(5)`, change the loop to `1 TO 5`, and the machine plays a
  five-step tune. The array holds as many as you give it.

## What's next

The machine plays a *fixed* sequence. In **Unit 4** it grows the sequence by one random panel
each round — the escalation that turns a performance into a game.
