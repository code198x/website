A program that only shows what you typed is not worth much. The turn comes when the
computer **works something out**.

## A sum from numbers you type

```text
ASK "First number? " INTO a
ASK "Second number? " INTO b
SHOW "The total is ", a + b
```

Type `7`, then `5`:

<Output>First number? 7
Second number? 5
The total is 12</Output>

You did not know the answer when you wrote that program, and you could not have: the
numbers come from whoever is typing. `a + b` is an instruction to work the total out from
whatever the two boxes hold at the moment that line runs.

The same line gives `12` today and `109` tomorrow. Arithmetic is `+`, `-`, `*` for
multiply and `/` for divide.

A number and a piece of text are different kinds of thing, and `+` works on numbers. It
does not stick two pieces of text together: that is what the comma in `SHOW` is for. So
ask for a number when you want to do sums with the answer, and ask for a name when you
want to show it. Languages disagree about this more than almost anything else. Some keep
the two strictly apart and make you say which you meant. Others swap between them so
freely that you can stop noticing. Knowing which one you are holding stays your job.

## A box that grows from itself

Here is the pattern that does the real work in games. Remember from Unit 4 that `=` means
*put this in the box*.

```text
LET score = 0
SHOW "Score: ", score
LET score = score + 10
SHOW "Score: ", score
```

<Output>Score: 0
Score: 10</Output>

Read `LET score = score + 10` as maths and it is nonsense, because nothing equals itself
plus ten. Read it as an instruction and it is clear: *take what is in `score`, add ten,
put the result back*.

That one move is how every score climbs, every total mounts up and every life count falls
(`LET lives = lives - 1`). You will write it in every game you ever make.

## When it's wrong, see why

- **You get a wrong total.** One of the boxes was still empty when the sum ran. Fill both
  of them before the line that adds them.
- **The answer is the two numbers stuck together**, like `75` instead of `12`. The
  computer joined them as text instead of adding them as numbers. Check that you asked
  for numbers, and that `+` is doing the work rather than a comma.
- **Someone typed something that is not a number.** `hello + 5` is not a sum anyone can
  do. A finished program checks the answer before trusting it; for now, type numbers.
- **`LET score = score + 10` still looks wrong to you.** Good, because it *is* wrong as
  maths. Read it as "the new score is the old score plus ten".

## What you've learnt

- The computer does **arithmetic**, working a new value out from ones it already has.
- It can work from values the **player gives**, so the same program gives different
  answers.
- A box can **grow from its own value**. That is the counter behind every score.
- `=` means **put this in the box**, which is exactly why a box can grow from itself.
