RUN. Choose **1–4** for 12, 60, 300 or 1,200 rolls. At a result, **R** starts a fresh batch of the same size, **A** adds that many rolls, and **N** returns to size selection. **Q** stops a running batch early; at a result or size menu it quits to BASIC.

## Keep the old result before changing it

The new p() array stores the previous six tallies, while pn stores their total. At line 400, copy the current sample into those variables. Only afterwards may line 410 clear t() and n for a fresh run.

The variable add chooses which operation happens: zero means start fresh; one means keep the current counts. DIM t(6) clears all six entries together. It does not clear the separate p() array.

The header routine prints the previous shares once. It divides each p(j) by pn, rather than by the changing current total. On the first run pn is zero, so it prints dashes instead of attempting division. Both totals stay visible at the top; the previous percentages remain fixed while the current chart develops.

<Question prompt="You finish twelve rolls, then press A. Why are the resulting samples of twelve and twenty-four not independent experiments?">

The twenty-four-roll sample contains all twelve rolls from its predecessor, plus twelve new ones. The two results overlap. R instead clears the current sample before drawing a fresh batch from the continuing pseudorandom sequence.

</Question>

## Make each press one choice

The subroutine at 8000 first waits for every key to be released, then waits for a new key. CODE reads its character code. Codes 65 through 90 are uppercase letters. Adding 32 and using CHR$ produces the lowercase equivalent. Digits are left unchanged.

The release gate prevents a held R from repeatedly starting batches. It also keeps a held Q from stopping a batch and immediately quitting its result. Release the key, then press again for another action.

The size menu rejects anything outside the strings `"1"` through `"4"`. Line 230 begins with twelve; the next three lines change b for the other choices. Choosing a size sets add to zero, so it always starts fresh. At a result, unknown keys loop back without altering either sample. GO TO selects a different part of the program; unlike GO SUB, it does not arrange a return.

## Count every roll, print less often

Before each batch, line 420 records its intended target and resets done to zero. n is the whole current sample; done is only this batch's progress. After adding twelve rolls to a sample of twelve, n is twenty-four but done is twelve.

The variable pace is one for batches of twelve and sixty, ten for the larger choices. At line 460, `i/pace=INT (i/pace)` is true when i is an exact multiple of pace. The extra `OR i=1` shows the first roll immediately. Every roll still updates the counts. Only display calls are spaced out, giving BASIC less printing to do. The result at 600 always redraws the exact final or stopped state.

Line 340 permits an addition only when `n+b<=9600`. At the limit, A displays a message and changes neither sample. R starts fresh. This limit keeps the experiment bounded; it does not mark a statistical threshold where randomness becomes trustworthy.

Try several twelve-roll batches, then compare larger ones. Larger samples often have shares closer to the fair-model reference, but a particular larger sample need not look more balanced than the preceding smaller one. No screen in this program proves fairness.

## Keep a copy

Quit with Q at a result or the size menu. Enter this direct command **without a line number**:

```basic
SAVE "dice" LINE 10
```

Press Enter at the tape prompt and wait for `0 OK`. In Emu198x, export the recording to a new `.tap` file using **Cmd/Ctrl+Shift+E**. The [saving guide](/systems/sinclair-zx-spectrum/basic/meet-basic/unit-02-remember-and-save/#keep-a-copy-outside-the-spectrum) explains how recording inside the Spectrum differs from keeping a host file.

Load the exported tape in a fresh 48K machine using `LOAD ""` and tape playback, or tape autoload. The size menu should appear. Initialisation clears both arrays, so this saves the reusable program rather than resuming the comparison you were viewing.

Check a complete cycle: choose twelve, add twelve, repeat fresh, select another size, stop it early, release Q and quit from the result. Counts should always add up to the displayed current total. The previous column should describe the result you just left, including a stopped partial result.

<summary>Keyboard notes</summary>

CODE uses I in extended mode; AND is Symbol Shift with Y. SAVE uses S in keyword mode. For LINE, enter extended mode, then Symbol Shift with 3. The SAVE command has no line number because you want to execute it now, not store it as part of the experiment.
