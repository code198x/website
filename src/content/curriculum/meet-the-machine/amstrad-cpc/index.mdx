The Amstrad CPC runs a **Z80** — the very processor you meet in
[Meet Assembly (Z80)](/meet-assembly/z80). So the instruction set carries over with nothing
to relearn: `LD` is `LD`, the jumps and loops and the stack are exactly as you know them.
This briefing is **only what makes the CPC the CPC** — its screen, its sound, its memory.
Everything else, you already have.

## Same chip, different computer

A **Z80A at 4 MHz**, instruction-for-instruction the same as the one in a Spectrum or an
MSX. For the processor itself, see [Meet Assembly (Z80)](/meet-assembly/z80); for the number
sense underneath it — binary, hex, two's complement, bit logic — see
[Foundations](/foundations/numbers-and-bits). What follows is the CPC's own character, and
nothing more.

## The screen

Three display modes trade colour against resolution: **mode 0** (160×200, **16 colours**),
**mode 1** (320×200, 4 colours), **mode 2** (640×200, 2 colours) — chosen from a palette of
**27**. A CRTC 6845 and a custom Gate Array drive it.

The headline difference from the Spectrum: **no attribute clash.** Colour here belongs to
the pixels, not to a separate coarse map laid over them — so the single most famous
limitation you'd learn to work around on the Spectrum simply isn't here. (The screen memory
has its own non-linear layout, which the briefing's later units would map.)

## The sound

Every CPC ships with an **AY-3-8912** — a **three-channel** sound chip — where the 48K
Spectrum had only a one-bit beeper. Tunes and effects that were a fight on the Spectrum come
far more readily here; it's the same chip the Spectrum 128 later gained.

## The memory

**64K** on the CPC464 and 664, **128K** on the 6128. The Z80 still sees a 64K address space;
on the 128K machines the extra memory is reached by **banking** it in through the Gate Array.

## What carries over

The Z80 instruction set and everything in Foundations are unchanged — only the screen, the
sound and the memory above are the CPC's own. That is the whole briefing, and the whole
point: meet what's different about the machine, then reuse everything you already know.

## Where to from here

You've met the machine. Now pick the language you'll write it in — the CPC shipped with two,
and your path forks here.

**Locomotive BASIC** — the language built into the CPC's ROM, ready the instant it switches
on. *(Meet Locomotive BASIC is on the way: the CPC's own dialect, not the Spectrum's — even
on the same Z80, the two BASICs share nothing.)*

**Z80 assembly** — down to the metal, in three steps:

1. [Numbers & Bits](/foundations/numbers-and-bits) — hex, bits and two's complement, the
   bridge into assembly. (The BASIC path skips this; the assembly path leans on it constantly.)
2. [Meet Assembly (Z80)](/meet-assembly/z80) — the instruction set itself. You'll see it
   shown on a **Spectrum** — because the Z80 is the same chip in every machine that has one.
   The few things that *aren't* the chip's — the screen, the sound, the memory — are the
   briefing you just read, so nothing there will catch you out.
3. Then the CPC's own assembly games.

Either way, the [universal groundwork](/foundations) you've already done never changes.
