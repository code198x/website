Boot Gloaming and you're simply *in the square*, mid-story: the wisp already gathering, the clock already running, no name spoken, no breath taken. Every game you've ever loaded knows better — there's a screen with a name on it, a moment that belongs to you, and a deliberate act of *beginning*. This unit builds that front door twice: once the obvious way, which works and teaches the pieces — and once the right way, which restructures the whole program and hands Unit 20 the key it needs.

## Milestone 1 — a door, hardwired

Everything the title needs already exists. The screen is `clear_bitmap`, the blackout `LDIR` from the lose screen, and two `print_string` calls — GLOAMING at row 8, PRESS SPACE at row 14, white on a black void. (Sparse is the aesthetic *and* the budget: on this machine, restraint photographs as atmosphere.) The sound is a fourth phrase for the beeper — `chime_dusk`, two cold tolls on a low A, then the game's little motif far off. And the key is a promise kept: Unit 5's try-this had you read SPACE — `$7FFE`, bit 0 — "fifteen units early". Tonight it's load-bearing.

So wire it the way anyone would first: at boot, draw the title, chime, and sit in a little loop reading SPACE until it drops — then fall through into the setup and the game we've always had.

One ordering detail in the setup rewards attention: the chime is called **after** `im 1 / ei`, unlike everything else sound-adjacent so far. Why? Its rests. `rest` counts silence in `HALT`s, and `HALT` waits for an interrupt — call the chime before `ei` and the first rest waits forever, on a machine that looks perfectly healthy and plays exactly one note. When one subsystem quietly depends on another being switched on, the order of two boot lines becomes a bug you can *hear*.

## What's wrong with the door

Play from it. Title, chime, SPACE, game — it all works. Now win, and look at where you are: THE NIGHT IS HELD, holding forever. Lose: NIGHT FALLS, forever. The title was real, but it wasn't a *place* — it was a preamble, executed once on the way in, unreachable ever after. The deeper problem is structural, and it's worth saying precisely: **"beginning the game" is not a thing this program can do; it's a thing that happened.** The setup code runs once, woven into the boot path, and nothing can ever ask for it again. Unit 20 needs to send you from the end screens back to a title that can start a *fresh night* — and this shape has no handle to grab.

## Milestone 2 — beginning becomes callable

The fix is the last restructure of the module, and not one visible byte changes on screen. Three moves:

1. **The setup body becomes `init_game`** — everything from zeroing `lit_count` to drawing the wisp, lifted whole out of `start` and given a name and a `ret`. Beginning is now a routine.
2. **The title becomes a state.** `STATE_TITLE` joins the machine — as state zero, the state the `game_state` byte's own `defb` boots into — and `title_step` owns the waiting: each frame, read SPACE; on a press, `call init_game`, switch to `STATE_PLAY`.
3. **The loop learns to dispatch.** The Unit 15 gate grows into the real thing: TITLE frames go to `title_step`, PLAY frames to `play_step`, WIN and LOSE hold. Each state now *names what a frame means*.

Watch what `start` shrank to: black border, state to TITLE, draw the title, start the heartbeat, chime. Boot no longer knows *anything about the game* — not where the lamplighter stands, not how many lives, nothing. It knows how to open the door; the door knows how to begin. This is the refactor pattern from Unit 10 wearing structural clothes: there, we deleted code the world had made redundant; here, we *moved* code until each piece had exactly one owner. The screen proves nothing changed; the shape proves everything did.

## When it's wrong, see why

- **One note, then silence, machine looks hung.** The chime ran before `ei` — its first `rest` is halting for an interrupt that can't arrive. Boot order: interrupts on, *then* anything that rests.
- **The title flashes past straight into the game.** The SPACE test is inverted — bit 0 reads **1** when up; `ret nz` (or `jr nz, .twait`) keeps waiting. Active-low, Unit 5's oldest lesson, still collecting.
- **SPACE mid-game restarts the night.** `title_step` is being called in every state — the dispatch must route only TITLE frames to it. A state machine is only as good as its gate.
- **Starting from the title gives a half-stale board.** Something didn't move into `init_game` — every mutable byte the game touches must be re-established there, not left to a `defb` that was only fresh at boot. (Unit 15's warning about `defb` initial values, now with teeth.)
- **The game begins on its own after a win.** The end states must *hold* — if WIN or LOSE frames fall through to `title_step`, a held SPACE from your last input starts a game nobody asked for. Unit 20 handles returning deliberately.

## Before and after

The unit began with a game that started without permission and ended with one that waits to be asked. Milestone 1 built every visible piece — screen, chime, key — and worked; milestone 2 changed nothing visible and mattered more: *beginning* went from an event in the boot sequence to a capability of the program, `init_game`, callable by anyone with a reason. The state machine now has its full shape — TITLE, PLAY, WIN, LOSE — with exactly one arrow missing: nothing yet leads *back*. One unit left.

## Try this: dress the door

The title is two strings and a void, which means it's cheap to art-direct. Recolour the name (write a different attribute in `print_char`'s path — or paint the title row's attributes after printing: lamp-gold `%01000110` reads beautifully on black). Move the rows. Add a third line — a copyright, your initials, `AN EVENING GAME` — one more `defb` string and one more call. Feel how fast iteration is when a screen is data.

## Try this: an impatient door

Make PRESS SPACE breathe: after printing, set FLASH on its cells — eleven attribute writes at row 14 — and the prompt pulses on the hardware's own clock, no code per frame. The oldest attract-mode trick on the machine, and it costs nothing the loop ever sees.

## Try this: any key to begin

Replace the SPACE read in `title_step` with Unit 7's gather idiom — all three direction half-rows plus SPACE's, OR'd together — so any key opens the door. Arcade-style. Then decide if you *want* it: a player resting their hand on QAOP at the title now starts before they meant to. Input design is choices, not just code.

## What you've learnt

- A title screen is **assembled from parts you had**: the printer, the blackout, the beeper, one new phrase.
- **Boot order can be audible** — anything that rests on the heartbeat needs the heartbeat running first.
- The hardwired door works and can't be reopened: **preambles aren't places**.
- **`init_game` turns beginning into a capability** — state zero owns the waiting, the dispatch names each frame's meaning.
- A pure restructure can be the most important diff in a module: **same bytes on screen, new shape underneath**.

## What's next

Every screen in Gloaming now exists — title, play, gold, black — and they form a line, not a loop: win or lose, the game holds its final screen forever, one SPACE away from a title it can never reach. **Unit 20** draws the last arrow: from either ending, back to a title that remembers your best night — and the module's final lesson is the one every game ends on: what must be reborn, what may persist, and how a state machine closes.
