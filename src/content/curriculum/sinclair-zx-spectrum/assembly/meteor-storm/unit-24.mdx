The browser experiment proves that our code can run when placed directly into a prepared machine. A distributable tape needs a different check: loading through the Spectrum's ROM from a fresh start.

Use the same finished program. This final lesson adds no new game code. First play it, then save the files you intend to share.

## Keep source and data together

Download **source** and **assets.inc**. The source contains the program; the companion contains the pre-shifted artwork and prepared course. Keep both in one directory. Saving only the assembly file leaves its include dependency missing.

You can also download a tape assembled from the current contents of both editors. Edits that have not been run yet are still included in that download, so test the version you actually intend to distribute. Revert restores both editors.

For an independent local build:

```sh
asm198x --dialect pasmo --cpu z80 --tapbas meteor-storm.asm -o meteor-storm.tap
```

Or use upstream Pasmo:

```sh
pasmo --tapbas meteor-storm.asm meteor-storm.tap
```

The tape contains a small BASIC loader and the machine-code block. You do not need to author a BASIC game to use that loading convention. The code begins at 32768 and establishes its own stack and interrupt route when entered.

## Load what you will share

Start a fresh 48K Spectrum emulator, mount `meteor-storm.tap`, enter `LOAD ""` and start tape playback. In Emu198x the equivalent command is:

```sh
emu198x-spectrum --machine spectrum_48k --tape meteor-storm.tap --autoload-tape --scale 3
```

Confirm that the title appears, Space launches after release, O/P steer and held Space boosts. Lose and retry; then return to the title. Complete a run when you can and check that the time and score records survive another retry within that session.

A snapshot saves a machine's state and can be useful while investigating a fault. It is not the same evidence as a fresh ROM load of the tape. A snapshot can preserve an already configured stack, interrupt mode or record that a fresh launch has not established yet.

<Question prompt="You set a best time, download the tape, reset, and load it again. Should that record still be there?">

No. Tape download assembles the source and initial data, not a recording of the running machine's RAM. Session records begin unset on a fresh program launch. Saving records across sessions would require a separate persistence feature.

</Question>

## Choose a next experiment

Keep a working copy before changing the game. Try one design change with a prediction: a different drift cadence, an altered event spacing or revised star artwork. State which behaviour should change and which should remain intact, then retest collision, retry and completion.

We have built a game whose positions and rules live in state, whose picture is drawn from that state, and whose progress is measured separately from time. Those distinctions will still matter when another game needs a different renderer, more objects or a different machine.
