A game needs to explain its controls and rewards before the player has to guess them. We will finish by reading the title and text routines that present those rules.

The title states the one-hit rule, O/P steering, held double speed, star values and the faster-finish bonus. The HUD keeps time, speed and score visible during flight. A result names the outcome, bonus, records and retry controls. None of these screens changes the contact rule.

## Draw characters without borrowing print state

`text` takes B=character row, C=column and DE=a zero-terminated string. Each character code selects eight bytes of ROM-font data. The routine computes the character's bitmap position using pixel_address, copies its eight rows, then advances to the next character column.

The address calculation uses `8*character + $3C00`. This places printable character 32 at the font's first space glyph. It is an address formula for the supplied Spectrum ROM font, not permission to draw arbitrary control codes as useful text. Our strings contain printable characters and a zero terminator.

The routine saves the text pointer and B/C while the glyph-copying work uses those registers, then restores them before continuing. Its caller should nevertheless treat all primary registers as changed after the complete text call.

## Centre from the actual length

`text_center` counts characters until the zero byte, subtracts the count from 32 and divides by two with a right shift. Integer division rounds down, which is the chosen centring rule when an odd spare column remains.

<AssemblyExcerpt checkpoint="finished" from="text_center:" to="; B=character row" />

METEOR STORM has twelve characters including its space. `(32-12)/2` gives column 10. Counting only letters, or treating a character coordinate as a pixel coordinate, would position it incorrectly.

`text` separately checks row and column bounds. It returns if row is at least 24 or column is at least 32, so a long string is clipped instead of wrapping into another row. An overlong centred string starts at column zero before that clipping.

<Question prompt="Would centring a 33-character instruction make all of it readable?">

No. There are only 32 character columns. Bounds checks prevent unwanted writes, but they cannot create room. Shorten the instruction or split it deliberately over two rows. Clipping is a guard, not a layout strategy.

</Question>

Change only the quoted title in `name_text`, preserving its final zero. Predict the new starting column and run. Try a short title and a deliberately overlong one, then restore METEOR STORM. Review the result at the actual displayed size, not only by counting source characters.

For a final play review, ask someone to launch, boost, collect a star and retry using the on-screen instructions. A correct keyboard routine cannot make an unexplained control discoverable.
