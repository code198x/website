Run it. Play five rounds. Notice: it's fun. Not because it's pretty — it's text on a white screen. It's fun because of the *pattern*. Your brain encounters a sequence, models it, and tries to hold it. Each round stretches the model. The moment it breaks, you know exactly where — and you want to try again.

## Compare to Bright Spark

Your text game and Bright Spark have the same logic. The same string stores the sequence. The same FOR loop plays it back. The same INKEY$ comparison checks the player's input. The difference:

- **Bright Spark has panels** — four large coloured rectangles drawn with FOR loops and PAPER. The colour makes each panel instantly recognisable.
- **Bright Spark has BRIGHT flashes** — the BRIGHT toggle catches the eye. You don't read which panel was played — you *see* it light up.
- **Bright Spark has distinct tones** — each panel has a unique pitch (C, E, G, high C). You can remember the sequence as a melody, not just a list of numbers.
- **Bright Spark has game feel** — the "Correct!" message, the score display, the "WRONG!" with border flash. Polish that makes each outcome feel significant.

The text version proves the mechanic works. Bright Spark proves that presentation makes it *better*. Neither is complete without the other. Mechanics without presentation is a puzzle. Presentation without mechanics is a screensaver. A game needs both.

## Pattern Recognition

Raph Koster's argument is that **fun is the feeling of learning patterns**. Your brain is a pattern-matching machine. It seeks structure in everything it encounters. When it finds a pattern, it feels satisfaction. When the pattern is just beyond its grasp, it feels excitement. When the pattern is mastered, it feels bored.

Bright Spark is a pure pattern game. There is nothing else — no story, no characters, no world. Just a sequence to remember. And it works because the sequence is always one step beyond your comfort zone. The game teaches you nothing except how far your own memory can stretch — and that turns out to be exactly the right lesson.

Every game uses pattern recognition, even games that don't look like memory games:
- **Tetris** — recognising which piece fits which gap
- **Chess** — recognising board positions and their implications
- **Dark Souls** — recognising boss attack patterns and when to dodge
- **Lucky Number** — recognising that binary search is the optimal pattern

When a game stops presenting new patterns, it stops being fun. That's why Bright Spark never ends — the sequence grows forever, and there's always one more round you *almost* got right.

## The Full Picture

Three games complete. Three design concepts:

| Game | Design concept | What you learnt |
|------|---------------|----------------|
| Lucky Number | **Feedback** | The game communicates through colour, sound, display |
| Wire Panic | **Tension** | Time pressure through layered, escalating feedback |
| Bright Spark | **Pattern** | Sequences, memory, and emergent difficulty curves |

And three sets of programming tools:

| Game | BASIC concepts |
|------|---------------|
| Lucky Number | PRINT, LET, INPUT, IF/THEN, GO TO, RND, PLOT, DRAW |
| Wire Panic | CLS, PRINT AT, BEEP, PAUSE, INKEY$, string variables |
| Bright Spark | FOR/NEXT, STEP, INK, PAPER, BORDER, BRIGHT, nested loops |

Game 4 — **Hot and Cold** — is a treasure hunt. You move a cursor around the screen, and the border tells you how close you are. It teaches **the game loop** — input → update → draw, running continuously — alongside position variables, ABS, SQR, and the power operator. The screen comes alive.
