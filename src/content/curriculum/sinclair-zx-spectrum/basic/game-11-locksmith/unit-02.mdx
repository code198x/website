Line 180 asks for a guess as a string — the player types four digits like `2341`. Line 190 validates the length: `IF LEN g$ <> 4 THEN GO TO 180` sends them back if they type too few or too many characters.

Lines 200–210 parse the string into a second array. `DIM g(4)` creates four slots. The FOR loop extracts each character with `VAL g$(i)` — `VAL` converts a single string character back to a number, just as it did in Bright Spark. After this loop, `g(1)` through `g(4)` hold the four guessed digits as numbers, ready to compare against `c(1)` through `c(4)`.

## String to array

The player types a string because that is natural — `2341` is one thing to type, not four separate INPUTs. But the program needs individual digits to compare position by position. The parsing loop bridges the gap: one INPUT for the player, four array slots for the logic.

`g$(i)` is a string slice — the i-th character of `g$`. `VAL` turns it into a number. This is the same `STR$`/`VAL` pair from Bright Spark, but in reverse: there you converted numbers to string characters to build a sequence; here you split a string into numbers for comparison.
