The computer picks a code. You crack it. That is the whole game — but first, the code needs to exist.

Line 55 creates an array: `DIM c(4)` — four slots, numbered 1 to 4. Line 60 fills each slot with a random digit from 1 to 6 using the same `INT (RND * 6) + 1` formula from earlier games. Lines 75–76 print the code so you can see it. Line 80 stops.

Run it a few times. Each run produces a different four-digit code — `3 2 5 1`, then `6 4 4 2`, then `1 5 5 5`. The code can repeat digits. That matters later when counting clues.

## Arrays as secrets

You used `DIM k(4)` in Quiz Master to store an answer key, and `DIM s(4)` to track scores per category. Both were lookup tables — you wrote values in and read them back by index. Here the purpose is different: the array holds a secret. The player will never see `c(1)` through `c(4)` directly. Instead, they will guess, and the program will compare their guess against the hidden array.

The array is the hidden state. Everything that follows — the guessing, the clues, the deduction — is the player trying to reconstruct what is inside `c()` without ever looking at it. For now, lines 75–76 reveal the code so you can verify the clue logic as you build it. The curtain comes down in unit 8.
