The player makes five moves. The computer makes four. If no one has three in a row after all nine squares are filled, the game is a draw.

<CodeFromFile src="sinclair-zx-spectrum/basic/game-13-three-in-a-row/unit-08/draw.bas" />

Lines 145 and 178 add the draw checks. After the player moves (line 145): if `moves = 9`, all squares are full — draw. After the computer moves (line 178): same check. The player moves fifth (moves 1, 3, 5, 7, 9) and the computer moves fourth (2, 4, 6, 8), so the draw can be detected after either side's move.

## Why both checks?

The player always has the last move (move 9 out of 9). But the win check runs before the draw check — if the player wins on move 9, line 140 catches it before line 145 fires. If no one wins after move 9, the board is full and it is a draw.

Line 178 catches the rare case where the computer's eighth move fills the board without either side winning — possible if the last remaining square does not complete any line.

Against the full AI, draws are the expected outcome. That is not a bug — it is the correct result of two competent players. The game teaches through inevitability: once you understand why every game draws, you understand the game completely.
