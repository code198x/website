Lines 650–670 are the new addition — three checks for the computer's own near-wins, identical in structure to the blocking checks but looking for value 2 (O) instead of 1 (X). They run *before* the blocking checks (lines 680–700) in the same loop.

The order matters. If the computer can win AND needs to block, it should win. The `mv = 0` guard ensures the first opportunity found takes priority. Since the winning checks (650–670) come before the blocking checks (680–700), a winning move always beats a block.

## Three-tier priority

The AI now has three layers, checked in order:
1. **Can I win?** (lines 650–670) — take the winning move
2. **Can they win?** (lines 680–700) — block the threat
3. **Neither** (lines 730–740) — random fallback

This is a priority system — the same pattern used in real game AI. Each layer represents a question. The AI asks them in order of urgency and takes the first action it finds. The code is mechanical; the intelligence is in the ordering.
