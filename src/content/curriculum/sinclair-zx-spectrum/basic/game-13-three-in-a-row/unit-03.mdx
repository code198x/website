The player places X's, but nobody checks whether they have won. Time to detect three in a row.

Lines 900–910 store the eight winning lines as DATA: three rows (1,2,3 / 4,5,6 / 7,8,9), three columns (1,4,7 / 2,5,8 / 3,6,9), and two diagonals (1,5,9 / 3,5,7). Each line is a triple of position numbers.

Lines 200–235 form the win-check subroutine. `RESTORE 900` rewinds DATA. The FOR loop reads each triple and checks: `IF b(p) <> 0 AND b(p) = b(q) AND b(q) = b(f)` — if all three positions hold the same non-zero value, someone has won. The winner's value (1 for player, 2 for computer) goes into `winner`.

Line 135 calls `GO SUB 200` after the player moves. Line 140 checks the result.

## DATA as a lookup table

In Cipher and Quiz Master, DATA held content — words, questions, answers. Here DATA holds *structure*: the rules of the game encoded as numbers. The eight triples define what "three in a row" means. The program does not know about rows, columns, or diagonals — it only knows about triples of positions. The DATA encodes the geometry.

This separation is powerful. If you changed the DATA to define a 4×4 board with different winning lines, the win-check code would work unchanged. The data describes the game; the code applies the rules.
