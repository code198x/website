Line 50 prints the labels once: "ALT:", "SPD:", "FUEL:" — all on one row at the top. Lines 110–130 update the values in place with `PRINT AT`, overwriting the previous numbers each tick.

The screen is now an instrument panel. Altitude, speed, and fuel are always visible at the same positions. No scrolling, no clutter.

## Landing outcomes

Lines 150–160 branch to separate landing sequences:

- Line 200: `TOUCHDOWN!` in green, with an ascending fanfare.
- Line 300: `CRASH!` in red, with a harsh buzz.

Each outcome gets its own presentation — colour, sound, and message working together. The same multi-channel feedback from Lucky Number and Reflex, applied to a more dramatic moment.

## The shape of a real-time game

The program now has the standard structure of every real-time game:

```
[initialise]
[draw the frame]
[read input]
[update physics]
[check for end condition]
[loop]
```

Init once, then loop: draw, input, update, check. This is the game loop pattern — the same structure that runs *Manic Miner*, *Jet Set Willy*, *Cybernoid*, and every real-time game on the Spectrum. The BASIC version runs slower than Z80 assembly, but the architecture is identical.
