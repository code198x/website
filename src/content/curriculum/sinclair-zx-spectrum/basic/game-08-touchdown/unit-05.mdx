`PAUSE 3` on line 440 waits three frames — roughly a twentieth of a second — before the loop repeats. This controls how fast the game runs. Without it, the loop runs as fast as the Spectrum can manage, which is too fast to see or react to. Higher numbers make the game slower; lower numbers make it faster. Try changing 3 to 1 or 10 to feel the difference.

Lines 450–470 check the landing speed once altitude hits zero. Speed 0–2: "PERFECT LANDING!" Speed 3–5: "Bumpy but safe." Speed 6 or more: "CRASH!" Each outcome uses `STOP` to end the program.

Line 480 changes from `IF alt > 0 THEN GO TO 150` to an unconditional `GO TO 150` — the loop now runs continuously. The landing checks on lines 450–470 break out of it when altitude reaches zero.

## Three outcomes, one variable

The landing speed is the only thing that matters. It does not matter how much fuel is left or how long the descent took. The player's entire performance reduces to a single number: how fast were you going when you hit the ground?

This keeps the game focused. One thing to manage (speed), one resource to spend (fuel), one number that determines the result. The three-tier outcome gives the player a target to aim for — not just "did I survive?" but "how well did I land?"
