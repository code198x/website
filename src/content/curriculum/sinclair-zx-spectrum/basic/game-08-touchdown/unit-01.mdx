Every game so far has waited for the player's input. This one does not wait. The lander is falling.

<CodeFromFile src="sinclair-zx-spectrum/basic/game-08-touchdown/unit-01/falling.bas" />

Seven lines. Line 100 sets altitude to 100. Line 110 sets speed to 0. Line 150 adds 1 to speed every frame — gravity. Line 190 subtracts speed from altitude. Line 210 prints both values. Line 480 loops back if the altitude is above zero.

Run it. The numbers scroll past as the lander plummets. Speed starts at 1, then 2, then 3 — gravity accelerates. Altitude drops by 1, then 3, then 6, then 10. The faster you fall, the more altitude you lose each frame. This is the simplest possible physics simulation: **speed accumulates, position changes by speed**.

## Gravity as code

In real physics, gravity adds roughly 9.8 metres per second every second. Here, `LET spd = spd + 1` adds 1 unit per frame. The number is simpler but the principle is identical — acceleration means the speed itself keeps changing. That is what makes falling feel like falling, not sliding. The gap between each altitude reading grows wider because the speed is always increasing.

The lander hits the ground and stops — `IF alt > 0 THEN GO TO 150`. When altitude reaches zero, the loop ends. But there is no landing yet, no control, no feedback. The lander just falls and stops. That is the point: understand the physics before adding the game.
