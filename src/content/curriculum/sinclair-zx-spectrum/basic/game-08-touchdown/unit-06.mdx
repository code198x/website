Line 360 is the key: `LET row = 20 - INT (alt / 5)`. It converts altitude (0–100) to a screen row (20–0). When altitude is 100, the row is 0 — top of the screen. When altitude is 0, the row is 20 — the ground line. Line 380 clamps the row so it never drops below the ground. Lines 420–430 draw: first erase the old position with a space, then print `"V"` at the new row.

## Number to position

The formula `20 - INT (alt / 5)` does two things. `alt / 5` scales the altitude from 0–100 down to 0–20 (the usable screen rows). `INT` drops the decimal so it maps to a whole row number. `20 -` flips the direction: higher altitude means a smaller row number, which is higher on the screen.

This is a common pattern in games: converting a **game value** (altitude in abstract units) to a **screen position** (row on the display). The game logic works in its own units. The display code translates.

The lander is just a `V` character — one letter, one cell. But it moves, and that movement gives the player something to watch. The dashboard shows the numbers; the lander shows the feeling.
