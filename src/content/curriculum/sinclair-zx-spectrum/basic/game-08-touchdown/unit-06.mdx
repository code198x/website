The numbers say the lander is falling. But you cannot *see* it. This unit puts a character on screen that moves.

<CodeFromFile src="sinclair-zx-spectrum/basic/game-08-touchdown/unit-06/lander.bas" />

Line 60: `PRINT AT 21, 0; "================================"` — a row of equals signs at the bottom. The ground.

Lines 160–230 move the lander:

1. Compute the screen row from altitude: `LET row = 20 - INT (alt / 5)`. High altitude puts the "V" near the top; low altitude puts it near the ground line.
2. Erase the previous position: `PRINT AT prow, 15; " "`.
3. Draw the new position: `PRINT AT row, 15; "V"`.

The "V" descends toward the ground line. Its position *is* the altitude — you can see how high you are without reading the number.

## PRINT AT with computed position

This is the first time `PRINT AT` uses a *variable* for the row. Until now, positions have been fixed: `PRINT AT 10, 10` always meant row 10, column 10. Here, the row changes every tick based on the altitude calculation.

`20 - INT (alt / 5)` maps altitude 100 to row 0 (top of play area) and altitude 0 to row 20 (the ground). The `INT` rounds down so the row is always a whole number. The `/5` scales 100 altitude units into 20 screen rows.

This pattern — computing a screen position from a game variable — is how every character-cell game places objects. The variable holds the game state; the PRINT AT makes it visible.

## Clear then draw

Lines 220–230: erase the old character, draw the new one. Without the erase, the screen would fill with "V"s. This **clear-then-draw** pattern is the simplest animation: remove the old frame, place the new one. You will use it in every game that moves anything on screen.
