The player can currently draw a line between any two nodes. But puzzles only allow specific connections. When the player selects two nodes, the program must check whether that pair appears in the connection list. If it does not, the connection is rejected.

## How It Works

**Lines 10-80** set up nodes, connections and the cursor as before.

**Lines 90-130** handle selection. When the player completes a two-phase selection (start node `s`, end node `p`), the program calls `GO SUB 300` to check whether this pair is valid before drawing.

**Lines 300-340** are the validation subroutine. It loops through all connection pairs, checking whether `(s,p)` or `(p,s)` matches any entry in `e()` and `f()`. Connections are unordered — connecting node 2 to node 4 is the same as connecting node 4 to node 2. Variable `v` is set to the connection index if found, or 0 if the pair is not valid.

**Lines 350-360** also check whether the connection has already been drawn by testing `d(v)`. A duplicate connection is rejected the same way as an invalid one.

**Lines 140-160** use the result. If `v` is 0, the program beeps and resets the selection without drawing. If `v` is a valid index, the line is drawn and `d(v)` is set to 1.

## Order-Independent Matching

The check tests both `(s,p)` and `(p,s)` against each stored pair. This is essential because the player might select node 4 first and node 2 second, while the DATA stores them as 2,4. Without this bidirectional check, half of all valid selections would be rejected.

## Feedback for Invalid Connections

When a connection is rejected, the program plays a low beep and resets the selection state. The player sees the start node return to green and knows their attempt failed. Clear feedback matters — without it, the player would not know why nothing happened.

## Try This

**Test all valid pairs.** Draw every required connection in the puzzle. Does the program accept them all, regardless of selection order?

**Test invalid pairs.** Try connecting nodes that are not in the required list. Does the program correctly reject them?
