The game has three screens: title, puzzle select and gameplay. This unit connects them into a complete flow. The player starts at the title screen, moves to puzzle select, plays a puzzle, sees their rating, and returns to the select screen. From there they can play another puzzle or quit.

## How It Works

**Lines 10-30** set up the game state. Array `st()` stores star ratings for all puzzles. Variable `gs` tracks the current game state: 0 for title, 1 for select, 2 for playing.

**Lines 40-60** form the main state loop. Based on `gs`, the program jumps to the appropriate screen routine:

- `gs = 0` — call the title screen subroutine. On return, set `gs = 1`.
- `gs = 1` — call the puzzle select subroutine. On return, set `gs = 2` with the chosen puzzle number.
- `gs = 2` — call the gameplay subroutine. On return, update the star rating and set `gs = 1`.

**Lines 70-80** handle the back key. During gameplay, pressing B returns to the select screen without completing the puzzle. During puzzle select, pressing B returns to the title screen.

## State Machine Pattern

The game flow is a simple state machine. Each state has an entry action (draw the screen), a run phase (handle input), and an exit action (clean up and transition). The main loop checks `gs` and dispatches to the correct subroutine.

This is the same pattern used in previous games for title/playing/game-over states. The difference here is the addition of the select screen as an intermediate state, creating a three-state loop rather than a two-state toggle.

## Screen Transitions

Every transition clears the screen with CLS. This is simple and reliable — no stale graphics carry over between screens. The clear-and-redraw approach works well because each screen is self-contained. The title screen draws itself from scratch. The select screen draws itself from scratch. The gameplay screen draws itself from scratch.

## Persistent State

Star ratings persist across the entire session. Completing puzzle 3 with two stars, then playing puzzle 7, then returning to the select screen shows both results. The `st()` array is never cleared unless the program restarts. This gives the player a sense of accumulating progress.
