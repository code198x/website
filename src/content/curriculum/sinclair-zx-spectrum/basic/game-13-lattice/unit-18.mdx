Some of the best Lattice puzzles arrange nodes in a circle. Rather than calculating these positions by hand, we use SIN and COS to space nodes evenly around a centre point. This is the first time we use trigonometry in the curriculum, and Sinclair BASIC makes it straightforward.

## How It Works

**Lines 10-20** set the centre of the circle (128,90 — roughly the middle of the puzzle area) and the radius (60 pixels).

**Lines 30-50** read the number of nodes, then calculate each node position using SIN and COS. The angle for node `i` is `(i-1) * 2 * PI / n`, where `n` is the total number of nodes. This spaces nodes evenly around the circle.

**Line 35** calculates the angle in radians. Sinclair BASIC SIN and COS take radians, not degrees. A full circle is 2 * PI radians, which is approximately 6.2832.

**Lines 40-45** compute the x and y positions: `x(i) = cx + r * COS(angle)` and `y(i) = cy + r * SIN(angle)`. COS gives the horizontal offset and SIN gives the vertical offset from the centre.

**Lines 60-100** read connection data and run the puzzle as normal. The game engine does not know or care that the nodes were placed with trigonometry — they are just x,y values in arrays.

## SIN, COS and Radians

If you have not used trigonometry before, the core idea is simple. SIN and COS convert an angle into horizontal and vertical distances from a centre point:

- **COS(angle)** gives the x offset (ranges from -1 to 1)
- **SIN(angle)** gives the y offset (ranges from -1 to 1)
- Multiplying by the radius scales those offsets to the desired size
- Adding the centre coordinates shifts the circle to the correct position

**Radians** are just a different way to measure angles. Instead of 360 degrees for a full circle, radians use 2 * PI (about 6.28). To convert degrees to radians, multiply by PI / 180. Sinclair BASIC has PI as a built-in keyword.

## Why Circles Make Good Puzzles

Circular arrangements create naturally interesting crossing challenges. When nodes are evenly spaced around a circle, connections between non-adjacent nodes often cross. The player must work out which connections to draw first to avoid blocking later ones. This is harder to judge visually than grid-based puzzles, raising the difficulty.
