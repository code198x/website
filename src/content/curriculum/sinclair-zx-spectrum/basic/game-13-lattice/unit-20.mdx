With three difficulty bands, the player benefits from a visual cue that tells them which tier they are playing. Changing the connection line colour per band gives each tier its own identity — white for Band 1, cyan for Band 2, magenta for Band 3.

## How It Works

**Lines 10-20** store the line colour for each band in an array. `DIM lc(3)` holds the INK values: `lc(1)=7` (white), `lc(2)=5` (cyan), `lc(3)=3` (magenta).

**Lines 30-40** determine the current band from the puzzle number and set variable `ic` to the corresponding colour from `lc()`.

**Lines 200-240** modify the line-drawing subroutine. Instead of always using INK 7, it uses `INK ic`. The line colour now depends on the current band.

**Lines 400-460** update the crossing detection subroutine. The ATTR check must now look for the current band colour, not just white. The test compares the sampled ink value against `ic`. This ensures crossing detection works correctly regardless of which colour the lines are drawn in.

## ATTR and Colour-Based Detection

The crossing detection relies on ATTR to detect existing lines. When all lines were white, the check was simple — any cell with ink 7 contained a line. With multiple line colours, the check must recognise any of the possible line colours.

The simplest approach is to check whether the ink value matches the current band colour. Since all connections within a single puzzle use the same colour, this works perfectly. If you ever mixed colours within a puzzle, you would need to check for all possible line colours.

## Visual Hierarchy

The colour choices are deliberate:

- **White (Band 1)** — high contrast, easy to see, appropriate for introductory puzzles
- **Cyan (Band 2)** — still clear, but cooler and more subdued than white
- **Magenta (Band 3)** — distinctive and slightly harder to track against black, matching the higher difficulty

The player quickly learns to associate each colour with a difficulty level. This is a simple but effective use of colour as information.
