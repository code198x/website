Puzzles require experimentation. Sometimes the player draws a connection that is valid and does not cross anything, but blocks a future connection. Without undo, the only option is to restart the entire puzzle. This unit adds an undo key that removes the last connection drawn.

## How It Works

**Lines 10-100** set up the puzzle as before. A new array `h()` records the order in which connections were drawn. Variable `hc` counts how many connections have been drawn so far.

**Lines 110-130** record each successful connection. When a line is drawn, the connection index is stored in `h(hc)` and `hc` is incremented.

**Lines 140-160** handle the undo key. When U is pressed and `hc` is greater than 0, the program undoes the last connection by setting `d(h(hc))` back to 0 and decrementing `hc`.

**Lines 170-200** redraw the entire puzzle after an undo. There is no way to erase a single line from the Spectrum screen without affecting everything around it. Instead, the program clears the graphics area, redraws all nodes, and redraws only the connections that are still marked as drawn in `d()`. This full redraw is simple and reliable.

## Why Full Redraw?

On the Spectrum, you cannot erase a line without also erasing any pixels it shares with other lines or nodes. The XOR drawing trick used by some programs has colour side effects. The cleanest approach is to clear and redraw everything. For Lattice, with a small number of nodes and connections, this is fast enough to feel instant.

## The History Stack

Array `h()` acts as a stack. Each new connection is pushed onto the end. Undo pops the last entry. This means undo always removes the most recent connection, which matches what the player expects.

If the player draws connections A, B, C, then presses undo twice, C and B are removed in that order. Drawing a new connection D then pushes D onto the stack. The history records the order of play, not just which connections exist.

## Try This

**Undo everything.** Draw several connections, then press U repeatedly until the puzzle is empty. Does the display stay correct after each undo?

**Undo and redo.** Draw a connection, undo it, then draw it again. The history stack should handle this cleanly — the connection goes from drawn to undrawn to drawn again.
