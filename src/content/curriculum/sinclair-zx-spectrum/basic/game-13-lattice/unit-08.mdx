Moving the cursor between nodes is half the input system. The other half is selection. The player presses SPACE to select the current node. The first press picks a start node. The second press picks an end node and draws a line between them. This two-phase selection is how every connection is made.

## How It Works

**Lines 10-70** set up the puzzle and draw nodes as before. Variable `s` tracks the selection state: 0 means no node is selected, and any other value holds the index of the selected start node.

**Lines 80-130** extend the input loop. When SPACE is pressed and `s` is 0, the current node becomes the start node. The circle is redrawn in cyan (INK 5) to show it is locked in. When SPACE is pressed and `s` is already set, the current node becomes the end node. A white line is drawn from `s` to `p`, and `s` resets to 0.

**Lines 140-150** prevent the player from selecting the same node twice. If `p` equals `s`, the press is ignored.

## Two-Phase Selection

The two-phase pattern is simple but effective:

1. **Phase 1:** Cursor moves freely. SPACE locks in the start node.
2. **Phase 2:** Cursor moves freely. SPACE at a different node draws the line and returns to Phase 1.

The visual feedback is important. The start node changes colour (green to cyan) so the player always knows which node they have selected and that the program is waiting for an end node. After the line is drawn, both nodes return to green and the cycle restarts.

## Cancelling a Selection

What if the player selects the wrong start node? Right now, there is no cancel. They must pick an end node to complete the action, even if it is wrong. Later, we will add undo to remove unwanted connections. For now, the two-phase flow is enough to make lines appear on screen.
