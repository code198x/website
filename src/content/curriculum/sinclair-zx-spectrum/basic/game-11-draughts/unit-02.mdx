The board array holds the game state, but the player needs to see the board. This unit draws an 8x8 chequerboard using PRINT AT. Dark squares are black (PAPER 0) and light squares are yellow (PAPER 6). No pieces yet, just the grid itself.

## How It Works

**Line 30** calls the draw board subroutine with `GO SUB 500`. This is the first subroutine in the program. Keeping the drawing code separate from the setup makes the code easier to read and reuse.

**Lines 510-560** loop through every row and column. For each cell, the even-sum check decides the colour. Dark squares get `PAPER 0` (black background), light squares get `PAPER 6` (yellow). Both print a space character to fill the cell with colour.

**Line 530** uses `GO TO 550` to skip line 540 when the square is dark. The Spectrum has no ELSE keyword, so we jump past the alternative branch manually. This is a pattern you will use constantly.

## Screen Coordinates

The formula `AT r + 2, c * 2 + 2` positions the board on screen. Adding 2 to the row leaves space at the top for labels. Multiplying the column by 2 and adding 2 gives each square a wider spacing and leaves a margin on the left.

The board occupies rows 3 to 10 and columns 4 to 18 on the Spectrum screen. That leaves room above for column labels, to the left for row labels, and below for the status area.

## Why a Subroutine

The board will be redrawn many times during a game - after every move, after captures, and when starting a new game. Putting the drawing code in a subroutine at line 500 means we call `GO SUB 500` whenever we need a fresh board. No duplication.

## Try This

**Swap the colours.** Change PAPER 0 to PAPER 1 (blue) for dark squares. Blue is the traditional colour for a draughts board. Which looks better on screen?

**Fill the whole screen.** Remove the `+ 2` offsets so the board starts at position 0,0. It fills the screen from the top-left corner. Not practical (no room for labels), but useful for understanding the positioning maths.
