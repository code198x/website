## How It Works

**Lines 1500-1598** implement the title screen. The screen clears to a dark background. "DRAUGHTS" appears in bright white at the top. Below it, the two piece types are shown in their colours: a red "o" for Player 1 and a green "o" for Player 2, along with "K" for kings. The input format is explained ("Enter moves as A3 B4"). `PAUSE 0` waits for a keypress before the game begins.

**Line 5** calls `GO SUB 1500` as the very first action, displaying the title screen before initialisation.

**Line 15** after the title screen, calls the board setup and drawing routines. The title screen clears itself before the game board appears.

## The Complete Game Loop

1. **Title screen** - piece symbols, input format, press any key
2. **Initialisation** - DIM array, fill starting positions, draw board and pieces
3. **Turn start** - check for no legal moves, display status, clear messages
4. **Input** - read move string, parse into coordinates
5. **Validation** - source piece, diagonal move, forward-only, occupied square, mandatory capture
6. **Highlighting** - briefly flash legal destinations
7. **Execution** - update array, check king promotion, draw cells, handle captures
8. **Multi-jump** - check for chain continuation, loop if available
9. **Win check** - count remaining pieces, declare winner if zero
10. **Turn switch** - alternate player, loop to step 3
11. **Game over** - display winner, play sound, offer replay

## What You Built

Draughts is roughly 220 lines of BASIC that enforce every official rule of the game. Over 32 units, you built:

- **A data model** - the 2D array with values 0-4 encoding empty squares, pieces, and kings
- **A rendering system** - PRINT AT with INK, PAPER, and BRIGHT for the board, pieces, labels, and status
- **An input parser** - string slicing with CODE and VAL to extract coordinates
- **A validation cascade** - layered checks for source, diagonal, direction, occupancy, and mandatory captures
- **State machines** - turn tracking, multi-jump chains with lock flags, king promotion
- **Win detection** - piece counting and move scanning for both victory conditions
- **Polish** - sound effects, move highlighting, error messages, replay, and a title screen

Every technique from previous games contributed. DIM arrays from Minefield. INK and PAPER from Colour Flood. CHR$ and CODE from Word Scramble. GO SUB architecture from Night Patrol. BEEP sequences from Hot and Cold. This is the largest and most complex program in the course so far.

## The Design Decisions

The game works because of choices made in unit 1:

- **Single character per square** - keeps the board compact and BASIC fast enough
- **Array values 0-4** - encodes owner and type in one number, so every check is a simple comparison
- **Coordinate input** - matches the labels the player sees, making input intuitive
- **Subroutine-per-feature** - each feature lives in its own line range, so adding kings did not break captures

## Try This

**Play a complete game.** Two players, full rules. Try to get a king. Execute a multi-jump chain. Play until someone wins by elimination or stalemate. Does the game feel fair and complete?

**Design a variant.** Change the starting position in the init subroutine. Try rows 1-4 and 5-8 with no gap, or start with 8 pieces each instead of 12. Small changes to the initial data create surprisingly different games.
