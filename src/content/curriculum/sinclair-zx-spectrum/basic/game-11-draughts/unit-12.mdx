Capturing is the heart of draughts. A piece jumps over an opponent's piece diagonally, landing two squares away. The jumped piece is removed from the board. This unit adds capture detection to the move validation.

## How It Works

**Line 955** introduces a new variable `j` (for jump). It starts at 0 (no capture) and is set to 1 if the move is a valid capture.

**Line 962** is the key branching point. If the move distance is 2 squares in both directions (`e = 2` and `f = 2`), it jumps to the capture validation at line 1100.

**Line 1120** calculates the intermediate square - the one being jumped. The jumped square sits exactly between the source and destination: `w = (q + v) / 2` and `x = (p + u) / 2`.

**Lines 1130-1170** validate the capture. The landing square must be empty (line 1110). The jumped square must contain an opponent's piece (lines 1140-1150). The jump must be forward for non-king pieces (lines 1160-1170).

**Line 1180** sets `j = 1` to flag that this is a capture, so the make-move subroutine knows to remove the jumped piece.

**Line 1055** in the make-move section handles the removal: it clears the jumped piece from the array and screen when `j = 1`.

## The Intermediate Square

The maths for finding the jumped square is elegant. If a piece moves from row 3 to row 5, the jumped row is `(3 + 5) / 2 = 4`. If it moves from column 2 to column 4, the jumped column is `(2 + 4) / 2 = 3`. Averaging the source and destination always gives the middle square.

## Try This

**Make a capture.** Move pieces so that one player's piece is diagonally adjacent to the opponent's, with an empty square beyond. Execute the capture and watch the jumped piece disappear.

**Try an invalid capture.** Jump to a square that already has a piece on it. Or try to jump over your own piece. Each should produce a clear error message.
