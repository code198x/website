Ordinary draughts pieces can only move forward - toward the opponent's side of the board. Player 1 moves toward row 8. Player 2 moves toward row 1. Moving backward is not allowed until a piece becomes a king.

## How It Works

**Line 980** checks Player 1's direction. If `t = 1` and the destination row `v` is less than the source row `q`, the piece is trying to move backward (toward row 1). The move is rejected with "Must move forward".

**Line 990** does the same for Player 2, but in reverse. Player 2 moves toward row 1, so if `v` is greater than `q`, the piece is moving the wrong way.

## Direction as a Rule

This is the first player-specific rule in the game. The diagonal check in unit 8 applies equally to both players. But the forward-only rule depends on who is moving:

- **Player 1:** Row numbers must increase (moving down the screen, toward row 8)
- **Player 2:** Row numbers must decrease (moving up the screen, toward row 1)

The variable `t` determines which rule applies. When we add kings in Phase 2, we will relax this rule for pieces with values 3 or 4. But for now, all pieces must move forward.

## Building Validation Layer by Layer

With this unit, we have four validation layers in place:

1. Input format and range (unit 6)
2. Source has player's piece (unit 7)
3. Move is diagonal (unit 8)
4. Move is forward (this unit)

Each check adds precision. A move that passes all four is a valid single-square diagonal forward move. Two more checks remain: the destination must be empty (unit 11), and we need to handle captures (unit 12).

## Try This

**Test backward moves.** As Player 1, try moving a piece from row 3 to row 2 (e.g. B3 A2). Confirm the error appears. Then try a valid forward move (B3 A4 or B3 C4).

**Remove the forward check.** Comment out lines 980-990 and play a few turns. Without the forward-only rule, pieces can retreat. This changes the game significantly - pieces would be much harder to trap.
