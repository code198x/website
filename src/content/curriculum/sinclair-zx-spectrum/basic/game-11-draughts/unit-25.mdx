A player also loses if they have no legal moves on their turn. This can happen when all their remaining pieces are blocked, unable to move forward or capture. The game must detect this at the start of each turn.

## How It Works

**Line 85** calls `GO SUB 1400` at the start of each turn, before the player is prompted for input.

**Lines 1400-1490** form the no-moves check. It scans the board for any piece belonging to the current player and tests whether it can move:

1. **Simple moves:** Check if any adjacent diagonal square is empty (line 1447)
2. **Captures:** Check if any two-square diagonal jump is possible (line 1450)

**Line 1405** initialises `n = 0` (no moves found). If any legal move is found, `n` is set to 1 and the scan exits early.

**Lines 1480-1485** check the result. If `n` is still 0 after scanning every piece, the current player has no legal moves. The opponent wins. A descending three-note sequence plays (pitches 0, -3, -7), distinct from the ascending victory fanfare.

## The Direction Iterator Again

The scan uses the same `i/k` direction iterator from unit 20. For each piece, it checks all four diagonal directions for simple moves and captures. The code is dense because it handles bounds checking, empty-square detection, and capture detection in a compact loop.

Lines 1455-1460 step through the four directions by incrementing `k` from -1 to 1, then incrementing `i` and resetting `k`. This compact iteration avoids writing four separate direction checks.

## Two Win Conditions

The game now has both win conditions from official draughts rules:

1. **Elimination** (unit 24): Capture all opponent pieces
2. **No moves** (this unit): Block all opponent pieces

Both are checked every turn. Elimination is checked after a move. No moves is checked before the input prompt. Together, they cover every possible game-ending state.

## Try This

**Force a stalemate.** Create a position where one player's pieces are all blocked. The game should detect this and award the win to the other player. The descending sound distinguishes this from a capture-based win.

**Test kings.** Kings can move in all four directions, so they are much harder to block. Verify that the no-moves check correctly considers all four directions for kings.
