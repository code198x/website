RUN begins at the title. S starts, R restarts or begins the next round, and Q quits. Complete a round and press R: O should start the next one. Restart that unfinished round and O should still start it.

## Two kinds of state

Line 20 creates the session values: wins, losses, draws and first. They are initialised once, before the title. Line 200 creates round state: a fresh board, zero moves, no winner, no winning line and an empty reason.

A restart now goes to 200 rather than using RUN. It preserves the session tally and first. That is why abandoning a round does not erase earlier results or change who starts. RUN remains a complete session restart.

The title has its own input loop. It waits for S or Q and releases the previous key before accepting input. When first is 2, line 220 goes straight to the computer's move path after drawing the board. An empty board leads O to its centre preference.

## Count a result once

Lines 5000–5020 increase exactly one tally and choose its message. The program then highlights a winning line, updates the display and waits at 5080. Ignored keys return to that waiting line, not to the scoring statements. Holding a key or pressing an unrelated number must never count the result twice.

R from a completed result uses `3 - first` to switch the next starter, then goes to 200. R during play goes directly to 200, preserving first. Those two routes deliberately have different meanings.

The board and O's last reason remain visible while the result waits. The game is silent: shapes, captions and the winning line provide the feedback. No timer pushes you past a position before you can read it.

<Question prompt="Why would GO TO 10 be wrong for the R command during play?">

It would clear the session tally, reset the starter and return to the title. We want a fresh round while keeping the session, so the correct destination is 200.

</Question>
