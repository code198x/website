Play 1. O should choose 2 and explain `first empty`. Play 5; O takes 3. Play 9 and X wins the diagonal. There must be no extra O move after that win.

## A routine returns a choice

The routine at 4000 starts mv at zero, meaning “no move selected”. It visits squares 1–9. When mv is still zero and b(j) is empty, it stores j in mv. Later empty squares do not replace that first choice. NEXT stays outside the conditional line.

The routine chooses but does not place. On returning, line 620 copies mv to n, stores O in b(n), increases moves and calls the cell drawing routine. Line 630 prints the selected square and a$, the reason supplied by the choosing routine.

The main loop now has two move paths. Human input always stores 1. O's path always stores 2. Both draw the accepted mark before calling the result scan, and both check whether the round has ended before handing over. We can remove the two-player turn variable and caption routine because these paths establish whose turn it is.

## A promise about the board

The choosing routine is called only when there is an empty square and the game has no winner. Under those conditions it must return a legal square. If a full board reached it, mv would remain zero and b(0) would be invalid. The end checks are therefore part of the routine's calling contract, not optional decoration.

The display says that O is choosing, then keeps its reason on the row below your prompt. A longer message is padded with spaces so a shorter later reason leaves no stale letters behind.

<Question prompt="Why not let every empty square replace mv in the loop?">

That would choose the last empty square instead of the first. Either can be a legal policy, but our stated rule and displayed reason must agree with the code. The `mv = 0` guard preserves the first choice.
