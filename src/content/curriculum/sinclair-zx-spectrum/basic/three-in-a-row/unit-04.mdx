Now the program plays back. The opponent's move is the heart of the game — and it is built from
the same line table you just wrote. The computer scans those eight lines looking for a line it can
*complete* (win now), then a line it must *stop* (block you), and only if neither exists does it
fall back to a random square. That ladder of rules is game AI.

## A line with two marks and a gap

The move routine (lines 600–800) reuses the winning-line table. For each line it asks: do two of
the three cells hold the computer's nought while the third is empty? Lines 650–670 check all three
positions a line's gap could be in — `b(p) = 2 AND b(q) = 2 AND b(f) = 0`, and the two other
arrangements. If so, `mv` is that gap and the computer wins. The same scan run again for the
player's mark (`= 1`, lines 700–760) finds a line *you* are about to complete, and takes the gap to
block it.

## Priority is the intelligence

The order is the whole point: **win first, block second, random last**. Line 690 jumps out the
moment a winning move is found, so the computer never blocks when it could win. Only when no line is
one-from-complete for either side does it drop to a random empty square (lines 780–790). The
computer is not searching ahead or being clever — it is applying three rules in order. That is
enough to make it genuinely awkward to beat, and it is the shape almost every small game AI takes:
a list of rules, tried in order of strength.

It plays well, but it still wastes its idle moves at random. Next: give those moves a strategy.
