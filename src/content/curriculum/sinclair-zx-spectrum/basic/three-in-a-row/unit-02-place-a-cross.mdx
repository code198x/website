## Accept a move before drawing it

INKEY$ supplies a character while a key is pressed, or an empty string when none is pressed. The `$` identifies a string variable. Line 260 keeps looking until k$ contains something. Q quits and R runs the program again, clearing the array and board.

The comparison on line 290 rejects characters outside `"1"` to `"9"`. Only then does VAL convert the character to a number. This order keeps unrelated keys away from both VAL and the array subscript.

Line 310 tests b(n). `<>` means “not equal to”. An occupied square sends us back to the input loop before anything changes. A legal move stores 1, then calls the same cell routine used for the initial numbers. This time b(n) is nonzero, so the routine continues into the cross drawing.

An IF condition that fails skips the rest of that BASIC line. The RETURN after printing an empty square therefore belongs to the empty-square case; it does not prevent a cross being drawn.

## Give one press one action

The routine at 9000 waits while INKEY$ is nonempty. It returns once the player releases the key. Calling it before the next input prevents a held key from being treated as a succession of moves. Hold 1 down to try it, then release and press a different number.

Two diagonals form X. Their ends lie ten pixels either side of the centre. A loop with z equal to 0 and 1 draws each diagonal twice, one pixel apart, making the mark substantial enough to read. The cell routine removes the old number with a space first.

<Question prompt="Would drawing the cross be enough to make a square occupied?">

No. Legality comes from b(n). Without `LET b(n) = 1`, another press would still find zero. The drawing displays the decision; it does not store it.
