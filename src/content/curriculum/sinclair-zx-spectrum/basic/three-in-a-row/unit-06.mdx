Lines 650–670 are the new addition — three checks for the computer's own near-wins, looking for two O's (value 2) in a line with the third square empty, exactly mirroring the blocking checks but for O instead of X. Crucially, they run as a **separate first pass**: one loop scans all eight lines for a win (lines 630–680), and only if it finds none does a second loop scan for a block (lines 700–760).

The order matters. If the computer can win *and* needs to block, it should win — a win ends the game in its favour. Scanning every line for a win before looking at a single block guarantees that: line 690, `IF mv > 0 THEN GO TO 800`, jumps straight to the move the instant any win is found, so the block pass never even runs. One combined loop would get this wrong — a block on an earlier line could be chosen before a win on a later one. Two passes keep "win" strictly ahead of "block".

## Three-tier priority

The AI now has three layers, each scanned in full before the next:
1. **Can I win?** (lines 630–680) — scan every line for a winning move
2. **Can they win?** (lines 700–760) — if not, scan every line for a block
3. **Neither** (lines 780–790) — random fallback

This is a priority system — the same pattern used in real game AI. Each question is answered completely before the next is asked: every winning line is checked before any blocking line, every block before the fallback. The code is mechanical; the intelligence is in the ordering.
