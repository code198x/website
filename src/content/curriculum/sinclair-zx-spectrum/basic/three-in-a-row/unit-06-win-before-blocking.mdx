Play 1, then 5. O first takes 2, then must block at 9. Its reason changes to `block`. Restart and play 1, 3, 7, 6. O replies 2, 4, 5, then wins at 8. On that final turn it could block your right column at 9, but winning takes priority.

## Ask the same question for either mark

The routine at 4500 receives mark: 2 when we want an O opportunity, 1 when we want an X threat. It returns mv, either the square that completes a line or zero when none exists. It does not change the board.

For each triple, there are three places the gap might be. Lines 4520–4540 cover all three: p and q occupied with f empty; p and f occupied with q empty; q and f occupied with p empty. Two equal marks are not enough unless the remaining square is free.

Each condition includes `mv = 0`. That preserves the first opportunity found in DATA order. RESTORE starts each search at the first triple. The variables used by the routine are shared BASIC variables, so its input and output names are a convention we must respect.

## The order makes the decision

Line 4000 asks about mark 2. If it finds a move, line 4010 sets the reason to `win` and returns immediately. Otherwise the same search runs for mark 1. A found threat becomes `block`. Only after both searches fail do we look for the first empty square.

Consider X in squares 1 and 2, and O in 4 and 5, with O to move. X threatens 3, but O can win at 6 now. Blocking first would miss the immediate victory. The priority is part of the game behaviour, not merely a tidy way to arrange code.

<Question prompt="If the first search returns zero, why can the second search reuse mv?">

Zero says there was no O winning move to preserve. The second call resets mv and looks for an X opportunity instead. After it returns, the caller knows which question supplied the answer because it chose mark before calling.

</Question>

The reason records the branch that succeeded. It does not claim that O planned several moves ahead. Try predicting the next reason before pressing your key.
