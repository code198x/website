In Hot and Cold, pressing a key moved the cursor one step. Here, the character moves *continuously* — pressing a key changes the *direction*, not the position. The character keeps going in whatever direction was last set.

<CodeFromFile src="sinclair-zx-spectrum/basic/game-07-tail-chase/unit-03/steering.bas" />

Two new variables: `dx` (horizontal direction) and `dy` (vertical direction). `dx=1, dy=0` means moving right. `dx=0, dy=-1` means moving up. The player's keypress changes dx and dy, and the movement line (`LET x=x+dx: LET y=y+dy`) applies whatever direction is currently set.

The nested IFs on lines 160-190 prevent the snake from reversing into itself. `IF k$="o" THEN IF dx<>1` means "only go left if not already going right." You can't do a 180 — only 90-degree turns. This is a **game rule** enforced by code. Without it, pressing the opposite direction would kill you instantly by running the head backward into the body. The rule exists to protect the player from an unfair death.

**Direction variables** (dx/dy) are a pattern you'll see in every game with movement. Instead of checking the key and directly changing x or y, you change the *direction* and let the movement code apply it. This separation means the movement logic doesn't need to know about keys — it just follows dx/dy. The input sets the direction. The physics applies it.
