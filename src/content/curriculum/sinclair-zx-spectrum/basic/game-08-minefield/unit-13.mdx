## How It Works

**Lines 20-70** present the menu. Three options with clear labels showing the mine count.

**Lines 80-90** use `INPUT` to get the choice. The validation `IF d < 1 OR d > 3` rejects invalid input and asks again.

**Lines 100-120** map the choice to a mine count:

```
100 IF d = 1 THEN LET n = 5
110 IF d = 2 THEN LET n = 10
120 IF d = 3 THEN LET n = 15
```

**Line 180** calculates the win target using `n`:

```
180 LET f = 0: LET w = 64 - n - 1
```

With 5 mines: 58 cells to reveal. With 15 mines: 48 cells.

| Difficulty | Mines | Safe cells | Win target |
|-----------|-------|------------|------------|
| Easy | 5 | 59 | 58 |
| Medium | 10 | 54 | 53 |
| Hard | 15 | 49 | 48 |

## Formula-Driven Difficulty

The mine count `n` drives everything. The placement loop runs `n` times. The win target is `64 - n - 1`. The HUD shows `n`. One variable controls the entire difficulty curve.

This is better than copy-pasting three versions of the game. Change the mine count, and everything adjusts automatically.

## Variable Name Gotcha

The neighbour-counting subroutine originally used `n` as its counter variable — the same name as the mine count. After the subroutine ran, `n` would be overwritten with a neighbour count instead of the mine count.

The fix: use `g` in the subroutine instead of `n`. Spectrum BASIC has no local variables — every variable is global. Choose distinct names for distinct purposes.

## Try This

**Fourth option.** Add "4. Extreme (25 mines)". That leaves only 38 safe cells on a 64-cell grid — brutal but possible.

**Show difficulty.** Print the chosen difficulty on the HUD: `PRINT "Mines: "; n`. The player should always know what they're up against.

## What You've Learnt

- **Menu input** — display options, read choice, validate
- **Variable-driven difficulty** — one value controls multiple systems
- **Formula design** — `64 - n - 1` derives the win target from the mine count
- **Variable naming** — global scope means names must be unique across subroutines
