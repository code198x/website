## Visit the instructions once

Line 10 now calls two routines. The first installs the graphics; the second draws the title and waits. S returns from routine 5000, so execution continues at line 100 and creates a new round. Q leaves through the shared exit routine.

The title is drawn with ordinary PRINT AT statements. The lines explain the objective, O/P movement, SPACE serve, paddle aiming, retry and quit. The short messages fit the Spectrum's 32 character columns.

Retry goes directly to 100, so players do not have to visit the instructions between attempts. The graphics remain installed during that running session, while the round's mutable state is rebuilt.

## Follow the whole cycle

| Situation | What happens next |
|---|---|
| Title | S starts; Q leaves |
| Ready | O/P move the attached ball; SPACE serves |
| Flight | O/P move the paddle while the ball continues |
| Miss or clearance | Movement stops; release the old key, then choose R or Q |
| Retry | Restore all bricks, centre the paddle and wait for a serve |
| Exit | Return to BASIC; RUN begins again at the title |

R and Q also work during ready and flight. They are checked before another candidate move is made.

## Reset the round, not just the picture

Line 100 recreates g and restores left, p, x and y. Line 110 restores direction, served and steps. The nested loops mark all eighteen bricks live, then the drawing routine reconstructs their pictures.

This order matters. Drawing eighteen bricks while leaving zeros in g would create decorations the ball could pass through. Resetting g without drawing the wall would create invisible obstacles. The count, state and picture must describe the same round.

<Question prompt="Why does retry jump to 100 rather than calling only the drawing routine at 1000?">

The drawing routine changes what we see. It does not reset removed bricks, movement direction or the served flag. Initialisation restores the rules as well as the picture.

</Question>

## Try the awkward exits

Start, serve and retry during flight. Check that the ball returns to its waiting position. Miss while holding a movement key; release it before choosing another attempt. Clear the wall and verify that the ball stops. Retry after that success and check BRICKS 18. Quit from the title, ready state, flight and result, using RUN to start again each time.

The game is deliberately silent. Progress is visible in the disappearing bricks and numeric count, so it does not depend on recognising the row colours. The final instructions say how to aim without needing a sound cue.

If R restores the picture but SPACE does nothing, inspect served at initialisation. If a held key races through a result, check the release loop at 4020. The next lesson keeps this exact program on tape and checks it from a fresh session.
