The question screen and the answer screen belong to the same toy. We’ll give
them the same heading, then avoid maintaining that heading in two places.

Continue with [Give the answer a rhythm](/systems/sinclair-zx-spectrum/basic/meet-basic/unit-10-give-the-answer-a-rhythm/). If starting with an empty
program, the first listing contains everything; the preceding two lessons
explain its selection, dots and sound.

## See the duplicated job

Add **lines 51, 52, 89, 91 and 92**, and replace **line 90**:

<CodeFromFile src="sinclair-zx-spectrum/basic/meet-basic/oracle/unit-11/steps/step-01.bas" lang="sinclair-basic" />

Lines 50–52 print the title, a divider and a blank line before the question.
Lines 89–91 do exactly the same job after the dots. The answer label has moved
to line 92. We have two identical blocks, reached at different moments.

Run it and compare the screens. To change the divider now, we would need to
change both copies. Missing one edit would make the two screens disagree.

## Give the job one home

Replace **line 50** and **line 89** with the calls below. Delete **51, 52, 90 and
91** by entering each number alone. Add **140 and 500–530**:

<CodeFromFile src="sinclair-zx-spectrum/basic/meet-basic/oracle/unit-11/steps/step-02.bas" lang="sinclair-basic" />

`GO SUB 500` means “run the routine beginning at line 500, then come back”. A
**routine** is a group of instructions doing a named job in our explanation;
Sinclair BASIC identifies this one by its starting line number. Enter `GO SUB`
with H after the line number. Enter `RETURN` with Y after its line number.

The first call at 50 runs 500, 510 and 520. `RETURN` at 530 resumes at line 60,
where the question waits. The call at 89 runs the same three printing lines,
but this time `RETURN` resumes at 92, before the answer label.

BASIC remembers the return point for each call. `GO TO 500` would not do that:
it changes the next line without arranging a return. The difference matters
when the same job is used in more than one place.

Line 140 deliberately stops the main program. Without it, execution would
continue into 500 after the answer, then reach `RETURN` without a matching call.
Enter `STOP` with **left Option/Alt+A** after the line number.

[Foundations: A Job With a Name](/foundations/structure/unit-02/) uses named
pseudocode routines. Our number 500 serves as the destination; it is a BASIC
line number, not an address in the Spectrum's memory.

<details>
<summary>What runs immediately after RETURN on the second call?</summary>

Line 92. BASIC returns to the instruction after the call at 89, not to the
question at 60. The routine's text is shared; the return point belongs to the
particular call.

</details>

## Change once and check twice

Replace the divider in line 510 with `"============"`. Run and inspect both
screens. Both should change because both call the same routine. Restore the
hyphens if you prefer their lighter appearance.

<Figure src="/images/sinclair-zx-spectrum/basic/meet-basic/completion/unit-11.png" width={352} alt="The shared ORACLE STONE heading appears above the selected answer." caption="The shared ORACLE STONE heading appears above the selected answer." />

The repeated job is small enough to understand completely. We have not added a
general-purpose layout system: this routine prints one fixed heading wherever
printing currently stands. It relies on the caller having selected readable
colours and a suitable screen position.

Save with `SAVE "oracle"`, export its tape and load it into a fresh emulator,
using [the saving guide](/systems/sinclair-zx-spectrum/basic/meet-basic/unit-02-remember-and-save/).
Check that both screens appear and the toy ends with `9 STOP`. Use `RUN` when you
want another consultation. It does not need an automatic replay loop to be finished.

Ask someone whether the wording makes clear that the response is chosen, not
reasoned out. That honesty is part of the design. Our next project will let a
person control a position rather than type an answer.
