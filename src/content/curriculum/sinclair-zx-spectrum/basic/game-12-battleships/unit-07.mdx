Bounds checking stops ships from running off the grid, but it does not stop them from landing on top of each other. Before placing a ship, we need to check every cell it would occupy. If any cell already contains a non-zero value, another ship is there and the placement must be rejected.

## How It Works

**Lines 80-110** run the overlap check before writing anything to the array. A FOR loop visits each cell the ship would occupy, using the same delta-based calculation from Unit 6. If any cell value is not 0, the variable `e` is set to 1 to flag an overlap.

**Lines 120-140** check the flag after the loop. If `e=1`, the program prints an error message and loops back to ask for a new position. If `e=0`, placement proceeds normally.

**Lines 150-180** write the ship into the array only after both bounds and overlap checks have passed. This ensures the array never contains an invalid placement.

## Check Before Write

This is a defensive programming pattern: validate first, write second. If we wrote the ship cells one at a time and discovered an overlap halfway through, we would need to undo the cells already written. By checking all cells first and only writing when everything is clear, we avoid that rollback problem entirely.

The check loop and the write loop use identical coordinate calculations. The only difference is what they do at each cell — one reads, the other writes. Keeping them in sync is important. If the check loop uses different coordinates from the write loop, ships could pass the overlap test but still collide.

## Try This

**Force an overlap.** Place the Carrier horizontally at A1, then try placing the Battleship horizontally at C1. The Battleship runs from C1 to F1, overlapping the Carrier at C1, D1 and E1. The program should reject it.

**Test adjacent placement.** Place the Carrier at A1 horizontally and the Battleship at A2 horizontally. They should not overlap because they are on different rows, even though they share the same columns.
