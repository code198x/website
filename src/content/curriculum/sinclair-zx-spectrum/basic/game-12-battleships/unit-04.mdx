A grid full of dots is hard to read. Colour makes the difference between a wall of text and a game board. Each cell type gets its own INK and PAPER combination: blue for water, grey for ships, red for hits, white for misses. A glance at the board should tell you everything.

## How It Works

**Lines 30-60** define the colour scheme. Before printing each cell, the code checks the array value and sets INK and PAPER accordingly. Value 0 (empty water) gets blue PAPER with blue INK. Values 1-5 (ship segments) get grey PAPER with white INK. Value 6 (hit) gets red PAPER with yellow INK. Value 7 (miss) gets cyan PAPER with blue INK.

**Lines 70-90** apply colours using embedded colour codes in the PRINT statement. The Spectrum lets you set INK and PAPER inline with `INK n;` before the character.

**Lines 100-120** reset colours after drawing each cell to prevent colour bleeding into adjacent characters.

## Colour Coding

The colour scheme serves gameplay. On the ship grid (left), the player sees:

- **Blue** = open water, no ship, not been fired at
- **Grey** = one of your ships
- **Red** = your ship that has been hit
- **Cyan** = opponent fired here but missed

On the tracking grid (right), the player sees:

- **Blue** = not fired at yet
- **Red** = hit (opponent has a ship here)
- **White/Cyan** = miss (no ship here)

Ships never appear on the tracking grid — that would reveal the opponent hidden fleet.

## Attribute Clashes

Each character cell on the Spectrum has one INK colour and one PAPER colour. You cannot have two different colours within the same 8x8 pixel cell. For a grid where each cell is one character, this is not a problem. But if you try to place labels or borders adjacent to coloured cells, the attributes may clash. Keep labels outside the coloured grid area.

**Try different colour schemes.** Swap red and yellow for hits, or use green for ships. Which combination gives the clearest distinction at a glance?
