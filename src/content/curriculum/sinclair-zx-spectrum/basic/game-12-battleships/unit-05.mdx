Players need to enter coordinates like "D7" to fire shots or place ships. The program must turn that string into two numbers: a column (1-10) and a row (1-10). It also needs to handle lowercase input — a player typing "d7" means the same as "D7".

## How It Works

**Lines 20-30** prompt the player and read the input string with INPUT.

**Lines 40-50** extract the first character using `i$(1)` and convert it to a column number with `CODE i$(1) - 64`. The CODE function returns the character code: "A" is 65, so 65 minus 64 gives column 1. "J" is 74, giving column 10.

**Lines 60-70** handle lowercase. The Spectrum INPUT command uses L-mode, which means typed letters arrive as lowercase. `CODE "a"` is 97, so `97 - 64 = 33` — clearly wrong. The fix: if the column value is greater than 26, subtract 32 to convert from lowercase to uppercase range.

**Lines 80-90** extract the row number from the rest of the string using `VAL i$(2 TO)`. This handles both single-digit ("D7") and double-digit ("D10") coordinates.

**Lines 100-120** validate that the column is 1-10 and the row is 1-10. Out-of-range values loop back to the prompt.

## The Lowercase Problem

On the Spectrum, INPUT starts in L-mode (lowercase). When a player types "d", the program receives the character with code 97, not 68. Subtracting 64 gives 33, not 4. The simplest fix is checking whether the result exceeds 26 — if so, the input was lowercase, and subtracting 32 corrects it. This works because the gap between uppercase and lowercase ASCII codes is exactly 32.

## VAL for Number Extraction

`VAL i$(2 TO)` converts the second character onwards into a number. For "D7", `i$(2 TO)` is "7" and `VAL` returns 7. For "A10", `i$(2 TO)` is "10" and `VAL` returns 10. If the string is not a valid number, `VAL` returns 0, which fails the range check and loops back.

## Try This

**Test edge coordinates.** Try "A1" (top-left corner), "J10" (bottom-right), and "a1" (lowercase). Confirm they all produce correct column and row values.

**Test bad input.** Enter "Z5", "A0", "A11", or just pressing ENTER with no text. Does the program handle each case without crashing?
