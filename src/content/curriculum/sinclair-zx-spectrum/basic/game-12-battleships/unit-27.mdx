Real players make mistakes. They press ENTER without typing anything, enter numbers where letters should go, type coordinates outside the grid, or input strings the program never expected. Robust input handling catches all of these cases and responds with helpful messages instead of crashes.

## How It Works

**Lines 30-40** check for empty input first. If `LEN i$ = 0`, the player pressed ENTER without typing. The program prints "Enter a coordinate (e.g. D7)" and loops back.

**Lines 50-60** check the minimum length. A valid coordinate needs at least two characters — a letter and a digit. If `LEN i$ < 2`, the input is too short.

**Lines 70-90** validate the letter. The first character must be A-J (or a-j). The CODE check ensures the character falls within the expected range. If it does not, the program prints "Column must be A to J" and loops back.

**Lines 100-120** validate the number. `VAL i$(2 TO)` must return a value between 1 and 10. If `VAL` returns 0 (non-numeric input), that is caught by the range check. The program prints "Row must be 1 to 10" for out-of-range values.

**Lines 130-140** validate direction input during placement. Only "H" and "V" (or "h" and "v") are accepted. Anything else triggers "Enter H or V for direction".

## Defence in Depth

Each validation catches a specific class of error:

- **Empty string** — prevents CODE and VAL from crashing on nothing
- **Length check** — prevents slicing beyond the string length
- **Letter range** — prevents nonsense column values
- **Number range** — prevents out-of-bounds array access
- **Direction** — prevents invalid placement

The checks run in order, and each one gates the next. An empty string is caught before the letter check runs. A non-letter is caught before the number extraction. This cascade prevents errors from propagating into the game logic.

## Helpful Error Messages

Generic "Invalid input" messages frustrate players. Specific messages teach: "Column must be A to J" tells the player exactly what went wrong and what to do differently. Each error message answers two questions: what happened, and what should the player do instead.

## Try This

**Hammer the input.** Try every kind of bad input you can think of: empty, single character, numbers only, letters only, special characters, very long strings. The program should handle all of them without crashing.

**Test boundary values.** Enter "A0", "A11", "K1", "a1", "j10". Boundary cases are where bugs hide. Confirm that only valid coordinates are accepted.
