## What You Will Build

A complete two-player battleships game. Each player places five ships on a hidden 10x10 grid, then takes turns firing shots at the opponent. Hits, misses and sunk ships are tracked and displayed. The first player to sink the entire enemy fleet wins.

## Why This Game?

Draughts used a shared board where both players could see everything. Battleships introduces **hidden information**. Each player has their own grid, and the game must keep it secret from the opponent. That means four arrays instead of one, careful screen clearing between turns, and a tracking grid that shows only what you have discovered so far.

This is also the first game where the data model is genuinely complex. Five ships of different lengths, each placed across multiple cells, each with their own health counter. When a shot lands, the program must figure out which ship was hit, whether it has been sunk, and whether the game is over. Array design matters here — the right structure makes everything else straightforward.

## What You Will Learn

### Phase 1: Grids, Ships and Shots (Units 1-16)

- **Four parallel arrays** — separate grids for ships and tracking, per player
- **Grid display with PRINT AT** — column and row headers, two grids side by side
- **INK and PAPER per cell** — water, ship, hit and miss each get distinct colours
- **Coordinate parsing** — converting "D7" into column and row numbers
- **Ship placement** — start coordinate, direction, bounds checking, overlap detection
- **Turn flow with hidden information** — CLS and handover screens between turns
- **Hit and miss tracking** — updating the tracking grid after each shot
- **Sound effects** — BEEP for hits and misses

### Phase 2: Sinking, Winning and Polish (Units 17-32)

- **Ship health arrays** — tracking hit counts per ship per player
- **Sunk detection** — comparing hits against ship length
- **Fleet status display** — showing which ships remain
- **Win condition** — all five ships sunk ends the game
- **Visual feedback** — FLASH on hits, multi-note fanfare for sinking
- **Input robustness** — handling every kind of bad input gracefully
- **Placement review** — letting players redo their layout
- **Rematch flow** — playing again without restarting
