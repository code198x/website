A ship sinks when every cell it occupies has been hit. In data terms, that means the hit count `h(o,v)` equals the ship length `l(v)`. The Destroyer sinks after 2 hits, the Carrier after 5. This unit adds the check that detects sinking and sets the sunk flag.

## How It Works

**Lines 100-120** check for sinking immediately after incrementing the hit counter. The comparison is simple: `IF h(o,v) = l(v) THEN LET k(o,v) = 1`. If Player 2 Submarine (ship 4, length 3) has been hit 3 times, `h(2,4) = 3` equals `l(4) = 3`, so `k(2,4)` is set to 1.

**Lines 130-140** print a sunk message if the flag was just set. The check `IF k(o,v) = 1 AND h(o,v) = l(v)` ensures the message appears only on the turn the ship sinks, not on subsequent turns (the hit counter will not increase further because the cell is already marked as hit).

## The Sunk Array

`k(2,5)` is a boolean-style array: 0 means afloat, 1 means sunk. It serves as a quick lookup — rather than recalculating `h(o,v) = l(v)` every time we need to know whether a ship is sunk, we check `k(o,v)` directly. This matters for the fleet status display and win condition checks coming in later units.

## Why Not Just Check h(o,v)?

We could skip the `k` array and check `h(o,v) >= l(v)` everywhere. But the sunk array gives us:

- **One-time detection** — we set the flag on the exact turn the ship sinks and can trigger a message
- **Fast win checking** — summing `k(o,1)` through `k(o,5)` is faster than comparing five hit counts against five lengths
- **Cleaner code** — `IF k(o,v) = 1` reads more clearly than `IF h(o,v) >= l(v)`

The `k` array is redundant in theory but useful in practice. A small memory cost for cleaner logic is a good trade.

## Try This

**Sink the Destroyer first.** It has length 2, so it sinks fastest. Place it somewhere memorable, hit both cells, and confirm the sunk message appears on the second hit.

**Check the sunk flag.** After sinking a ship, print `k(o,v)` to confirm it is 1. Print `k(o,v)` for a ship that has not been sunk yet to confirm it is 0.
