Lines 200–290 handle the player's turn. Line 200 prints "Your turn!" Line 210 starts a FOR loop — one pass per digit in the sequence. Lines 220–260 wait for a valid key press. Line 270 flashes the panel the player chose. Line 280 loops back for the next digit. Line 285 prints "Done!" when the full sequence is matched.

## Debouncing with INKEY$

Lines 220–230 look redundant but both are essential:

- Line 220: `IF INKEY$ <> "" THEN GO TO 220` — wait until **no** key is held down.
- Line 230: `IF INKEY$ = "" THEN GO TO 230` — wait until a key **is** pressed.

Why both? Imagine the player presses "2" for the first digit. Without line 220, the program immediately reads "2" again for the second digit — the key is still held down. Line 220 waits for the player to release the key before line 230 waits for the next press. One loop drains, the other fills.

Line 240 captures the key into `k$`. Line 250 converts it to a number with `VAL`. Line 260 rejects anything outside 1–4 by jumping back to the release-wait — so pressing "Q" or "7" does nothing.

## Try it

Run the program. Watch the sequence flash, then press the matching keys. The panels flash as you press them — the same `GO SUB 900` subroutine handles both the computer's turn and yours.

Try holding a key down. The debouncing means it only registers once. Now delete line 220 and hold a key — the same digit repeats for every position in the sequence. That single line is the difference between responsive input and chaos.
