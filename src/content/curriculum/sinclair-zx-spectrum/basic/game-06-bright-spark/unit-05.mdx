Lines 230–330 handle the player's turn. Line 230 prints "Your turn!" Line 240 starts a FOR loop — one pass per digit in the sequence. Lines 250–290 wait for a valid key press. Line 300 flashes the panel the player chose. Line 310 loops back for the next digit. Line 320 prints "Done!" when the full sequence is matched.

## Debouncing with INKEY$

Lines 250–260 look redundant but both are essential:

- Line 250: `IF INKEY$ <> "" THEN GO TO 250` — wait until **no** key is held down.
- Line 260: `IF INKEY$ = "" THEN GO TO 260` — wait until a key **is** pressed.

Why both? Imagine the player presses "2" for the first digit. Without line 250, the program immediately reads "2" again for the second digit — the key is still held down. Line 250 waits for the player to release the key before line 260 waits for the next press. One loop drains, the other fills.

Line 270 captures the key into `k$`. Line 280 converts it to a number with `VAL`. Line 290 rejects anything outside 1–4 by jumping back to the release-wait — so pressing "Q" or "7" does nothing.

## Try it

Run the program. Watch the sequence flash, then press the matching keys. The panels flash as you press them — the same `GO SUB 700` subroutine handles both the computer's turn and yours.

Try holding a key down. The debouncing means it only registers once. Now delete line 250 and hold a key — the same digit repeats for every position in the sequence. That single line is the difference between responsive input and chaos.
