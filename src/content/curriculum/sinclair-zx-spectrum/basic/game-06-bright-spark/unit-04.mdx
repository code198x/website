The computer plays the sequence. Now the player repeats it.

<CodeFromFile src="sinclair-zx-spectrum/basic/game-06-bright-spark/unit-04/input.bas" />

Lines 130–240 handle the player's turn:

```
FOR i = 1 TO LEN s$
  IF INKEY$ <> "" THEN GO TO 140
  IF INKEY$ = "" THEN GO TO 150
  LET k$ = INKEY$
  LET p = VAL k$
  IF p < 1 OR p > 4 THEN GO TO 140
  GO SUB 600
  IF k$ <> s$(i) THEN GO TO 400
NEXT i
```

## Key drain

Lines 140: `IF INKEY$ <> "" THEN GO TO 140` — wait until *no* key is pressed. This is **key draining**: if the player is still holding a key from the previous press, the program waits for them to release it before accepting the next input. Without this, a single long keypress would register as multiple inputs.

Line 150 then waits for a new press: `IF INKEY$ = "" THEN GO TO 150`.

## Validation

Line 180: `IF p < 1 OR p > 4 THEN GO TO 140` — if the player pressed a key that is not 1, 2, 3, or 4, ignore it and wait again. Only valid panel keys are accepted.

Line 200: `IF k$ <> s$(i) THEN GO TO 400` — compare the player's key to the expected panel at position `i` in the sequence. If they match, the loop continues to the next panel. If not, game over.

## The mirror

Line 190: `GO SUB 600` flashes the panel the player pressed. The player sees *their* input reflected visually — the same flash and tone the computer used. It feels like playing an instrument: press a key, see the panel light up, hear the tone. The input is mirrored, not just accepted.

## Correct and wrong

If the player gets every panel right, the loop finishes and the program prints "Correct!" then adds another panel to the sequence (GO TO 50). If any panel is wrong, GO TO 400 triggers the game-over sequence — a low buzz and a score.

The game now works: the computer plays, the player repeats, the sequence grows. All that remains is the ending.
