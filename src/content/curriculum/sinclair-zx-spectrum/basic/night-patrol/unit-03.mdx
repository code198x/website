RUN. Walk away from the entrance and return without the file: nothing should end. Reach the file at (27,3), read the changed instruction, then return to (3,16). The result should stay on screen until you choose R or Q.

## Remember an event

got is a flag: zero means the file is still waiting, one means you carry it. Line 380 checks the player's coordinates and sets the flag. The drawing routine now shows the file only while got is zero. When you leave its square, restoring that square produces empty floor.

Line 390 needs both the entrance coordinates and `got=1`. AND means every condition must hold. Merely standing on the entrance cannot win. The message routine at 2500 also reads got, so the instruction follows the same state as the objective.

## Leave the movement loop

outcome starts at zero. A successful return sets it to two and jumps to 4000. We reserve one for capture, which comes with the guard. The result routine redraws the player, prints the ending and waits for a menu choice. It does not return to the movement loop, so holding a direction cannot keep walking after the game ends.

The new 8000 routine reuses the release gate from last lesson, then waits for a fresh key at 8010. A direction held while arriving home is not a result choice. R also waits for release before jumping to 100, where position, got, outcome and steps are reset and the archive is redrawn. Unknown keys return to the result's input routine.

<Question prompt="What would happen if retry reset the position but left got equal to one?">

The player would restart at the entrance already carrying the file. The next objective check could immediately win. Resetting an attempt means resetting its facts as well as its picture.

</Question>

After winning, retry and check that the file is visible again. Retrieve it a second time, then quit from the result. RUN should start another unguarded attempt. These checks exercise two different ways of starting over: the game's own reset and BASIC's program start.
