RUN. Hold **I** to go up, **J** left, **K** down and **L** right. Try uppercase letters too. **R** returns you to the entrance; **Q** ends the program. The file is scenery at this stage.

## Propose, then accept

LET stores values. x and y remember the player position; dx and dy describe a possible change. INKEY$ reports a currently held key, or an empty string when there is none. Each pass clears both offsets before checking the key. An unrecognised key therefore means no movement.

| Key | dx | dy |
|---|---:|---:|
| I | 0 | −1 |
| J | −1 | 0 |
| K | 0 | 1 |
| L | 1 | 0 |

Line 310 calculates nx and ny, the proposed position. Line 320 checks `m$(ny,nx)`. If it contains character 145, the program skips the move. The outside of this map is solid wall, so a player moving one square at a time cannot reach an out-of-range index. Opening a hole in that boundary would require an explicit bounds check.

Only an accepted move replaces x and y. Separating the proposal from the stored position means a rejected move needs no undo operation.

## Restore what was underneath

The routine at 2000 draws one square, using r and c as its requested row and column. It starts with floor, then considers a wall, file, entrance and player. Later choices can replace earlier ones, so the player appears over an object while occupying its square.

Line 340 remembers the old square in r and c before changing x and y. Drawing that square now restores its underlying object. Line 350 draws the new player square. We do not clear and rebuild the whole archive for one footstep. steps counts accepted moves, although this version does not display it as a score.

<Question prompt="Why would printing a blank space behind the player damage the entrance?">

The entrance is drawn over floor. A blank would erase its picture when the player moved away. Reconstructing the square from its position draws the entrance again.

</Question>

## Let go before retrying

A held movement key should repeat. A held R should make one fresh start. Line 220 calls 8100, which waits while INKEY$ is nonempty. Once you release the key, RETURN lets the program restart at 100. GO TO jumps without arranging a return; GO SUB remembers where to come back.

Try every direction, press against a wall, then release all keys. The player should stop. Walk over the entrance and away again: its symbol should survive. Hold R briefly and release it; you should get one reset, not a repeated redraw. If the program stops immediately after drawing, check that line 20 really was deleted.
