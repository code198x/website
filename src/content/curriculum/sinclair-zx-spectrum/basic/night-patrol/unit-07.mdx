Moving the guard changes its view, but much of that view may stay the same. We can prepare only the differences, then let BASIC apply a short record during play.

Keep **Mark what can be seen** running or saved. There are **no program edits in this lesson**. We will work through data now and install it with the moving view next lesson.

## Follow one real step

The guard moves from (7,5) to (8,5), still facing east. Its old mask has eleven cells; its new mask has ten. Here is the actual record for that step:

```basic
8210 DATA 8,5,1,10,5,-168,-137,-201,141,173
```

| Field | Value | Meaning |
|---|---|---|
| gx, gy, gd | 8, 5, 1 | New guard pose |
| bn | 10 | Number visible afterwards |
| n | 5 | Number of changes to read |
| Signed cells | −168, −137, −201, 141, 173 | Three removals, two additions |

A minus sign means remove this cell from sight. It does not mean a negative map coordinate. ABS removes the sign: `ABS -168` is 168, which decodes to (8,5).

| Change | Cell | Map position | Why it matters |
|---|---:|---|---|
| Remove | 168 | (8,5) | Now occupied by the guard itself |
| Remove | 137 | (9,4) | Outside the narrower part of the shifted fan |
| Remove | 201 | (9,6) | Outside the narrower part of the shifted fan |
| Add | 141 | (13,4) | Newly reached |
| Add | 173 | (13,5) | Newly reached |

The unchanged cells are 169, 138, 170, 202, 139, 171, 140 and 172. Write the original eleven indices on paper, cross out the three removals and add the two new ones. You should finish with ten. Those eight unchanged cells need no drawing work.

<Question prompt="Why are bn and n different numbers?">

bn describes the finished view: ten visible cells. n describes the work to reach it: five changes. Counting changes alone cannot tell us the size of the resulting view. In this game bn is read as descriptive data; n controls the update loop.

</Question>

## Give each phase a contract

Every phase record follows the same order: three pose values, visible count, change count, then exactly that many signed cells. READ advances through these values. The next phase uses RESTORE to select its own line, so there is no dependence on the previous record's length.

Startup is different from a step: there is no old view. Line 8900 adds the whole opening mask to an empty v$. Line 8200 represents phase zero with no changes, because phase 60 already ends at the same pose. Runtime steps select phases 1–60, then return to one.

The preparation rule is: removals are cells in the old mask but not the new one; additions are cells in the new mask but not the old one. Cells in both need no entry. The explicit `IF n=0 THEN RETURN` makes a record with no work leave immediately, without reading cells or redrawing the player. Sinclair BASIC can skip an empty FOR range; the guard also makes that no-work contract visible in our routine.

## Prepare elsewhere, play on the Spectrum

These records are ordinary BASIC numbers. The Spectrum reads them; it does not run a hidden machine-code engine. For this fixed map and predictable patrol, computing sight before play trades a larger DATA table for less calculation during each update.

A changed wall, patrol or fan invalidates the prepared views. Keep those three things and the table together. A wandering guard or a door that opens during play would need more preparation or a different runtime approach.
