RUN. The title shows the player, guard, file and exit symbols, explains the sight colour and warns that the guard looks back. Press **S** to start or **Q** to quit. During play hold **I/J/K/L** to move, **R** to retry and **Q** to quit.

## Remember a brief press

INKEY$ handles held movement well, but a short press can begin and end while BASIC is busy elsewhere. The ROM also stores a newly pressed key at address 23560, named LAST K in the manual. If INKEY$ is empty at line 250, CHR$ converts that stored code into k$ instead.

Line 260 clears the stored key after reading it, and line 150 clears it at the start of an attempt. Otherwise the same old press could be reused whenever no key was held. This is one remembered key, not a queue of every press. R and Q are checked again after this read because they can arrive through either path.

## Reset the attempt, keep the map

Line 10 prepares graphics, shows the title, then converts the map strings. Retry jumps to 100, so it does not repeat the map conversion. The map remains the same; an attempt's state must not.

| State | Fresh value |
|---|---|
| Player | (3,16) |
| Guard | (7,5), east |
| phase and beat | 0 |
| got, outcome and steps | 0 |
| v$ | Spaces, then the full opening mask |
| Remembered key | Cleared |
| tick | Current frame-counter byte |

The redraw follows those resets. Line 140 selects the full opening record at 8900, applies it, draws the guard and writes the objective. Starting with an empty mask prevents old sight cells surviving a retry.

The title and result screens use the release-and-read routine at 8000. Movement holds still repeat during play. Keeping those input policies separate makes a held direction useful without turning a held result choice into several attempts.

<Question prompt="Why restore the whole opening view on retry instead of applying phase one's changes?">

Phase one's changes assume the opening view already exists. A retry can follow any phase, so its old view is not that starting point. Clearing the mask and adding the full opening record establishes the required state directly.

</Question>

The finished listing loads one extra graphic pattern at 7540. It is a small dot, unused by this game's drawing routines. The old direction arrays also remain initialised but unused by the phase table. Neither is an extra gameplay feature.

## Play every ending

Start from the title, wait through a full patrol, move into sight and retry. Then fetch the file and return safely. Try lowercase and uppercase controls, a held movement key, a brief tap and an unrelated key. At each result, release your previous key before choosing R or Q. Quit during play too, then RUN to see the title again.

The game is complete: one predictable guard, readable cover and a return journey. The remaining job is keeping a copy that survives closing the emulator.
