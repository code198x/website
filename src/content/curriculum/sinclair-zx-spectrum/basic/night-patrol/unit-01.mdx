A wall is a decision waiting to happen. For now we will draw it; next lesson we will ask the map whether a player may cross it.

Use **Sinclair BASIC on a stock 48K PAL ZX Spectrum**. Begin with a new program and enter this listing. Numbered lines are stored in numerical order. Colons separate statements on one line; gaps between numbers leave space for later work. Enter `RUN` without a line number. The archive, file and entrance should appear, followed by `9 STOP statement, 20:1`. That is the planned end of this drawing program. There is no player to move yet.

## Read a map

Lines 7200–7370 hold eighteen quoted strings, each thirty characters long. A hash marks a wall; a space marks floor. Preserve those spaces when typing. `DIM m$(18,30)` makes eighteen fixed-length strings. `m$(r)` selects a whole row; `m$(r,c)` selects its character at column c. These indices start at one.

DATA stores values in the program. READ consumes the next value; RESTORE chooses where reading begins. The map routine starts at 7200 so it cannot accidentally consume the character patterns instead. Its outer FOR/NEXT loop visits each row, while the inner loop visits that row's columns. It replaces each hash with the brick character, leaving floor as spaces.

Line 10 calls three subroutines with GO SUB: prepare graphics, read the map, draw the screen. RETURN comes back to the statement after the call. This keeps each job together, even though the routines live farther down the listing.

## Make four little pictures

A user-defined graphic has eight rows of eight dots. Each DATA value supplies one row. The dot weights, left to right, are 128, 64, 32, 16, 8, 4, 2 and 1. Add the weights of the dots you want lit. The player's first row is 24: 16 + 8, the two middle dots. The brick's first row is 255: all eight dots.

`USR "a"` gives the memory address of the first graphic's pattern. POKE stores each value there; j runs from 0 through 31 to fill four consecutive eight-byte patterns. This use of USR looks up an address. It does not call machine code. CHR$ turns a character number into a printable character: 144 is our player, 145 the brick, 146 the file and 147 the entrance.

## Map coordinates and screen coordinates

We describe positions as **(column, row)**. The map runs from column 1 to 30 and row 1 to 18. PRINT AT takes **screen row, column**, with screen rows starting at zero. We draw map row r at screen row r + 1, leaving room for two heading rows. Column zero remains a left margin.

| Object | Map position | PRINT AT position |
|---|---|---|
| File | (27, 3) | 4, 27 |
| Entrance | (3, 16) | 17, 3 |

BORDER sets the surrounding border; INK and PAPER select foreground and background colours. CLS clears the display. The map drawing loop prints whole rows, then draws the two objects over their floor squares.
