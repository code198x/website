Lines 120–127 handle input. The player types a compass direction — N, S, E, or W. Each letter is checked against the matching exit array. If the player types "S" and `s(rm) > 0`, then `dest` is set to the room number stored in `s(rm)`. If the exit does not exist, `dest` stays at 0.

Line 130 catches invalid moves. If `dest` is 0 — either the player typed a direction with no exit, or typed something unrecognised — the program prints "You can't go that way!" and loops back. Line 135 updates `rm` to the new room. Line 190 loops back to the display at line 75.

## The string comparison

`IF d$ = "N" OR d$ = "n"` checks for both uppercase and lowercase input. On the Spectrum keyboard, normal typing produces uppercase letters, but the check handles both cases. Each direction gets its own line (124–127), each consulting its own array.

Notice how the direction lookup works: the player's typed letter maps directly to an array. "N" maps to `n(rm)`. "S" maps to `s(rm)`. The arrays are named after the directions they represent. This is not required by the language — we could have used `DIM a(20,4)` — but naming the arrays `n`, `s`, `e`, `w` makes the code read like English: "the north exit from the current room."

## Try it

Run the program and explore. Start in room 1 (exits S and E). Go south to room 5. Go east to room 6. Try to go north from room 6 — "You can't go that way!" Keep going. You will find rooms with two exits and rooms with four. Try to build a mental map as you explore. How far can you get before you lose track of where you are?
