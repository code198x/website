Rolling dice is not interesting. Counting the results *is* interesting — because patterns appear.

<CodeFromFile src="sinclair-zx-spectrum/basic/game-05-dice-roller/unit-03/tally.bas" />

Six counter variables — `t1` through `t6` — one per face. Inside the `FOR` loop, a chained `IF` increments the matching counter on each roll. After 100 rolls, the tallies print.

Run it. Each face appears roughly 15–18 times. Run it again — different numbers, but the same rough distribution. The die does not favour any face; with enough rolls, they converge toward equal.

## Accumulation

That convergence is the design concept: **Accumulation**. Each individual roll is unpredictable — you cannot know what the next one will be. But 100 rolls together reveal the pattern: six faces, roughly equal. The pattern was always there; you just needed enough data to see it.

Try 10 rolls instead of 100 (change line 50 to `FOR i = 1 TO 10`). The tallies are wildly uneven — maybe four 3s and zero 6s. Try 1000. The tallies are almost perfectly equal. More rolls, clearer pattern. That is accumulation.

## Two patterns working together

This program combines two patterns you know:

- **FOR/NEXT** — counted repetition (from this game)
- **Chained IF/THEN** — selection from a set (from Oracle Stone)

The loop generates each roll. The chained IF routes each roll to the right counter. Neither pattern is new; what is new is using them *together*. Most programs are assembled from patterns you already know, combined in new ways.
