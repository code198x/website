## What changed

**Line 50:** `INPUT "How many rolls? "; n` — the player decides the scale. Ten rolls for a quick glance; a thousand for a convincing demonstration. The loop on line 110 uses `n` as its limit: `FOR i = 1 TO n`.

**Lines 270–320:** Bar charts. Each line draws a row of asterisks proportional to the tally:

```
INK 2: FOR j = 1 TO t1: PRINT "*";: NEXT j: PRINT
```

A `FOR` loop inside a `PRINT` — one asterisk per count. `INK 2` (red) for face 1, `INK 6` (yellow) for face 2, and so on. Each face gets its own colour. The result: six horizontal bars, roughly equal length, in six colours.

This is **data visualisation** — turning numbers into pictures. The bar chart shows the distribution at a glance. Equal bars mean a fair die. One long bar and five short ones would mean a biased die. You can *see* fairness.

## The experiment

Run it three times: with 10, 100, and 1000 rolls. Watch the bars:

- **10 rolls:** wildly uneven. One face might not appear at all.
- **100 rolls:** roughly similar, but noticeably uneven.
- **1000 rolls:** nearly identical length. The pattern is clear.

That visual progression — chaos becoming order — is **Accumulation** made visible. The design concept is not abstract; it is six coloured bars getting more equal as the numbers grow.
