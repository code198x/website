## How It Works

**Line 110** initialises the display string: `LET b$ = ""`. It starts empty.

**Lines 230-260** handle a correct keypress:

```
230 IF k$ <> a$(p TO p) THEN ... GO TO 140
240 LET b$ = b$ + k$
250 LET p = p + 1
260 PRINT AT 20, 0; INK 4; b$; "       "
```

Line 240 is the key: `LET b$ = b$ + k$`. This **concatenates** — adds the new character to the end of the existing string. After typing "c", "a", "t", the string grows:

| After typing | `b$` value |
|-------------|-----------|
| c | "c" |
| a | "ca" |
| t | "cat" |

**Line 260** displays the growing string in green. The trailing spaces clear any leftover characters from a previous display.

## Concatenation

`+` joins strings together:

```
LET b$ = b$ + k$
```

This reads `b$`, appends `k$`, and stores the result back in `b$`. It's like `LET n = n + 1` for numbers, but with strings.

## Wrong Keys Are Ignored

Line 230 checks `IF k$ <> a$(p TO p)` — if the key is wrong, jump back to the loop without updating `b$` or `p`. The display string only grows when the player types correctly. Wrong keys are silently rejected.

## Try This

**Show the gap.** Instead of just the typed characters, show what's left too: `PRINT AT 20, 0; INK 4; b$; INK 7; a$(p TO LEN a$)`. The typed part appears green, the remaining part white.

**Backspace.** Add a check for key code 12 (delete): `IF CODE k$ = 12 AND p > 1 THEN LET p = p - 1: LET b$ = b$(1 TO LEN b$ - 1)`. Now the player can correct mistakes.

## What You've Learnt

- **String concatenation** — `b$ + k$` joins strings
- **Growing strings** — build up one character at a time
- **Visual progress** — showing the player what they've typed
- **Silent rejection** — wrong keys don't update the display
