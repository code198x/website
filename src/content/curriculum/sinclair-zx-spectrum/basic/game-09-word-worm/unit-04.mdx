## How It Works

**Line 110** shows the target word at the top: `PRINT AT 0, 0; "Type: "; a$`. The player knows what to aim for.

**Lines 200-220** read and display keypresses:

```
200 LET k$ = INKEY$
210 IF k$ = "" THEN GO TO 130
220 PRINT AT 20, 0; "Key: "; k$; "  "
```

If nothing is pressed, the loop continues — the word keeps falling. If a key is pressed, it's shown at row 20. Either way, the loop runs again.

## Input and Animation in One Loop

This is the key insight. The game loop does two things every iteration:

1. **Check the counter** — should the word move down?
2. **Check the keyboard** — did the player press anything?

Neither blocks the other. The word falls at its own pace. The player types at their own pace. Both happen inside the same loop.

```
130 REM start of loop
...counter logic, word movement...
200 LET k$ = INKEY$
210 IF k$ = "" THEN GO TO 130
220 PRINT AT 20, 0; "Key: "; k$
230 GO TO 130
```

## Try This

**Key echo.** Instead of printing at row 20, print the keypress next to the falling word: `PRINT AT r, 20; k$`. Watch how your typing appears alongside the falling word.

**Count keypresses.** Add `LET g = 0` before the loop and `LET g = g + 1` when a key is pressed. Print the total at the bottom.

## What You've Learnt

- **Non-blocking input** — `INKEY$` reads without stopping
- **Combined loop** — animation and input in the same structure
- **Empty string check** — `IF k$ = ""` means nothing was pressed
- **Display feedback** — showing keypresses to the player
