## One array, six entries

`DIM t(6)` creates a numeric array with six entries, all initially zero. Read `t(2)` as “the tally for face two”. Its valid positions are 1 through 6, the same range produced by the die expression.

Line 450 now stores the face, increases that face's tally and increases n, the total counted rolls. `LET t(d)=t(d)+1` reads the old count and writes back one more. It changes exactly one entry. A second RND call here would be a mistake: the counted face could differ from the one displayed.

The loop counter i says which repetition is running. The variable n says how many rolls have actually been counted. Those values grow together here, but keeping n separate will help when we allow an early stop.

<Question prompt="After faces 2, 2, 6 and 1, what should the six tallies contain?">

In face order they are 1, 2, 0, 0, 0, 1. The total is four. Each roll contributes one to exactly one entry, so the sum increases once per roll.

</Question>

## Give the display two jobs

A subroutine is a group of numbered lines that can be called and returned from. `GO SUB 1000` remembers where to come back, runs the header routine and reaches RETURN at 1090. Execution then resumes after the call. `GO SUB 1100` prints the current totals in the same way.

Line 600 calls both routines after rolling. Line 750 then stops the program. Without that STOP, execution would continue into the routines without a matching call, eventually reaching a RETURN with nowhere to return to.

The header clears the old rolls, prints a title and labels, then places face numbers. PRINT AT takes **row, column**, counted from zero at the top left. The expression `5+2*(j-1)` places faces on rows 5, 7, 9, 11, 13 and 15. The blank rows will hold bars later. Array positions beginning at one and screen coordinates beginning at zero are separate conventions.

The routine at 1100 prints n at the top. Its loop reads each t(j) and places it beside the corresponding face. Trailing spaces after a count erase leftover digits when this routine is reused on a changing display.

RUN again. DIM resets the tallies and line 30 resets n: this is a fresh sample, not twenty-four rolls accumulated across two runs. A wrong total is an accounting problem; an uneven spread is not.

<summary>Keyboard notes</summary>
