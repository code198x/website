RUN and watch the chart form. Each row has twenty possible filled cells, representing a fixed scale from zero to 100%. Try another RUN and hold Q during rolling. The result should say it stopped early; the counts must still add up to the total shown.

## Move the display into the loop

Line 430 draws the frame before rolling. Line 450 counts a roll and increases done, the amount of work completed in this batch. Line 460 calls the display routine. The first calculation therefore has n equal to one, not zero.

INKEY$ reads the currently held key as a string, or an empty string when no key is down. Lines 470–480 accept q or Q and jump to the result at 600. IF runs the statements after THEN only when its condition is true. OR accepts either letter case; GO TO 600 continues at the result routine instead of the next loop iteration. The program checks between display updates, so stopping is not instantaneous while BASIC is printing.

The result redraw includes every counted roll. Line 725 compares done with b to distinguish an early stop from a completed batch. We keep all the counts already made; there is no unfinished roll to subtract.

## Share a fixed scale

Line 1140 calculates `INT (20*t(j)/n+0.5)`. It converts the share into a width from zero to twenty cells, rounding to the nearest cell. Each cell represents five percentage points. A share of 25% fills five cells; 100% fills all twenty.

h$ holds twenty hash characters and z$ holds twenty spaces. A string is text, and its name ends in `$`. `h$(TO width)` takes the first width characters. When width is zero, that slice is empty. `z$(TO 20-width)` supplies the unfilled part. Together they always print twenty characters, erasing any longer bar from the previous update. CHR$ 91 and CHR$ 93 print the surrounding brackets.

Small nonzero shares can round to no filled cells. Keep the numeric column: the coarse bar gives a quick comparison, while the number gives more detail. The percentage is rounded separately to one decimal place.

<Question prompt="Face two has occurred twice in four rolls. The next roll is a six. What happens to face two's count, percentage and bar?">

Its count stays at two. Its share falls from 50% to 40%, and its bar shrinks from ten cells to eight. Every share uses the new total, even though only the face-six tally increased. That is why the display recalculates all six rows.

</Question>

The header is drawn once during rolling. The updating routine overwrites the total, six counts, shares and bars without clearing the whole screen. This keeps the layout in place while the data changes.

If a bar never shrinks, inspect the spaces printed after its hashes. If a larger count looks like an extra digit has survived, inspect the spaces after numeric output. Redrawing text means replacing its old footprint as well as printing the new value.
