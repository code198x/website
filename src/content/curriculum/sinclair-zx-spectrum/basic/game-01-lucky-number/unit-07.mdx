Ten lines. Read them before you type them — you should be able to explain every one:

- **Line 10:** Store the secret number in `n`
- **Line 20:** Set the guess counter `c` to zero
- **Line 30:** Add one to the counter
- **Line 40:** Ask the player for a guess, store it in `g`
- **Line 50:** If the guess equals the number, jump to the ending
- **Line 60:** If the guess is too low, say so
- **Line 70:** If the guess is too high, say so
- **Line 80:** Go back to line 30 for another guess
- **Line 100:** Print the victory message
- **Line 110:** Print how many guesses it took

No mysteries. No black boxes. Every line uses something you've learnt in the last five units.

## Play It

Type `RUN` and play. Binary search works well: start at 50, then 25 or 75, then halve again. You can find any number in seven guesses or fewer.

![The complete text game — six guesses, narrowing in, then "Correct! Found in 6 guesses"](/images/sinclair-zx-spectrum/basic/game-01-lucky-number/unit-07-putting-it-together/complete.png)

The trail of guesses tells the story: too high, too low, too low, too high, too low, correct. Each guess used information from the previous one. The counter tracked them all. "Found in 6 guesses" is the payoff.

## Compare It to Lucky Number

Your text game and Lucky Number do the same thing. The same variables — `n` for the secret, `g` for the guess, `c` for the count. The same logic — three IF/THEN checks, a GO TO loop, a branch to the ending.

The difference is everything around the logic: the rainbow title screen, the big block-pixel digits, the temperature bar, the border colour shifts, the victory celebration. Those are the visual subroutines — the black boxes from Unit 1 that you typed in without understanding.

The game logic is ten lines. The visual polish is another 220. Both matter — the logic makes it work, the polish makes it feel like a game worth playing. But you built the part that matters most: the part that thinks.

## Experiment

The secret number is always 42. That's boring after the first play. Try changing line 10:

- `10 LET n = 7` — a small number, easy to find
- `10 LET n = 99` — right at the top of the range
- `10 LET n = 1` — the edge case

Each one works. The logic doesn't care what `n` is — it compares, decides, and loops regardless. That's the power of variables: the same code handles any number.

But wouldn't it be better if the number were different every time? That's the last piece of the puzzle.

## What You've Learnt

- **Ten lines** make a complete game — no line is wasted
- **Every concept connects:** LET stores, INPUT asks, IF/THEN decides, GO TO loops
- **A guess counter** uses `LET c = c + 1` inside the loop
- **The game logic** is the same whether surrounded by visual subroutines or not
- **Variables make code flexible** — change `n` and the game changes with it
