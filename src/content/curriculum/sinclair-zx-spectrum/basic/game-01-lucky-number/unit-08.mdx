## The Title

```basic
20 PRINT "== Lucky Number =="
30 PRINT
```

Line 20 prints the game's name. The `==` either side is decoration — it makes the title stand out. Line 30 is `PRINT` with nothing after it, which prints a blank line. It adds a gap between the title and the game, so the screen doesn't look cramped.

## The Guess Counter

```basic
50 LET c = 0
```

This creates a variable `c` to count guesses. It starts at zero because the player hasn't guessed yet.

```basic
70 LET c = c + 1
```

Every time the player makes a guess, this line adds 1 to `c`. The first time through, `c` goes from 0 to 1. The second time, from 1 to 2. And so on.

This is a pattern you'll use constantly: `LET c = c + 1`. It looks odd — how can `c` equal itself plus one? It works because the Spectrum calculates the right side first (`c + 1`), then stores the result back in `c`. It's not an equation; it's an instruction. "Take what's in `c`, add 1, put the result back."

## The Victory Message

```basic
120 PRINT "Correct!"
130 PRINT "You got it in "; c; " guesses."
```

Line 130 uses **semicolons** to print text and a variable on the same line. The Spectrum prints three things one after another:

1. `"You got it in "` — the text (with a space after "in")
2. `c` — the value of the guess counter
3. `" guesses."` — more text

The semicolons connect them. Without semicolons, each would print on its own line. With semicolons, they flow together into one sentence.

This is the first time you've mixed strings and numbers in a single PRINT line. The rule is simple: separate each item with a semicolon, and the Spectrum prints them all on one line, left to right.

## GO TO Instead of STOP

In Unit 6, the program used `IF g = n THEN STOP` to end the game. Now it uses:

```basic
80 IF g = n THEN GO TO 120
```

Instead of stopping immediately, it jumps to line 120 — the victory message. The program prints "Correct!" and the guess count, then ends naturally because there are no more lines to run.

`STOP` was fine when all the program had to do was stop. But now there's a victory message to print first, and `GO TO` lets you jump to it.

## The Complete Flow

1. **Lines 10-30** — Title and setup. Runs once.
2. **Lines 40-50** — Pick the random number and reset the counter. Runs once.
3. **Line 60** — Ask for a guess. The loop starts here.
4. **Line 70** — Count the guess.
5. **Line 80** — If correct, jump to the victory message.
6. **Lines 90-100** — Print "Too low!" or "Too high!"
7. **Line 110** — Loop back to line 60.
8. **Lines 120-130** — Victory message. Only reached by the GO TO on line 80.

## Try This

**Best score.** Play the game five times. What's your best (lowest) number of guesses for a number between 1 and 100? If you use the halving strategy (guess 50 first, then halve the remaining range each time), you can always find it in 7 guesses or fewer.

**Personalise it.** Add `INPUT "Your name: "; n$` near the start and change line 120 to `PRINT "Well done, "; n$; "!"`. Now the game knows who's playing.

**Change the range.** Make it 1 to 10 for an easy game, or 1 to 1000 for a hard one. Remember to change both the `RND` formula and the prompt.

## What You've Learnt

- **PRINT with semicolons** — `PRINT "text"; variable; "text"` prints everything on one line
- **Counting** — `LET c = c + 1` adds 1 to a variable each time it runs
- **Blank lines** — `PRINT` with nothing after it prints an empty line
- **GO TO for flow control** — jumping to a specific section instead of using STOP
- **Program structure** — setup at the top, loop in the middle, ending at the bottom
