So far your programs talk *at* the player. They print messages and numbers, but they never listen. A guessing game needs to listen — the player has to type a guess.

That's what `INPUT` does. It stops the program, waits for the player to type something, and stores whatever they type in a variable.

The Spectrum prints `7`. Here's what happened:

- **Line 10** — `INPUT a` stops the program and waits. Whatever number you type gets stored in the variable `a`.
- **Line 20** — `PRINT a` prints the value in `a` — the number you just typed.

Run it again. Type a different number. The output changes because `a` holds whatever you gave it.

## Asking for Text

Variables like `a` and `g` hold numbers. But what if you want to ask for a name? You need a **string variable** — a variable that holds text instead of a number.

String variables have a `$` sign after the name. `n$` is a string variable. `name$` is a string variable. The `$` is the signal: this variable holds text.

<CodeFromFile src="sinclair-zx-spectrum/basic/game-01-lucky-number/unit-03/input-name.bas" />

Run it. The prompt asks for your name. Type your name and press **ENTER**.

![Hello, alex printed on screen](/images/sinclair-zx-spectrum/basic/game-01-lucky-number/unit-03-asking-a-question/input-name.png)

The Spectrum greets you by name. Notice the semicolon in `PRINT "Hello, "; n$` — it makes the Spectrum print everything on the same line. Without the semicolon, `Hello,` and your name would appear on separate lines.

## Number Variables vs String Variables

This is important:

- `INPUT g` — waits for a **number**. The player types digits. The value is stored as a number you can do maths with.
- `INPUT n$` — waits for **text**. The player types letters, words, anything. The value is stored as a string.

If you use `INPUT g` and the player types letters instead of a number, the Spectrum shows an error. It expects a number and won't accept anything else. String variables accept everything — numbers, letters, spaces, the lot.

For the guessing game, you'll use `INPUT g` because guesses are numbers.

## The Semicolon in PRINT

You've seen two uses of the semicolon now:

- In `INPUT` — `INPUT "Pick a number: "; g` connects a prompt to a variable
- In `PRINT` — `PRINT "Hello, "; n$` prints two things on the same line

Without the semicolon in PRINT, each PRINT statement starts a new line. With a semicolon, the next item continues on the same line. You'll use this a lot.

## Try This

**Ask and repeat.** Write a program that asks `INPUT "Tell me a word: "; w$` and then prints the word three times using three PRINT lines.

**Two questions.** Ask for a name and then a favourite number. Print both. You'll need two INPUT lines and two PRINT lines.

**What happens if you type text into a number INPUT?** Try `INPUT a` and type "hello" instead of a number. See the error message? That's the Spectrum telling you it expected a number.

## What You've Learnt

- **INPUT** — stops the program and waits for the player to type something
- **Prompts** — `INPUT "message"; variable` shows a message before the cursor
- **String variables** — names ending in `$` hold text (`n$`, `name$`)
- **Number vs string input** — `INPUT g` expects a number; `INPUT n$` accepts text
- **Semicolons in PRINT** — `PRINT "text"; variable` prints everything on one line
