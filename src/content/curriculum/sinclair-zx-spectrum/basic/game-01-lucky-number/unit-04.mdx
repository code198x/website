So far, your programs have talked *at* the player. PRINT puts text on screen, but the player has no way to respond. The program runs and finishes. No conversation.

Lucky Number is different. It asks a question — "Your guess?" — and waits. The player types a number. The game uses that number. That's `INPUT`.

Type `RUN`. The screen clears and a prompt appears at the bottom: **Pick a number:** followed by a flashing cursor. The program is waiting. It won't continue until you type something.

Type a number — say, `7` — and press ENTER. The screen shows: `You picked 7`.

`INPUT` does two things. First, it displays the prompt string — the text in quotation marks. Second, it waits for the player to type a value and stores it in the variable after the semicolon. In this case, the player's answer goes into `g`.

After INPUT finishes, `g` holds whatever number the player typed. Line 20 prints it back, proving the program heard them.

## Numbers Only (For Now)

INPUT expects a number. If you type a word instead of a number, the Spectrum will complain. Variables that hold text have a `$` at the end of their name — like the `k$` and `a$` you typed in Lucky Number. We'll explore text variables in a later game. For now, stick to numbers.

## INPUT vs PRINT

`PRINT` talks to the player. `INPUT` listens. Together, they create a conversation:

1. The program says something (PRINT)
2. The program asks a question (INPUT)
3. The player answers
4. The program uses the answer (LET, PRINT, or anything else)

That's the structure of every interactive program. Lucky Number does this in a loop — ask, respond, ask again — but the building blocks are the same ones you just used.

This conversation is what makes games interactive. The player has **agency** — their input matters, the game responds to it, and the response changes what the player does next. A program that only PRINTs is a slideshow. A program that PRINTs and INPUTs is a conversation. That's the difference between watching and playing.

## What You've Learnt

- **INPUT** displays a prompt and waits for the player to type a value
- The answer is stored in a **variable** — `INPUT "prompt"; g` puts the answer in `g`
- You can **use the answer** in calculations — `a + 10`, `g + h`
- **Each INPUT overwrites** the variable — typing a new guess replaces the old one
- **PRINT talks, INPUT listens** — together they make programs interactive
