Run it. The screen goes black. A title appears: `*** STORY BUILDER ***`. Six questions follow. Then the screen clears, a short beep sounds, and the story prints in cyan.

The story is the same shape as before — questions in, narrative out. But it *feels* different. The black background, the title, the pause before the reveal, the colour shift when the story appears — these turn a working program into a *thing*.

## What changed

**Line 20** sets the stage: `INK 7` (white text), `PAPER 0` (black background), `BORDER 0` (black border), then `CLS` to repaint the whole screen. The Spectrum starts with white paper and black ink — we reversed it.

**Line 30** prints a title. The asterisks are decoration — they frame the name and make it feel like a header, not just another line of text.

**Lines 140–150** create the dramatic pause. `PAUSE 50` waits one second (the Spectrum runs at 50 frames per second). `BEEP 0.1, 24` plays a short high tone — a "here it comes" signal. The player is waiting. That wait is deliberate: the moment before the reveal matters more than the reveal itself.

**Line 160** switches to `INK 5` (cyan). From this point, everything prints in a different colour. The colour shift tells the player "this is the output, not the input" without saying so in words.

**Line 290** switches back to `INK 7` (white) for the closing line. The story lives in its own colour.

## The design lesson

None of these changes affect what the program *does*. It still asks questions and prints a story. But they change what it *feels like*. The black screen creates focus. The pause creates anticipation. The colour shift creates a boundary between asking and telling.

This layer — presentation, timing, atmosphere — is what game designers call **polish**. Polish does not change the mechanics. It changes the experience. A program without polish works. A program with polish *works on you*.

## Make it yours

Write your own questions. Write your own story template. Change the colours — try `INK 4` (green) or `INK 2` (red) for the story. Change the pause length — `PAUSE 100` for more drama, `PAUSE 25` for less.

Add more questions. Add more story. The program is yours now.

Then show it to someone. Watch their face when the story appears. That reaction is what programs are for.

## What you have learnt

Across four units, you have met:

| Command | What it does |
|---------|-------------|
| `PRINT` | Puts text on the screen |
| `CLS` | Clears the screen |
| `INPUT` | Asks a question, stores the answer |
| `INK` | Sets the text colour |
| `PAPER` | Sets the background colour |
| `BORDER` | Sets the border colour |
| `PAUSE` | Waits for a number of frames |
| `BEEP` | Plays a tone |

And three ideas:

- **String variables** (`n$`, `a$`) remember text.
- **Semicolons** join text and variables into one line.
- **Polish** changes how something feels without changing what it does.
