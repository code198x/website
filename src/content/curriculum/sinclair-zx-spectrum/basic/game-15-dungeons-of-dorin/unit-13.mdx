## How It Works

**Lines 180-184** check for monster collision during movement. Before the player moves to a new cell, a loop checks all monster positions. If a living monster (HP greater than 0) occupies the target cell, combat begins. The variable `i` is set to the monster index, and the combat subroutine at line 800 is called.

**Lines 800-814** set up the combat screen. The monster type index `l(i)` is used to READ the monster DATA for its name, stats, and gold value. CLS clears the screen to make room for the combat display.

**Line 814** prints the combat header: "COMBAT:" followed by the monster name in red, bright text. This immediately tells the player what they are fighting.

**Line 816** shows both HP values — the player current HP and the monster current HP. Seeing both numbers lets the player judge whether to fight or flee.

**Lines 822-828** present the combat menu: A to attack, F to flee. PAUSE 0 waits for input. Invalid keys loop back to wait again.

## Mode Switching

The combat trigger represents a mode switch. The program has two distinct modes: exploration (viewport, movement, fog of war) and combat (text-based, turn-by-turn). The switch happens when the player walks into a monster, and switches back when combat ends (through victory, death, or fleeing).

CLS is the visual marker of this transition. The dungeon disappears and the combat screen takes its place. When combat ends, the dungeon redraws. This is not subtle, but it is clear — the player always knows which mode they are in.

## DATA and RESTORE

The combat setup uses RESTORE 1500 to reset the DATA pointer to the monster table, then READs forward to the correct entry. This is the standard pattern for accessing specific records in a DATA block when you know the index. The loop on line 806 skips entries before the target, and line 808 reads the one that matches.
