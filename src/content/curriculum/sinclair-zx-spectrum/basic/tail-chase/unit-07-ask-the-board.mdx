## Two views of one body

`DIM g(16,24)` creates one numeric entry for every world cell. Zero means free; one means snake. Initialisation marks the same four cells placed in a and b. Food is stored separately and does not count as snake occupancy.

Line 310 reads `g(nr,nx)`. The bounds check still comes first: an out-of-range candidate is rejected before the grid can be indexed.

An occupied square is normally blocked. The exception requires both **no growth** and **the exact departing tail square**. The source rejects occupancy when grow is 1, or either coordinate differs from the tail. If neither coordinate differs and the tail leaves, the move is legal.

The body scan routine is now removed. The ordered arrays remain: a grid alone cannot identify which occupied cell should disappear next.

## Keep both representations consistent

For an ordinary move, clear the departing cell in g and erase its picture. Then advance the tail. After choosing the new head slot, write its coordinates and mark that new cell in g. On growth, skip the clearing and tail advance.

The order matters when the head enters the departing tail square. Clear that cell first, then mark it occupied for the new head. Reversing those writes would leave a visible head on a cell the grid calls free.

The board has 384 entries, but the moving loop does not scan all 384. It reads the candidate and updates the changed cells. Initialisation still prepares the whole grid. This trades extra stored state for a direct occupancy question; every state change must honour that agreement.
