## Capacity is not length

The arrays now have **twelve slots**, but only **four live cells**. `t` identifies the tail slot and `h` the head slot. Start with t=1 and h=4. On an ordinary move, advance t to 2 and h to 5, then write the new head in slot 5. Slots 2–4 keep their coordinates.

The old values in slot 1 remain in memory. They are no longer part of the body. Likewise, a zero in an unused slot does not describe a snake cell at world (0,0). The live body starts at t and contains exactly n positions.

After slot 12, the next slot is 1. The checks at lines 350 and 390 implement that wrap. This is a **circular buffer**: the storage is reused in a circle while the snake can move in any legal direction.

| Before | Ordinary move | Growing move, introduced next |
|---|---|---|
| Live slots 9,10,11,12 | Live slots 10,11,12,1 | Live slots 9,10,11,12,1 |
| Tail 9, head 12, length 4 | Tail 10, head 1, length 4 | Tail 9, head 1, length 5 |

Wrapping an array index never wraps a world coordinate. The wall rule is unchanged.

## Find the live cells

The collision scan starts `slot` at t and visits n positions. It increments slot and wraps it after 12. `j` counts how many live positions have been visited; it is no longer necessarily the array index. On an ordinary move the first live position is excluded because that tail leaves.

The old shifting version copied three row/column pairs per move before writing the head. This version changes indices and writes one new pair. That counts one kind of work; it does not measure the whole BASIC loop, which still scans the body and draws characters.

At each stop, enter `PRINT t;" ";h;" ";n`. To inspect all allocated pairs in the circular copy, enter:

```basic
FOR j=1 TO 12: PRINT j;" ";a(j);" ";b(j): NEXT j
```

The inspection may disturb the picture; the stored coordinates are what we are comparing. Enter CONTINUE to reach the next stop, predicting again before inspecting. STOP and PRINT change timing, so this is not a speed test.
