## Keep positions in order

`a(1)` and `b(1)` form the tail's row and column. Slots 2 and 3 hold the middle cells. Slot 4 holds the head. `DIM a(4)` and `DIM b(4)` create two numeric arrays with four positions each. The arrays work as a pair: changing a row without its matching column would describe a different square.

The starting positions are (8,6), (8,7), (8,8), (8,9). After a step right they should be (8,7), (8,8), (8,9), (8,10). Save this idea before reading the copying loop: discard the oldest position and append one new position.

Line 390 copies slot 2 into 1, then 3 into 2, then 4 into 3. Line 400 writes the new head into slot 4. In this version `t=1` and `h=4` remain fixed. `n=4` records the number of live cells. `grow` is always zero for now.

The new body graphic, code 149, uses row bytes 0,60,126,126,126,126,60,0. Its blank corners and full middle distinguish it from the face. The old head becomes a body cell, the departing tail is erased, and the new head is drawn. The middle cells already look right.

## Check the proposed square

The routine at 3500 scans slots 2 through n, setting `hit=1` if any row/column pair equals the candidate. It skips slot 1 because the tail is leaving on this move. A candidate outside the arena was already rejected before this scan.

Only after the tests pass do we erase or copy anything. The picture reports the coordinates; its colours never decide collision.

<Question prompt="Why not copy slot 4 into 3 first, then slot 3 into 2?">

That second copy would read the new value of slot 3, losing its original position. Copy towards lower indices in ascending order so each source is read before it is overwritten.

</Question>

From the starting position, turn down, left, then up on consecutive moves. The head can enter the starting tail square because the tail has already advanced. Check that four distinct cells remain, then retry. A bend that stretches or duplicates the body usually points to copying order or a mismatched row and column.
