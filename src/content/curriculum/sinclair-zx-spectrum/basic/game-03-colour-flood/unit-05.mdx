## How the Check Works

The FOR/NEXT loop runs through the sequence string, one character at a time:

1. **Lines 76-78** — debounce: wait for any held key to be released, then wait for a new press.
2. **Line 80** — `LET k$=INKEY$` captures the key.
3. **Line 82** — `LET c=VAL s$(i)` gets the expected colour number.
4. **Line 84** — `IF k$=STR$ c` compares the key pressed against the expected colour. If they match, jump to line 100 (correct). If not, fall through to line 88 (wrong).

The comparison `k$=STR$ c` works because INKEY$ returns a string ("2") and `STR$ c` converts the expected number to a string ("2"). Strings compare with `=` just like numbers.

## Correct vs Wrong

- **Correct** (lines 100-108) — border flashes the player's colour, BEEP at the right pitch, short pause, border back to black. The loop continues to the next colour.
- **Wrong** (lines 88-94) — border turns red, low BEEP, "Wrong!" message, program stops.

## Try This

- Change the hardcoded sequence to `s$="111"`. All blue — easy to test.
- Press the wrong key deliberately. Does the red border and low BEEP feel like a clear error signal?
- Change the correct BEEP pitch from `VAL k$*3` to `VAL k$*5`. The tones spread further apart.

## What You've Learnt

- **String comparison** — `k$=STR$ c` compares the player's key against the expected colour
- **Debounce pattern** — wait for release, then wait for press; prevents one keypress counting twice
- **Immediate feedback** — correct keypresses flash the colour; wrong keypresses flash red
- **FOR/NEXT through a string** — the loop index reads each character in sequence
