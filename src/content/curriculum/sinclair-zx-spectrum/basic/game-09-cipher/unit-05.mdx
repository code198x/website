## The word list

Lines 30–60 hold 20 words in DATA — four lines, five words each. All computing-themed: SPECTRUM, COMPUTER, KEYBOARD, PROGRAM, SCREEN, and so on.

## Random selection with RESTORE

Line 80: `LET pick = INT (RND * total) + 1` — a random number from 1 to 20.

Line 90: `RESTORE` — this rewinds the DATA pointer back to the beginning. Without RESTORE, the second round would continue reading from wherever the first round left off.

Line 100: `FOR i = 1 TO pick: READ w$: NEXT i` — read through DATA until you reach the chosen word. If `pick` is 7, this reads (and discards) words 1–6, then keeps word 7 in `w$`.

This is the **RESTORE + counted READ** pattern for random selection from DATA. It is the pre-array technique — you do not need DIM or indexed access. Just rewind, count forward, and take what you find.

## The design lesson

Look at the game's logic: the guessing loop, the letter check, the lives, the display — none of it changed. Only the DATA changed. You added 19 words and a random picker. The *code* is the engine; the *DATA* is the content.

That separation is the headline concept: **Data-Driven** design. The same engine plays differently because the content it reads is different. Change the words, change the game. Add more words, make the game last longer. Use shorter words, make it easier. Use longer words, make it harder. One program, infinite variations.

Try adding your own words. Each one is a single DATA entry — no code change needed.
