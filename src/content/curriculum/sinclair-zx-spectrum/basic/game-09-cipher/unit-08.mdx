## What changed

**Title screen (lines 30–80).** Instructions and `PAUSE 0`. The player knows the rules before the first word appears.

**Lives bar (lines 310–330).** Instead of a number, lives display as green asterisks: `*****` for 5 lives, `***` for 3. The bar shrinks visually as lives are lost — a resource gauge, like Touchdown's fuel bar.

**Consistent layout.** Title, score, word, lives, tried letters, prompt, feedback — all at fixed positions. The screen is a dashboard the player reads without thinking.

## The design lesson

Open the program and look at lines 90–120 — the DATA. Twenty words. Now change them:

```
90 DATA "DOG","CAT","FISH","BIRD","FROG"
100 DATA "LION","BEAR","DEER","WOLF","DUCK"
```

Run it. The game is now an animal-guessing game. The logic did not change — the display, the lives, the letter checking, the score tracking — all identical. Only the words changed.

That is **Data-Driven** design. The code is the engine. The DATA is the content. The same engine serves any word list: computing terms, animals, countries, football teams, characters from a book. One program, infinite games.

This separation — content vs logic — is how every modern game works. A level editor changes the levels, not the physics engine. A modding tool changes the weapons, not the combat system. Cipher is the simplest form of that idea: the DATA is the level editor, and you are the level designer.

And two design concepts:

- **Data-Driven** — the content shapes the experience, not the code. Change the DATA, change the game.
- **Difficulty curve via content** — short words are easier, long words are harder. No code change needed.
