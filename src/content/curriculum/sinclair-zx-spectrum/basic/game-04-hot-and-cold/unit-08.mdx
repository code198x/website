Twenty-six lines. A hidden treasure. A cursor. INKEY$ for movement. SQR for distance. Border colour for feedback. Win detection. The complete game loop:

1. **Input** (line 100-110) — wait for INKEY$
2. **Erase** (line 120) — remove the cursor
3. **Update** (lines 130-160) — change x/y based on the key
4. **Draw** (line 170) — show the cursor at new position
5. **Calculate** (line 190) — distance to treasure
6. **Feedback** (lines 200-230) — border colour from distance
7. **Check** (line 240) — has the player won?

## The Universal Pattern

Every game you've built has a loop:

| Game | Loop structure |
|------|---------------|
| Lucky Number | INPUT → compare → feedback → GO TO |
| Wire Panic | countdown → check INKEY$ → decrement → GO TO |
| Bright Spark | play sequence → wait for input → compare → GO TO |
| Hot and Cold | INKEY$ → move → calculate → feedback → GO TO |

Lucky Number's loop waited for INPUT — turn-based. Wire Panic's loop ran on a timer — countdown-driven. Bright Spark's loop alternated between computer and player — sequence-driven. Hot and Cold's loop runs continuously — player-driven.

All four are the same pattern. The difference is *what triggers the next pass*: player input, a timer, a sequence, or continuous polling. Game designers choose the loop type based on the experience they want:

- **Turn-based** (INPUT) — thoughtful, no time pressure
- **Timed** (PAUSE + countdown) — urgent, escalating pressure
- **Sequence-based** (FOR through a pattern) — call-and-response
- **Continuous** (INKEY$ polling) — fluid, immediate, real-time

From here on, every game uses a continuous loop. Hot and Cold is where the training wheels come off.

Four games. Four design concepts. Half the Foundations phase complete.

| Game | Design concept | Key insight |

Game 5 — **Letter Soup** — teaches **content vs logic**: separating what varies (the word list) from what's fixed (the scramble-and-check mechanics). It introduces DATA/READ, string slicing, and the principle that makes games moddable.
