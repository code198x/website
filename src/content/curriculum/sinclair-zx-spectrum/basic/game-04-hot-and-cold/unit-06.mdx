The game loop runs: move, calculate distance, update border. But it needs to *end*. When does the player win?

```
470 IF x=tx THEN IF y=ty THEN GO TO 600
```

When the cursor's position (x, y) exactly matches the treasure's position (tx, ty), the game jumps to the celebration. Two conditions, both must be true — the x coordinates match AND the y coordinates match. This is the **win condition**.

Hot and Cold's win condition is simple: be on the same cell as the treasure. Later games will have more complex conditions — score thresholds, all items collected, boss defeated — but the principle is the same: a test that, when true, transitions the game from "playing" to "won."

The celebration (lines 600-690) uses familiar patterns: border strobing with random colours, ascending BEEPs, the treasure revealed with FLASH, and a centred "FOUND IT!" message. The celebration exists because **reward** makes finding the treasure feel like an achievement, not just a state change. Without the fanfare, the game would just... stop.

## What You've Learnt

- **Win conditions** test whether the player has achieved the goal
- `IF x=tx THEN IF y=ty` — both coordinates must match (nested IF for AND)
- **Celebrations** transform a state change into a felt achievement
- The transition from "playing" to "won" is a **state change** in the game
