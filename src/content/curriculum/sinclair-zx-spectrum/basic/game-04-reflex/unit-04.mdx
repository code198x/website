A number alone does not tell the player much. "Your time: 12" — is that good? Add a rating and a colour, and the number comes alive.

Lines 150–180 map the time to a word and a colour:

| Time | Rating | Colour |
|------|--------|--------|
| Under 5 | Lightning! | Green (4) |
| 5–14 | Quick! | Cyan (5) |
| 15–29 | OK | Yellow (6) |
| 30+ | Slow... | Red (2) |

The `AND` keyword lets you check two conditions at once: `IF t >= 5 AND t < 15` means "between 5 and 14 inclusive." You saw this pattern in Lucky Number's border feedback — same idea, different context.

## Multi-channel feedback, again

The player now gets three channels:

1. **Number** — the raw time, for precision.
2. **Word** — the rating, for meaning.
3. **Colour** — green to red, for instant emotional read.

You built the same three-channel pattern in Lucky Number (distance → border colour → directional sound). The channels are different but the principle is identical: say the same thing multiple ways, and the player absorbs it faster than any single channel alone.

## Calibrating

Are the thresholds fair? Run the program ten times and note your scores. If you consistently hit 8–12, the "Quick" band should cover that range. If "Lightning" is impossible, widen it.

The thresholds are design decisions, not code decisions. The code works at any setting; the *feel* depends on getting the bands right for a human player.
