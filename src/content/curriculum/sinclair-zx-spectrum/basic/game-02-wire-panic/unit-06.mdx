In Lucky Number, you stored numbers in variables: `LET n=42`, `LET c=0`. Numbers are useful for counting, calculating, and comparing. But INKEY$ doesn't return a number — it returns a *character*. When the player presses "3", INKEY$ gives you `"3"` — the text character three, not the number three.

To work with text, you need **string variables**.

## Strings Have Names Too

A string variable holds text instead of a number. Its name ends with `$`:

<CodeFromFile src="sinclair-zx-spectrum/basic/game-02-wire-panic/unit-06/string-var.bas" />

![Hello, Spectrum — then Hello, World](/images/sinclair-zx-spectrum/basic/game-02-wire-panic/unit-06-text-variables/string-var.png)

`n$` holds `"Spectrum"`, then it changes to `"World"`. The `$` at the end of the name tells the Spectrum this variable holds text, not a number. Without the `$`, the Spectrum would expect a number and complain.

You've already used string variables without realising: `LET k$=INKEY$` in Unit 5 stored the pressed key in `k$`. Every time you wrote `IF k$=""`, you were comparing a string variable to an empty string.

## Comparing Strings

String comparison works the same way as number comparison — with `=`:

<CodeFromFile src="sinclair-zx-spectrum/basic/game-02-wire-panic/unit-06/compare.bas" />

The secret is `"b"`. INKEY$ returns the pressed key in `k$`. Line 60 compares them: `IF k$=secret$`. If they match, you win. If not, the program tells you what you pressed and tries again.

This is the exact pattern Wire Panic uses to check which wire the player cut. The secret wire is stored in a string variable, the pressed key is stored in another, and the comparison decides whether you live or die.

## How Wire Panic Uses String Variables

Here are the relevant lines from the game:

Lines 50-80 convert the random wire number `w` (a number, 1-4) into `w$` (a string, "1"-"4"). This is necessary because INKEY$ returns strings, not numbers. You can't compare a string to a number — `k$=w` would fail. You need `k$=w$` — string compared to string.

Line 650 captures the keypress. Line 810 compares it: `IF k$=w$ THEN GO TO 1000`. If the player pressed the correct wire's key, jump to defusal. If not, fall through to explosion.

The conversion on lines 50-80 is a bit clumsy — four IF/THEN lines to turn a number into a string. Later in the curriculum (Game 5), you'll learn `STR$` which does this in one step. For now, the explicit approach shows exactly what's happening: the number 3 and the string "3" are different things, and you sometimes need to convert between them.

## Numbers vs Strings

| | Numbers | Strings |
|---|---------|---------|
| **Variable name** | `n`, `c`, `g` | `n$`, `k$`, `w$` |
| **Stored value** | A number: `42`, `0`, `-5` | Text: `"hello"`, `"3"`, `""` |
| **Arithmetic** | Yes: `n+1`, `c*2` | No |
| **Comparison** | `g=42`, `n>10` | `k$="3"`, `w$=secret$` |
| **PRINT** | Shows the number | Shows the text |
| **From keyboard** | INPUT gives numbers | INKEY$ gives strings |

The key insight: `3` and `"3"` are different things. The number 3 can be added, multiplied, compared with `<` and `>`. The string `"3"` is a character — it can be compared with `=` but not added to other numbers. INKEY$ gives you strings. Arithmetic needs numbers. String variables bridge the gap.

## What You've Learnt

- **String variables** end with `$` — `k$`, `w$`, `n$`
- They hold **text**, not numbers — `"hello"`, `"3"`, `""`
- **String comparison** uses `=` — `IF k$="3" THEN...`
- **INKEY$ returns strings** — the character, not the number
- **Numbers and strings are different types** — `3` ≠ `"3"`
- Wire Panic converts `w` (number) to `w$` (string) so it can compare with `k$`
