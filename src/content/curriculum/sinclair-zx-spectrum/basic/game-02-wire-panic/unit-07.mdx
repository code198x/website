You now have every piece: CLS clears the screen, PRINT AT positions text, PLOT/DRAW creates graphics, BEEP makes sound, INKEY$ checks the keyboard, and string variables compare keys. What's missing is *time* — the thing that makes Wire Panic urgent.

## PAUSE — Waiting

`PAUSE n` stops the program for `n` fiftieths of a second. The Spectrum runs at 50 frames per second, so `PAUSE 50` waits one second. `PAUSE 25` waits half a second. `PAUSE 100` waits two seconds.

<CodeFromFile src="sinclair-zx-spectrum/basic/game-02-wire-panic/unit-07/pause-demo.bas" />

"Wait for it..." appears, two seconds pass, then "Two seconds later!" appears. PAUSE controls the rhythm of the game — how fast things happen.

**Important:** PAUSE also breaks early if the player presses a key. This means a player can interrupt a PAUSE by pressing something — which is exactly what Wire Panic needs. The game pauses between ticks, and the player can act during that pause.

![The countdown at zero — "Time is up!"](/images/sinclair-zx-spectrum/basic/game-02-wire-panic/unit-07-counting-down/timeup.png)

Eight lines. `t` starts at 10 and decreases by 1 each tick. Each tick: display the number (PRINT AT), play a sound (BEEP with pitch matching `t`), wait (PAUSE 50 = one second), subtract 1, and loop back. When `t` drops below 0, the countdown is over.

This is the heartbeat of Wire Panic — stripped to its simplest form. A variable counting down, a display updating, a sound ticking, a pause between ticks.

This is the structure of every timed action game: a loop that counts down, checks for input, and branches based on what happens. The **game loop** from Hot and Cold (Lucky Number, Unit 4) meets the **time pressure** from Wire Panic.

The structure is identical to your 10-line countdown:

1. **Display** (line 510) — draw the countdown digits
2. **Visual feedback** (lines 520-610) — timer bar, border colour, LEDs
3. **Sound** (line 630) — tick with descending pitch
4. **Wait** (line 640) — PAUSE 40 (0.8 seconds per tick)
5. **Check input** (lines 650-690) — did the player press a wire key?
6. **Decrement** (line 700) — `LET t=t-1`
7. **Check timeout** (line 710) — has time run out?
8. **Loop** (line 720) — go back to step 1

Every timed game uses this pattern. The specifics change — different displays, different inputs, different timings — but the structure is always: update, check, wait, repeat.

## What You've Learnt

- **PAUSE n** waits for n/50 seconds — `PAUSE 50` = one second
- PAUSE **breaks early** if a key is pressed
- **A countdown** is a variable that decreases each tick
- **The timed game loop**: display → sound → pause → check input → decrement → loop
- This pattern is **universal** — every timed game uses it
