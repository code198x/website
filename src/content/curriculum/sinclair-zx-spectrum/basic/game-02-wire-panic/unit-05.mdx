In Lucky Number, `INPUT` asked a question and waited. The program stopped. The player typed. The program continued. Everything happened in turns — the computer's turn, then the player's turn.

Wire Panic can't wait. The countdown is running. The timer bar is filling. Every second matters. If the game stopped to ask "which wire?" the tension would vanish. The player needs to act *while the game is running*.

That's `INKEY$`.

INPUT is for conversations. It's not for emergencies.

## INKEY$ Checks

`INKEY$` doesn't wait. It checks the keyboard *right now* and immediately returns the result:

- If a key is pressed, `INKEY$` returns that key as a string — `"a"`, `"3"`, `"z"`
- If no key is pressed, `INKEY$` returns an empty string — `""`

<CodeFromFile src="sinclair-zx-spectrum/basic/game-02-wire-panic/unit-05/inkey-checks.bas" />

Line 30 checks the keyboard. If nothing is pressed (`k$=""`), line 40 loops back and checks again. The moment a key is pressed, line 50 prints it. The program never stops — it just keeps checking until it finds something.

The empty string `""` is important. It's how you know *no key is pressed*. Every INKEY$ check is a yes/no question: is someone pressing a key right now? `""` means no. Anything else means yes.

## Live Detection

The real power of INKEY$ shows in a loop:

<CodeFromFile src="sinclair-zx-spectrum/basic/game-02-wire-panic/unit-05/live-display.bas" />

![Live key detection — "Key: g" appears while the key is held](/images/sinclair-zx-spectrum/basic/game-02-wire-panic/unit-05-checking-the-keyboard/live-display.png)

This program runs forever (GO TO 30). Every cycle, it checks the keyboard. Hold a key and "Key: g" appears. Release it and "(nothing)" appears. The display updates continuously, without ever stopping to ask.

This is **real-time input** — the game checks the keyboard as part of its loop, not as a separate conversation. The countdown keeps ticking. The timer keeps filling. And somewhere in the middle of all that, the program glances at the keyboard: "is the player pressing anything?" If yes, act on it. If no, keep going.

## INPUT vs INKEY$

| | INPUT | INKEY$ |
|---|-------|--------|
| **Behaviour** | Stops and waits | Checks and continues |
| **Returns** | Whatever the player typed (after ENTER) | The key being pressed right now (or "") |
| **ENTER needed?** | Yes | No |
| **Game stops?** | Yes | No |
| **Best for** | Questions, data entry | Action games, real-time control |

Lucky Number used INPUT because the player needed to think. Wire Panic uses INKEY$ because the player needs to act *now*. The choice between INPUT and INKEY$ is a **design decision** — it determines the rhythm of the game. Turn-based or real-time. Thoughtful or urgent.

## What You've Learnt

- **INKEY$** checks the keyboard without stopping the program
- It returns the **key being pressed** or **""** (empty string) if nothing is pressed
- **INPUT waits, INKEY$ checks** — turn-based vs real-time
- The choice between them is a **design decision** about game rhythm
- INKEY$ goes inside a **loop** — the game keeps running while it checks
- Keys are returned as **strings** — `"1"`, `"a"`, not numbers
