A quiz you can only play once isn't much of a game. Adding replay means the player can try again immediately — and improving their score becomes the goal.

<CodeFromFile src="sinclair-zx-spectrum/basic/game-10-quiz-master/unit-09/replay.bas" />

Line 430 asks "Play again?" after the results. Line 440 checks the answer: if the player types `y`, `GO TO 20` jumps back to line 20 — past the DIM on line 10 (which can only run once) and into the setup block that reinitialises everything.

Lines 20–50 are the setup block. `RESTORE` rewinds the DATA pointer to the beginning. The FOR loop reloads the correct answers into `k()`. `RESTORE 600` jumps to the category data. The second FOR loop zeros the category scores. `score` and `n` reset to 0. Everything is fresh for a new round.

## Why GO TO 20, not GO TO 10?

`DIM k(8)` on line 10 reserves memory for the array. On the Spectrum, calling DIM on an array that already exists gives an error. So on replay, we skip line 10 and jump to line 20 — the arrays still exist from the first play, they just need new values.

## Data-driven design

The quiz now has a property that Cipher introduced: **the content is separate from the code.** To add a fifth category, you'd add a DATA block (category name, colour, two questions) and change the loop bounds. To add harder questions, you'd change the DATA. The program's logic — read, display, check, score — never changes.

This is what "data-driven" means in practice. The code is the engine. The DATA is the fuel. Change the fuel, change the experience.
