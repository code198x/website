Line 80 sets `lv = 1`. Line 90 uses `RESTORE 900 + (lv - 1) * 10` to point READ at the correct DATA block — level 1 starts at line 900, level 2 at 910, level 3 at 920. Each block follows the same format: width and height, then row strings. Line 110 checks the sentinel: `IF w = 0 THEN GO TO 790`. Line 180 displays the level number. After a level is completed, line 750 increments `lv` and line 760 jumps back to line 90, where RESTORE recalculates the starting DATA line for the next level.

Lines 910–926 add two new levels. Level 2 is a 6x6 grid with one crate and one target placed diagonally — the player must navigate around walls. Level 3 has two crates and two targets, introducing the possibility of blocking yourself. Line 930 holds the end marker `DATA 0,0`.

## RESTORE as a level selector

RESTORE normally rewinds READ to the beginning of all DATA. With a line number argument, it rewinds to a specific line. The expression `900 + (lv - 1) * 10` is arithmetic level selection: level 1 maps to 900, level 2 to 910, level 3 to 920. Each block gets exactly 10 line numbers of space (900–909, 910–919, 920–929), even if the level does not use all of them.

This convention — fixed spacing between DATA blocks — is what makes the arithmetic work. If levels had variable spacing, you would need a lookup table of starting line numbers. The fixed stride keeps the code simple at the cost of wasting a few line numbers.

## DIM re-creates the array

When `GO TO 90` runs for level 2, line 150 executes `DIM g(h, w)` again with the new level's dimensions. In Spectrum BASIC, DIM always creates a fresh array filled with zeros, discarding any previous array of the same name. This is not a bug — it is the reset mechanism. The old level's crate positions, target states, and pushed results all vanish. The new level's DATA fills the clean array from scratch.
