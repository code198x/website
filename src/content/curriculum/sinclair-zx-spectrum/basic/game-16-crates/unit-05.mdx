## Four cell states

The array now holds five possible values: 0 (floor), 1 (wall), 2 (target), 3 (crate), and 4 (crate-on-target). State 4 is the interesting one. A crate sitting on a target is not "a crate and a target in the same cell" — it is a single combined state with its own value, its own colour (green PAPER 4), and its own behaviour when pushed off again.

This is state encoding at work. Rather than tracking crates and targets in separate arrays and cross-referencing them, a single number captures the full reality of each cell. The cost is more branches in the push logic. The benefit is that the array remains the single source of truth — no synchronisation bugs between parallel data structures.

## The computed PAPER trick

`PAPER (7-ps*5)` is a neat expression. When `ps` is 0 (floor), it evaluates to `PAPER 7` — white. When `ps` is 1 (target), it evaluates to `PAPER 2` — red. One expression, two colours, no IF statement. It appears at lines 460, 178, 190, and 197 — every place the player is drawn or erased. The alternative would be four IF/THEN branches. The computed form is shorter and, once you see the pattern, clearer.
