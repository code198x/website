Lines 320–500 add the input loop. Line 320 waits for the player to release any held key — `IF INKEY$ <> "" THEN GO TO 320`. Line 330 waits for a new key press. Together, these two lines create debounced input: one move per press, no matter how long the key is held. Lines 360–390 map I/J/K/L to direction offsets `dy` and `dx`. ## Debounce with two loops

INPUT waits for a line of text and ENTER. INKEY$ returns whatever key is held right now, or an empty string if nothing is pressed. It never waits. That makes it responsive, but it also means a single key press can register many times — the Spectrum scans the keyboard roughly 50 times per second, and a human press lasts several frames.

The two-line debounce at lines 320–330 solves this. The first line spins until the key is released. The second line spins until a new key appears. One press, one move. This pattern will reappear in every INKEY$-driven game from here on.

## Why I/J/K/L?

The layout mirrors the cursor diamond on the right side of the keyboard: I up, K down, J left, L right. It keeps the player's hand in one position, leaving the other hand free. It also avoids cursor keys, which on the Spectrum are Caps Shift combinations and harder to detect cleanly with INKEY$.
