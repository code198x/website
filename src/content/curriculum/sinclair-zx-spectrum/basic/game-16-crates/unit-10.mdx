## What the data defines

Look at what changed across ten units and what stayed the same. The push mechanic — lines 180–198 — was written once in Unit 4 and barely modified since. The win check was written once in Unit 6 and never touched. The level loader was written in Unit 1 and reused for every level. All the variety in the game — three different puzzles, different grid sizes, different crate arrangements — comes entirely from the DATA lines. The engine is fixed. The content is data.

This is the pattern behind every data-driven game. The code defines the rules. The data defines the experience. Add a new level and the game grows without any code changes. The DATA at lines 900–930 could hold thirty levels instead of three, and the engine would play them all without modification.

## One rule, all complexity

Crates has one mechanical rule: push a crate one cell in your direction of movement, but only if the cell beyond is empty. You cannot pull. You cannot push two crates. You cannot push diagonally. From that single constraint, every puzzle emerges. Level 3's two-crate arrangement is tricky not because the rules are complex, but because the *space* interacts with the rule in non-obvious ways. The walls create bottlenecks. The targets demand specific destinations. The push-only rule means order matters — push crate A first or crate B first, and the outcomes differ.

This is the deepest lesson in the game: constraint creates depth. More rules do not make better games. One rule, applied to a well-designed space, can be inexhaustible.
