Quiz Master's code is organised into clear sections:

- **Lines 10-38:** Title screen
- **Lines 40-140:** Main game loop
- **Lines 150-208:** Results screen
- **Lines 250-260:** Answer-to-row mapping subroutine
- **Lines 300-344:** Question card drawing subroutine
- **Lines 500-570:** DATA (questions and answers)

Each section has a purpose. REM comments mark the boundaries. Line numbers are grouped by hundreds. You can find any part of the program by knowing its section.

This is **code organisation** — not a BASIC command, but a **craft skill**. A well-organised program is one you can navigate, understand, and change. A poorly organised program works too — but when you need to fix a bug or add a feature, you can't find anything.

The conventions:
- **Low numbers** (10-200) for the main program flow
- **Middle numbers** (200-900) for subroutines
- **High numbers** (9000+) for DATA
- **REM comments** marking each section's purpose
- **Consistent spacing** — 10-spacing for readability

These are the same principles every professional codebase uses, expressed in BASIC's line-number system.

## What You've Learnt

- **Sections** group related code by line number ranges
- **REM headers** mark section boundaries
- **Subroutines** live in their own section, separate from the main flow
- **DATA** lives at the end, separate from code
- **Organisation is a craft skill** — it doesn't change what the program does, but it changes whether you can maintain it
