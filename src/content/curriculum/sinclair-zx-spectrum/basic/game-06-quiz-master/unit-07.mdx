RESTORE to a line number lets you keep separate question banks. The player picks a category and the game loads the matching questions.

## How It Works

**Menu (lines 10-80).** Three options with INPUT. The validation on line 90 loops back if the choice is outside 1-3.

**RESTORE to line (lines 100-120).** Each category has its DATA at a different line number: Science at 500, Geography at 600, History at 700. The player's choice determines which RESTORE runs.

**Coloured headers (lines 170-190).** Each category prints its name in a different ink colour — green for Science, blue for Geography, red for History. This gives each category a visual identity.

## Organising DATA

The three DATA blocks are self-contained sections. Each starts at a round line number (500, 600, 700) with three questions. This spacing leaves room for expansion — you could add more questions to each section without them overlapping.

```
500 DATA ... (Science question 1)
510 DATA ... (Science question 2)
520 DATA ... (Science question 3)
600 DATA ... (Geography question 1)
```

Line numbering conventions become important as programs grow. Grouping related DATA in hundreds or thousands keeps things organised.

## Try This

**Add a fourth category.** Write three more questions at line 800, add option 4 to the menu, and add `IF k = 4 THEN RESTORE 800`. Pick a colour for the header.

**Random category.** Instead of a menu, pick a random category: `LET k = INT (RND * 3) + 1`. The player doesn't know what's coming.

## What You've Learnt

- **RESTORE to line** — loads a specific DATA section: `RESTORE 500`
- **Category design** — separate DATA blocks at spaced line numbers
- **Coloured headers** — INK gives each category a visual identity
- **Line numbering** — group related code and data at round line numbers
