You've used GO SUB as a black box since Game 1 — the digit renderer, the text centering routine, the panel flash. Now you learn what it does.

`GO SUB` jumps to a line number, runs the code there, and `RETURN` jumps back to where it was called. The key difference from GO TO: **GO SUB remembers where it came from**. RETURN knows where to go back. GO TO doesn't.

<CodeFromFile src="sinclair-zx-spectrum/basic/game-06-quiz-master/unit-02/gosub-demo.bas" />

Lines 20-70 call GO SUB 100 three times with different text. Lines 100-150 print a bordered message. The subroutine doesn't know or care what `t$` contains — it just displays it. The calling code sets up the data, the subroutine handles the presentation.

This is **reusability**. Quiz Master's question card subroutine (line 300) is called eight times — once per question. If you wanted to change how questions look, you'd change one subroutine, not eight copies of the same code. That's the power of structure: **change one place, affect everywhere**.

## What You've Learnt

- **GO SUB** jumps to a subroutine and remembers where to return
- **RETURN** jumps back to the line after the GO SUB
- Subroutines let you **write code once, use it many times**
- Change the subroutine → change every place that calls it
