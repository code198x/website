The question display code runs every round: clear the screen, draw the header bar, print the question, draw the options. It's the same code repeated inside the loop. `GO SUB` lets you write it once and call it from anywhere.

## GO SUB and RETURN

<CodeFromFile src="sinclair-zx-spectrum/basic/game-06-quiz-master/unit-05/gosub-demo.bas" />

`GO SUB 100` jumps to line 100 — like `GO TO`, but the Spectrum remembers where it came from. When it hits `RETURN`, it jumps back to the line after the `GO SUB`. The code at line 100 is a **subroutine** — a reusable block you can call from anywhere.

Lines 250-260 convert `k$` into a row number `y`. Both the correct and wrong feedback paths need this mapping, so extracting it into a subroutine avoids duplicating four IF statements each time.

## Why Subroutines Matter

Without subroutines, every round would repeat the same 15 lines of display code. With `GO SUB`, the main loop is clean:

```
READ ... GO SUB 300 ... wait for key ... check answer ... NEXT
```

Each step is one line. The detail lives in the subroutines, out of the way. This is the same idea that will scale to much larger programs — and it's why the visual progression doc calls Quiz Master "the most polished Foundations game."

## Try This

**A second subroutine.** Extract the "draw header bar" code (lines 304-312) into its own `GO SUB 280`. The question card subroutine calls `GO SUB 280` — subroutines can call other subroutines.

**STOP before subroutines.** Add `STOP` or `GO TO` before line 250 to prevent the program from accidentally falling into the subroutine code. Without it, execution would run straight into the subroutine after the main loop ends.

## What You've Learnt

- **GO SUB** — jumps to a subroutine, remembering where to come back
- **RETURN** — jumps back to the line after the GO SUB call
- **Reusable code** — write once, call many times
- **Clean main loop** — detail lives in subroutines, the loop reads like a plan
