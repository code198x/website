## Structure as Design

**Structure** in game design means the same thing as in programming: organising pieces so they work together and can be changed independently. A well-structured game has:

- **Reusable components** — the question card subroutine works for any question
- **Separated concerns** — DATA holds content, code handles logic, subroutines handle display
- **Consistent patterns** — every question follows the same flow
- **Room to grow** — adding questions, categories, or features doesn't require rewriting

A poorly structured game might work, but it's brittle. Change one thing and three others break. A well-structured game bends without breaking.
