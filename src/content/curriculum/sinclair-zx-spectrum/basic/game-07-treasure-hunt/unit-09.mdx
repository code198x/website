## What Changed

**Line 90.** `LET m = 500` sets the time limit — 500 ticks is 10 seconds at 50Hz.

**Line 100.** Records the start time immediately before the game loop begins.

**The HUD (lines 700-760).** Now calculates and displays time remaining on every loop iteration:

```
710 LET e = PEEK 23672 + 256 * PEEK 23673
720 LET d = INT ((e - t) / 50)
730 LET w = m - d
740 IF w < 0 THEN LET w = 0
750 PRINT AT 0, 0; "L:"; l; " C:"; f; " V:"; v; " T:"; w; "  "
```

`d` is elapsed seconds. `w` is time remaining (`m - d`). The `IF w < 0` guard prevents negative numbers.

**Line 280.** `IF d >= m THEN GO TO 400` — when elapsed ticks exceed the limit, game over.

**Line 1100.** The next-level subroutine resets the timer with a fresh `PEEK` reading. Each level starts with a full countdown.

## Timer in the Game Loop

The timer doesn't stop the game. It runs alongside everything else:

1. Draw player
2. **Update HUD (with timer)**
3. Check input
4. Move player
5. Check collisions
6. **Check time** — game over if expired
7. Repeat

This is the standard pattern for real-time constraints in a game loop.

## Try This

**Shorter time.** Change `m = 500` to `m = 250` (5 seconds). Much more urgent.

**Time bonus.** When the player collects a coin, add 50 ticks to `m`: `LET m = m + 50`. Coins now buy time.

## What You've Learnt

- **Countdown timer** — start time plus limit, checked each frame
- **Timer in HUD** — display remaining time alongside other stats
- **Timer reset** — record a new start time for each level
- **Game over on timeout** — another way to lose besides running out of lives
