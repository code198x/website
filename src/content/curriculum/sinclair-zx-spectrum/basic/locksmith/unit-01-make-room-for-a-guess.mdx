Before a lock can judge a guess, the player needs somewhere to enter it. Start with four empty spaces and a drawing routine we can use again.

Use a **48K ZX Spectrum** session. Save any program you want to keep before entering NEW, then type this new program. If you need a reminder about entering keyword tokens, use [Meet BASIC](/systems/sinclair-zx-spectrum/basic/meet-basic/unit-01-make-the-spectrum-answer/).

Enter RUN. The board appears, with TRY 1 beside four underscores. The ordinary STOP report at the bottom is expected: this first program draws and stops. It does not read keys yet.

## Put the picture in its place

PRINT AT takes a row followed by a column. Both start at zero: row 0 is the top, and column 0 is the left edge. Line 2000 places the editable field on row 17, below the separator on row 16. Starting its underscores at column 7 leaves room for the attempt number.

Semicolons join the items in a PRINT statement without moving automatically to another line. Another AT can place the next item elsewhere. The spaces in `"_ _ _ _"` separate the four positions without needing four PRINT statements.

Line 10 chooses a black border and paper, white ink and bright colours, then clears the display. The INK values inside PRINT give the heading and separator cyan while the instructions remain white. These local print controls let one statement use more than one colour.

## Give each routine a job

`t` is the attempt number. `g$` will hold the guess as a string: an ordered sequence of characters. For now it is empty, written as two quotation marks with nothing between them.

GO SUB 1000 calls the board routine. RETURN at 1080 resumes execution after that call. GO SUB 2000 then draws the editable field, and its RETURN reaches STOP on line 240. The gaps between line numbers leave room for the game we will build around these routines.

<Question prompt="Why must the main program stop after drawing the editable field?">

Without STOP, execution would continue into the routine at 1000 as ordinary sequential code. Its RETURN would have no outstanding GO SUB to return from. Calling a routine and falling into it are different paths.

</Question>

Try changing the initial value of t to 3, then RUN again. TRY 3 should appear without changing the drawing routine. Restore t to 1 afterwards. If the board is displaced, check the order of row and column; if RETURN fails, check line 240 and both GO SUB calls.
