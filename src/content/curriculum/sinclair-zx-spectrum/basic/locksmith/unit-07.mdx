Line 490 changes the win check from an inline STOP to `GO TO 540`, and line 510 sends the lose path to `GO TO 600`. Lines 540–590 build the win screen: clear the board, reprint the title centred via `GO SUB 9000`, "Code cracked!" with the guess count, and an ascending fanfare. Lines 600–650 build the lose screen: "Out of guesses!", the code revealed digit by digit, and a low buzz.

The `GO SUB 9000` at lines 550 and 610 is a small centring helper — it prints `a$` centred on row `y` (`PRINT AT y, (32 - LEN a$) / 2; …`). Both outcome screens reuse it to place the title, so the heading lands in the same spot whether you win or lose.

Both screens clear the game display and present the result fresh. The player's last view is the outcome, not the guess history — the ending has the stage to itself.

## Revealing the hidden state

The lose screen reveals the code: `FOR i = 1 TO 4: PRINT c(i);: NEXT i`. This is the first time the player sees the contents of the secret array. The curtain falls.

Revealing the code on loss serves two purposes. It gives the player closure — they were trying to deduce `4 2 6 3`, and now they know. And it gives them a post-mortem: "I had the 4 and the 2 by guess 6 — if I had tried swapping positions 3 and 4, I would have had it." The reveal turns failure into a learning moment.

The win screen does not reveal the code — the player already knows it, because they guessed it. Instead it shows the guess count: "You got it in 5 guesses." The number is the player's score, and it invites the question: could I do it in fewer?
