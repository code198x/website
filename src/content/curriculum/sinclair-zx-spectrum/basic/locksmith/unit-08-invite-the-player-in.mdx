## Fit the rules to the game

The title answers the questions a new player needs: four digits, values 1–6, repeated digits, ten tries. EXACT means the right digit in the right place; OTHER means the right digit elsewhere. “Each digit counts only once” is the rule our frequency counts enforce.

The lock drawing uses ordinary characters. Its four question marks match the four spaces the player will fill. Colour separates headings, clues and controls, while words carry their meaning. We do not need a new drawing subsystem to make this small game readable.

## Three places to wait

The title loop waits at 130 for S or Q. The game loop waits at 250 for digits, editing and round commands. The result loop waits at 5250 for R or Q. Each has a different set of valid actions because the program is in a different state.

Line 150 rejects anything other than S. When S is recognised, execution continues to 200 and creates a round. It does not need an explicit GO TO because 200 is already the next numbered line.

<Question prompt="Why does R jump to line 200, while RUN starts at line 10?">

R requests another round, so it recreates the code, attempt count and board without repeating the title. RUN starts the program from the beginning, including the initial display settings and instructions. The two entry points offer different journeys into the same game loop.

</Question>

Check Q at the title, then RUN and S. Enter a short guess, complete it, delete a digit and replace it. Finish a round, replay with R and quit with Q. RUN should bring the title back.

If S seems unresponsive, release it after pressing: the round's release gate waits before accepting a guess. If R returns to the title, check that its branches still point to 200. Keep the final listing before trying changes to the wording; a PRINT that runs past the intended row can disturb the board around it.
