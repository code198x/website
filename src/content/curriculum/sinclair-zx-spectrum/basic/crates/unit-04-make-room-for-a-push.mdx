Walking needs one destination. Pushing needs two: the crate's current square and the square beyond it. We must check both before moving anything.

Continue from the walking program. This version pushes onto **plain floor only**. Targets will become usable destinations once we teach the rule that preserves them.

Line 240 now rejects only walls. Line 250 sends a crate to the push routine at 400; ordinary floor and targets still reach the walking code at 500. Code 4 is reserved for a crate on a target, which the next lesson will create.

`br = nr + dr` and `bc = nc + dc` step once more in the same direction. Line 410 checks those coordinates before line 420 reads the cell. Line 430 accepts only `bv = 0`, plain floor. Walls, targets and another crate all reject the push here.

Only then do lines 440 and 460 change the grid: the old crate cell becomes floor and the beyond cell becomes a crate. Line 480 redraws that destination. Execution continues into line 500, where the player moves into the crate's former square. The existing redraws repair the player's old cell and draw the player at the new one. One successful push counts as one step.

<Question prompt="Why not erase the crate first, then check the square beyond it?">

If that square is blocked, the attempt must leave the crate where it was. Erasing first would create a partial move that we would have to undo. Checking first lets rejection leave every position unchanged.

</Question>

## Give a bad push an escape route

R returns to line 20. `DIM` recreates the grid, the original assignments fill it, and line 80 resets the player and count. We rebuild the **starting room**, rather than trying to reverse each move. The tile graphics need no rebuilding because they have not changed.

Run. From the starting position, press **I, L**, releasing between presses. The second step pushes the crate from `(5,4)` to `(5,5)`. The player ends at `(5,4)` and STEPS reads 2. Press R: both return to their starting squares and STEPS returns to zero.

Now try **I, L, K, L, I, I**. The first upward push moves the crate to `(4,5)`. The last I tries to push it onto the target at `(3,5)` and is rejected at this stage. The count stays at 5. R restores the room.

A crate against an outer wall can be impossible to recover because we cannot stand outside the warehouse to push it back. Restart makes that mistake recoverable without pretending it was an illegal move. If a rejected push makes a crate disappear, check that every rejection happens before line 440.
