## Collision is a lookup

Lines 420–450 do it. Line 410 already worked out the destination `nr, nc`; line 420 reads what is
there — `LET v = g(nr, nc)` — and line 430 blocks a wall: `IF v = 1 THEN GO TO 320`, returning to the
input loop without moving. Line 450 is stricter still: `IF v <> 0 AND v <> 2 THEN GO TO 320` blocks
anything that is not floor or target, which catches crates and any cell type added later. Only when the
cell is clear does the player step onto it.

## Why this is so cheap

Earlier games checked boundaries with arithmetic — `IF x < 1 OR x > 30`, one condition per edge. Here
collision is a single array read, because the level data already records what each cell is. "Can I move
here?" becomes "what number is in this cell?" That is the payoff for building the world as an array in
unit one: the same structure that draws the screen answers movement, with no separate wall list and no
special case for corners. Checking *what is walkable* instead of *what is blocked* also means a new
cell type is safely solid until you decide otherwise.
