The room currently lives in several assignments and a border-building loop. A small map would let us see the layout in one place. We will change its representation while keeping the same room and movement rules.

## Choose an alphabet

Each string is one row, and each character describes one cell:

| Symbol | Meaning | Stored cell |
|---|---|---|
| `-` | Floor | 0 |
| `#` | Wall | 1 |
| `.` | Target | 2 |
| `C` | Crate on floor | 3 |
| `*` | Crate on target | 4 |
| `P` | Player on floor | 0, plus player coordinates |
| `+` | Player on target | 2, plus player coordinates |

Use eight **visible symbols** per row. A dash is floor; a space is not part of this alphabet. The combined symbols preserve the cell underneath an object.

## Decode one character at a time

Line 20 creates the empty array, resets the count and completion flag, then calls 4000. This replaces the old assignments. `RESTORE 8000` tells READ where the map begins. The graphics routine has its own `RESTORE 7200`; neither routine relies on where the other last stopped reading.

For each row, `READ m$` takes the next string. The column loop extracts `m$(c)`, a one-character slice, into `b$`. Lines 4030–4090 translate the symbol into `v`, then line 4100 stores it in the grid. For P or +, we also record `pr,pc`. The player never becomes a cell code.

`v` starts at -1 for each character so an unrecognised symbol cannot silently reuse the previous cell's code. This version still assumes the supplied map is valid; the next lesson will reject that -1 and other malformed input before play.

The eight DATA rows reproduce the preceding room exactly. R calls the loader again, rebuilding the original positions from those strings. Moving a crate changes `g`, not the DATA text.

After loading, 6000 counts all targets and those still uncovered. Line 86 recognises a map whose crates already cover them all. That makes completion depend on the loaded state as well as later pushes.

## One room, three representations

We edit a readable map, keep it in the program, and build a working grid from it.
Those are related jobs, but they do not need identical representations.

| Representation | What it contains | When we use it |
|---|---|---|
| Authoring | Eight rows of symbols that we can read as a room | When designing or changing the starting layout |
| Stored | Those strings in the program’s DATA lines | When loading the room or restarting it |
| Runtime | Numeric cells in `g`, plus `pr,pc` for the player | When checking moves, pushing crates and drawing the current room |

Trace row 6, `"#-P----#"`. Its third character is P. The loader sets
`pr=6`, `pc=3` and `g(6,3)=0`: the player stands on floor. The player’s position
is separate from the cell underneath. After a move, the coordinates can change
while the stored P stays where it was. That is how restart finds the original
position again.

expecting every part of it to fit into one array.

## Count cells before counting bytes

Eight rows of eight symbols describe **64 cells**. Our runtime array also has
64 numeric elements. That does not mean the whole map or array takes 64 bytes:
the program stores line information and string syntax, and BASIC has its own
representation for numbers and arrays.

For comparison, a different program could choose one byte per grid cell. Its
cell payload would be `8 × 8 × 1 = 64` bytes, before player coordinates or other
bookkeeping. That is a proposed encoding, not the storage used by this BASIC
array. A file’s size, the space occupied by loaded data and the work needed to
read it answer different questions.

We decode the strings when entering or restarting the room. During a move, we
can inspect the grid directly instead of translating the whole map again.
Keeping both forms uses space, but gives us readable starting data and a working
state that can change independently.

<Question prompt="Why must the map loader use RESTORE 8000 even though it reads only strings?">

Graphics loading has already advanced the shared DATA reader. READ does not choose a DATA section by the variable’s type. RESTORE explicitly selects the map before any row is read.

</Question>
