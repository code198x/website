The player can deliver the crate. Now the program needs to recognise that delivery. We will first display a count, then use it to finish the room.

The routine at 6000 scans the starting room once. `left` counts cells containing an uncovered target, code 2. `total` counts all targets, including code 4, a target already covered by a crate. Line 85 calls it whenever the room is rebuilt.

During play we already know the two cells involved in a push. If the crate leaves a target, line 475 adds one to `left`. If it enters a target, line 476 subtracts one. Walking changes neither. This avoids scanning the whole array after each step.

The GOALS readout prints `total - left`, the number filled, followed by the total. Room one starts at **0/1** and a delivery makes it **1/1**. This gives delivery a textual cue as well as the green crate.

<Question prompt="A crate leaves one target and enters another in the same push. What happens to left?">

Leaving adds one uncovered target; entering removes one. The net change is zero. Both tests must run: making the second an alternative to the first would lose half of the update.

</Question>

Run and deliver with **I, L, K, L, I, I**. The readout should become 1/1, but movement is still allowed. Push the crate off using the route from the previous lesson and it should return to 0/1. R resets the room and its count.

## Make a complete visit

Replace line **10**.

Add lines **140, 590, 2510, 5000, 5010, 5020, 5030, 5040, 5050, 5060, 5070, 5080, 5090, 5100, 5110, 5120**.

Line 10 now builds the graphics, then calls the instructions at 5000. That routine clears the remembered key, explains the controls and uses the same input routine to wait for S or Q. `RETURN` begins the room only after S.

After an accepted step, line 590 sets `won = 1` when no targets remain uncovered. The status routine prints the delivery message. On later input, Q and R are handled **before** line 140 prevents further movement. Success therefore stops walking but still permits replay or exit.

`won` is a flag: zero means the room is active; one means it is complete. Restart already resets it at line 80, along with the player and step count. A held direction cannot act as R or Q, so completing a room cannot dismiss its own ending.

<Figure src="/images/sinclair-zx-spectrum/basic/crates/teaching/complete-delivery.png" width={352} alt="Room one completed with a delivered crate, GOALS 1/1 and a replay or quit message." caption="All targets are covered. Movement stops; R replays and Q leaves." />

Run from the instructions. Try an unrelated key, then S. Solve the room, try another movement key, replay with R, and quit with Q. Also try Q directly from the instructions on another RUN. Each replay should restore the crate, player, zero steps and GOALS 0/1.

If the completion message appears but walking continues, check line 140. If replay leaves GOALS at 1/1, check that the call at 85 follows the room's reconstruction. You now have a complete one-room game. The next work makes its room easier to describe and extend.
