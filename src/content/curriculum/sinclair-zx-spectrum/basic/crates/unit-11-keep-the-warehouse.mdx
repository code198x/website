The warehouse is complete: three rooms, deliberate movement, restart, delivery and another game. Keep a version that rebuilds everything it needs when loaded.

No program edits are needed in this lesson. The complete source is the final state from lesson ten.

## Save an entry point

Press Q to return to BASIC. Follow the [tape workflow in Meet BASIC](/systems/sinclair-zx-spectrum/basic/meet-basic/unit-02-remember-and-save/#keep-a-copy-outside-the-spectrum), using this unnumbered command:

```basic
SAVE "crates" LINE 10
```

The tape header stores the name `crates` and the entry line 10. That line rebuilds the custom characters and tile tables before displaying the instructions. Saving only a running screen would not demonstrate that the program can do that work again.

Follow the ROM recording prompt and export the recorded tape using your emulator's controls. Keep the readable BASIC source as well. If the tape contains older recordings too, remember that the ROM searches from the current tape position: exporting again does not necessarily remove earlier programs.

Start a fresh 48K session, attach your saved tape and enter:

```basic
LOAD "crates"
```

Start tape playback. After loading, the instructions should appear automatically. If the ROM keeps searching, check playback, the program name and the position on the tape. If an older version appears, check which recording you exported or loaded.

## Check a whole visit

Begin with S. Try a blocked step and a legal push, restart, then solve room one. Advance to room two, make a bad push and restart that room. Finish it and advance to room three. Deliver one crate and check that the other is still needed. Finish, replay, then begin a new game. Quit with Q.

The rooms should have the same original walls, targets and starting positions. Restart resets the current room; a new game returns to room one. STEPS counts successful movement, including pushes. There is no timer, compulsory shortest route or penalty for thinking.

<Question prompt="Why reload in a fresh session when the current game already works?">

The fresh session does not contain our custom characters or variables. Reaching the instructions and playing all three rooms there checks that the saved program rebuilds its graphics, reads the right maps and starts with the intended state.

## A warehouse you can change

The grid stores the world. Player coordinates identify the overlay. Movement inspects a proposed change before accepting it, and the drawing routine shows the resulting state. DATA supplies the starting rooms, so a restart can discard a damaged puzzle position without changing its map.

For an optional new puzzle, keep a copy of the finished game and edit one room's eight DATA strings. Check its symbols and counts, find a solution, then ask someone to play it without your route. Observe where they pause or get trapped. Structural validity is useful, but the choices available to the player determine whether the puzzle is interesting.

The program, pixel artwork and three room designs are original course material, covered by the [samples repository's MIT licence](https://github.com/code198x/code-samples/blob/main/LICENSE). The game is deliberately silent. Delivered crates change colour, the GOALS count reports progress, and a message marks completion. There is no undo or automatic warning of an unsolvable position; R is the way back to the start of a room.
