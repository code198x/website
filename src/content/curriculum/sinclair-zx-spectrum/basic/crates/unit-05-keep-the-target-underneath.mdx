A crate can cover a target, but the target must still exist when the crate leaves. We need a stored state for both things occupying the same square.

Continue from the floor-only pushing program. We will add **4: crate on target** to the world codes.

## Trace the two cells

Before changing the source, trace what a push must leave behind and put ahead:

| Crate starts on | Destination underneath | Old cell after push | New cell after push |
|---|---|---|---|
| Floor (3) | Floor (0) | Floor (0) | Crate (3) |
| Floor (3) | Target (2) | Floor (0) | Crate on target (4) |
| Target (4) | Floor (0) | Target (2) | Crate (3) |
| Target (4) | Target (2) | Target (2) | Crate on target (4) |

`v` remembers the crate's old state; `bv` remembers the destination. We read them before changing either cell, so both facts remain available during the update.

## Deliver it, then move it again

Run and try **I, L, K, L, I, I** from the start. The final push now succeeds: the crate reaches `(3,5)` and changes colour. There is no victory message yet; we are checking target preservation while movement remains available.

To push it off again, continue **L, I, I, J, K**. You walk round to `(2,5)` and push down. The crate moves to `(4,5)`, while the player stands on the uncovered target at `(3,5)`. Step right with L and the empty ring becomes visible. Press R to restore the room.

If a target vanishes, check line 450 and the remembered `v`. If a delivered crate stays yellow, inspect the new cell code and line 470 before changing its colour. Crates and targets must each keep their total count through every push; only their positions and coverage change.
