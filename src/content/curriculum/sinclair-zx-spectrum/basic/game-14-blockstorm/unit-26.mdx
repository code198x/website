The first five waves introduce enemy types gradually. Waves 6-10 combine them all in denser formations at higher speeds. By wave 8, the screen is full of enemies, bombs are falling, and the game loop is running noticeably slower. Wave 10 has 20 enemies and BASIC is visibly struggling. This is deliberate.

## How It Works

**Wave 6 (14 enemies, speed 2):** All four enemy types in three rows. Two bombers drop projectiles from the back row. Scouts in the middle row can dive. The player faces offence and defence simultaneously — the complete Blockstorm experience.

**Wave 7 (14 enemies, speed 2):** Two V-formations interleaved. The staggered positions create harder target alignment. Every shot must thread through gaps. Scouts and bombers in strategic positions add pressure.

**Wave 8 (16 enemies, speed 2):** A dense block formation. Enemies are packed tight — four rows of four. The formation fills the screen width. The game loop now processes 16 enemies per frame: erase, move, draw, collision check for each. The first signs of slowdown appear.

**Wave 9 (18 enemies, speed 1):** Complex mixed formation with speed 1 — the formation moves every single game tick. Eighteen enemies means 18 erase-draw cycles per formation move, plus bullet checks, bomb management and HUD updates. The loop time increases noticeably.

**Wave 10 (20 enemies, speed 1):** Maximum density. A full grid of enemies: four rows of five. Twenty enemies, three bombs, two bullets, the player — all moving and collision-checking every frame. The frame rate drops. The game feels sluggish. The player can feel BASIC struggling to keep up.

## The Slowdown is the Lesson

Wave 10 is not poorly designed. It is honestly designed. The game engine works correctly — every enemy moves, every collision is checked, every sprite is drawn. But there are so many objects that BASIC cannot process them all quickly enough. The frame rate drops from a playable 5-8 frames per second to a choppy 3-4.

This is the performance wall. It is not a bug to fix. It is a fundamental limitation of interpreted BASIC. The Spectrum processor runs at 3.5 MHz, fast enough to handle 20 sprites at machine code speed. But the BASIC interpreter adds overhead to every operation — variable lookup, line scanning, floating-point arithmetic. By wave 10, that overhead consumes more time than the actual game logic.

## Try This

**Play wave 10.** Experience the slowdown firsthand. How does the frame rate feel compared to wave 1? Is the game still playable? Still enjoyable?

**Remove enemies.** Start wave 10 with 10 enemies instead of 20. Is the frame rate noticeably better? This confirms that the number of on-screen objects directly drives performance.
