## Save a program that starts itself

Quit with Q if the game is running. Prepare your emulator's tape recording or file-saving controls, then enter:

```basic
SAVE "drift" LINE 10
```

The filename identifies the saved program. LINE 10 tells a later LOAD where to begin execution. We choose the program's beginning so it builds its direction tables and shows the title before the flight starts.

The exact recording controls depend on the emulator. Follow [Keep a copy outside the Spectrum](/systems/sinclair-zx-spectrum/basic/meet-basic/unit-02-remember-and-save/#keep-a-copy-outside-the-spectrum) for the setup and file workflow. Keep the resulting tape file somewhere you can find again.

A BASIC tape and an emulator save state have different jobs. The tape loads the program through the Spectrum's loader. A save state resumes a particular machine session, which can be useful, but does not test whether the program can initialise itself on a fresh machine.

## Load into a fresh 48K machine

Open a fresh 48K session, attach the tape and use the emulator's playback controls. Enter:

```basic
LOAD "drift"
```

The title should appear after loading. Start with S, make a short burn and check that the DRIFT readout follows the motion. Try a wall failure and R, then complete a gentle dock and retry again. Finish with Q and enter RUN to return to the title.

If loading waits without finding the program, check that the correct tape is attached and playback has started. If the program loads but does not begin automatically, check that you saved with LINE 10; RUN can still start a correctly loaded listing. If a flight fails because an array is missing, start from line 10 rather than jumping into the reset at 100.

<Question prompt="A save state resumes a ship already moving near the dock. What has that check not shown about your tape?">

It has not shown that the tape contains a loadable program, that loading reaches the title, or that the program creates its direction tables and initial state. A fresh tape load exercises those steps; resuming an existing session bypasses them.

</Question>

## Explain the flight you made

Before putting the game away, choose one successful approach and describe it in terms of the stored state. Where was the centre? Which way did the nose point? Which velocity component did the next burn change?

Those questions explain why the controls can feel strange at first. A picture of the nose tells us the next thrust direction, while the velocity tells us where the ship is going now. The docking rule brings that motion and the position together.

Keep a working tape before experimenting with the program. A small change to a threshold can make a large difference to the approach; change one thing, predict what it will do and compare it with a fresh flight.
