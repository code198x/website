Without checking, the player can probe the same cell twice — wasting a guess on information they already have.

Lines 380–390 add two checks before processing the probe. Line 380: if the cell holds a distance value (1–8), it has already been probed — "Already probed!" and back to the grid without counting a guess. Line 390: if the cell is -1, the target there has already been found — "Already found!"

Both checks use `GO TO 180` to redraw without incrementing `guesses`. The player is not penalised for trying a cell they have already visited — they just get a reminder.

## State as validation

The grid array does double duty. It stores game state (what is at each cell) AND enables input validation (has this cell been probed?). A cell with value 0 or 9 is a valid target. Anything else (1–8 or -1) is already known. The program does not need a separate "visited" array — the game state itself contains the answer.

This is the same principle as Cipher's `tried$` string, but using numeric values in an array instead of characters in a string. The data structure that records the game also validates the next move.
