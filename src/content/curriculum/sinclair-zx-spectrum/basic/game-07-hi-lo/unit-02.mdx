The program shows the first number, asks "Higher or lower?", then reveals the second and checks whether the player was right.

## AND

Lines 110–140 use `AND` to check two conditions at once:

```
IF g$ = "H" AND b > a THEN PRINT "Correct!"
```

This means: the player guessed "H" *and* the next number is higher. Both must be true. If the player guessed "H" but the number is lower, the condition fails.

`AND` joins two conditions into one check. You saw it briefly in Reflex (the rating thresholds); here it is the core mechanic. Every correct/wrong check requires knowing *what the player said* and *what actually happened*.

## The equal case

Line 150 handles draws: `IF b = a THEN PRINT "They were the same!"`. This is a design decision — should a draw count as wrong, right, or neither? Here it is treated as a neutral event. The brief said to handle it explicitly; ignoring it would mean the player is marked wrong when there was no right answer.

## One guess, one result

The program ends after one guess. That is a turn, not a game. The next unit adds the loop that turns it into a streak.
