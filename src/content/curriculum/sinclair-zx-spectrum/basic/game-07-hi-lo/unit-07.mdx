`STOP` is abrupt. A game over screen is a proper ending.

Line 260 changes from `STOP` to `GO TO 400`. Lines 400–450 build the game over screen: line 400 flashes the border red and plays a low buzz — the opposite of the green/high correct feedback. Line 420 clears the screen. Lines 430–450 print the title, "GAME OVER", and the streak.

The game over screen mirrors the correct-guess feedback but inverted. Green, high, "Correct!" vs red, low, "GAME OVER". The player already learnt what green and red mean during the game — the ending uses the same language at a bigger scale.

## Endings as structure

Every game so far has followed the same pattern: build the game first, then add the ending. That is deliberate. The game over screen is not part of the core logic — it is presentation. Line 260 could just as easily say `STOP`, and the game would still work. The game over screen is there for the player, not for the program.

But it matters. A game that ends with `STOP` feels like it broke. A game that ends with a screen, a sound, and a score feels like it finished. The difference is one `GO TO` and five `PRINT` lines.
