`INKEY$` is on the N key in extended mode: press CAPS SHIFT and SYMBOL SHIFT together, release them, then press N. `#` is SYMBOL SHIFT and 3.

## What INPUT was doing

`INPUT` hands the bottom of the screen to the ROM. It prints the prompt there and shows a cursor. Then it runs a small line editor: the player can type, delete and change their mind, and nothing reaches the program until Enter. That suits a name or a number with several digits.

The editor also owns the space it uses. A long answer makes the lower part of the screen grow upwards, and the board above it scrolls away. Lines 3015 and 6010 redrew the whole board after any answer longer than sixteen characters, to put back what the scroll had moved. Those lines fixed the symptom. Reading single keys removes the cause: nothing is typed, so the lower screen never grows.

## Read the keyboard with INKEY$

`INKEY$` reads the keyboard at the instant the program asks. If one key is down, the result is that key's character. If nothing is pressed, the result is the empty string `""`. It never waits. If the player presses a key while the program is busy elsewhere and lets go before the next reading, that press is missed.

The routine at 3200 wraps that up as "wait for one press". Line 3200 keeps reading until it gets a character and stores it in `a$`. Line 3210 then keeps reading until the keyboard is empty again. Only then does line 3220 return.

That second loop matters because a finger is slow compared with the program. After accepting the row, the program checks it, echoes it, returns and reaches the column prompt in a little over a tenth of a second. An ordinary press lasts longer than that. Without line 3210, the column's `INKEY$` would find the row key still down and take it as the column as well. With it, one press makes one choice, however long the key stays down.

The row prompt accepts 3, and the column prompt reads the same key before you let go, so the probe is row 3, column 3. Hold the key longer and the next row and column prompts take 3 again: the board reports a repeated probe.

We timed it in an emulator. Without line 3210, a press held for a sixth of a second became row 3, column 3, and one held for most of a second went on to repeat the probe. Only very short taps, under a tenth of a second, chose the row alone. With line 3210 in place, a key held for three seconds still made one choice. Put line 3210 back afterwards.

Line 5085 waits for an empty keyboard before the instructions accept a key. When you type `RUN`, the Enter key that starts the program may still be down when the instructions finish printing. Without this line it could skip them.

## Prompts in the lower screen

`PRINT #1;` sends what follows to the bottom two lines, the area that `INPUT` used. `#1` names stream 1, which the ROM connects to the keyboard and that lower area. `AT` inside it counts from the top of the lower area, so `AT 0,0` is its first line and `AT 1,0` its second. The ordinary `PRINT` still draws the board above.

Lines 100 and 110 now set `pl`, the prompt line, as well as the label: 0 for the row and 1 for the column. Line 3005 clears the old column line before a new row prompt. Line 3010 prints the prompt with three trailing spaces, which rub out the previous answer. After a key passes the checks, line 3045 echoes it straight after the prompt. The prompt text `" (1-8, Q): "` is eleven characters long, so `LEN p$+11` is the column just after it, whatever the label. Every `PRINT #1` ends with a semicolon, so the print position stays on its line instead of moving down.

After a row, the player sees `Row (1-8, Q): 3` above `Column (1-8, Q):`. The chosen row stays visible while they pick the column.

## The checks get shorter

`INKEY$` gives at most one character, so the length check at line 3030 had nothing left to catch, and it is gone. Line 3020 still accepts q or Q from either prompt. Line 3040 still refuses anything outside `"1"` to `"8"`: 0, 9, letters, Space and Enter all show the same message at 3100 and wait for another key. `VAL` only ever sees a single digit.

The instructions and the replay prompt use the same routine. Line 5090 prints the start prompt in the lower screen, line 5100 waits for a key, and line 5110 leaves on Q; any other key starts the round. At the end of a round, line 6000 prints the replay prompt and clears the old column line, and line 6010 waits for a key. R plays again, Q leaves, and anything else shows the reminder at line 6040.

## A line nobody read

Line 10, `LET stage=6`, sets a variable that no other line reads. Until [Read the sonar](../unit-04-read-the-sonar/), line 1010 printed it in the title as `SONAR - STAGE`. When that line began printing the band legend instead, `stage` lost its only reader, and line 10 stayed behind. Deleting it changes nothing a player can see.

`SAVE "sonar" LINE 10` still works. With line 10 gone, the Spectrum starts from the first line after it, line 15, which shows the instructions. Save over your old copy that way, start a fresh 48K session and load it to check.

## Check it

From the instructions, press any key. At the row prompt, press 0, 9, a letter and Space: each shows the reminder, and the board stays still. Press a row and watch it appear beside the prompt. Press a column and hold it for a few seconds: one probe, and the next row prompt waits for a fresh press. Probe a cell twice and check that the count does not rise. Find the target, press a key other than R or Q, then R. Check the empty board and zero count, and press Q.

If a choice sometimes registers twice, look at the release loop at 3210 before anything else.
