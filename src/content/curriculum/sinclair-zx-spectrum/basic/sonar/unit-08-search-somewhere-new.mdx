## From a fraction to a coordinate

Spectrum RND produces a value from its pseudo-random sequence. For this expression it lies between zero and one, below one. Multiplying by eight gives a value below eight; INT rounds down to one of 0 through 7; adding one gives a coordinate from 1 through 8.

Line 20 does this separately for row and column. Everything else keeps using `tr` and `tc` as before. The distance rule, band boundaries and recorded clues do not need to know how the target was selected.

`RANDOMIZE` without a number uses the machine's timing state to choose a starting point in the sequence. We call it once, after the player leaves the instructions. Retry goes to line 20 and continues the sequence. Repeatedly reseeding inside the selection loop would tie successive results to very similar timing; it is not a way to guarantee better variation.

<Question prompt="If two rounds choose the same target, must there be a bug?">

No. Each coordinate is selected from the same range again, so a repeated position is allowed. The things to check are that coordinates stay in range and that each round begins with empty knowledge, not that every target differs from the previous one.

</Question>

## Play through the clues

For a useful probe, consider all earlier readings together. A cell that is near one probe might still be impossible because it is too close to a far probe. The board now keeps those observations for you.

Play several rounds. After each retry, check the blank board and zero count. Check repeated probes in an ordinary search, then complete a discovery. There is no limit or pass mark: the counter records how the search unfolded.

For a controlled debugging run, you can temporarily restore the fixed target line from the preceding lesson, then restore this random version afterwards. Do not change the clue calculation while testing target selection. Changing one part at a time makes a surprising result easier to explain.
