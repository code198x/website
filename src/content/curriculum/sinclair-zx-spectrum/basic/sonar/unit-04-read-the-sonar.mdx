## Classify once

Line 170 still calculates the exact distance. Line 171 checks the far band first, replaces `d` with code 3 and jumps straight to the display preparation at 180. Line 172 does the same for medium. If neither branch matched, line 173 changes a positive distance to code 1. Zero passes through unchanged.

That jump matters because we reuse `d`. After converting a far distance to 3, running the medium test would mistakenly convert that code again. Each probe must be classified once. Until the conversion, `d` is a distance; afterwards it is a code with the meanings in the table.

The letters and status message now explain the code. The legend stays above the board, so the player need not remember the band boundaries. Colour still separates cells, but the clue is readable without relying on colour.

<Question prompt="A probe is six steps from the target. Why must line 171 jump past the next two tests?">

It changes 6 to the far code 3. Without the jump, the next test would see a value greater than 2 and treat that code as a distance, changing it to medium. The jump preserves the first correct classification.

</Question>

## Ask a useful question

A far clue means at least five steps, not exactly five. Before probing again, imagine which cells still agree with the clue. A probe among them might find the target; a probe elsewhere might separate possibilities more clearly. Neither approach requires guessing a hidden direction.

For a boundary check, temporarily put the target at `(1,1)`. Probe `(1,1)` through `(1,6)`: the results should be `*`, N, N, M, M, F. Probe `(8,8)` and expect F again. Restore the ordinary target `(3,6)`.

We still erase the previous probe. Try keeping two or three clues on paper and using them together. That small inconvenience is the reason for our next change: a board that remembers what we have discovered.
