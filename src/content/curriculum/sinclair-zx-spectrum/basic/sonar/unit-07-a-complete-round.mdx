## Begin and end deliberately

The call at line 15 displays the instructions. The routine at 5000 prints the rules and reads an answer: Enter starts, Q leaves, and other answers show the instructions again. Returning from that routine continues with the round setup at line 20.

After each probe, line 300 checks for code zero and transfers to the replay prompt at 6000. The board and discovery message remain visible. R begins another round; Q leaves; other answers produce a reminder without destroying the result. Uppercase and lowercase letters both work.

`GO TO 20` restarts the round directly. It is not a subroutine call that needs a later RETURN. Every replay follows the same setup path, so there is no growing chain of unfinished calls.

## Reset the state, not just the picture

At line 20, the target is still the fixed `(3,6)`. DIM replaces the old array, and the nested loops fill the new one with -1. The next lines clear the count, old marker, selected coordinates, clue value and temporary strings. Only then is the new board drawn.

Clearing the screen alone would leave the clues in the array. A later redraw could bring the old search back. Resetting the data first gives drawing a genuinely empty search to show.

<Question prompt="Why keep the target fixed while checking retry?">

We can reproduce the same probes and expected clues. If an old marker or count survives, we can identify a reset fault without wondering whether a newly chosen target caused the difference.

</Question>

Run the program from its instructions. Find the target, enter an invalid replay answer, then enter R. Check that all cells are unknown, the count is zero and there is no latest marker. Repeat this several times. Test Q from the instructions, the row prompt, the column prompt and the result screen.

This is already a complete small game: instructions, play, discovery, retry and exit. It is intentionally silent. The symbols and messages carry the feedback, so there is no sound setting needed to understand what happened.
