Line 320 checks each key against the sequence: `IF k$ <> s$(i)` compares the player's key to the i-th character of the string. Get it wrong and the game prints "Wrong!" and stops. Get it right and the FOR loop continues to the next digit.

Lines 350–370 handle a successful round. Line 350 prints "Correct!" Line 360 pauses for half a second. Line 370 jumps to `GO TO 150` — which appends another random digit to `s$` and replays the whole sequence from the start. The sequence grows by one character each round.

## The game loop

The program now has a real game loop, but it is not a simple `GO TO` back to the beginning. The loop starts at line 150 (add a digit), plays the sequence (180–220), gets the player's input (240–340), and either ends (320, wrong answer) or jumps back to 150 (370, correct). Each pass through the loop makes the sequence longer, and the entire sequence replays from the start.

This is the design concept behind Simon: **recognise, reproduce, extend**. The computer shows the pattern. The player reproduces it. Then the pattern grows. The tension comes from the growing gap between what you can hold in memory and what the game demands.

## Try it

Play it. The first round is one panel — trivial. The second is two. By round five or six, you are concentrating. By round eight or nine, most people fail. The game gets harder without adding any new code — the difficulty is in the data, not the logic.
