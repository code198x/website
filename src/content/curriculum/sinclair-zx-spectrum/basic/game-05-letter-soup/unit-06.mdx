Letter Soup doesn't show all the letters at once. They appear one by one, each with an ascending tone. The FOR loop walks through the scrambled string, printing one character per pass with a BEEP that rises in pitch:

```
360 FOR i=1 TO LEN s$
370 PRINT AT 8,c+i*2-2; PAPER 1; INK 6; BRIGHT 1;s$(i TO i)
380 BEEP 0.05,5+i*2
390 NEXT i
```

The ascending pitch creates **anticipation** — each letter builds on the last, and the rising melody says "here it comes." The player watches the word assemble, trying to recognise it before all the letters appear. Sometimes you see the answer before the reveal finishes. That moment — when the pattern clicks before the last letter appears — is one of the most satisfying feelings in the game.

This is a tiny detail — a few lines of code — but it transforms the experience. Without the animation, the letters would just *appear*. With it, they *arrive*. Game designers call this **juice** — the small details that make interactions feel polished. The ascending reveal costs almost nothing to implement but adds drama to every round.

## What You've Learnt

- **Character-by-character reveal** using `s$(i TO i)` in a FOR loop
- **Ascending pitch** (`5+i*2`) creates anticipation — each tone higher than the last
- **Anticipation** is a design tool — making the player wait increases the payoff
- Small details (**juice**) transform functional code into a satisfying experience
