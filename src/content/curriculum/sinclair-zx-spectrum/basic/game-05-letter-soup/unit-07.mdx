Letter Soup's difficulty comes from one place: word length. A 3-letter word like "cat" has 6 possible arrangements. A 9-letter word like "adventure" has 362,880. The scramble algorithm doesn't get harder — the words do.

The DATA ordering makes this work:

```
9000 DATA "cat","sun","bird","fish","lemon"
9010 DATA "planet","castle","trumpet","dinosaur","adventure"
```

Rounds 1-2: 3 letters. Rounds 3-4: 4 letters. Round 5: 5 letters. The progression is gentle — each step up adds one letter, which roughly multiplies the difficulty. By round 10, "adventure" has so many possible arrangements that brute-force guessing is hopeless. The player must actually recognise the word.

This difficulty curve is entirely in the DATA. The code doesn't know or care that the words get longer. It scrambles whatever READ gives it. If you reversed the DATA — "adventure" first, "cat" last — the game would start hard and get easier. If you used all 5-letter words, the difficulty would be flat.

The **designer** controls difficulty through **content**. The **programmer** builds a system that handles any content. This separation is what makes games scalable: one engine, infinite content.

## What You've Learnt

- **Word length** creates difficulty naturally — more letters = more arrangements
- **DATA ordering** controls the difficulty curve without changing code
- The same code handles any word — **the system is content-agnostic**
- **Designers control difficulty through content**, not code changes
