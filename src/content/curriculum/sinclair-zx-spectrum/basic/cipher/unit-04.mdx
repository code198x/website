Line 240 starts an empty string `z$`. Line 380 shows it on screen so the player can see what they have already guessed. Line 460 appends each new guess: `LET z$ = z$ + g$`.

Lines 410–440 are the duplicate check: a FOR loop scans every character of `z$`. If any character matches the current guess, the `already` flag flips to 1. Line 450 catches it: "Already tried!", a pause, then back to the input prompt. No life lost.

## Scanning a string

The check is a character-by-character search. `z$` starts empty. After three guesses (say E, A, T), it holds `"EAT"`. To check whether S has been tried, the loop walks positions 1, 2, 3 — comparing each character. None match, so S is new.

This is the simplest possible membership test: walk the string, compare each character. It works because the string grows by one character per guess, and the alphabet has only 26 letters — the string will never be longer than 26 characters. More efficient data structures exist, but for 26 characters on a 3.5 MHz machine, a linear scan is instant.

The `z$` string is also a display aid. Printing it shows the player exactly which letters they have used, helping them think about what to try next.
