Lines 180–190 place the creature in a random room, avoiding the pit (there is no point having the creature start in the pit). Line 360 now shows both hazard positions for debugging.

Lines 400–410 add the smell clue, reusing the same adjacency subroutine. Set `chk` to the creature's room, call `GO SUB 740`, and if `adj = 1`, print "Something smells terrible..." The subroutine does not know it is checking for a creature — it just answers the same question: "Is room `chk` next to room `rm`?"

Line 580 checks whether the player walked into the creature's room. If so, lines 840–860 show the death screen: "The creature got you!"

## Two hazards, one subroutine

The adjacency subroutine now serves two callers. Line 380 checks for the pit's draft. Line 400 checks for the creature's smell. The code is identical in structure — set `chk`, call the subroutine, read `adj`. The only difference is which room number goes into `chk`.

This is the power of `GO SUB`. Without it, we would need to copy the four-way check twice — once for the pit, once for the creature. With the subroutine, adding a new adjacency check costs two lines instead of six.

## Smell is different from draft

Both clues use adjacency, but they mean different things. The draft is fixed — the pit never moves, so a draft in room 5 always means the same thing. The smell changes meaning every turn because the creature moves. A room that smelled terrible last turn might be safe now, and a room that was silent might suddenly reek. The same sensing mechanism, applied to a moving target, creates a fundamentally different kind of danger.
