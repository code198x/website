Quit with Q and prepare your emulator's tape recording controls. At the BASIC prompt enter `SAVE "caverns" LINE 10`, without a program line number. Follow [Keep a copy outside the Spectrum](/systems/sinclair-zx-spectrum/basic/meet-basic/unit-02-remember-and-save/#keep-a-copy-outside-the-spectrum) to record and export the tape.

The name identifies the program. LINE 10 records where execution should begin when it loads. The title appears first; S then runs the setup at 200, recreating the expedition. The BASIC save may include variables, but this entry path deliberately starts afresh rather than resuming a partly explored cave.

## Test the copy, not the old session

Open a fresh 48K session, attach the exported tape, enter `LOAD "caverns"` and start playback. The title should appear after loading without another RUN command.

1. Start with S and move into a neighbouring room.
2. Check a clue against what you find beyond that exit.
3. Reach a creature arrival and escape, or complete the return journey.
4. Press R and check that the entrance, treasure count and patrol start are restored.
5. Press Q to leave the program.

If loading keeps waiting, check the tape name and playback. If the program loads without starting, check that the saved command included LINE 10. RUN can start a loaded listing, but repeat the save and fresh-load check to establish that the tape itself starts correctly.

<Question prompt="A saved tape shows the title correctly. Does that prove its replay clears collected treasure?">

No. Loading checks the entry point. Replay reaches a different path, beginning at 200. Collecting something and restarting checks that DIM and the treasure assignments restore the expedition.

</Question>

You have built a world whose description, connections, objects and moving inhabitant are separate pieces of state. The order in which they change determines whether a clue can help. Keep this working copy before experimenting with another map or patrol, so you have a known expedition to return to.
