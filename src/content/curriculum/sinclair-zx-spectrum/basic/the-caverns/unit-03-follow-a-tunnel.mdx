## Translate a key into a direction

INKEY$ gives a pressed character, or the empty string when no key is down. The input loop waits for a character, then handles Q and R. The direction loop compares it with each character of `"NSEW"` and `"nsew"`, so either case works. A match stores the direction's index in dir.

NEXT sits on a separate line from the IF. A false IF skips the remainder of its own line; the loop must still reach NEXT when a particular direction does not match.

Space is different from no key: `" "` contains one blank character, while `""` contains none. Space is a valid wait action. Other unmatched characters return to input without changing the world.

## Decide where to go before going there

Set dest to the current room first. That is where waiting leaves us. For a direction, replace dest with `m(rm,dir)`. A zero destination means a wall, so display a message and return before the turn count changes.

Only after validation do we increment turns and copy dest into rm. GO TO 270 redraws the new room, then waits for another action. This separation gives later hazard checks somewhere to examine a proposed move before accepting it.

The routine at 9000 waits until the key is released. Hold S at the entrance: you should move once into the Root chamber, not continue south into the Still pool. Release it and press again for another action.

<Question prompt="Why does Space count a turn when the room number stays the same?">

A turn records an accepted action, not necessarily movement. Waiting will later give the creature a chance to move while you stay put. A wall is rejected before that point.

</Question>

Explore the names and exits. The map is fixed, so returning by the opposite tunnel should lead back where you came from. If a room is wrong, check its DATA link before changing the input code.
