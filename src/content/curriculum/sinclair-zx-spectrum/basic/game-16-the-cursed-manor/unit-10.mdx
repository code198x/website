Reading the same long description every time you enter a room gets tiresome. Classic text adventures show a detailed description on the first visit and a brief one on returns. The player gets atmosphere on arrival and speed on subsequent passes.

## Visit Flags

An array `v(r)` tracks whether the player has visited room `r`. When `v(r) = 0` (first visit), the game shows the full description and sets `v(r) = 1`. On later visits, it shows just the room name and a short summary. The LOOK command (next unit) will let the player re-read the full description whenever they want.

## How It Works

**Line 28** adds `DIM v(20)` for visit flags. All values start at 0 — no rooms visited.

**Lines 200-240** check `v(r)` before displaying. If `v(r) = 0`, the full description prints and `v(r)` is set to 1. If `v(r) = 1`, only the room name and a brief reminder print.

**The brief descriptions** come from a second string array `b$(20,40)`. Each room has both a full description (`d$`) and a brief one (`b$`). The DATA lines grow by one string per room.

**The entrance hall** example: first visit might read "A grand entrance hall with a sweeping staircase. Dust covers every surface. Portraits line the walls, their eyes seeming to follow you." Return visits: "The dusty entrance hall."

This pattern — first-visit detail, return-visit brevity — is standard in text adventures. It respects the player's time while still delivering atmosphere.

## Try This

**Visit a room twice.** Enter the library, leave, and return. The second description should be shorter. Confirm the flag works correctly.

**Reset visits.** Add a debug command "RESET VISITS" that sets all `v()` values back to 0. Useful for testing descriptions without restarting the program.

**Write both descriptions for every room.** The full descriptions set the scene. The brief ones should be three to five words — enough to remind the player where they are without slowing them down.
