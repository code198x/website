The game is large — possibly the largest BASIC program you have written. The Spectrum has limited memory (about 41K available for BASIC programs). Long variable names, redundant code, and inefficient data storage all consume bytes. This unit focuses on making the program smaller and faster without changing its behaviour.

## Where Memory Goes

In Spectrum BASIC, memory is consumed by three things: the program text (every character in every line), variables (strings and arrays), and the system stack. You can reduce the first two significantly.

## How It Works

**Variable name shortening.** Spectrum BASIC stores the full variable name for every reference. `score` uses 5 bytes each time it appears. `s` uses 1 byte. Across hundreds of references, this saves thousands of bytes. Rename long variable names to single characters, keeping a comment table at the top of the program.

**REM line at line 1** lists all variable mappings: `r=room, s=score, t=turn, c$=command, v$=verb` etc. This is essential — without it, the shortened code is unreadable. The REM line itself costs bytes, but it is worth it for maintainability.

**Remove spaces.** Spectrum BASIC does not need spaces between keywords and values. `LET r = 1` can be `LET r=1`. The saved byte per space adds up across thousands of lines. However, readability suffers — apply this only after the code is stable.

**Combine short lines.** Multiple statements on one line with `:` reduce line overhead. Each line has 4 bytes of overhead (line number + length). Combining `LET a=1` and `LET b=2` into `LET a=1: LET b=2` saves 4 bytes. Across hundreds of lines, this is significant.

**Shorten strings in DIM.** `DIM r$(20,30)` reserves 30 characters per room name. If the longest name is 18 characters, `DIM r$(20,18)` saves 240 bytes. Audit every string array and set the dimension to the actual maximum.

**Remove debugging code.** Any test commands (WAKE ALL, WHERE CAT, UNLOCK cheat) should be removed from the final version. Each unused command wastes memory and processing time.

## Try This

**Check free memory.** Print `PRINT 65535 - USR 7962` (or `PRINT FRE ""` on some BASIC variants) to see how much memory remains. Do this before and after optimisation to measure the savings.

**Shorten variable names.** Pick the five most-used variables and shorten them. Re-run the game and confirm nothing broke. Shortened names are the biggest single saving.

**Benchmark a turn.** Time how long one game turn takes (from input to next input prompt). After combining lines and removing spaces, time it again. The difference should be noticeable in long subroutines.
