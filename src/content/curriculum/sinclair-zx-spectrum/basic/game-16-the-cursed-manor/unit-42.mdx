The cat already has a turn — it moves randomly each time the player acts. Free guests deserve the same. After the player's command is processed, each free guest gets a turn to do something: move, speak, or wait. This is the NPC turn system, inspired by The Hobbit's autonomous characters.

## The Turn Loop

After the player acts, a loop runs through all NPCs (the cat and all free guests). Each NPC's turn is processed by a subroutine that checks their state and decides what they do. The result may be movement, dialogue, or nothing — NPCs are not obliged to act every turn.

## How It Works

**Lines 2000-2030** are the NPC turn loop. It runs after the player's command is fully processed, before the display routine loops back. First the cat's turn (already written), then each guest's turn in order.

**Lines 2040-2060** process one guest's turn. The first check: is the guest free (`gs(i) = 2`)? If not, skip — frozen and waking guests do not act. If free, call the guest's behaviour subroutine.

**Lines 2050-2055** decrement wake timers. If `gw(i) > 0`, decrement by 1. If `gw(i)` reaches 0, transition from waking to free: `LET gs(i) = 2`. Print a message: "[Name] shakes off the last of the stone and looks around." This happens during the NPC turn, so it feels like a natural event.

**The NPC turn is invisible when nothing happens.** If all guests are frozen and the cat does not move, the NPC turn produces no output. The player does not notice the system running. When guests start waking and acting, the turn system reveals itself gradually.

**Turn order** — the cat goes first, then guests in order (1-5). If order creates conflicts later (two NPCs in the same room), you resolve them sequentially. The first to act has priority.

## Try This

**Observe the cat's turn.** The cat was already acting. Now notice it as part of the structured NPC loop — same behaviour, cleaner code.

**Test the wake timer.** Set a guest to waking state with a timer of 3. Take three turns and watch them transition to free. The message should appear on the third turn.

**Watch for timing issues.** Do NPCs act before or after the display? The current order is: display room, read input, process command, run NPC turns, loop to display. This means NPC actions appear in the next display cycle. If that feels delayed, consider printing NPC action messages immediately during their turn.
