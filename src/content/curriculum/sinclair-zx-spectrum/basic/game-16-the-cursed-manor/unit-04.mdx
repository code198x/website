North and south work. Now add east and west to complete the four cardinal directions. The manor is a two-dimensional space, and the player needs all four compass points to explore it properly.

## Four Exit Arrays

Each room now has four exit values: `n(r)`, `s(r)`, `e(r)`, and `w(r)`. The movement code follows the same pattern for each direction — check the command, check the exit, update the room number.

## How It Works

**Lines 20-30** dimension four arrays for exits. `DIM n(20)` reserves space for north exits for all 20 rooms, even though you only have a few rooms so far. Planning ahead avoids redimensioning later.

**Lines 400-490** now handle all four directions. Each block follows the same three-line pattern: check the command string, check the exit value, update `r` or print the "cannot go" message. This repetitive structure is intentional — it is easy to read, easy to debug, and easy to extend.

**The exit display** now lists all four possible directions. The code checks each exit array and builds a string of available directions, separated by commas.

## Try This

**Create a four-room square.** Set up rooms so that going north then east reaches the same room as going east then north. Consistent connections prevent the player from getting confused.

**Combine the direction checks.** All four direction blocks share the same structure. Could you use a subroutine with parameters to reduce repetition? Think about how you would pass the direction string and array.

**Add UP and DOWN.** Some rooms in the manor will have stairs. Add `u(r)` and `d(r)` arrays and handle GO UP and GO DOWN commands.
