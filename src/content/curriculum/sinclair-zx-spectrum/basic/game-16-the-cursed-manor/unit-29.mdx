Room descriptions mention furniture, paintings, and windows. Players will try to examine them. If the parser says "I do not know that word" when the player types EXAMINE TABLE, the illusion breaks. Scenery objects cannot be taken or dropped, but they can be examined — and sometimes they hide clues.

## Scenery Data

Scenery is simpler than items. Each scenery object has a name, a room, and an examine description. There is no carry state, no drop logic, no inventory. The EXAMINE command checks scenery after checking items and guests.

## How It Works

**Lines 38-40** dimension scenery arrays. `DIM sn$(15,15)` for names, `DIM sl(15)` for locations, `DIM sd$(15,60)` for descriptions. Fifteen scenery objects cover the most important features.

**Lines 9300-9315** store scenery in DATA statements. Each entry is a name, room number, and description. Examples: "table" in the kitchen ("A heavy oak table, scarred with knife marks"), "portrait" in the entrance hall (this is separate from the portable portrait item — this is a large painting on the wall), "bookshelf" in the library ("Hundreds of leather-bound volumes, thick with dust").

**Lines 710-730** extend EXAMINE to check scenery. After items and guests, the code loops through scenery objects. If the name matches and the scenery is in the current room, the description prints. If EXAMINE fails all three checks (items, guests, scenery), the final error message appears.

**Scenery handles TAKE gracefully.** If the player types TAKE TABLE, the code checks items first (no match), then prints "You cannot take that." This is better than "I do not see that" — the game acknowledges the object exists but cannot be carried.

## Try This

**Examine everything mentioned in room descriptions.** If a room description mentions a fireplace, add it as scenery. Players will try to examine anything that sounds interesting. Missing scenery breaks immersion.

**Add a hidden clue.** One scenery object — perhaps a painting or a bookshelf — should reveal an extra hint when examined. "Behind the painting, you notice scratches on the wall forming a pattern." Hidden details reward thorough players.

**Test TAKE on scenery.** Try to take every scenery object. Each should produce "You cannot take that" rather than a confusing error. The parser should always acknowledge things that exist.
