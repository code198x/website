Hardcoding each room in IF statements works for three rooms but will not scale to twenty. DATA and READ let you store all room information in a compact table at the end of the program, then load it into arrays at startup.

## The Data Table

Each DATA line holds one room: name, description, and four exit numbers (north, south, east, west). A FOR loop reads them all into arrays. When you need to change a room, you edit one DATA line instead of hunting through IF blocks.

## How It Works

**Lines 20-40** dimension the arrays. `DIM r$(20,30)` stores room names (up to 30 characters each). `DIM d$(20,80)` stores descriptions. The exit arrays `n()`, `s()`, `e()`, `w()` remain as before.

**Lines 50-70** read room data in a loop. For each room, READ pulls the name, description, and four exit numbers from the DATA lines. The loop runs from 1 to `nr` (number of rooms), so adding a room means incrementing `nr` and adding one DATA line.

**Lines 9000-9020** hold the DATA. Each line is one room. The name and description are strings (in quotes), followed by four numbers for exits. This table is the single source of truth for the manor's geography.

**The display subroutine** now reads from arrays instead of setting variables with IF statements. `r$(r)` and `d$(r)` give the name and description for whatever room number `r` holds.

## Try This

**Add two more rooms.** Write DATA lines for a dining room and a study. Connect them to existing rooms by setting the exit numbers. Increase `nr` to match.

**Print a room count.** After loading all rooms, print "Loaded [nr] rooms" and PAUSE to confirm the data loaded correctly. This kind of startup check catches DATA errors early.

**Experiment with string length.** What happens if a description exceeds 80 characters? Try it and observe how the Spectrum handles the overflow. You may need to adjust the DIM size or split long descriptions across multiple PRINT statements.
