The first unit hardcoded the room description into the opening text. That works for one room, but this game has twenty. You need a way to store room data separately from the display code, so the same printing routine works for any room.

## Room as Data

A room needs a name and a description. Store the name in `r$` and the description in `d$`. A variable `r` tracks which room the player is in — room 1 is the entrance hall.

When the game loop runs, it checks `r` and sets `r$` and `d$` accordingly, then prints them. The display code does not care which room it is — it just prints whatever `r$` and `d$` contain.

## How It Works

**Line 10** sets the current room to 1. This variable will change when the player moves, but for now it stays fixed.

**Lines 100-120** are the room data subroutine. `ON r GO SUB` would be ideal, but with only one room a simple IF suffices. Line 110 sets the room name and description for room 1.

**Lines 200-230** display the room. CLS clears the screen, then the room name prints in bright white, followed by a blank line and the description. This section will not change as you add more rooms — only the data subroutine grows.

**Lines 300-310** are the input loop. The player types a command, and the program loops back to redisplay the room. In later units, the command will be parsed and acted upon before redisplay.

## Try This

**Add a second room.** Create room 2 with `IF r = 2 THEN LET r$ = "Library": LET d$ = "..."`. Change line 10 to `LET r = 2` and confirm the display routine shows the new room.

**Colour the room name.** Use `INK 6` (yellow) for the room name and `INK 7` (white) for the description. The visual distinction makes it easier to scan the screen.

**Count the turns.** Add a variable `t` that increments each time through the loop. Print it alongside the room name to track how many commands the player has entered.
