The first-visit system saves time, but sometimes the player wants to re-read a room description. The LOOK command forces the full description to display regardless of the visit flag. It is one of the most important commands in any text adventure.

## Forcing a Full Description

LOOK does not change any game state. It simply temporarily overrides the visit check and displays the full description. The visit flag stays at 1 — the next normal entry still shows the brief version.

## How It Works

**Lines 350-370** handle the LOOK command. When `c$ = "LOOK"`, the code sets a temporary flag `lf = 1`, then jumps to the display routine. The display routine checks `lf` — if it is 1, the full description shows regardless of `v(r)`. After display, `lf` resets to 0.

**The display routine** now has two reasons to show the full description: `v(r) = 0` (first visit) or `lf = 1` (LOOK command). Both trigger the same long description. This avoids duplicating the display code.

**LOOK also shows exits.** After the room description, the exit list prints. This reinforces the habit of typing LOOK when the player feels lost — they get both the description and the available directions in one command.

## Try This

**Test the flow.** Enter a room for the first time (full description). Leave and return (brief description). Type LOOK (full description again). Leave and return once more (brief again). The flag should not change from LOOK.

**Add LOOK to the command summary.** At some point you will add a HELP command. For now, make a mental note that LOOK is the first utility command — it changes nothing but gives information.

**Try EXAMINE ROOM as a synonym.** If the player types "EXAMINE ROOM" instead of "LOOK", should it do the same thing? Add a second check. The synonym system in unit 27 will handle this properly, but a quick fix works for now.
