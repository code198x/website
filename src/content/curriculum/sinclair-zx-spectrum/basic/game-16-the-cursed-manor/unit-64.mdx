## How It Works

The complete game runs a tight loop:

1. **Display** the current room — illustration, description (full or brief), guests, items, cat, exits
2. **Read** the player's command
3. **Parse** — expand abbreviations, replace synonyms, split into verb and noun
4. **Dispatch** — route the verb to the correct handler
5. **Execute** — perform the action, update game state, print feedback
6. **NPC turns** — cat moves, free guests move and act, wake timers decrement
7. **Events** — distant sounds, ambient atmosphere
8. **Loop** back to display

Every system you built — rooms, movement, items, guests, parser, puzzles, NPC autonomy, scoring, illustrations, sound, darkness, dialogue, abbreviations — slots into this loop. They interact through shared state: arrays, flags, and variables that multiple systems read and write.

## What You Built

**20 rooms** connected by six-directional movement, with locked doors, first-visit descriptions, LOOK command, and line-art illustrations. The manor has a ground floor, upper floor, cellar, and grounds.

**6 items** — silver key, lantern, grimoire, amulet, tinderbox, and portrait — each with a pickup, drop, examine, and special-use function. A carry limit forces strategic choices.

**5 frozen guests** — Colonel Blackwood, Lady Ashworth, Dr Hartley, Mrs Pemberton, and the Maid — each with clues, three-state descriptions (frozen, waking, free), dialogue, and autonomous movement and actions when freed.

**A two-word parser** that splits input into verb and noun, expands synonyms, accepts abbreviations, and dispatches to command handlers. It handles errors gracefully with context-sensitive messages.

**A puzzle chain** — key unlocks tower, tower holds grimoire, grimoire describes ritual, combination opens chamber, chamber holds amulet, tinderbox lights lantern, amulet makes cold fire, portrait reveals name, ritual breaks curse.

**Autonomous NPCs** — the cat wanders with personality, free guests move between preferred rooms, perform actions, speak, and respond to gifts. Distant events report NPC activity in adjacent rooms.

**Atmosphere** — ambient events, room-specific sounds, darkness mechanics, response variety, and a tonal shift after the ritual (menacing to peaceful).

**A scoring system** that tracks exploration, discovery, and puzzle completion, with a perfect score of 120 and four rating tiers.

**A title sequence**, instructions page, and ending sequence that frame the game as a complete, polished product.

## What You Learnt

Across 64 units, you learnt how to build a complex, interactive program from scratch. Not by writing it all at once, but by layering systems one at a time — each one small enough to understand, test, and debug before moving to the next.

**Data-driven design** — rooms, items, guests, and events stored in DATA statements, loaded into arrays, and processed by generic routines. Adding content means adding data, not rewriting code.

**State management** — flags, arrays, and variables that multiple systems share. The lock array controls movement. The guest state array controls descriptions, behaviour, and dialogue. The ritual flag changes the entire feel of the game.

**Input processing** — abbreviation expansion, synonym replacement, verb/noun parsing, and context-sensitive error handling. A pipeline that transforms raw text into game actions.

**Autonomous characters** — NPCs that act independently, with weighted movement, context-sensitive actions, and dialogue. The game world continues to function even when the player does nothing.

**Puzzle design** — prerequisite chains, clue distribution, and feedback that guides without solving. Every puzzle has a clear solution reachable through in-game information.

**Atmosphere and polish** — sound, illustrations, varied responses, ambient events, and a tonal arc. The game does not just work; it feels like a place.

## What Comes Next

You have completed the Spectrum BASIC curriculum. Sixteen games, from a number guessing game to a full text adventure. You understand how BASIC programs are structured, how data drives behaviour, how state machines model complexity, and how interactive systems respond to user input.

These skills transfer directly to every other programming language and platform. The concepts — loops, conditionals, arrays, state, parsing, input handling — are universal. The Spectrum taught you how computers think. Everything else is syntax.

## Try This

**Play the game from start to finish.** No debugging commands, no shortcuts. Play it as a player, not a programmer. Is it fun? Is it satisfying? Does the ending feel earned?

**Give it to someone else.** Watch them play without helping. Where do they get stuck? What do they try that the parser does not understand? Their experience reveals blind spots in your design.

**Think about what you would change.** More rooms? More items? More puzzles? A time limit? Multiple endings? Every design decision opens new possibilities. You now have the skills to pursue any of them.
