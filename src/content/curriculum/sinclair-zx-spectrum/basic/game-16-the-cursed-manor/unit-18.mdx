Taking an item changes its state, but the player needs to keep it as they move between rooms. Carried items travel with the player. They do not appear in room descriptions. They appear in the inventory instead. This unit ensures that carried items behave correctly across movement.

## Carried State

When `ic(i) = 1`, item `i` is carried. The room display loop skips carried items. The movement code does not need to change — carried items have no room location, so they automatically follow the player.

## How It Works

**The display loop** (lines 270-280) already checks `ic(i) = 0` before listing an item in the room. Carried items (`ic(i) = 1`) are invisible in room descriptions. This was set up in the previous unit — now you can verify it works across multiple rooms.

**Lines 560-565** in the TAKE handler set `ic(i) = 1` when an item is picked up. The item's location `il(i)` is set to 0 (no room). These two values together mean "the player has this item."

**The movement code** does not mention items at all. When the player moves from room 3 to room 4, carried items stay carried. Their state does not depend on the room — it depends on the `ic()` array. This separation is important: room state and item state are independent systems.

**Testing carried items** — take the key in the library, move to the corridor, move to the entrance hall. At no point should "silver key" appear in any room description. The key is with the player, not in a room.

## Try This

**Carry an item through the whole map.** Take the key and visit every room. Confirm it never appears in any room description. The item is invisible to rooms but present with the player.

**Try taking an item you already carry.** Type TAKE KEY when you already have it. The game should say "You are already carrying that." Add this check before the pickup code.

**Print carried count.** Add a line that prints the number of carried items in the status area. Loop through `ic()` and count the 1s.
