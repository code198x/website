## INKEY$ for continuous control

You used `INKEY$` in Bright Spark to read single key presses. Here it does something different: it checks whether a key is held down *right now*, inside the game loop. No waiting, no debouncing. The loop runs constantly, and each pass checks whether SPACE is pressed.

This is the difference between turn-based and real-time input. `INPUT` stops the program and waits. `INKEY$` samples the keyboard without stopping. The game keeps running whether or not the player presses anything — gravity does not wait.

## Why -2 and not -1?

Gravity adds 1 to speed each frame. Thrust subtracts 2. That means holding SPACE does more than cancel gravity — it actively slows the lander down. This gives the player real control: tap SPACE to slow your descent, hold it to come almost to a stop. If thrust were only -1, it would barely counteract gravity, and landing would be nearly impossible.
