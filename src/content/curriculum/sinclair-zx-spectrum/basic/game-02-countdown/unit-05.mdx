The game detects the keypress. But it doesn't know *how fast* you were. To measure reaction time, you need a counter that ticks up inside the INKEY$ loop. When the player presses a key, the counter holds the score.

"Time: 289" — that's your reaction speed measured in loop iterations. Lower is better. The number depends on how fast you pressed and how fast BASIC runs the loop.

## How Counting Works

`LET t=t+1` looks odd — t equals t plus one? In maths, that's impossible. In programming, it means "take the current value of t, add 1, and store the result back in t."

Each time the loop runs: t goes from 0 to 1, then 1 to 2, then 2 to 3... When the player presses a key, the loop stops and t holds the total number of passes. More passes = slower reaction.

## The Timeout

Line 130 checks `IF t>500`. If the player doesn't react within 500 loop iterations, the game gives up. Without this, a player who walked away would leave the program running forever.

The timeout message "Too slow!" appears in red — a clear signal that the round is lost. Try changing 500 to 100 for a much tighter window, or 2000 for a generous one.

## Try This

- Win with the lowest score you can. Under 10? Under 5? (It depends on how fast the loop runs — on a real Spectrum, even instant reactions score around 2-3.)
- Change `IF t>500` to `IF t>50`. Now you have about one second to react. Is that enough?
- Add `115 PRINT AT 14,10; INK 7;t` to see the counter ticking up in real time while you wait. It slows the loop down (PRINT takes time) but it's satisfying to watch.

## What You've Learnt

- **Counting in a loop** — `LET t=t+1` increments a variable on each pass
- **Using a counter as a timer** — the number of loop iterations measures elapsed time
- **Timeout** — `IF t>500` prevents the loop from running forever
- **Lower is better** — fewer iterations = faster reaction
