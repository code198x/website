You know that `INKEY$` checks the keyboard without waiting. But what if you *want* to wait — just not with `INPUT`? What if you want the program to pause until the player presses any key, without needing them to type a word and press ENTER?

You build it yourself with a loop.

## The Pattern

<CodeFromFile src="sinclair-zx-spectrum/basic/game-02-countdown/unit-05/wait-key.bas" />

![Press any key... You pressed a key!](/images/sinclair-zx-spectrum/basic/game-02-countdown/unit-05-waiting-for-a-keypress/wait-key.png)

Run it. The screen says "Press any key..." and nothing happens. Press any key and the message changes to "You pressed a key!" with a beep.

Line 30 is the key: `IF INKEY$ = "" THEN GO TO 30`. If no key is pressed, jump back to line 30 and check again. If a key *is* pressed, the condition is false — `INKEY$` isn't empty — so the `GO TO` is skipped and the program moves to line 40.

This is a **busy loop**. The Spectrum runs line 30 thousands of times per second, checking the keyboard each time, going nowhere until something happens. It's like standing at a window watching for the postman — you check, nothing, check again, nothing, check again, there they are.

## Why Not INPUT?

`INPUT` waits too, but it requires the player to press ENTER. For a reaction timer, you want the timing to start the instant they press *any* key — not when they find the ENTER key. The `INKEY$` loop responds to any keypress immediately.

There's another difference: `INPUT` shows a cursor and expects typed text. The `INKEY$` loop is invisible. The screen shows whatever you printed, and the program silently waits in the background. It's cleaner.

## The Building Block

This tiny pattern — `IF INKEY$ = "" THEN GO TO` the same line — is the foundation of the reaction timer. In the next unit, you'll add a counter inside this loop to measure how long the player takes. The loop spins, the counter ticks up, and when a key is finally pressed, the counter tells you how fast they reacted.

## Try This

**Sound on press.** Change the BEEP pitch. Try `BEEP 0.1, -5` for a low thud, or `BEEP 0.05, 20` for a high chirp.

**Multiple waits.** Add a second prompt after line 50 — `PRINT "Press again..."` then another `IF INKEY$ = "" THEN GO TO` loop on a new line. The program waits twice.

**Specific key.** Change line 30 to `IF INKEY$ <> "s" THEN GO TO 30`. Now the program only continues when the player presses S. Every other key is ignored.

## What You've Learnt

- **Busy loop** — `IF INKEY$ = "" THEN GO TO` the same line creates a wait-for-keypress loop
- **Any key** — the loop responds to any keypress, not just ENTER
- **Invisible waiting** — no cursor, no prompt character; the screen shows only what you've printed
- **Foundation** — this pattern is the core of the reaction timer you're building
