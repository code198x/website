In Lucky Number, you used `INPUT` to get the player's guess. `INPUT` stops the program and waits — nothing happens until the player types something and presses ENTER. That's fine for a guessing game, but it's no good for a reaction timer. You need to check whether a key is pressed *right now*, without stopping.

That's what `INKEY$` does.

## What INKEY$ Returns

`INKEY$` checks the keyboard at the exact moment it runs. If a key is being held down, it returns that key as a single character. If no key is pressed, it returns an **empty string** — a string with nothing in it, written as `""`.

It doesn't wait. It doesn't pause. It checks once and moves on.

Here's a program that shows what `INKEY$` returns:

<CodeFromFile src="sinclair-zx-spectrum/basic/game-02-countdown/unit-04/inkey-show.bas" />

Run it. The screen fills with... nothing. `INKEY$` returns an empty string over and over, and `PRINT k$;` prints empty strings. Now hold down a key — say **A**. You'll see a stream of `a` characters.

The semicolon after `k$` keeps each character on the same line (you learnt this in Lucky Number). Without it, each `PRINT` would start a new line and the screen would scroll constantly.

## Checking for "No Key"

A more useful pattern: check whether `INKEY$` is empty and respond differently.

<CodeFromFile src="sinclair-zx-spectrum/basic/game-02-countdown/unit-04/inkey-check.bas" />

![Dots with letters when keys are pressed](/images/sinclair-zx-spectrum/basic/game-02-countdown/unit-04-press-any-key/inkey-check.png)

Run it and watch the dots flow across the screen. Each dot means "no key pressed." Now hold a key — the dots are replaced by that letter. Release the key and the dots resume.

Here's what's happening:

- **Line 10** — `LET k$ = INKEY$` checks the keyboard and stores the result in `k$`.
- **Line 20** — if `k$` is empty (no key pressed), print a dot.
- **Line 30** — if `k$` is not empty (a key is pressed), print the key.
- **Line 40** — `GO TO 10` loops back to check again.

The program runs this loop hundreds of times per second. Each time around, it checks the keyboard and reacts. This is the heart of real-time input.

## The Empty String

`""` is an empty string — a string containing no characters at all. It's not a space. It's not invisible text. It's genuinely nothing.

`INKEY$` returns `""` when no key is pressed. The condition `k$ = ""` means "is this string empty?" and `k$ <> ""` means "is there something in this string?"

You'll use this pattern constantly: check `INKEY$`, compare it to `""`, and decide what to do.

## INPUT vs INKEY$

| | INPUT | INKEY$ |
|---|---|---|
| **Waits?** | Yes — program stops until ENTER is pressed | No — checks once and moves on |
| **Returns** | Whatever the player typed | One character, or `""` if no key is pressed |
| **Use for** | Questions, menus, typed answers | Real-time gameplay, reaction tests |

`INPUT` is a conversation: "What's your answer?" `INKEY$` is a glance: "Is anything happening right now?"

## Try This

**Specific key.** Change line 30 to `IF k$ = "s" THEN PRINT "S!";` — now it only reacts to the S key. Everything else is ignored (dots still print from line 20).

**Break out.** The program loops forever. Press **Caps Shift + Space** (BREAK) to stop it. This key combination interrupts any running program on the Spectrum.

## What You've Learnt

- **INKEY$** — checks the keyboard without waiting; returns one character or `""` if no key is pressed
- **The empty string `""`** — what `INKEY$` returns when nothing is happening
- **Non-blocking input** — the program keeps running whether or not a key is pressed
- **The difference** — `INPUT` waits for the player; `INKEY$` checks instantly and moves on
- **String variables** — `k$` and `w$` hold text, not numbers
