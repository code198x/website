Line 340 changes from printing "Wrong!" and stopping to `GO TO 430`. Lines 430–480 build the game over screen: line 430 flashes the border red and plays a low buzz — the opposite of the green/high correct feedback. Line 450 clears the screen. Lines 460–480 print the title, "GAME OVER", and the streak. Then lines 550–580 wait for a key and `GO TO 180` to deal a fresh game.

The game over screen mirrors the correct-guess feedback but inverted. Green, high, "Correct!" vs red, low, "GAME OVER". The player already learnt what green and red mean during the game — the ending uses the same language at a bigger scale.

## Endings as structure

Every game so far has followed the same pattern: build the game first, then add the ending. That is deliberate. The game over screen is not part of the core logic — it is presentation. Line 340 could just as easily say `STOP`, and the game would still work. The game over screen is there for the player, not for the program.

But it matters. A game that ends with `STOP` feels like it broke. A game that ends with a screen, a sound, a score, and an invitation to play again feels like it finished. The difference is one `GO TO`, a colour, a sound, and a few lines of text.
