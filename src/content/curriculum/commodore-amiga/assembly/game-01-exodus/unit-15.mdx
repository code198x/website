The game plays to completion, but it starts immediately and can't restart. In this unit, we add a title screen and a complete game loop: title, play, and result — with fire button transitions between each.

![Exodus Unit 15](/images/commodore-amiga/game-01-exodus/unit-15/screenshot.png)

"EXODUS" appears in the game area against the gradient sky. The panel sits below, empty and waiting. Press fire to begin.

## Three Game States

The game state machine expands to three states:

```asm
GAME_TITLE          equ 0
GAME_PLAYING        equ 1
GAME_COMPLETE       equ 2
```

The main loop checks the state and branches accordingly:

<CodeFromFile src="commodore-amiga/game-01-exodus/unit-15/snippets/03-state-machine.asm" />

In the title state, the loop does nothing except check the fire button. When fire is pressed, `start_game` sets up everything and switches to playing. When the level completes, the result shows until fire is pressed again — then the bitplane is cleared, the title is redrawn, and the state returns to title.

This is a complete game loop. The program never exits; it cycles through title, play, and result indefinitely.

## Drawing the Title

Six letter glyphs spell "EXODUS" on the game bitplane:

<CodeFromFile src="commodore-amiga/game-01-exodus/unit-15/snippets/01-draw-title.asm" />

Each letter is an 8x8 glyph, drawn at 8-pixel intervals starting at x=128, y=80. The `draw_bitplane_glyph` subroutine works identically to `draw_panel_glyph`, but writes to the game bitplane instead of the panel bitplane.

The letter font data uses the same format as the digit font — 8 bytes per character:

```asm
font_E:
            dc.b    %01111110
            dc.b    %01100000
            dc.b    %01100000
            dc.b    %01111100
            dc.b    %01100000
            dc.b    %01100000
            dc.b    %01111110
            dc.b    %00000000
```

The bitmap font system now handles digits 0-9, a slash, and the letters E, X, O, D, U, S. Adding more characters is trivial — define 8 bytes and call `draw_bitplane_glyph`.

## The start_game Subroutine

When fire is pressed on the title screen, `start_game` handles the entire transition:

<CodeFromFile src="commodore-amiga/game-01-exodus/unit-15/snippets/02-start-game.asm" />

It clears the title text, resets all creatures to their starting positions, resets the score counters, changes the game state, draws the terrain and exit markers, and draws the initial score display. Everything the game needs is initialised in one place.

The bitplane clear uses a tight loop:

```asm
clear_bitplane:
            lea     bitplane,a0
            move.w  #BITPLANE_SIZE/4-1,d0
.clr:
            clr.l   (a0)+
            dbra    d0,.clr
            rts
```

`CLR.L` zeros 4 bytes at a time. For an 8,000-byte bitplane, that's 2,000 iterations — fast enough to complete within the vertical blank.

## Restart Flow

After the level completes and the result is shown, pressing fire triggers a restart:

```asm
.complete_update:
            btst    #6,$bfe001
            bne     .frame_end
            bsr     clear_bitplane
            bsr     draw_title
            move.w  #GAME_TITLE,game_state
            move.w  #COLOUR_PANEL_BG,panel_bg_val
```

The panel background is restored to its default colour (clearing the green/red result), the bitplane is cleared, and the title is redrawn. The game is ready for another round.

## If It Doesn't Work

- **Title doesn't appear?** Check that `draw_title` is called before the main loop starts, and that the bitplane pointer is patched before the Copper list is installed.
- **Fire doesn't start the game?** The fire button test reads `$BFE001` bit 6. Low means pressed. Make sure the title state checks `GAME_TITLE` (0), not some other value.
- **Game doesn't restart?** The complete state must clear the bitplane, redraw the title, reset `game_state` to `GAME_TITLE`, and restore `panel_bg_val` to `COLOUR_PANEL_BG`.
- **Terrain appears on title screen?** Make sure `start_game` calls `clear_bitplane` before drawing terrain. If terrain is drawn without clearing, it'll overlap with the title text.

## What You've Learnt

- **Three-state game loop** — title, playing, and complete form a cycle. Each state has its own update logic and transition trigger.
- **Bitplane text rendering** — 8x8 letter glyphs drawn directly to the game bitplane. The same technique works for digits, letters, and symbols.
- **Game initialisation subroutine** — `start_game` encapsulates all setup in one callable routine, making restart trivial.
- **State restoration** — returning to the title means clearing the display and resetting Copper values. Every visual element must be explicitly restored.
