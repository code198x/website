## What You're Building

Time pressure.

A game without urgency is just a leisurely stroll. This unit adds a 60-second countdown timer. Reach a home before time runs out or die trying. Move faster to earn bonus points.

By the end of this unit:
- 60 second timer per attempt
- Timer displayed on screen
- Timeout = death
- Faster = more bonus points

## The Timer Variable

We store the timer as a frame count. At 50Hz PAL, 60 seconds equals 3000 frames:

<CodeFromFile src="commodore-amiga/game-01-signal/unit-13/snippets/01-timer-constants.asm" />

Using frames instead of seconds gives us precise control. The timer decrements once per frame in the main loop.

## Updating the Timer

Each frame, we subtract 1 from the timer. When it hits zero, the frog dies:

<CodeFromFile src="commodore-amiga/game-01-signal/unit-13/snippets/02-update-timer.asm" />

The `bgt.s` (branch if greater than, signed) handles the comparison. When timer becomes zero or negative, we trigger death.

We skip the timer update when the frog is dying—no point counting down during the death animation:

```asm
            ; Update timer (only when not dying)
            cmp.w   #STATE_DYING,frog_state
            beq.s   .skip_timer
            bsr     update_timer
.skip_timer:
```

## Displaying Seconds

Players think in seconds, not frames. We convert frames to seconds using DIVU:

<CodeFromFile src="commodore-amiga/game-01-signal/unit-13/snippets/03-display-timer.asm" />

DIVU divides a 32-bit dividend by a 16-bit divisor. The quotient (seconds) ends up in the low word. We extend the 16-bit timer to 32 bits with `ext.l` before dividing.

## Time Bonus

Reaching home faster should reward the player. We calculate a bonus based on remaining time:

<CodeFromFile src="commodore-amiga/game-01-signal/unit-13/snippets/04-time-bonus.asm" />

If you reach home with 30 seconds remaining, you earn 60 bonus points (30 × 2). The faster you move, the bigger the reward. The `and.l #$ffff,d0` masks off the remainder in the high word, keeping only the quotient.

## Resetting the Timer

The timer resets in two places:

**Game initialisation** (new game):
```asm
init_game:
            move.w  #START_LIVES,lives
            clr.l   score
            move.w  #TIMER_START,timer      ; Reset timer
```

**Frog reset** (after reaching home or death):
```asm
reset_frog:
            ; ... other reset code ...
            move.w  #TIMER_START,timer      ; Reset timer for new attempt
```

Each attempt starts fresh with 60 seconds.

## Display Position

We place the timer on the left side of the start zone, opposite the score:

```asm
TIMER_X         equ 56          ; Pixel X position (left side)
TIMER_Y         equ 236         ; Same row as score
TIMER_DIGITS    equ 2           ; 2 digits (00-60)
```

Two digits suffice since the timer never exceeds 60 seconds.

## The Urgency Effect

The timer transforms gameplay. Without it, players could wait forever for a safe gap. With it, they must take risks. The countdown creates tension—especially in the final seconds.

The time bonus adds another layer: do you play safe and just survive, or push for speed and higher scores?

## Key Takeaways

- **Frame-based timing** gives precise control (3000 frames = 60 seconds)
- **DIVU** converts frames to displayable seconds
- **Timeout triggers death** via existing trigger_death routine
- **Time bonus** rewards faster play (remaining seconds × 2)
- **Timer resets** on each new attempt
- **Urgency** transforms leisurely play into tense action
