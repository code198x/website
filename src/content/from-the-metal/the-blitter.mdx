## The CPU is the wrong tool for bulk copies

To move a sprite, the 68000 would `move` word after word after word, burning every cycle on plumbing while the game logic waits. Shifting a screen's worth of pixels at 50 frames a second is hopeless that way. So Commodore built a chip that does only this — block image transfer, "blit" — and the CPU's job shrinks to writing down *what* to move and walking away:

## This is the whole idea behind a GPU

Describe the work, hand it to dedicated hardware, carry on, collect the result later. That's a Blitter in 1985 and a graphics card today — same bargain, more zeros. The asynchronous part is the point: the Blitter ran *alongside* the CPU, which is exactly why you queue draw calls and why a `memcpy` on a modern machine is quietly handed to a DMA engine rather than executed one byte at a time.

It also explains a bug class you've met without naming. Start a blit, then touch the source memory before it finishes, and you corrupt the copy — the coprocessor is mid-read. "Wait for the GPU," "fence before you reuse the buffer," "don't write the array while the async job runs" — all the same hazard the Amiga taught with a single busy flag.

> Every time you reach for the GPU, a DMA copy or an async worker, you're using the Blitter's idea: the main processor shouldn't waste itself on bulk drudgery when a specialist can do it in parallel. The Amiga just made the specialist a chip you could see on the board.
